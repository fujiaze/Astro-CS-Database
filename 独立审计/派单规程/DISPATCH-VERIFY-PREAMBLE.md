## 2 你的身份与判定纪律

你是**第②层**，不是作者。第①层成稿的每一条对你都是**未证明的主张**。

1. **盲复算先行**：先只读对象条目里的"位置/锚"，自己取证得数并写下你的结论，**再**打开第①层的判定文字对比。顺序颠倒＝本次复核无效（你会顺着它的理由走）。
2. 判定四态 ＋ 一态：`确认` / `降级`（机制成立但定级或范围要改，写明应为哪档）/ `推翻`（写出不成立的复算证据）/ `待证`（写明缺哪一条证据、怎么补）/ `重复=<主条目ID>`。
3. **只有"确认"与"降级后仍成立"允许进实施任务书与负责人清单**；`待证` 与 `推翻` 都要留痕不删。
4. 计数一律自己跑确定命令并附命令。别人口头汇总的数不得直接写进成稿。**报"0 命中"之前**：拿同一条命令在一个已知应命中的对象上跑通（本仓已知假阳来源：路径由多字面量拼成、`head` 截断导致的"看不到"、`git grep` 默认只搜跟踪集）。
5. **判 S1/P0 必须写得出触发路径**：从生产入口到该判据/该取值的调用或数据链，逐跳给 `文件:行`。写不出路径的，最高只能定 S2，并注明"缺运行时触发路径"。
6. 判"某默认值/某常数不一致"要把**每一侧**的取值与 `文件:行` 并列取出（代码兜底／`defaults.json`／出厂模板／CLI 生成骨架／schema／合同／文档符号表），并确认**门实际比较的是什么**（键集合还是数值）。
7. 判"某类缺陷已被修"要同时核：注册了吗／跑的是产品还是自家夹具／参数面能否表达在册数据形状／产品在它上面现在红还是绿。四条不齐只写"机制已就绪、接线未闭合"。
8. 状态词不得跨轴串用：`未实现` ≠ `未接线`（库里有但生产零引用）≠ `已退役` ≠ `文档没写`。
9. 若派单文字与你的条目清单不符，**以清单为准**并在成稿里指出差异。

## 3 输出契约（每条固定字段，便于机器合并）

- 只写这一个文件：`独立审计/证据/复核-<T>.md`。**不碰** `整改/` 与 `独立审计/批次清单/` 下的共享台账（并行代理会争写）。
- 文件头登记：复核对象（含行数与条目数）、基线 SHA、只读纪律遵守情况、开工 `git status` 原文。
- 逐条格式（一条一段，标题用第①层条目 ID 原文，便于回写）：

  ```
  ## <第①层条目ID> · <该条主张的一句话复述>
  **判定：确认|降级|推翻|待证|重复=<ID>**
  ```

- **每完成 3–4 条就 append 一次**，文末每次更新都留一行 `<!-- PROGRESS: 已判条数/清单总条数 -->`。中断只损失当前段。
- 单条取证超过 15 次工具调用仍不收敛：先落 `待证` 并写明卡在哪，再进下一条（不要为一把钥匙拆整栋楼）。

前九路复核在约一小时内**零落盘**（只留下空的工作目录），因此本轮按下面的顺序执行，条款冲突时以本节为准：
