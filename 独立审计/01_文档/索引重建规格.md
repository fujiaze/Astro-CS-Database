# 索引重建规格

`docs/DOCUMENT_INDEX.yaml` 是全文档集的唯一索引地图（标准 01 §3）。本规格给出它应有的字段模型、两轴取值来源、上游校验规则，以及一条**可红可绿**的门判据；开发节点据此重写索引与 `eng/tools/doccheck/check_doc_index.py`（门 ID `DOC-INDEX`）。

## 1 登记对象集：从跟踪集派生，不从目录状态派生

登记对象集（universe）的唯一推导方式：

```bash
git -C <仓库根> -c core.quotePath=false ls-files
```

按下列规则切分，不掺任何磁盘遍历（`os.listdir` / `os.walk`）结果：

| 子集 | 判据 | 登记义务 |
|---|---|---|
| 文档层 | 跟踪集中扩展名为 `.md/.rst/.txt` 的文件 | 全部登记，含仓库根、`docs/**`、`实验/**`、`工程控制/**` |
| 文档型数据件 | 跟踪集中位于文档目录内的 `.yaml/.yml/.csv/.json` | 全部登记，`kind: machine-data` |
| 机器合同与配置 | `eng/contracts/**`、`eng/packaging/config/**` | 登记为 `kind: machine-source`，只填路径/主题/被谁说明，不填上溯指针 |
| 证据与产物 | `artifacts/**` | 登记为 `kind: evidence`，允许批量条目（同前缀一行 + 计数），但路径前缀必须实存 |
| 代码 | `lib/**`、`eng/**` 源码 | 不入本索引，由 `lib/**/module.yaml` 与注册面承载 |

三条硬守卫，缺一即判红：

1. **零对象守卫**：文档层子集为空 ⇒ 直接判红并输出"扫描面为空（fail-closed）"。索引文件缺失、未被跟踪或 YAML 解析失败同样判红，不得跳过内容检查。
2. **口径外零容忍**：`kind: doc` 的对象数必须等于 `git ls-files '*.md' '*.rst' '*.txt' | wc -l`（减去显式登记的排除项），不等即红。排除面每一条形如 `{pattern, reason, evidence}`，`reason` 必须是"生成物 / 证据快照 / 第三方 vendored"三类之一，且被本门逐条复算：命中对象数与声明数一致。
3. **禁止目录名派生判据集合**：判据的取值集合（命名空间前缀、门 ID 词表、角色枚举、主题枚举、状态词表）一律来自本规格的固定枚举或跟踪集中的登记文件，**不得**由 `run/`、`工程控制/` 等易变目录的目录名现算。本仓已有教训：`eng/tools/doccheck/check_doc_hygiene.py` 的 `namespace_prefixes()` 从 `run/` 与 `工程控制/` 的目录名列表推导命名空间前缀，而 `run/` 按工程规范不入库——干净克隆上该目录不存在，前缀集合退化为空，门对全部对象恒判通过。同一形态的守卫若只加在外层（"扫描面非空"）而洞在被嵌套的内层（"判据集合非空"）仍然失明，因此每条判据集合都要各自带非空断言。

## 2 字段模型

```yaml
doc_index:
  version: "3.0.0"
  entries:
    - path: "docs/science/PHOTOMETRY.md"
      kind: doc                       # doc | machine-data | machine-source | evidence | generated
      role: 科学定义                   # §3 枚举，单值
      topic: photometry-calibration   # §4 枚举，单值
      canonical: true                 # 该主题的正本；每主题恰好一条 true
      upstream:
        clause: "§2.1"                # 条款号，必须实存
        title: "创新点一：测光校准到测光星等坐标系"   # 必须与该节标题逐字相等
        extras: ["§4.2", "§3.3"]      # 可选补充条款，同样双要素
      downstream: auto                # 由门现算并写回；auto 表示不信任手工值
      status: 现行                     # 现行 | 生成 | 证据 | 待迁 | 已出库（登记态，非交付状态阶梯）
      layer: 2                        # 权威层级 1|2|3|4
      owner: lib/algorithms/photometry  # 相关代码落位（可空）
      notes: ""
```

字段规则：

- `path`：仓库相对路径，正斜杠，全索引唯一；文件必须实存于跟踪集（`memory.md` 一类先登记再处置，未登记即缺陷，登记了而文件不存在同样是缺陷）。
- `kind` + `status` 组合受约束：`generated`/`evidence` 不得同时 `canonical: true`。
- `owner` 指向的代码路径必须实存；无对应代码时留空，不写目录名占位。
- 索引自身必须被索引登记（`path: docs/DOCUMENT_INDEX.yaml`），否则"现存文档全部登记"不成立。

## 3 `role` 轴取值与来源

取值 = 《目标文档架构》§2/§3 的角色格子，封闭枚举，不随目录增减自动扩张：

```text
顶层决策 | 科学定义 | 算法推导 | 架构设计 | 架构设计（接口面） | 架构设计（详细设计）
模块工作细节 | 合同说明 | 标准与检查 | 标准与检查（机器门） | 标准与检查（版本治理）
标准与检查（任务包治理） | 标准与检查（干活手册） | 标准与检查（工程规范）
负责人面 | 负责人面（验收规范） | 研究与佐证 | 操作与运营 | 操作与运营（性能）
操作与运营（诊断） | 操作与运营（依赖锁定） | 操作与运营（节点接入） | 操作与运营（开发上手）
索引与登记面 | 术语与词表 | 限制与未决登记 | 追溯登记 | 实验单元（旁挂佐证）
任务包与过程记录 | 入口与导航 | 第四层代码 | 机器事实源
```

来源规则（判据，不是映射表）：一份文档的 `role` 由它**回答什么问题**决定，由其登记条目的一句话职责判定；门校验的是"role ∈ 枚举"与"role 的目标目录 == path 所在目录"（目标目录表固定在本规格 §3.1）。**禁止**从 `path` 的第二段推断 role——那正是当前把 `docs/api/`、`docs/audit/`、`docs/quality/` 等六目录变成"无格可落"的原因，也禁止把 role 反推自目录名。

## 4 `topic` 轴取值与来源

- 取值 = 《目标文档架构》§4 主题正本清单逐行分配的主题 ID，另加登记面与过程类主题；本枚举 55 值，与 §4 表行数不等时差额即待补主题，由 C6 判红。取值清单：`photometry-calibration`、`absolute-snr-weighting`、`additive-sky-seamless`、`healpix-area-overlap`、`noise-model`、`uncertainty-propagation`、`rejection`、`integration`、`upm`、`astrometry-projection`、`product-storage-form`、`cli-surface`、`exit-codes`、`event-stream`、`config-contract`、`resource-gate`、`cpu-backend`、`threading-budget`、`pipeline-block`、`scheduler`、`public-abi`、`io-boundary`、`module-map`、`build-graph`、`compatibility-release`、`numeric-tolerance`、`gate-thresholds`、`ci-pipeline`、`validation-freeze`、`experiment-unit`、`acceptance-layers`、`status-ladder`、`versioning`、`glossary`、`known-limitations`、`license-compliance`、`literature-registry`、`doc-index`、`traceability`、`diagnostics`、`terminology-symbols`、`science-scope`、`unified-model`、`star-detection`、`psf`、`calibration`、`cosmetic`、`platesolve`、`gaia-query`、`acr-equivalence`、`coverage`、`resampling`、`owner-overview`、`task-package`、`evidence-ledger`）。
- 来源规则：主题 ID 与新增主题一律在《目标文档架构》§4 表内登记后，索引才允许使用；门校验 `topic ∈ 枚举`，并校验**每个 topic 恰有一条 `canonical: true`**。枚举同样禁止从文件名或目录名派生。
- 一份文档可有次要主题：次要主题写在 `notes` 里以 `also:` 前缀登记，门不据此判 canonical 冲突。

## 5 上游校验规则（号—标题双要素）

现行门只要求正文前 25 行内出现"上游"与"ASTROCS_DESIGN.md"两个 token，因此一个把机制挂错节、甚至挂到不存在的节的指针可以过关：仓内 265 条索引条目里有 73 条把上游写成 `§8.4（模块与 ABI）`，而 §8.4 标题是"顶层结构"、"模块与 ABI"是 §8.5。

重建后的判据：

1. 条款号存在性：`§x.y` 必须命中 `ASTROCS_DESIGN.md` 的实际小节号（机器扫描 `^### ` 行得到号—标题对，不接受硬编码清单）。
2. 标题一致性：指针括号内标题与该节标题按"去空白后逐字相等"比较；无括号标题视为不合格（只给号不给标题即红）。
3. 双要素同源：文档抬头的上游与索引条目 `upstream` 必须给出同一组号—标题对；不一致即红（这是"上游与索引打架"的现形）。
4. 机制级可追溯：`layer: 1` 的条目不要求上游；`layer: 2|3` 必须有；`kind: generated|evidence` 允许 `upstream: n/a` 但必须带 `notes` 说明其生成来源。
5. 指针完整性方向可查：`canonical: true` 的条目所对应的上位节，其"索引"行必须回指该文档；缺回指即红（把"权威链从顶上断"变成机器可判）。

## 6 可红可绿的门：判据清单

单条检查项 = `name / 判据 / 输入对象数守卫 / 正例 / 负例`。全项 `--self-test` 自带夹具，且夹具对象必须落在临时目录，不改仓库文件。

| # | 检查名 | 判据 | 零对象守卫 | 正例 | 负例（必须判红） |
|---|---|---|---|---|---|
| C1 | `universe_non_empty` | 文档层对象数 > 0 且等于跟踪集 md/rst/txt 数减排除面 | 本身即守卫：0 ⇒ 红 | 干净克隆跑一次，计数 = `git ls-files '*.md' \| wc -l` 派生值 | 把 `ls-files` 换成对不存在目录的遍历 ⇒ 红 |
| C2 | `entry_paths_exist` | 每条 `path` 在跟踪集实存 | 条目数 0 ⇒ 红 | 全条目通过 | 追加一条指向已删除文件的条目 ⇒ 红 |
| C3 | `docs_fully_registered` | 文档层每个对象恰有一条登记（含索引自身、含 `实验/`、`工程控制/`） | 文档层 0 ⇒ 红 | 现集合全登记 | 删掉一条登记 ⇒ 红；把口径缩回只查 `docs/**` ⇒ 本项应红（口径判定见 C4） |
| C4 | `scope_exclusions_justified` | 排除面每条带 `reason ∈ {生成物, 证据快照, 第三方}` 且命中数与声明数一致 | 声明排除但命中 0 ⇒ 红（空排除项＝隐藏口径） | 排除 `artifacts/evidence/**` 且计数相符 | 把 `实验/` 写进排除面而不带理由 ⇒ 红 |
| C5 | `role_legal_and_placed` | `role ∈ §3 枚举` 且 `path` 落在 §3.1 允许目录 | role 枚举为空 ⇒ 红（枚举不得现算自目录） | 每份文档 role 与目录相符 | 把 `docs/audit/x.csv` 的 role 写成 `合同说明` 却留在 `docs/audit/` ⇒ 红 |
| C6 | `topic_canonical_unique` | 每个 `topic` 恰一条 `canonical: true`，且 `canonical` 条目的 `kind` 不是 `generated/evidence` | 某 topic 条目数 0 却出现在枚举里 ⇒ 红 | 全主题一条正本 | 复制一份同主题文档并同样标 canonical ⇒ 红；一条都不标 ⇒ 红 |

| C8 | `upstream_title_verbatim` | 括号内标题与节标题去空白逐字相等 | — | `§8.5（模块与 ABI）` | `§8.4（模块与 ABI）` ⇒ 红（现存 73 条即此形态） |
| C9 | `top_down_pointer_present` | 最高设计每机制节有 `索引：` 行，且其目标条目 `canonical` 回指该节 | 全文 `索引：` 行数 0 ⇒ 红 | §7 各节成对 | 删除 §8.1 的索引行 ⇒ 红（现状即此，73/0 类断点应被判出） |
| C10 | `no_dangling_anywhere` | 全仓任何 `路径` 形态指针（含反引号内 `路径:行`、非 `docs/` 前缀如 `lib/`、`实验/`、`工程控制/`、根文件）在跟踪集可解析 | 扫描面为空 ⇒ 红 | 全解析 | 在任一文档写 `` `docs/不存在的页.md:12` `` ⇒ 红；写 `实验/x/README.md:16` 指向不存在文件 ⇒ 红（现行门因 token 只认 `docs/` 前缀而失明） |
| C11 | `writing_style_clean` | 正文无日期、无流水号、无 commit/散列字面量、开头无元信息块；命中即红并给出行号 | 判定规则表为空 ⇒ 红 | 纯现行条款文体 | 加一行 `> ID: X-001 状态: FROZEN 日期 2026-01-01` ⇒ 红 |
| C12 | `derived_fields_stale` | `downstream: auto` 的条目，门现算与快照不一致 ⇒ 红并输出差值 | 全条目为手工值 ⇒ 红（说明回写通道断了） | 全 auto 且相符 | 手工把 255 改成 3 ⇒ 红 |

失败输出必须逐项给：检查名、对象计数、被判红的前 10 条对象路径。`DOC-INDEX` 门不可 waiver；红灯不得以"索引未跟踪"或"解析器缺失"降级为跳过——这两种情形本身就是 C1/C2 的红。

## 8 重建与迁移的事务顺序

一条动作表行的执行 = 一个原子提交，内含三改：文件（新建/改写/删除）、索引条目（登记/改指/注销）、指针（改指到新路径或改指到 canonical）。顺序约束：

1. 先落 C1–C4（对象集与口径），否则后续判红无意义；
2. 再落 canonical 标记（C6）——它定义"谁是正本"，是合并行的目标；
3. 然后按《迁移合并清单》W1（补上位指针）→ W2（立缺格）→ W3（目录归一）→ W4（主题合一）→ W5（写法收口）→ W6（过程层出库）执行，每波结束跑一次 C1–C12；
4. 待定案、缺去向、去向不存在三类行在对应波次内**保持红灯不 waive**，直到补齐举证或指定去向。

## 覆盖率自报

- 本规格覆盖：登记对象集推导规则 1 套（4 类子集 + 3 条守卫）、字段模型 12 个、role 枚举 32 值与落位判据表 16 行、topic 枚举 55 值、上游校验 5 条、门检查项 12 条（每条带零对象守卫、正例、负例）、与现有 12 个检查名的能力差对照（9 组）、重建事务顺序 4 条。
- 未覆盖：`docs/contracts/INDEX.yaml`（合同 ID 图）的字段级规格——它与文档索引是两张不同登记面，需按同一排除面判据另立一节，本文只规定"两者不得互相承载对方的行"；生成物（`docs/modules/registry/**`、`lib/**/README.md`）的再生成器与索引回写接口未给字段级合同；C11 的写法词表（日期形态、流水号形态、散列长度阈值）留给门禁设计件（D7）细化，本处只定"命中即红 + 给行号"。
