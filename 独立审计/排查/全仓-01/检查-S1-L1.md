### 黄-1 ｜ 黄 ｜ docs/ASTROCS_DESIGN.md:523、:559 ｜ ②行文逻辑＋④幻觉与锚

**问题**: §7.2「机器输出：`--json` 时 stdout 恰为一个 JSON 文档」——按 L1 自身定义（§7.1/:522）`--json <path>` 是**运行**的配置挂载（每次运行必带），故该句在 L1 语境下指“运行时 stdout 恰为一个 JSON 文档”；实现中运行态 stdout 是 **JSONL 事件流（每行一个事件）**，“单 JSON 文档”只适用于 `--version`/`doctor`/`--template` 的裸 `--json`。§7.3:559 在“每次运行”段落又重复「机器输出仍恰为一个 JSON 文档」，与紧邻的“运行事件默认走 JSONL 事件流”同指同一 stdout，前后打架。

**证据**:
- lib/infrastructure/cli/jsonl.h:3-6「机器通道 = stdout：**每行恰一个 UTF-8 JSON 事件（JSONL）**；`--json`（--version/doctor/模板）时 stdout 恰一个 JSON 文档 —— **这些命令不发事件**」；jsonl.h:186-188 逐事件 `std::fputs(..., stdout)`。
- lib/infrastructure/cli/commands.cpp:2258-2261「运行事件流 = **默认输出**，不需要旗标开启…**stdout 恒为纯 JSONL/单 JSON 文档**，人可读摘要走 stderr」。
- lib/infrastructure/cli/parser.cpp:57-58「允许裸用（不取值）的旗标: 顶层 --version、doctor 的 --json / 子命令 --template --json；其余取值旗标缺值 → 2」——运行态 `--json` 必须取值。
- docs/api/CLI_PROTOCOL_V1.md:43 把两种模式并列成不同态: 「`--json`: stdout 恰一个 JSON 文档; 运行事件流: stdout 每行一个 UTF-8 JSON 事件」。

**反方核验**: L1:523 第二分句确实写了「运行事件默认走 JSONL 事件流（唯一 schema，含 progress/resource/artifact/backend/final 等 kind），stdout 无日志污染」，可辩为压缩表述；但两分句同指同一 stdout，且 :559 第三次强调“恰为一个 JSON 文档”，按 L1 实现协议会得到与代码相反的契约。

**建议改法**: 把“单 JSON 文档”限定到 `--version`/`doctor`/`--template` 的裸 `--json`，并写明运行态 stdout = JSONL 事件流（末行 `final`），人可读摘要走 stderr。
