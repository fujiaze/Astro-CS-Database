### 红-1 ｜②合同锚/机读性｜eng/contracts/config/module_dll_contract.schema.json:180

**问题**：模块 DLL 合同 schema 是**非法 JSON**——`"dll_name": { "type": "string", "pattern": "^astrocs_[a-z0-9_]+\\.dll$|^acsd\.exe$" }` 中 `^acsd\.exe` 是**单反斜杠**（`\.`），而 JSON 字符串只允许 `" \\ / b f n r t uXXXX` 转义。任何严格 JSON 解析器读该文件即抛错，「机器校验的合同 schema 唯一事实源」（AGENTS §7）本身不可机读。
**证据**：① 静态解析实测：`python3 json.load` → `Invalid \escape: line 180 column 85 (char 6796)`；对 eng/contracts/** 非样例 JSON 全量逐一解析，**唯一失败文件即本件**（同式前半段 `\\.dll` 是正确双写，笔误仅在 `.exe` 一段）；② 消费面全仓 grep `module_dll_contract`（py/cpp/h/sh/cmake）：仅 `eng/tools/quality/check_module_map.py:11` **文档字符串点名**、`eng/packaging/config/config_registry.json:2144` 目录说明、`docs/contracts/CONFIG_CONTRACT.md` 与两篇 owner 文档提及——**无任何 json.load/jsonschema 消费者**，该合同从未被机器校验，坏转义因此长期零暴露；③ 反方核验——eng/tests/config 的 CFG001-004 只解析 `eng/contracts/schemas/phase_config_*.schema.json`，不触碰 `eng/contracts/config/` 四件套。
**影响**：未来任何「接入该 schema 做机器校验」的任务第一步即崩；dll/exe 名约束的 `pattern` 在 JSON 层不可表达 ⇒ 合同事实上未冻结。
**建议**：改一行 `^acsd\\.exe$`；并给 eng/contracts/** 补一条「严格 JSON 可解析」机器判据（可挂 CHK-REGISTRY-VALIDATE 或合同校验步骤）。本切片只读不改。
**所属面**：②（兼 ③：登记为机读合同的对象实际不可机读）。
