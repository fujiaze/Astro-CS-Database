# 04 二次核对

**本轮状态：待复核。** 本件是独立复核的**执行框架与登记面**，不含任何已完成的复核结论。
它的作用是：01／02／03 件的每一条判定在进最终工单之前，必须先在这里落一个复核结论（确认／降级／推翻／待实跑），并给出复核所依据的**独立取证动作**。

**为什么必须有这一件**：01–03 条目的原始判定来自"读码＋确定性静态复算"，其中相当部分由单一取证路给出；本包的取证面已实证过三类会在无人复核时把结论带偏的形态——
① 检索式自身写错（pathspec 写成单元素导致假"零命中"、`head` 截断导致假"无某调用"、`-c` 数行不数出现次数）；
② 先验被派单写错（"两份实现"实为四份、"创新点①上游主检测器"实不成立、"球面面积解析近似"实无对象可查）；
③ 结论外溢（一族骨架的缺陷被误推到另一族，而后者实测正确）。
⇒ 未经本件复核的条目**一律不得进工单**。

## 1 复核规程（七条，逐条强制）

| # | 规程 | 为什么 |
|---|---|---|
| V-1 | **禁复用被审实现**。复算面积、通量、几何、统计量的条目必须自写一套算法，不复用仓库函数、不 import 仓库 Python；两套以上算法互校时，互差要给出 | 同构复制的期望检不到缺陷；双实现互校在本包已两次抓到复核路自己的缺陷（角点转写错、投影辅助式漏归一化分量） |
| V-2 | **自校项必须含能抓结构性错误的量**（如"总量守恒"、闭式极限、置换不变量的反例），且输入严格单位化 | 只看逐点残差会漏掉"整体自洽但模型错"的形态 |
| V-3 | **旧台账只当线索**。已判过的条目一律盲复算，不沿用旧结论；旧件保留但标注为历史读数、不作证据 | 两处文档计数与注册表现值已全量漂移，而"漂移只在总量不在结构" |
| V-4 | **判定只覆盖版本库跟踪内容**；本机残留、`run/`、未跟踪目录一律不算仓库问题；判"路径不存在"只用跟踪集＋删除历史 | 磁盘存在性会反判；`run/` 内容随时可被回收 |
| V-5 | **单条取证上限**：每条给"一条命令可判"的取因式（列构建目标、列调用点、跑该检查步）；达上限仍不收敛则标 `待定`，不得靠推理补全 | 取证预算花在更高危项上的收益更大；已有一路在超上限后自曝并留痕 |
| V-6 | **可达性先于严重度**。凡结论带"产品字节"者，复核第一件事是独立复算它在当前树是否生产可达；不可达即封顶 S2，可达即升 S1 | 定级里的可达性这一维放错位置会让整批结论虚高或虚低 |
| V-7 | **统计与覆盖率不作交付物**。复核回执必须给三件分母（复核了多少条／其中按件还是按行／推翻了几条）＋ 记录位置 ＋ "为什么这么多／为什么这么少"；判红按件不按行 | 门读数≠精读；按行汇总会把一件缺陷放大成几十条 |

**每轮复核的取证动作一律只读**，零 git 写、零 `git config` 写、不跑构建／ctest／`eng/**`、不在被审仓库内落文件；工作中间件落本包目录之外。凡"某门现在实际是红是绿""某接线补齐后是否真跑通"这类只能由实跑定案的，一律落 §5 的 `待实跑` 档，不得由静态推演补全。

## 2 四档复核结论

| 档 | 含义 | 对工单的影响 |
|---|---|---|
| **确认** | 独立取证给出同一结论，且触发路径逐跳复现 | 进工单 |
| **降级** | 事实成立但严重度或档位不成立（最常见：不可达、已被下游另一道卡兜住、属两不同适用域） | 进工单但改档；整改范围按降级后重算 |
| **推翻** | 事实不成立（原判含检索式假零命中、夹具与实现同域误读、两说实为两域、旧口径已被上游反转消解） | 不进工单；**必须回改 01/02/03 三件的对应行并留订正痕迹**，不得只在本件登记 |
| **待实跑** | 静态读到机制成立、rc 或频率只能由运行定案 | 挂 §5 清单，工单里标 `BLOCKED-待跑`，不得当作已核或不修的理由 |
