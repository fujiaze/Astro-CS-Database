# 修复顺序与验收判据 · ①测光星等坐标系

排序原则（依赖驱动，不是建议）：**先让判据可信 → 再让验证面能红 → 再补实现守卫 → 再改表示与门 → 再订正登记面 → 再落证据 → 最后才动科学口径**。
理由是本链的缺陷形态集中在"合同写明强制而实现零落地、而门结构上判不到它"与"判据与真值同源"两类：
先动实现会被现有恒绿门吞掉（改了也看不出来），先动口径会在无判据的情况下把不确定取值写进正本。

每条给"怎么算修好"＝**一条正例（正确实现必绿）＋ 一条注入已知错必红的负例**。负例一律按 N-24 的资格规则设计：
先确认该判据在"真值无效应"时会归零或判红，再谈数值。

## 顺序不可反的三处理由（供节点自查）

1. **R1 先于一切**：现有 `p1phot` 的注入证据本身 fail-open（A8），在它被修好之前，任何"实现已修＋注入必红"的自证都不成立。
2. **R2 先于 R3**：`n_points`/provenance/`channel` 类守卫一旦收紧，会把现网夹具与模板大面积判红（A1 的 45/45 恒等基线、真实帧缺 `FILTER` 头）。必须先把判据输入与夹具改到读产品面，再收紧，否则整改被误读成"改对反而判红"而回退。
3. **R4/R7 需变更流程**：`PHOTOMETRY.md:191` 的"否则 =0"、§16.1 的 `m(x,y)`、门 ② 的可达域、median 偶数约定都是正本自定条款；按 §8 的查证闭环（派子代理回一手依据 → 订正条文 → 改实现 → 补 Oracle/负例）逐条推进，一个问题走到闭环再进下一个。
