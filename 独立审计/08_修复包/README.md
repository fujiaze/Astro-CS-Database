# 修复包（按创新点分目录）

一个点一个目录，六件齐备：缺陷、**已确立的算法与验证程序**、修复顺序与验收判据、二次核对结果、**正向规格**、**文档订正意见**。
开发节点拿到一个目录就能开工，不需要回仓库重新推导，也不会把已经核过为正确的那一侧改错。

## 目录

| 点 | 目录 | 覆盖范围 |
|---|---|---|
| ① | `①测光星等坐标系/` | 孔径测光 → 定标 → 星等坐标系；含滤镜透过率、SIP 畸变口径、测光施加与检出侧质心/饱和判据 |
| ② | `②跨帧绝对信噪比/` | 参考通量 → 逐像素与逐帧信噪比 → 权重与方差传播 → 导出端方差；含"排除自身"的准确主语与叠加权重口径 |
| ③ | `③加性天光无缝/` | 加性天光与乘性响应分离、天光平面、接缝度量、叠加排异（含停止闸的正确形式） |
| ④ | `④面积交叠与分配/` | 球面像元与投放区交叠、加钻与反向加钻、面积精确性三处独立失效的合并整改 |

## 六件的固定作用

| 文件 | 内容 | 用途 |
|---|---|---|
| `01_缺陷清单.md` | 逐条：编号／事实／档位／到产品字节的逐跳触发路径／取证成稿锚；同族母题合并并标复现模块数 | 看要改什么 |
| `02_已确立的算法与验证程序.md` | **已核过为正确**的式子（含符号约定、归一化、量纲、适用域）、有锚常数、可复用的独立验证程序、以及"不要动"清单 | 照它实现，不重推；防止把对的一侧改错 |
| `03_修复顺序与验收判据.md` | 依赖排序的整改批次；每条给"怎么算修好"＝一条正例＋一条"注入已知错必红"的负例；"改对反而判红"的门与夹具列为同批项 | 提交前自证 |
| `04_二次核对.md` | 每条缺陷由**未参与原审查**的复核路独立判定：确认／降级／推翻，附复算式与数据 | 决定进不进最终工单 |
| `05_正向规格.md` | **主程序要照它写的正向规格**：每个科学量与每条式子给定义／单位／坐标系／归一化／适用域／精度与容差的误差预算来源；每个常数给四档来源；每条不变量给「什么输入下必须成立、违反时具名报什么」；退化与「未测」的表示方式；生产入口与参数下发路径 | 开发节点照此实现，不看缺陷清单也能写对 |
| `06_文档订正意见.md` | 逐条：哪份文档哪一处、现在是不清／多说／与上级冲突／锚失效，**给出可直接替换的订正文本**（只写现行要怎样，不写过程） | 文档侧一并收口 |

## 本轮优先级（负责人指定）

**先做程序科学性与正向规格，门禁只记录不设计。** 门禁是给未来版本迭代用的，必须**依据已定稿的正向规格另行独立制作**；
本轮若先动门禁，等于让门禁去迁就尚未定稿的口径。
⇒ 门禁类缺陷照常登记（见 `⑤工程接线与门禁/01_缺陷清单.md` 与 `06_文档订正意见.md`），
但**不改门禁设计、不扩门禁判据**；`05_门禁/` 两份门禁件在本轮之后定稿。

## 二次核对的规程（先定规程再核对）

1. **一条缺陷要两件独立证据才算"确认"**：机器可复算的那件，加一次独立复核（复核路**禁止复用被审实现**，自写参照实现或闭式推导）。
2. **复核要判三态**：确认（原结论成立）／降级（现象在，后果或档位被高估）／推翻（现象不成立）。推翻必须给出反证式或原文。
3. **复核同时检查"修法"而不只检查"病"**：处方无效或有害的，标"勿照此改"并给正确方向（试点已抓出一次：某修法只把残差抬到容差下 1800 倍处，仍检不出）。
4. **复核要跑一遍"自校"**：涉及几何或数值实现的，自校必须含总量守恒这类能抓结构性错误的项（试点两次靠它抓到复核路自己的错）。
5. 只有"确认"与"降级后仍成立"的条目进最终工单清单；"推翻"的留在 `04_二次核对.md` 里作留痕，不进工单。
