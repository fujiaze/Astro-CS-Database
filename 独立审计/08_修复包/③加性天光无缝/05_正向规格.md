**定义**：经过 L7(一轮) 排异后，送入 L4 的观测数。

**正向规格**：
- **输入**：L1 输出的 `n_total`，
  - L7(一轮) 剔除各原因的计数
- **输出**：`n_retained = n_total - Σ(n_excluded_reason_i)`
- **值域**：`[0, n_total]`
- **门限**：`n_retained < min_samples` 导致 L4 返回 `INSUFFICIENT_DATA`
- **无效输入**：`n_retained > n_total` → 实现 bug，硬故障
- **对接点**：L4 入口检查，manifest 字段 `n_controls_included`

## 9 自校准栅栏（几何约束）

### 9.1 概念与目的

天光模型的节点密度受两个因素制约：
1. **物理可辨识性**：节点过密会导致模型过拟合噪声；
2. **计算资源**：样条求解器的复杂度随节点数立方增长。

因此需要一个**自适应节点生成回路**，根据数据分布（control 间距、信噪比、残差图景）动态调整节点数。该回路的核心是**自校准栅栏**机制：当相邻 control 的间距过大时自动插入候选节点，当间距过小或信息冗余时合并节点。

### 9.2 间距阈值函数 `h_min(h_avg)`

**公式**：
```math
h_min = max(α · h_avg, h_absolute_min)
```

其中：
- `h_avg` = 当前帧所有相邻 control 对的平均角距离（度）
- `α ∈ (0.5, 1.0)`，保守取值 `α = 0.7`
- `h_absolute_min` = 绝对下限，由最小 patch 尺度决定，约 `0.01°`（~36"，典型 CCD 像素尺度）

**五件套**：

| 组件 | 内容 |
|---|---|
| **值** | `α = 0.7`（比例因子）、`h_absolute_min = 0.01°` |
| **量纲** | `α` 无量纲，`h_absolute_min` 为角距离（度） |
| **来源档** | `docs/plugins/algorithms_phase2/11_upm.md §4.2`（节点密度约束） |
| **锚** | "节点间距不应小于 patch 尺度的 1/10，也不应大于平均间距的 70%" |
| **待确认** | `h_absolute_min` 需根据具体仪器的像素尺度标定 |

**具名约束**：
- 对每一对相邻 control `(c_i, c_j)`，计算其角距离 `h_ij = angular_distance(ra_i, dec_i, ra_j, dec_j)`
- 若 `h_ij > h_max_candidate`（见下一节），则在该对中点处生成一个**候选节点**
- 若 `h_ij < h_min`，则该对中的较新控制点（或按某种启发式选择）标记为**可合并**

### 9.3 候选节点生成上限 `h_max_candidate`

**公式**：
```math
h_max_candidate = β · h_avg
```

其中 `β ∈ (1.5, 3.0)`，保守取值 `β = 2.0`。

**五件套**：

| 组件 | 内容 |
|---|---|
| **值** | `β = 2.0` |
| **量纲** | 无量纲 |
| **来源档** | 性能 profile（需 benchmark 生成），目前保守取值 |
| **锚** | "超过平均间距两倍的 gaps 才值得插入新节点" |
| **待确认** | **是**，需根据目标硬件性能 Profile 确定（Linux x64 / Windows x64 可能不同） |

**具名约束**：
- 生成的候选节点数量不能超过 `max_nodes_absolute - K_current`（K_current 是当前节点数）
- 超过预算时，按 `Δχ² / degree_of_freedom` 评分，保留 top-K

### 9.4 自校准回路的输入/输出/失败行为

**输入**：
- `control_list`: 当前帧的所有 control（含 ra_deg/dec_deg、control_variance 等）
- `sky_model`: 当前迭代的样条模型（含节点系数）
- `config`: 配置（`α`, `β`, `max_nodes_absolute`）

**输出**：
- `return rc`: `OK` / `INVALID_CONFIG` / `EXCEEDED_BUDGET`
- `out node_positions`: 更新后的节点位置数组（含新增候选）
- `out provenance`: 节点增减的历史记录

**成功态**：`rc == OK`，`node_positions` 长度 ≤ `max_nodes_absolute`，所有节点有限且满足间距约束。

**失败态**：
| 错误码 | 触发条件 | `node_positions` 内容 |
|---|---|---|
| `INVALID_CONFIG` | `α ≥ 1.0` 或 `β ≤ α` 或 `max_nodes_absolute < 4` | 空 |
| `EXCEEDED_BUDGET` | 即使只保留 top-K 仍超出预算（极端情况） | `node_positions[:max_nodes_absolute]`（top-K） |

**精度约束**：
- `angular_distance` 计算使用球面三角法（Haversine 或 Vincenty），误差 ≤ `1e-8°`
- 同配置重复运行必须位精确相同（确定性排序 + 固定 seed）

**接线**：
- 调用者：L4 的主求解器循环（IRLS 每迭代 N 次后重新评估节点密度）
- 被调用者：`lib/algorithms/coverage/src/sky_spline.cpp::refine_nodes_adaptive()`

## 10 01–06 条判据的正向规格与注入必红

本点（缺陷④）共 **6** 条判据，本文给每一条的正向规格（第几条就列几条）。06 件不归我管，不讨论。

### 判据 01：天光模型平滑性与连续性

**缺陷描述（01）**：加性天光模型存在非物理的电平台阶（step discontinuity），破坏平滑性假设。

**正向约束**：
1. **模型形式**：采用薄板样条（thin-plate spline）或径向基函数（RBF），保证至少 C¹ 连续（一阶导数连续）。
2. **节点间距**：相邻节点角距离 `h ∈ [h_min, h_max]`，其中 `h_min = max(0.7 · h_avg, 0.01°)`，`h_max = 2.0 · h_avg`。
3. **相对电平台阶**：相邻 control 之间的相对差异 `rel_step = |Σ_bg(c_i) - Σ_bg(c_j)| / max(Σ_bg(c_i), Σ_bg(c_j), ε)`，要求 `rel_step ≤ 0.1`（10% 变化门槛，作为诊断而非强制门）。
4. **光滑正则化强度**：弯曲能权重 `λ_bend` 取自 `docs/science/PHASE2_UPM.md §6` 的经验范围 `[0.01, 0.1]`，默认 `λ_bend = 0.05`。

**五件套（相对电平台阶门限）**：
| 组件 | 内容 |
|---|---|
| **值** | `rel_step_max = 0.1`（10%） |
| **量纲** | 无量纲 |
| **来源档** | `ASTROCS_DESIGN.md §2.3`（平滑性要求）、`02 §3.2` |
| **锚** | "相邻 patch 间的面亮度相对变化不应超过 10%，否则提示未充分平滑" |
| **待确认** | 否（经验阈值，可作为诊断而非硬性剔除） |

**读取对象**：
- `sky_model.node_positions`、`sky_model.node_coefficients` → 计算每个 control 处的预测值 `Σ_bg(c)`
- 通过 Voronoi 或 k-d tree 找出空间邻接对 `(c_i, c_j)`
- 计算每对的 `rel_step`，统计 `count(rel_step > 0.1)` 与 `mean(rel_step)`

**期望方向**：
- 正常情况下，绝大多数（>90%）相邻对的 `rel_step ≤ 0.1`
- 若 `count(rel_step > 0.1) / n_pairs > 0.2`（20% 的跨度过大），则判红（模型不够平滑）
- 若 `mean(rel_step) > 0.2`，强烈提示问题

**注入必红**：
1. **构造台阶**：手动将某个节点的系数设为异常大值（例如 10×正常幅度），使相邻 `rel_step > 0.5`
2. **验证**：模型拟合后检查是否检测到该台阶并标记 `smoothness_violation = true`
3. **负例**：构造一个完全平滑的模型（均匀天光场），验证 `rel_step ≈ 0` 且无告警

### 判据 02：面积交叠一致性

**缺陷描述（01）**：patch 之间的面积交叠（overlap area）未被正确建模，导致同一物理区域被多次校正或漏校正。

**正向约束**：
1. **patch 边界定义**：每个 control 的 patch 由其 Voronoi 细胞（Voronoi cell）定义，即该 control 到最近邻居的所有点的集合。
2. **交叠面积计算**：相邻 control 的 Voronoi 边界是共享的线段（二维情况）或平面（三维），理论上交叠面积为 0（理想划分）。实际中由于离散采样，需要考虑"有效支撑域"的重叠。
3. **有效支撑比**：`support = sup_sum / n_valid`，其中 `sup_sum` 是 patch 内对最终估计有贡献的有效样本数，`n_valid` 是该 patch 内的总样本数。要求 `support ≥ 0.2`（规则 1）。
4. **覆盖率统计**：整幅图像的 `total_coverage = Σ_n_pixels_covered / n_image_pixels`，应接近 100%（允许边缘缺失）。

**五件套（支持度下限）**：
| 组件 | 内容 |
|---|---|
| **值** | `support_min = 0.2` |
| **量纲** | 无量纲（比例） |
| **来源档** | `docs/science/PHASE2_UPM.md §7a` 规则 1、`02 §7.1` |
| **锚** | "低于 20% 支撑比的 patch 不足以提供可靠的天光估计" |
| **待确认** | 否（与 02 一致） |

**读取对象**：
- `P2ControlObservation.support` → 逐观测的支持度
- `TilingResult.coverage_fraction` → tile 级的覆盖率
- `frame_manifest.n_controls_included` vs `n_controls_total` → 整体覆盖统计

**期望方向**：
- `mean(support)` 应 ≥ 0.5（中等偏高）
- `count(support < 0.2)` 的比例应 < 5%（剔除少量低支撑是合理的）
- `total_coverage` 应 ≥ 0.95（95% 以上图像被覆盖）

**注入必红**：
1. **构造低支撑**：人为将一个 patch 的有效样本数降为原来的 10%（`support = 0.1`）
2. **验证**：该观测应被剔除（reason=1）且计数进入 `rejection_counts.low_support`
3. **负例**：构造一个高支撑 patch（`support = 0.9`），验证其保留且权重正常

### 判据 03：天光模型数值稳定性

**缺陷描述（01）**：样条求解过程中出现数值不稳定（如矩阵病态、IRLS 发散、解溢出）。

**正向约束**：
1. **正则化强度**：弯曲能权重 `λ_bend` 应在 `[0.01, 0.1]` 范围内，避免欠正则化（过拟合）或过正则化（欠拟合）。
2. **条件数门限**：设计矩阵的条件数 `κ(A) ≤ 1e12`，否则视为秩亏（rank deficient）。
3. **IRLS 收敛标准**：相对残差变化率 `|χ²^(k) - χ²^(k-1)| / χ²^(k-1) ≤ 1e-8`，最大迭代次数 `max_iter = 50`。
4. **解的有界性**：节点系数 `|coefficient_i| ≤ 1000 ADU`，超过则视为溢出。

**五件套（条件数上限）**：
| 组件 | 内容 |
|---|---|
| **值** | `condition_number_max = 1e12` |
| **量纲** | 无量纲 |
| **来源档** | `docs/algorithms/PHASE2_UPM_IMPL.md §6.3`（数值稳定性） |
| **锚** | "条件数超过 1e12 意味着矩阵近乎奇异，Schur 消元会失去精度" |
| **待确认** | 否（标准数值分析实践） |

**读取对象**：
- `sky_model.condition_number`（若求解器输出）
- `convergence_stats.iterations`、`convergence_status`
- `sky_model.chi2_red` 及其 `chi2_defined` 标志

**期望方向**：
- 正常情况下，`condition_number` 应 ≤ `1e8`（良好条件）
- `convergence_status == "OK"` 且 `iterations < 30`（快速收敛）
- `chi2_red` 有限且处于合理范围 `[0.5, 5.0]`

**注入必红**：
1. **构造病态矩阵**：将所有 control 的位置设为几乎共线（或极密集的 cluster），使设计矩阵近似奇异
2. **验证**：求解器应返回 `RANK_DEFICIENT` 错误码，`chi2_red = null` + `chi2_defined = 0`
3. **负例**：构造一个良条件的数据集（均匀分布的 control），验证求解器成功收敛

### 判据 04：area_weight 与 control_ivar 的分配逻辑

**缺陷描述（01）**：面积加权（area_weight）与 `control_ivar` 的结合方式不明确，导致同一物理区域可能被过度代表或代表不足。

**正向约束**：
1. **科学权重源**：`control_ivar = 1 / control_variance` 是唯一科学权重源，任何面积加权都必须基于此。
2. **两级权重结构**：
   - 第一级：`weight_abs = quality_factor × control_ivar`（绝对权重，单位 `1/ADU²`）
   - 第二级：`weight_norm = weight_abs / Σ_j weight_abs,j`（归一份额，用于 UPM 内部的单次迭代分母）
3. **对外发布口径**：所有产品路径（manifest、JSON）中发布的权重一律取**绝对式**（`weight_abs`），不发布归一份额。
4. **禁止口径选择开关**：实现中不得存在任何 `weight_mode` / `use_area_weight_override` 等形态的选项。

**五件套（quality_factor 初始值）**：
| 组件 | 内容 |
|---|---|
| **值** | `quality_factor_initial = 0.5` |
| **量纲** | 无量纲（乘性因子） |
| **来源档** | `docs/science/PHASE2_UPM.md §5`（两级权重性质）、`02 §2.1` |
| **锚** | "无质量 flags 时，quality_factor = 0.5 作为基准权重；flags 会根据问题类型下调" |
| **待确认** | 否（与 02 一致） |

**读取对象**：
- `P2ControlObservation.control_ivar` → 原始科学权重
- `P2ControlObservation.quality_flags` → 解码为 `quality_factor`
- `TilingResult` 的 provenance 中是否记录了 `weight_normalized = false`

**期望方向**：
- `weight_abs` 的值域应为 `[0, ∞)`，零权重对应于退化观测
- `weight_norm` 仅在求解器内部使用，不出现在产品中
- manifest 中的权重字段（若有）必须明确标注是 `weight_abs` 口径

**注入必红**：
1. **构造零权重**：设置 `control_variance` 非有限 ⇒ `control_ivar = 0` ⇒ `weight_abs = 0`
2. **验证**：该观测应完全不参与样条求解（L4 内部跳过该行），并在 provenance 中标记 `zero_weight_reason = "low_ivar"`
3. **负例**：构造一个高 `control_ivar` 的观测（小方差），验证其获得高权重且对模型影响大

### 判据 05：tiled product 的物理正确性

**缺陷描述（01）**：tile 写出的天光校正版（sky_subtracted_value）与模型预测（sky_model_value）不一致，或减去错误的背景层。

**正向约束**：
1. **减法关系**：`sky_subtracted_value = value - sky_model_value`，其中 `value` 是原始的 patch median（background-clean），`sky_model_value` 是该 control 处天光模型的预测。
2. **标度一致性**：两者必须在同一标度下相减（都是 ADU 或都是 `ADU·sr⁻¹`），不允许混用。
3. **覆盖度声明**：`coverage_fraction` 必须反映实际参与校正的像素占比，不能虚报。
4. ** provenance 记录**：若因 `sigma_floor` 保护而钳位了 `sky_model_value`，必须记录 `applied_sigma_floor = true`。

**五件套（sky_model_value 的地板保护）**：
| 组件 | 内容 |
|---|---|
| **值** | `sigma_bg_floor = 1.0 ADU` |
| **量纲** | ADU（σ 口径） |
| **来源档** | `docs/science/PHASE2_UPM.md §8`（退化面）、`02 §1.4` |
| **锚** | "天光模型的标准差不能为零，否则样条退化为刚性插值" |
| **待确认** | 否（确保可辨识性的物理必要量） |

**读取对象**：
- `TilingResult.sky_subtracted_value`、`TilingResult.sky_model_value`
- `TilingResult.provenance.applied_sigma_floor`
- `TilingResult.coverage_fraction`、`n_pixels_used`

**期望方向**：
- `sky_subtracted_value` 应与 `value` 同量纲（ADU），可正可负
- `sky_model_value` 应≥ `sigma_bg_floor = 1.0 ADU`（若曾应用地板保护）
- `coverage_fraction` 应在 `[0.5, 1.0]` 之间（极端低的覆盖率提示退化）

**注入必红**：
1. **构造不匹配**：手动让 `sky_subtracted_value ≠ value - sky_model_value`（故意设错）
2. **验证**：sanity check 应捕获该不一致并判红（`inconsistency_violation = true`）
3. **负例**：构造一个完美符合关系的 product，验证 sanity check 通过

### 判据 06：留痕残留检测的完备性

**缺陷描述（01）**：3σ gate 未覆盖全部留痕残留场景，某些高对比度天体或密集星场中存在漏检。

**正向约束**：
1. **3σ gate 公式**：`|pixel_residue| > 3.0 × σ_bg` 判定为留痕残留，剔除原因码 5。
2. **簇大小阈值**：单个或少量（≤ 3 个）像素的 3σ 超标不触发整体剔除（仅标记 provenance），≥ 4 个像素的连通簇才整体剔除观测。
3. **σ_bg 的来源**：使用 L4 输出的 `sky_model.sigma_bg_estimate`（样条拟合得到的全局噪声估计），而非单 pixel 的局部噪声。
4. **像素残差的定义**：`pixel_residue = pixel_intensity - sky_model.predict(pixel_position)`，即观测值减去天光模型预测。

**五件套（簇大小阈值）**：
| 组件 | 内容 |
|---|---|
| **值** | `min_cluster_size = 3` |
| **量纲** | 计数（pixel 数） |
| **来源档** | `docs/science/REJECTION.md §5.2`（留痕图景）、`02 §7.2` |
| **锚** | "孤立或少量像素的异常不足以构成留痕模式" |
| **待确认** | 否（与 REJECTION.md 一致） |

**读取对象**：
- `pixel_residues[y,x]`（像素级残差图）
- `TilingResult.reason_code`（观测级剔除原因）
- `rejection_counts.trail_residue`（累积计数）

**期望方向**：
- `count(|pixel_residue| > 3σ)` 的比例应较低（< 5% 的像素触发 3σ gate）
- 触发 reason=5 的观测数占总观测数的比例应 < 10%（留痕是少数）
- 对于已知的人造留痕注入，召回率应 ≥ 90%

**注入必红**：
1. **人造留痕**：在模拟数据中注入一条人工留痕（沿某条路径叠加高对比度信号）
2. **验证**：该路径上的 control 应被 reason=5 剔除，且 `n_trail_residue` 计数正确
3. **负例**：构造一个无留痕的真实数据（均匀星场），验证没有误删（reason=5 计数为 0）
