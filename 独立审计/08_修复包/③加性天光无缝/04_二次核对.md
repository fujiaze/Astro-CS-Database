## 1. 复核口径

| 项 | 规定 |
|---|---|
| 独立性 | 复核者**不得**以本包 `01`/`02`/`03` 为取证来源；从被审基线（`c8f64e9a`）与权威链（`ASTROCS_DESIGN.md` → `docs/science/`、`docs/algorithms/`、`docs/plugins/`、`docs/contracts/`）重新取到同一事实，才算确认 |
| 盲复算 | 已成稿的判定（含通读批次自己的定级、第②层复核的"确认"）**只当线索**；已判条目须盲复算后再比对，不得整批照抄 |
| 三态定义 | `确认` = 独立取证得到同一事实与同一方向；`降级` = 事实成立但档位/影响范围/方向依据不足（须写明缺哪一跳）；`推翻` = 事实不成立或机制描述错误（须写反证与位点） |
| 方向必核 | 每条"偏红/偏绿"的判词须独立复推一次方向；方向判错即整条推翻 |
| 档位重定 | 档位以复核者能写出的最长触发链为准，不受本包原档约束；写不出到产品字节的链 ⇒ 不得判 S1 |
| 单条取证上限 | 每条 ≤ 10 次工具调用；超限即登记"取证未收敛"并缩窄到该条的最小可判子集，不得无限展开 |
| 落盘节奏 | 每 5 条落一次盘；补派按**已落盘行的行集差**，不看本件的队首 |
| 纪律 | 只读被审仓库；零 git 写、零 `git config` 写；不跑构建/ctest/`eng/**`；不在仓库内落文件；只写本点独占目录 |
| 不得整批确认 | 一次复核批的结论若全部为 `确认`，须附每条的独立取证位点清单，否则该批作废重做（历史教训：门读数 ≠ 精读） |

## 5. 复核者必须知道的三件方法论事项（本包形成过程中的实测教训）

1. **成稿的自我订正优先于成稿正文**：`01` D-26 的机制描述（"回落到整张网格范围外推并正常返回 0"）来自逐跳复核后的订正版本，原始 finding 的表述是"未命中的格返回 0.0"。复核时若只读 finding 正文会核到**已作废的机制**，从而误判为推翻。
2. **"两处同名不同物"是本点最常见的假阳源**：`civar`（稀疏控制点）与 `ivar`（稠密背景面）、Phase2 `min_samples = 5` 与 Phase1 `min_samples = 64`、`data_type` 与 `value_dtype`、`排除自身`（参考面构造）与 `排除自身`（方差传播的分母）——四组都已被判为**两个适用域而非同名异值冲突**。复核者立新案前必须先做这一层消歧。
3. **一条缺陷可能同时是"门的正确行为"**：`02` §3.2 的 `n <= 4` 与正本 `n == 4` 观测等价、§3.4 的 `rc = 0 + status = INVALID_INPUT` 由生产侧 hard fail 承载、§3.1 的 minmax 式才是正确样板 —— 这三处都曾被视为缺陷而核后不成立。复核者若在这三处立新案，须给出"等价性论证失效"的具体输入。
