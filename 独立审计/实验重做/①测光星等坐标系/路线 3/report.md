#### B. 实验腿设计

**假说**：H0: FOV 缓冲 1.2 与钳位界 1.0/10.0 对 Gaia 查询成本与定标星稳定性的影响是可量化的，且存在一个"足够大但不浪费"的最优区间。

**实验方案**（纯 Python + numpy，固定 seed）：

```python
# code/T1_fov_clamping.py
import numpy as np
from scipy.optimize import minimize_scalar

def simulate_gaia_query_cost(fov_deg, star_density=1e4):
    """
    模拟不同 FOV 下 Gaia 查询的星数与成本。
    假设星密度 ~1e4 颗/deg²（拥挤场上限）。
    """
    area = np.pi * (fov_deg/2)**2  # 球冠面积近似
    n_stars = area * star_density
    # 查询成本正比于星数（简化模型）
    return n_stars

def analyze_fov_sensitivity():
    fov_range = np.linspace(0.1, 30, 100)
    costs = [simulate_gaia_query_cost(f) for f in fov_range]
    
    # 寻找"临界点"：星数 < 2000（早停阈值）对应的最大 FOV
    threshold = 2000
    max_safe_fov = fov_range[np.where(np.array(costs) <= threshold)[0][-1]]
    
    print(f"早停阈值 {threshold} 对应的最大安全 FOV: {max_safe_fov:.2f} deg")
    print(f"当前钳位界 10.0 deg 是安全值的 {10.0/max_safe_fov:.1f}x")
    
    # 分析缓冲 1.2 的影响
    fov_under_estimate = 0.5  # 假设真值 0.5 度被低估
    fov_estimated = fov_under_estimate * 1.2
    cost_ratio = simulate_gaia_query_cost(fov_estimated) / simulate_gaia_query_cost(fov_under_estimate)
    
    print(f"低估时缓冲 1.2 使成本增加到 {cost_ratio:.2f}x")

if __name__ == "__main__":
    np.random.seed(42)
    analyze_fov_sensitivity()
```

#### C. 理论推导腿

02 中是否有 FOV 计算公式？查阅 `02_已确立的算法与验证程序.md`：

- **式-N-15**（据①路引用）："两条入口同一 FOV 公式"已核数值同口径，但**未给这三个数的推导**。
- FOV 计算公式应为：`fov_radius_deg = pixel_scale_deg × sqrt(W² + H²) / 2 × 1.2`

**数学分析**：
- `pixel_scale_deg × sqrt(W² + H²) / 2` 是几何计算的半对角线角尺度

**结论**：理论推导腿**只能支撑几何部分**，缓冲 1.2 与钳位界 1.0/10.0 属于**工程安全边界**，应归类为"项目约定值"。

**关键发现**：

| 测量项 | 实测值 | 解读 |
|--------|--------|------|
| 早停阈值 2000 颗对应的最大安全 FOV | **0.40 deg** | 远低于钳位界 10.0 deg |
| 钳位界 10.0 deg 是安全值的倍数 | **24.9x** | 非常宽松 |
| 缓冲 1.2 在 FOV 低估 20% 时的成本增加 | **1.44x (44%)** | 平方放大效应 |
| 星数绝对增量（FOV=0.5→0.6 deg） | **+864 颗** | 可接受范围 |

**结论**：
1. FOV 半径与星数呈**平方关系**（area ∝ fov²），缓冲因子会被平方放大。
2. 缓冲 1.2 在 FOV 低估 20% 时会使星数增加约 44%（1.2² = 1.44）。
3. 对于 FOV > 8 deg 的场景，10.0 度钳位界开始生效，防止查询过大。
4. **10.0 deg 的钳位界过于宽松**——早停阈 2000 对应的安全 FOV 仅 0.40 deg，10.0 是其 25 倍。这意味着只有极小 FOV（<0.4 deg）的天区会触发早停，大多数天区会直接到 10 度上限。

**订正意见**：
- `1.2` 作为缓冲因子是**合理的工程裕量**（对应±20% WCS 解算误差）。
- `1.0 deg` 作为下限**合理**——小于 1 度时星数不足可能导致定标不稳定。
- `10.0 deg` 作为上限**过于保守**，建议改为更紧的值如`3.0 deg`或根据早停阈动态调整。

**诚实边界**：
- 本模型假设星密度恒定为 1e4 颗/deg²，实际天区会有显著差异（高银纬可能低 1-2 个数量级）。
- 真实 WCS 解算误差分布需从历史数据反推，才能确定最优缓冲值。

```python
# code/T2_adaptive_magnitude.py
import numpy as np

def simulate_gaia_census(mag_limit, sky_area_deg2):
    """
    模拟 Gaia 在给定星等极限下的星数。
    基于 Gaia 星表累积分布的经验近似。
    """
    # 经验公式：N(m) ≈ N0 × 10^(0.3*(m - m0))
    # Gaia G=20.7 时约 16 亿颗星，sky_area 为平方度
    N0 = 1.6e9
    m0 = 20.7
    total_sky = 41253  # 全天平方度
    
    # 归一化到天区比例
    fraction = sky_area_deg2 / total_sky
    # 星等极限对应的星数比例
    mag_factor = 10**(0.3 * (mag_limit - m0))
    
    return N0 * fraction * mag_factor

def analyze_adaptive_strategy(sky_area=100):
    """
    分析自适应阶梯策略的效率。
    """
    mag_steps = [12, 13, 14, 15, 16]
    early_stop_threshold = 2000
    
    print(f"天区面积：{sky_area} deg²")
    print("="*60)
    
    total_queries = 0
    cumulative_stars = 0
    
    for i, mag in enumerate(mag_steps):
        n_stars = simulate_gaia_census(mag, sky_area)
        cumulative_stars += n_stars
        
        # 早停判断
        if n_stars >= early_stop_threshold or i == len(mag_steps) - 1:
            print(f"Step {i}: mag<{mag}, n_stars={n_stars:.0f} [{'EARLY STOP' if n_stars >= early_stop_threshold else 'LAST STEP'}]")
            total_queries = i + 1
            break
        
        print(f"Step {i}: mag<{mag}, n_stars={n_stars:.0f}")
    
    print("="*60)
    print(f"总查询次数：{total_queries}/5")
    print(f"最终累积星数：{cumulative_stars:.0f}")
    
    # 对比：若只用单一星等极限
    mag_16_only = simulate_gaia_census(16, sky_area)
    print(f"\n若直接使用 mag<16 单档查询：n_stars={mag_16_only:.0f}")
    print(f"自适应策略节省星数比例：{(mag_16_only-cumulative_stars)/mag_16_only*100:.1f}%")

if __name__ == "__main__":
    np.random.seed(42)
    analyze_adaptive_strategy(sky_area=100)  # 假设典型 FOV 覆盖 100 deg²
```

- 但代码逻辑是**逐档累加**而非**取最大一档**，导致累积星数是各档之和
- **正确做法应为**：第一档 mag<12 已达 9,521 颗→直接早停，不再查后续档位

**订正意见**：
自适应阶梯查询的正确语义应是**顺序试探、首次达标即早停**，而不是"累加各档星数"。建议修改策略为：

```text
Step 0: 查询 mag<12 → n=9,521 ≥ 2000 ✓ → 早停，使用这批星
```

而非当前的"错误理解"：
```text
Step 0: 查询 mag<12 → n=9,521
Step 1: 查询 mag<13 → n=18,996 (累计 28,517)
...
累积所有档 → 292,935 颗（严重浪费）
```

**建议登记方式**：
将自适应阶梯描述修正为"顺序试探、首次达标即止"的语义，早停阈 2000 对多数天区会在第一步（mag<12）即触发。

**诚实边界**：
- 本模型假设星密度恒定为~95 颗/deg²@mag<12，实际天区差异大。
- 对于高银纬或特殊天区，mag<12 可能不足 2000 颗，此时才会进入下一档。

**查询策略的数学本质**：
- 星等每增加 1 mag，星数约增加 10^0.3 ≈ 2.512 倍
- 采用自适应阶梯意味着**按需索取**：如果低星等档已达早停阈，就不必再搜更暗的星
- **理论推导只能证明"自适应比暴力扫描更高效"**，但具体档位值仍需经验调优

**早停阈 2000 的理论依据分析**：
- Gaia ConeSearch API 的性能瓶颈通常在返回星数 > 几千时显著下降
- 2000 颗星的匹配与坐标反投影计算量在合理范围内（秒级）
- 超过 2000 颗星时，后续增加的星点对 WCS 解算的贡献边际递减

**结论**：早停阈 2000 是**性能工程值**，不是科学常数。

### F1：UPM 背景平面进 SNR 的方差预算

**交换的量**：UPM 建立的连续天光参考平面如何贡献到逐像素的方差σ_F 中？

**问题**：
- UPM 拟合的是加性天光偏差 b(x,y)，其本身有不确定性 σ_b(x,y)
- 该不确定度应如何计入最终 SNR 计算中的噪声项？

**假说**：H0: UPM 背景平面的方差贡献应作为**帧间系统差的代理项**加入 SNR 的方差预算。

**理论推导框架**：

根据噪声模型分解：
```text
σ_F² = σ_src² + σ_sky² + σ_read² + σ_UPM²
```

其中 σ_UPM²是 UPM 背景估计的不确定度传播到信号层的部分。

UPM 通过稀疏背景采样点拟合背景平面，其不确定度来源于：
1. 采样点的测量噪声（泊松噪声 + 读出噪声）
2. 拟合模型的欠定性（多项式阶数不足或过高）
3. 真实信号污染（采样点被源泄漏）

**诚实边界**：
- 本模块需设计纯 Python+numpy 实验量化 σ_UPM 的量级
- 实际 background mask 的泄漏（源污染）会显著增大σ_UPM，需从数据中估计

### F2：Drizzle 权重进测光拟合的有效暴露度
