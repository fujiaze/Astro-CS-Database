**(6) 普查自测的三例逐条判定**

`eng/ci/failclosed_survey.py:197-232`：

- G1（`:201-203`）`("G1", "真实注册表普查可跑通且无假绿", not good["failures"] and good["units"] > 50, …)`
  ——两个合取各有问题：`not good["failures"]` 是**拿普查自己的 0 红当自己的正例**（循环自证，按记忆 ⑩/⑫ 属"验证与真值同源"），
  `units > 50` 是**无来源魔数**。我对"抄来的历史观测量"这一说法**不采信**：
  该文件与归档表同在 `25c8227d` 一次落地，当时实算观测量是 **230**（不是 50），
  50 从未等于任何已知读数 ⇒ 它是随手数，不是抄来的测量值。区别对修法有影响：
  若为"抄来的观测量"，修法是接回真值；实为"无来源魔数"，修法是**改成等于实算值或单调棘轮**（成稿改法恰好覆盖，故不改判级）。
  可证的不判别力：注册表被裁到 51 单元（例如 step 展开逻辑回归、聚合项被拆平），G1 仍绿。
- G2（`:204-214`）合成两单元注册表（一个有 outputs、一个空且非 waivable），断言两行 `ok` 皆真
  ——即**"通过普查"在自测里也是纯元数据谓词**：T-OK 的 `outputs=["run/x.json"]` 与 T-BAD 的 `outputs=[]` 是全部变量，
  两者的 `command` 都是 `["python3","-c","pass"]` 且从不执行。
- N1（`:215-222`）`RC.evidence_verdict = lambda *a, **k: None  # 恒绿注入` → 断言 `len(res2["failures"]) == 2`
  ——全普查唯一的负例，注入点是**被普查者与共享受体函数同一个对象**（`evidence_verdict`）。
  它证明的是"聚合逻辑会把恒绿抓成假绿"，**不证明任何一门有判别力**；
  且按记忆 批判据④（负例须落在该门自己的豁免分支里）衡量：`evidence_verdict` 的三条豁免分支
  （`SILENT_OK_UNITS` 名单、`waivable`、`path_exists` 的 glob 分支）无一条被 N1 触及——
  它把函数整个替换掉，绕过了所有分支。⇒ **普查的自测不满足本仓自己的负例纪律。**

**(7) 该普查要变成"有证据资格"需要具备什么**（我给的设计要求，供 AUD-502 直接引用）

1. **对象必须是被普查的门**：每个单元一条注入负例——构造"该门所判对象的最小缺陷料"，**真跑该门命令**（`subprocess`），断言 rc≠0；
   门的 `--self-test` 若只测自己，则该负例必须由普查调用门的 `--fault-inject <类型>`，而不是调用一个共享函数。
2. **负例必须落在该门自己的豁免/兜底分支里**（记忆 批判据④）：每条判据的红要能穿过它自己的 `if not X: return PASS`；
   否则记为"该门 fail-open 面未覆盖"，不得计入"通过"。
3. **面的归属与 runner 同源**：普查用 `run_checks.index_steps()`（含继承）取单元，并断言"普查面 == runner 强制面"；
   今日 42 个不一致单元即为该项的验收负例。
4. **单元数锚必须是实算值**：`units == len(index_steps(registry))`，或 `>=` 登记高水位并只增不减并留痕；
   `not failures` 不得同时充当"跑通"与"无假绿"两件事——拆成 G-跑通（结构断言）与 G-判别力（每条负例逐条点名）。
5. **名号如实**：门与两份文档中的"全门禁 fail-closed 普查"若仍只测 runner 证据面，须改名为
   "runner 证据管道 fail-closed 契约普查"（成稿 A-03 改法①，与我的取证一致），并把它在 `03_GATES.md §3` 的
   "P0／阻塞合并"含义限定为"runner 契约红"，不再被读作"全部门禁判别力已核"。
6. **回放 vs 现算必须一致**（记忆 批判据⑩）：加一条门核对
   `artifacts/evidence/**/FAILCLOSED_SURVEY.md` 的 units/entries 与 `run/ci/failclosed-survey/survey.json` 现算值相等，不等即红；
   或把跟踪件改成每次 CI 由 `--md-out` 覆写（并显式登记 `mutates_workspace`）。

## 对门禁重建设计（AUD-502）的输入

把 W1/W2 转成设计约束（每条都给出"来自哪条取证"与"怎样算满足"，可直接抄进 AUD-502）：

**D1 入口唯一化**

**D2 空集守卫（把"零有效执行⇒红"写成规范，再写成一份实现）**

- 定义要写死：**有效执行 = 该单元真跑了命令并给出 PASS/FAIL**；`SKIPPED(platform)`、`SKIPPED(waivable)`、
  `SKIPPED(optional_input)`、`PASS(reused_fingerprint)` 一律不计为有效执行（今天 `run_checks.py:136-138` 的
  `FAIL_VERDICTS` 恰好排除全部 SKIP，`run.py:1236` 也排除，两侧都缺"有效执行数"这个量）。
- 单一实现点：把守卫放进 `gate_common.py`/`declared_inputs.py` 同层共享模块，两入口都调用它（同 `declared_inputs.py` 的做法）；
  禁止在两文件各写一份三分支。
- **把 W4-A3 的适用范围写全**：现有两条注释只分别覆盖"同一 77 退出码"（`run_checks.py:96-97`）与
  "同一 declared_inputs 情形"（`run.py:93-95`），**未覆盖本次出事的三类判定**

  "两入口对同一注入情形给出同一 verdict＋同一 rc"（正例：同一步在两侧都跑 `--platform` 对翻；负例：注入平台不符 ⇒ 两侧必同红）。
- SKIP 语义正名：`run.py:92` 不得再把平台跳过塌成 `SKIPPED(waivable)`（两因必须可分）；
  rc=0 的非 PASS 态（现 `FATDUCK_PENDING`，`run.py:1514`）要么 rc≠0，要么在 CI 面上禁止出现，二选一并写进 `03_GATES.md §5`。

  `--all --profile linux-main` 在 Windows 上 rc=1（今天 rc=0 的风险面就是这类组合）。
- 副作用一并收口：入口的"只查询"模式（`--explain`/`--plan-only`）目前也会经 `write_per_step_result`
  （`run_checks.py:600`）落盘，且 `run.py` 默认写 `artifacts/ci/<sha>/`（跟踪目录）——
  **重设计必须提供一条零写盘的查询面**，否则只读审查节点永远只能读码、拿不到 rc，第②层复核算永远停在"待证"。

**D3 注册表内部一致性（platform × profiles）**
- 事实前提：`CHK-ALGO-WIRING` 同时登记 `platform: linux` 与 `profiles: [..., windows-main]`、`waivable: false` ⇒
  Windows CI job 按 `run.py:625-626 + 890-902 + 111-113` 必判 FAIL(prerequisite)/rc=1。
- 约束：新增注册表校验判据（住 `validate_registry.py`，R 系列）——
