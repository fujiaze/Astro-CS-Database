### CR-18-1 · 帧级聚合里的"目录计数一致性门"是恒真门，没有证据资格
- 轴：R（主轴）/ D
- 位点：`lib/algorithms/noise_snr/wrapper_phase1/snr_frame_science.cpp:151-161`
  ```
  for (std::size_t i = 0; i < sources.size(); ++i) {
    if (std::isfinite(out.snr_f[i])) { out.local_snr[i] = out.snr_f[i] / med; ++indices_used; }
  }
  if (indices_used != out.n_used) { out.reason = "internal catalogue count mismatch"; ... }
  ```
- 上位依据：`AGENTS.md §5`「判据必须非退化：…恒真门没有证据资格」、`AGENTS.md §9`
  「对『看起来通过』的结果保持怀疑：空断言…都算未完成」。条文面对该门零提及
  （`git grep -n "internal catalogue count mismatch" -- docs` 0 命中）。
- 现状：`out.snr_f[i]` 只在 :128 `if (!rok[i]) continue;` 之后被写入，写入值是
  `rn_snr[i] = r.snr_optimal`，而 `r.snr_optimal` 已在 :61 经
  `std::isfinite(out->snr_optimal) && out->snr_optimal > 0.0` 过滤；其余槽位保持 :81 的
  NaN。`out.n_used` = :133 `used_snr.size()`，而 `used_snr` 与 `rok` 在同一升序循环里
  1:1 增长 ⇒ `indices_used == n_used` 是**代数恒等式**，不存在任何输入能使其不等。
- 差在哪：门的方向被构造钉死为永绿：它不能捕获它声称要捕获的东西（目录行与 SNR 槽错位），
  因为两者由同一 `rok[]` 决定；真发生错位（例如 compact 循环被改成非升序）时它仍绿。
- 后果：不产错值（本帧数值不受影响），但 `p1_snr.json` 的 `n_snr_catalogue` 与逐源数组
  长度一致性主张（`DATA_SEMANTICS:579-580`）实际上**没有任何机器门**在把——读代码的人
  会以为有。
- 定级：S3（写不出"产物错值或对外主张不成立"的触发路径：值面由 :133 与 :128 同源，
  本就一致；缺的是门的证据资格，不是数值）
- 怎么算修好：把它改成能红的形式——例如断言「`out.snr_f.size() == out.n_input` ∧
  逐源 `local_snr` 与 `snr_f` 的有限位掩码逐位相等」，并在 :115 并行区与 :126 compact
  区之间做一次真实交叉核对（对每个 i：`rok[i]` ⇔ `isfinite(snr_f[i])`），补一条
  注入负例（人为翻转一位 rok）证明判红；同时把该门的口径登记进 `docs/contracts/DATA_SEMANTICS.md` §13.4。
- 置信：CONFIRMED（逐跳读完 :81/:110-121/:126-133/:151-156 的写入-读取集合，代数上必等）
