## 2. 可机械化判据提案：怎么判"退役标注不合规"

### 2.0 先说清现状与口径冲突（这是提案的前提）

仓库**已有**一套统一注释块与机器判据：`eng/ci/check_retired_code.py`（门 `CHK-RETIRED-CODE` ＋ `CHK-RETIRED-CODE-SELFTEST`，ID 出处 `eng/ci/checks.json`），唯一格式逐字为 6 个 token：

```text
RETIRED-CODE-RETAINED + WHAT: + WHY-KEPT: + STATUS: + EXIT: + AUTHORITY:
```

实测本基线：全仓跟踪的 `.c/.cpp/.cc/.cxx/.h/.hpp/.py` 共 **1950** 个文件里，`RETIRED-CODE-RETAINED` 块 **12** 个，其中 **11 个六 token 齐备且各字段非空（合规）**，1 个不合规——而那 1 个是**本代理近似实现的假阳性**（`eng/tests/unit/v6_p3_proj/sin_roundtrip_gate.py:12-13`：Python docstring 里以 `**` 起首的行被我的"注释行"规则误判为注释块；该块实际不是注释块）。R2 候选（前 40 行有横幅 token 而无 RETAINED 块）**0** 条。

**冲突点（决定新判据怎么写）**：标准 04 §4:39 要求退役块标注"退役**原因**、**替代实现**与**日期口径**"三件；而 `ENGINEERING_SPEC.md §2`／`check_retired_code.py` 的六字段里 **只有原因（WHY-KEPT），没有"替代实现"专字段，也没有"日期"字段**。所以：

- "缺原因"→ 现网**已可判**（R3 的 `WHY-KEPT` 空/缺即违规）；
- "缺替代"→ 现网**不可判**（无任何门检查）；
- "缺日期口径"→ 现网**不可判**，且与负责人已裁的文档口径"文档内禁日期与历史"方向相反 ⇒ 这一维**不能**用"必须写绝对日期"来实现，否则新增判据与既有裁决打架。本提案把它改成"必须给出**可解析的时点凭据**"（条款号或裁决号也算），把口径冲突留给负责人裁（见 §2.4）。

结论：**不新造第二套块格式**。做法是给现有六字段块加两维扩展字段，并把三形态判据挂在同一门上——避免"同一事实两套写法"这种本清单反复出现的根因。

### 2.1 扩展字段（在既有 6 token 之后追加，向后兼容）

```text
// ── RETIRED-CODE-RETAINED (ENGINEERING_SPEC §2 保留则注释) ─────────────
// WHAT:       …            （现有，必填）
// WHY-KEPT:   …            （现有，必填）
// STATUS:     …            （现有，必填）
// EXIT:       …            （现有，必填）
// AUTHORITY:  …            （现有，必填）
// REPLACED-BY: <仓库内可解析锚>   （新：替代实现；无替代时逐字写 NONE + 理由）
// AS-OF:      <条款号|裁决号|commit>（新：时点凭据；禁裸日期字符串）
```

`REPLACED-BY` 的合法值必须**可机械解析**：`lib/**` 或 `eng/**` 的路径（可带 `:行`）、`SCI-*`/`ALG-*`/`DATA-*`/`API-*` 锚号、`module_ports.registry.json` 的模块 ID，或字面 `NONE`。
`AS-OF` 的合法值：`ASTROCS_DESIGN.md §x.y` 式条款号、`ENGINEERING_SPEC.md §x` 式条款号、负责人裁决号（如 `PSFSW-RETIRE-01`）、或 40 位 commit SHA；**明确禁止** `2026-09-25` 这类裸日期（现网 10 条退役注释全是裸日期形态，见 §2.5 的存量清单）。

## 4. 本清单三条最重要的结论

1. **墓碑注释正在给符号可解析判据"喂活"**。`CON-DOC-SYMBOLS` 用 `lib/**.h` 全文正则判文档符号是否存在，而 5 枚已撤下符号在 `lib/**/*.h` 里的唯一存活文本就是退役注释本身 ⇒ 门绿，但被核的对象其实已经没了。这是一处 **fail-open**：一条注释满足了一个存在性判据。修它的方式不是删注释（会立刻红），而是 §2 的批 A 同批处理＋把该门的语料从"头文件全文"收窄为"头文件声明面"（去掉注释后再匹配）。
2. **"不被任何 target 编译"这一档最危险**，本清单 54 条落在该档，其中至少 5 组其实有运行期消费者（`module_loader` 2 件、`eng/tests/{backend,cpu,abi}` 34 TU 由 pytest 现场 `cc`）。字面档名会把它们指向删除；正确动作是接进构建面或如实登记为夹具。工包给的四档词表在这类对象上不够用，CSV 里有 2 条我显式标为 `非四档项`（行 89：`star_detector.cpp` 在生产 target 而 `orchestrator.h` 属 ALONE 闭包的双档冲突；行 90：`wrapper_phase1/` 四目录在生产 target 且被调用，仅因目录命名违规入表），宁可多写一句也不写错档。
3. **同一能力的第二套事实源是主要成因**：第二套构建面（13 个 Makefile 对 CMake 唯一事实源）、第二套 `PipelineFrame`（`aio_pipeline_engine.cpp`）、第二份同名实现（`calibration/cpp` 对 `calibration/src`）、第二套 ID 命名空间（`astrocs.phase3.resample` 对 `astrocs.p3.resample`）、第二份退役标注格式（单行 `/* RETIRED 日期 */` 对六字段块）。标准 04 §3:33 与 §4:39 的"只一份"如果机械化，本清单里过半条目会自动消失。
