### CR-06-01 · 生产把空间项默认阶定成 order 2，而权威链三处分别要求 0（验收前）与 1（登记默认）
- 轴：**C（主）+ D**
- 位点：`spatial_gain.h:80` `  int order_requested = 0;      // 0=关闭（逐位退化）/1/2；>2 被钳到 2` 与 `spatial_gain.cpp:327` `    const int order_req = std::min(p.order_requested, 2);`
- 上位依据：`实验/photometric-magnitude/docs/p1-spatial-gain.md` §5.2:434「`photometry.fit.spatial_gain_order`（默认 **1**；0=关闭）」；§6:450「**【最高优先，阻塞实现】**…**在 `F_instr` 换成 PSF 稳健口径之前，不建议在生产上开启空间增益**」；§6:454「(c) 通过 (b) 之前，`spatial_gain_order` 默认保持 **0**（= 现行 FIX-P1 行为）」；§3.4:217-218「order 2…**在真实数据上分半不可复现（corr 0.929 / p10 0.41）、在聚集星分布下直接崩掉（24% 形状误差）**；**order 1 是稳健的甜点**」；§3.5:233 order 2 在聚集 N=100 时 13.18%「比不做还差」。
- 现状：生产回退值在 `lib/infrastructure/scheduler/src/module_adapters.cpp:5471` `  constexpr int kDefaultSpatialGainOrder = 2;`，:5473-5476 仅当配置里真有 `photometry.fit.spatial_gain_order` 整数键时才覆盖；而 `git grep -rn "spatial_gain" -- eng/packaging docs/contracts lib/include` ⇒ **零命中**（出厂 `defaults.json` 与 `phase_config_normalize.schema.json` 都没有登记这 7 个键）⇒ 缺省配置下实际跑的就是 order 2。
- 差在哪：同一个键的四侧取三个互斥数值（结构默认 0 / 登记建议 1 / 验收前必须 0 / 生产回退 **2**），且被权威实验文档列为"验收前必须保持 0"的项，在生产取了该文档实测最不可复现的那一档。

### CR-06-06 · Simpson 奇区间分支在 `n_int==3` 时多算一项 `2·y[0]·h/3`，把积分系统性抬高；三处"独立"实现同错
- 轴：**R（主）+ S**
- 位点：`spectrum_integrator.cpp:150-156`
  ```
  int n_13 = n_int - 3; // 前 n_13 个区间用 Simpson 1/3 (必须为偶数)
  sum = y[0] + y[n_13];
  for (int i = 1; i < n_13; ++i) { ... }
  sum = sum * h / 3.0;
  ```
  当 `n_int==3` 时 `n_13==0` ⇒ `sum = y[0] + y[0] = 2y[0]`、循环不执行、`sum = 2y[0]h/3`，随后 :159 又对同一 3 区间加完整的 3/8 项。
- 上位依据：`docs/algorithms/PHOTOMETRIC_FIT.md:196`「Simpson 1/3 复合（尾 3/8）」＋`lib/algorithms/photometry/docs/algorithm.md:121`「积分法则：Simpson 1/3 复合公式」。复合式的定义是"前 n_13 个区间的贡献"，n_13=0 ⇒ 贡献必须为 0；条文未授权任何端点加项。
