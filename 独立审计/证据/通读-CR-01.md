### CR-01-02 · `map_filter_name` 的比较器不核对长度：`FILTER` 关键字缺失即静默解析成 `"Baader R"`
- 轴：**R（主轴）+ D**
- 位点：`filter_curve_json.h:359-362`
  ```cpp
  return std::equal(a.begin(), a.end(), b, b + std::strlen(b),
      [](char c1, char c2) { return std::tolower(c1) == std::tolower(c2); });

  ```
- 上位依据：本文件头注释 :18 逐字引 `CODE_STANDARD.md §MUST`「禁止 silent config fallback 改变科学语义——曲线名解析不到时必须报错，不得静默取到别的曲线」；`CONFIG_CONTRACT.md §4 匹配语义（CFG-002 冻结）`「不做大小写/空白/Unicode 归一，**不解析别名**（`aliases` 为空对象 = 显式声明"本库不解析任何别名"）」，§2a.7 承认存在"`FILTER` 关键字解析出的库键"这一独立步骤 ⇒ 映射表本身有条文外的存在理由，但**解析失败必须是"未解析"**。
- 现状：`std::equal` 五参重载语义是"对 first range 每个元素成立即 true"，**`a` 为空串时 first range 长度 0 ⇒ 恒真**；`a` 比 `b` 短且为 `b` 前缀时同样 true——它从不检查长度相等。于是：

  - 前缀串按表内**第一条能包住它的**目命中：`"Gree"→"Baader G"`、`"Bl"→"Baader B"`、`"Lu"→"Baader UV/IR Cut / L CMOS Optimized"`、`"H-al"→"Baader 7nm H-alpha"`、`"Oi"→"Baader 8.5nm OIII"`。
  上游无兜，逐字贴出 `lib/infrastructure/pipeline/orchestrator/cpp/src/orchestrator.cpp:2629-2633`：
  ```cpp
  std::string filter_str;
  const char* filter_cstr = fn_kv_get(frame_, "header", "FILTER");
  if (filter_cstr) filter_str = filter_cstr;
  std::string filter_name = curve_json::map_filter_name(filter_str);
  ```

  关键字不存在时 `filter_str` 保持 `""`，无"缺失即拒"分支，只把 `"Baader R"` 打进日志。
