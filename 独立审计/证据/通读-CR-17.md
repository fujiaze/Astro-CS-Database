### CR-17-1 · 本头文件自称 SAT-001 优先级链的唯一可测实现，生产第二入口却另写了一份并且标签集合不同
- 轴：C（上下级一致）+ D（设计符合）
- 位点：`saturation_policy.h:7`「规则（唯一事实源=上述 SCI 条款，本头文件只是它的可测实现）」；被对照面
  `lib/infrastructure/scheduler/src/module_adapters.cpp:6646`「`double sat_level = snr_cfg.value("saturation_level", 0.0);`」、
  `:6649`「`} else if (std::isfinite(sat_level) && sat_level > 0.0) {`」、`:6650`「`sat_source = "config";`」、`:6655`「`sat_source = "noise_config";`」、
  `:6659`「`sat_source = "fits_header";`」、`:7111`「`frame["noise_saturation_source"] = sat_source;`」
- 上位依据：`docs/science/NOISE_MODEL.md:52`「电平来源优先级 = 显式 `cfg.saturation_level>0` > 帧元数据 FITS `SATURATE` > `DATAMAX`」；
  `eng/contracts/schemas/phase_config_normalize.schema.json:347`「来源优先级（**冻结**，逐级显式登记）：`noise.saturation_level` > `snr.saturation_level` > FITS 头 SATURATE/DATAMAX；三级皆无 ⇒ 显式 DISABLED_NO_METADATA，禁静默」。
  即合同冻结的是**三级**链 + 逐级登记。
- 现状：`resolve_effective_saturation(double cfg_level, ...)`（:44-49）只有**两级**入参（单一 cfg + 头字符串），
  标签由 `saturation_level_source`（:52-59）给出 `{CFG_EXPLICIT, HEADER_SATURATE, HEADER_DATAMAX, NONE}`；
  而 scheduler 路径自行实现 `{noise_config, config, fits_header, unset}`，且把 SATURATE 与 DATAMAX 折叠成同一个 `fits_header`
  （`p1_fits_saturation_level` module_adapters.cpp:1290 内部按 SATURATE→DATAMAX 顺序返回，对外只报 `fits_header`）。
  全仓检索 `"CFG_EXPLICIT"` 只出现在本头文件与 `lib/algorithms/noise_snr/tests/p1noise/p1noise_saturation_test.cpp:189`；
  生产侧断言的是另一套词表：`eng/tests/unit/p1snr/p1snr_noise_cfg_wiring_test.cpp:269`「`== "noise_config"`」。
- 差在哪：同一条被合同标为「冻结」的优先级链存在两份互不引用的实现与两套来源标签词表，本头文件 :7 的「唯一事实源…可测实现」陈述与仓库事实不符。

### CR-17-2 · `saturation_level_source` 的 cfg 参数在生产被硬写成 0.0，cfg 供电平会登记成 `SOURCE=NONE` 与 `FILTER=ENABLED` 并存
- 轴：R（运行时正确）+ C
- 位点：`saturation_policy.h:52`「`inline const char* saturation_level_source(double cfg_level,`」与 `:55`「`if (std::isfinite(cfg_level) && cfg_level > 0.0) return "CFG_EXPLICIT";`」；

  `docs/contracts/DATA_SEMANTICS.md:539` data 行「电平来源优先级 = 显式 `cfg.saturation_level>0` > …」。头文件 :51 自述该标签用途是「写 photo_stats 供消费方 **fail-closed** 判定」。
- 现状：:4716 已把有效电平写回 `ncfg.saturation_level`，:4721 再调 `saturation_level_source` 时第一个实参是字面量 `0.0`，
  于是该调用永远看不到 cfg 分支；`saturation_filter_state(ncfg.saturation_level)`（:4720）用的是**已解析**电平，两者取的是不同的量。

  一旦 `ncfg.saturation_level` 的默认值或上游 cfg 直连被启用（`fn_noise_default_cfg` 之后无人覆盖 ⇒ 现为 0），电平来自 cfg 而 SOURCE 报 `NONE`。

  （检索：`git grep -n "NOISE_SATURATION_SOURCE\|noise_saturation_source" -- eng/contracts docs/contracts` ⇒ 零命中），所以也没有枚举校验会拦住它。
- 定级：S3（当前默认 cfg 电平为 0，实跑产物不致错值；缺"生产上 cfg 电平非 0"的触发路径 ⇒ 降级并注记）

  或在本头文件把 :52 的形参改名/加注释明确「必须传**覆盖前**的 cfg 电平，禁止传解析结果」，并补一条 `p1noise_saturation_test` 断言 `cfg>0 ⇒ "CFG_EXPLICIT"` 且 FILTER=ENABLED。
- 置信：CONFIRMED（调用点原文已读，默认值路径 orchestrator.cpp:4669-4672 已读）

### CR-17-4 · 头文件对 `snr_phot/median_snr` 给了两套互斥语义，其中「置 1.0」那套与实现不符
- 轴：C（同文件内注释 vs 实现）

  同一结构体 :586「`double snr_phot; // IDW 全局尺度 [无量纲] = median(SNR_F) (P5-SNR 重定义)`」；:577「`SNR(ra,dec) = snr_phot × (IDW_spherical(points, query) / median_snr)`」；

### CR-17-10 · 逐源 SNR 计算失败的星被静默丢弃，帧产品里的丢弃原因账目因此不平（SNR-001 破口）

  该类可达：`snr_estimator.cpp:74-77` 当 flux 列（`row[2]`）非正/NaN 且振幅兜底 `F = 2πAσ²/3 ≤ 0` 时返回 0
  ——注意 `snr_estimator.cpp:861` 的入选判据是 `A > B`，**不蕴含 `A > 0`**（背景 B 可为负 ⇒ A 可为负 ⇒ F 可为负）。
