#### CR-43-01 · 板尺度常数的导出式在本文件被写错一个 1e-3 因子，且同文件内两套精度互不自洽
- 轴：C（上下级一致）为主，兼 S
- 位点：`ipv_select.cpp:57` 逐字 `// 206.265 = (180×3600)/π, 把 um/mm 直接转为 角秒/像素`；`ipv_select.cpp:58` `static constexpr double IPV_ARCSEC_PER_UM_PER_MM = 206.265;`；`ipv_select.cpp:62` `static constexpr double IPV_ASEC_PER_RAD = 206264.80624709636;`
- 上位依据：`docs/contracts/DATA_SEMANTICS.md:1055`「**板尺度常量量纲**：`206.265 = (180×3600)/π × 1e-3`，即 §18.1 的 `s0=206.265·pixel_um/focal_mm`（ipv_select.cpp:57 `IPV_ARCSEC_PER_UM_PER_MM`）」；:1058「`XPIXSZ` 以 μm 记，故 header_pointing 与 config 两条路径统一用 206.265」
- 现状：码面数值 = 206.265（与合同正本逐字一致，**数值合规**）；注释给的导出式 `(180×3600)/π` 少 `×1e-3`。我复算：`(180×3600)/π = 206264.80624709636`，`×1e-3 = 206.26480624709636 ≠ 206.265`。同文件 :62 用全精度值，:58 用舍入值，二者按 :57 的式子**互推不成立**（差 +9.4e-7 相对）。
- 差在哪：注释式与合同式差 1e-3 量级（读注释复算会得 206265 而非 206.265）；而合同把舍入值定为正本，于是同文件出现"舍入常数定角秒/像素、全精度常数定角秒/弧度"两套板尺度精度。
- 后果：① 沿 :57 注释复算 s0 的人/门会得到错 1e-3 的 s0；② `s0`（FOV、查询半径、FOV 过滤盒）与 `xi/eta`（W 面角秒坐标）由两套精度导出，交叉核账时对不齐；产品数值本身不失真（合同已钉 206.265）。
- 定级：S3（注释/一致性面，不改产品字节；后果面我写不出"产物错值"）
- 怎么算修好：:57 注释补 `× 1e-3`（与 DATA_SEMANTICS:1055 同式）；若要统一到全精度（`IPV_ASEC_PER_RAD*1e-3`）**必须同批**改 `module_adapters.cpp:3302`、`:4506` 与 `DATA_SEMANTICS.md:1055/:1058`、`PLATESOLVE.md:237`、`scheduler/README.md:20-21` 六处"逐位一致"声明，否则一致性门反判红。

- 轴：R（运行时正确）

- 差在哪：一个 ABI 违约（调用方给了条数没给数据）被归到 §4a.4 明确区分开的另一个失效面，且 :481 `out.valid = true` 已经置真。
- 后果：失效面归因错——真"指向/星表通道故障"与"星表实现缺陷"在日志与 `m_lim_empty_sweep` 上不可分；:643 的错误串把两种都推给"无成功查询结果/星表通道"。

- 怎么算修决：:242 改为「`ret==0` 时要求 `count>0 ⇒ 三指针齐备`，否则 `return -1`（并 `free` 非空者）」；同批在 `gaia_client` 侧确认该形态是否可能出现（缺该角证据即维持 S3）。
