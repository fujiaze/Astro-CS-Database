### CR-20-01 · `per_px <= 0.0` 分支在"已判超预算"之后返回"可行"，是不可行的 fail-open 出口
- 轴：R（主轴）／D
- 位点：`lib/algorithms/coverage/src/block.cpp:51` `if (per_px <= 0.0) {`，紧随 `:52-54` `out->micro_chunk_required = 1; out->status = 0; return 0;`
- 上位依据：`block.h:9` 「OOM：正常路径减块，不 swap；单 tile 仍超则 tile 内 micro-chunk」+ `block.h:40` 「`int status; // 0=ok, 1=unfeasible`」。条文面未规定"零成本即视为可行"（检索式：`git grep -n "unfeasible\|不可行" -- docs lib/algorithms/coverage`）。
- 现状：控制流进入 :51 的前提是 `:40 peak <= budget` **不成立**（即 `fixed_overhead` 单独已超过 `sf·L`）；此时 `per_px = N_B·B_sample + B_px + N_B·B_sample`（:46-50）若为 0，代码不写 `error`、把 `status` 置 0，并把 `estimated_peak_bytes` 留在 :37 的**超预算值**上返回。
- 差在哪：`status=0` 的语义是"方案可行"，而此分支下唯一可行的判据（`fixed_overhead ≤ budget`）恰恰已被证伪；真正的不可行检查 `:57 available < per_px` 被 :51 的早退跳过，`available<0` 的判红永不到达。
- 后果：块规划器对"固定开销本身超预算"报 OK，调用方（`stage2.cpp:1017-1020` 以 `plan.status == 1 ⇒ return 6`）不会中止，随后按 `block_pixels = output_pixels`（:36 原值）整块申请内存 ⇒ 对外"内存预算受控、不 swap"的主张在该输入形态下不成立。
- 定级：S2（**缺生产触发路径**：两个生产调用点 `stage2.cpp:737` `bp.scratch_bytes_per_pixel = 16;` 与 `:1013` `= 8;` 恒使 `per_px > 0`，故只经测试或未来调用方可达）
- 怎么算修好：把 :51 分支改为"仍按 :56-65 判可行性"（`available < 0 ⇒ status=1 + error`），或在 :51 前先判 `fixed_overhead > budget`；同时补一条负例：`covering_frames=0 ∧ scratch_bytes_per_pixel=0 ∧ fixed_overhead > sf·L ⇒ status=1`（现有 `eng/tests/unit/p2_block_plan_test.cpp` 无此形态）。
- 置信：CONFIRMED（逐行控制流复算：`:40` 落入 else ⇒ `peak > budget`，`per_px=0` ⇒ `:56-57` 不可达）

### CR-20-03 · `safety_factor` 无上界且非法值静默回退常数
- 轴：S（主轴）／R
- 位点：`lib/algorithms/coverage/src/block.cpp:20` `const double sf = in->safety_factor > 0.0 ? in->safety_factor : 0.75;`
- 上位依据：对照口径见 `docs/science/NOISE_MODEL.md:55`「`variance_floor` 非有限或 ≤0 时…**不静默回退到任何常数**」与 `docs/contracts/DATA_SEMANTICS.md:543`「拒绝即终态，无常数回退路径」；内存系数一侧的同类条文零提及（检索式：`git grep -n "safety_factor\|memory_limit" -- docs/science docs/contracts ASTROCS_DESIGN.md`）。
- 现状：`sf` 允许任意 `>0`，包括 4.0、1e6；`budget = memory_limit_bytes * sf`（:39）⇒ 用户上限被参数自身放大；`≤0`（含 0 与负）不拒绝而回退 0.75。
- 差在哪：一个"安全系数"在语义上必须 ≤1，代码既不校验上界也不记录被回退；越界值把内存闸门变成可调倍率。
- 后果：`memory_limit_mb` 这一对外承诺的资源约束可被单个未校验字段成倍突破（偏绿）。
- 定级：S3（两个生产调用点显式传 0.75，故当前不可达；作为闸门缺陷登记）
- 怎么算修好：`:20` 改为 `(sf <= 0.0 || sf > 1.0) ⇒ status=1 + error`；同批把 0.75 的来源补进 `docs/architecture/PERFORMANCE_MODEL.md`（否则仍是无锚常数），并同步 `eng/tests/unit/p2_block_plan_test.cpp` 的期望。
- 置信：CONFIRMED
