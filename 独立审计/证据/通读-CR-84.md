### CR-84-01 · SHA-256 自测向量未覆盖全场景
- 轴：**S 支撑**
- 位点：:691-720 `acs_secure_loader_self_test_v1()` 中的三个测试向量
- 上位依据：FIPS 180-4 Appendix B 定义了多个测试向量；当前只覆盖空串、"abc"、长跨块串三例
- 现状：self_test 仅校验了 3 个向量，未覆盖 edge cases（如单块内不同长度、边界对齐情况等）
- 差在哪：测试覆盖率不足可能导致某些边缘情况下的实现错误未被发现
- 后果：若实际使用中触发未覆盖的边界条件，可能产生错误的 hash 值，导致模块加载失败或安全漏洞绕过
- 定级：**S2**（可致产品错值，但触发路径需依赖特定输入模式，非普遍性）
- 怎么算修好：补充 FIPS 180-4 附录 B 全部 7 个测试向量，或至少覆盖所有边界情况
- 置信：**PARTIAL**（缺完整向量列表的手动核证，建议自动化 fetch）

### CR-84-02 · realpath 结果与入参不一致即拒绝可能存在误杀
- 轴：**D 设计符合** / **R 运行时正确**
- 位点：:439-445 `if (strcmp(canon, abs_copy) != 0)` 拒绝逻辑
- 上位依据：文档称"入参本身必须已是 canonical 文本 (不含 symlink/.. 分量)"
- 现状：realpath 结果与入参不一致直接拒绝，无论原因
- 差在哪：未区分"入参含 symlink/..导致解析变化"和"入参本身就是合法但非常规形式（如结尾无斜杠的目录）"两种情况
- 后果：合法路径可能在某些文件系统状态或配置下被误拒，降低可用性
- 定级：**S3**（降级为可用性问题，不致错值）
- 怎么算修好：增加更细粒度的检查——只有当解析结果指向不同物理位置时才拒绝
- 置信：**PARTIAL**（需实测不同文件系统行为）

### CR-84-03 · CPU 阈值三者的语义与边界条件未明
- 轴：**S 支撑**
- 位点：:114-116 `LOAD_HIGH_THRESHOLD=90.0`, `LOAD_THROTTLE_THRESHOLD=70.0`, `LOAD_FULL_SPEED_THRESHOLD=60.0`
- 上位依据：`engineering_authoritative/docs/04_RESOURCE_AWARE_ORCHESTRATOR_SPEC.md` §4.3
- 现状：三个阈值并存，但未说明它们之间的转换逻辑（例如：从 60% 升至 70% 时是否立即 throttle？从 70% 降至 60% 时是否立即恢复？）
- 差在哪：缺少 hysteresis（迟滞）机制的明确定义，易造成频繁切换
- 后果：CPU 负载在 60-90% 区间波动时可能导致 throughput 震荡
- 定级：**S2**（可致性能不稳定）
- 怎么算修好：补充迟滞机制（例如 throttle→resume 需从 70% 降至 50% 而非 60%）并给出标定依据
- 置信：**PARTIAL**（需核对 SPEC 原文及 Python 原型）

### CR-84-04 · os_margin 固定 2GB 缺乏可配置性
- 轴：**D 设计符合** / **S 支撑**
- 位点：:75 `os_margin_bytes = 2LL * 1024 * 1024 * 1024`
- 上位依据：RESOURCE_AWARE_ORCHESTRATOR_SPEC §3.1 内存预算公式
- 现状：构造函数中 os_margin 有默认值 2GB，但该值硬编码
- 差在哪：SPEC 若要求"根据系统总内存动态调整"则此处违约；若允许固定值也应有注释说明来源
- 后果：小内存机器（如 8GB）可能因 2GB margin 过度保守而频繁拒绝准入门槛；大内存机器（如 128GB）则过于激进
- 定级：**S2**（影响任务成功率）
- 怎么算修好：改为 `总内存 * X%` 的动态计算，或由配置文件传入
- 置信：**PARTIAL**（需核对 SPEC 的可配置性要求）

### CR-84-05 · uncertainty_factor 默认值 1.0 无误差传播依据
- 轴：**S 支撑**
- 位点：:76 `uncertainty_factor = 1.0`
- 上位依据：H-002 Python 原型 `admission_controller.py`
- 现状：默认值为 1.0（即不乘任何放大因子），但预测峰值+预约的总和直接与预算比较
- 差在哪：缺乏对 FrameCostEstimator 预测误差的统计标定；默认值应基于历史数据的置信区间（如 95% CI）
- 后果：若预测存在系统性低估，可能导致内存超卖 → OOM
- 定级：**S1**（可致产物错乱或直接 crash）
- 怎么算修好：补充误差标定实验，给出 uncertainty_factor 的推荐取值范围（如 1.2-1.5）
- 置信：**UNPROVEN**（缺历史数据）
