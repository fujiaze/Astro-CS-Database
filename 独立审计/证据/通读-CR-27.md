## 3.2 findings

### CR-27-09 · `is_ok` 在循环外初始化为 true 且循环内不重置，σ-clip 循环恒只跑 1 次，`max_iterations=5` 与整段多轮剔除逻辑是死代码
- 轴：R（主轴）＋S（该阈值的实际效果无锚可核）
- 位点：`ipv_itertrans.cpp:436-440` 与 `:594-595`
  ```
  436	    bool is_ok = true;
  437	    int iters_so_far = 0;
  ...
  440	    while (iters_so_far < max_iterations) {
  ...
  594	        iters_so_far++;
  595	        if (is_ok) break;
  ```
  循环体内 `is_ok` 的**全部**写入点：`:553 is_ok = true;`（`sigma <= halt_sigma`，而调用侧传 0.0 ⇒ 几乎不触发）、`:576 is_ok = true;`（`nb == 0`）、`:584 is_ok = false;`（紧跟 `:585 break`）。没有任何一处把 `is_ok` 在每轮开始时复位为 false。
- 上位依据：本文件 :324 登记的流程"2. 循环 (最多 max_iterations 次)"；:554 与 :577 两处注释"不退出, 重拟合后退出 (break 被注释掉)"说明设计意图是"标记收敛→再拟合一轮→退出"，即存在多轮迭代；调用点 :998 传 `5, // max_iterations`。`docs/algorithms/PLATESOLVE.md` 层无次数条文（见 3.1 表），故唯一意图证据即本文件自身注释。
- 现状：由于初值为 `true` 且无复位，第 1 轮结束时 `is_ok` 必为 `true`（既未触发失败 break 也未 return 的话），:595 立即 break ⇒ **循环体最多执行一次**；`iters_so_far` 恒 ≤1，`result.n_iterations` 恒 ≤1（再被 :1041/:1049 加工成 2 或 3），`sigma` 只按"未经相对剔除的残差分布"估计一次，随后的重拟合不再有第二次剔除机会。

### CR-27-21 · `Logger` 无条件向 stderr 输出并把每行 flush 与全局互斥绑定，在 OpenMP 并行段内是一次全序列化点
- 轴：R
- 位点：`ipv_log.h:92`（`std::lock_guard<std::mutex> lock(mtx_);` 覆盖 :114 的文件写＋:115 flush＋:118 `fprintf(stderr)`）

- 现状：即使日志未启用（`enabled_ == false`），每条调用仍要：取全局锁 → 拼时间戳（`strftime`）→ 拼行 → `fprintf(stderr)` → 释放锁；启用时再加一次文件写＋`fflush`。迭代内部（`ipv_itertrans.cpp:483,533,571` 等 debugf 全在 `while` 体内）同样按条付出。

- 定级：**S3**（无正确性后果，且我依派单禁跑基准 ⇒ 未测；不测就不升档，如实登记）
- 怎么算修好：`log()` 开头加 `if (!enabled_ && !stderr_enabled_) return;` 之类的零成本出口（用 `std::atomic<bool>` 快路径，仍保留锁内写出）；把 `flush` 频率降为按级别或按批量；并把 stderr 通道与文件通道的锁分离。改后须与 `PLATESOLVE.md:335-337` 的确定性主张（"同输入同线程数 bitwise 一致；线程 1/2/4 一致"）一起复跑——日志顺序本不在 bitwise 产物内，但要在回执里写明这一点，避免被误读为改了科学面。
- 置信：PARTIAL（锁/flush/无条件 stderr 三项代码事实 CONFIRMED；性能后果未实测，派单禁跑构建与基准）
