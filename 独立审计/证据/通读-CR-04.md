## 1.2 findings

### CR-04-1 · `perf_trend_maxw` 判据方向与其声称语义相反：真加速判红、变慢恒绿
- 轴：R（主）/ C（条文与实现打架）
- 位点：`p1phot_tests_perf.cpp:116` `P1PHOT_CHECK(cs, paritym >= 0.25, "perf_trend_maxw");`（`paritym` 定义于 :109 `paritym = (t1w > 0.0) ? tmw / t1w : 1e30;`，`tmw` 为 max 线程档耗时 :105）
- 上位依据：只在本文件头部注释——`:8` "perf_trend : T(threads=max)/T(threads=1) ≥ 0.25× (无负加速趋势, 容噪)"；`CMakeLists.txt:48` 复述为 "perf 哨兵 (parity 4x / trend 0.25x, 比值语义)"。文档面零提及：检索式 `git grep -n -e "parity" -e "0.25" -e "负加速" -- docs/ *.md`（命中仅 DRIZZLE/NOISE/GATES 的无关项）、`grep -n -e "perf" -e "并行" docs/algorithms/GATES_AND_TOLERANCES.md`（无 P1-PHOT 性能行）。
- 现状：判据要求比值 **不小于** 0.25。比值 `tmw/t1w` 的语义：>1 = 多线程更慢（负加速），<1 = 加速。
- 差在哪：不等式方向定死了——任何"负加速"（ratio>1）必然满足 `>= 0.25`⇒该门对所声称要防的场景**恒真**；反之它只在 `ratio < 0.25`（即 max 档比单线程快 4× 以上）时翻红，也就是**并行做得越好越容易判红**。1024² 逐像素校正为可分割负载，8 线程近线性即 ratio≈0.125。
- 后果：①`p1phot_performance`（ctest 注册见 `CMakeLists.txt:137`）在核数 ≥8 的开发/CI 节点上，对被正确并行的实现给出 RED；②该门在证据面上登记为"无负加速趋势"，实际不提供该项保证⇒对外"性能哨兵覆盖负加速"的主张不成立。
- 定级：S2（触发路径为 `ctest → p1phot_performance → main():116`，非生产数据路径；缺"是否已在真实节点误红"的实跑证据）
- 怎么算修好：把 :116 改成上界判据（例如 `paritym <= 1.0 + ε` 且 ε 有标定来源并登记进 `GATES_AND_TOLERANCES.md`），或删掉该门、把"疑似提前退出/退化"检查改为状态断言（见 CR-04-2 的 `rc/nm` 断言），同时改 `CMakeLists.txt:48` 与 :8 注释使三处口径一致。必须同批：若无 OpenMP 分支（:101 `nmax=4`⇒:105 `tmw=t4w`）保留，需显式 SKIP 或判红，否则同一条断言在 4 核机上退化为 `parity4` 的复制。
- 置信：CONFIRMED（方向由不等式代数确定，未实跑）

### CR-04-2 · 计时循环丢弃 `rc`/匹配数/诊断量，三个 perf 哨兵可由"根本没做校正"的运行满足
- 轴：R
- 位点：`p1phot_tests_perf.cpp:82` `(void)rc;`；`:62` `int nm = -1;`（:80 传入 `&nm` 后全文再无读取）；`:64-65` `PhotometricDiag dg; std::memset(&dg, 0, sizeof(dg));`（:80 传入 `&dg`，之后再无任何读取）
- 上位依据：`docs/algorithms/PHOTOMETRIC_FIT.md:122-126`（§5c）"取消时返回未收敛状态不写 location/scale"——即被测入口存在"提前返回、不做完工作"的状态；`docs/algorithms/GATES_AND_TOLERANCES.md` 无任何 perf 门行（同 CR-04-1 检索式）。本文件头部 :3-12 自称"门必须稳…比值哨兵"，未声明允许在未成功完成计算时计时。
- 现状：`time_run` 只取墙钟最小值，唯一使用返回码的一行是 `(void)rc;`；`nm`（匹配星数）、`sc/sg`、`dg`（诊断）全部丢弃，无论 `rc` 为何都返回 `best` 并进入 :114-116 三条断言。
- 差在哪：方向确定——`rc != 0` 或 `nm == 0` 的路径只会**少做**工作⇒`t4w`/`tmw` 变小⇒比值变小⇒`< 4.0` 两条判据**更偏向通过**（fail-open）；即并行回退还被"少干活"掩护时门照绿。
- 后果：`P1PHOT PERF PASS` 这一对外主张（"并行不倒退"）可以在被测函数完全失败/零匹配时成立；性能证据与功能证据脱钩，`p1phot_performance` 的绿色不构成任何"校正被执行过"的证据。

- 怎么算修好：在 `time_run` 内每次 `rep` 后断言 `rc == 0 && nm > 0`（并把 `dg` 的关键字段纳入或如实注明只看 `rc/nm`），不满足即 `cs.failures++` 并打印 `rc`；同时新增 fault 名（如 `perf_run_status`）以与故障注入登记表对齐——改此须同批检查 `FaultRegistry` 是否已登记该名字，否则新门不被注入验证。
- 置信：CONFIRMED（代码事实）；"实际是否会走失败路径"PARTIAL（未实跑，缺 `pc_calibrate_simple_f64` 在该夹具下返回非零的证据）

### CR-04-5 · P2/P4/P5/P6 断言链依赖被测函数不返回退化路径，而退化路径是被文档承认的合法输出
