### lib/include/astrocs/core/variance_floor.h

#### D1 · variance_floor 实现与 NOISE_MODEL §7 的"夹逼不变量"存在概念性偏离风险

- **轴**: D (设计符合)
- **位点**: variance_floor.h:1-31 (文件头注释对规范的重述)
- **上位依据**: docs/science/NOISE_MODEL.md §7「Floor 夹逼不变量」："任意**可用** variance 经 floor 夹逼后 ivar 有限；clamp **只作用于可用方差**；**不可用一律 ivar=0（不得由 clamp 产生）**"
- **现状**: 代码实现 (variance_floor.h:123-126):
```cpp
inline double apply_variance_floor(double v, const VarianceFloor& f) {
    if (!std::isfinite(v) || v <= 0.0) return v;   // 不可用/损坏：不伪装
    return std::max(v, f.value);
}
```
- **差在哪**: 实现正确——对不可用方差原样透传，不对 clamp 后的结果判断不可用。但文件头注释 (line 26-27)"不可用（v<=0）与非有限**原样透传**，绝不伪装（§7「不可用一律 ivar=0，不得由 clamp 产生」）"表述清晰，实现与条文一致。**无实际缺陷，此条仅作为审查记录留存**。
- **后果**: 无 (实现与设计一致)。
- **定级**: S3 (概念性偏离风险已排除，仅为审查覆盖)。
- **怎么算修好**: N/A (已合规)。
- **置信**: CONFIRMED (代码 - 条文逐字比对)。

### lib/infrastructure/scheduler/src/artifact.cpp

#### C1 · FNV-1a hash 的"科学 payload 语义"注释与数据合同潜在不一致

- **轴**: C (上下级一致)
- **位点**: artifact.cpp:49 ("FNV-1a 64 稳定 hash (仅用于科学 payload 语义; 顺序固定)")
- **上位依据**: eng/contracts/data/artifact_contract.json 对 provenance hash 的定义；DATA-003 manifest content_digest 使用 SHA256，非 FNV-1a。
- **现状**: code:
```cpp
// FNV-1a 64 稳定 hash (仅用于科学 payload 语义; 顺序固定)
std::string Provenance::science_hash() const {
    uint64_t h = 1469598103934665603ULL;
    ...
}
```
- **差在哪**: 注释声称"仅用于科学 payload 语义"，但未在代码或使用处看到该 hash 的输出被写入 artifact descriptor 或 manifest。若此 hash **本应** 是 contract 中定义的 provenance hash，则与 DATA-003 的 SHA256 要求冲突；若此 hash **仅内部使用**，则注释误导（"科学 payload"易让人误解为对外合同字段）。需核查：① science_hash() 的实际调用者；② contract 中 provenance hash 的确切算法指定。
- **后果**: 若 science_hash 被误当作对外 provenance digest，会导致产物 hash 与 manifest 声明不符（AIO_ERR_HASH_MISMATCH）；若仅内部使用，则是文档误导风险。
- **定级**: S2 (未触发生产路径，但可能误导后续开发)。
- **怎么算修好**: ① 查 science_hash() 调用链，确认其用途；② 如对外使用，改为 SHA256；③ 如内部使用，修正注释明确"internal use only"。
- **置信**: PARTIAL (缺调用链核查，需 git log + rg "science_hash")。
