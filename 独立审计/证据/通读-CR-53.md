### CR-53-1 · 文件头宣称的"环境变量即可注入"用法在这份实现里根本不会注入失败——注入关闭与"程序挺过 OOM"两者外部表现完全相同
- 轴：C（主轴）＋ R
- 位点：`:55` `    if (!g_armed) { g_seq++; return 0; }`；对照 `:4` ` * 用法: OOM_FAIL_AT=N OOM_COUNTDOWN=1 OOM_MIN=a OOM_MAX=b OOM_TOTAL=path program */`
- 上位依据：条文面零提及"必须显式 arm 才注入"。检索式：`git grep -n "OOM_FAIL_AT"`（全仓 3 命中：本文件 `:4`/`:40`、`p1star_tests_main.cpp:9`）；`p1star_tests_main.cpp:9` 与 `CMakeLists.txt:89`（"negative 组: LD_PRELOAD interposer (第 N 次 malloc 失败…)"）都把用法描述为"预载 + 环境变量"。设计面对"malloc 负例"的要求见 `docs/algorithms/STAR_DETECTION_ALGORITHMS.md` §11.4 TEST-STAR-DESIGN-001（`CMakeLists.txt:5` 引为合同锚），该节只规定"负例组"，未规定注入必须靠 arm。
- 现状：`init_once()` 从 `OOM_FAIL_AT` 只写 `g_fail_at`（`:44`），**不写 `g_armed`**；`g_armed` 仅由 `sdet_oom_arm()`（`:26-31`）置位。因此 `LD_PRELOAD=…so OOM_FAIL_AT=7 <program>` 这条被本文件自己文档化的用法，全流程只计数不失败，进程正常退出、`OOM_TOTAL` 正常写出、无任何"注入未生效"的告警。
- 差在哪：一个"注入开关默认关"的构件，其接口文档却把开关描述成默认开；关闭态与"被测代码真的扛住了分配失败"在退出码与产物上不可区分。
- 后果：任何按 `:4` 用法接线的门（含被 `:2` 点名的批次 R 样板 `run/local/bughunt_batchR/oom_inject.c` 的下游、以及 `docs/ci/` 未来登记的 malloc 负例）会得到**恒绿**的"OOM 安全"结论。方向已钉死：注入关闭 ⇒ 无分配失败 ⇒ 被测程序 rc 与其正常值一致 ⇒ 判据"崩溃/报错才算没挺住"必绿。本仓现有唯一驱动方（`p1star_tests_core.cpp:732`）绕过了该路径，故现存门未被骗。
- 定级：S2（缺生产触发路径：测试面构件，不进产品字节；但对外主张"malloc 事务化负例"的证据强度受影响）
- 怎么算修好：①`:4` 用法行改为必须显式 `sdet_oom_arm(N)`，或②`init_once` 中 `if (at) { g_fail_at=…; g_armed=1; }` 并同时更新测试侧避免双重锚定；无论哪种，需在**未注入任何一次失败**时于 `oom_report`（`:76-87`）写一条"零注入"记录（例如 `OOM_SEQ` 里加 `armed=0`），使"注入未发生"成为外部可见事实而不是沉默。两处必须同改：只改文档不改代码，`OOM_FAIL_AT` 仍是死键；只改代码不设 armed 上报，`p1star_tests_core.cpp:834`（统计模式 `arm(-1)`）的语义会被误当成注入模式。
- 置信：CONFIRMED（逐行读；`g_armed` 全部写点只有 `:30`，读点只有 `:55`，检索式见上）

### CR-53-2 · `OOM_MIN` 单独设置时被静默忽略：尺寸窗要求 `g_max > 0` 才生效
- 轴：R
- 位点：`:56` `    if (g_max > 0 && ((long)n < g_min || (long)n > g_max)) return 0;`
- 上位依据：条文面零提及。检索式：`git grep -n "OOM_MIN"`（仅本文件 `:4`/`:42`）。文件头 `:3` 把 `OOM_MIN/OOM_MAX` 描述为一对可用的字节过滤。
- 现状：过滤整体由 `g_max > 0` 把门；只设 `OOM_MIN=a`（`g_max` 保持 `:16` 的 `0`）时条件短路，**任何尺寸**的分配都参与计数与失败；且 `g_min==0` 时 `(long)n < g_min` 恒假，故"设 min 不设 max"与"什么都不设"行为等价——用户以为开了下界窗，实际开的是全量窗。
- 差在哪：一个"设了一半的过滤器"退化成全量过滤器而不报错，注入点位置随全图分配序漂移。
- 后果：按窗注入的负例（例如"只让 16 MB 的图像缓冲失败"）会把失败打到别的尺寸上；若该点走的是 STL/`bad_alloc` 终止路径，父侧分类进 `aborts`（`p1star_tests_core.cpp:866`）仅打印，实测窗内行为一次都没被验。方向：不制造假绿（`oom_graceful_checkpoint_exists` 仍可能由别的 N 满足），但会**把指定窗口的覆盖悄悄换成另一窗口的覆盖**——即"验了 A 点"被登记成"验了 B 点"。
- 定级：S3（本仓当前无按窗驱动的调用方，缺触发路径）
- 怎么算修过：`init_once` 里 `g_min > 0 && g_max == 0` 时要么把 `g_max` 视作 `LONG_MAX`，要么直接拒绝注入（不 arm／写 armed=0 记录）；两种都要同批改 `:3-4` 的用法串。
- 置信：CONFIRMED

### CR-53-4 · 已定标 float 帧上把常数 65535 当饱和参考电平，正是 SCI 明文"必须判红"的那个用法
- 轴：C（主轴）＋ S
