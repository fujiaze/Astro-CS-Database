# Stage1 Agent 执行规则

> 本页面为已冻结规范，定义 Agent 执行 Stage1 任务时的行为规则。

## 1. 单次连续执行

用户按 Agent 调用次数计费。读取任务包后，应在一次授权执行中连续完成所有不依赖用户新决策的工作，**不得在"审计完成、Wiki 更新、代码修改、测试完成、实验完成"等普通节点反复停下**。

## 2. 允许中断的情况

只有以下情况允许中断：

1. 剩余全部工作都被同一个未冻结科学语义阻塞；
2. 必须执行不可逆或破坏性操作，且任务包未授权；
3. 发现任务明显超出 Stage1 / HISS 范围。

若某个未决工程选项不阻塞其他工作，应写入 `DECISION_QUEUE.md` 并继续。

## 3. 绝对禁止

- 不新建仓库，不复制完整旧仓库作为"新工程"；
- 不修改或实现 Stage2；
- 不自动启动 710 帧或其他全量回归；
- 不用 Python 原型代替正式 C++ 实现或正式性能实验；
- 不把未冻结的实验结论直接写成最终默认标准；
- 不创建用户可见的 HISS v1/v2 双路线；
- 不交付完整仓库、构建产物、测试数据、缓存或大型日志。

## 4. 执行顺序

1. Phase 0：仓库就地审计
2. Phase 1：冻结 Wiki 文档
3. Phase 2：接口与数据契约落地
4. Phase 3：C++ 实现已冻结内容
5. Phase 4：C++ 未决工程实验（只汇报，不冻结）
6. Phase 5：正确性测试与性能剖析
7. Phase 6：精简交付 ZIP

## 5. 最终精简 ZIP 要求

交付必须小，只包含应用到旧仓库所需的新增/修改/删除信息和报告。**不要压缩整个仓库。**

推荐结构：

```text
AstroCS_Stage1_HISS_Delivery/
├─ 00_README.md
├─ APPLY_IN_PLACE.md
├─ MANIFEST.json
├─ MANIFEST.sha256
├─ DELETE_LIST.txt
├─ git_diff.patch
├─ changed_files/
├─ wiki/
├─ tests/
└─ reports/
```

## 6. 禁止打包内容

- 完整旧仓库
- `.git/`
- build、dist、bin、obj
- 编译器缓存
- 原始天文测试数据
- HISS 大样本
- Python 环境
- IDE 配置缓存
- 数百 MB 日志
- 重复副本
- Stage2 输出
- 710 回归结果
