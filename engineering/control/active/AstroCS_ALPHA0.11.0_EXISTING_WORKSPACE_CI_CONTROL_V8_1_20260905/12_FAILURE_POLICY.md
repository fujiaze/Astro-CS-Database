# 12｜失败处理（简化版）

每个失败只分四类：

- `CODE_FAIL`：源码/文档/测试不符，自动创建具体修复任务。
- `ENV_FAIL`：缺工具/权限，输出准确安装或授权项；继续不依赖它的任务。
- `RESOURCE_FAIL`：OOM、低利用率、泄漏、超时，保留监控证据并派发性能修复。
- `FATDUCK_PENDING`：Fatduck 离线，仅真实数据门禁等待；GitHub Windows CI 不受影响。

禁止宽泛重试。相同命令在相同 SHA/环境下最多自动重试一次，且仅限已识别的瞬时网络/runner 中断；测试失败、数值失败和编译失败不自动重试。

禁止为通过测试而：放宽容差、跳过测试、吞异常、改 PASS 文件、禁用监控、减少样本到失去意义、改用旧缓存或旧制品。

finding 必须包含 task/check ID、完整 SHA、命令、预期、实际、最小复现、责任模块和建议验收；前台据此自动派发，不再建立层层人工 checkpoint。
