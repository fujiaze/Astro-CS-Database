# 规范 07 · ACSD 改名与完整动态运行

本规范规定品牌统一为 ACSD，以及完整动态运行形态的整改要求。

## 1. 品牌统一

软件名称统一为 ACSD，覆盖代码、构建与文档：

| 面 | 统一为 |
|---|---|
| 可执行入口 | Windows `acsd.exe`、Linux `acsd` |
| C++ 命名空间 | `acsd` |
| 库与构建目标 | `acsd_*` |
| 预处理宏、ABI 前缀 | `ACSD_*` |
| 头文件目录 | `include/acsd/` |
| 产品标识、manifest、日志 schema | ACSD 口径 |
| 文档与 README | ACSD |

- 重命名用脚本做机械替换并人工核对，保持符号一致；重命名改动与功能改动分开提交，便于核对。
- GitHub 仓库名是否更改由项目负责人处理，代码与文档先统一为 ACSD。

## 2. 完整动态运行形态

- 唯一入口 `acsd`，其余能力以动态库承载或在入口内部实现，不设子入口。
- 计算核按 CPU 指令集分别编译为动态库：Windows 为 dll、Linux 为 so；主程序保持基线指令集。
- 运行时检测 CPU 能力，结合 benchmark 结果选取对应指令集动态库加载；不支持或缺库时回退基线，指令集核与基线数学等价。
- 每个算法模块可作为独立动态库；基建按稳定职责合并为有限动态库。

## 3. benchmark 接入

- benchmark 按 kernel 测量数值误差、吞吐、线程扩展与内存带宽，生成机器画像。
- 画像结果写入程序 config 目录，运行时自动读取；调度器据画像选取指令集库与编排参数。
- 画像缺失时按保守口径运行并提示经过，不阻塞；不指定输出路径。

## 4. 调度器动态自适应

- 不写死 CPU 核心数与内存上限：worker 数与并行宽度由运行环境自动获取（可用核、亲和性、cgroup、Job Object）结合 config 决定。
- 内存上限可用百分比表达；运行参数优先读 config，其次从运行环境获取。
- 一个资源预算源统一调度，模块不私建线程池，科学内核单层并行。
- 编排参数（窗口大小、预取深度、帧并发、工作窃取）由性能探针实测迭代，不使用固定经验值。

## 5. 动态库加载检查

- 加载前检查 CPU 特征、manifest、ABI 与清单授权路径；失败报错，不搜索未授权路径。
- 跨动态库不传 STL、异常、RTTI 与编译器私有类型。

## 6. 完成判据

- 全仓品牌统一为 ACSD，入口与库命名一致；
- 指令集动态库运行时选取生效，benchmark 画像落 config 并接入调度；
- 资源参数动态自适应，无写死核心与内存。
