# 规范 06 · 代码与注释审查

本规范规定文档定稿后，如何依据 detail 对全部代码与注释做极为详细的审查和修正。本阶段不跑构建与测试。

## 1. 审查依据与时序

- 直接依据 docs/detail，参照 science 与 engineering 正本；在 detail 定稿后进行。
- 按模块分片，逐文件、逐函数审查；先审查、登记问题，再按片订正。
- 本阶段只做静态阅读与代码订正，不编译、不跑测试、不碰门禁。

## 2. 审查维度

| 维度 | 检查内容 |
|---|---|
| 功能一致 | 实现的算法、步骤、参数与 detail 一致，科学口径与 science 一致 |
| 端口与数据 | 输入输出块、类型、单位、字段名正确，端口只接同一种对象 |
| 生命周期 | 块的生产、消费、销毁与声明一致，无长期副本与泄漏 |
| 错误处理 | 每个失败产生稳定错误码，无空捕获、忽略返回值、只记日志、静默降级 |
| 并发 | 线程只来自调度器预算，无私建池、嵌套并行、数据竞争 |
| I/O | 文件读写经统一 I/O，无绕过、无未声明写文件 |
| 资源 | 无硬编码线程/内存，缓冲与阈值自适应或走配置 |
| 边界 | NaN/Inf/缺失、奇点、空输入处理正确 |

## 3. 硬编码处置

逐处登记硬编码数值，按来源处置：

- 有科学推导：保留，注释给出推导与出处；
- 可由输入几何或物理关系导出：改为现场计算；
- 需标定：移入 config，注明来源与单位；
- 无依据经验值：改为自适应或删除。

## 4. 死代码与重复

- 识别并处理：未被调用的代码、重复实现、占位与 TODO 残留、实验性分支、静默回退路径。
- 同一能力保留一份实现，重复的合并；退役代码删除，或保留统一注释块写明原因与影响面。
- 不保留「以防万一」的回退、重试与兼容层。

## 5. 注释审查

- 注释解释为什么这样做：物理依据、口径、约束、非显然处理；
- 注释与代码同步更新，删除过时、矛盾、复述代码的注释；
- 科学常数与公式注释指向 science 正本或文献编号，不在注释堆叠历史；
- 每个模块开头有说明其职责的注释，公共接口有用途、参数、返回与错误语义说明。

## 6. 命名与风格

- 命名清晰一致，与文档术语对应；品牌统一为 ACSD（规范 07）。
- 函数短小、职责单一；头文件接口最小，内部实现不外露。

## 7. 审查产出

- 代码审查报告：逐模块问题清单（位置、对应文档条款、现状、应为、处置）；
- 订正后的代码；硬编码与死代码处置台账。
- 订正完成后再进入品牌统一与动态运行整改（规范 07）。

## 8. 完成判据

- 代码与 detail 逐条一致，偏差全部处置；
- 无死代码、重复实现、静默回退；注释与代码一致；
- 硬编码按来源处置完毕。
