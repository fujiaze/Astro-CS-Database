# 规范 04 · 对抗性审稿（十轮以上）

本规范规定文档迁移完成后、代码治理开始前，对文档集与实验单元的多轮对抗性审稿。

## 1. 审稿对象与时序

- 对象：最高设计、docs/science、docs/engineering、docs/detail 骨架，以及全部实验单元（含小论文、实验代码、结果、文献台账）。
- 时序：文档迁移完成后开始，连续进行十轮以上；审稿定稿前不进入代码治理。
- 审稿由 agent 亲自阅读原文完成，不使用代码扫描或脚本判定替代阅读；机器词表只给候选，结论由阅读推导得出。

## 2. 审稿姿态

按科学论文审稿标准，以红队姿态主动证伪：

- 引用：文献真实存在、DOI 可解析、引用与原文一致、适用域匹配；
- 推理：前提成立、推导无跳步、统计方法正确、结论不超出验证边界；
- 误差：误差预算完整、传播一致、偏差可解释、置信区间正确；
- 覆盖：边界、奇点、退化情形、失效域与反例是否讨论；
- 实验：方法与论文一致、seed 固定、正负例有判别力、结果可复现。

## 3. 对抗方法

- 构造反例：极端输入、低信噪比、光污染、高对比、奇点邻域、覆盖缺口，尝试推翻结论。
- 盲复算：遮住既有判定独立取证，再与原结论对比，判一致、偏松或偏严。
- 交叉核对：论文、science 正本、实验代码、结果数字四者一致；与上游开源实现对照。
- 验证判据能红能绿；恒真、空断言、不读真实对象的判据判无效。

## 4. 轮次组织

- 每轮设定明确检查焦点并记录问题，建议逐轮覆盖：

| 轮次焦点 | 内容 |
|---|---|
| 结构与索引 | 权威链、唯一正本、双向索引、文件夹 README |
| 引用真实性 | 逐条核对文献与开源代码 |
| P1 | 测光拟合推导、误差预算、线性口径 |
| P2 | 信噪比定义、噪声项、天光单调性 |
| P3 | 守恒映射、构造闭合、奇点 |
| P4 | 稠密重建算子、预测方差 |
| P5 | 天光平面、加权、接缝判据 |
| 实验与复现 | seed、正负例、结果复算 |
| 跨文档一致性 | 符号、单位、常数、口径 |
| 反例与边界 | 红队反例、失效域、诚实边界 |

- 十轮后若仍有未决问题，继续追加轮次直到收敛，不以轮次凑数。

## 5. 问题处置

- 发现不严谨处：能由现有证据订正的直接订正论文与正本；需要新证据的设计并补做实验，再据结果订正。
- 科学方法有更合理选择时，查一手文献与开源实现裁决，不盲从现行文档。
- 问题按严重程度分级（阻断/须修/建议），逐项闭环并复审。

## 6. 收敛判据

- 连续两轮未发现新的须修及以上问题；
- 全部阻断与须修项闭环、复审通过；
- 论文、正本、实验、结果四者一致，证据齐备。
收敛后文档集定稿，作为 detail 推理与代码治理的权威依据。
