# 规范 08 · 编译与 CI 重做

本规范规定仓库治理完成后的双平台编译，以及门禁与 CI 的重建。

## 1. 时序

- 文档迁移、对抗审稿、detail 产出、代码治理、改名与动态运行整改全部完成后，才开始编译。
- 先完成双平台全量编译与警告清理，再依据定稿文档重新设计 CI 与门禁。

## 2. 删除旧门禁

治理开始时先物理删除旧门禁与 CI，包括：

- `.github/workflows/` 下全部流水线文件；
- eng/ci 目录与各类检查器脚本；
- 文档中的门禁、检查清单类旧文件（其有效口径已吸收进新正本）。

删除在确认有用判据已由新文档承接后进行；重建以新文档为唯一依据。

## 3. 双平台编译

- Windows（MSVC）与 Linux 分别全量构建全部目标：静态库、动态库、唯一入口、测试。
- 双平台零编译警告，警告从代码修正；动态库导出与 ABI 正确。
- 平台相关源码分别编写，平台无关代码复用；平台受限项如实记录。
- 编译优化在不影响数学精度处开启，浮点归约与特殊函数保持口径，关键结果通过数值等价核对。

## 4. CI 与门禁重建

- 每条门禁对应定稿文档一条款，映射登记；条款变更时同步门禁。
- 判据可信：正确实现绿、注入对应缺陷红，正负例随附；恒真、空断言、不读真实对象的判据无效。
- 关键口径缺失 fail-closed；合法降级显式、可溯、不改科学语义。
- 分层：单元、模块、合同、集成、端到端、视觉、发布；分档：快速档高频回归，集成/测量档覆盖重型场景。
- 性能门越界真判红；并行判据采样隔离。

## 5. 结果纪律

- 红灯不以 waiver 覆盖，SKIP 不计通过；退出码、判据值、日志、证据落档。
- CI 在 Windows 与 Linux 运行，全部门禁通过、GitHub 状态全绿，记录运行链接。

## 6. 完成判据

- 双平台全量编译零警告；
- CI/门禁依据定稿文档重建并 GitHub 全绿；
- 全绿后成品帧就绪，进入目视验收。
