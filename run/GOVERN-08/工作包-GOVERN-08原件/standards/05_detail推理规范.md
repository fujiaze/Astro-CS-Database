# 规范 05 · detail 细节文档推理

本规范规定二级细节文档如何由一级正本推理产出。

## 1. 产出依据与时序

- detail 全部内容由 docs/science 与 docs/engineering 一级正本推理得出，在一级文档审稿定稿后产出。
- 写 detail 前先读最高设计相关条款，再读对应 science 与 engineering 分册，然后展开。
- detail 不引入无上游依据的科学口径；新发现的实现必要决策回溯到一级正本补要点。

## 2. detail 承载内容

| 类别 | 内容 |
|---|---|
| 模块工作细节 | 每个模块的职责、输入输出块、算法步骤、参数与边界处理 |
| 数据对象 | 字段、类型、单位、生命周期、派生关系 |
| 接口落地 | 函数签名、端口、ABI、序列化结构 |
| 阶段详细设计 | 节点顺序、注册表、调度单元、并行切分 |
| 验收与运维 | 模块级判据、配置项、故障与日志落点 |

## 3. 与一级正本的关系

- 不遗漏：一级正本的每条实施要求在 detail 有对应承接。
- 不冲突：detail 的口径与一级一致；发现一级表述不足以支撑实现时，回到一级补全，不在 detail 另立结论。
- 不复述：detail 引用一级的公式与结论编号，重点写「怎么落地」，不重复推导。

## 4. 书写要求

- 写清框架、代码范围、目录与文件、数据结构、函数名，能直接指导开发与 debug。
- 按模块或子系统分册，每册开头标注对应一级条款。
- 遵循规范 02：正向书写、无日期版本编号、论文式引用。
- 每个 detail 分册所在文件夹配极简 README。

## 5. 审查

- detail 产出后核对：一级实施无遗漏、无冲突，函数名与端口和设计一致。
- detail 与一级的一致性问题逐项订正；detail 作为代码治理的直接依据。

## 6. 完成判据

- 模块、数据对象、接口、阶段设计均有 detail 承接，可直接据以写代码；
- 与一级正本双向一致，无遗漏冲突。
