# 规范 01 · 仓库目录与文档迁移

本规范规定仓库目标目录结构，以及如何把现有文档迁移到位、清理历史内容。

## 1. 目标目录结构

```text
仓库根/
├── AGENTS.md                 干活手册（随本包提供正本）
├── README.md                 项目面向读者的入口
├── VERSION                   版本唯一事实源
├── CMakeLists.txt            构建唯一入口
├── docs/
│   ├── ASTROCS_DESIGN.md     最高设计（随本包提供正本）
│   ├── DOCUMENT_INDEX.yaml   全文档唯一索引
│   ├── GLOSSARY.md           术语
│   ├── science/              一级·科学正本
│   │   ├── algorithms/       算法推导
│   │   └── experiments/      指向实验单元的索引与定稿小论文
│   ├── engineering/          一级·工程正本
│   └── detail/               二级·细节文档
├── lib/                      源码（algorithms / infrastructure）
├── eng/                      合同、测试、CMake、工具、packaging/config
├── 实验/                      科学实验单元
└── testdata/                 真实数据与只读数据集索引
```

## 2. docs 三个文件夹职责

| 文件夹 | 层级 | 职责 |
|---|---|---|
| `docs/science/` | 一级 | 核心科学算法：公式、常数、判据、算法推导；每条结论有论文、实验或开源代码证据 |
| `docs/engineering/` | 一级 | 与科学无关的工程设计：整体架构、行为合同、接口、资源、构建、发行、日志错误等标准 |
| `docs/detail/` | 二级 | agent 据 science 与 engineering 推理产出的模块细节、数据对象、接口落地，直接指导开发 |

- science 与 engineering 是最高设计下的详细权威，平级、互不越界：科学公式不进 engineering，工程合同不进 science。
- detail 只做一级正本的展开，不另立与一级冲突的口径。

## 3. 迁移规则

1. 先按主题归并现有文档：同一主题的多份文档合并为一份正本，保留最完整、口径最新的内容，其余删除。
2. 科学主题迁入 `docs/science/`，工程主题迁入 `docs/engineering/`；一时无法判定归属的，先读内容依据其是「物理口径」还是「行为/架构口径」区分。
3. 迁移时同步去除日期、版本、任务编号、裁决叙事与历史表述（规范 02）。
4. 每份迁入文档标注上游最高设计条款；最高设计各节的下级索引指向迁入后的路径。
5. 更新 `docs/DOCUMENT_INDEX.yaml`，与迁移后的文件树逐项一致。
6. docs 一层只保留最高设计、索引、术语与三个文件夹；迁移完成后 docs 下无 algorithms、architecture、audit、contracts、modules、standards、traceability 等旧目录，其内容已并入对应文件夹。

## 4. 历史内容清理

下列内容物理删除，有用口径先吸收进新文档再删：

- 根目录旧一级文档：ENGINEERING_SPEC、CONTROL_PACK_SPEC、ACCEPTANCE_SPEC、FATDUCK_ACCESS、memory 等；
- 历史包：独立审计、工程控制目录；
- 门禁与 CI（按规范 08 处置）；
- 空目录、重复归档件、研究过程的临时副本。

删除前确认有用内容已在新正本中承接；删除在文档迁移与审稿完成后统一进行。

## 5. 文件夹 README

- 每个文件夹内放一个 `README.md`，用一到三句话说明该文件夹是什么、放什么内容，供 GitHub 网页浏览。
- README 极简，不含规则、流程与元信息；规则放对应正本。
- 示例：`docs/science/README.md` 内容为「科学正本：核心算法的公式、常数、判据与推导，每条结论由论文、实验或开源代码支撑。」

## 6. 迁移完成判据

- docs 下只剩最高设计、索引、术语与三个文件夹，主题无重复、正本唯一；
- 每个文件夹有极简 README；DOCUMENT_INDEX 与文件树一致；
- 每份文档双向可追溯；历史内容清理完毕。
