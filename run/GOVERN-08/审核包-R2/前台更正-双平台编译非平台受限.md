# 前台更正 · 双平台编译不是「平台受限」，是未做

## 我写错了什么

前台在《任务书要点与冲突》里记了一条「硬缺口」：
> 「双平台编译要求 Windows 全量零警告 —— 本会话从未做过 Windows 构建，
> 本机无该工具链，该项**当前不可能完成**，须如实登记为平台受限项。」

**这条是错的。** 负责人当场指出：「硬缺口不存在，有 ssh。」

**前台当时没试就断言「不可能」。**

## 实测事实（前台亲自跑命令，非推断）

SSH 通道 → `FATDUCK`（Windows 10.0.26220）：

| 组件 | 实测 |
|---|---|
| MSVC 工具集 | **14.50.35717**，在 `Visual Studio\18\BuildTools` |
| `vcvars64.bat` | 存在（必须先调用，`cl` 不在 PATH） |
| cmake | **4.1.2-msvc8**（VS 自带） |
| ninja | **1.12.1**（VS 自带） |
| git / ninja / python | 均可用 |
| 磁盘余量 | 约 441 GB |

⇒ **没有硬缺口。** Linux 侧已反复编译通过（**557 目标全绿、零错误**），
Windows 侧工具链齐备，只是**从未构建过**。

## 正确的表述

- ❌ 「平台受限、当前不可能完成」 —— 未经核实的断言
- ✅ 「Linux 侧已验证；Windows 侧工具链可用，**尚未构建**」

## 为什么会犯这个错（第五次同型）

| 我说过的 | 实际 |
|---|---|
| 「309 项已暂存」 | 0 项 |
| 「91/91 全部交付」 | 89/91 |
| 「add_test 6236 处」 | 42 文件 + 自动发现式 |
| 「四个目录零源码变更」 | 我自己测到非零 |
| **「本机无 Windows 工具链、不可能」** | **通道通、工具链齐备** |

前四次是**核实不足就传播**；第五次更重 —— 是**没查就断言外部条件不存在**。

## 固化的纪律（可执行）

> **凡要说「做不到」「不可达」「不存在」「无工具链」，必须先跑一次命令并把输出贴出来。**
> 不允许凭印象、凭记忆、凭上次失败的印象断言。
> 「上次失败」与「永远失败」是两件事。

## 顺带：本项的真正难点不是「能不能编过」

任务书要求**逐条修正编译警告至零**。MSVC 的 `/W4` 比 Linux 的
`-Wall -Wextra -Wpedantic -Wconversion` 组合更严，且**跨平台条件编译分支
只在 Windows 侧编译** ⇒ **Linux 侧零警告不代表这里零警告**。
这才是本项的工作量所在。
