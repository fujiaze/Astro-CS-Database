1. **§4 的锚点解析含启发式**：仓根相对路径优先，其次后缀唯一、基名唯一。实测**第 1 遍交付件的引用里裸文件名占 74.7%–83.5%，仓根相对只占 10.3%–20.2%**（§5.1bis F2，两组分词口径不同）。带目录但写成相对路径、或干脆只有裸名的引用，**无法机械判定它当时指向哪个文件**。⇒ **§4.2 的「载体已删 5,887」是上界不是定案**，逐条判定须由第 2 遍各车道做。同理，§5.1bis F3 的「198 条仓根引用已死 / 其中 143 条基线受控后被删」在**逐文件层面是近似值**（`CMakeLists.txt` 这类歧义裸名可能解析到错误文件），但**聚合层面是硬的**（整棵测试树受控数为 0）。
2. **§2.2 的 63 片是 SRS-1/SRS-2 的机械结果**，未做人工负载均衡；`docs/engineering`（84 份 / 16,483 行 / 2 片）等层内单片行数会偏离 11,000。
3. **§3.2 的排序用「锚点可复用率」代理「第 1 遍阻断密度」**。后者只能逐份读得（台账 §2.2 已证：三种正则给出 455 / 448 / 4183 三个互斥值）。⇒ 排序是**可复现的代理排序**，不是「阻断密度」的精确排名。**若需要精确阻断密度，须先重出 §4 的阻断小节台账。**
4. **§1.3 只复核了台账甲类 A1–A7 共 7 条**。台账甲类共 13 条、A9/A10/A13/A14 与乙丙丁各档**本单未逐条复核**。
5. **A5 只做静态阅读**：`return 0` 对调用方的成功语义需实跑 e2e 才能判，按红线 §9 列待前台执行项，本单**未跑**。
6. **§5.1 的特征扫描是正则代理**：命中与否不等于做没做（例如「符号级枚举」若写成中文描述「按符号表枚举」会被记为未命中）。**故 §5.1 的 41% / 56% / 57% 是下界**，方向可靠，绝对值偏低。
7. **未读 `run/GOVERN-08/审核包-R2/` 下 2 个未跟踪在制品**（`00-符合性证据盘点.md`、`00-门禁设计正本输入.md`），未评估其内容是否与本计划重叠。
8. **本单零 git 写、零编译、零执行仓内脚本**：所有分母与分类均由内联复刻谓词得出，与 `rebuild_denominator.py` 的输出**未经逐文件比对**（该脚本属仓内脚本，红线禁止执行）。
