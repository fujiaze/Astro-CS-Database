## 3 B1 的独立代码取证结论

### 3.1 四路证据逐条复现

**证据 1 — 权重函数本体。** 作者给 `weight_chain.cpp:93-104`，**行号准确**。原文：

```cpp
// lib/algorithms/integration/phase2_integrate/src/weight_chain.cpp:93
bool weight_from_snr(double snr, double reference_flux, double* out_weight,
                     std::string* err) {
  ...
  if (!positive_finite(reference_flux)) {
    set("reference_flux F_ref must be finite and > 0 (w = SNR^2 / F_ref^2 undefined)");
  if (!positive_finite(snr)) {
    set("SNR must be finite and > 0 (flux-type F_ref/sigma_F)");   // :101
  }
  const double w = (snr / reference_flux) * (snr / reference_flux);  // :104
```

`snr` 与 `reference_flux` 确为两个独立入参，`:101` 失败串逐字含 `flux-type F_ref/sigma_F`。**若分子是逐源实测通量，该函数签名根本不需要 `reference_flux` 这一入参。** 成立。

**证据 2 — Phase1 生产者。** 作者给 `snr_frame_science.cpp:188-200`，**行号准确**。原文 `:188`–`:196`：

```cpp
SnrSourceRow ref_row;
ref_row.id = "__frame_reference_median_fwhm__";
ref_row.flux_adu = ref_flux;          // :190  参考通量本身被当作该行的源通量
ref_row.fwhm_px = med_fwhm;
SnrSourceResult ref_res;
if (!source_snr(ref_row, cfg, &ref_res)) { ... }   // :193  同一个 Horne 函数
...
out.reference_snr_f = ref_res.snr_optimal;         // :199
```

`source_snr()`（`:40`–`:63`）是纯 Horne 最优提取，入参即 `row.flux_adu`。把 `F_ref` 填进 `flux_adu` 再求 `snr_optimal`，得到的**就是** `F_ref/σ_F`。写进 HiPS 头的 `ACSD_FRAME_SNR` 取自此处。**成立，且这是最强的一路。**

**证据 3 — 配对性定理。** 作者给 `:165-173`，**行号准确**。原文逐字：

```
//   SNR_f = a_f·F_ref/σ_f  ⇒  SNR_f²/F_ref² = a_f²/σ_f² = w_f
// 成立当且仅当分母 F_ref 与定义 SNR 时所用参考通量是同一个。
```

定理的正确读法是：`w = SNR²/F_ref²` 要等于 `1/σ_F²`，**必须 `a_f = 1`**，即分子必须就是 `F_ref` 本身。同一文件 `:171`–`:173` 进一步说明逐帧检出通量中位数回退会「丢掉帧间标度因子 `a_f²`」而 `unclosed_invalid_reference_flux`。**成立。**

**证据 4 — 冻结 schema。** 作者称控制点值 = `F_ref/sigma_F`。`eng/contracts/schemas/unified/sparse_snr_layer.schema.json` 中 `control_points.items.properties.sparse_snr_value.description` 逐字：

> 控制点**绝对**通量型 SNR 值 = F_ref/sigma_F,c（无量纲，与 frame_snr 同物理口径、同逐帧参考通量 F_ref；非相对因子，不得再乘帧级标量）

**成立。**

**补充独立第五路（作者未列，但支持同一结论）**：`weight_chain.cpp:80` 有 `kUnclosedWrongSnrSemantics` 闭合码——代码层存在一个专门用于拒绝「SNR 语义用错」的 fail-closed 分支，说明维护者确实把 `source_snr` 与 `frame_snr` 当两个不可互换的对象，这与顶点 `:177` 的新表述同向。

### 3.2 「原 §2.2 是不是本来就错？」——是

改前 `:124` 原文：

> 交付物是 PSF 信号信噪比：由星点 PSF 测光给出逐源 `SNR_F = F/σ_F`，`F` 为已扣独立局部背景的拟合域通量，`σ_F` 为逐源通量不确定度。

**两处错**：
1. **分子错**——交付物是 `frame_snr` + `sparse_snr_layer`，二者分子是 `F_ref`（证据 2、4），不是逐源实测通量；
2. **来源错**——「由星点 PSF 测光给出」不成立。帧级 SNR 在参考轮廓处求值，通量输入是 `F_ref`（配置/公共锚/固定星等导出，见 `frame_snr.schema.json` 的 `reference_flux_source` 枚举 `fixed_magnitude | group_median | config | unavailable`），**不是**对本帧星点做测光的结果。FWHM 来自星表、噪声来自本帧，通量不是。

作者**同时删掉了「由星点 PSF 测光给出逐源」这个短语**，改写为「参考轮廓取星点目录的中位 FWHM 加本帧 `sigma_sky`」。这一处与代码 `:182`（`med_fwhm = median_of(used_fwhm)`）、`:183`（`ref_flux = cfg.reference_flux_adu`）逐项对应。

### 3.3 「订正是改正，还是把更根本的错误固化成正本？」

**答：是改正，不是固化。** 理由：

1. 定案方向由**四路互相独立的证据**支撑（权重函数签名、Phase1 生产者、配对性定理、冻结 schema），四路分属不同层（算法接口、Phase1 聚合、理论注记、合同），不是同一句话的四处复述；
2. 代数上该方向是**唯一**能同时满足 `w = SNR²/F_ref²` 与 `w = 1/σ_F²` 的选择——分子换成逐源实测通量，两个等式立刻不相容。`:332` 新增的「该恒等式要求 `SNR` 的分子与 `F_ref` 是同一参考通量，分子换成逐源实测通量后 `1/σ_F²` 不成立」**正是恒等式的成立条件，是本次整改最有价值的一处增补**；
3. 作者没有回避更根本的问题：它把「由星点 PSF 测光给出」这个**来源性**错误一并删掉了，而不是只换符号、留下错误来源。

**但定案正确不等于执行完备。** 作者在同一行引入了新问题：`:124` 把 `σ_F` 绑定到「该轮廓」（参考轮廓），紧邻的 `:125` 又把同一符号 `σ_F` 绑定到「该源通量」（逐源）——见 N3。`:158` 与 `:332` 更是把「`σ_F` 口径定义处」同时指派给三个不同小节——见 N2。

**残留风险（须登记）**：顶点 `:124` 的分子 `F_ref` 与实验单元正本 `实验/absolute-snr/docs/frame-snr-canon.md:14`–`:15` 的 `SNR_frame = F_signal / sigma_F`、`F_signal` 已扣局部背景**不一致**。见 N5。
