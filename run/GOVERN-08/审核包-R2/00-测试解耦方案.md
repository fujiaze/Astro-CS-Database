## 3. 解耦方案

### 3.1 目标状态（两态互不污染）

```
不装门禁（默认，唯一产品态）
  └─ 构建图 = 根 CMakeLists.txt + 14 个子图；零门禁源文件参与
  └─ 验收 = 编译 + 运行 + 产品 manifest 17 个 unit 全部落位

装门禁（可选态，显式选择）
  └─ 独立源码根 gates/，自带 CMakeLists.txt 或纯 Python runner
  └─ 从 gates/ 配置：cmake -S gates -B build/gates
  └─ 根 CMakeLists.txt 全文不出现 gates ⇒ 不可能误入默认路径
```

### 3.2 「不装」是什么样——**必须实测验证**（本车道已做静态半边，构建半边列待前台）

不装门禁时项目完整 = 下列 5 条**同时**成立。

| # | 断言 | 本车道静态结论 | 构建实测 |
|---|---|---|---|
| 1 | 默认图零门禁源文件 | ✅ 15 个 CMakeLists 闭包内，`eng/tests/` 仅 `conformance/noop`（产品件） | 待前台 |
| 2 | 默认图零测试框架注册 | ✅ 可达性口径为 0（§1.2） | 待前台 |
| 3 | configure 成功 | 未跑（车道禁编译） | 待前台 |
| 4 | 全量构建成功 + `acsd` 产出 | 目标已声明 `CMakeLists.txt:1304 add_executable(acsd ...)` | 待前台 |
| 5 | 产品 manifest 17 unit 全部落位 | `eng/packaging/acsd.product.json` 现列 17 件 | 待前台 |

静态半边的复跑命令见 §6.1。**「完整可编译可运行」这一条本车道只能给静态证据与执行程序，
不能给结论——按 AGENTS.md §9，需编译/测试才能完成的验证列为待前台执行项。**

### 3.3 ⚠️ 阻断解耦的实测真问题：`eng/tests/` 里躺着一个已安装产品模块

`eng/tests/conformance/noop/`（5 件）**不是**测试件：

```bash
grep -n 'acsd_noop' eng/cmake/install_layout.cmake
#   :46   acsd_runtime acsd_io acsd_noop acsd_cpu_baseline     ← 产品 install unit 清单
#   :85   install(TARGETS acsd_noop ...)                        ← 真安装规则

grep -n 'MOD-NOOP' eng/packaging/install-tree.contract.json
#   :11   { "unit_id": "MOD-NOOP", "kind": "module",
#           "install_path": "modules/acsd_noop.so", "required": true }   ← required

grep -n 'MOD-NOOP' eng/packaging/acsd.product.json
#   :11   "module_id": "acsd.conformance.noop", "status": "IMPLEMENTED"
```

**⇒ 后果**：任何把 `eng/tests/` 当作「门禁树、可整体删除/整体另置」的政策，都会删掉一个
`required: true` 且 `IMPLEMENTED` 的已安装产品模块。**这是本方案唯一的硬前置**——
`eng/tests/conformance/noop/` 必须先迁出 tests 树（或明确豁免），之后才谈得上「另置门禁」。

### 3.4 「装」是什么样——三种可选形态（**推荐第 1 种**）

| 形态 | 显式选择方式 | 根图是否被污染 | 评价 |
|---|---|---|---|
| **① 独立源码根（推荐）** | `cmake -S gates -B build/gates`；`gates/CMakeLists.txt` 内 `add_subdirectory(.. acsd-build)` | 否 | 根图零改动；门禁可选由**选不选这个 configure** 表达 |
| ② 纯 Python runner | `python3 gates/run.py --judge docs/science/...` | 否 | 最轻；与「基于文档（不读代码）设计判据」的前置一致 |
| ③ 仓内 CMake option | `-DACSD_GATES=ON` | **是** | ⛔ **不采用**：这正是「嵌回默认构建」 |

**不变量（机器可查）**：

```bash
grep -c 'gates' CMakeLists.txt        # 必须为 0
grep -cE 'eng/tests' CMakeLists.txt    # 当前为 1（:324 conformance/noop），迁出后必须为 0
```

形态 ① 与 ② 的区别只在是否需要 CMake；门禁判据本身应走形态 ②，
因为负责人已明示**门禁设计的前置是文档定稿、不是读代码**——用 Python 直接消费 `docs/` 更贴合。

### 3.5 明确不得做的事

- 不得把 `eng/tests/validation` 的任何文件加进根图或任何子图；
- 不得把 `CMakePresets.json` 的 `testPresets` 当作门禁挂载点（见 §4.3）；
- 不得让门禁产出**发布判决**（承接 `前台裁定-门禁定位与推进次序.md:44`）。
