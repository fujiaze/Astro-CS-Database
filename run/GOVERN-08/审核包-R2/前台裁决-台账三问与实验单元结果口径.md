# 前台裁决 · 台账三问 + 实验单元「结果」口径

## 一、丁类 23 条（ACR 退役）—— **裁定：计入关闭**

车道把它单列并标 UNRESOLVED、不替我选，这是对的。裁定理由：
- 这 23 条不是「缺陷还在」，而是「**生产实现本身被删**」；
- 关键事实：**那条加速路径在本轮动手之前就字面量返回假**，从未在生产启用过一次
  ⇒ 退役它**不改变任何一次实际执行**；
- 退役是**负责人裁定的动作**，动作已完成且编译验证通过（556 目标零错误、链接目标缺失 0）。

⇒ **计入关闭。** 剩余未关闭按**口径 A = 599** 计（不是 622）。
⚠️ 但**不得**据此把「甲类 13 条」也核销 —— 甲类是另一批（指向生产行为缺陷），
**删载体不关闭它们**，那条红线仍然有效。

## 二、两个同名「§6」的命名空间冲突 —— **裁定：统一**

车道指出：台账 §6 是「作者推翻交付件的记录」，而整改件 §6 是「本车道推翻台账的记录」，
**两者同名但含义相反**，且台账原文不含整改件那三条 ⇒ 每轮都会有人按原文多算。

**裁定**：审计推翻记录**按所在文件定位，不按节号定位**；
后续所有跨文件引用**必须写「文件名 + 该文件内的章节标题」，禁止只写 §编号**。
已要求台账车道在其两份文件里补一条命名空间说明。

## 三、S4 的 112 条源判决文本不在仓内 —— **裁定：登记为不可回溯，不再假装可核**

车道实测：S4 那 112 条的源 ID **只存在于台账自己里**，`git grep` 在对应基线零命中。
⚠️ 而台账创建于 `9712b4af` —— **比它要判定的那些提交都晚**。

**裁定**：
- 这 112 条**降级为「仅有二手结论、无一手判决文本」**，在台账里显式标注；
- **不得**把它们与有一手文本可核的条目**同等计入**收敛判断；
- 若要恢复可回溯，须重新对那批材料做一遍有判决文本的审稿 —— 归入后续遍次。

## 六、一处必须记的：台账车道自曝的错误

它推翻**自己上一版**的一个「已关闭」：某样条缺陷的三个曲率项全是正确值的 2 倍，
而上一版台账**拿那个错误的常数当证据给自己背书**；前台第一次复验时也照抄了。

⇒ **这与本轮反复出现的同一形态一致：拿一个看起来合理的量当证据。**
台账车道据此怀疑自己更早的两处组计数也是这么来的 —— **那两处本轮已证伪或要求独立复算**。
**这种「自己的证据给自己背书」是最难自查的一类，因为它读起来完全合理。**
