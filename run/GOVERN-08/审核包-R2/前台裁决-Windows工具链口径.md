# 前台裁决 · Windows 构建的工具链口径

## 车道报了一个真冲突，前台裁定：**按冻结合同用 VS17 生成器，不用 Ninja、不用 VS18**

### 仓内冻结合同的原文禁令
`eng/packaging/schemas/preset-contract.json` 逐字列出禁用项：
```
"vs2026":           ["vs2026", "Visual Studio 18"]
"ninja_generator":  ["Ninja", "ninja"]
"future_toolset":   ["v144", "v145"]
"static_crt":       ["/MT"]
```
对应 preset `win-msvc-17.14.39-x64` → 生成器 **`Visual Studio 17 2022`**。

而前台给车道的实测环境是 **VS18 BuildTools + MSVC 14.50 + cmake 4.1.2 + Ninja**
⇒ **前台给的指令违反仓内冻结合同。** 车道据此拒绝擅自使用，**处置正确**。

### 裁定
1. **一律按 preset 走**（VS 17 2022 生成器）。**不得使用 Ninja、不得使用 VS18。**
2. 若该主机上确有 VS2022 而探测时我漏看 ⇒ 直接用，无需再请示
   （前台先前探测已看到该目录下**同时存在**「18」与「2022」两个条目，VS2022 很可能在）。
3. 若**只有** VS18 ⇒ **如实登记为「工具链漂移」**，并**同时**做两件事：
   - 用 VS18 跑一次**只为暴露警告**（不作为交付构建），把跨平台警告一次收干净；
   - 交付构建**记为「因工具链漂移未完成」**，并写清差在哪（生成器版本、工具集版本、
     CMake 版本、SDK 版本四项逐项对比）。
   ⚠️ **不得**把 VS18 构建产物当作「双平台全量编译通过」交付。
4. **不得**为迁就本机而改 preset 或改合同禁令 —— 那是把标准改成迁就环境。

### 关于「禁令没有执行器」
车道查出：执行校验的脚本已在删旧门禁那一轮物理删除，`.github/workflows/` 也没了
⇒ **这些禁令目前只有合同文本、没有机器执行**。仓库自己已登记此事并注明
「需负责人决定是恢复执行器还是改由 CI 侧承担」。

**前台处置：不恢复执行器。** 依据是负责人裁定「所有判决全部作废、CI 删干净」。
⚠️ 但**这意味着工具链漂移不再会被任何机制自动拦住** ⇒ 只能靠人按合同核对。
**本单的裁定因此格外重要**：它就是当前唯一的守口。

## 关于主机在线窗口
车道实测该主机**有在线窗口**（约 07:00–23:30），前台实测工具链成功后 70 秒它即掉线。
⇒ **不是「不可行」，是「当下休眠」。**
**裁定：等窗口重开后重试**，不得写成「永久不可行」。车道已起轮询器，处置正确。

## 前台自己的错误（须记录）
前台派单里写的「主机 `FATDUCK`（**10.0.26220**）」—— **`10.0.26220` 是 Windows
版本号，不是 IP**。真实地址是 Tailscale 地址。
⚠️ 该串会被 `inet_aton` 按三段式解析成 `10.0.102.108` ⇒ **照抄会去连一台无关主机，
并把结果误判成「主机不可达」。** 车道据此自查纠正，处置正确。

⇒ **派单里凡写主机身份，必须写「名称 + 真实地址」，版本号不得与地址混写。**
