# T08 断言副本检测器

## 这个工具是什么，不是什么

一句话：把「一处改动 → 全仓同步」从靠人记得，变成机器可查的分母。

这个项目三轮审稿暴露的病根不是审得不够狠，而是**同一断言天然散落多处，而审稿与订正是分片做的**。git log 里三轮结论依次是：

- `128a1b00` 第一轮：四车道全部零收敛，发现项远超预期
- `6934b1a1` 第一轮订正：五条车道逐条落实
- `c0bec7f7` 第二轮：零收敛，且订正本身引入了三十余个新问题
- `18dd6c64` 把重复断言收敛为唯一正本（止血轮）
- `8a6eb88d` 第三轮：**方向问题已统一，但止血又造矛盾，收敛度量本身不可信**

也就是说，专门做的止血轮本身制造了新矛盾，而那个本该证明问题已消除的计数，本身不可信。工具要治的就是这两件事：把「断言散落在哪」查清楚，把「计数在什么口径下数的」钉死。

**不是什么**：不是判据，不产出阻塞退出码，不进默认构建，不被任何门禁调用，不自动改任何文件。判定由人阅读上下文做出。

交付物：

| 件 | 路径 |
|---|---|
| 工具 | `eng/tools/doccheck/check_assert_dup.py` |
| 目录说明 | `eng/tools/doccheck/README.md` |
| 本报告 | `run/GOVERN-08/审核包-R2/T08-断言副本检测器.md` |

文件名与并行车道的 `check_anchors.py` 不冲突：全仓现存的两份锚点脚本在 `run/SCI-FIX-NOISE-01/scripts/check_anchors.py` 与 `run/EXPORT-CROP-01/check_anchors_into_mine.py`，目录与 basename 全异，且语义不重叠——它们锚定「代码行号锚点是否失效」，本工具锚定「断言特征串在哪些文件、哪些层次、是否逐字一致」。

## 一、工具能抓什么

### 五种查询模式，各自针对一种真实发生过的形态

| 模式 | 抓的形态 | 对应三轮审稿里的哪一条 |
|---|---|---|
| `--text` | 同一断言逐字散落多处 | 「只改了 8 个副本中的 1 个」；`数据对象（各自具名）` 21 处 |
| `--regex` | 正则锚点定位 | 「正则形态写死，变了形态就漏」 |
| `--ident` | 大小写混合 / 下划线风格不同的同一类型名 | `GaiaCreateDiagnostics`（`aCr`）被终检正则零命中 |
| `--ident --prefix` | 前缀包含关系 | `bilinear` ⊂ `bilinear_4quad`，逐字相等比较必漏 |
| `--num` | 同一常数的旧值 / 截断值 / 近似值 | `1.044` vs `1.0415`；`211034.6` 禁抄值；`1.482602218505602` vs `…023` |
| `--strength` | 强度词出现而同段无限定词 | 「一律以 schema 为准」与「本列是唯一正本」同文件相隔 48 行 |

### 分层判定：正本讲原则、细节讲实现、登记册讲索引

按项目权威链分 12 层，每层标注「该层该讲什么」与「初判时怎么用」：

| 层 | 路径 | 该层该讲 |
|---|---|---|
| L0 顶点 | `docs/ACSD_DESIGN.md` | 只写顶层结论 |
| L1 正本·科学 | `docs/science/**` | 公式、常数、判据、推导 |
| L1 正本·工程 | `docs/engineering/**` | 架构、行为合同、工程标准 |
| L2 细节 | `docs/detail/**` | 模块工作细节、数据对象与接口落地 |
| R 登记册·地图 | `docs/DOCUMENT_INDEX.yaml` | 全文档集唯一地图 |
| R 登记册·术语 | `docs/GLOSSARY.md` | 术语与单位口径 |
| L3 合同面 | `eng/contracts/**` | schema 与机器可读合同 |
| L3 配置面 | `eng/packaging/config/**` | 机器可读配置与默认值、溯源锚 |
| L3 代码 | `lib/**` | 实现 |
| L3 工具 | `eng/tools/**`、`eng/tests/**` | 工程工具与测试集 |
| EXP 实验单元 | `实验/**` | 实验报告、复现脚本、裁决记录 |
| GOV 审核包 | `run/**` | 审稿、订正、裁决过程记录（默认不扫） |

前九层是实测出来的：审稿记录里副本分叉**几乎全部出现在跨层处**，同层内反而少；而 `L3-CONFIG` 这一层是实测后补的——「配置锁旧值、正本已改」是本仓的活分歧，只扫 docs 会整层漏掉。

### 逐字一致性：数值与公式是否逐字相同

- `--text` / `--ident` 给逐字串；
- `--num` 给数值近邻 + **相对差（科学计数法）** + 公共前缀位数 + 邻居类别（同前缀·不同精度 / 同量级·疑似旧值 / 同整数部·疑似旧值）；
- 归一化（NFKC + 上下标折叠 + `√`/`sqrt` + 乘号统一 + 去空白）后形态唯一 = 同一个式子的不同写法，归一后不同 = 需要人看。

### 口径块：直接针对「收敛度量本身不可信」

第三轮审稿判定收敛度量不可信，最直接的证据是**跨口径配对**：记录里「`§` 改前 709 → 改后 46」这一行，全树改前是 709、子集改后是 46，两个不同口径被配成 before/after。另有「计数 ≠ 行数 ≠ 文件数 ≠ 断言数」、「33 行」被当成「33 条断言」（实为 9 条）。

所以每条查询的输出都自带口径块：

```
搜索根 / 查询模式 / 查询原文 / 前缀阈值 / 相对差阈值 / 文件类型过滤 /
剪掉目录 / 额外排除 / run_面 / 大小写策略 / 行形态过滤 / 计数单位 /
扫描文件数 / 耗时秒 / 禁止：不得与其它口径或轮次的数字配成 before/after
```

**计数单位**这一项是刻意加的：本工具的口径是「命中处数（一行内多次出现按多次计）」，文件数与层数另计。第三轮实测 T06-r2 记录里的 `§` 计数是 36（出现次数）还是 32（含 `§` 的行数）——两个数都不是记录里写的 35。工具把这三个量分开报，不许折叠成一个。

### 同名不同义：标出来，不当成重复

工具的初判词表里，「同名不同义·候选」是一档而不是错误：

```
同名不同义·候选 —— 归一后形态 N 种，锚点之外表述有实质差异；
                   须逐处读上下文确认是不是同义
```

而且**工具从不输出「这是重复，去删掉」**。它输出的是「这些行长得像，请读」。这一点是硬约束，不是文风：三轮审稿里被推翻的判定全部是靠重读原文推翻的，而被推翻的**自证数字**全部出自计数。

**负例已知漏检：1/6**（NEG-4）——这不是 bug，是逐字匹配的定义后果，工具的 banner 与报告都写明了。

⚠️ **NEG-6 是我写报告时自己踩的坑，保留在报告里。** 我最初把 `1.044` / `1.0415` / `1.0442` 写成「同一常数三套有效位数并存」的正例。复核原文后发现不是：

| 位置 | 说的什么 | 性质 |
|---|---|---|
| `docs/science/drizzle/DRIZZLE.md:255` | 全天穷举给出 `0.9941 → 1.0196 → 1.0322 → 1.0384 → 1.0415`（`nside = 4, 8, 16, 32, 64`），`:256` 明写「序列随 `nside` 单调上升」 | nside ≤ 64 的上确界 |
| `lib/algorithms/drizzle/healpix_drizzle/spherical_overlap.cpp:30-34` | 「`nside=256` 全局最大 = `1.043827` x hp_res」「随 NSIDE 单调收敛于 `~1.044`」 | **同一序列的更高一档**，且只出现在注释里（`grep -rn "1\.044" lib/ --include=*.cpp` 排除注释后 **0 命中**） |
| `docs/engineering/governance/UNRESOLVED.md:35` | 裁-16 把 `1.0442` 与 `9003`、`1.25`、`min_samples` 并列为「门限本身无推导」的待裁项 | 另一个待裁门限，与上两者未必同量 |

所以 `1.0415`（nside ≤ 64）与 `1.043827`（nside = 256）是**同一条单调序列的两档**，不是分歧。工具把三个数摆在一起是对的；**我据此写出的「三套值并存＝矛盾」是错的，已改。** 留在报告里是因为它恰好演示本工具的核心纪律：命中是分母，判断必须来自阅读——**包括报告作者自己的阅读**。

#### NEG-1：量级护栏是补过的，补之前会误报

第一次实跑 `--num 1.482602218505602` 时命中了 `实验/engineering-evidence/l2_performance/gates/real4_w16_gate.json:4066` 的 `1482.63` 和 `docs/science/algorithms/PHASE2_SAMPLER.md:78` 的 `14.826`——它们与 `1.4826` 只共享 5 个字符前缀，但差 10 倍与 1000 倍，不是精度变体。

补的护栏：公共前缀必须**越过候选数的整数部至少 2 位**，且相对差 < 0.5。补后重跑，这两条不再命中；控制组确认它们确实存在于仓内（`grep -rln "1482.63" 实验/` 有命中，`grep -n "14.826" docs/science/algorithms/PHASE2_SAMPLER.md` 命中 `:78`），所以「不命中」是护栏生效，不是查不到。

#### NEG-2：命中 ≠ 矛盾，这是工具最重要的负例

`docs/science/algorithms/DRIZZLE_GEOMETRY.md:167-171` 原文：

> **数值纪律**：常数按上式**求值**，取值来源 = 求值结果；`211034.6` 与上式相差 −1.97e-4（相对），会使 `nside` 决策在每个倍频程的 `finest ∈ (211034.6/2^k, 211076.285/2^k)` 窗口内**少取一阶**

`211034.6` 是仓内明令「不得使用」的禁抄值（`docs/science/DISPUTE_RESOLUTION.md:204`：「`211034.6` **不得使用**」）。`--num` 照样命中它。但读上下文就知道：这是**故意写出来的反例**，用来说明抄错值的后果。工具输出带上下文全文，读者一眼能看出这是反例——这正是「工具帮人查、判定由人做」的落点。若工具把这条标成「数值分歧·需人裁」并暗示该改，那就是误伤。

同一次查询还命中 `docs/science/resample/RESAMPLE.md:269` 的 `211076.2851`（正本值 `211076.28514206142` 的 7 位截断，出现在参数表里），这条读起来更像真需要人看的候选。**同一模式、同一查询，一个该改一个不该改**——这就是为什么计数与命中都不能当判据。

#### NEG-3：本仓已实测过的伪阴性，工具复现了

```
$ python3 eng/tools/doccheck/check_assert_dup.py --text "唯一术语权威"
命中 0 处 / 0 个文件
$ python3 eng/tools/doccheck/check_assert_dup.py --text "唯一性登记"
命中 1 处 / 1 个文件   →  docs/DOCUMENT_INDEX.yaml:86
      上下文：      duty: "全项目术语与别名唯一性登记（词典锚点）"
```

而 `run/GOVERN-08/审核包-R2/T07-重复断言收敛-detail-glossary.md:352` 的自证段逐字写：

> 索引中与本单相关的字符串实测：`数据对象（各自具名）` 0、`FITS 产品` 0、**`唯一术语权威` 0**、`point_source_information` 0…

**那个「0」是伪阴性**：索引确有该职责的错误声明，但它写的是「唯一性登记」，不含搜的五字。止血轮用自己的检索键证明「索引没问题」，而真正的问题恰恰在索引里。这是本项目实测过的「抓不到不含该子串的行」，工具复现了它。

至于索引的「唯一性登记」与 `docs/GLOSSARY.md:5` 的「不是术语定义的正本」**是不是真矛盾**——工具不下判断。读原文后可以有两种读法（索引说的是「叫法与别名的唯一登记」，词典说的是「不是定义正本」），也可能仍是台账滞后。**登记给前台裁决。**

### 准确率小结

| 口径 | 数字 |
|---|---|
| 正例命中率 | **6/6 = 100%**（POS-7 另计） |
| 负例误报率 | **0/6 = 0%** |
| 负例已知漏检 | **1/6**（NEG-4，逐字匹配的定义后果） |
| 分母 | 正例 6 条、负例 6 条，样本小；`--strength` 与 `--ident --prefix` 的噪声量见第三节，**不计入准确率**，因为它们是喂给阅读的候选流，不是二值判定 |
