## 2. 本片判定与最重 3 条

**判定：不通过。** 本片承载 `.hiss` / `.hcsd` 科学产品的写入与读取路径。发现**一条权威规范与实现直接矛盾**（Magic、版本号、压缩级别三处），以及**一份被提交的测试输出快照，其汇总计数器全为零、却宣称 21/21 通过，并把两处真实缺陷记为 `OK`**。

### 最重第 1 条 · `HEALPIX_FORMAT_SPEC.md` 是权威正本，但它与实现的 Magic、版本号、压缩级别三处直接矛盾

AGENTS.md §3 规定**文档高于代码，冲突时以文档为准订正代码**。本片实测三处正面冲突：

| 规范（权威） | 实现（实测） |
|---|---|
| `:259` Magic = **4 字节** `0x48 0x49 0x53 0x53`（`'HISS'`） | `hiss_writer_smoke.cpp:103` `memcmp(head, "ACSHISS\0", 8)` —— **8 字节** `"ACSHISS\0"` |
| `:344`「当前格式**未在文件中显式存储版本号**，版本通过 Magic 标识区分」 | `hiss_writer_smoke.cpp:107-112` 从偏移 8 读 `uint32_t ver` 并断言 `ver == 1` —— **版本号确实被存了且被检验** |
| `:38`、`:262`、`:274`、`:316` JSON 头用 zstd **level=5** 压缩 | `test_output.txt:7`「`[hiss][codec] 内置注册: ZSTD (level=3)`」 |

**为什么这条最重**：规范 §2.2 / §4.1 给出的字节级布局（4+4+4 头部，之后紧跟 ipix/pixel/snr 三个平铺数组）与实现**结构性地不同**——实现是 **tiled + subblock** 形态（`test_output.txt:84-89` 可见 `子块 type=1 flags=0x0001 uncompressed=12288 compressed=12288 codec=0 transform=0`、`header_offset=20 header_size=418`）。**这不是一个字段写错，是整份正本描述的是另一个格式。**

**后果**：任何按本规范实现的第三方读取器（`:370-380` 明写本规范面向浏览器按需加载的互操作场景）都会在不同时刻从两个不同的偏移开始解析 `.hiss`，且**两边都会自认为合规**。

### 最重第 2 条 · `test_output.txt:293-298` 汇总计数器全为零，却宣称「实际通过: 21 / 21」

被提交进仓的测试输出快照，末尾：

```

总计: 21
通过: 0
失败: 0

```

**`通过` / `失败` / `跳过` 三个计数器全部是 0**，而紧邻的 `实际通过` 是 21/21。这精确落在本项目已固化的检查项「**打印但不计入汇总 ⇒ 可制造绿色产物**」上：**逐条 `OK:` 行印在文件里（21 条），三个真正的汇总计数器从未被递增，最后用另一条路径报出一个 21/21。**

### 最重第 3 条 · 同一份快照把两处真实缺陷记为 `OK`

**TEST 13（`:149-152`）**：

```
[hiss][reader] SNR 数据长度不匹配: got=52 expected=28 (n_points=0)
  [已知问题] read_tile_snr 返回 -4 — Writer/Reader SNR 二进制布局不一致
  Writer 写入 52B (含 snr_phot/median_snr/idw_power 三个 double), Reader 期望 28B (仅 n_points+points)
  OK: SNR 独立读取测试完成 (已知问题: Writer/Reader SNR 二进制布局不一致, 待底层修复)
```

`read_tile_snr` **返回 -4（失败）**，文件不匹配的**真实字节数都被记下来了**，然后被转写成一行 `OK:`。这是**恒真门在测试层的化身**：一个已知的、已量化的、写读双方布局不一致的缺陷，被计为一个通过项，抬高了 21/21 里的 1。

**TEST 16（`:202-203`）**：测试名为「**未知必需子块拒绝**」，实际行为是

```
  read_tile 返回 0 (当前实现按 type 查找, 未全扫描未知必需子块)
  OK: 未知必需子块测试完成 (行为记录: Reader 按 type 查找, 未主动拒绝未知必需子块)
```

`read_tile` 返回 **0 = 接受**，测试名声称的是「拒绝」，输出却是 `OK:`。**一条以「拒绝」命名的判据，在「不拒绝」时也判绿。**

**机理**：这不是断言写错，而是**判据的期望值被写成了「记录当前行为」而不是「要求的为」**。修法不是把这两行改成 `FAIL`，而是先裁决：这两项到底是**未完成的必需功能**（应从分子中剔除并挂红灯），还是**已接受的现状**（则不应出现在「正确性测试」的 21 里）。这是产品决策，不是审稿人可代决的。
