## 3. 待修项 1 · 退出码语义互斥（P0，最优先）

### 3.1 先查生产代码，判定哪一侧语义为真

派单要求「先 read 生产代码确认哪个语义是真的」。结论：**正本正确，冲突方不是重复声明，而是工具局部码。**

机器事实源 `lib/infrastructure/cli/exit_codes.h:7-19`（`acsd::ExitCode`，文件头自述「本文件是 11 个
退出码在仓库内的唯一定义处」）：

| 码 | 枚举名 | 行 |
|---|---|---|
| 3 | `INPUT` 输入缺失、格式或 hash 错误 | `:10` |
| 4 | `SCIENCE` 科学验证/数值不变量失败 | `:11` |
| 5 | `BACKEND` backend ABI、签名、CPU 特征或加载失败 | `:12` |
| 6 | `COMPUTE` 计算执行失败 | `:13` |
| 7 | `IO` I/O 失败 | `:14` |

`ERROR_HANDLING_STANDARD.md:87-99` 的码值语义表与该头文件**逐名逐值完全一致**（0/2/3/4/5/6/7/8/9/10/70），
且 `docs/ACSD_DESIGN.md:348`（最高设计 §7.2）按序叙述与之一致：成功、参数或配置错误、输入缺失、
科学不变量失败、后端加载失败、执行失败、I/O 失败、输出验证失败、用户取消、磁盘写满、未分类内部错误。
**三级链路自洽 ⇒ 正本无误，不动正本语义。**

### 3.2 冲突的真实成因

`PUBLIC_API.md` 原 §「退出码表（stage2 进程级）」逐条**忠实记录了实现**：`stage2.cpp:201-219`
确实 `return 3`。进一步实测：

- `stage2.cpp:11-29` 的 include 面**无** `exit_codes.h`；全文件**无** `ExitCode` 引用（仅用
  `acsd::crypto` / `acsd::healpix` 命名空间）；
- `main()`（`stage2.cpp:120`）以**裸整数** `return` 收敛，实测返回集 = 0,1,2,3,4,5,6,7。

所以这不是「同一张表被抄了两遍」，而是 **`acsd-stage2` 这个诊断/工具二进制以裸整数占用了
`acsd::ExitCode` 的码值空间，并给了不同含义**。缺陷根因在实现侧，文档侧只是如实记录。

### 3.3 已落改动

**`ERROR_HANDLING_STANDARD.md` §7** 新增适用边界（不弱化、不删表，只加约束）：

> **本表的适用边界**：本表只解释 `acsd::ExitCode` 枚举成员在三个生产命令上的语义。未 include
> 本头文件、以裸整数 `return` 收敛的诊断/工具二进制，其返回值不属于本表……两者共用同一码值空间时，
> 以 `acsd::ExitCode` 成员的语义为准，非枚举来源的裸整数不获得本表的语义。

**`PUBLIC_API.md`** 改引用正本 + 保留接口面确有的补充语义，**未删任何一行实测值**：

- 标题 `### 退出码表（stage2 进程级）` → `### \`acsd-stage2\` 工具返回值（工具局部，非 \`acsd::ExitCode\`）`；
- 抬头显式指向 `ERROR_HANDLING_STANDARD.md` §7 为正本，并声明本表**不是**其接口面副本、不得反查；
- **补齐原表缺失的两行**：码 0（成功，`:2009`）、码 1（未捕获异常兜底，`:2013/:2017`）——
  原表只列 2–7，对 `acsd-stage2` 返回 0/1 的情形无任何登记；
