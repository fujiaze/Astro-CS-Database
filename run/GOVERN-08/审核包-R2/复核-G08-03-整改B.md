## 4. `DEPENDENCY_RULES.md:31` 争议 —— 我的独立裁决

### 4.1 逐字引文（`docs/engineering/DEPENDENCY_RULES.md:31`，实测原文）

```
- 机器路径政策：CMake 与构建输入不得读取 `F:/`、`C:/Users/<user>`、`/home/<user>` 等机器绝对路径
  （fresh configure 必须可复现）；Windows 正式工具链的安装位置由 preset 显式声明，属白名单例外；
```

### 4.2 裁决

> **作者对，前台错。**

- 该行**逐字**包含独立分句「**MSYS2/MinGW 依赖面禁止**」，这是一个**与机器路径政策并列的独立约束**，
  不是路径政策的派生推论。因此前台转述的「已证伪 / 与 MinGW 无关」**不成立**。
- 作者的表述也**准确且有分寸**：他说「该行确以机器路径政策为主，但逐字包含…可作**辅证**」，
  并声明「本单未引用它」——即他没有把它当作主证据，而是另起四路机器事实。
- **附带价值**：该行正是「禁 MinGW」在**依赖/路径政策面**的落点，与 `toolchain.ps1:7` 的
  「**禁** MSYS2/MinGW」、`preset-contract.json` 的 `forbidden.mingw_msys` 构成同一事实的三个面。
  本车道 §5.1 的「事实裁决」结论因此更稳固，而不是更弱。

**请前台**：不要把「该行与 MinGW 无关」写进审核包；该行是**有效辅证**。
