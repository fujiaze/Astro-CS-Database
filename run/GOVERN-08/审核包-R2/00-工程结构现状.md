### 2.1 不一致 #1：`coverage` 被编进**三个**目标、跨**两张**构建图

这是负责人点名的可疑项，实测比「被单独构建成一个目标」更碎：

| 编译单元 | 目标名 | 所在图 | 声明处 |
|---|---|---|---|
| `coverage/src/coverage.cpp` | `acsd_phase2` | 根图 | `CMakeLists.txt:684` |
| `coverage/src/coverage.cpp` | `acsd_phase2_integrate` | 根图 | `lib/algorithms/integration/phase2_integrate/CMakeLists.txt:35` |
| `coverage/src/coverage.cpp` | `phase2` | **未接根图** | `lib/algorithms/coverage/CMakeLists.txt:49` |

同样被三处重复编译的：`upm.cpp`、`identifiability.cpp`、`rejection.cpp`、`sampler.cpp`、`integrate.cpp`、`block.cpp`、`stage2_common.cpp`。
同一目录还在根图里被切成**另外两个独立目标**：`acsd_identifiability`（根:672，只编 `identifiability.cpp`）与 `acsd_hips_properties`（根:707，只编 `coverage/hips_properties.cpp`）。

⇒ **一个设计上的单一数据对象 / 单一 mosaic 节点，在构建图里散成 3 个 target（根图）+ 1 个孤岛 target（`phase2`）。**

**关于 `phase2` 这个孤岛 target 的精确事实**（逐条实测）：
- 声明：`lib/algorithms/coverage/CMakeLists.txt:42 add_library(phase2 STATIC …)`，**target 名没有 `acsd_` 前缀**，是全仓唯一。
- 根的 14 处 `add_subdirectory` 里**没有** `lib/algorithms/coverage`。
- 枚举全仓 72 处 `target_link_libraries(`，提到 `phase2` 的只有 3 处：`coverage/CMakeLists.txt:95/:111/:116` —— **都是同一张未注册文件里声明的 compat 工具**。
- **没有任何 mosaic 阶段目标依赖它**；`eng/cmake/install_layout.cmake` 不提它；两个 preset 都不含它。
- 它**不在默认构建里**（其目录不在图内），只有单独 `cmake -S lib/algorithms/coverage` 才构得出来（该文件 `:12` 有自己的 `project(astro_phase2)`）。

**关于「重叠图算法是不是 13 个对象之一」——需要精确区分两层**：
- `coverage` **对象**确实在 13 个之列（`ACSD_DESIGN.md:179`）✅ 前台既有判断正确。
- 但**重叠图算法本身不是数据对象**，它是 `coverage` 对象的**产生者之一**。依据：`docs/science/algorithms/PHASE2_COVERAGE.md:22-23` 把算法与对象分列；`docs/engineering/PROJECT_SPEC.md:50` 称其为 **overlap graph**（一个图）；登记面是模块卡 `docs/detail/registry/acsd.phase2.coverage.md:24`「建立输入帧 / 区域的重叠图」。
- 设计还画了红线：`acsd.phase2.coverage.md:27-28`「**不做权重**；coverage 是几何 / 数据有效域，不是权重」。
