# 前台裁决 · ACR 两份一级正本：**保留，代码是偏离方**

## 一、查了什么

车道报「删 ACR 会让两份一级科学正本指向不存在的对象」，按纪律未擅动，请求裁定。
前台查了权威链，**结论与车道的前提相反**：

- **最高设计 §1.3「非目标」逐字列**：「GPU 与 CPU/GPU 混合生产路由
  （**相关实验源码隔离保留，生产不可达**）」；
- **最高设计 §8 的目录树逐字标注**：`acr/` ——「**隔离实验（生产不可达）**」；
- 那两份正本自己在开头就写：「**`ACR` 是隔离实验，生产不可达**
  （`ACSD_DESIGN.md` §1.3/§8.1）；本文件定义其工作域等价…」。

⇒ **两份正本与最高设计完全一致，且它们对 ACR 地位的陈述是对的。**

## 二、真正的偏离方是代码

车道实测的三处活接线 —— 根构建把 ACR 的头目录加入主库的公共头搜索路径、
把一个包含该头的源编进主库、生产代码在运行期真的调用 ACR 的注册/查询/加载 ——
**与最高设计的「生产不可达」直接冲突**。

⇒ **不是「删代码让正本落地」，是「代码漂移进了非目标区域」。**
按 AGENTS.md §3「文档高于代码，代码与文档冲突时以文档为准订正代码」——
**订正方向是代码，不是文档。**

## 三、裁定

1. **两份一级科学正本：保留，不删、不改。** 它们是最高设计 §1.3 非目标条款的
   下级承接，删掉它们反而**切断最高设计非目标条款的下级索引**
   （最高设计 `:87` 与 `:210` 两处下级索引都指向它们）。
2. **删除 ACR 时，同步从这两处最高设计的下级索引里摘掉 ACR 索引项** ——
   不是删文件，是**改指向**，因为索引项在最高设计里。**这两处须你点头**（最高设计）。
3. 若日后要做「GPU 与 CPU/GPU 混合生产路由」——**那是改变非目标条款**，
   属负责人决策，不在本轮范围。

## 四、由此确定的删除处置（覆盖此前裁决的甲类一条）

此前我把「树外接线」定为**甲类·迁出**。**据此更正为乙类·随树退场**：

- 那些接线**唯一的用途就是接 ACR**（注册 ACR 内核、查 ACR 注册表、确保 ACR 桥接加载、
  那个只包含 ACR 头的源文件）⇒ **不是「ACR 之外的独立行为」，随树一并退场**。
- 但**必须保留的是「无 GPU 时的回退路径」本身** —— 回退是有价值的产品行为，
  不是 ACR 的一部分。⇒ **把回退逻辑迁到 ACR 树之外，不迁 ACR 的注册/桥接。**
  这是本条唯一需要小心的地方，**前台会在编译验证时重点核对**。
- 那条**全仓无人消费的哑开关**随树退场删掉（避免留下「以为能关其实不生效」的第二层假承诺）。

## 五、记录一条本轮的判断纠错链
车道报「删 ACR 会让正本悬空」→ 前台查权威链 → **发现正本是对的、代码是偏离方**
→ 前台此前的「甲类迁出」裁决**因此改为乙类退场**。
