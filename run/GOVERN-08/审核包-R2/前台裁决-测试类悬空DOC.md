# 前台裁决 · 两个整类报错的测试类与其悬空 DOC 指针

## 事实（前台独立复核，不采信转述）

`eng/tests/arch/test_backend_arch.py:6` 与 `eng/tests/arch/test_phase3_module_arch.py:6` 各自把
`DOC` 指向 `docs/architecture/` 下的文件，`setUpClass` 以 `open(DOC)` 读入。
`docs/architecture/` **整个目录已不存在**，两个测试类**整类报错**，根本跑不到类体内的断言。

## 归因：前台先前的报法是错的

前台一度以为是自己删除机读资产时删掉了这两个文档。**实测不成立**：那两个文档路径在删除动作
之前就已不存在。真实情况是——文档内容在权威对齐时**已被改指到 `docs/engineering/` 下**
（两份文件现在都在那里），而**测试侧的指针从未同步**。

⇒ 这不是「删除动作的新增损伤」，是**一次文档迁移只改了源侧、没改消费者**的既有缺陷，
与本项目已反复查出的「改内容没改引用」是同一类。前台此前的归因不成立，已更正。

## 处置（前台裁定，授权另派车道执行）

1. **第一顺位不是拆那几行断言，而是修 DOC 指针** —— 指针坏着，拆行永远执行不到。
   把两个测试类的 `DOC` 改指到 `docs/engineering/` 下的现存文件，并**核对内容确实承载**
   该类要验的东西（不得只改路径不核对内容）。
2. **然后**再处理那几处永久绿断言（在指针修好、类能真正执行之后）。
3. ⚠️ 此类问题的教训并入本轮纪律：**迁移文档时必须同时扫消费者**，且验收要实跑该类，
   不能只看「文件在不在」——文件不在与类报错是同一个现象的两种表现。
