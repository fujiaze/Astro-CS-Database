## 1 两处缺陷的机理锁定（重跑的前置）

### 1.1 缺陷 A：浮点像素索引被截断成无符号整数

`lib/algorithms/star_detection/src/sdet_image.cpp:382-404` 的 `sdet_median_inplace<F>()`：

```cpp
// HEAD（修复后）:402
const F lo = *std::max_element(v->begin(), v->begin() + mid);
return (F)(0.5 * ((double)lo + (double)(*v)[mid]));
// 修复前（1ef0849c^）:394
const std::size_t lo = *std::max_element(v->begin(), v->begin() + mid);   // ← 浮点被截成无符号整数
```

- 容器元素是 `F`（`float`/`double`）的**像素量与噪声量**；`std::size_t` 转换对负值是**未定义行为**，对 `[0,1)` 一律截成 0。
- **只作用于偶数样本分支**（`:391` `if (n % 2 == 1) return (*v)[mid];` 先行返回）。奇数样本逐位不变。

**受影响调用链**（逐点核对）：

```
sdet_median_inplace  ← sdet_median_of_finite(:413) / sdet_mad_sigma_impl(:424, :427)
  ↓ 经 sdet_robust_median_d / sdet_robust_mad_d
sdet_compute_bgnoise()  sdet_api.cpp:713-757
  ├ :727/:728  逐行 3 轮 5σ clip 的 median / MAD
  └ :755       行间中位数            ⇒ pr.bgnoise  (:1591)
sdet_api.cpp:1591 pr.bgnoise
  ├ :1615 locthreshold = 5·bgnoise
  │    ├ :1982  sdet_detect_ex（sdet_api.cpp 自带的盲检 ABI 入口）O10 对称门 → continue
  │    └ :2276 ★sdet_detect_guided_impl（权威路径）⑤ O10 对称门 → verdict = SDET_GD_REJECT
  └ :1616 thr = pr.bg + 5·bgnoise
       ├ :1749  sdet_detect_ex 的候选生成
       └ :2196 ★sdet_detect_guided_impl 的 `if (v > thr) ++counthigh`（饱和邻域计数）
sdet_api.cpp:1593/:1595 pr.bg = sdet_robust_median[_d](src, np)  ⇒ :1612 dynrange ⇒ :1613 sat_threshold ⇒ :1616 thr
sdet_api.cpp:812   sdet_gauss_fit 的 bkg0 3σ 裁剪（sig0）
```

⚠️ **`sdet_prepare_field` 是 `sdet_api.cpp` 内部两条路径共用的**（`sdet_detect_ex` `:1737`、引导 `:2150` 都调它），所以 **`pr.bgnoise` / `pr.bg` 在权威的星表引导路径上一样被算出来**。

⚠️ 但**生产 `module_adapters` 的 `blind_diagnostic` 分支不走 `sdet_api.cpp`**（见 §1.1.1）—— 上表 `:1749`/`:1982` 属 `sdet_detect_ex` 这个**遗留 FP32 ABI 入口**，`module_adapters` 在 `blind_diagnostic` 下走的是 `wrapper_phase1` 的另一套检测器。

### 1.1.1 ⚠️ 关键：三路分支，只有一路受影响（复核后订正）

**产品 `star_detection` 有两套完全不同的检测实现**，由 `module_adapters.cpp` 的模式门分流（`:3426` 缺省 `auto`；`:3886` 有星表但无取向先验 ⇒ 降级 `blind_diagnostic`；`:3895` 有星表 + 有取向先验 ⇒ `catalog_guided`；`:3914` `const bool guided = ...`）：

| 分支 | 调用点 | 阈值从哪来 | **受缺陷 A 影响？** |
|---|---|---|---|
| **`catalog_guided`（权威路径，`authoritative=true`，`:4144-4146`）** | `module_adapters.cpp:4069` `sdet_detect_guided_ex_f64(...)` | `sdet_api.cpp:1591 pr.bgnoise` → `:1616 pr.thr`、`:1615 pr.locthreshold`；`:2196 if (v > thr) ++counthigh`、`:2276` O10 对称门 | ✅ **是** |
| **`blind_diagnostic`（显式降级 / 诊断初值）** | `module_adapters.cpp:4149` `det.detect(...)` | `wrapper_phase1/star_detector.cpp:153` `thr = cat.background + detection_sigma_ * cat.noise_sigma`，而这两个量来自同文件 `:73-141 estimate_background`，它用 **`nth_value(scratch, kn, kn/2)`（`:97/:103`，只 `return v[k]`，**无偶数中位平均**）** | ❌ **否** |

⚠️ **这条订正推翻了三方说法中的两方**：
- 正本 `STAR_DETECTION.md:192`「本册的阈值判据与召回阈表只在**盲检**路径下有定义」——这句说的是**判据的适用范围**，不是生产代码里哪条路径带这个缺陷；
- `T10-Windows构建.md:374` 说「P1 星表成员与 P2 绝对 SNR 的源集合会动」——**实质成立**，因为权威的 `catalog_guided` 分支确实读 `thr` 与 `locthreshold`；
- 本单作者中途曾按正本那句把它判成「过宽」，**该中间结论已撤回**（§6-R4）。

⇒ **一句话口径**：**权威路径（`catalog_guided`）受影响；诊断/初值路径（`blind_diagnostic`）不受影响。** 这与直觉相反，必须写明。

**未受影响**：`sdet_api.cpp:639` 的 `reject_star` RMSE 门走的是 `sdet_median_of`（`:172-177`，本来就是正确的两中位数平均）。

### 1.2 缺陷 B：LLP64 位宽截断发生在校验之前

`P3CropWindow` 坐标是 `long`（`lib/algorithms/projection/p3_wcs.h:186-212`）。Windows `long` 32 位 ⇒ 越界坐标静默截断后放行，Linux 具名拒绝。修复方式是在窄化**之前**用 `long long` 校验值域。

⚠️ **对数值基线的影响面比缺陷 A 小得多**：合法输入**逐位不变**。仓内**没有任何测试**断言「越界输入被放行」（清点见 §5-B7），所以缺陷 B **没有推动任何在册数值基线**；它推动的是一条**行号锚**基线（§3.2）。

## 4 科学口径影响判定：修复后的行为与正本是否一致

### 4.1 判定：**一致。旧基线是按错误行为冻结的。**

**不需要调任何参数。判定闭合在正本条款上。**

**第一层（决定性，独立成立）：估计器的语义合同本身封死了「偶数中位数」这个自由度。**

star-detection 三份正本（`STAR_DETECTION.md`、`STAR_DETECTION_ALGORITHMS.md`、`STAR_DETECTION_IMPL_DESIGN.md`）对「偶数样本的中位数怎么算」**命中数为 0 —— 正本未规定**。这一点必须如实说：**判定不是靠「正本规定了偶数中位数」成立的。**

判定靠的是正本为 `bgnoise` 立下的**物理量、量纲与偏差结构合同**：

| 正本条款 | 原文 | 旧实现是否满足 |
|---|---|---|
| `ALG-STARDET-001.md:36` | 「**量纲 ADU；输出量 = 单像素噪声 RMS `σ_n`**」 | ❌ 截成 `size_t` 后输出不再是 RMS |
| `ALG-STARDET-001.md:37-39` | 「估计量 `σ̂_n = σ_n·√(1−ρ_adj)`。**仅在 `ρ_adj = 0` 时无偏**」 | ❌ 引入了 `ρ_adj` 之外的**第二个偏差源** |
| `ALG-STARDET-001.md:48-49` | 「纯独立高斯噪声下实测无偏：`σ̂_n/σ_n` = 0.99792」 | ❌ 旧实现实测 **0.97135** |

⇒ 正本声明的**唯一**允许偏差源是 `ρ_adj`。行内差分 `d[y,x] = I[y,x] − I[y,x−1]` 是**近零均值量、常为负**，负浮点转 `std::size_t` 是 UB。⇒ **修复后的行为与正本一致；旧基线是按违反该声明的行为冻结的。**

**第二层（补强，排除「修复引入了正本未授权的新口径」）：**

全仓 8 份正本把偶数中位数**逐字**冻结为 `(hi+lo)*0.5`，其中 `docs/science/algorithms/COSMETIC_ALGORITHMS.md:239-243`（ALG-COS-005）连**实现手法都一样**（`lo = *max_element(v.begin(), v.begin()+n/2)`），并在 `:428-430` 冻成 **bitwise 断言**（`FIX-COS-F`）。另见 `CALIBRATION_ALGORITHMS.md:89`、`PHASE2_SAMPLER.md:113,281,460`、`PHASE2_REJECTION.md:70,85`、`NOISE_SNR.md:430`、`PHASE2_UPM.md:94`、`PUBLIC_API.md:1507-1508`。⇒ 修复是**回归正本约定**，不是引入自由度。

**第三层（仓内自带反证）：**

`lib/algorithms/star_detection/src/sdet_api.cpp:170-171` 有第二个中位数实现，注释自称：

> 「内部: 有代表性的中位数（**与 sdet_image.cpp 的 robust_median 同式**: 奇数取中位元素, 偶数取两中位均值）」

修复前二者**并不同式**；修复后才同式。⇒ **代码自己就是证据。**

**第四层（对「检出更多假源」这一行为变化的定性）：**

- `docs/science/detection/STAR_DETECTION.md:50`：「`bgnoise` 是未平滑原图的**单像元背景噪声标准差 `σ_n` 的稳健估计**…**除数 √2 只在 `ρ_adj = 0` 时给出无偏的 `σ_n`**」
- `docs/science/algorithms/STAR_DETECTION_ALGORITHMS.md:108-110`、`:160`：`bgnoise` 的第二个消费者是对称性门 `max(|Ar|,|Ac|) < 5·bgnoise`。**这条门在两条路径上都生效**（盲检 `sdet_api.cpp:1982`、权威引导 `sdet_api.cpp:2276`）⇒ 压低 `bgnoise` **双向**放宽阈值候选门与对称性门 ⇒ 假源**同时**从两条路进来，且**权威的星表引导路径也在其中**。

⇒ 「检出更多假源」**不是修复引入的新自由度，而是修复消除的一个偏差的下游后果**。修复后的行为（对称门更严、假源更少）正是正本要的样子。

### 4.2 若不一致应当停下上报的情形 —— **未触发**

若「更严格的阈值 ⇒ 更少假源」与正本的「虚警密度 ≤0.1/千像素」或「召回率 ≥99%」冲突，本单必须停下。实测**未触发**：`ALG:334` 与 `GATES_AND_TOLERANCES.md:65` 的虚警门是**上界**（假源更少只会更绿），`GATES:64` 的召回门是**下界**，且正本 `:192` 已把召回阈表**限定在盲检路径**上（而引导路径走的是 O10 对称门与拟合质量门，不是 `thr`）。**没有需要调 κ 或调参数才能同时满足的正本条款。**
