## 3. A3 / A4 根因归纳

**A3 根因（两层）**

1. *机制层*：`run_all.sh:22-23` 在每次 run 的**末尾**对**整个单元**（含刚被重写的产物、全部源码与判据正本）重算 sha256 并覆盖锚文件 ⇒ **自愈锚，检出力为零**。它不是「锚过期了」，是「锚这个机制在本单元从未具备检出力」。
2. *执行层*：因为上游输入 `run/RELEASE-05/vis/**` 不在本仓，`run_all.sh` **一次都没跑完过**，所以连「自愈」都没发生 —— 锚停在 `a0a3d208`（09-23 10:00）从未更新。于是它同时是**过期的**和**无用的**：既检不出真变化，又对 11 项合法改动长期误报。

**A4 根因（三层，互相独立）**

1. *命名层*：生产者写 `bitwise_eq`、消费者查 `bitwise`，判据恒走 fail-closed 分支 ⇒ **一个恒红门被伪装成「证据齐备时不给数」的合规行为**。fail-closed 本身是对的，但被一个纯命名错误触发时，它的红是假的。
2. *版本层*：`final_numbers.py` 已被重写（注释标 TRUTHFUL-CONCLUSION-01，把硬编 20/103 改为同源计数），而 `final_numbers.json` **从未重跑** ⇒ 归档里仍是旧硬编值 `20/103/188`，且缺 `bitwise_source` / `bitwise_unavailable_reason` 两个新键（派单说的 `reason=None` 在归档里其实是**键根本不存在**，即归档落后一整代 schema）。
