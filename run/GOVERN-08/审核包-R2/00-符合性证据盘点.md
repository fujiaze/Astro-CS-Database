### 1.3 token 抽取与分类规则

逐行抽取「反引号内 token」与「路径形态 token（正则 `[\w\.\-\*]+(/[\w\.\-\*]+)+(\.[A-Za-z0-9]+)?`）」，对每个 token 依次判定：

1. token **逐字** ∈ 受跟踪集（`git ls-files`） → `ALIVE`
2. token **逐字** ∈ §1.1 的 1341 已删集（由 `git show --diff-filter=D` 直接导出，逐件可信） → `DEAD`
3. 否则判 `UNRESOLVED`，不计入本件结论（避免猜路径）

**不做相对路径猜测、不做 basename 近似匹配**——那正是本项目栽过的坑（总台账 `:237` 把 `lib/phase3_session/p3_export.cpp` 抄成 `lib/algorithms/projection/p3_export.cpp`，导致后续每一轮都查不到，见 `00-阻断总台账.md:275-287`）。

> ⚠️ **本车道试过并放弃的一种口径，留作后车道的坑位记录**：
> 曾用 `git log --all --pretty=format: --name-only --diff-filter=A` 构造「历史曾受跟踪的全集」当分母。**该口径不可信**——实测它**漏掉了 `eng/tests/unit/CMakeLists.txt`、`eng/tests/io/test_fits_stream_contract.py`、`lib/algorithms/shared/healpix/tests/test_healpix_oracle.cpp`**（`grep -cxF` 于其输出均得 0），而这三件由 `git show --diff-filter=D` 可直接证明确实存在过并已被删。
> ⇒ **判定「载体是否曾存在」只能用 `git show --diff-filter=D <commit>`，不能用 `--diff-filter=A` 的 log 汇总。** 本件 §1.1 的 1341 集正是用前者构造的。

### 1.4 「现态断言」的判定

只收**现在时**的符合性/一致性声明（`CONFORMANT` / `机器保证` / `双向机器复核` / `由…校验` / `必须仍可解析` / `真仓库当前判红` / `已机器化` …）。
**不收**历史过程记录（带日期、状态词「已修（XXX，YYYY-MM-DD）」、"源件实测"、"既往轮次归档在 …"）。这一刀把 `artifacts/evidence/governance-01/**` 与 `实验/engineering-evidence/**` 的大部分条目排除在外——它们是**归档证据**，不是现态登记面。
