## 4. 切片规则 GEN-2-SLICE（抗漂移）

### 4.1 原台账的病与本单的两条对策

**病**：片定义挂在**绝对行数**的等分块上，且**完成度记在片号上**。分母一涨（+160.6%），片号整体重排，已完成的片号对不上新片号 ⇒ 进度归零或重复计；且没有任何重切触发点。

**规则 A（分层键稳定）**：片的首要身份是**顶层四域** `docs` / `实验` / `lib` / `eng` —— 这四个键就是「审查主体」定义本身（`git ls-files docs 实验 lib eng`），与行数无关、与内容增删无关，是本仓最稳的结构单位。域内按**路径字典序**排序（字典序即层级序，模块天然连续），顺序累加行数，每满 `T = 11,000` 行切一片，**单文件不跨片**；单文件 > T 者独占一片并标 `超大片: true`。片另记 `主模块`（该片内占比最大的三级目录）供派单定位，**不参与片身份**。

> **分层深度为什么取 1 而不是 3**：实测按三级目录分层得约 330 层，绝大多数不足 T 行 ⇒ 片数 **367**、片行数中位仅 **249** 行。分层过细会把容量约束架空（理论车道 70，实际 367）。取顶层域作分层键后得 74 片、中位 10,834 行。**两种做法的对比已实测，不是拍脑袋。**

**规则 B（完成度按文件记账，不按片号记账）—— 抗漂移的关键**：一份交付件声明它读了哪些**文件路径**。重切片只改片号、不改文件集合，故「已读一遍」的判定 = 文件路径集合，重切后依然成立：既不会因片号漂移而丢失，也不会因片号重排而重复计数。**片号只是派发与排程用的视图，不是进度的真相源。** 由此，任何一次重切都不需要回滚历史记账。

### 5.3 「既往产出计入几遍」判定规则 D1

台账原话（`轮次台账.md:46`）：**「既往产出不计入遍数。」** 展开为可执行五条：

| 规则 | 内容 | 依据 |
|---|---|---|
| **D1-1** | **遍 = (片, 遍序号) 二元组**。一遍 = 对**同一片**材料的一次完整重读。遍是全局轮次，不是单片阅读次数 | `轮次台账.md:5` |
| **D1-2** | **既往产出 = 0 遍**。广度不是遍数：G08-05「十轮对抗审稿」实为十个问题各一车道；后续 25 条车道「每片只读一遍」 | `轮次台账.md:45-46` |
| **D1-3** | **重复覆盖不算第二遍**（除非按 D1-4 判为达标遍）。片09–14 对 s000–s005 的第二遍阅读，因其基线 commit 与第 1 遍不同、不构成「同一片材料的完整重读」，**不折算为第 2 遍** | `轮次台账.md:5`；三轮基线 `1208d5a0 → ed33f57f → ef3dc516` 各不相同（`00-收敛度量.md:154`） |
| **D1-4** | **一片被 ≥2 份**独立**交付件各自登记 100% 逐行读完，且都在同一基线 commit 上** ⇒ 该片可计 **1 遍**。仅 1 份登记 ⇒ 计 **0 遍**，只登记为「已覆盖」 | `轮次台账.md:5` 完整重读之义 |
| **D1-5** | **覆盖率 < 85% 的片**，其阅读**不计入**任何遍，只登记「部分覆盖」 | 台账 85% 目标（`轮1v3` 各片 §0 自陈 100%） |

**明确回答派单两问**：
- **哪些算「已读一遍」？** 按 D1-4：需 ≥2 份独立交付件、各自 100% 逐行读完、且同一基线。实测**无一片满足**（8 个旧片中 6 个虽有 2 份交付件，但两遍基线不同 ⇒ 按 D1-3 不计第 2 遍；另 2 个只有 1 份交付件）⇒ **当前完成遍数 = 0**。
- **重复覆盖算不算第二遍？** **不算。** 6 份重复是同基线外的复核，只把对应片推进到「已覆盖」，不产生新遍。
