## 2. 修法：路径表达文法

### 2.1 一条文法，替代三处正则放宽

新增 `path_expression()`（工具内），从 token 起点按文法把作者写下的**完整**表达读出来，返回 `(无空格读法, 完整读法)`：

- **段内允许**：ASCII `[A-Za-z0-9_+.~@]`、glob 元字符 `* ?`、花括号组 `{a,b}`（逗号只在括号内合法）、以及**非 ASCII 的字母/数字/组合记号**（按 `unicodedata.category` 判，`L/N/M` 放行、`P/S/Z/C` 终止——`实验/a，b.md` 里的 `，` 是散文分隔不是文件名）。
- **段间分隔**：`/`，或**单个 ASCII 空格**；空格后的一段必须是**纯 ASCII**（` 的硬件字段禁令` 是散文不是路径段）。
- **终止**：CJK 与 ASCII 标点、空白、制表、引号。

「无空格读法」单独返回，是为了不让散文尾巴污染判据：`实验/.../03_缺陷账本_重开清单.md AR-048` 里的 `AR-048` 是条款号，判存在性时不能算进路径。

### 2.2 五条判据边界（写进代码注释，挡住后来者）

| # | 边界 | 本仓实证 |
|---|---|---|
| 1 | **前缀不是路径**。原文没写通配元符，就不许补全 | `ls -d lib/phase1 lib/phase2 lib/phase` → 三者全不存在，只有 `lib/phase1_session/` |
| 2 | **花括号按集合判，不按命中数判**：展开后**每一项**都必须存在 | `实验/…/step{0,1,2}.sh` 里 step0 其实是 `.sh`、step1/2 是 `.py`——「命中一个就放行」会吞掉它 |
| 3 | **星号按集合判**：命中 ≥1 即可 | `lib/phase*` 在 shell 语义下指 `lib/` 下以 `phase` 开头的**目录项**；只索引文件会把这类判成零命中 |
| 4 | **空格续写只许成功、不许改写** | `eng/tools/e2e/seam_footprint.py --self-test` 是「路径 + 命令行参数」，整条吞成一个假路径 token 就是抽取精度退化 |
| 5 | **「不判」不等于「吞掉」** | 占位形态过去**整条从未被检查过**（`classify_token` 把 `<>` 直接判 `none`）；现在单列 `path_placeholder`（ADVISORY） |

### 2.3 判定链

```
token 解析不到
  └─ judge_path_expression(text, at, ...)
       ├ 占位形态（<>）            → unjudged：只计数 + 单列 path_placeholder（ADVISORY）
       ├ glob / 花括号形态         → 展开命中 ⇒ resolved；零命中 ⇒ **仍是 dangling_path**，
       │                              token 换成作者写下的完整表达
       ├ 解析到 exact/dir/ext     → resolved（含 CJK 续写、`「节名」黏连剥离）
       ├ X.h/.cpp 复合简写         → 头 + 源都在 ⇒ resolved；缺一 ⇒ **仍是 dangling_path**
       ├ 含空格形态且能解析        → resolved
       └ 其余                      → literal：按**原 token** 报悬空（真悬空身份不漂移）
```

最后一条是关键：**续写只许把「missing」变成「resolved」，永远不许改写真悬空的 token**。

### 2.4 匹配器的两个实测 bug（我自己踩的，已修并入消融）

1. **字面前缀取成了整条路径**：`phase_config_{...}.schema.json` 展开后 `lit` 覆盖全部段，`prefix` 成了完整文件名，而索引是按**父目录**建的 → 全部 0 命中。
2. **目录不在匹配池里**：`lib/phase*`、`testdata/M42*`、`panel{1,2,3}` 命中的都是**目录项**，只索引文件会把它们判成「一个都没命中」。

两处都已各自变成消融项 A10 / A7。

## 5. 如实登记的副作用

1. **`dangling_path` 净减 59，全部是假悬空**；真悬空**净减少 0**。硬判定合计 1346 → 1287。
2. **新增类别 `path_placeholder`（ADVISORY，30 条）**：占位形态过去整条从未被检查过，现在可见。**任何按类别名读 JSON 的下游脚本会看到一个新类**。若下游把 `ADVISORY` 成员一并计入，会虚增 30 条。
3. **30 条真悬空的 token 变了**（`eng/ci` → `eng/ci/**` 等）。`stable_key` 是 `(类别, 来源文件, 令牌)`，所以 `--baseline` 差集里这 30 条**同时出现在「消失」与「新增」两侧**。任何按 token 匹配的下游脚本必须把这 30 组配成对，否则会误判成「30 条新缺陷 + 30 条修复」。
4. **含空格形态的判定是单边的**：续写只许成功、不许改写（§2.2 边界 4）。若某条含空格的路径**真的不存在**，工具仍会报它被截断的前缀（`testdata/T2`）而不是完整串——**这是刻意选择**，为了不动真悬空的诊断。仓内 5 组含空格引用全部命中，暂无实际损失。
5. **`match_pattern` 对首段就带通配符的形态（如 `*/x/*.md`）在全仓 20 万条路径时如实报「算不出来」**（`pattern_uncomputable`），不谎报零命中。当前仓内 0 条触发。
6. **`path_placeholder` 的正则按空格终止**，所以 `out/<group>/{full.png, tiles/tile_r{r}_c{c}.png, vis_report.json}` 这类带空格的占位形态会被截在第一个逗号后（`eng/tools/e2e/render_vis.py:53`）。是 ADVISORY，不判缺陷；如实登记。
