### 1.2 A1 的判据（一句话可陈述）

> 某文件判 **GENERATED**，当且仅当它的**内容可由仓内运行器按固定输入重新产出**，其正确性由生成器与判据保证，读它不产生新的人工语义；否则判 **HUMAN**，因为它是不可再生的正本、输入数据或人工裁决记录。

这条判据不是新发明，它把两车道各自摸到的直觉合并成一句可判定的话：

- G1 的「产出面」——目录里有运行器 ⇒ 内容可再产出；
- GEN-2 的「自述 `generated_by` / `derived_from`」——文件自己说了谁生成了它 ⇒ 可再产出；
- 反过来：**管道的输入数据表**（响应曲线）与**人工决策台账**（修复台账）都不可再产出，必须留在人工侧。

### 1.3 为什么采纳 G1 的结构、保留 GEN-2 作对照

采纳 G1 作主体有三条理由：

1. **G1 显式区分「机器校验」与「机器生成」。**`eng/contracts/data/clause_registry.json` 被 `eng/tests/contracts/product_family/field_constraints_oracle.py` 读取校验，但它是人手写的合同注册表；`lib/infrastructure/pipeline/module_ports.registry.json` 自陈由 `eng/tools/quality/check_block_flow_ports_vs_code.py` 双向机器复核，带 `owner` / `frozen_at`。两者都是机器**校验**而非机器**生成**，故 P3 豁免判 HUMAN。GEN-2 没有这个区分，只能靠内容信号碰运气。
2. **G1 的 P3 手写面豁免拦住了「按登记面声明把 `eng/contracts/**` 一刀切」这个错误。**`docs/DOCUMENT_INDEX.yaml:24` 与 `docs/engineering/DOCUMENT_GOVERNANCE.md:24` 都写了「机器源与台账不进 docs，落在 `eng/contracts/` 与 `artifacts/evidence/`」——这是**声明**不是谓词；`docs/DOCUMENT_INDEX.yaml:34` 自己就写明「机器源（.json/.csv/.py 等）不因跨域而自动取得登记资格」。**资格与生成性是两件事。**
3. **G1 的 SRS-1 抗漂移规则被采纳**（见 §3.1）。

保留 GEN-2 作对照的理由：**它在两处边界上给出了与 G1 不同的答案，而且在这两处都对或更细**。判定式的可争议性必须留证，GEN-2 就是这份证物。

## 3. 片划分

### 3.1 抗漂移切片规则 SRS-1 + SRS-2（采纳车道 A）

原台账的病根是**片定义挂在绝对行数上**：`:18` 用「总行数 ÷ 11k」直接算车道数，分母一涨，63 这个数就无声作废，且没有任何重切触发点。

新规则把片身份挂在**目录分层**这条结构轴上：

```
SRS-1  层内 LPT 均衡装箱
       层 = 固定目录分层（docs/science、docs/engineering、docs/detail、
             lib/algorithms/<模块>、lib/infrastructure/<模块>、eng/<子>、实验/<单元>）
       每层片数 n = ceil(层行数 / C)，C = 11,000
       层内文件按「行数降序 → 放进当前最空的一片」(LPT) 分配
       严格不跨层
SRS-2  尾域合并：层行数 < 2,000 的层并入同根 TAIL-<root> 层
```

**为什么抗漂移（本单实证验证）**：片数只依赖各层自己的行数，不依赖全仓总量。本次分母变动导致 9 个层的行数变化，但——

- **38 个层的片号与成员一字未动**；
- **6 个层行数变了但片数、片号不变**（`ENG-contracts` / `ENG-tests` / `EXP-absolute-snr` / `EXP-engineering-evidence` / `EXP-healpix-polar` / `EXP-m42-realdata`）；
- **只有 3 个层的片数真的变了**，全部因 §1.4 裁定把整份文件移进或移出该层：

| 层 | A1 片数 | G1 片数 | A1 行数 | G1 行数 | 变动原因 |

## 9. 分母与片清单的执行规程

以下规程对后续每一遍审稿车道**强制**，写清「怎样算走完一片、怎样算走完一遍、证据放哪」。

### 9.1 三条硬性前置

1. **片清单是仓内文件，不是 `/tmp`。**唯一权威片清单：
   `run/GOVERN-08/审核包-R2/分片清单/片清单-权威版.yaml`
   `/tmp/r3/`（旧 v3 的 63 片清单）**已确证丢失**（`test -d /tmp/r3` → GONE），63 片划分不可复现。**任何车道不得把片清单写到仓外临时目录**——本项目已因此丢过工作包与切片清单。
2. **按片走，不按目录走。**每条车道开工前先从 `片清单-权威版.yaml` 取**一个片号**，读该片的全部成员文件（成员路径逐条列在 YAML 里）。
3. **按遍记，不按片号记。**完成度记在 **(片号, 遍序号)** 上；片号只是派发视图，不是进度的真相源。

### 9.2 怎样算「走完一片」

一片走完当且仅当**四条同时成立**：

| # | 条件 | 判据 |
|---|---|---|
| 1 | **成员全覆盖** | 交付件声明的目标文件集合 **⊇** 该片 `成员文件` 全集；缺一不算走完 |
| 2 | **逐份实读 ≥ 85%** | 逐份记「清单行数 / 实读 / 覆盖率」，按 D1-4 / D1-5；< 85% 只能登记「部分覆盖」，**不计入遍数** |
| 3 | **零遗漏声明** | 明确写出未读部分及其理由；沉默不算声明 |
| 4 | **片号 + 遍序号双记** | 交付件头部写明 `片号: <片号>`、`遍序号: <n>`、`基线 commit` |

超容量片（`INF-scheduler-001` 16,260 行、`ALG-photometry-001` 14,079 行）**按 D1-4 的 85% 口径很可能长期走不完**，处置待 U3 裁决；在裁决前不得自行拆块并宣称走完。

### 9.3 怎样算「走完一遍」

一遍走完当且仅当**91 个片全部满足 §9.2 的四条**。满足后遍序号 +1，进入下一遍。

- **重复读同一片不是新的一遍。**单片被读两次而其余 90 片没读，不构成一遍（D1-3）。
- **基线不同的两次阅读不算同一片材料的两遍**（D1-1 + D1-3 收紧条）。
- **十遍是底线**（`轮次台账.md:2`），不是目标。
- **收敛条件：连续三轮零发现**（`轮次台账.md:3`）。当前连续零发现轮数 = 0。

### 9.4 证据放哪

| 证据 | 落点 |
|---|---|
| 逐份审稿记录 | `run/GOVERN-08/审核包/审稿/轮<N>遍-片<NN>.md`（仓内，不写 `/tmp`） |
| 覆盖率表 | 交付件 §0，逐份给「清单行数 / 实读 / 覆盖率」 |
| 发现项 | 同件，标注 `文件:行` 与所属片号 |
| 完成度汇总 | 追加到 `run/GOVERN-08/审核包/审稿/轮次台账.md`，按 (片号, 遍序号) 记 |
| 分母/片划分变更 | **不得由车道单方面改**；走 §9.5 的重切流程 |

### 9.5 分母或片划分需要变更时

1. 改 `authoritative_build.py`（判定式或切片规则），**不手改 YAML**；
2. 复跑，产出新的 `分母实测-权威版.json` 与 `片清单-权威版.yaml`；
3. **按 SRS-1 的抗漂移性质验证**：未受影响的层，其片号与成员应当**一字不动**。若动了，说明规则被破坏，须查因；
4. 出重切映射表（旧片号 → 新片号 + 文件集合），**完成度按文件路径重算，不按片号重算**，历史记账不回滚；
5. 两份旧片清单（`片清单-G1.yaml`、`片清单.yaml`）**保留不删**，只在文件头加注取代说明。
