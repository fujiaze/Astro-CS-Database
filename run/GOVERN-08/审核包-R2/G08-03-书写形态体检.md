### 1.3 判别规则（与「什么必须保留」边界的一致性）

本单采用的判别规则，**就是本单任务书给出的那一条**，原样执行：

> **编号指向机器可查的登记对象 ⇒ 保留；编号指向写作/修复过程 ⇒ 违规。**

该规则与边界的自洽性论证（这就是为什么它不与边界冲突）：

- 边界的本质是**溯源键的保留**。`PERF-501`、`G-RES-01`、`CHK-PROD-WIRING`、`ERR-P2-UPM-001`、`SCI-UPM-001`、`DISP-P3PROJ-001` 这类编号，回答的是「这条判据/这张数据/这个错误码在仓内的哪个文件里」，删掉即断链，故必须保留。
- 规范 02 §2 禁的是**叙述性过程痕迹**。`P-198`、`DOC-404`、`R-52`、`M3`、`A44`、`G08-10`、`V17`、`V19R3` 这类编号，回答的是「这是第几次派单/第几轮裁决/第几版」，与仓内任何文件无稳定映射，删掉不损失任何可查性，反而制造正文对写作过程的依赖，故必须删。
- 因此判别不需要看编号的**形状**，只需看它**解引用到哪里**：
  - 能解到仓内一个文件/一个 JSON/一张表的行 ⇒ 保留；
  - 只能解到一次派单、一次裁决、一个版本号、一份已删的过程台账 ⇒ 违规。
- 规范 02 §5 另有一条与本规则同向的硬要求：「**开源代码记录项目、版本、文件位置**」。这使 `SCAMP tag v2.14.0 = commit ef915ded…` 这类**外部项目**的版本号与 commit **必须保留**——它是本仓引用外部实现的可核锚，与本仓自己的过程编号性质相反。本单据此把 `SCIENTIFIC_REFERENCES.md:131/133/141/147/177/179/181/183`、`CALIBRATION.md:434` 的 OSS commit 判为**误报**（见 §5）。
