# 前台裁决 · 所有判决全部作废

负责人裁定（逐字）：**「所有判决全部作废啊」**，并追加 **「把 ci 什么的全都删干净」**。

## 这条比「删门禁」更彻底，必须写清边界

先前一轮按「所有门禁都移除」执行，删的是**判据与注册面**。本条把范围明确到
**判决本身**：

| 面 | 处置 |
|---|---|
| 判据代码、测试、预言机、自检 | **已移除**（`c0bb707d`，编译验证 557 目标全绿） |
| 流水线里的判红 / 判绿判决 | **一律作废，不建** |
| **G08-10「重建 CI 门禁并 GitHub 全绿」整项** | **作废** |
| CI 配置与其派生物（检查清单、闸门脚本、CI 专有资产） | **删干净** |
| 任何「以机器判决为通过依据」的表述 | **作废** |

## 直接后果

1. **G08-10 作废。** 任务书要求「逐条门禁映射定稿文档条款、补正负例与 fail-closed
   口径、双平台流水线全绿」——与本裁定正面冲突，不再执行。
2. **不建任何产出判决的流水线。** 即使日后配流水线，也只做编译验证、**不产出判决**。
3. **G08-09 双平台编译**口径随之收窄为：**由前台在本地验证能编译**，
   「零警告」作为前台自验标准记录在交付件里，**不转化为任何自动门**。
4. **验收链上不再有任何机器判决。** 正本里凡写「以门通过为据」之处，
   一律改为「须由对抗性审核重新推导结论并构造反例确认」。

## 已作废的判决是否需要回改结论？

**不逐条回改结论，但必须改「依据」的表述。**

被作废的是**判决这个机制**，不是它得出的**读数** —— 读数由实验与代码产生，
不因判决机制作废而失效。

⚠️ 但凡「某结论成立」是**以某道门通过为唯一依据**的，**该结论要降为未验证**，
不得继续以确定语气成立。这一类由各车道按此口径逐条甄别。

## 一条纪律

本项目已反复出现「机制变了、内容留着不动」的形态：
删了判据却留着「门通过」的措辞、删了归档却留着「读数已验证」的表述。
**机制作废必须连带清理依据表述，否则作废只停在纸面。**
