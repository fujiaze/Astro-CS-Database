# T08 锚点与指针校验器

工具：[`eng/tools/doccheck/check_anchors.py`](../../../eng/tools/doccheck/check_anchors.py)
本单交付两件：工具一个、本报告一篇。工具只**新增**该目录下这一个文件，未改动任何既有文件。
未执行任何 git 写操作。

---

## 0. 先说这个工具是什么、不是什么

**是**：一个帮人找「文档引用指着的对象不存在」的查问题工具。

**不是**：不是判据，不是门禁。按新正本「测试是独立工具集、不是门禁」，它：

- 默认退出码**恒为 0**（`--fail-on-findings` 是显式选择项，默认不启用）；
- 不进默认构建，不挂任何 CI 必过项；
- **不自动改任何文件**。

判定由人做。工具只负责把候选摆出来并标好出处。

### ⚠ 硬限制：计数只给分母，判定必须来自阅读

本项目已实测：以正则抓不到大小写混合的标识符，也抓不到不含该子串的行。因此：

- 本工具报出的条数是**真实缺陷数的下界**，不是上界，也不是全集；
- 「没报出来」**不等于**「没有问题」；
- 任何一份「计数对得上」的表都不能当通过依据。本报告里所有数字都带口径，
  口径写在数字旁边。

## 1. 为什么分两类报，且为什么第三类最危险

三轮审稿反复踩的是同一族缺陷，分两级，量级相同、隐蔽程度递增：

| 类别 | 含义 |
|---|---|
| **路径悬空** `dangling_path` | 被引用的文件/目录根本不存在 |
| **锚悬空** `dangling_anchor` | 文件**存在**，但被引用的章节在它里面不存在 |

只报「引用无效」会把最隐蔽的一类埋掉：**路径修了锚没修**。路径能打开了，
读的人以为找到了内容，其实停在错误的章节上。量级不变、发现难度上一个数量级。

第三类是本单点名的那个坑：

| 类别 | 含义 |
|---|---|
| **节名真·文件错** `section_wrong_file` | 节名**真实存在**，只是不在被指的那份文件里 |

按「节名不存在」的常规改法去修，会把真节名换成假节名——**越修越坏**。
所以这一类单独报，并把「这个节名真正在哪」一并告诉人。

记录里的原话（`T06-r2-审稿-DOC-DETAIL-GLOSSARY.md:117`）：

> 「节名『进程退出码』**真实存在，只是不在 `LOG_AND_ERROR.md` 而在 `ERROR_MODEL.md`**
> ⇒ X-09 的**问题识别成立、给出的落点指错文件**。」（O1）

工具对这一类的处理是三值判定，**从不替人选**：

- 节名在目标文件里 → 通过；
- 节名不在目标、但在**唯一一个**别的文件里 → `section_wrong_file`，并把真落点报出来；
- 节名不在目标、且在**多个**文件里都是标题 → `ambiguous_target`，列候选待人判。

### ⚠ 章节存在性怎么判：逐文件核实真实标题

工具**为每个目标文件单独解析标题、建立章节号集合**，再判定该引用在该文件里是否存在。
绝不使用「这个编号在仓库里某处出现过」当作存在的证据。

这是必须的。本项目已实测：同一个节号在不同文件里的含义完全不同。
`docs/engineering/contracts/SCHEDULER.md` 有 0 个 `## n` 编号章节
（实测 `grep -cE '^## [0-9]'` → 0），而代码里引的是 `§1`/`§3`；
同车道 `LOG_AND_ERROR.md`（`## 5 错误对象与退出码映射`）与
`ERROR_MODEL.md`（`## 7 进程退出码`）才有编号。「进程退出码」在后者有、前者无。

解析器要处理本仓真实存在的标题形态，否则会漏：

- 编号 + 字母后缀：`## 14a`、`### 2a.1`、`## 4a.`、`## 3a 坐标 frame`；
- 附录：`## 附录 A. 术语`；
- 代码围栏内的 `#` 是注释不是标题，必须跳过（否则会凭空造出章节）；
- 章节存在但**内容不含被引对象**——这一类本工具**抓不到**，见第 4 节盲区。

## 2. 工具能抓什么

| 类别 | 抓什么 | 依据 |
|---|---|---|
| `dangling_path` | 仓根相对路径指向不存在的文件/目录 | 磁盘全集判定 |
| `dangling_anchor` | 文件在，但 `§N` / `第N章` / `附录 X` 在该文件里不存在 | 逐文件标题集 |
| `section_wrong_file` | 节名不在被指文件，但在别的文件真实存在 | 全仓节名反查 |
| `quote_not_found` | 内容锚登记的 `quote` 在目标文件里查不到（文件在、内容不在） | 逐字子串 |
| `replacement_residue` | `「§N→节名」`批量替换的残渣指纹 | 形态匹配 |
| `anchor_title_mismatch` | 节号命中但括注标题与真实标题不一致 | 仅合同面 |
| `ambiguous_target` | 路径后缀或节名匹配到多个真实目标——**同名多义** | 候选枚举 |
| `untracked_target` | 磁盘有、git 无（不是悬空，但会让门禁在干净克隆上失真） | git 跟踪集 |
| `unresolved_relative` | 相对/裸名路径解析不到——**不判悬空** | 降级 |
| `clause_id_anchor` | `ALG-CAL-001 §10` 这类条款 ID 锚——不判存在性 | 降级 |
| `unresolved_bare_anchor` | 裸 `§N`（无路径）——自指/仓外标准/代称三者不可区分 | 降级 |
| `external_ref` | 指向仓外标准/文献，仓内不可判定 | 降级 |

### 同名不同义：标出，不折叠

工具从不把同名目标折叠成「重复引用」，也从不默认取第一个：

- **同名多义（路径）**：同一后缀匹配到多个真实文件 → `ambiguous_target`，列全部候选。
- **同名多义（节名）**：同一节名在 k 个真实文件里都是标题 → `ambiguous_target`，列候选。
  实测 `「参数与常数」` 是 11 份文档的标题；这种必须由人判。

### 章节存在性不靠「仓内是否出现过」

这一条是本工具与「grep 一下编号」的根本差别。实测对照：

```
# 朴素做法（错误）：只看编号在仓库里有没有出现过 → §3.7 能解析 → 假通过
$ grep -rn '§3.7' docs/ | wc -l          # 有命中，于是判「通过」
# 真相：DATA_SEMANTICS.md 同时有
### 3.7 帧身份与输入清单摘要   (:145)
### 4.4 溯源最小集             (:231)
# 也就是说 §3.7 解析得到的是另一个节
```

`check_anchors.py` 的做法是把 `§3.7` 解析到 `### 3.7 帧身份与输入清单摘要` 这一行，
再拿括注/节名去比对，判题不符。

## 4. 跑全仓的真实结果

不是「已构建」，是**跑了**：

```
$ cd "/workspace/Astro CS Database" && python3 eng/tools/doccheck/check_anchors.py \
    --json /tmp/acsd_anchor_scratch/full_run.json
```

### 扫描口径

- 文件清单来源：`os.walk（磁盘全集）+ git ls-files（跟踪集）`
- 实际扫描文件：**1531**
- 扫描面：`docs`、`eng`、`lib`、`testdata`、`gaia` + 仓库根 `.md`
- 排除**顶层**目录：`.git`、`artifacts`、`run`、`build`、`out`、`logs`、`site`、`node_modules`
- 排除任意层级：`third_party`、`__pycache__`、`.pytest_cache`、`.dsh-code-index`

三处口径是被本项目实测逼出来的，不是偏好：

1. **解析全集用磁盘，git 只用来判「未入版本控制」。**
   `.gitignore` 的 `build/` 规则让 `docs/engineering/build/` 整层脱离版本控制
   （`git check-ignore` 实测：`.gitignore:20:build/`）。拿 git 集当解析全集，
   指向那 4 份一级正本的每一条引用都会被误判成悬空。
2. **排除目录只从「引用发起面」排除，不从「解析面」排除。**
   `run/`、`artifacts/` 下有大量历史文档副本，文档确实会指向 `run/...`。
   把它们排除出解析全集，每一条指向 `run/` 的引用都会误判。
   但后缀匹配**只认正本**：一个裸后缀若只在历史副本里出现，那正本就是没了——
   那是路径悬空，不是「同名多义」。
3. **排除的是顶层同名段，不是任意同名段。**
   早先用「路径里任意一段命中排除名」，结果把 `docs/engineering/build/` 整层误杀。

## 5. 它抓不到什么（如实说盲区）

1. **锚在、内容不在。** `「WCS 计划」一节（:22–31）不含 85、不含「半球」` 这类
   「章节解析成功但该节没有这条域」的缺陷，**纯结构检查抓不到**。
   这是记录点名的第五类形态，本工具对它无能为力。

2. **漏报无法用抽样证明。** 30/30 确认的是**报出的准**，不是**该报的报全了**。
   本工具只报出下界，真实缺陷数必然更多。

3. **裸 `§N`（2419 条）三类不可区分。** 自指 / 仓外标准 / 分册代称，
   文本形态上无法区分。工具全部降级为 `unresolved_bare_anchor`，不冒充缺陷。
   要消掉这一大块，必须先补「代称 → 文件」映射表（工具内置了 5 条，不够）。

4. **条款 ID 锚 810 条不判。** `ALG-CAL-001 §10` 这类需要
   「合同 ID → 承载文档」映射表。仓内 `eng/contracts/anchors/anchor_contract.json`
   有 29 条 `resolvers` 可作起点，但不足以覆盖全量 ID 空间。

5. **`sha256` 一概不算。** `defaults.json` 登记的 `sha256` 是 **16 位十六进制**，
   而标准 SHA-256 是 64 位；且 `ANCHOR_CONTRACT.md` 写明的归一化算法
   （N1–N5）与实际值是否自洽**在四份审稿记录里均无记载**。
   强行计算必然 53/53 全错，那是构造性错报。本工具只报「引文查不到」。

6. **相对路径要靠人补前缀。** `docs/detail/**` 实测 733 处引用里，
   8 个「MISSING」全是相对前缀组合（`include/astro_scalar.h` 拼接
   `lib/algorithms/shared/` 后存在）。工具不做前缀猜测，一律降级
   `unresolved_relative`（491 条）。**宁可漏，不可猜**。

7. **同轮次混口径。** `docs/**` 实有 167 份 `.md`，git 跟踪 164 份；
   `实验/` 下另有大量证据快照（`file_audit_before.json` 这类**记录过去文件树**的
   文件，按引用扫会产出上千条假悬空）。因此默认扫描面**不含** `实验/`，
   与 `DOCUMENT_INDEX.yaml` 自订口径一致；要扫用 `--with-experiments`，
   且那批结果应单独看。

8. **不解析 JSON-Pointer 片段。** `X.json#/$defs/foo` 在 `#` 处截断，
   片段本身不校验（仓内实测 9 处 `#/$defs` + 23 处 `#anchor`，
   当前全部可解析，但本工具**没有验证这一点**）。

9. **不判文献编号 `[N]`。** 论文式 `[N]` 引用断链（记录称 `SECURE_LOADER.md`
   的 `[4][5][6]` 悬空）本工具不查。同时**不能**简单判：
   `PUBLIC_API.md` 的 `[6][16][32][64][256][512][1024]` 是数组维度，
   记录明写「判为数组维度/位宽写法，非文献引用，不计」。

10. **不做语义同义判定。** `F_ref`（顶点：视宁度/天光依赖的孔径轮廓通量）
    vs `F0`（science：固定星等档锚通量）这类「符号相同、物理量不同、
    且出现在权威顶点」的最高危同名不同义，本工具**完全看不见**。
    它只能告诉你「这个名字在哪些文件出现」，不能告诉你「两处含义不同」。
    记录同时留了一条**否决**先例：`a_k` 被判同名不同义后经逐条复核**推翻**——
    这类误伤只能靠人读，工具帮不上也不该帮。

11. **判定粒度是 (文件, 行, token, 目标)。** 记录点名要求
    「不得按行计分」：`UNIFIED_OBJECTS.md:124` 同一行既有 6 条有效引用又有 1 条死路径。
    工具按 token 分开记，不按行合并；但**同一 span 的多个属性**（如既悬空又是节号陷阱）
    仍记为两条，请勿简单相加。

## 7. 复盘：否决了什么

本单共派 6 个子代理分头建与验（超出派单要求的 3–5 个，因发现一个方向不足以覆盖
「引用形态普查」而加投）。逐条复核后**否决**的内容如下——否决理由都是
「会引入假阳性或超出工具定位」：

| # | 被否决的建议 | 出处 | 否决理由 |
|---|---|---|---|
| 1 | 把 `--fail-on-findings` 设为默认 | 通用检查器惯例 | 直接违反新正本「测试不是门禁、不产出阻塞退出码」 |

| 5 | 任何空括注 `（）` 都算替换残渣 | 第一版实现 | 全仓产出 15375 条假残渣（`main()`、`hexdigest()` 遍地） |
| 6 | 「最高设计，」这类空槽位宽形态 | 第一版实现 | 「本文档，权威链自上而下」是正常中文行文 |
| 7 | 相对路径按若干候选前缀拼接解析 | 733/8 的教训反着推 | 拼接要猜，猜错就是真漏报；降级 `unresolved_relative` 让人判 |
