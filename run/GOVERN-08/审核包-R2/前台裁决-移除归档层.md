## 车道提出的三个待确认项与前台裁决

### 一、基线不干净，脏文件正落在删除面 —— 裁决：按车道处置办
工作树 12 个未提交改动来自上一车道（G08-04 自检覆盖与恒真门），其中三份
`results/*.json` 正落在本单删除面。按 AGENTS.md §7 后到者不回滚覆盖：

  自愈锚改成只校验不生成、四条腿恒 `return 0` 改为返回失败数、列名 `bitwise` 订正为
  `bitwise_eq`。
- **重新生成的 json 按 A 类删除**，但**备份的是工作树当前内容**（不是 HEAD 内容），
  逐字节留档后才删。
⇒ 上一车道「刷新归档」这个动作本身方向已被否（刷新一个不该存在的层），
但它的**代码侧修法**是真收获，随本单保留。

### 二、两个 D 类文件 —— 裁决：同意车道拟处置
- **`ANCHOR.sha256` 迁到 `实验/m42-realdata/code/`**。理由：它只覆盖 code/*.py、
  run_all.sh、docs/*.md、README.md、REPORT_paper.md 共 11 项，**不覆盖任何 results
  文件**，属代码完整性而非归档层。保留上一车道把它从「自愈锚」改成「只校验不生成」
  的修法。
  ⚠️ **附加约束**：按负责人「判据不可信、不必核实为通过」的裁决，该锚**只能作变更检测
  用，不得作为正确性证据**，须在迁入处与单元 README 写明。
- **`SNAPSHOT.sha256` 与 `RUN.sha256` 随 A 类删除**。前者第 12–15 行正是四个
  results/*.json 的校验和，即归档同步机器件，正是被否掉的方向。
