## 1. 全仓引文核实清单

### 1.1 方法（可复跑）

机械重建，不靠人眼通读：

1. **C/C++**：自写状态机逐字符切分，区分**字符串**与**注释**两类 token；支持**相邻字面量拼接**（中间只容空白）、`\"` `\\` `\n` 转义还原；`//` 与 `/* */` 区间内的引号一律不计。
2. **Python**：`tokenize.generate_tokens` 取全部 STRING token（含 docstring）。
3. **抽引文**：
   - **形态 A（带引号）**：文档指称 `docs/**.md §X` 的**最外层括号对**内，用**栈**配对抽「…」/『…』（支持 `「全链没有「权重模式」…」` 同型嵌套）；引文归属取**最近的、在该引号之前**的文档指称。
   - **形态 B（无引号）**：`（<文档> §X（节名）：<从句>）` —— 冒号后整段即被引从句，按 `、，,;；` 切子句逐条核对。
4. **核对**：对 `docs/**` 全部 md 逐字子串匹配，另做去空白/去 markdown 强调的宽松二次匹配。
5. **基线取数**：`git archive HEAD | tar -x` 导出纯净快照到 `/tmp/g08_05/baseline`，与改后工作树**对同一份脚本**跑同一遍，集合差分 —— 避免「边扫边改」导致计数漂移。

> **形态 B 是本单的关键发现**：派单点名的**主项**（`module_adapters.cpp:14051`）的伪引**根本没有「」**，它是裸从句摆在 `（…§3.1（数据对象）：…）` 冒号后。只按「」成对抽取的扫描器会**整条漏掉主项本身**。我第一版扫描器即栽在这里，补了形态 B 后才把它捞出来。
