### 1.4 SIP 系数的真实域（决定「怎么接」，不是新造）

读生产的两处实现，确认 SIP 是**像素域**多项式，不是 astropy `wcs.sip` 期望的中间世界坐标（度）域：

- 前向：`module_adapters.cpp:4754-4757` — `p1_sip_poly(sip.a, xp-crpix1, yp-crpix2, sip.order, &A); wcs.pix2sky(xp+A, yp+B, ...)`
  即 `U = dx + A(dx,dy)`、`V = dy + B(dx,dy)`，`dx,dy` 是像素偏移、修正量加在像素上。
- 生产消费方（drizzle）：`wcs_sip.cpp:255-261` 同式（CD 矩阵在 SIP **之后**才乘）。
- 布局与多项式：`p1_sip_poly`（`module_adapters.cpp:4487`）与 `evalSipT`（`wcs_sip.cpp:79-95`）同式同布局 `i*6+j`。

⇒ **把落盘系数直接写进 `astropy.wcs.wcs.sip` 是量纲错误**（度域 vs 像素域，相差约 1/2.69e-4 deg/px ≈ 3720 倍，且旋转 90°）。
本单因此**不**走 `wcs.sip` 属性，而是把产物的 `wcs.sip` 以生产同域同式接到 astropy 的投影/反投影两侧（见 §2.3）。
代码注释里写明了这条禁忌，避免后来者「顺手改成 wcs.sip」而重新制造盲区。

### 1.6 一条决定性事实：好/坏两份产物的 WCS 块逐字节相同

取同一帧、同 solver 的两份（`out5/R58fix/` 正常 vs `out5/R58fix2/` 坏），做 JSON 扁平化逐叶比对：

```
differing leaf keys: 373
   /samples          370      (samples[].roundtrip_px)
   /forward_cross_ref 1
   /max_forward_cross_deg 1
   /max_roundtrip_px  1
wcs + sip identical: True      ← wcs 段与 wcs.sip 段**零差异**
```

⇒ **任何「从 WCS/SIP 重算」的判据都无法区分这两份产物**（重算量逐位相同）。
唯一有鉴别力的期望量，就是产物**自己落盘**的残差字段。这正是本单的判别依据

补充实测：26.08 px **恰等于**该产物前向 SIP 畸变幅度 `max|(A,B)|`（实测 26.0827 px）——
坏产物的残差就是「前向加了畸变、逆向没减」的特征量，与 `forward_cross_ref=_sip` 的自述一致。
