# 前台裁决 · 遗留格式退场的写入面

## 车道报告的冲突成立，裁 **A**

派单要求「删代码及其构建注册」，同时把写入面限定为 `lib/**` 与 `docs/**`。
但七个生产源文件的构建登记在**根 `CMakeLists.txt`**，`lib/` 下那份自述「根构建文件是
唯一产品事实源」⇒ **只删源文件不改根构建，构建必断。**

**裁定：写入面扩到根 `CMakeLists.txt` 与 `eng/tests/unit/CMakeLists.txt`。**
本轮做「删代码 + 删全部构建注册」这一个自洽改动。

**这是我派单写窄了。** 我给车道限定 `lib/**` 时没检查构建登记在哪一层 ——
与我在门禁那一单把「6236」当成受控规模、在这条把写入面写窄，是同一类错误：
**先假设一个范围，没核它是不是自洽的。**

## 车道遵守纪律的做法值得记

它在动手前发现「照字面执行会撕裂构建图」，**停下上报，不擅自越界**。
本项目此前出现过子代理越权写入他人交付件的事件，这条车道是反例：
**知道自己该做什么，也知道什么不该做。**

## 第 1 步结论已定论且证据独立

`.hiss` / `.hcsd` 判为**可删的重复产物 + 默认关闭的遗留比较通道**，三条独立证据链：
1. 一级科学正本逐字写「**生产路径只落标准 HiPS，不落任何 legacy 容器**」，并标某旧入口
   「零生产调用者」；
2. 生产编排文件全篇仅一处命中且在注释里；编排头文件逐字写「legacy 合并段 removed」；
   残留写出口**默认关闭**；
3. 浏览器后端已迁移到标准读取面；读旧格式的界面只属独立图形程序，不在生产三命令路径上。

⇒ 与最高设计 §1.2 / §8.1 / §10「阶段交换唯一媒介是磁盘 HiPS」一致。
