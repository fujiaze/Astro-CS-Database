## 3. 发现清单

### 3.1 阻断（3）

#### B1 · `m_ref` 的「适用域限定」含数学错误，且已由「终裁」传播进冻结正本

- **位置**：`docs/science/DISPUTE_RESOLUTION.md:290-298`（§27 终裁）；`docs/science/CONTROL_WEIGHT_SNR.md:199-208`
- **现状**：§27 终裁写「`w` 对 `m_ref` 的不变性是**代数恒等**」，紧接着写「**生产组成臂只近似成立**，实测档漂移 1.9%–4.2%」。**代数恒等不可能只近似成立** —— 两句互斥。机理写作「σ_F² 含源光子散粒项，源主导时 **F_ref 的归一不再与 SNR 完全抵消**」。`CONTROL_WEIGHT_SNR.md:207` 复述同一机理，`:202` 加「只在天光受限臂成立」，`:208` 据此推出「跨帧比对须限同一 m_ref 档，两档不可混比」。
- **应为**：该终裁须**重写**。正确表述为：恒等式 `w = SNR²/F_ref² ≡ 1/σ_F²` **无条件精确成立**；条件性的是 **`w` 本身**是否对 `m_ref` 不变 —— 因为 `σ_F` 是 `F_ref` 的函数（源光子项 `F·P_i/g`）。正确机理 = 「σ_F 随 F_ref 变 ⇒ 右端 `1/σ_F²` 随之变；左端与右端始终相等」。由此派生的工程规则（限同一 `m_ref` 档）**可以保留**，但依据必须换成「σ_F 含源项」而非「归一不相消」。
- **证据**：我用仓内**已发布**的 JSON 数值做盲复算（§5），两臂 × 6 个 `m_ref` 全部满足 `|SNR²/F_ref² ÷ 1/σ_F² − 1| ≤ 3.3e-16`（1–2 ulp）。生成该数字的脚本 `exp04_refmag_chain.py:149-156` 自己把此式标为恒真门、证据资格为空。`docs/engineering/UNRESOLVED_REGISTER.md:3218` 亦已点名其失效形态（「`σ_F := f_ref/snr`」的同义反复）。

#### B2 · `frame_snr` 分子两义（`F_ref` vs `F_signal`），人读合同与机器合同漂移方向相反

- **位置**：17 处 —— `docs/engineering/UNIFIED_OBJECTS.md:37`、`docs/detail/UNIFIED_MODEL.md:43`、`docs/detail/registry/acsd.phase1.noise-snr.md:88,91`、`docs/science/CONTROL_WEIGHT_SNR.md:20,197,263`、`docs/science/PSF_SIGNAL_WEIGHT.md:124,147`、`实验/absolute-snr/docs/frame-snr-canon.md:14`、`实验/absolute-snr/docs/EXP-05-ABSOLUTE-SNR.md:49,444,685`、`实验/absolute-snr/results/REVERSE_VERIFY_CANON.md:9`、`实验/additive-sky-seamless/{README.md:570,REPORT_experiment.md:282}`、`实验/photometric-magnitude/docs/PHOTOMETRY_LITERATURE_REVIEW_ARCHIVE.md:91`
- **现状**：顶点 `:124` 定分子为 `F_ref` 并**显式禁止**逐源实测通量。`F_signal` 的定义是「已扣独立估计的局部背景」= 逐源实测通量。二者不是同一物：`F_ref,k = 10^(−0.4(m_ref−ZP_k))` 是 `m_ref=6.0` 的**帧级标量**，`DATA_SEMANTICS.md:602` 自称 `frame_independent_fixed_magnitude`「无『组』概念」；`F_signal` 逐像素随源变。
  - **同格自相矛盾**：`docs/detail/UNIFIED_MODEL.md:43` 在**同一个表格单元格**内先写「通量型口径 `F_ref/σ_F`」，再写「`SNR=F_signal/σ_F`」。
  - **同块自相矛盾**：`实验/absolute-snr/docs/EXP-05-ABSOLUTE-SNR.md:49` 式 (1.1) 用 `F_signal`，`:57` 式 (1.3) 写 `w = 1/σ_F² = SNR²/F_ref,k²` —— 二者共存要求 `F_signal ≡ F_ref,k`。
  - **两合同面不一致**：`UNIFIED_OBJECTS.md:37`（人读）= `F_signal`；`eng/contracts/schemas/unified/frame_snr.schema.json:322`（机器）= `SNR_k(F_ref) = F_ref/σ_F,k`。机器面已单向迁移，人读面未回改。
- **应为**：`frame_snr` 分子唯一取 `F_ref`。`F_signal` 保留名，但**只**用于 `source_snr`（逐源诊断量，顶点 `:125` 已如此规定）。`UNIFIED_OBJECTS.md:37` 必须与 `frame_snr.schema.json:322` 对齐。

### 10.7 两条经我亲自验证的新阻断（来自 F_syn 分片回报，计入本件）

**B4 · 机器合同把 `F_syn` 说成「ADU 等价、非物理」，与冻结正本**及其自身同一文件**冲突**
- **我亲自验证**：
  ```
  sed -n '355p' eng/contracts/schemas/unified/frame_snr.schema.json
  ```
  逐字：「`reference_flux_common` 的单位口径。F_syn (Gaia XPSD absolute spectral integral) = **与 F_instr 同标度的合成通量单位（ADU 等价），非物理 W/m^2**。」
- **冲突一（对正本）**：`PHOTOMETRY.md:74,76,173` 逐字声明 `F_syn` 是物理量 `W·m⁻²·nm`（`F_syn = hc·N_γ`，`hc = 1.986445857e-16 J·nm`），并明写「`F_instr` 单位 ADU，与 `F_syn` **量纲不同**」。按 AGENTS §3，科学正本高于工程合同 ⇒ schema 该行错。
- **冲突二（对自己）**：**同一文件 `:374`** 逐字写「本帧测光零点 **`ZP_k = ZP_syn − 2.5*log10(k_photo,k)`**，满足 `mag = ZP_k − 2.5*log10(F_adu)`」。这个修正量**只有在 `ZP_syn`（F_syn 制）与 `F_adu`（ADU 制）不同标度时才存在**；若 `:355` 成立（ADU 等价），该修正量恒为 0、自相抵消。`:355` 与 `:374` 不可能同真。

**B5 · ADU 侧 `ZP` 的定义式在 DATA 合同中缺失（静默偏差量级极大）**
- **我亲自验证**：
  ```
  sed -n '590p' docs/science/DATA_SEMANTICS.md
  ```
  逐字：「| frame_depth_m5_mag | f64/null | mag | **m_5 = ZP − 2.5·log10(F_5)**；无 ZP → null |」（`F_5` 单位 ADU）。
  ```
  grep -n "ZP_k\s*=" docs/science/DATA_SEMANTICS.md     # → 无命中
  ```
  ⇒ `ZP_k` 的定义式**在 DATA 合同中完全不存在**；`:608` 的 `F_ref,k = 10^(−0.4·(m_ref − ZP_k))` 用了一个本文件从未定义、也未声明用的是 `ZP_syn` 还是 `ZP_k` 的符号。
- **后果量级**：`ZP_syn` 与 `ZP_k` 之差 = `2.5·log10(k_photo)`。按仓内自报实测 `location = 16.2 dex`（`module_adapters.cpp:5527`）⇒ `k_photo = 10^(−16.2) = 6.27e-17` ⇒ 差 **40.5 mag**。消费方若把落盘的 `zero_point_mag`（ZP_syn，F_syn 制）直接配 ADU 通量，`m_5` 与 `F_ref,k` 整体偏 40.5 mag，**且无任何告警**。
- **应为**：在 `DATA_SEMANTICS.md` §13.4 显式写 `ZP_k = ZP_syn,k − 2.5·log10(k_photo,k)`，并声明 `zero_point_mag` 落的是 **ZP_syn（F_syn 制）**。
- **佐证（代码是对的，错的只是合同文本）**：`lib/infrastructure/scheduler/src/module_adapters.cpp:7179` `zp_inst_of_key[key] = zps - 2.5*log10(kp)` —— 代数经独立验算成立（由 `F_adu = F_syn/scale` 推得）。**这正是本域的典型失效形态：实现正确、合同缺定义、错误只在按合同书写消费方时才显形。**
