## 1. 复核结论 → 处置 → 注入实测

### 1.1 【最严重】B3 的 G6a 恒真门

**复核结论**：绝对臂 `1/recon_absolute(s) = 1/(1/s) = s` 逐位恒等，`est` 与 `true` 是同一数组 ⇒ `median_ratio ≡ 1` ⇒ `abs_dev ≤ 1e-12` 恒真。相对臂只有下界 `>0.05`，污染越重越绿。

**独立确认（整改前代码，/tmp 副本）**

| 探针 | 实测 |
|---|---|
| `1/recon_absolute(sp)` 是否逐位等于 `sp` | **否**，max 相对差 `1.485e-16`（1 ulp）；`sp2` 恰好相等 |
| `cross_frame_ratio_dev([1/sp1,1/sp2],[sp,sp2])` 的 `median_ratio` | `1.0`（精确） |
| 相对臂基线 `rel_ratio` / `rel_dev` | `0.772416` / `0.2276` |
| 注入「帧级标量 ×2」 | `rel_ratio=0.386208`，`rel_dev=0.6138` → **绿** |
| 注入「`sp2` ×1000」 | `rel_ratio=0.000772`，`rel_dev=0.9992` → **绿** |
| 注入「两帧共乘因子 7.0」 | `median_ratio = 1.0` **精确** ⇒ 共模盲区确认 |
| `c1/c2` 复算 | `c1=1.684075`、`c2=1.300807`、`c2/c1=0.772416` ⇒ 与 `rel_ratio` 逐位一致 |

> **见 §2.1**：复核对「逐位恒等」的机制描述不准确（结论不变，且理由更强）。

**处置：G6a 重做。**

核心设计：**换掉参照量的来源**。新建「已知噪声场装置」——

```
v_k(p)  : DELTA×DELTA 块上恒定的噪声标准差（生成参数）
img_k   = rng_k.normal(0,1) * v_k          # 无结构污染
T_k     = 1 / v_k                          # 解析精确真值（SNR 空间）
```

- 该块内每个像素的噪声标准差**精确**等于 `v_k(p)`，故 `T_k` 是解析精确真值，不是估计量。
- **为什么不再同源**：`T_k` 由 `v_k` 直接给出，`v_k` 只出现在 `np.random.default_rng(seed).normal(0,1)*full` 这一行；它从不经过 `represent_absolute` / `recon_absolute` / `represent_relative` / `effective_sigma_relative` / `cross_frame_ratio_dev` 的 est 臂。整改前 `est=[1/sp1,1/sp2]`、`true=[sp,sp2]` 是**同一批数组**，比值恒等于 1；现在 `true` 是生成参数，`est` 是被检验量。
- 设计前自问（恒真门三型）：①代数恒等式型 —— 否，参照量不是待检验量的逆或导出量；②结构对称型 —— 否，两臂的 `true` 与 `est` 来自互不相交的数据路径；③往返自证型 —— 否，`T_k` 不由 `est` 往返导出。

## 2. 我推翻/订正的复核判定

### 2.1 「逐位恒等」的机制描述不准确（结论不变，理由更强）

**复核原文**：「绝对臂 `1/recon_absolute(s) = 1/(1/s) = s` **逐位恒等**，`est` 与 `true` 是同一个数组 ⇒ `median_ratio ≡ 1`」。

**实测**：
```
1/(recon_absolute(sp))  vs  sp : bitwise==s? False, max 相对差 = 1.485e-16 (1 ulp)
1/(recon_absolute(sp2)) vs  sp2: bitwise==s? True,  max 相对差 = 0.0
```
即 `1/(1/s)` 在 IEEE-754 下**并非**逐位等于 `s`（差 1 ulp）。

**结论仍成立，但理由更强**：`median_ratio ≡ 1` 不是因为「逆函数逐位还原」，而是因为 `cross_frame_ratio_dev(est, true)` 里 `est` 与 `true` 是**同一批数组**，于是 `e/t ≡ 1` **与任何浮点舍入无关**。判据的恒真性比复核描述的更强 —— 即使把 `1/recon_absolute` 换成任何别的函数，只要两臂喂同一个数组就恒绿。整改正是从这一层根因入手（换掉 `true` 的来源），而不是去修那个逆函数。

### 2.2 B2 证据的行号订正

复核给 `README.md:275-277` 与 `scia_common.py:381-382`；实测为 **`README.md:268` / `:284` / `:398` / `:437`**（四处均载）与 **`scia_common.py:384-385`**（`lo`/`hi` 两行）。裁决方向不变。

### 2.3 「22289× 取了最有利的一条」的措辞需要收紧（处置不变）

复核说 22289× 是「取最有利的一条」。实测表明它**不是** 23 条重放读数里的最大值：23 条里的最大值是 **`A_bglimit.E_stacking` 的 1,283,962.23×**；22289.47× 是 `A_full.dynrange_T_p1`，恰好是**旧 sens 探针那两个分位里的 max**（探针只比 p1/p99 两项）。
