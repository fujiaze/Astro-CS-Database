### 阻断（2）

#### B-01　全文档唯一索引不是合法 YAML，12 条登记条目已脱出 `active` 区段

- **位置**：`docs/DOCUMENT_INDEX.yaml:97`，另 `:348 :353 :363 :384 :399 :455 :475 :561 :712 :954 :959`，共 12 处；区段边界 `:993`
- **现状**：12 条 `- path:` 行的缩进不是规范的 4 空格，而是 8/12/16 空格。YAML 解析器在 `:92` 开始解析块映射时于 `:97` 遇到块序列起始，直接报错：
  ```
  while parsing a block mapping
    in "docs/DOCUMENT_INDEX.yaml", line 92, column 7
  expected <block end>, but found '<block sequence start>'
    in "docs/DOCUMENT_INDEX.yaml", line 97, column 9
  ```
  全文件 183 条 `- path:` 的缩进分布：4 空格 171 条、8 空格 8 条、12 空格 3 条、16 空格 1 条。
- **应为**：索引必须能被解析器读入；否则"全文档集唯一索引地图"在结构上不存在。
- **证据**：
  1. `python3 -c "import yaml; yaml.safe_load(open('docs/DOCUMENT_INDEX.yaml',encoding='utf-8'))"` → `ParserError`。
  2. **回归由 `ed33f57f` 自身引入**：上一版 `git -c core.quotepath=false show ed33f57f~1:docs/DOCUMENT_INDEX.yaml` 的 200 条 `- path:` **全部**为 4 空格，`safe_load` 成功、读出 200 条 active；当前版 12 条被改缩进。
  3. **不是无害的**：`eng/tools/quality/gen_module_readmes.py:215` 对该文件调用 `yaml.safe_load`，异常时于 `:217` 返回 `OWNERSHIP_INDEX_UNPARSABLE`，该函数是"授权面"读取器（`:206-207`），返回空授权集 ⇒ 生成器失去全部写入授权（fail-closed，设计如此）。索引中 `status: GENERATED` 条目实测 **11** 条（`grep -c 'status: GENERATED'` = 11），这 11 份生成页当前**无法再生成**。且该错误串把原因写成"无授权面证据"而非"索引文件坏了"，**会把排障引向错误方向**。
  4. **反证「只是外观问题」不成立**：仓内治理正本自己把它列为缺陷条件——`docs/engineering/DOCUMENT_GOVERNANCE.md:71`「**判缺陷**：文件树里有、索引里没有；索引里有、磁盘上没有；**索引条目自身解析失败**」。
  5. **讽刺点一**：`ed33f57f` 提交说明新增了一类"机器结构上抓不到、只能人读"的缺陷，**首条即 YAML 映射键重复**（`DOCUMENT_GOVERNANCE.md:81` 的 C3-1）；但 C3-1 只覆盖"重复键后者覆盖前者且不报错"，**没覆盖更基础的"根本解析不了"**。同一次提交却交付了一个连解析器都进不去的 YAML。
  6. **讽刺点二**：索引的机器门 `check_doc_index.py` 已被 `ed33f57f` 删除（`git -c core.quotepath=false ls-files | grep doc_index` 零命中）。仓内仅剩的两个消费方中，`check_cfg002_registry.py` 用纯文本正则（`.strip()` 吃掉缩进，对本缺陷**免疫**），真正会炸的只有 `gen_module_readmes.py` 一个——**恰好是唯一没人盯的那一个**。
