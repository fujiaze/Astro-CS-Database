## 1. 判定式：什么算「生成物」

### 1.1 判定式 G1（可机器复跑）

```
G1(f)  ⟺  P0(f) ∨ [ P1(f) ∧ P2(f) ∧ ¬P3(f) ]

P0  vendor   ：路径含 third_party/vendor/external        ⇒ VENDOR（单列，不并入生成物）
P1  产出面   ：路径命中「运行记录面」正则闭集
P2  数据形态 ：扩展名 ∈ {json, jsonl, csv, out, log, tsv}
P3  手写面   ：路径命中手写面豁免（优先级高于 P1）
其余          ⇒ HUMAN（人工产物）
```

### 1.2 判定式为何这样定（立身之本）

**关键区分：「机器校验」≠「机器生成」。**

- `eng/contracts/data/clause_registry.json`（4,159 行）被 `eng/tests/contracts/product_family/field_constraints_oracle.py` 读取校验，但它是**人手写**的合同注册表 ⇒ P3 豁免 ⇒ HUMAN。
- `lib/infrastructure/pipeline/module_ports.registry.json`（2,197 行）自陈「由 `eng/tools/quality/check_block_flow_ports_vs_code.py` 双向机器复核」，带 `owner` / `frozen_at` ⇒ 机器**校验**而非**生成** ⇒ HUMAN。
- 反证面：`eng/contracts/ledgers/` 下机读台账由生成器写出 ⇒ P1 命中 ⇒ GENERATED。

**登记面自己写的声明不能当判定式。** 仓内有两条声明：

- `docs/DOCUMENT_INDEX.yaml:24`：「机器源与台账不进 docs，落在 `eng/contracts/` 与 `artifacts/evidence/`」

## 3. 片划分

### 3.1 抗漂移切片规则 SRS-1 + SRS-2

原台账的病根是**片定义挂在绝对行数上**：`:18` 用「总行数 ÷ 11k」直接算车道数，分母一涨，63 这个数就无声作废，且没有任何重切触发点。

新规则把片身份挂在**目录分层**这条结构轴上：

```
SRS-1  层内 LPT 均衡装箱
       层 = 固定目录分层（docs/science、docs/engineering、docs/detail、
             lib/algorithms/<模块>、lib/infrastructure/<模块>、eng/<子>、实验/<单元>）
       每层片数 n = ceil(层行数 / C)，C = 11,000
       层内文件按「行数降序 → 放进当前最空的一片」(LPT) 分配
       不跨层
SRS-2  尾域合并：层行数 < 2,000 的层并入同根 TAIL-<root> 层
       （消除「一条车道只读 23 行」的碎片）
```

**为什么抗漂移：**

1. **片数只依赖各层自己的行数**，不依赖全仓总量。某层变大只增加该层的 `n`，其它 40 层的片号与成员**一字不动**。
2. **容量是下界不是切片输入**。旧规则用「总量 ÷ C」求车道数，容量一变全体作废；新规则里 `C` 只在 `ceil(层行数/C)` 里出现，层内结构稳定时片号稳定。
3. **片清单入仓**（`片清单.yaml`），不再是 `/tmp/r3/s000.txt`。漂移时按 SRS-1 重跑即可复现，并可与旧片号做映射。
4. **LPT 消碎片**：旧式顺序贪心会留下 23 行、29 行的尾片；LPT 后最小片 1,012 行。

**SRS-2 的漂移代价（如实登记）**：某小层行数跨过 2,000 阈值时，它会从 TAIL 层独立出去，该层片号重排。这是本规则唯一的不稳定点，已在 §7 登记为待裁项。

### 3.2 片数依据：为什么是 92

```
片数 = Σ_层 ceil(层行数 / 11,000) = 92
     = 理论下限 70  +  22 片「不跨层」装箱余量
```

两条约束同时决定 92，缺一不可：

1. **容量下界**：92 ≥ ceil(766,744 / 11,000) = 70。低于 70 必然有车道超容量。
2. **不跨层**：层是语义完整的最小单位（一个 `lib/algorithms/<模块>` 拆到两条车道会割裂模块认知）。41 个层各自取整，向上取整累计多出 22 片。

**若允许跨层，片数降到 70。** 我不这么做——省 22 条车道的代价是模块被割裂，而本项目的审查对象是**跨文件语义矛盾**（正本与代码互斥、口径冲突），割裂模块会显著降低发现率。这 22 片是**为语义完整性付的显式成本**，不是浪费。

**2 片超容量（如实登记，未隐藏）**：

| 片号 | 行数 | 原因 |
|---|---:|---|
| `INF-scheduler-001` | 16,260 | 单文件 `lib/infrastructure/scheduler/src/module_adapters.cpp` |
| `ENG-packaging-001` | 14,962 | 单文件 `eng/packaging/config/filters.json` |

两片都是**单文件成片**——文件本身超过容量，无法再切。`轮1v3-片01.md` §0 记该文件 16,252 行由单车道读完 100%；本文件在 HEAD 已涨到 16,260 行。这两片建议**按段拆读**并单独登记覆盖率，处置见 §7。

分档：<2k: 3   2k–5k: 8   5k–9k: 37   9k–11k: 42   >11k: 2
