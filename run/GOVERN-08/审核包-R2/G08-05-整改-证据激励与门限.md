| # | 缺陷 | 原文位置 | 后果 |
|---|---|---|---|
| D1 | 证据量由判决导出 | `:38 if r["ok"]:` | 恒真门永绿 ⇒ 恒计入；真门一旦判红 ⇒ 证据被扣。**激励方向相反** |

**D1 的方向性论证**（这是机理的核心，不是修辞）：设门 G 的证据量 `E(G) = |{check c : c.gates ∋ G ∧ c.ok}|`。则

- G 恒真 ⇒ 每个引用它的 check 恒 `ok` ⇒ `E(G) = |{c : c.gates ∋ G}|`（上界），**证据量最大化**；
- G 有效判别且**发现了真实缺陷** ⇒ 该 check 变红 ⇒ `E(G)` **下降**。

即「越恒真证据越多、越有效越扣证据」。`E(G)` 是 `G` 自身绿度的**单调不减函数**，与「`G` 有多可信」无关甚至反相关。

### 1.3 改后口径

**唯一认可的独立证据**：本门在 `qa_matrix.json` 登记的 mutation 中，**实测观测到本门自身变红**的条数（`evidence/mutations.json` 里 `targets_covered[gid] is True`）。

选它的理由，逐条对齐任务书的禁则：

| 任务书要求 | 本口径是否满足 |
|---|---|
| 独立于该门自身判决 | ✅ 判红的门照样拿满额证据（它**被执行并判定过**）。恒真门恒拿 `red=0`，拿不到满额 |
| 不得改成另一个由该门自身导出的量 | ✅ 数据源是 `run_mutations.py` 注入缺陷后的实测记录，不读 `oracle_baseline.json` 的 `ok` |
| 无基线不得判满额 | ✅ `baseline_ok` 或 mutation 记录缺失 ⇒ `EV_UNKNOWN`，`counts_as_pass=False`，**绝不默认 true** |

**三级证据强度，分开记不合并**（合并就是把弱证据伪装成强证据）：

- `gate_level_red` —— 本门自身被观测变红，**唯一可判满额**；
- `validator_level_red` —— spec/doc 类：校验器判红但未逐门隔离，**只证明校验器能红，不证明本门能红** ⇒ 不判满额；
- `dispatched` / `undetermined` —— 排期与调度事实，不参与 PASS。

**三个正交理由**，说明它不是「换一个由自身导出的量」：
1. 判据的**目标**登记在 `qa_matrix.gates[].mutations`，属规格面，与运行结果无关；
2. 观测**来源**是 `run_mutations.py` 注入缺陷后的 `results[]`，与 `oracle_baseline.json` 的 `ok` 无数据流关系；
3. 失效方向相反：旧口径下**门变红 ⇒ 证据减少**，新口径下**门变红 ⇒ 证据增加**。

### 1.5 新自检如何暴露反激励

`self_check()` 随台账写入 `case_ledger.json.self_check`，并打进 `06_case_ledger.log` 与 `rc_summary.json`（`ledger_self_check`），**不是死代码**。

两个数：

| 字段 | 含义 | 静态推导值 |
|---|---|---|
| `n_full_marks_without_gate_level_red` | 满额但实测无法判红 | **0** |
| `n_hole_under_retired_rule` | 被退役口径判满额、但无门级红证据 | **8** |

**自检可被证伪**：第一个数**必须恒为 0**，且它不是靠代码写死 0，而是 `full` 与 `gr < 1` 两个条件的真实求交。任何人把 `counts_as_pass` 改回由自身绿度导出，这个数立刻离开 0 —— **反激励结构会自己暴露自己**。

第二个数是**基线**：它把「若不改口径，这 8 门会拿满额而实测判不了红」这件事固化进产物，任何人看台账都能立刻看到洞的大小。改口径前后 `40 − 32 = 8` 即本次整改的实际收益。

8 门名单：`G-RD-04`、`G-BASE-05`、`P0-01`、`P0-02`、`P0-03`、`P0-04`、`P0-05`、`P0-06`。

**这 8 门为何降级（如实登记，不掩饰）**：它们全部是 `structural` / `p0_root_cause` 面。其登记的 spec/doc mutation 被检出时，校验器是**按规则集**（`V-ORACLE-MUSTNOT`、`V-LEDGER-ZERO` …）整体判红的，`run_mutations.py:47` 记的是 `rules`，**不产生 `targets_covered`**，因此无法证明「该门单独变红」。它们此前拿满额靠的是 `:53/:58/:63` 的字面量 `True`，**不靠任何证据**。降级是如实登记，不是把门判红。

### 1.6 「独立证据量不存在吗」—— 存在，但有两处必须承认的局限

**结论：存在，且可离线导出。** 数据源 `evidence/mutations.json`（`run_mutations.py` 产出，56 条 mutation 全检出）已在仓内，44 门全部有非空 `mutations` 登记，**无需新造数据**。

**局限一（重要，影响本次结论的强度）**：`gate_level_red` 是**门级**量，不是 **check 级**量。一个门可以内部搭载恒真 check 而整体仍获满额。本仓就有实例：`实验/TAUTOLOGY_REGISTER.md:356` 登记 `qa_oracle.py:250-256` 的 `CHK-ANA-11F` 为恒真门（`m = abs(xj/xj − 1) + abs((0.8²·xj)/(0.8²·xj) − 1)`，两边字面相同 ⇒ `measured ≡ 0.0`，函数体从不引用参数 `B`），但 `G-ANA-11` 另有 `CHK-ANA-11` 真检出 3 条 mutation ⇒ 门级判红 ⇒ 新口径仍给满额。
⇒ **本次整改不能被读作「32 门已证明无恒真成分」**。它证明的是「32 门各自被实测观测到能变红」。check 级恒真成分需要另设一道 check 级自检（见 §6）。

**局限二**：`n_hole_under_retired_rule = 8` 是**下界不是上界**。若某门登记的 mutation 恰好破坏的是 oracle 的独立重算而非该门自身的同源性，该门仍会显示 `gate_level_red ≥ 1`。本口径能证明「该门有判别力已被观测到」，**不能证明「该门没有自证成分」**。判别依据仍须按项目纪律逐门读原文。
