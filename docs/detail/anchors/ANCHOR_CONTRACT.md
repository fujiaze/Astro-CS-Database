## 1 适用范围（撤销后的口径）

**行锚只用于外部文献与外部代码两类目标**。**指向本仓任何文件（代码或文档）一律不留行号**：
文档之间的位置表达一律用**内容锚**（§9）或 `§条` 引用，不得写 `某文档.md:N`；
文档指向本仓代码同样不得写 `cpp/foo.cpp:123`。

原「`docs/**/*.md` 全域行锚扫描 + 规模声明（C7）逐字复测」条款属仓内行锚制度，随 2026-09-30
撤销一并作废；`anchor_contract.json.doc_globs` 的文档扫描面不再作为行锚判定面。

保留下来的行锚形态（仅用于外部文献与外部代码）：

`@text
path/to/file.ext:N          path/to/file.ext:N-M
path/to/file.ext:N,M        path/to/file.ext:N/L          path/to/file.ext#N
path/to/file.ext:N（symbol）    path/to/file.ext:N + backticked symbol
`@

**一行多锚 = 逐 token 各成一条独立锚记录**：`<file>:N-M / :A-B / :C`
是**三个**锚；续锚与首锚同文件、同登记规则（§3），各自判界内（C3）、各自判边界空行（C6）、
各自参与符号绑定（C4）。该逐 token 口径由解析实现与对抗性审查共同保证。

**`#N` 是行号锚，`§N` 是章节引用——两者各自独立、取值互不代用**：
C 头文件/脚本里的 `#158` 指第 158 行；引用章节一律写 `§条` 并写全路径，
不得写 `…#4a` 形态（会被读成行号）。

## 2 锚的语义义务

本节只管**外部锚**（指向外部文献与外部开源实现，登记面见 §4.1）。指向本仓任何文件
（代码或文档）的行锚一律不写，原先以仓内文件为目标的语义义务随仓内行锚撤销一并作废。

1. **锚是断言**：`file:N` 断言「本文档所描述的该符号/行为位于 file 的第 N 行」；
   目标移动即锚失效，**更新行号时锚所指向的符号、公式、默认容差保持逐字不变**
   （语义不变，只改数字），任何顺手改写语义的编辑都属越界。
2. **一个锚一个目标**：锚目标必须能被唯一解析；存在同名多候选时显式钉死唯一目标。
3. **边界行只取有内容的行**：`file:N` 的 N、`file:N-M` 的 N 与 M 都必须是**有内容的行**；
   边界落在空行 = 锚没指向任何内容。订正方式仍是「只改数字」：区间锚裁掉边界空行，
   单行锚平移到其后首个非空行。
4. **语义已变的不硬凑**：被引内容已不在该处（不是边界空一行而是整体漂走）时，
   行号取值只来自实际内容位置；或在 §4.1 登记为已知漂移。

原第 3 条「SCI 修改从 SCI 发起」只服务于 ALG 文档引述 SCI 冻结声明原文的**仓内文档**行锚豁免，
该情形已由 §9 内容锚承载，随仓内行锚撤销一并作废。

## 3 解析规则（代码与外部锚）

外部锚的目标**不在本仓**，无法在本仓解析（原 `exact` / `contract-rule` /
`basename-unique` 三步与 `doc-relative` 步都只在仓内路径面上定义，随仓内行锚撤销一并作废；
`anchor_contract.json.resolvers` 的 `doc`/`doc_prefix` 显式规则面同步失效）。

外部锚一律**逐条登记**在 `unresolved_registry.json`（只减不增）；未登记即由对抗性审查判红。
登记不是放行：登记项只是「暂时无法判」的显式台账，新增一条要在同一提交里
写清 `kind`/`reason`/`owner`/`handoff` 并抬高 `max_entries`（棘轮）。
仓内文档之间的定位一律走 §9 内容锚。

## 4 审查判据（无机器门）

原 checker 判据表随仓内行锚机器门撤销不再自动执行；下列各条保留为**人工审查判据**，
由对抗性审查逐条核对。原 C1（作用域文档 `docs_tracked` 扫描）与 C7（本文件 §1 规模声明
逐字复测）只服务于**仓内文档扫描面**，随该面一并作废。

| 规则 | 断言 | 失败含义 |
|---|---|---|
| C2 anchor_resolved | 每个锚经 §3 唯一解析到真实跟踪文件，或已登记于 unresolved_registry | 目标改名/删除，或同名分歧未登记 resolver，或新出现的未解析锚未登记 |
| C3 range_in_bounds | start/end 落在 1..目标行数 内且 start<=end | 目标变短或锚越界（典型漂移） |
| C4 symbol_binding | `bindings` 声明的 (doc, target, symbol)：该文档内必存在指向 target 且**行范围内逐字包含** symbol 的锚 | 符号整体消失 = STALE_BINDING；符号已移出全部锚范围 = BINDING_VIOLATION（漂移锚） |
| C5 exemptions_live | 每条豁免必须命中至少一个真实锚 | STALE_EXEMPTION（锚已不存在，豁免必须删除） |
| C6 boundary_blank | 已解析且界内的锚，其 start/end 行**都不是空行**（空行口径 = `read_lines`：只去一个尾换行后的空串；**纯空白行不算空行**，用 rstrip 判空会误报） | 锚的边界落在空行 = 锚没指向内容 |
| C8 unresolved_registry | 未解析锚必须已登记；登记项必须仍命中；条目数 ≤ max_entries | 新未解析锚未登记 / STALE_REGISTRY / 棘轮被突破 |

### 4.1 外部锚的豁免（exemptions）与未解析登记（unresolved_registry）纪律

已由 §9 内容锚取代，不进入本节两处登记面。

两处都是**登记**而非放行，`kind` 取值以数据文件为准（不跨登记面代用）：
`exemptions` 每条给出 `kind` / `reason` / `owner` / `evidence`，
`unresolved_registry` 每条给出 `kind` / `reason` / `owner` / `handoff`。现行取值：

`exemptions`（`anchor_contract.json`；外部锚，**永久不判**）一类：

- `EXTERNAL_REFERENCE`：锚指向未 vendor 进仓库的外部开源实现（photutils / astropy /
  DeepSkyStacker 等）或外部许可证据文件，属文献与开源对照引用，非本仓源码锚。

## 5 维护义务（同提交规则）

以下各条只适用于**外部锚**（指向外部文献与外部开源实现）。指向本仓任何文件
（代码或文档）的引用不走本节：仓内文档之间一律按 §9 内容锚（同提交更新

- **新增解析不到的锚**（外部引用）→ 同一提交登记 `unresolved_registry.json` 并抬高
  `max_entries`；锚能修好时**必须先删登记项**（否则判 STALE_REGISTRY，登记项不能留成僵尸）。
- **引用 Markdown 章节**写 `§N`，不要写 `#N`（见 §1 形态消歧）。

## 9 内容锚（content anchor，R-54 首选形态）

**适用面**：一切「引用某段规范文本/某个文档表行」的位置表达（登记面、测试期望、判据表）默认用**内容锚**，
不用行号。行锚（`文件:N`、`文件:N-M`、`文件:N,M`、`#N`）**只用于外部文献与外部代码**，仓内任何文件
（代码或文档）之间一律用内容锚或 `§条` 引用（见 §1 撤销口径）。两者分工：内容锚承载
「这段文本文义上是哪一段」，行锚承载「外部目标位于第几行」。

### 9.1 形态（唯一机器形态）

```text
{ "id": "<锚 id>", "path": "<文档/文件仓库相对路径>", "quote": "<被引原文（可多行）>",
  "sha256": "<16 位十六进制内容指纹>", "value_text": "<该引文里被锁住的取值/字面量文本>" }
```

- `id`：区分目标；无区分力 token（单字、单词、泛词）**不能**充当 id（R-54 §2）。复合键面（配置旋钮、滤镜、
  协议字段）一律用**复合键路径**（如 `03_star_detection.min_area`、`filter-negative.bader r`）。
- `path`：目标文件；文件不存在 ⇒ 判红（fail-closed）。
- `quote`：**归一化后**在目标文件全文内的**连续子串**；长度 ≥ 2 字符（`MIN_QUOTE_CHARS`）。
- `sha256`：`quote` 的归一化指纹（§9.2）。
- `value_text`：该锚必须锁住的那个取值/判据文本（数值按**数值**相等提取原文 token；字符串按**大小写不敏感**
  定位后取原文写法）。它必须**逐字出现在 `quote` 内** ⇒ 锚锁的是「值」，不是「任意能找到的句子」。

### 9.2 归一化与指纹（唯一算法）

```text
N1  CRLF -> LF
N2  逐行去首尾空白（strip）
N3  行内连续空白折叠为单个空格
N4  丢弃归一化后为空的行
N5  以 "\n" 连接
fingerprint(quote) = sha256(N1..N5(quote).encode("utf-8")).hexdigest()[:16]
```

归一化只做「空白层面」的对齐，**不做**大小写折叠、Unicode 归一或标点替换：
文档大小写/全半角改写仍会判红（这是特性，不是缺陷）。

### 9.3 判据（全部可红；实现唯一 = `eng/tests/config/cfg_anchors.py`）

| 编号 | 判据 | 判红条件 |
|---|---|---|
| D1 | 区分力下限 | `quote` 归一化后 < 2 字符，或锚里混入位置字段（`line`/`token_line`/`ref_line`） |
| D2 | 唯一命中 | 归一化 `quote` 在归一化全文内命中 **0 次**（锚不成立）或 **≥2 次**（无区分力，须加长引文） |
| D3 | 指纹自洽 | 重算指纹 ≠ 登记 `sha256` |
| D4 | 值覆盖 | `value_text` 不在 `quote` 内（锚没锁住该值） |
| D5 | 登记面零行号 | 登记面（JSON 全文）出现 `文件:行`；测试期望或登记点写行号 |
| D6 | 同一目标唯一 | 同一 `id` 在同一面出现两次而 `path/quote` 不同 |

命中偏移 -> 行号的换算由实现提供（`anchor_matches` 返回 1 基行号），**该行号只用于报告**，
**只读不回写**：登记面与测试期望保持零行号（R-54 §4）。

### 9.4 何时仍用行锚 / 标记行（R-54 §3）

- 机器必须在**表格/矩阵**中定位（表头行、矩阵行、`CFG002-ANCHOR: <id> -> <登记面>` 标记行）：保留标记行形态；
  标记行必须**进入锚合同**（本节）并**进入判据**（由对抗性审查断言恰出现一次且指向的登记项存在），
  标记行只出现在表格/矩阵定位处，散落正文充当「注释」不算标记行。
- 正文散文**不撒**标记（无表格/矩阵可定位时不引入标记行）；散文里的位置引用一律走内容锚。
- 配置登记面（`config_registry.json` / `defaults.json` / `filters.json`）**一律零行号**：
  位置信息一律「锚 id + 内容指纹」（R-54 §4）。

### 9.5 正例 / 负例

```text
正例：{"id": "detection.threshold_sigma", "path": "docs/science/STAR_DETECTION.md",
       "quote": "| `threshold_sigma` | 5.0 | sigma | ... |", "sha256": "<16 位>", "value_text": "5.0"}
负例 A（锚不成立）：quote 在目标文档内 0 次命中 -> D2 判红
负例 B（无区分力）：quote = "默认"（全文出现 12 次）-> D2 判红
负例 C（太短）：quote = "4" -> D1 判红
负例 D（指纹过期）：改了文档表行的说明文字但没更新 sha256 -> D3 判红
负例 E（值没锁住）：value_text = "6.0" 而引文里只有 "5.0" -> D4 判红
负例 F（行号混入）：登记面写 "docs/science/PSF.md:7" 或锚里带 "line" 字段 -> D5/D1 判红
```
