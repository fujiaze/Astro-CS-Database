# 文档体系治理规范（DOCUMENT GOVERNANCE）

> 上游：docs/ASTROCS_DESIGN.md §0（文档权威与索引）、§0.1（文档写法）；docs/DOCUMENT_INDEX.yaml（登记规则见 docs/engineering/DOCUMENT_GOVERNANCE.md））。
> 地位：文档体系的分层模型、准入判据、写法判据、登记面判据、上游抬头与正向书写条款的唯一正本；文档集目录拓扑的正本在 `docs/DOCUMENT_INDEX.yaml`。
> 判据同源：本文每一条都写成可判定的谓词——给输入面、红条件、计数证据三种要素——执行面是第 6 节的对抗性审查逐条覆盖。
> 谓词形式：本文每一条都写成可判定的谓词（输入面、红条件、计数证据三要素），但**谓词形式不构成登记为机器门禁的依据**——文档域不设机器门，正确性由对抗性审查逐条覆盖，机器面若出现同义判据视为重复建设（判据边界见 `VALIDATION_EVIDENCE_STANDARD.md` §12.5、§12.6）。

## 1. 分层模型与目录规范

```text
docs/
  ├── ASTROCS_DESIGN.md         最高设计（权威链顶点）
  ├── DOCUMENT_INDEX.yaml       全文档机器索引（唯一索引地图）
  ├── GLOSSARY.md               术语表（全局）
  ├── KNOWN_LIMITATIONS.md      已知偏差与限制
  ├── science/                  科学正本：公式、常数、判据与算法推导（只读权威）
  │   └── algorithms/              算法推导与逐符号实现锚定
  ├── engineering/              工程正本：合同、架构、标准、CI 门禁规范
  │   └── abi/ checks/ cpu/ data/ io/ observability/ v6/
  ├── detail/                   细节实施：模块页、算法与插件实现设计、阶段详细设计、锚契约
  │   └── registry/                模块登记与注册表说明
  ├── traceability/             需求—文档—代码追溯（CSV 台账）

# 留原位的机器合同件（按扩展名分流：md 全部归入上面三集）：
#   contracts/  standards/  architecture/  modules/
#   它们被代码按固定路径读取，不由本文档的层归属覆盖。
```

- 每层由上层推出；下层可补充细节，但与上层一致、不遗漏上层的实施项；
- 每个目录配中文 `README.md` 说明职责边界与内容；目录招牌件按"每目录必有 README"治理，登记于目录本身、不入规范索引段（`docs/DOCUMENT_INDEX.yaml`）；
- 科学公式与算法推导的权威在 `docs/science/`（含 `algorithms/`）；架构权威在最高设计 §8。

## 2. 各层准入判据

| 层 | 准入 | 退出 |
|---|---|---|
| 科学线（`docs/science/`） | 载有公式、常数、判据、容差、冻结定义的科学正文；每篇可溯源到实验单元与一手资料佐证 | 内容降级为接线说明 ⇒ 移出科学线 |
| 工程线（`docs/engineering/`；机器合同件留原位：`docs/contracts/`、`docs/standards/`、`docs/architecture/`） | 载有行为合同、命令树、调度/资源/AIO 边界的工程权威正文 | 内容降级为流水说明 ⇒ 并入对应细节面 |
| 细节与运维（`docs/detail/`；机器件留原位：`docs/modules/`、`docs/traceability/`） | 上层文档的落地细化、模块工作细节、机器合同说明；与上层口径冲突的内容不成立 | 被晋升为上层（须有上层条款承载） |

- 细节面每篇抬头有「上游：〈上层文档 §条〉」区；科学线与工程线每篇抬头有「上游：docs/ASTROCS_DESIGN.md §条」区，书写形态按 §4.5 的号—标题双要素；
- **科学佐证纪律（全局）**：科学线每篇的一级断言须能被 `实验/` 单元与一手公开资料支撑；非创新点算法（校准、platesolve、cosmetic 等）同样要求「一手文献 + 成熟开源实现 + `实验/` 复算」三支撑，文献与项目版本写入文档头部佐证来源区并进 `docs/DOCUMENT_INDEX.yaml`；
- **上层文档是权威**：代码与细节面向上层对齐；发现冲突时按 `AGENTS.md` §8 的查证流程处置，再订正文档或改代码并补 Oracle/负例。

## 3. 锚纪律与机器门

- **文档内不留指向仓内文档的行锚**：引用本仓其他文档一律用内容锚（引文 + 内容指纹）或 `§条` 引用；行锚只用于外部文献与代码（锚合同的唯一正本 = `docs/detail/anchors/ANCHOR_CONTRACT.md`）；
- 引用外部文献与代码的行锚与被引对象同提交更新；行锚两侧内容发生位移时同批改锚。
- 文档域的锚存活与锚规模一致性由第 6 节的对抗性审查逐条覆盖。

## 4. 索引与引用维护纪律

### 4.1 通用维护纪律

1. 每条 `docs/` 路径引用与索引条目在同一批改动内闭合：`docs/DOCUMENT_INDEX.yaml` 与 `docs/TRACEABILITY.csv` 同批更新，由第 6 节的对抗性审查确认索引闭合后才算完成；
2. 引用重写规则：`docs/` 前缀路径按新拓扑改写；markdown 相对链接逐条解析改写；裸名 `ASTROCS_DESIGN.md` 在 `docs/` 外带 `docs/` 前缀、在 `docs/` 内保持裸名；
3. 本域改动面不含 `eng/contracts/` 冻结 schema、`实验/` 单元、`testdata/`、`gaia/`；这些面的处置属各自域；
4. 索引与文件树一致：未登记即缺陷，登记不存在同样是缺陷；判定按 §4.2 的对象集与 §4.7 的排除面执行。

### 4.2 登记对象集与口径外排除面

登记对象集只从版本控制的跟踪集派生，唯一推导命令是 `git -c core.quotePath=false ls-files`。跟踪集按扩展名与目录切成五个子集：文档层（`.md`、`.rst`、`.txt`）、文档型数据件（文档目录内的 `.yaml`、`.yml`、`.csv`、`.json`）、机器合同与配置、证据与产物、代码。磁盘遍历结果——未跟踪文件、构建残留、本机临时目录——一律不进对象集。

- **口径外零容忍**：文档层对象数必须等于跟踪集内 `.md`、`.rst`、`.txt` 文件总数减去登记在册的排除项。两侧计数不等即缺陷，缺陷输出给检查名、两侧计数与被判红的前 10 条对象路径。
- **排除面是登记项**：每一项写 `pattern`、`reason`、`evidence` 三字段，缺任一字段即缺陷。`reason` 取封闭枚举三值：生成物、证据快照、第三方 vendored。
- **排除面逐条复算**：每一项的 `pattern` 在跟踪集上的命中对象数必须与其声明计数一致；声明了排除项而命中数为 0，按隐藏口径判红。
- 索引面自身的缺失、未被跟踪、解析失败同样判红，不得跳过内容检查。

### 4.3 判据集合的来源与非空

判据的取值集合是判据的输入面，其来源与规模都是判据本身的一部分。

- **来源必须可指认**：取值集合来自封闭枚举文件或跟踪集内的登记文件，指认不到具体文件即判红。禁止由目录名、目录名列表、glob 结果或任何随工作区状态变化的现算得到。适用集合至少包括：写法判据的命中形态、命名空间前缀、门 ID 词表、角色枚举、主题枚举、状态词表、排除面的 `reason` 枚举。
- **每条集合各自带非空断言**：集合解析后为空（规则数为 0）即判红。禁止「集合读不到就按全部合规处理」。
- **非空断言落在被嵌套的内层**：一个判据套着另一个判据时，内层集合各自断言；外层「扫描面非空」不构成内层「判据集合非空」的证明。门禁面的对应条款见 `docs/engineering/VALIDATION_EVIDENCE_STANDARD.md` §7。
- **判红形态**：以工作区里不保证入库的目录名列表作为枚举来源。该目录在干净克隆上不存在，集合退化为空，判据对全部对象恒判通过。门禁面的判据读取路径不随工作区内容增减。

### 4.4 双轴封闭枚举与正本唯一性

每条索引条目带两轴单值字段：`role` 取该文档回答的问题类型，`topic` 取该文档所属主题。

- 两个轴的取值都是封闭枚举，逐条列举在跟踪集内的枚举文件里；枚举文件逐行列举全部取值，枚举条目数与实际使用集合的差值即待补取值，逐条判红。
- 两轴取值禁止由 `path` 的第二段、文件名或目录名推断，也禁止由目录名反推取值。判定只做两件事：取值是否落在枚举内；`role` 的目标目录是否属于该 `role` 的允许目录集合。
- `role` 的允许目录对应表是登记项，与枚举同文件维护；文档落在不属于其 `role` 允许目录的位置即判红。
- 每个 `topic` 恰有一条 `canonical: true`；零条或多条均判红。
- `kind: generated` 与 `kind: evidence` 的条目不得同时 `canonical: true`。

### 4.5 指针完整性

- **上游双要素**：文档抬头与索引条目给出同一组「条款号 + 条款标题」，写作形态为 `§x.y（该节标题）`。只给号不给标题判红。
- 条款号必须命中被引文档的实际小节号；条款标题与该节标题去空白后逐字相等。两条任一不满足即判红。
- 文档抬头与索引条目给出的双要素必须同源，不一致即判红。
- **下推指针完整性**：标记 `canonical: true` 的条目所对应的上位节，其「索引：」行必须回指该文档；缺回指即判红。最高设计每个机制节都有「索引：」行，缺行即判红。
- 层级豁免：`layer: 1` 的条目免上游；`layer: 2` 与 `layer: 3` 必须有；`kind: generated` 与 `kind: evidence` 允许 `upstream: n/a`，但必须给生成来源说明。

### 4.6 派生字段与快照陈旧

- `downstream` 是派生字段，由索引自身按跟踪集现算并写回；条目取值写 `auto` 表示以现算为准。
- 派生字段与其快照不一致即判红，输出给逐条差值（现算值与快照值）。
- 「全部条目为手工值」这一状态即判红：它说明派生通道断开，快照不再由任何一侧维护。
- 派生规则只有一处实现，其他文档不复述该规则。

### 4.7 引用悬空判定的排除面

引用扫描的判定面与排除面分开写，报告必须分栏给出。

- **形态类只计数**：glob 形态（含 `**`）、占位形态（含尖括号）、含空格的形态不作路径存在性判定，只计命中数。
- **目标态路径不判红**：目标态文档里描述应为或新增的路径按设计不存在，只计数，不判红。
- **证据面外单列**：不入库的运行产物目录里的引用单列为「证据面外」，不计入悬空引用；该类引用不可复算的事实由 `docs/KNOWN_LIMITATIONS.md` 登记。
- 三类排除的命中数逐条随报告给出；扫描面对象数减去三类排除命中数之和，必须等于被判定对象数，不等即判红。
- 排除面按 §4.2 的三字段与三分类 `reason` 登记，`reason` 取同一封闭枚举。

## 5. 正向设计纪律

- **文档正文只写现行设计**：陈述现行口径本身（"X 是 Y" + 出处锚），不出现裁决类表述与沿革叙述（订正记录、旧口径对照、决策编号引用）；
- **变更轨迹不落文档**：变更过程与判定轨迹由记忆系统与治理域承载，文档不承担沿革记录功能；
- **订正 = 整段重写为现行口径**：删除订正注记、历史对照与编号引用，代之以正向表述 + 现行佐证锚；
- **佐证来源区只挂现行依据**：文献、开源实现、实验复算；
- **历史痕迹清零**：日期、版本沿革、任务编号、基线 SHA 不出现在跟踪文档；文档头部只保留「上游：〈上层文档 §条〉」与现行佐证锚；
- 对抗审查把"正文含沿革叙述或历史痕迹"判红。

## 6. 对抗审查准入

- 每完成一篇上层文档（内容 + 佐证），该篇即入对抗审查域：科学性（公式/常数/判据 vs 文献与实验）、内容（与下层文档、代码一致性）、表述（口径、术语、结构）三面；
- 审查发现回写治理域的问题台账（编号续编），修复按订正流程执行；同一阶段的下层文档与代码同批进入复查域；
- 第 4、7、8 节的每条谓词由本节审查逐条覆盖，审查记录给检查名、输入面、实测计数与判红对象路径。

## 7. 写法判据的封闭词表与分层施加

### 7.1 分层施加与豁免面

写法判据只作用于**正式文档层**：`docs/**`、仓库根 `*_SPEC.md`、`docs/ASTROCS_DESIGN.md`、`AGENTS.md`。过程层与证据层以过程记录与任务编号为本分，不按正式文档层的写法判据逐字判定——逐字套用会让整批过程件恒判违规，读数失去判别力。

- **豁免面（封闭枚举）**：`docs/research/**`、`docs/references/**`、`artifacts/**`、`实验/**/results/**`，退役件的失效标注区，以及本文件 §7.2 词表所在的围栏块。
- 豁免面内的写法问题改判两种具名判据：**角色错放**——应落在过程层或证据层的件留在正式文档层；**缺处置登记**——采纳、驳回、悬空三类处置没有登记面。
- 豁免面逐条列举，解析后规则数为 0 即判红。禁止「豁免面读不到就按全部适用处理」。

### 7.2 命中形态（封闭枚举）

下表的围栏块是写法判据词表的**登记面本身**，按 §7.1 的豁免面处理：判定器跳过该块，其余正文与全部代码块照常判定。词表因此可以写成人读的字面形态，而不与它自己判定的那五类命中相撞。

```text
类别 | 命中形态 | 适用层
日期 | YYYY-MM-DD；YYYY/MM/DD；YYYY 年 M 月 D 日；MM-DD 独立出现；Q[1-4] 后随四位年份 | 仅正式文档层
流水号与工作项 | [A-Z]{2,6}-<数字>，减去在册标识命名空间；任务编号 后随冒号；工单；回执 | 仅正式文档层
commit 与散列 | 40 位十六进制独立 token；7-12 位十六进制独立 token；sha256 后随冒号或等号再随字面量（字段名允许，值不允许） | 仅正式文档层
元信息块 | 文件前 5 行内出现 状态: / 版本: / 日期: / 作者: / ID: 形式的键值行 | 仅正式文档层
历史叙事 | 此前；曾经；已作废为；历史上；轮次名与 曾 的组合（只判形态，不判语义，避免误伤科学文档里的对照句） | 仅正式文档层
```

- 在册标识命名空间（合同层与实验层已登记的 ID 家族）逐条登记在跟踪集内的命名空间面上，按该面判定，不按泛化正则判定。
- 词表的元数据面（适用层、登记面位置、豁免面清单）随词表同块维护，判定器按块首的类别列读适用层。

### 7.3 判定与配例

- 命中即判红并给行号。
- 词表是判据的输入面，按 §4.3 登记来源并各自带非空断言；词表为空即判红。
- 每条命中形态配正例与负例：负例是在正式文档层加一行元信息块键值行或一个日期字面量，必须判红并给行号；正例是同样内容写进豁免面，必须判绿。
- 词表只有一处实现。`docs/` 下的其他文档不复述本表的形态清单，只引用本节。

## 8. 订正意见与登记面的交付形状

### 8.1 订正意见

对文档的每条订正意见给五个字段，缺任一字段即不算交付：

1. 被订正位置：文件 + 锚；
2. 现状原文：逐字短引，不超一句；
3. 订正后完整文字：可直接替换粘贴的整句或整段，不写「建议澄清」；
4. 依据：上位文档的条款号、一手文献，或实现事实的位置；
5. 同句还出现在哪些文件：口径唯一要求一并改，逐处列全。

订正意见分三类各自成节：**错**（与正本、实现或文献矛盾）、**缺**（无出处、无适用域、无单位、无常数推导）、**乱**（同一事实在多处各说一种、上下级重复正本、层级倒置）。只写「表述不清」不构成交付。

同一事实的每一处出现都在同批改动内改齐；只改一处即判缺陷。订正意见不写责任归属与过程流水。

### 8.2 正向规格里的常数

正向规格件里的每个常数给五件，缺任一件即不算规格：值、量纲与单位、来源档（文献值、公式导出、实验标定、待确认）、锚（位置 + 一句内容锚）、待确认时的保守方向取值与影响范围（哪个产品量、偏大还是偏小、量级）。留空不算规格。

### 8.3 登记面

登记面（限制与未决登记）每条给四项：内容、为什么必须由负责人裁、阻塞哪个交付面、现有证据或倾向。登记面不承担裁决，也不写过程流水、责任归属与变更轨迹。

## 9. 仓库根条目登记面

### 9.1 根固定条目

```text
仓库根固定条目（无扩展名者以本条文字登记）：

文件：README.md / AGENTS.md / VERSION / CMakeLists.txt / CMakePresets.json /
      .clang-format / .editorconfig / .gitignore / .gitattributes /
      eng/build/build.sh / eng/build/toolchain.ps1
目录：docs/ / lib/ / eng/ / 实验/ / testdata/
```

- 本表是仓库根条目与根目录的**唯一登记面**：根目录出现本表之外的条目即为缺陷；
- 新产物落位到对应目录，不散落根目录；确需新增根条目或根目录，先登记并经负责人核准后生效；
- 根 `VERSION` 无扩展名，是产品版本唯一事实源（最高设计 §13），以本条文字登记；
- `eng/build/toolchain.ps1` 是 Windows 侧构建与自检脚本，其依赖面只允许仓内 vendored 依赖与系统工具链（机器路径政策见 `DEPENDENCY_RULES.md`）；
- 根目录不得出现运行产物：命令行运行产物只落块级 `output_dir`（最高设计 §10），开发与 CI 过程产物与过程日志落 `run/`，ctest 残留归 `run/Testing_archive/`；
- 版本信息按阶段出现：alpha 阶段之前代码与产物中不含版本信息，进入 alpha 阶段后一律由根 `VERSION` 派生或与其一致（单源条款 = `docs/engineering/RELEASE_STATUS.md` §2）。

### 9.2 外部只读数据集

不由本仓生成、不随仓库分发、仅供本地实验引用的数据，在根目录以具名目录放置，全部由 `.gitignore` 排除。已登记：

| 目录 | 内容 |
|---|---|
| `gaia/GaiaDR3/` | Gaia DR3 星表数据 |
| `gaia/GaiaDR3SP/` | Gaia DR3 谱表数据 |

判据（五条同时成立才算合规）：

1. **只读引用**：代码只按路径读取，不写入；
2. **不入库**：整目录被 `.gitignore` 排除，索引与元数据另在 `testdata/` 内管理；
3. **不被根构建引用**：不进 CMake 输入面，不影响 fresh configure 的可复现性；
4. **不被检查器当作仓库内容**：文档索引与门禁的对象集从跟踪集派生，不掺磁盘遍历（§4.2），因此这些目录天然不在扫描面内；
5. **一旦被代码消费或需要入库，移入 `testdata/` 或证据目录**，并同步改本表与 `.gitignore`。

## 10. 随包参照副本的分级

工作包、审核包与外部交付件可以携带根文档或正本的**参照副本**。副本的效力固定为：

- **不替换仓库正本**：权威链只认仓库内的正本（最高设计 §0）；
- **不构成权威**：副本与正本不一致时以正本为准；
- **不进提交面**：随包副本不随仓库提交，也不被构建与门禁当作仓库判据的输入；
- **识别形态**：副本须在抬头写明它是随包参照副本及其对应的仓库正本路径，读者据此回到正本。

同一事实的权威只存在于仓库正本一处；副本与正本出现口径差时，按 §8.1 的订正形状在正本侧处理。
