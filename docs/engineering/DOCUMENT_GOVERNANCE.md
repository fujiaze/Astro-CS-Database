# 文档体系治理规范（DOCUMENT GOVERNANCE）

> 上游：docs/ACSD_DESIGN.md §0（文档权威与索引）、§0.1（文档写法）；docs/DOCUMENT_INDEX.yaml（登记规则见 docs/engineering/DOCUMENT_GOVERNANCE.md））。
> 地位：文档体系的分层模型、准入判据、写法判据、登记面判据、上游抬头与正向书写条款的唯一正本；文档集目录拓扑的正本在 `docs/DOCUMENT_INDEX.yaml`。
> 执行面：**文档域不设机器门**。第 3、4、7 节的每一条都是**人读检查清单**，由 agent 逐轮打开文档、逐项目视执行、逐项留证（写下检查项、实际读到的内容、判定、发现的缺陷路径）。**不产出机器 PASS 记录，不注册检查项，不以「机器已校验」描述文档正确性。**
> 谓词形式：本文的检查项写成可判定的谓词（输入面、缺陷条件、计数证据三要素），**谓词形式不构成登记为机器门禁的依据**。机器面若出现同义判据，视为与本清单重复建设（判据边界见 `VALIDATION_EVIDENCE_STANDARD.md` §12.5、§12.6）。

## 1. 分层模型与目录规范

```text
docs/
  ├── ACSD_DESIGN.md         最高设计（权威链顶点）
  ├── README.md              docs 入口导航
  ├── DOCUMENT_INDEX.yaml       全文档机器索引（唯一索引地图）
  ├── GLOSSARY.md               术语表（全局）
  ├── science/                  科学正本：公式、常数、判据与算法推导（只读权威）
  │   └── algorithms/              算法推导与逐符号实现锚定
  ├── engineering/              工程正本：合同、架构、标准、CI 门禁规范
  │   └── abi/ cpu/ data/ io/ observability/
  ├── detail/                   细节实施：模块页、算法与插件实现设计、阶段详细设计、锚契约
  │   └── registry/                模块登记与注册表说明
```

`docs/` 下**只有人读文档**。机读的合同 schema、合同数据与配置一律落 `eng/contracts/**`、
`eng/packaging/config/**` 等工程目录，由代码按固定路径读取；文档域不承载机读资产
（`docs/` 下的 `.csv` / `.json` 台账一律不新建，已存在的按本条迁出）。
**豁免**：`docs/DOCUMENT_INDEX.yaml` 是文档集自身的索引地图，按本文件 §4.4 与
`docs/ACSD_DESIGN.md` §0 作为唯一索引载体保留在 `docs/`，不适用本条迁出。
另：已知限制台账的人读面为 `artifacts/evidence/known-limitations-ledger/LIMITATIONS.md`，
不在 `docs/` 根层。

**规则 6（跨域豁免登记）**：`docs/DOCUMENT_INDEX.yaml` 的登记面是**人读件**。
落在 `docs/**` 之外的件只在下面两类里具名豁免登记，每条豁免须在该条目的 `notes` 里写明它凭什么被登记：

1. **跨域人读件**：它是所属域唯一的人读正本面，删掉后无处可查。当前两条：`实验/裁决台账.md`（实验域分歧终裁面，`docs/ACSD_DESIGN.md` §12.1 点名的终裁载体）、`artifacts/evidence/known-limitations-ledger/LIMITATIONS.md`（已知限制台账的人读面）。
2. **人读正本所直接依赖的判据实现**：该件是某份人读正本明定的判据载体或纪律实现，去掉它正本的反向指针不可达。当前两条：`eng/contracts/ledgers/ledger_schema.py`（`docs/engineering/CONFIG_SCHEMA.md` 明定的台账 schema 载体）、`eng/tools/source_scan.py`（本文件 §7 写作纪律所依赖的扫描实现）。

机器源（`.json` / `.csv` / `.py` 等结构化或可执行件）**不因跨域而自动取得登记资格**：只有落进第 2 类、且有人读正本对它有直接指针时才登记，并且必须具名写进本条。反过来，索引 `coverage` 字段的措辞必须与本条一致，不得一边声明某类件不登记、一边把它们登记在册。

引用本规则的规则号必须在本文可读到定义；**只被引用而无处定义的规则号本身即缺陷**（见 §4.4 的 C3-5：词表读空后按全部合规处理是最危险的失真）。

- 每层由上层推出；下层可补充细节，但与上层一致、不遗漏上层的实施项；
- 每个目录配中文 `README.md` 说明职责边界与内容；目录招牌件按"每目录必有 README"治理，登记于目录本身、不入规范索引段（`docs/DOCUMENT_INDEX.yaml`）；
- 科学公式与算法推导的权威在 `docs/science/`（含 `algorithms/`）；架构权威在最高设计 §8。

## 2. 各层准入判据

| 层 | 准入 | 退出 |
|---|---|---|
| 科学线（`docs/science/`） | 载有公式、常数、判据、容差、冻结定义的科学正文；每篇可溯源到实验单元与一手资料佐证 | 内容降级为接线说明 ⇒ 移出科学线 |
| 工程线（`docs/engineering/`） | 载有行为合同、命令树、调度/资源/AIO 边界的工程权威正文 | 内容降级为流水说明 ⇒ 并入对应细节面 |
| 细节与运维（`docs/detail/`） | 上层文档的落地细化、模块工作细节、机器合同说明；与上层口径冲突的内容不成立 | 被晋升为上层（须有上层条款承载） |

- 细节面每篇抬头有「上游：〈上层文档 §条〉」区；科学线与工程线每篇抬头有「上游：docs/ACSD_DESIGN.md §条」区，书写形态按 §4.5 的号—标题双要素；
- **科学佐证纪律（全局）**：科学线每篇的一级断言须能被 `实验/` 单元与一手公开资料支撑；非创新点算法（校准、platesolve、cosmetic 等）同样要求「一手文献 + 成熟开源实现 + `实验/` 复算」三支撑，文献与项目版本写入文档头部佐证来源区并进 `docs/DOCUMENT_INDEX.yaml`；
- **上层文档是权威**：代码与细节面向上层对齐；发现冲突时按 `AGENTS.md` §8 的查证流程处置，再订正文档或改代码并补 Oracle/负例。

## 3. 锚纪律

- **文档内不留指向仓内文档的行锚**：引用本仓其他文档一律用内容锚（引文 + 内容指纹）或 `§条` 引用；行锚只用于外部文献与代码（锚合同的唯一正本 = `docs/detail/anchors/ANCHOR_CONTRACT.md`）。
- 引用外部文献与代码的行锚与被引对象同提交更新；行锚两侧内容发生位移时同批改锚。
- **人读核对项**：每轮打开引用他人文档的那几行，把 `§条` 打开、确认标题与内容确如描述；行锚打开确认落在所述内容上。发现漂移就当场改锚，不留待下轮。

## 4. 引用与登记纪律（人读检查清单）

本节全部是**人读**检查项。执行方式：逐轮把 `docs/` 整树与跟踪集各读一遍，逐项核对，**逐项写下检查名、实际计数、记为缺陷的对象路径**；核对结论回写本节清单下方的留证区。

### 4.1 通用维护纪律

1. 每条 `docs/` 路径引用在同一批改动内闭合：被引文件真实存在，且新文件已在 `docs/DOCUMENT_INDEX.yaml` 登记。
2. 引用重写规则：`docs/` 前缀路径按新拓扑改写；markdown 相对链接逐条解析改写；裸名 `ACSD_DESIGN.md` 在 `docs/` 外带 `docs/` 前缀、在 `docs/` 内保持裸名。
3. 本域改动面不含 `eng/contracts/` 冻结 schema、`实验/` 单元、`testdata/`、`gaia/`；这些面的处置属各自域。
4. 索引与文件树一致：未登记即缺陷，登记不存在同样是缺陷；两者都要**打开文件确认**，不能只看清单。

### 4.2 检查项 C1——`docs/` 路径无悬空

- **查什么**：把 `docs/` 全树与 `eng/`、`lib/`、`CMakeLists.txt`、脚本、schema、测试里的 `docs/...` 路径引用逐条打开，确认目标真实存在。
- **判缺陷**：目标不存在且不是「应为/将新增」的目标态路径。
- **不判**：glob 形态（含 `**`）、占位形态（含尖括号）、含空格的形态——只计命中数，不作存在性判定；目标态路径只计数。
- **留证**：写扫描面对象数、排除形态命中数、被判定对象数、记为缺陷的对象路径逐条。

### 4.3 检查项 C2——文件树无漏项

- **查什么**：把 `docs/` 真实文件树与 `docs/DOCUMENT_INDEX.yaml` 的登记条目**双向**比对。
- **判缺陷**：文件树里有、索引里没有；索引里有、磁盘上没有；索引条目自身解析失败。
- **对象集口径**：只从 `git -c core.quotePath=false ls-files` 派生。未跟踪文件、构建残留、本机临时目录一律不入对象集。
- **留证**：写两侧计数与差集路径逐条。

### 4.4 检查项 C3——结构上抓不到、只能人读的缺陷类型

以下缺陷**不会被任何结构化解析抓到**，因为它们在语法上合法、只有在人读正文时才会显形。每轮必须逐项打开读：

| # | 缺陷类型 | 为什么机器抓不到 | 人读怎么认 |
|---|---|---|---|
| C3-1 | **YAML 映射键重复** | YAML 解析器对重复键默认**后者覆盖前者、不报错**；`docs/DOCUMENT_INDEX.yaml` 等登记面若同一映射出现两次同名键，读出来的值只反映最后一条，前一条的错值无人看见 | 打开每个含映射的登记文件，逐个映射**逐键数一遍**，同名键出现第二次即缺陷 |
| C3-2 | **括注标题与节标题语义相符但字面不一致** | 条款号命中就通过，标题是否「意思对得上」不是结构问题 | 逐条把 `§x.y（标题）` 与被引文档该节的标题并排读，判断是否同一件事 |
| C3-3 | **正文自述与实际内容相反** | 文档说的和文档写的是两回事，解析器只读文本不判断真伪 | 逐篇读正文里的每个「已/全部/唯一/无」类断言，回到被指对象确认 |
| C3-4 | **同义重复登记** | 同一事实在两处各登一次，两条都自洽 | 逐条找同一 ID、同一文件、同一判据的第二个落点 |
| C3-5 | **集合/词表读空后按全部合规处理** | 读不到就跳过，判据对全部对象恒通过 | 逐条确认每个词表**真的读出了条目数**，读出 0 条即缺陷 |
| C3-6 | **表格行数与正文声称的行数不一致** | 表格本身合法 | 逐张表数行，与正文声称的行数并排核 |

### 4.5 检查项 C4——上游指针双要素

- **查什么**：每篇文档抬头与索引条目给出的「条款号 + 条款标题」，打开被引文档确认节号真实存在、标题逐字相符。
- **判缺陷**：只给号不给标题；节号不存在；标题不一致；抬头与索引条目两处不一致。
- **下推**：标记 canonical 的条目，其上位节的「索引：」行必须回指该文档；最高设计每个机制节都要有「索引：」行。
- **豁免**：`layer: 1` 免上游；生成件与证据件可写 `upstream: n/a`，但要给生成来源说明。

### 4.6 检查项 C5——跨文档合同 ID 存在

- **查什么**：把文档里出现的每个合同 ID（`SCI-*` / `ALG-*` / `DATA-*` / `API-*` / `ARCH-*` / `MOD-*` / `TEST-*` / `ENG-*`）拿到合同注册表 `eng/contracts/data/contract_index.yaml` 与各级正本里逐个确认。
- **判缺陷**：ID 在注册表与正本里都查不到；或同一 ID 在两处指向不同内容。
- **留证**：写抽查 ID 数、命中数、查不到的 ID 逐条。

### 4.7 留证

每轮执行完本节，把检查名、输入面、实际计数、记为缺陷的对象路径写进本节末尾的留证区。**留证是人写的观察记录，不是机器输出**；没有留证的检查项视为未执行。

## 5. 正向设计纪律

- **文档正文只写现行设计**：陈述现行口径本身（"X 是 Y" + 出处锚），不出现裁决类表述与沿革叙述（订正记录、旧口径对照、决策编号引用）；
- **变更轨迹不落文档**：变更过程与判定轨迹由记忆系统与治理域承载，文档不承担沿革记录功能；
- **订正 = 整段重写为现行口径**：删除订正注记、历史对照与编号引用，代之以正向表述 + 现行佐证锚；
- **佐证来源区只挂现行依据**：文献、开源实现、实验复算；
- **历史痕迹清零**：日期、版本沿革、任务编号、基线 SHA 不出现在跟踪文档；文档头部只保留「上游：〈上层文档 §条〉」与现行佐证锚；
- 对抗审查把"正文含沿革叙述或历史痕迹"判红。

## 6. 对抗审查准入

- 每完成一篇上层文档（内容 + 佐证），该篇即入对抗审查域：科学性（公式/常数/判据 vs 文献与实验）、内容（与下层文档、代码一致性）、表述（口径、术语、结构）三面；
- 审查发现回写治理域的问题台账（编号续编），修复按订正流程执行；同一阶段的下层文档与代码同批进入复查域；
- 第 4、7、8 节的每条谓词由本节审查逐条覆盖，审查记录给检查名、输入面、实测计数与判红对象路径。

## 7. 写法检查（人读清单）

### 7.1 分层施加与豁免面

写法检查只作用于**正式文档层**：`docs/**`、仓库根 `*_SPEC.md`、`AGENTS.md`。过程层与证据层以过程记录与任务编号为本分，不按正式文档层的写法逐字判定——逐字套用会让整批过程件恒判违规，读数失去判别力。

- **豁免面**：`docs/research/**`、`docs/references/**`、`artifacts/**`，退役件的失效标注区，以及本节 7.2 的围栏块本身。实验域的运行结果不设豁免面：运行产物不落文档域，其读数由实验报告正文承载。
- 豁免面内的写法问题改判两种具名项：**角色错放**——应落在过程层或证据层的件留在正式文档层；**缺处置登记**——采纳、驳回、悬空三类处置没有登记面。
- 豁免面**逐条列举**；执行时逐条打开确认，**确认不了就当它适用**，不按「大概不在里面」跳过。

### 7.2 要读的写法形态（下表由人逐行对读，不是判定器的词表）

打开正式文档层的每篇，**逐行读**，对上表任一形态即记为写法缺陷并给行号：

```text
类别 | 形态
日期 | YYYY-MM-DD；YYYY/MM/DD；YYYY 年 M 月 D 日；MM-DD 独立出现
流水号与工作项 | [A-Z]{2,6}-<数字>（在册标识命名空间除外）；任务编号 后随冒号；工单；回执
commit 与散列 | 40 位十六进制独立 token；7-12 位十六进制独立 token；sha256 后随冒号或等号再随字面量
元信息块 | 文件前 5 行内出现 状态: / 版本: / 日期: / 作者: / ID: 形式的键值行
历史叙事 | 此前；曾经；已作废为；历史上；轮次名与 曾 的组合
```

- **在册标识命名空间的排除靠人判断**：合同层与实验层已登记的 ID 家族（`SCI-*` / `ALG-*` / `DATA-*` / `API-*` / `ARCH-*` / `MOD-*` / `TEST-*` 等）是**合法内容**，形似流水号但不是缺陷。逐个 ID 打开确认它在册后再放行；不在册的形似 ID 就是缺陷。
- 本表只有这一处。`docs/` 下的其他文档不复述这张表，只引用本节。

### 7.3 判定与留证

- 命中即缺陷，记行号。
- 词表为空、豁免面读空、或读不出条目数，本身就是缺陷（见 §4.4 的 C3-5、C3-1）——**「读不到就当全部合规」是最危险的失真**。
- 配例靠人做：随机抽一篇正式文档，人为加一行元信息块键值行或一个日期字面量，确认自己认得出；同样内容放进豁免面，确认自己放得过。
- 留证格式同 §4.7：检查名、输入面、实际计数、记为缺陷的对象路径。

## 8. 订正意见与登记面的交付形状

### 8.1 订正意见

对文档的每条订正意见给五个字段，缺任一字段即不算交付：

1. 被订正位置：文件 + 锚；
2. 现状原文：逐字短引，不超一句；
3. 订正后完整文字：可直接替换粘贴的整句或整段，不写「建议澄清」；
4. 依据：上位文档的条款号、一手文献，或实现事实的位置；
5. 同句还出现在哪些文件：口径唯一要求一并改，逐处列全。

订正意见分三类各自成节：**错**（与正本、实现或文献矛盾）、**缺**（无出处、无适用域、无单位、无常数推导）、**乱**（同一事实在多处各说一种、上下级重复正本、层级倒置）。只写「表述不清」不构成交付。

同一事实的每一处出现都在同批改动内改齐；只改一处即判缺陷。订正意见不写责任归属与过程流水。

### 8.2 正向规格里的常数

正向规格件里的每个常数给五件，缺任一件即不算规格：值、量纲与单位、来源档（文献值、公式导出、实验标定、待确认）、锚（位置 + 一句内容锚）、待确认时的保守方向取值与影响范围（哪个产品量、偏大还是偏小、量级）。留空不算规格。

### 8.3 登记面

登记面（限制与未决登记）每条给四项：内容、为什么必须由负责人裁、阻塞哪个交付面、现有证据或倾向。登记面不承担裁决，也不写过程流水、责任归属与变更轨迹。

## 9. 仓库根条目登记面

### 9.1 根固定条目

```text
仓库根固定条目（无扩展名者以本条文字登记）：

文件：README.md / AGENTS.md / VERSION / CMakeLists.txt / CMakePresets.json /
      .clang-format / .editorconfig / .gitignore / .gitattributes /
      eng/build/build.sh / eng/build/toolchain.ps1
目录：docs/ / lib/ / eng/ / 实验/ / testdata/
```

- 本表是仓库根条目与根目录的**唯一登记面**：根目录出现本表之外的条目即为缺陷；
- 新产物落位到对应目录，不散落根目录；确需新增根条目或根目录，先登记并经负责人核准后生效；
- 根 `VERSION` 无扩展名，是产品版本唯一事实源（最高设计 §13），以本条文字登记；
- `eng/build/toolchain.ps1` 是 Windows 侧构建与自检脚本，其依赖面只允许仓内 vendored 依赖与系统工具链（机器路径政策见 `DEPENDENCY_RULES.md`）；
- 根目录不得出现运行产物：命令行运行产物只落块级 `output_dir`（最高设计 §10），开发与验证过程产物与过程日志落 `run/`；
- 版本信息按阶段出现：alpha 阶段之前代码与产物中不含版本信息，进入 alpha 阶段后一律由根 `VERSION` 派生或与其一致（单源条款 = `docs/engineering/RELEASE_STATUS.md` §2）。

### 9.2 外部只读数据集

不由本仓生成、不随仓库分发、仅供本地实验引用的数据，在根目录以具名目录放置，全部由 `.gitignore` 排除。已登记：

| 目录 | 内容 |
|---|---|
| `gaia/GaiaDR3/` | Gaia DR3 星表数据 |
| `gaia/GaiaDR3SP/` | Gaia DR3 谱表数据 |

判据（五条同时成立才算合规）：

1. **只读引用**：代码只按路径读取，不写入；
2. **不入库**：整目录被 `.gitignore` 排除，索引与元数据另在 `testdata/` 内管理；
3. **不被根构建引用**：不进 CMake 输入面，不影响 fresh configure 的可复现性；
4. **不被检查器当作仓库内容**：文档索引与门禁的对象集从跟踪集派生，不掺磁盘遍历（§4.2），因此这些目录天然不在扫描面内；
5. **一旦被代码消费或需要入库，移入 `testdata/` 或证据目录**，并同步改本表与 `.gitignore`。

## 10. 随包参照副本的分级

工作包、审核包与外部交付件可以携带根文档或正本的**参照副本**。副本的效力固定为：

- **不替换仓库正本**：权威链只认仓库内的正本（最高设计 §0）；
- **不构成权威**：副本与正本不一致时以正本为准；
- **不进提交面**：随包副本不随仓库提交，也不被构建与门禁当作仓库判据的输入；
- **识别形态**：副本须在抬头写明它是随包参照副本及其对应的仓库正本路径，读者据此回到正本。

同一事实的权威只存在于仓库正本一处；副本与正本出现口径差时，按 §8.1 的订正形状在正本侧处理。
