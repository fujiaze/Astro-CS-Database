# 文档标准

本文依据最高设计的文档要求[1]，规定正式文档应说明的内容与写法。归属、索引和维护方式由文档治理规范定义[2]。

## 分层与阅读

最高设计拥有用户目标与顶层边界；science 与 engineering 是同级一级正本，分别拥有科学定义和工程合同；detail 是二级实施细节。代码实现这些定义。索引是地图，README 是目录入口，均不构成额外权威层。

文档开篇用自然语言说明主题与上层依据，不设状态、作者、日期等元信息块。先解释目的、关键机制和适用边界，再给公式、接口或细节。每个目录的 README 用一两句说明内容和主要入口；全树登记由文档索引承担[3]。

## 内容要求

| 文档类型 | 应说明的内容 |
|---|---|
| 科学正本 | 被估计量、符号与单位、前提、推导、随机与系统误差、可辨识性、数值精度、失效域及真实参考资料 |
| 架构与工程合同 | 组件职责、生产者与消费者、数据载体、所有权和寿命、并发与资源、错误与取消、持久化和兼容边界 |
| 模块与接口细节 | 真实入口与签名、入参/返回值、单位与坐标、像元口径、错误码/异常、调用方、配置及受影响下游 |
| 排障说明 | 可观察症状、相关阶段、日志/指标、最小复现、预期不变量及真实源码和用例位置 |

按主题需要组织内容，不为凑模板重复空节。科学常数给值、量纲、来源与适用条件；输入几何可推导的量写推导，实验标定量给可复现依据，待确认值明确说明限制。模型中缺失的误差项如实命名，不能填零冒充完整。

## 唯一口径与实现状态

同一术语引用拥有它的正本，保持被估计量、单位、坐标和有效域一致。下层可解释怎样实施，不能重定义物理量。消歧用完整正向陈述与出处；避免多处逐字复制同一套公式或产品政策。

目标设计、源码存在、静态接线、执行结果与独立科学支持分开写。以“应当”“目标”说明设计要求，以具体代码或运行证据说明事实。没有运行证据时不得把接口完成或路径存在写成科学闭环；事实对应方法见追溯规范[4]。

## 引文与表达

正文使用编号引文，末尾列实际读过、支持所述结论的文献或文件。仓内用可点击的文件路径；外部资料给 DOI、标准页或稳定地址，必要时标章节、页码与对象版本。引文内容、数学量和适用范围应核对原文，不凭标题或二手转述赋予结论。

正文不放日期、提交号、任务流水、历史对照或裁决过程。真实参考文献出版信息、机器 schema 标识及 API 中确有语义的版本字段正常保留。公式、接口表和 Mermaid 图用于解释机制，避免机械锚、虚构 ID 与重复导航。

实验与收敛记录按证据身份保存复现所需的历史事实，不套用正式设计的删改规则。修改文档时同步路径和索引，以结构检查辅助人工阅读；不设人工逐字计数、全树强制复读或专门注入写法错误的流程要求。
