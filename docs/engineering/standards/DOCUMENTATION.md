# 文档标准

上游：最高设计的文档权威与索引、文档写法两章[1]；写法与治理判据见
`../governance/DOCUMENT_GOVERNANCE.md`[2]。

文档分层、每类文档的必备内容与引用口径的工程正本。

```text
L0 最高设计与纪律   docs/ACSD_DESIGN.md、AGENTS.md
L1 科学正本         docs/science/**（公式、常数、判据、推导；权威）
L2 工程正本         docs/engineering/**（架构、行为合同、工程标准；权威）
L3 细节文档         docs/detail/**（模块工作细节、数据对象、接口落地）
L4 索引             docs/DOCUMENT_INDEX.yaml（全文档集唯一地图）
```

- 目录拓扑与登记的唯一地图是 `docs/DOCUMENT_INDEX.yaml`；文档索引的核对见 `../governance/DOCUMENT_GOVERNANCE.md`[2]。
- 文档域的正确性由人读对抗性审核逐条覆盖，不产出机器判红判绿；每个目录放一个极简 README，
  一两句说明该目录是什么、给谁看。

- 每份 science 文档：目的、科学定义、公式、变量与单位、假设、有效域、不保证什么、失效条件、
  系统误差、随机误差、数值精度、参考文献、采纳或改编或不适用的说明、科学与算法合同 ID。
- 每份模块文档：职责与非职责、公共 API、依赖与调用方、数据合同、所有权、并发、错误、配置、
  性能、诊断、用例、源码地图。
- 每份排障文档：症状、可能阶段、对应日志或指标或错误码、最小复现、预期不变量、
  源码与文档与用例路径。
- 正式文档集只保留现行设计；权威只取正式文档集内的现行条目。

## 判据的名词口径与上位冻结语句的同向性

下层正本与验收判据引用上位冻结语句里的名词时，只取该冻结语句之义，**不复述、不改写、不换词**。

同向性规则：

1. **口径只在一处**：名词的定义在上位冻结语句出现处；下层正文引用它时给条款号与标题，不复述定义；
2. **反义即缺陷**：下层把该名词取成反义含义（把表达层量当数据形态、把绝对量当相对量、把「不可辨识」读成「不许出现数值」等）时，以上位冻结语句为准并立即订正下层；
3. **逐条比对**：验收判据与上位冻结语句的名词口径逐条比对，出现反义即判红；比对方向固定为「下层判据 → 上位冻结语句」，不自建上位口径；
4. **执行面**：该比对属文档域，按 `../governance/DOCUMENT_GOVERNANCE.md` 的对抗性审核准入口径[2]，由人读对抗性审核逐条覆盖；文档域不设机器执行项。若同一比对在别面具备实质判据则按该面登记；自检必须含「注入反义表述即判红」的负例，只有正例自检不足以证明判据有牙。
5. **澄清用正向陈述**：需要消歧时直接写现行口径的正向句子，不写成对另一种说法的纠正（写法纪律见 `../governance/DOCUMENT_GOVERNANCE.md`[2]）。
