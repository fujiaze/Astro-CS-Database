# ACSD 人工科学与工程审查方法（不是自动门禁）

审查对象是**当前真实调用的生产代码及其真实输入输出**，而不是过去的Issue、历史日志、脚本绿灯、固定夹具或规定必须出现的“PASS数字”。主Agent应理解一个模块做了什么、数学为什么成立、数据从哪里来、内存由谁持有、真实天文图像是否合理；独立复核可帮助发现盲点，但不能替代证据推理。

## 1. 按一条真实数据链审，不按仓库路径数量审

拿一个来自M42的有效原始像元（包括合法星点、天空背景、坏点或饱和各类），在调试器、源码或有限的定向记录中追踪：
1. FITS解释/偏置暗平场、真实DQ与饱和和校准后的数值/单位；
2. Gaia/IPV的真实WCS与像元中心、局部Jacobian、选中的nside/order；
3. 原CCD像元与目标叶真实足迹交叠及Drizzle系数R，贡献被累到哪些实际touch叶，得到怎样的signal与support；
4. 多帧区域是如何建立真正覆盖交叠、冻结同一sky基准；Sky纠正在哪一次应用；
5. 一处叶的原始有效候选、传统排异方法与判定原因、每个实际非负权与`Σwx/Σw`输出，以及无支持/全拒/零权/合法负值状态；
6. 球面叶如何被目标WCS重采样和写入FITS，以外部独立读取工具和真实星点/背景确认。

同一函数值在两端调用同一错误kernel而相等，不能证明正确。人工画出输入/输出变量单位、索引与作用方向，并按数学公式直接复算具有物理意义的局部实例。出现异常时优先查调用链和模型而不是增加一批自动夹具。

## 2. 审模块责任：是否真的“流水线”

在生产代码实测时逐次查看`read_leaf_block`传入范围、实际读取范围及返回ArrayView/Lease；追踪一块在生产者交付Pipe后如何被消费者读取、何时释放、是否触发真实背压与取消；查Region是否只处理当前触及的叶，是否有意外重新构建全域std::map/std::set与dense`Nleaf×Nframe`；检查Sky拟合的小型全局屏障和跨进程正式产品的必要性。

任何“这个过程在自己的整个输入完成后才返回一个整图ArrayRef给下游”的设计，必须说明它为什么数学上无法流式化；若没有充分理由，直接改为有界块消费者。检查一帧、两个面板及多帧真实内存曲线，查明peakRSS构成，不凭框架自动宣称内存有界。

## 3. 审真实科学性

判断从观测得到的最终物理量是否清楚：源像元采样、WCS/SIP方向、PSF、ADU/SR标度、pixfrac、球面面积、响应身份、Sky加性差、传统排异、非负权均值与Export层级。未知Gain/Read/QE/有效响应导致的噪声/绝对精度缺口要记真实范围，**不为了“完美通过”开发另一种新研究方法**。

看真实M42的星点FWHM/椭圆率、孔径能量、星云低频/背景、高阶是否有块状伪纹、不同面板真正二维天球接缝、数据缺孔与无支持的区别。不能以FITS大小=4096²、WCS可逆、内部数据hash、产品声明完备代替科学画质。

出现不同结果，区分**旧main已证实有误的计算**、V2迁移引入的回归、物理输入不可辨识与性能近似。旧错不需要被逐位复现；V2修正必须能够明确说出原来错在哪里、采用何种科学事实更正、对真实输出有何影响。

## 4. 审性能：源代码级解释实测

读main生产分块、几何Lru、Sky稀疏解、Rejection小栈、Export共享缓存实现，然后看V2实际有没有同等功能。记录同机器、同科学工作量的真实 wall/CPU/活跃线程/RSS/字节I/O/cache miss/有效输出，找最慢的函数、长寿命buffer或重复读盘的实际调用者，解释为何慢。不能用“新框架成本”替代profile、不能由人工规定的20%线或CI评分裁定数学好坏。

要留意第三方库分配不受Runtime细粒度自动计费，以及异步消费者仍持有lease时的生存期；如果出现资源不足，不要通过全域扩大预算、降低NSIDE或减少帧来掩盖缺陷。

## 5. 记录方式：只保留当前事实，不堆审查轮次

每次实际修复的提交消息或当前任务Issue说明“修改的真实函数/前后数据流/数据规模/数学原因/内存热点/实际输出与剩余缺陷”。若一个小定向实验有必要复算，可在当前scratch覆盖运行，采集值得解释的实数/截图或FITS路径，不提交大量夹具或每轮历史报告。已修正的问题从当前 [TASKS](TASKS.md) 中消失或改成最新事实；不维护回合一到九的永久任务目录，也不设置假绿假红的自动判决。

判断进度不是给一个全局PASS，而是**说明哪些真实输入和产物已正常工作，哪些代码仍未迁完、哪里存在已解释的科学/性能问题**。解决后继续向原main完整功能和196帧交付推进。
