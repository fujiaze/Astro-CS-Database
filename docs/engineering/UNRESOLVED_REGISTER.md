## 1. 分层与读法

本面按处置性质分三层：

- **§2 方向裁决**：结构性或产品方向的分歧，读码不能定案，负责人给一句方向，或指定哪一条条款退出现行约束。
- **§3 来源核实**：作者身份与原始意图类问题，仓内查不出，负责人给事实。
- **§4 已裁**：结论已定、可回填正本的条目，列出供正本回填时取用。

每条给四项：内容、为什么必须由负责人裁、阻塞哪个交付面、现有证据或倾向。编号是本登记面的稳定键，引用方按编号指称，不引用本登记面以外的中间件。

本面不承担裁决，不写过程流水、责任归属与变更轨迹；裁决结论落回相应正本后，按 §5 的规则把该条从 §2 或 §3 移入 §4。

## 4. 已裁（5 条）

结论已定，供回填正本时取用；回填后本层条目由 §5 的规则处理。

| 编号 | 结论 | 落点 | 附带的待办 |
|---|---|---|---|
| 裁-1 | 算法模块是独立动态库；装出去的共享库无一在链接行上、无一落在活加载器扫描的目录，现状判为实现缺陷 | 模块交付形态正本 | 补齐整条加载链：安装布局放进加载器真会扫的目录、加载器要的清单入仓、补一条装载即必被加载的门；最高设计「或在可执行程序内部实现」那半句按变更流程处理 |

## 10. SCI-P5-1 · P5 主入口 rc=1 的根因：两条严格不变性门此前近乎恒真

### 10.2 根因（车道逐条取证，前台复核方向一致）

差异**全部落在生产求解器的输出量**上，不是判据实现、不是夹具、不是随机源：未校正臂接缝读数与固化值逐位相同；真实数据腿 `c7` 的相关系数等读数亦逐位相同；但**生产天光面的模型形态变了**：

- `n_params` 58 → **49**，`rank` 49 → 49

固化读数对应的一档里 `n_params = 58` 而 `rank = 49`，即求解系统在 **9 维零空间**上取最小范数代表；当前一档 `n_params = rank = 49`，**零空间消失、系统满秩**。

**关键判定**：三条红门里有两条是**依赖零空间吸收规范自由度**的严格不变性——

- `A6_subset_invariance`（任意覆盖子集上 cell 级加权均值不变）
- `A9_final_gauge_near_noop`（`final_gauge` 在整帧上是 no-op）

在秩亏最小范数解下规范方向被零空间吸收，**这两条门近乎恒真**；零空间消失后它们必须在新模型下重新推导。**它们的红不是判据被违反，是判据的前提变了。**

第三条 `W1_control_ivar_best` 不同类：它比三臂的相对次序与幅度比，次序不变（`control_ivar` 仍最小），幅度比从 2.7×/13× 降到 4.7×（`snr²` 一侧），跨过 0.20 门槛。

1. 按新模型重推阈值（须给出与确定性下限同级的依据，不能只改数字）；
2. 改写判据含义（例如把 `A9` 从「G ≡ 0 的代数恒等式」改写为「G 的量级上界」）；
3. 登记为「当前实现下该四要素不可检验」，与本单元诚实边界第 1 条同口径。

## 15. SCI-P3-2 · 前台 G08-04 车道报告的「闭式 (π/3)A_chart/A_exact−1 = ½ρ² 且分辨率无关」是**测量 oracle 的缺陷**，不是物理结论

### 15.1 事实

G08-04 的 P3+P4 车道报告了一条「新闭式」：`(π/3)·A_chart/A_exact − 1 = ½ρ²`，系数实测 **0.49978**，

### 15.2 前台独立复核（不采信车道结论，自己算）

**(1) 被积函数指数错误**：代码 `solid_angle_gnomonic` 的 docstring 与实现都写成

|---:|---:|---:|---:|---:|---:|

| ρ | √(1+ρ²)−1 | ρ²/2 | 相对差 |
|---:|---:|---:|---:|

## 25. GATE-3 · 星点检测的背景 σ̂ 存在**静默置地板**的 fail-open（R10 构造反例，前台已核实代码）

**归属**：P2（生产实现）　**状态**：**最高优先级待修**——这是本轮唯一一处**生产侧 fail-open**

### 25.1 前台核实的代码（逐行）

`lib/algorithms/star_detection/wrapper_phase1/star_detector.cpp:117-123`：

```cpp
*sigma = std::sqrt(sum / static_cast<double>(kn > 0 ? kn : 1));
// CLEAN-401 缺陷修（fail-closed）：原 `if (*sigma < 1e-9)` 对 NaN 判假 ⇒ NaN 帧
// 会把 NaN 当 σ 放行（假源爆炸，见函数上方保留块「已知缺陷」）。非有限 ⇒ 显式失败。
if (!std::isfinite(*bg) || !std::isfinite(*sigma)) return false;
if (!(*sigma > 0.0)) *sigma = 1e-9;
return true;
```

CLEAN-401 为修「NaN 被当 σ 放行」，把判定从 `*sigma < 1e-9` 改成 `!(*sigma > 0.0)`。
**该改法把 `sigma == 0` 也一并路由进了同一个分支**——而该分支的动作是**静默置地板**（`*sigma = 1e-9`），
不是显式失败。函数对 NaN 是 fail-closed，对 0 却是 fail-open，**处置自相矛盾**。

下游 `lib/algorithms/noise_snr/wrapper_phase1/snr_frame_science.cpp:89` 的守卫是：

```cpp
if (!std::isfinite(cfg.sigma_sky_adu) || !(cfg.sigma_sky_adu > 0.0)) { … return out; }
```

`1e-9 > 0.0` ⇒ **地板值恰好通过下游守卫**。链上无第二道拦截。

### 25.2 触发条件与后果（R10 实测）

当裁剪窗内像素**全为常量或全被掩膜**（常量/掩膜像素占比 **≥ 0.40**）时，第二阶 MAD **恰为 0**，
裁剪窗塌成 3e-9，落进上述分支 ⇒ `σ̂ = 1e-9` ⇒ **`SNR_frame` 高估约 2×10¹⁰ 倍**。
0.30–0.38 区间还有**无告警退化带**（高估 1.8–10.6 倍）。

### 25.3 为什么这一条最优先

- 它在**生产实现**里，不是实验脚本；
- 它**不是恒红**而是**恒绿方向的错误**（把异常值变成极小 σ ⇒ SNR 极大 ⇒ 一切判据看起来通过）；
- 1e-9 的地板值**恰好绕过了下游的正值守卫**；
- R10 同轮补出了 R04 待补实验 E2 的定量阈值：`r = σ_s/σ_n ≈ 3.2` 时单调性斜率已由 0.498 降到 0.192，
  `r≈9.5 → 0.048`，`r≈32 → 0.005`；而 M42 M2/M5 帧的 2.44–3.66 **正在半衰点上**
  ⇒ `frame-snr-canon.md` §2.7 现写的结构阈值**偏松约 1 个量级**。

### 25.4 修法方向（待负责人确认，不单方面改生产码）

把 `sigma == 0` 从「静默置地板」改为**显式失败**（与 NaN 同处置），并给下游一个**下界以上的合理性门槛**
而非仅 `>0`。注意这会改变现有读数（凡落在退化带的帧将从「通过」变为「失败」），属口径变更，
需按 AGENTS §8 走变更流程并登记读数差异。

## 32. GATE-3 已修：星点检测背景 σ̂ 的生产 fail-open（G08-07 处置）

**归属**：生产实现 `lib/algorithms/star_detection/wrapper_phase1/star_detector.cpp`　**状态**：已修（+20 / −3）

### 32.1 改了什么

```cpp
-  if (!(*sigma > 0.0)) *sigma = 1e-9;      // 静默置地板（规范 06 §2 明禁的静默降级）
+  if (!(*sigma > 0.0)) return false;        // σ == 0 与 NaN 同处置：显式失败
```

同时把函数上方的「已知缺陷」保留块从「已实施修法（两道）」改为「三道」，并把第 ③ 道写清。

### 32.2 为什么这是对的（三条）

1. **σ 的语义**：σ 是裁剪后残差的 RMS。RMS 恰为 0 意味着裁剪窗内像素**全为同一常量或全被掩膜**，
   不是「噪声极小」，而是「该窗没有噪声信息」。
2. **旧处置是静默降级**：规范 06 §2 明禁「静默降级」。地板值 1e-9 让下游
   `SNR = F/σ` 得到 ~1e9 的量级，而下游守卫（`snr_frame_science.cpp:89`）只拒 `sigma_sky_adu <= 0`
   ——**1e-9 恰好通过**，链上无第二道拦截。
3. **调用方已有稳定错误码路径**：`detect()`（`:132-135`）与 `module_adapters` 的 `catalog_guided`
   臂对 `false` 都产生 `ErrorDomain::DATA` 的具名错误 ⇒ 不需要新增错误码，也不会静默通过。

### 32.3 口径变更的读数影响（须登记）

本修正会把**落在退化带的帧从「通过」变为「失败」**：

| 常量/掩膜像素占比 | 旧行为 | 新行为 |
|---|---|---|
| ≤ 0.30 | σ 正常 | 不变 |
| 0.35–0.38 | σ/true 0.31→0.11，SNR 高估 3.2→8.9×（**无告警**） | 不变（仍通过，但仍在无告警退化带内） |
| **≥ 0.40** | σ 塌成 1e-9，SNR 高估 **1.999e+10 倍**，判绿 | **显式失败**，`ErrorDomain::DATA` |

⇒ 这是**有意的口径收紧**，不是回归。归档读数中若有落在 ≥0.40 的帧，其 SNR 值不再可用。
登记为口径变更，随 G08-09 重新出数时一并核对。
