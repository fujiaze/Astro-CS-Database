# 协作与文件分工

本文依据最高设计的职责分层和科学证据要求[1]，说明设计、实施与独立复核如何协作。任务的具体授权和文件清单决定本次写入范围，本文不以固定车道覆盖用户指令。

## 职责

前台科学与工程架构负责人通读上层正本和真实调用图，亲自维护最高设计、科学与工程正式正本，明确模块所有权、typed 数据合同及可辨识性边界。执行 Agent 按确定规格修改实现、接口、构建与测试，记录真实命令、输入、输出和未完成项；文档事实核查不授权其重新选择参考通带、WCS、SNR 或误差模型。前台独立检查模型、代码行为与证据是否相符，不以实施者的成功摘要替代核对。

生产代码、合同、测试与文档的具体写域在任务开始时点明。执行者发现科学矛盾时先给出一手依据、独立反例及实现事实，由前台裁决并订正唯一正本，再据此实施。文件分工用于防止覆盖，不增设永久 A/B/shared 权限或共享文档登记审批。

## 任务与并发修改

派单列出先读的最高设计、science、engineering 与 detail 路径，说明修改目标、文件范围和交付证据。Normalize 的实施依据由科学、生产链、数据合同与接口规格组成[2–5]；研究包和实验报告提供背景，不另立定义。

并行任务优先划分互不重叠的文件。必须改同一文件时先交流具体段落和修改顺序，保留未合并内容；发现工作区冲突先协调，不重置、覆盖或强制丢弃他人改动。跨域适配若已在任务授权内，应一并完成；超出范围的修改给出路径、原因和影响，由任务负责人统一安排。

## 模型变化与实现变化

保持数学行为的重构，以已定义估计量、单位和可复现输入对照数值。改变科学模型的工作需要一手依据、独立数值反例或实验与实现事实，由设计负责人修订唯一正本，再同步受影响实现与测试。测试 Oracle 是检验工具，其定义服从科学正本；不能用放宽容差或保留不合模型的断言掩盖差异。

报告区分接口声明、静态接线、构建执行、产品观测和独立科学支持，具体追溯要求见[6]。未执行的项目直接标明，失败过程保留在所属实验单元。

## 交付与合并

每组变更有清楚目的，说明文件、行为、验证范围和未决问题。提交、推送、分支与合并按用户本次授权执行；共享文件的整合顺序由实际并发关系决定。文档协作不新增差异单审批、固定合并点或发布权限。发布决定由项目负责人作出[1]。
