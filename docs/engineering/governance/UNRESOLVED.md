# 未决登记

本页依据最高设计[1]，登记尚缺输入、独立证据或负责人取舍的具体问题。已由正式正本确定的模型直接作为实施依据，不再交给执行者选择。问题状态不构成研发或合法输入的审批门。

## 已明确的依据

Normalize 的科学、架构、字段和接口以对应正本为准[2–5]：IPV 实际尝试解 WCS；共同参考由具名 SED/response 或显式积分通量定义；平面模型经同次 Drizzle 完成球面精度；点源通量精度通过同条件 T 才能转换为面亮度精度；大面默认 FP32、稀疏和元数据 FP64；信号合法且 precision unavailable 的帧可保留产品身份。

阶段内目标为 Runtime typed payload，科学 cache/spill 与开发快照分开。descriptor、IR、端口登记和 AIO 读写按真实生产者与消费者同步，不以机器 schema 冻结文字覆盖科学正本。跨设备与通带组合由用户选择，报告系统失配，阶段二最终只写单 signal HiPS，Export 输出普通二维 WCS FITS，不凭空生成方差。

文档索引覆盖 Git 跟踪的 docs 全部文件，科学与工程正本同级；自动结构检查辅助人工语义复核，详见治理规范[6]。这些事项不属于待裁。

## 待核实的数值与实现问题

下表给出需核实的断言和影响。它是问题导航，未在本页重跑的读数不作为当前实现已发生的事实；复核须关联具体代码、输入和输出。可按现行正本直接修复的事项为实施项，需要改变定义的反例才回到科学负责人。

| 标识 | 需核实的对象 | 影响与所需证据 |
|---|---|---|
| 裁-5 | 裸 HiPS 与归档形态的信号、支持及低支持像元等价性 | 同一输入产品在两形态下独立读取，分离格式量化、无效值与浮点误差 |
| 裁-6、核-1 | 测光空间响应阶数的实际默认、配置来源和可辨识性 | 当前配置→拟合→标度应用调用链；阶数选择的独立留出证据，不能按无来源默认宣称科学完成 |
| 裁-8、核-3 | 纯 CPU 生产要求与构建闭包 | 真实编译源集、链接依赖和可达路径；依据最高设计修实现，不扩大生产后端目标 |
| 裁-9、裁-13 | 球面逐格交叠误差与总量闭合的区别 | 独立曲边/HEALPix 真值、完备性负例、适用域及误差预算；求和闭合不能替代逐格正确性 |
| 裁-14 | 条件参考方差与经验重复测量散度的关系 | 同估计量、同背景/PSF/条件协方差下的独立随机实验；经验差异单独解释，不自行更换生产分母 |
| 裁-15 | drop、未收缩源面积、面积归一量和支持的字段对应 | 按科学正本追到真实 R 和 writer 单位；同名异物或不同量混用按合同修复 |
| 裁-16、核-5 | 缺来源的数值阈值、稳健尺度常数及适用域 | 一手原文、独立推导或可复现标定；先报告未知来源及影响，不凭审批将其变为科学常数 |
| 裁-19 | 背景参考与自相关项的实现位置 | 正本中的估计量、真实残差/求解路径、独立注入；确认是否重复或遗漏，不凭名称判断 |
| 裁-20 | 饱和与掩膜作用于模板、噪声和空间支持的关系 | 明确数据域、正例与故障注入，按真实有效样本计算分母；判据与模型不符时同步订正 |
| 裁-21 | 两帧等稀疏覆盖输入下的可辨识性和显式退化 | 最小合法帧集的实际执行、未约束自由度和输出状态；不以帧数替代物理定义 |
| 裁-22 | 非对称裁剪后的 CRPIX 与目标 WCS | 独立 WCS 读写器和实际裁剪几何；参考像元不强制等于画幅中心 |
| 裁-23 | 重采样相关噪声读数的定义和适用性 | 仅在有明确输入协方差的实验内复算；单 signal Export 不发布无依据最终方差 |

问题的科学定义由对应专题正本拥有。不能将上述表中的待核实描述当作已经证实的缺陷，也不能用文档修订宣布数值问题已经解决。

## Normalize 实施与证据缺口

| 标识 | 责任边界 | 仍需取得的事实 |
|---|---|---|
| ENG-B1 | typed Runtime、八节点端口、writer 与 AIO 的逐边一致性 | 实际对象类型、所有权、输入版本、producer/consumer、正式 cache 和生命周期；sidecar 调用存在不等于全部边完成 |
| ENG-B2 | IPV 求解及正式失败诊断 | 每帧真实 attempts、hint、目录、检测/匹配数、错误原因和输出 WCS；正常失败日志不受开发快照开关控制 |
| 裁-18、裁-27 | 参考通量方差与面亮度方差分别建模，T 同位置同条件 | 阶段一球面 controls、模型可读性和独立条件 GLS；不以此授权切换阶段二生产权重 |
| 裁-28、裁-29 | 稠密面与稀疏/元数据分别保持精度 | 实际 typed 载荷、AIO 写读和 FP64 round-trip，不以单个全局精度位或字段声明当保证 |
| 核-6 | 执行结论须有可取得的证据 | 缺命令、输入或输出的结论标为未证实；根据需要复测，不补造 VERIFIED |

无原始 WCS 头与真实 solver 失败分开记录。已发生的求解结果只支持其输入和代码范围，不能外推到仅做头部普查的其它帧。求解未成功的帧不得球面化，其他合法帧仍按合同保存，并在运行清单反映不完整集合。

## 配置与机器载体一致性

配置合同[9]集中维护配置、模板和运行清单的字段与实现对应。打包模板与 CLI 模板的默认值及块形态、schema 与 parser 接受的配置分支、run-manifest schema 与实际 writer 的字段词表仍有一致性缺口；具体位置和静态差异在该合同登记，本页不复制字段表。后续实施需同步这些生产与消费面，并用实际生成的模板、解析结果和 manifest 读写核对，不能由文档已订正推断机器载体已一致。

响应曲线身份应绑定实际内容和解析对象。目录中的曲线统计摘要不是加密内容身份，测光残差小也不能唯一辨认物理响应；两者均不能单独证明所用通带正确。配置合同说明曲线定位、内容身份、模型声明与测光诊断各自承担的责任[9]。

## 治理与发布边界

裁-7、裁-10、裁-11、裁-24、裁-25、裁-26 所涉及的文档归属、索引覆盖和检查执行面，以文档治理和追溯规范为准[6–7]：没有固定模块数、审批档位或全绿后开发的条件。可复核的数值测试、损坏输入校验与资源测量继续按其实际用途维护。

核-2、裁-12、核-4 所涉及的表述分别按科学适用域、注释标准和负责人发布权处理，不以未知授权历史阻挡已明确目标的修复。真正需要负责人决定的是尚未确定的产品取舍和发布安排，记录具体选项与影响，不把实现缺口包装成重新选择模型。
