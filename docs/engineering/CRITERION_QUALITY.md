# 判据质量规范

> 上游：docs/ACSD_DESIGN.md §12.1（科学正确性与三重佐证）、§12.2（三类实验数据）

本文件规定什么叫「有判别力的判据」，哪些形态不合格，仓内已有哪些合格写法可以照抄，以及整改时如何选用。
适用于 `lib/`、`eng/`、`实验/` 三棵树下的全部判定点：断言、校验、诊断量、自检入口。
判据的载体是**源码本身 + 人读对抗性审核 + 实验复核**：定性问题由审核者逐条定性，不产出自动判红判绿。
因此本规范约束两件事 —— 写代码时的自律，以及审核时对既有写法的定性；它不描述任何注册或执行流程。

---

## §1 判据的合格形态

判据的价值不在于「跑起来是绿的」，而在于**同时具备两种能力**：在实现正确时绿，在实现有缺陷时红。
只有第一种能力的判据不产生任何信息 —— 它是一次恒真的仪式，成本却与真判据相同，还会在报告里冒充证据。

一条判据要合格，必须同时满足以下五条。它们不可互相替代：任何一条缺失，判据都退化为不合格形态之一。

### 1.1 期望值独立于被测量

判据两侧（被测量与期望值、实测与阈值、产物与复算值）**不得同源**。
期望值只能来自四类来源：

| 来源 | 说明 | 仓内实例 |
|---|---|---|
| 外部标准 | 公开的、可被第三方复核的权威常数 | `lib/infrastructure/pipeline/module_loader/secure_loader.c` 的自检用 FIPS 180-4 公开摘要向量 |
| 冻结合同 | 仓内的合同 JSON / schema / 正本文档 | `eng/contracts/resource_gate_v1.json` |
| 解析推导 | 由被测量之外的量算出的上界或闭式解 | `lib/infrastructure/scheduler/src/mosaic_window.cpp` 的 `window_peak_bound_bytes` |
| 另一次运行的产物 | 与本次被判定记录不同的那一次测量 | —— |

反过来，下列来源一律不构成期望值：被测函数自己算出的值；与生产同一表达式的测试内副本；
同一份 JSON 里紧挨着的另一个字段；模块级常量在别处的赋值表达式。

### 1.2 先证明自己被执行过

判据必须先自证**确实碰到了被判定对象**，再对结果下判断。
「没找到被测对象」「集合为空」「样本数为零」都必须判红，绝不能读作通过。

典型写法是给判据加一条**非退化锚**：先断言被比较的量真的动过、真的非空、真的逐个比对过，
再执行真正的比较。

### 1.3 双向

同一条判据、同一套容差、同一个函数，必须能同时给出两个结论：正确输入绿、注入缺陷红。
只有绿侧或只有红侧，判据都无法证明自己有牙齿。

### 1.4 裁决接线

判据算出的结论必须接到**能挡住谁**的出口上：进程退出码、事件流的 severity、manifest 的 status、
构建失败，或**读到这条结论并据此行动的审核者**。写进产物 JSON 的某个字段、而没有任何读取方，
不构成裁决 —— 那是记录。「没人读」在任何载体下都等于「没有裁决」，包括人工载体。

### 1.5 失败诚实传播

失败路径上，「我没做」必须与「我做了，结果是 0」可区分。三条硬要求：

- **不可用态不得用合法值表示**。需要用数值哨兵时，取一个不可能出现在合法值域里的值（约定上取非有限值），
  并让下游的自然检查（有限性判据、符号判据）拦住它。用 0 或 -1 作哨兵的前提是它们不属于该量的合法值域。
- **失败不得就地降级为默认值后继续**。降级必须留痕：单独的降级标志位、具名的原因码、或直接失败。
- **失败原因不得坍缩**。分配失败、解析失败、参数非法是不同的域，映射到同一个错误码等于把可区分的失败压成不可区分。

## §2 八类不合格形态与可机械识别特征

以下八类形态互相交叉，一条判据可以同时属于多类。每一类给出可被机械检索的特征。

### 2.1 恒真判据

任何输入都通过，判别力为零。

| 识别特征 | 检索方式 |
|---|---|
| 无符号量与 0 或负界比较 | 对 `size_t` / `std::size_t` / `uint32_t` / 计数型 `int` 出现 `>= 0`、`> -1`、`== 0` 的"非负即通过"型断言 |
| 布尔量被赋字面量后不再被重写 | `bool ok = <literal>` / `ok = True` / `ok = False`，其后到函数结束无任何对该变量的重新赋值，且该变量被 `if` 读取或作为裁决传出 |
| 裁决参数直接是字面量 | 门的 `verdict=` / `ok=` / `result="PASS"` / `all_pass` 接字符串或布尔常量，且同一字典里还带着实测值 |
| 语言已保证的性质被当作判据 | 对首成员偏移、`sizeof` 等已被语言或前序静态断言强制为真的性质再写运行时断言 |
| 判据只有一侧平台分支有内容 | `#ifdef` / `#if` 的 `#else` 分支体为空或只有 `(void)x;`，非当前平台零断言通过 |
| 常量天然满足的区间判据 | 下界写成 1、写成默认值、或写成与被测常量同源的表达式 |
| 全部断言包在存在性守卫内 | 整个判据体被 `if (obj exists)` / `if (find(...) != end())` 包住，而否定分支直接返回成功 |

### 2.2 恒红判据

任何输入都失败。

| 识别特征 | 检索方式 |
|---|---|
| 判据的依据物已被删除或迁移 | 判据读的文件、导入的检查器、参照的正本在仓内不存在；这类判据在导入期即整体失效，不是逐条红 |
| 导入期失败被当成逐条红 | 模块级 `import`、`spec.loader.exec_module`、`exec(open(...))` 指向的路径不存在 ⇒ 整个文件的用例一条都采不到 |
| 精确相等用于只在精确算术下成立的不变性 | 对只在实数域不变的量（缩放不变性、谱分解不变性）用浮点逐位相等判定 |
| 浮点非有限值参与算术 | 两个无穷相减、`inf - inf`、用 `NaN` 比较做检测 |
| 在布尔数组上取极值 | `argmax` / `argmin` 作用于布尔或阈值序列，未确认该序列一定越过门 |
| 脚本退出码与判据脱钩 | shell 脚本的最后一条命令是 `echo` / `rm` / `cat` / `printf`；或刻意省去 `set -e` 而保留 `pipefail` |
| 平台分支只有非当前平台实现 | 读目录类、只读保护类判据只在 POSIX 或只在 Windows 成立，而门对另一平台也要求通过 |
| 失败被 `pass` / `continue` 吞掉后由外层计数 | 负例红与「跑不起来」合并，两者不区分 |

### 2.3 自证式判据

判据两侧同源，判据只是在证明被测对象与自己一致。

| 识别特征 | 检索方式 |
|---|---|
| `X == g(X)` | 模块级常量由某表达式赋值，判据又断言该常量等于同一表达式；出现「读自己打印的数字再与自己的列表长度比」 |
| oracle 是生产表达式的逐字副本 | 测试/检查器内声明为独立 oracle 的函数，其实现与被测路径同形（同一排序、同一几何公式、同一插值核） |
| 期望值由被测函数生成 | 期望数组/期望值由与被测代码相同的生产函数 `finalize` / `compute` / `build` 现场算出 |
| 同函数同入参跑两次比对 | 同一函数、同一入参调用两次，比两次输出 —— 这只验确定性，不验正确性 |
| 确定性由被测方自报 | 裁决读取的是被测子进程自己打印的状态串，而可独立比较的数据就在手边却未被读取 |
| 影子预言 | oracle 自己调用了被测对象来算期望值 |

### 2.4 默认值自证

判据只检查零值 / 空值 / 缺省值，坏实现同样给得出。

| 识别特征 | 检索方式 |
|---|---|
| 只验「返回零结构且不崩溃」当作拒绝判据 | 断言 `width == 0 && height == 0` 出现在「恶意输入必须被拒绝」的用例里 |
| 断言自己从未赋值的字段 | 测试构造结构体后只赋部分字段，却断言另一字段等于其类内缺省值 |
| 断言本地默认构造容器的尺寸为零 | 断言刚 `new` 出来的空容器的 `size() == 0`，发生在任何 I/O 之前 |
| 空集归约喂给闭区间阈值 | `max(..., default=0.0)`、`mean([])`、`median([])` 的结果直接进 `<=` 或 `>=` 判定 —— 空输入恰好产出"通过" |
| 缺输入渲染成 0 后当实测读 | 上游产物缺失时下游统计量落 0，随后被当作「实测为 0」写进结论 |
| 计数器恒 0 的分支被计入总量 | 某项计数只记失败不记成功，汇总层当零处理 |

### 2.5 名义判据

名称、注释或 docstring 声称检查 X，函数体从不检查 X。

| 识别特征 | 检索方式 |
|---|---|
| 名字声称的量在体内从不被比较 | 名字含 `independent` / `cross` / `oracle` / `consistency` / `align` / `selection` / `faster` / `invariance` / `frozen` / `gate` / `verify` / `check` / `guard` / `lifecycle`，体内找不到对同名量的比较 |
| 控制形参被接收后丢弃 | 函数签名声明控制开关，函数体开头 `del` 或不使用它，构造命令行时该开关不起作用 |
| 文档声明的负例在代码里不存在 | docstring 写明的负例控制、对照组、独立复核，对应标识符全文不出现 |
| 头部列出的覆盖项无对应用例 | 文件头声明的验收项在全文无任何用例涉及（常见于只 `#include` 了头文件就声称覆盖） |
| "独立"实为同族 | 声称对照生产求解器，实际两侧是同一族函数的不同实现，共用同一套几何/索引逻辑 |
| 比较量纲错位 | 声称逐元素对比，实际按固定步长抽样 |

### 2.6 空壳断言

判据的描述还在，判据本体已空。

| 识别特征 | 检索方式 |
|---|---|
| 注释描述判据后紧跟结构结束 | 注释块完整写出判据内容，其后是循环右括号、函数右括号或 `return`，无任何断言 |
| 用例以无条件成功收尾 | 用例名声称某性质，函数体末尾是 `SUCCEED()` / `pass` / `return`，与该性质无关 |
| 断言消息与断言值脱节 | 消息里写的量纲、取值或数量与断言表达式携带的不是同一个量 |
| 断言被 `if` 吞 | 多个实质断言被存在性 `if` 包住，条件不成立时函数照常返回成功 |
| 编辑遗留 | 断言被删后注释未删，读起来像有判据 |

### 2.7 硬编码 PASS

裁决值是字面量，或与测量脱钩。

| 识别特征 | 检索方式 |
|---|---|
| 裁决字段接常量 | `verdict=` / `ok=` / `conclusion=` / `status=` 接字符串常量，而实测值在同一表达式附近 |
| 诊断量算了不判 | 派生量被算出并落盘，但全文没有任何比较把它与阈值或期望值连起来 |
| 期望值与实测值并排存放 | 同一字典里同时写 `expected` 与实测字段，全文无任何一处比较这两个字段 |
| 退出码与自身算出的失败数脱钩 | `main()` 算出失败计数但不 `return` / 不 `sys.exit`；或退出码取自一个与失败数无关的表达式 |
| 陈旧重写导致 `return True` | 判据重写后遗留无条件成功返回 |
| 退出码硬编码常量 | 函数在失败分支上返回固定码，与实际原因无关 |

### 2.8 双读法

同一个字段 / 返回值被两处按互斥语义消费。

| 识别特征 | 检索方式 |
|---|---|
| 布尔返回在成功与失败分支含义不同 | 一个 `bool` 返回：成功路径表示「成功」，失败路径表示「取消」/「跳过」，调用方按同一语义读 |
| 不变式与断言方向相反 | 文件头写下的不变式（如「判定非 ok 当且仅当退出码为某值」），在同文件另一处断言相反方向 |
| 同名字段两套哨兵约定 | 两个头文件对同名状态字段约定不同的缺省含义 |
| 一个值填多个语义不同的字段 | 同一个量被写进几个命名不同、含义不同的输出字段 |
| 失败串与实际比较的阈值不同 | 失败诊断消息里写死的阈值与真正参与比较的形参不是同一个 |
| 枚举别名 | 两个不同的枚举值返回同一个 token，下游按 token 审计时两种状态不可区分 |

## §3 仓内已有的合格写法模板库

以下每条都已回到源码打开对应段落逐字核对。
「它守住了什么」一栏给出该写法所防御的失效面 —— 这是选用模板时的主要依据。

### 3.1 判据本体类

**T1 · `lib/infrastructure/scheduler/src/mosaic_window.cpp`**
判据函数与其解析上界函数同处一个编译单元，四条子判据缺一不可。
每条都被设计成能被特定退化实现打红：峰值为零判红（挡未记账）；峰值超过解析上界判红（上界来自独立的解析公式，不是被测值）；
同窗口大小、不同总图规模时峰值必须相等（挡与总规模耦合）；两个窗口都装满时窗口更大者峰值必须**严格**更大。
代码注释明确写出「严格」是反恒真的关键，并指出「不减」这一较弱表述会被常量驻留满足，属退化判据。
**守住**：内存驻留量不被常量或未记账的分配蒙混过关。

**T2 · `lib/algorithms/drizzle/healpix_drizzle/wcs_sip.cpp`**
在数学奇点分支前用自然语言写死了哨兵政策：必须返回非有限值让下游的有限性判据拦住；
不得返回有限哨兵值 —— 哨兵会被有限性判据放行而静默映射到错误像素，且精确对跖点的公式值恰好就是零。
**守住**：投影奇异与无效几何不被伪装成合法坐标。同一文件的另一方向违反了自己的这条规则，说明该政策是逐调用点适用，不是逐文件适用。

**T3 · `lib/algorithms/coverage/src/upm.cpp`**
同一政策的另一实例，且把理由写得更具体：不可用一律取非有限值；
零是 gauge 参考帧的合法取值，用零当哨兵会让调用方把「无模型」读成「无校正」，即 fail-open。
**守住**：模型可用性不得被读成校正量为零。

**T4 · `lib/infrastructure/aio/src/aio_sparse_punch.h`**
落盘后回读验证：写前算摘要 → 打洞 → 丢弃页缓存 → 再算摘要 → 不一致时返回专门的失配码；
另加一条「洞提交了但分配字节没有下降 ⇒ 判红，不得当成功」。
**守住**：写动作的持久性与真实释放，而不是只相信返回值。

**T5 · `lib/infrastructure/aio/src/hips/aio_hips_writer.cpp`**
产品集校验通过 reader 重开产物进行，而不是相信写者自己的账本；
manifest 与磁盘**双向**核对（声明了而磁盘没有 / 磁盘有而未声明）；另有专用故障注入旋钮，
注释点名它等价于哪种缺陷、由哪条校验规则捕获。
**守住**：声明与事实的双向一致；写路径的失败不能靠写者自述掩盖。

**T6 · `lib/infrastructure/pipeline/module_loader/secure_loader.c`**
自检比对 FIPS 180-4 的公开摘要向量（空串、短串、跨块长串），期望值完全来自外部标准；
配套还有「无法判定 ⇒ 保守拒绝」的口径，以及对规范化路径与磁盘字节哈希的真实外部状态比对。
同一函数末尾另有两处 `sizeof` 比较，已被头文件的静态断言强制为真 —— 同一函数内正反两种写法并存，是很好的对照。
**守住**：实现正确性 + 路径规范化；不可判定不得当通过。

### 3.2 错误域与失败传播类

**T7 · `lib/infrastructure/scheduler/src/module_adapters.cpp`**
节点失败时按原始错误域记录轨迹，而不是改写成通用域；同文件另有把分配失败映射到资源域、把解析失败映射到数据域的写法。
**守住**：内存耗尽不得被报成用户数据格式错；错误域不得在节点边界被抹平。

**T8 · `lib/infrastructure/scheduler/src/export_stream.cpp`**
同一函数内，写头失败被分类为写失败并置对应标志位；开文件失败却只发取消信号。
**守住**：真实文件系统失败与用户取消必须可区分。右侧是反例，说明这是漏改而非设计。

**T9 · `lib/infrastructure/aio/src/aio_pipeline.cpp`**
一处导出检查了短写并据此返回非零；同文件的另一条导出路径的多次写调用全部丢弃返回值后返回成功。
**守住**：产物截断不得被当成完整产物。

**T10 · `lib/algorithms/psf/src/dpsf_psf.cpp`**
同一个 catch 块，在一条批量路径上写「分配失败」状态码，在另一条批量路径上写「参数非法」状态码。
**守住**：未知内部异常不得被报成调用方几何非法。前者合格、后者不合格，区别在于所选状态码的**声明含义**，不在于它是否「笼统」。

**T11 · `lib/algorithms/calibration/src/cosmetic_corrector.cpp`**
统计量退化（尺度为零）时显式置「检测不可用」标志并直接返回，不判定任何列，
注释引用真实帧上该退化确实发生的证据，并写明禁止按零尺度判成全坏或全好。
**守住**：退化输入不得被静默判出一个看似正常的结论。

**T12 · `lib/infrastructure/scheduler/src/runtime.cpp`**
节点失败轨迹记录原始错误域。
**守住**：错误域在跨层传播中不被改写。

### 3.3 判据非退化与双向类

**T13**
P+N+E 三段门：正例必须绿；用独立 oracle 几何把被测量投影回另一种归一分母，该投影必须红；再加端点退化例。
文件头写明负例的作用是证明容差**确有分辨两种归一分母的能力**，并声明本门不调用被测函数来产生期望值。
**守住**：容差不是任选的；判据确实在检验它声称的性质。

**T14**
非退化锚：先断言被比较的两个重建场**确实不同**（注释标为 non-vacuous），再谈它们是否一致。
**守住**：判据先证明自己被执行过。

**T15**
明确写出该断言在冻结配置下恒成立、不存在任何合法配置能进入该块，
并紧接着指名「若把某开关改回条件成立即真，本测试转红」。
**守住**：结构性恒真的判据应当**如实声明并指名可红的改动**，而不是删掉或假装有判别力。

**T16**
三阶段双向排除：基线必须通过（排除恒红）；两个不同的注入点分别必须失败（排除恒真）；
注入名必须真实存在，否则子进程仍会通过，因此显式检查子进程返回码。
**守住**：一套判据同时排除两个方向。

**T17**
`--selfcheck` 反向证明：用探针真实布局构造一个**故意破坏**的镜像（字段重排 + 漏字段 + 常量污染），
断言锁必然报警；锁对被破坏镜像仍然放行即视为门失效并非零退出。
**守住**：锁本身不是恒真。

**T18**
负例基础设施的三重自证：先证明沙箱基线自身全绿（否则整个负例面无意义）；
每条注入执行前记录树摘要，执行后必须证明**真的改了东西** —— 没改即判红并点名「注入是空操作，靶点已失效」；
注入抛异常必须显式报告，不得静默算过。
**守住**：负例面本身可用。

**T19**
正控制（未变异源码必须全绿）+ 锚文本失配检测（锚在目标文件里必须恰好出现一次，否则报 missed 而不是静默跳过）
+ 每条变异必须失败。
**守住**：变异测试框架不退化为空转。

**T20**
强制「注入前后必须不同」：注入态与非注入态的状态与持久性档位任一相同即判负例为 vacuous。
**守住**：负例没有真的注入。

**T21**
变异前置断言：先断言待变异的文本当前确实存在于文档中，注释写明「否则本 mutation 无效」。
**守住**：变异目标先得存在。

**T22**
非退化要求直接写成一条违规：「未找到某作用域声明（判据非退化要求）」。
**守住**：找不到被测对象不等于通过。

**T23**
注入未生效时主动失败：返回码符合预期但注入其实没发生（缓冲吸收了全部输出）时，
判为「本用例零证据，不得计为通过」，而不是跳过或通过。
**守住**：失败的注入被记成通过的证据。

**T24**
白名单回归哨兵：临时把被拒样本加进白名单，断言 `allowed()` 仍拒绝它。
头注写明排除保证与白名单解耦 —— 即使白名单被误加回，也必须拒绝。
**守住**：把白名单放宽这一伪修复被直接封死。

**T25**
外部权威逐像素对照；参照 tile 缺失时计成 mismatch 而不是静默跳过；末尾是「缺失、冗余、像素不符三者皆为零」的硬门。
**守住**：映射关系由仓外标准背书，且缺失不可被跳过。

### 3.4 前置与裁决接线类

**T26**
fail-closed 前置。注释点名历史失效形态：跳过装饰器在依赖库缺失时把整类用例静默变成 OK，使该层验收不可能失败。
**守住**：前提不满足时不得表现为通过。

**T27 · `eng/tools/quality/resource_monitor.py`**
阈值唯一数值源是冻结合同 JSON，导入期 fail-closed，并逐段核对父目录层级；
文件内不发明默认数值。
**守住**：阈值不漂移、缺合同即失败。

**T28**
用外部权威算法的标准向量作期望值。
**守住**：实现的正确性由外部标准判定，而非由自身往返。

## §4 可机械批量排查的形态清单

以下每条都可作为一次性全仓扫描的规则。识别模式给出可检索的形状，「为什么」说明该形状为何足以定性，
「建议动作」给出处置方向。

| # | 识别模式 | 为什么 | 建议动作 |
|---|---|---|---|
| M1 | `bool X = <literal>`（或 `ok=True`）之后到函数结束无重新赋值，且 `X` 被 `if` 读取或作为裁决传出 | 裁决位与数据无关，判据不能被数据推翻 | 先确认该变量不是循环累积标志（有 `break` 的累积标志是合格写法）；确认后改接实测条件 |
| M2 | 裁决字段的 `verdict=` / `ok=` / `status=` 接字符串或布尔常量，且同一表达式附近存在实测值 | 结论不是从数据算出来的 | 用实测条件替换字面量；替换后必须接 §1.4 的裁决出口 |
| M3 | 无符号量（`size_t` / `uint32_t` / 计数型 `int`）与 0 或负界比较 | 类型上不可能失败 | 换成与意图匹配的下界（「至少发生一次」用严格大于零），或补非退化锚 |
| M4 | `max(..., default=0.0)` / `mean([])` / `median([])` 的结果进闭区间阈值 | 空输入恰好产出通过 | 空集先判红再比较；或改用不产生默认值的中位数实现 |
| M5 | 同一字典里 `expected` 与实测字段并排，全文无比较两者的运算符 | 期望值只是装饰 | 补比较；若期望值确实无法计算，删掉该字段而非留着冒充 |
| M6 | 空 `catch` 体 / `(void)` 丢弃可失败函数的返回值 | 失败信号被就地丢弃 | 按 T7–T11 分类映射到正确的域与状态码 |
| M7 | `main()` 算出失败计数但无 `return` / `sys.exit`；脚本末条命令是 `echo` / `rm` / `cat`；`set -uo pipefail`（缺 `-e`） | 退出码与判据脱钩 | 把退出码接到失败计数上；脚本补 `-e` 与显式非零退出 |
| M8 | 整块断言包在存在性 `if` 内，否定分支返回成功 | 条件不成立即零断言通过 | 否定分支改为失败，或补非退化要求（见 T22） |
| M9 | 名字含 `independent` / `oracle` / `cross` / `consistency` / `selection` / `invariance` / `frozen` 的函数，体内无对应量比较 | 名称承诺与实现不符 | 要么实现该比较，要么改名（语义层，不涉及风格） |
| M10 | 两条门条目的「被测量表达式 + 阈值」二元组完全相同，只有门名与说明文字不同 | 门清单虚增，实际无新增判别力 | 合并为一条；或让第二条换用独立的被测量 |
| M11 | 判据中的期望值取自某个合同字典，而被测模块也加载同一个字典 | `X == g(X)` | 期望值改取外部标准、手推闭式，或另一次运行的产物 |
| M12 | 错误路径上把结果置为 0 / -1 / 空串 / 全零 memset，而该量的合法值域包含这些值 | 失败与合法结果同形 | 改用非有限值哨兵（见 T2 / T3），或另置独立的降级标志 |
| M13 | 阈值由本次被判定记录自身的散布量算出（如「三倍本次标准差」） | 阈值与被测量同源，判据只反映本次记录的噪声 | 阈值改取冻结合同或预先标定的常数 |
| M14 | 两个不同特异度的 `catch` 映射到同一错误码，或同一 `catch` 把不同异常类型映射到同一码 | 失败域坍缩 | 按 §1.5 拆分为具名错误码；先核对该码在头文件中的声明含义 |
| M15 | 模块级 `import` / `exec_module` / `exec(open(...))` 指向的路径 | 路径不存在时整个文件的用例采不到 | 先验证路径存在；不存在则该文件按「判据整体失效」单独立项，而不是逐条记红 |
| M16 | 阈值的字面量只出现在定义被测量量的那个文件里，全文无对合同/标准文件的引用 | 阈值无出处 | 把阈值迁到合同文件，判据只读合同 |
| M17 | 一个 `try` 包住多个测试用例的调用 | 首个抛出后续不再执行，汇总计数失真 | 每个用例独立异常边界 |
| M18 | Python 判据辅助函数里 `assert` 之后 `return` 而非 raise | pytest 下恒绿 | 改 raise |
| M19 | 派生量被算出并序列化，全文无任何比较使用它 | 算了、记了、没判 | 补比较，或删除该字段 |
| M20 | 输出字段名暗示某个实测量，取值却是字面量 | 产物里印的不是测出来的数 | 改为实测值；确无测量能力则删除该字段 |
| M21 | 一个字段被多次赋值，后一次无条件覆盖前一次 | 后写的值抹掉先写的证据 | 改为只在证据缺失时补位，并加条件 |
| M22 | 同一重载/同一函数的两条分支返回不同含义的第二个值 | 调用方按统一语义读 | 统一为同一套语义，或在返回类型上区分 |

## §5 已知易误判清单

以下都是判据在检索阶段看起来可疑、但打开源码后不成立或定性需要改判的形态。
记录它们是为了避免后来者重复踩坑。

**E1 · `pass` 只有在与被守卫语句同层时才是抑制。**
某校验脚本在「字段缺失」分支里写了一个 `pass`，看起来是放行违规。实际那个 `pass` 比紧随其后的
违规登记语句深一层缩进，登记语句始终执行 —— 该 `pass` 是死代码，实际行为比注释**更严**。
**判据**：看缩进层级，不看关键字。

**E2 · 「读到 None 就 return」只有在读取本身不登记违规时才是 fail-open。**
某规则函数对读取结果判 `None` 即返回。打开读取助手可见：缺文件时助手先登记一条违规，再返回 `None`；
助手还有「缺文件不得静默通过」的默认语义。
**判据**：先看助手的默认参数与登记顺序，再看调用点的早退。

**E3 · 所有异常映射到同一个码，不必然是缺陷。**
某组捕获全部映射到同一个「内部异常」码，头文件已声明该码含义。映射是诚实的 —— 真实缺陷在别处（清理缺失）。
**判据**：核对该码的**声明含义**是否真的涵盖这些异常；涵盖则映射合格，清理问题另立。

**E4 · 同一个 catch 在不同调用点映射到不同码，合格与不合格取决于所选码的声明含义。**
某模块两条批量路径对同一类未知异常分别写「分配失败」与「参数非法」。
前者合格（分配失败确实涵盖内存异常），后者不合格（未知内部异常不是调用方几何非法）。
**判据**：不是看它笼统不笼统，是看所选码覆盖不覆盖真实异常集。

**E5 · 有限零值当失败态，只有在零属于合法值域时才是缺陷。**
**判据**：先确认该量的合法值域；零不在值域内且伴随明确标记时，不构成缺陷。

**E6 · 空集上的全称/存在量词是否真空，取决于夹具能否为空。**
**判据**：夹具保证非空时写法合格，但该保证必须被断言，而不是被假定。

**E7 · 结构性恒红的结论要区分「代码恒红」与「采集恒红」。**
代码层面的结论可靠，但判定点在实际复跑或读证据时以何种形态呈现，需要另行确认：
是整体报错、被静默跳过，还是根本没被触达。
**判据**：两者分别记录，不要合并成一句「永久红」。

**E8 · 解析估算出的恒红候选，必须先打开实际证据核对。**
一处判据被解析估算预测为恒红；打开仓内实际证据后，估算被证伪，判据实际为绿。
**判据**：实际证据优先于解析估算，恒红候选一律先开证据面。实验域不设运行结果归档，
该证据面是按固定 seed 复跑 `实验/` 单元的 `code/` 所得读数与实验报告正文的记载，不是落盘归档。

**E9 · 机械绑定产生的三类常见假阳性。**
lambda 的形参不是未定义名；源文件所在目录的 CMakeLists 不是唯一的注册面；两个编号相同但全名不同的测试不互相遮蔽。
**判据**：这三类在报出前各自复核一遍。

**E10 · 「某布尔量被赋初值」在循环里通常是累积标志。**
循环内初值为真、遇错置假并跳出、末尾断言 —— 这是合格写法。
**判据**：必须读完整个块再定性，不能只看初始化那一行。

**E11 · 空 catch 是否缺陷，取决于它吞掉的异常会不会改变错误域。**
已经如实记录过的重复路径再 catch 一次是合理的；吞掉会改变错误域的异常不是。
**判据**：问「这条异常被吞掉后，上层看到的失败域变了吗」。

**E12 · 枚举缺省值不等于默认值自证。**
某状态字段缺省为「无」，判据断言它等于「环境原因」—— 只要缺省值确实被赋过、且判据分支覆盖了赋值路径，这就是真判据。
**判据**：确认判据所在分支里该字段确实被写过。

## §6 整改时的选用规则

### 6.1 写新判据时

先确定这条判据要主张什么性质，再按主张的形状选模板：

| 主张的性质 | 选用 |
|---|---|
| 「某个量被某条定律约束」 | T1（解析上界）或 T6（外部标准） |
| 「某种失败能被检出」 | T13（P+N），或 T16 / T17 / T19 |
| 「这道门不是空转的」 | T14（非退化锚）+ T22（找不到即红） |
| 「前提不满足时不算通过」 | T26（fail-closed 前置） |
| 「失败路径诚实」 | T2 / T3（哨兵政策）+ T7–T11（错误域分类） |
| 「注入没生效不能算过」 | T20 / T23 |
| 「某个放行保证没被放宽」 | T24 |
| 「声明与事实一致」 | T4 / T5 |

选定之后，**必须同时**满足 §1.1–§1.5 五条。模板只提供骨架，五条要求要逐条在实现里落实。

### 6.2 改旧判据时

**先在同一个文件里找已经写对的那一段。** 这是成本最低、争议最小的改法：把正确写法搬过去，而不是重新设计。
仓内「同文件内已有正确写法、邻近处漏改」是最高频的缺陷形态 —— 它说明缺陷是漏，不是不会。

只有当邻近处找不到正确写法时，才需要引入新模板；引入时按 §6.1 选。

### 6.3 三条不可替代的原则

**期望值独立不可用调阈值替代。** 两侧同源时，收紧或放宽阈值都不产生判别力；必须把其中一侧换成外部参考。

**结构性恒真应当如实声明，不要删也不要假装。** 按 T15 的写法：写明在什么配置下恒成立，并指名哪一处改动会让它变红。
这样它仍然承担「配置一旦放宽就立刻拦下」的作用。

**零证据应当报零证据，不应当通过。** 按 T23：注入未生效、目标未找到、前提不满足，都必须显式失败并说明原因，
而不是跳过或放行 —— 跳过与放行会让「没有验证」在报告里长得像「验证通过」。

### 6.4 推广纪律

**模板按判据推广，不按文件推广。** 同一个文件内部，正确的写法和硬编码 PASS 的写法经常并存；
文件级的「已整改」不构成判据级的合格。

**新增判据必须同时新增接线。** 裁决要接到退出码、事件 severity、manifest status 之一，
或接到读到它并据此行动的审核者；只写进产物字段而无人读取的，是记录不是判据。

**阈值必须可追溯到四处之一**：外部标准、冻结合同文件、手工推导的界、另一次运行的实测。
其余来源的阈值一律重写，并按 M13 / M16 纳入批量排查。

**每条判据要能说出它上一次红是什么时候、因为什么。** 答不上来的，说明它是恒真或者阈值无出处。
