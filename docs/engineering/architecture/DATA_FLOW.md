# ACSD 数据流、执行模型与线程预算

本文依据最高设计[1]和系统架构[2]，说明每个阶段消费与产出的数据、执行载体、取消与错误，以及线程预算的来源和分配。命名块字段和阶段调度机制由对应合同规定[3–4]。

## 载体

同阶段目标为 Runtime 管理的 typed 对象/数组块；科学 spill/cache 显式登记且 OFF/ON 相同；当前节点间 output_dir 文件约定是需迁移的实现状态。跨阶段只经磁盘产品与 manifest，不共享内存。字段与生命周期见命名块合同[3]；Normalize 具体边和迁移见阶段数据合同[8]。

## normalize 的数据流

| 方向 | 数据对象 | 形态 |
|---|---|---|
| 输入 | 亮场帧 + 母版校准帧（偏置/暗流/平场） | FITS / XISF，经统一 I/O 边界读入 |
| 输入 | 运行配置（滤镜、精度模式、落盘形态、块级 `output_dir`） | JSON |
| 中间 | 校准像素面、有效与坏点掩膜、背景与噪声面、权威 WCS、星点绑定行、PSF 模型、测光归一化后的像素面、帧级与稀疏信噪比 | 目标为 typed payload；当前正式工作文件仍有消费者；科学 cache 不受 DEV_MODE 控制，快照只旁路 |
| 输出 | 逐帧 signal HiPS + frame_science.json；有来源的辅助层可选 | 磁盘产品 + manifest + 哈希 |
| 输出 | 结构化 JSON（声明产物路径与必需字段，可显式组装为 `mosaic` 输入；输出清单不自动等同完整运行配置） | JSON |

测光输出按真实响应和标度状态声明单位，不一律称原生 ADU 或绝对物理通量。目标是在 photometry 施加一次标度，noise 与 Drizzle 消费同版本 PhotoAppliedPlane；科学 spill 由 Runtime 预算决定，与开发构建开关无关。


## mosaic 的数据流

| 方向 | 数据对象 | 形态 |
|---|---|---|
| 输入 | 一组合同兼容的 `normalize` HiPS 产品树及其运行清单 | 磁盘产品 |
| 中间 | 参考精度重建、面亮度精度传递、重叠图、背景控制与差模、排异后样本和支持 | 目标由阶段 Runtime 管理；当前文件约定按真实消费者迁移 |
| 工作持久化（可选） | 正式背景模型/cache 或开发诊断 | 身份分开；开发数据不供科学消费者取数 |
| 输出 | 仅一个 signal 科学图像通道的马赛克 HiPS + 运行清单 | 标准 HiPS 元数据与层级 + manifest + 哈希 |

相对天空的模型、连通分量规范与低频保真由天空正本[9]定义。参考通量精度、面亮度精度和背景控制方差分别表达；通带、PSF 与乘性失配单独报告。支持度、方差与权重可在阶段内使用，不成为最终第二层图像。

## export 的数据流

| 方向 | 数据对象 | 形态 |
|---|---|---|
| 输入 | 合同兼容的单 signal HiPS 及 manifest（只读），不限定来自哪个阶段 | 磁盘产品 |
| 中间 | properties 读取结果、目标投影 WCS、重采样后的子块 | 单节点执行期的内存对象；节点间交换面是 `output_dir` 文件约定 |
| 输出 | 普通二维 WCS FITS signal，继承有效响应与单位 | 磁盘产品 + 运行/校验记录 |

Export 按声明核重采样，不从 signal 制造缺失的方差或协方差。独立 WCS、通量与 PSF 检验范围由投影科学正本[10]规定。

## 完成判定

运行清单列出预期帧、实际产品、失败/取消与能力状态；产品完整性不等于科学精度已验证。检查命令与退出码以 CLI 协议[11]的实际接口为准。

## 串行与并行分层

以下执行形态需与实际实现逐项核对，不表示所有节点已完成统一租约迁移或取得并发等价实测。

| 路径 | 切分单位 | 最大并发 | 调度器 | 同步点 |
|---|---|---|---|---|
| `normalize` 校准 | 逐像素单层循环 | 运行时租约 | OpenMP parallel for（static） | 节点完成后发布输出；循环同步按实际指令核对 |
| `normalize` drizzle | 逐源像素候选（确定性条带分片） | 运行时租约 | OpenMP + 缓存 | 按条带索引升序左折叠归约 |
| `mosaic` 采样器 | 逐控制格 | 运行时租约 | 标准线程池 | 格屏障 |
| `mosaic` 信号面求解 | 全图；逐观测权重行 | 主迭代 1；权重取租约 | 主迭代串行；权重逐调用线程池 | 无 |
| `mosaic` 逐块 / 排异 / 集成 | 逐块（动态认领） | 运行时租约 | 逐块并行原语 | 无屏障，跨任务零浮点归约 |

## 锁、原子与 I/O 串行

| 共享对象 | 原语 | 粒度 |
|---|---|---|
| 读路径 | 无进程级互斥量 | 每次调用独立句柄，句柄线程私有、不跨线程转移；剩余串行化点统一走计数式锁守卫，等待时间计入资源时序工件的 `lock_wait_ns` 列 |
| 拒绝计数 | 原子量 | 逐样本 |
| drizzle 计数器 | 原子量；浮点归约用逐条带暂存累加加条带索引升序左折叠 | 逐块 |
| 稠密缓存 | 互斥量 | 逐写 |
| 内存预算 | 原子计数器 | 逐分配 |

HiPS reader 的目标是每个 worker 使用独立数据集句柄，不跨线程并发操作同一句柄；共享句柄只能串行访问。当前实现是否采用逐调用打开或 worker 内复用，应核对具体 AIO reader，不能由 CFITSIO 内部锁推断宿主句柄可安全共享[5]。

## 取消、超时与异常

| 项 | 语义 |
|---|---|
| 编排器取消 | 原子标志，退出码 9（用户取消或超时），检查点在节点之间 |
| 信号处理 | 处理程序设置取消标志，当前块完成即退 |
| 超时 | 阶段配置 `timeout_ms`，超时同取退出码 9；取消与超时同码，不另设超时码 |
| 异常传播 | C ABI 边界捕获并转为返回码，无异常跨动态库 |

## 确定性与嵌套并行

| 约束 | 规则 |
|---|---|
| 浮点求和顺序 | 按输入索引固定顺序，归约方式在算法正本登记 |
| 输入顺序 | 帧标识、格索引、像素索引固定，不依赖线程调度 |
| 内核嵌套并行 | 科学内核的并行区内不再启动另一层并行区；帧任务与帧内轴按同一调度预算分配，后台服务另计资源 |

浮点归约顺序冻结是结构性不变量，判据是事前冻结的浮点容差；两者不可互换。比较配置与适用域由测试标准规定[12]；ULP通用下限和归约界疑点另行记录，不由该句保证所有算法满足。

## 线程预算的唯一来源

- worker 数由机器画像和全局预算对象解析；无有效画像使用已声明的保守基线，不能因缺画像拒绝合法输入。可用 CPU 取亲和性、cgroup 与作业对象的交集，不是机器总核数。
- 预算按阶段 → 工序 → 内核层级显式分配，任何时刻活动 worker 之和不超过预算。
- 预算对象承载调用方从预算借到的值，不是 worker 数的第二来源。
- 后端线程池与模块内 OpenMP 线程数一律经宿主回调注入（由预算派生），与模块内直接设定线程数无关。
- 分配策略区分CPU计算、I/O和后台服务；CPU内核不超过租约与内核块提示，I/O池/队列按独立有界预算执行并纳入进程观测。当前AIO有多worker发布尾部实现，不能用“异步I/O恒1线程”的旧描述代替实际路径。

预算对象字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `cpu_workers` | int | 无默认，由机器画像与全局预算对象注入 | CPU worker 数；0 表示自动，由画像与预算对象决定 |
| `io_workers` | int | 同上 | I/O worker 数；0 表示自动 |
| `deterministic` | bool | true | 固定种子、顺序与归并以得到可复现结果 |
| `memory_budget_bytes` | uint64 | 0 | 内存预算字节数；0 表示由 `memory_limit_mb` 决定 |

命令行面不接受 worker 数或确定性旗标：预算由机器画像与全局预算对象给出，不由命令行覆盖。工具面的 worker 旗标供分阶段调试与基准使用，不进发布安装面。GPU 路由开关与第二个可执行入口不在合同面内。

## 并行轴分配

`normalize` 各节点有两个可独立分配的并行轴：**帧级**（同时处理几帧，受内存闸门约束）与**帧内**（每帧几条线程，受线程预算约束）。两轴按乘积分配，乘积是同时真正在算的线程数，必须不超过运行时租约给出的线程预算。

```text
in_flight = min(n, frame_workers) // frame_workers = min(lease, 内存闸门上限)
inner_omp = max(1, thread_budget / in_flight) // thread_budget = lease
总并行度 = in_flight × inner_omp ≤ thread_budget
```

变量取义：`n` 是本次运行的帧单元数（对照实验中按帧计档时写作 `n_units`）；`lease` 是调度器注入该节点的线程租约，唯一解析面是调度器的 `node_thread_budget`；`frame_workers` 是帧级轴的上限，取租约与内存闸门上限的较小者；`thread_budget` 是租约本身；`in_flight` 是同时在算的帧数；`inner_omp` 是每帧的帧内线程数。此分配式适用于 `n ≥ 1`、正租约且内存允许至少一帧的情况；空输入或连一帧也无法容纳时由输入与资源处理给出明确状态，不计算零分母。除法按整数除法取下限，`max(1, …)` 保证帧内轴至少 1。内存上限 `cap = floor(MemAvailable × kP1FrameMemSafetyFrac / (W×H×B/px))`，其中 `MemAvailable` 是运行时可用内存读数，`W`、`H` 是单帧像素宽高，`B` 是每像素字节数的标定值，`kP1FrameMemSafetyFrac` 是安全系数；系数的数值源、落点与标定口径见性能模型[7]。帧级宽度因内存或输入帧数低于租约时，具备并行能力的内核可使用剩余帧内预算。

当内存允许 `frame_workers = lease` 且 `n ≥ lease` 时，`in_flight = lease`，本式给出 `inner_omp = 1`。当 `n < frame_workers` 时，即使内存未限制帧轴，也须按 `in_flight = n` 分配帧内预算。只有 `n ≥ frame_workers` 时，才能写成 `I = max(1, L / F)`，其中 `I = inner_omp`、`L = lease`、`F = frame_workers`。预算分配式本身不证明数值等价，仍需对应运行对照。

**暂存池对有效宽度的限制**：drizzle 投影内每帧的暂存槽上限为 `K`。内核线程数足以承接帧内预算时，模型为 `W_eff = in_flight × min(inner_omp, K)`。若内核另受 `num_threads` 限制，则有效帧内宽度取三者的最小值。达到预算帧内宽度要求 `K ≥ inner_omp` 且 `num_threads ≥ inner_omp`；按此槽数模型，所需最小整数 `K` 为 `inner_omp`，更大取值不再增加该模型的宽度。该式只描述预算与暂存容量，实际忙碌率、内存和耗时仍需实测；参数来源与适用域见[7]。

口径统一：本节两轴式与「活动 worker 之和不超过预算」是同一预算的两种陈述。单个科学内核内部的并行度就是帧内轴，内核内只有这一个并行区。三命令各自独立进程，线程预算不跨命令、不跨阶段共享。

帧级并发可重叠读写、星表查询和求解等串行段，帧内并发用于具备并行能力的内核。实际速度、内存与有效宽度由同二进制、同输入受控对照确定，不把某次趋势写成任意数据域的单调规律。

## 节点内并行度的解析面

节点线程预算的唯一解析面是调度器的 `node_thread_budget`：

1. 调度器注入的租约（节点配置的 worker 数）存在时以它为准，只收紧不放大；显式值 1 表示串行参考路径，非数值输入收敛为显式串行。
2. 租约不存在时（直接调用节点的非调度路径：工具面直调、单元、集成）取进程有效 CPU 预算，即进程注入的可用核（亲和性与 cgroup 的交集），未注入时现算同一口径 `min(可用核, 配置上限)`；缺省不是 1。

理由：快慢不得建立在使用方是否传参之上。

## 浮点归约顺序的冻结锚点

- **mosaic 背景控制归约**：控制观测按固定观测索引归约；若实现分阶段归一，须分别固定每一步的求和顺序。控制字段见工件合同[13]，其科学统计含义由天空正本[9]规定；背景控制逆方差不等于参考点源或最终面亮度的逆方差。
- **mosaic 采样器**：worker 数只来自运行时租约；格由原子取号动态领取，结果写回固定槽位，归约顺序与线程调度无关。
- **drizzle 浮点归约**：主并行区用逐条带暂存累积（无浮点 reduction 子句）；块合并是逐条带暂存池加按条带索引升序左折叠归约，累加与归约解耦，浮点结合树与线程数、调度顺序无关。整数计数器统计不作为浮点归约锚。

## 并发度对照的可复现性

任何「并发度 A 与 B」的对照必须同时满足四条，缺一即不成立：

1. **固定资源**：固定可用 CPU、租约与内存预算，记录生效限制；预算估计变化单独研究，不为取得并发档位任意改变内存安全标定。
2. **固定二进制**：使用同一可执行文件与动态库，并记录实际文件哈希及构建来源；`source_sha` 或 `build_source_digest` 相等均不能单独证明产物字节相同。
3. **记生效值并按 `in_flight` 判档**：从分配快照取实际值，档位判据是 `in_flight = min(n_units, frame_workers)`，不是 `frame_workers`；帧轴与帧内轴必须分开立论。
4. **重复对照**：同并发、同二进制重复运行，测量运行波动；科学数值按预定义容差比较，时间戳等运行元数据单独处理。

执行结论需链接对应实验的输入、命令与输出；本文的分配式不替代并发等价实验。

若内存上限来自瞬时可用量而非实际预留，应在受控运行中核对峰值工作集和其它进程竞争，不能仅凭估计式宣称无超预算风险。

## 异步与取消

- **工作流与内核分开编排**：Normalize 可由调度器异步启动依赖已满足的帧内节点和独立帧工作流；内核计算使用明确预算下的并行区，不私建 async/future/promise 链或嵌套线程池[4,6]。I/O 预取与写出可通过有界流水线重叠。
- **队列必须同时具备容量上限、背压、取消、超时与错误传播五要素**，不使用无界队列；队列合同见[5]。
- **取消**：取消请求经令牌或原子标志传到各内核安全点；等待在途任务停止并释放对象后归还租约，关闭 writer，隔离未完成产品并记录 incomplete manifest[11]。不在任务仍访问缓冲时提前回收资源。

## 使用约定

- 模块仅通过预算对象读取已分配预算，生效值由 `effective_cpu_workers(exec)` 与 `effective_io_workers(exec)` 返回。
- 嵌套模块复用同一预算；嵌套模块新建等规模线程池即越界。
- 异步队列容量由 `memory_budget_bytes` 推导。
- 实现与合同不符时记录具体位置、行为和影响，按现行设计修复；不把登记状态设为运行审批条件。
