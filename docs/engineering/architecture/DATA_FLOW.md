# ACSD 数据流、执行模型与线程预算

本文是 `docs/engineering/` 的数据流与执行正本，回答三件事：每个阶段消费与产出什么数据、以什么载体流动；运行时怎么切分并行、怎么管取消与错误；线程预算从哪来、按什么轴分配。命名块的字段合同见 `../contracts/PIPELINE_BLOCK.md`，三阶段调度机制见 `../contracts/SCHEDULER.md`。

## 载体

| 载体 | 范围 | 形态 | 规范依据 |
|---|---|---|---|
| 命名块（`PipelineFrame`） | 单节点执行期 | 内存对象，带冻结元数据（名字、形状、类型、单位、可缺性、生产者、消费者、生命周期） | `../contracts/PIPELINE_BLOCK.md` |
| 阶段内文件约定 | 同阶段节点之间 | `output_dir` 下的具体产物（文件或产品目录），生产者写、消费者按同一路径读 | `../contracts/PIPELINE_BLOCK.md` 载体合同 |
| HiPS 产品树 | 跨阶段 | 磁盘目录 + manifest + 哈希 | `../contracts/HIPS_STORAGE_FORM.md` |
| 运行配置 | 阶段入口 | JSON 块列表，每块一个块级 `output_dir` | `../contracts/CONFIG.md` |

跨阶段流转的载体只有 HiPS 产品树；阶段内节点的交换面是 `output_dir` 文件约定，不是命名块。

## normalize 的数据流

| 方向 | 数据对象 | 形态 |
|---|---|---|
| 输入 | 亮场帧 + 母版校准帧（偏置/暗流/平场） | FITS / XISF，经统一 I/O 边界读入 |
| 输入 | 运行配置（滤镜、精度模式、落盘形态、块级 `output_dir`） | JSON |
| 中间 | 校准像素面、有效与坏点掩膜、背景与噪声面、权威 WCS、星点绑定行、PSF 模型、测光归一化后的像素面、帧级与稀疏信噪比 | 单节点执行期的内存对象；节点间交换面是 `output_dir` 文件约定 |
| 输出 | 逐帧 HiPS 产品树（signal / support / variance / ivar / 可选稀疏信噪比标准层） | 磁盘产品 + manifest + 哈希 |
| 输出 | 结构化 JSON（声明产物路径与必需字段，符合 `mosaic` 输入格式） | JSON |

测光输出语义：产物通量处于逐帧相对测光零点的线性面亮度；测光归一化在 `measure_flux` 同一步内施加到像素，不落中间面。

## mosaic 的数据流

| 方向 | 数据对象 | 形态 |
|---|---|---|
| 输入 | 一组合同兼容的 `normalize` HiPS 产品树及其运行清单 | 磁盘产品 |
| 中间 | 覆盖重叠图、控制采样点与其逆方差、公共天光面与逐帧偏差、归一化后的样本面、逐像素排异结果与服务支撑度 | 单节点执行期的内存对象；节点间交换面是 `output_dir` 文件约定 |

天光平面的模型语义（加性天光面加逐帧偏差、`calibrated = raw − δ_k`、保留公共天光面）正本在 science 分册；排异与集成的数据对象语义（逐像素按几何可贡献帧数路由、逆方差加权、支撑度归约）正本在 science 分册的排异与集成卷。

## 完成判定

每个阶段的输出以运行完成清单为交付判据。机器可核入口是 `acsd doctor --run-manifest <manifest.json>`，命令与退出码语义见 `../contracts/CLI_PROTOCOL.md`。

## 串行与并行分层

| 路径 | 切分单位 | 最大并发 | 调度器 | 同步点 |
|---|---|---|---|---|
| `normalize` 校准 | 逐像素单层循环 | 运行时租约 | OpenMP parallel for（static） | 无屏障、无块级同步点 |
| `normalize` drizzle | 逐源像素候选（确定性条带分片） | 运行时租约 | OpenMP + 缓存 | 按条带索引升序左折叠归约 |
| `mosaic` 采样器 | 逐控制格 | 运行时租约 | 标准线程池 | 格屏障 |
| `mosaic` 天光面求解 | 全图；逐观测权重行 | 主迭代 1；权重取租约 | 主迭代串行；权重逐调用线程池 | 无 |
| `mosaic` 逐块 / 排异 / 集成 | 逐块（动态认领） | 运行时租约 | 逐块并行原语 | 无屏障，跨任务零浮点归约 |

## 锁、原子与 I/O 串行

| 共享对象 | 原语 | 粒度 |
|---|---|---|
| 读路径 | 无进程级互斥量 | 每次调用独立句柄，句柄线程私有、不跨线程转移；剩余串行化点统一走计数式锁守卫，等待时间计入资源时序工件的 `lock_wait_ns` 列 |
| 拒绝计数 | 原子量 | 逐样本 |
| drizzle 计数器 | 原子量；浮点归约用逐条带暂存累加加条带索引升序左折叠 | 逐块 |
| 稠密缓存 | 互斥量 | 逐写 |
| 内存预算 | 原子计数器 | 逐分配 |

HiPS 读路径的线程模型：每次调用各自打开、读取、关闭，句柄只活在调用栈帧内；句柄表与错误栈由 CFITSIO 自带的 `Fitsio_Lock` 保护，只读打开走已有打开检测直接返回、不复用句柄。

## 取消、超时与异常

| 项 | 语义 |
|---|---|
| 编排器取消 | 原子标志，退出码 9（用户取消或超时），检查点在节点之间 |
| 信号处理 | 处理程序设置取消标志，当前块完成即退 |
| 超时 | 阶段配置 `timeout_ms`，超时同取退出码 9；取消与超时同码，不另设超时码 |
| 异常传播 | C ABI 边界捕获并转为返回码，无异常跨动态库 |

## 确定性与嵌套并行

| 约束 | 规则 |
|---|---|
| 浮点求和顺序 | 按输入索引固定顺序，归约方式在算法正本登记 |
| 输入顺序 | 帧标识、格索引、像素索引固定，不依赖线程调度 |
| 嵌套并行 | 外层已并行时内层串行；唯一豁免是看门狗线程（独立预算） |

浮点归约顺序冻结是结构性不变量，判据是事前冻结的浮点容差；两者不可互换。容差数值与可满足性下限的正本在 `../testing/TEST.md` 的通用容差规则。

## 线程预算的唯一来源

- worker 数只来自 benchmark 生成的机器画像与全局预算对象。可用 CPU 取亲和性、cgroup 与作业对象的交集，不是机器总核数。
- 预算按阶段 → 工序 → 内核层级显式分配，任何时刻活动 worker 之和不超过预算。
- 预算对象承载调用方从预算借到的值，不是 worker 数的第二来源。
- 后端线程池与模块内 OpenMP 线程数一律经宿主回调注入（由预算派生），与模块内直接设定线程数无关。
- 分配策略：串行 I/O 与控制面恒 1 线程；CPU 内核获得 `min(预算, 内核块提示)`；异步 I/O 流水线恒 1 专用线程；后台服务（看门狗、资源监控、进度日志）恒 1 线程加独立小预算，不入科学预算池。

预算对象字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `cpu_workers` | int | 无默认，由机器画像与全局预算对象注入 | CPU worker 数；0 表示自动，由画像与预算对象决定 |
| `io_workers` | int | 同上 | I/O worker 数；0 表示自动 |
| `deterministic` | bool | true | 固定种子、顺序与归并以得到可复现结果 |
| `memory_budget_bytes` | uint64 | 0 | 内存预算字节数；0 表示由 `memory_limit_mb` 决定 |

命令行面不接受 worker 数或确定性旗标：预算由机器画像与全局预算对象给出，不由命令行覆盖。工具面的 worker 旗标供分阶段调试与基准使用，不进发布安装面。GPU 路由开关与第二个可执行入口不在合同面内。

## 并行轴分配

`normalize` 各节点有两个可独立分配的并行轴：**帧级**（同时处理几帧，受内存闸门约束）与**帧内**（每帧几条线程，受线程预算约束）。两轴按乘积分配，乘积是同时真正在算的线程数，必须不超过运行时租约给出的线程预算。

```text
in_flight = min(n, frame_workers) // frame_workers = min(lease, 内存闸门上限)
inner_omp = max(1, thread_budget / in_flight) // thread_budget = lease
总并行度 = in_flight × inner_omp ≤ thread_budget
```

变量取义：`n` 是本次运行的帧单元数（对照实验中按帧计档时写作 `n_units`）；`lease` 是调度器注入该节点的线程租约，唯一解析面是调度器的 `node_thread_budget`；`frame_workers` 是帧级轴的上限，取租约与内存闸门上限的较小者；`thread_budget` 是租约本身；`in_flight` 是同时在算的帧数；`inner_omp` 是每帧的帧内线程数。除法按整数除法取下限，`max(1, …)` 保证帧内轴至少 1。内存闸门上限 `cap = floor(MemAvailable × kP1FrameMemSafetyFrac / (W×H×B/px))`，其中 `MemAvailable` 是机器画像给出的可用内存，`W`、`H` 是单帧像素宽高，`B` 是每像素字节数的标定值，`kP1FrameMemSafetyFrac` 是帧级内存闸门安全系数；两个系数的唯一数值源、落点与取值口径见 `../resources/PERFORMANCE_MODEL.md`，本式不复述其取值。闸门把帧级轴压到远低于租约时，帧内轴仍固定为 1 会让 CPU 预算空转，因此帧级被压低时剩余预算必须转给帧内轴。

不变式：帧级宽度未被内存压低时本式退化为 `inner_omp = 1`，即该分配只改变预算怎么用，不改变任何节点的数值路径。当帧单元数 `n ≥ frame_workers` 时 `in_flight = frame_workers`，上式等价于 `I = max(1, L / F)`，其中 `I = inner_omp`、`L = lease`、`F = frame_workers`；`n < frame_workers` 时必须回到 `min(n, frame_workers)` 的原式，两条不可互换。

**有效宽度的第三个因子**：drizzle 投影内部的暂存池上限 `K` 会把帧内轴再截一次，`W_eff = in_flight × min(inner_omp, K)`；`K` 是暂存池份数上限，`num_threads` 是 drizzle 投影内核拿到的线程数，`W_eff` 是实际同时在算的线程数。由 `min(inner_omp, K)` 对 `K` 单调不降可知，`W_eff` 达到帧内轴宽度 `in_flight × inner_omp` 当且仅当 `K ≥ inner_omp`；`K < inner_omp` 时多余线程在暂存池上空等。因此 `K` **没有唯一最小取值**：可行区间内的任一取值给出同一满宽，总份数在该区间内不变。`K` 的实际生效值还被内核的 `min(num_threads, K)` 截断，故达成满宽的充要条件是 `min(num_threads, K) ≥ inner_omp`；把 `K` 取成 `num_threads` 只是其中一条充分条件，其来源链、适用域与算例由资源正本给出[7]，本节不复述。

口径统一：本节两轴式与「活动 worker 之和不超过预算」是同一预算的两种陈述。单个科学内核内部的并行度就是帧内轴，内核内只有这一个并行区。三命令各自独立进程，线程预算不跨命令、不跨阶段共享。

**分配形态的结论**：不采用「一帧独占全部核心」。在有效宽度恒定的同二进制受控对照下，帧在飞数越少则墙钟单调变差、CPU 占用单调变低、内存单调变省。根因是每帧都有不可并行的串行段（FITS 读、产品写出与球面重采样在帧内串行、星表查询、天体定位节点无帧级并行），帧级并发正是把这些串行段互相重叠的手段。分配式的改动依据是实验域的收益记录。

## 节点内并行度的解析面

节点线程预算的唯一解析面是调度器的 `node_thread_budget`：

1. 调度器注入的租约（节点配置的 worker 数）存在时以它为准，只收紧不放大；显式值 1 表示串行参考路径，非数值输入收敛为显式串行。
2. 租约不存在时（直接调用节点的非调度路径：工具面直调、单元、集成）取进程有效 CPU 预算，即进程注入的可用核（亲和性与 cgroup 的交集），未注入时现算同一口径 `min(可用核, 配置上限)`；缺省不是 1。

理由：快慢不得建立在使用方是否传参之上。

## 浮点归约顺序的冻结锚点

- **mosaic 天光面权重归一**：两阶段——分子 `raw_w = quality_factor × control_ivar` 冻结后，再按控制的 `sums[ck]` 做 per-control 归一化（该步另乘几何可靠性因子）；遍历顺序为观测索引的固定顺序。权重公式本身以 `../data/ARTIFACTS.md` 为准，本节只冻结归约顺序，不复述权重公式。
- **mosaic 采样器**：worker 数只来自运行时租约；格由原子取号动态领取，结果写回固定槽位，归约顺序与线程调度无关。
- **drizzle 浮点归约**：主并行区用逐条带暂存累积（无浮点 reduction 子句）；块合并是逐条带暂存池加按条带索引升序左折叠归约，累加与归约解耦，浮点结合树与线程数、调度顺序无关。整数计数器统计不作为浮点归约锚。

## 并发度对照的可复现性

任何「并发度 A 与 B」的对照必须同时满足四条，缺一即不成立：

1. **钉住**：用 CPU 掩码钉住可用核，使租约确定；需要更高的内存闸门上限时下调标定值 `kP1FrameBytesPerPixel`（它只是闸门旋钮，不进任何数值路径），改标定值等于改源码，必须重新记录构建指纹。
2. **判同一二进制**：以 `build_source_digest` 相等为前提；`source_sha` 相等不构成前提。
3. **记生效值并按 `in_flight` 判档**：从分配快照取实际值，档位判据是 `in_flight = min(n_units, frame_workers)`，不是 `frame_workers`；帧轴与帧内轴必须分开立论。
4. **负对照**：同并发、同二进制的重复运行必须逐字节零差异，否则该对照无判别力。

按上述四条执行的结果：同一二进制、同一帧集，只变 `in_flight` 与 `inner_omp` 时全部 FITS 与必同 JSON 逐字节相同，组级星表聚合也逐字节相同，即帧级并发与帧内并发都不改变科学产品。

残留风险：内存闸门上限是瞬时快照而非预留，无交换内存的机器上目标配置的峰值驻留集接近安全垫上限。

## 异步与取消

- **异步只有两类**：I/O 流水线（读写双缓冲）与后台服务。科学计算路径不使用异步执行或 promise 链，不嵌套并行。
- **队列必须同时具备容量上限、背压、取消、超时与错误传播五要素**，不使用无界队列；队列契约见 `../contracts/ASYNC_IO.md`。
- **取消**：命令行事件流发出取消 → 全局原子取消标志 → 各内核取消点；取消后预算立即回收，取消单元不落盘。

## 使用约定

- 模块仅通过预算对象读取已分配预算，生效值由 `effective_cpu_workers(exec)` 与 `effective_io_workers(exec)` 返回。
- 嵌套模块复用同一预算；嵌套模块新建等规模线程池即越界。
- 异步队列容量由 `memory_budget_bytes` 推导。
- 实现面与本文件条款的偏差逐条登记，不得静默；未登记的偏差按判红处理。
