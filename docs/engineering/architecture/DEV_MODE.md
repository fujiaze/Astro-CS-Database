# 开发模式与构建期能力边界

## 为什么需要一条边界

ACSD 的科学产物是帧级 HiPS 产品树与结构化 JSON：单帧标准化只把校准后的像素面写成球面产品，节点之间通过内存管线传递像素面与辅助量。开发期间，为了逐节点复核、复算与性能剖析，需要在磁盘上留下中间图像、检查点与探针读数；发布版本不需要这些，也不应把它们编进二进制。

这条边界是**构建期**的，不是运行期配置：同一个能力要么在二进制里，要么不在。把它做成运行期开关会让发布版带着一整套只在开发期有意义的分支，使行为难以归因、产物难以判定。

## 开关

一个主开关与三个子开关，子开关默认跟随主开关：

```cmake
option(ACSD_DEV_MODE              "开发模式：启用中间产物落盘/检查点/探针（发布版 OFF）" OFF)
option(ACSD_DEV_INTERMEDIATE_CACHE "开发模式子项：中间产物落盘" ${ACSD_DEV_MODE})
option(ACSD_DEV_CHECKPOINT         "开发模式子项：检查点与续跑" ${ACSD_DEV_MODE})
option(ACSD_DEV_PROBES             "开发模式子项：性能探针"     ${ACSD_DEV_MODE})
```

主开关默认关闭，子开关取主开关的值。发布打包以 `-DACSD_DEV_MODE=OFF` 构建；开关通过 `target_compile_definitions` 传播到对应目标，各能力以编译期条件包裹。

**开关的授权边界只有一条**：开关决定**中间产物是否额外打印/落盘**，**不得改变执行路径**。同一个输入在开关的两种取值下必须走同一条计算路径、读同一份数据、给出同一份结论；唯一的差别是磁盘上多或少几份复核用的中间件。凡"关掉开关就走另一条路"（改用别的数据来源、或改变流程存续）都属越权，按缺陷处置。

## 覆盖的能力

**帧级平面产物落盘**。校准面、清理面、坏列掩膜与测光施加面（`calibrated_`、`cleaned_`、`badcol_`、`badcolsrc_`、`photoapplied_`）只作**额外输出**：供逐节点复核与复算，**不参与任何取数路径**，也**不属于产品面**。它们落在产品面之外的工作区（见「中间产物的工作区与开关」）。内存块传递是性能阶段的目标。

**检查点与续跑**。记录每帧已完成的阶段，使中断后可按帧粒度跳过已完成的整帧、只重跑未完成的整帧。

**性能探针**。低开销的运行时探针，用于资源与时序剖析。

## 标准模式下的产物面

**标准模式的产物只有两项**：**逐帧 HiPS 产品树**与**一个阶段二输入 JSON**。两次运行之间的交换只通过这两项（以及运行级 manifest）发生。阶段一内部节点之间交换的像素面与辅助量**不是产物**：它们应落在**产品面之外的工作区**（见下节），标准模式运行结束后不留在产品树内。**内存块传递是性能阶段的目标**。

**逐帧 JSON 是调试输出，不是产物**。`p1_wcs.json`、`p1_sources.json`、`p1_phot.json`、`p1_snr.json`、`p1_psf.json`、`p1_flux.json`、`p1_final.json` 等不应出现在产品面内；它们是阶段一内部依赖边的载荷，与帧级平面件同属工作区。开关只决定这些额外输出**是否保留**（保留供复核 vs 运行结束即清理）。依赖边的载体改为内存块承载后，调度器按端口名注入与取用，节点顺序的保证不再依赖文件落盘；该改造属**性能阶段**。

**`p1_stack.json` 属跨进程契约，不是调试输出**。它写在逐帧 HiPS 产品树内，阶段二在**另一个进程**中读取其中的 `finest_input_arcsec` 以导出天光面节点几何。凡跨阶段交换的内容都属 HiPS 产品树与阶段二输入 JSON 的契约面，**不随本开关关闭**。

**平台与构建形态宏**（共享库导出、异常模型、CFITSIO 锁统计等）与开发模式无关，不随本开关变化。

## 中间产物的工作区与开关

**产品面与工作区的边界**。产品面（输出目录中被视作产品的那部分）**只应含**逐帧 HiPS 产品树与阶段二输入 JSON；其余中间产物——帧级平面件与逐帧 JSON——落在**工作区**。工作区在产品面**之外**（同级兄弟目录，与产品目录同文件系统以保持落盘的原子替换语义），运行结束即按开关决定是否保留。运行级 manifest、资源读数与调度图属运行记账，与本节的开发期额外输出分开处置。

**开关语义**。开关只决定中间产物**是否保留**（保留到工作区供逐节点复核与复算 vs 运行结束即删），**不改变执行路径、不改变任何数值与判据、不改变节点顺序**。产品面内不得因开关取值而出现或消失文件。

**取数保持现状**。同进程内的写后读回（热路径）本步保留：写、读位置一并移出产品面，取数机制不变。把取数改为内存块是**性能阶段**的独立项，不属本节。

## 运行前检查与中间产物

输入面在运行前校验，运行期间不再需要中间产物校验。输入面包含两类：观测亮场，以及母版校准帧（偏置、暗流、平场）。对它们的要求是存在、匹配、合法。

**已实现的部分**。合法性检查已覆盖：母版平场的有效性，母版单位与标度声明的解析，暗流约定，平场归一化键与其取值规则，平场中位区间键的形状与有序性，输入亮场清单的存在与非空，以及每帧产品目录键的唯一性。存在性同时已具备**清单式**形态：运行前把该次运行需要的校准帧逐个列出并核对，缺项即点名报出（不再只由读取失败体现）。运行前检查集中在阶段一调度适配层的 `p1_prerun_input_check`，在进入节点之前一次性执行。

**匹配检查**。校准帧（母版偏置、暗流、平场）与亮帧的**图像尺寸必须一致**。判据只有尺寸一条：不比较滤镜、增益、温度等。三面都查：母版之间、每个母版与每一帧亮帧。几何经 `aio_read_header_only` 与 `aio_get_geometry` 读取头部取得，**不加载整幅像素**；失败按数据域错误报出并落原因，错误信息点名具体文件与两侧尺寸。

**中间产物的取数与缺失判定（退役登记）**。校准面的取数路径与"产物缺失怎么办"的判定，都是"中间产物要经磁盘"这一现状的产物：产物在盘上，才需要判它在不在；才需要讨论缺了是回退、报错还是留痕。内部载荷移出产品面之后，取数路径**只保留一条**——产物存在则取之，缺失则由统一 I/O 以明确的上游错误暴露，绝不静默改用原帧，也不另设判定门。

据此，阶段一的两处实现**退役**：`p1_calibrated_path` 只保留**一条**路径（返回该产物的路径），"缺了改用原帧"的回退分支不保留；`p1_prerun_calibrated_check` 由"缺失即 fail-closed"的门改判为**不阻塞的显式诊断读数**（逐帧上报缺失，供复核），`calibrated_fell_out` 留痕不再需要。两处共用的编译期条件（`ACSD_DEV_INTERMEDIATE_CACHE`）一并删除——**同一个输入不得有第二种行为**。

**运行前合法性与「不设门禁」的关系**。运行前检查的 fail-closed 是**输入域合法性判定**（母版与亮帧不属于同一读出几何时不得继续），不是阻塞正常流程的门禁：通过的运行不被任何检查拦截，检查只产出可复核的读数与明确失败。最高设计第 13 章针对的是把正常流程挡在关卡后面的机制，两者不冲突。上一条退役的"中间产物缺失即 fail-closed"不属输入域合法性，它是产物面判定，故按退役处置。

**内存块传递的清点（性能阶段）**。取数侧的改造**不在本步范围**：本步只把中间产物的**位置**移出产品面，取数机制不变。内存块传递须处置的取数面：校准面与测光施加面的读取侧、以及四个逐帧 JSON（`p1_wcs`、`p1_sources`、`p1_phot`、`p1_snr`）的阶段一内部读回。调度器侧已有块流能力：`lib/infrastructure/scheduler/src/block_flow.cpp` 的 `set_input`、`set_input_f64`、`product`、`run_unit`。接线方式按第 13 章的复用条执行——在已有文件上暴露并使用该公开 API，**不得另写一份等价实现**；块的角色与生命周期取自该公开面，不在调用方各自约定。该改造另受两条结构约束：块流执行器按**帧**驱动而阶段一节点体按**整次运行**组织（各含帧循环与帧内并行轴），且公开 API 只装载**扁平标量缓冲**（无结构化载荷、无 F32 阶段边界注入）⇒ 它是**架构返工**，列为独立阶段。

**性能阶段的耦合登记**。内存块传递若落地，写侧门控与取数侧绑定**必须同批**，不得只做一侧。该约束**不约束本步**：本步的开关只决定工作区是否保留，产品面内容不随开关取值变化。

**发布构建可用性**。判别标准只有一条：**标准构建下中间产物不需要落在磁盘上，且同一个输入只有一种行为**。当前仓库的实际状态与目标有两处差距：① 写侧尚未门控，校准面与测光施加面仍照常落到输出目录；② 取数侧的两处判定按编译期条件分叉——定义开关时回退原帧并留痕继续，未定义时返回缺失路径并 fail-closed，**同一份配置在两种构建下得到两种行为**。因此当前**未达成**，且差距 ② 属缺陷（开关越权改变执行路径）。达成路径 = 取数侧改内存块（消除分叉）+ 写侧按开关额外输出 + 阶段二输入 JSON 接线，三者同批。

## 与数据流文档的关系

本文件定义构建期能力边界，是上位正本；数据流文档描述节点之间交换什么、以什么形态交换，其"中间量是单节点执行期的内存对象、标准模式不落盘"的措辞由本文件给出依据并指向本文件。产物命名规则只有一份实现，位于阶段一调度器适配层。
