# 开发模式与构建期能力边界

## 为什么需要一条边界

ACSD 的科学产物是帧级 HiPS 产品树与结构化 JSON：单帧标准化只把校准后的像素面写成球面产品，节点之间通过内存管线传递像素面与辅助量。开发期间，为了逐节点复核、复算与性能剖析，需要在磁盘上留下中间图像、检查点与探针读数；发布版本不需要这些，也不应把它们编进二进制。

这条边界是**构建期**的，不是运行期配置：同一个能力要么在二进制里，要么不在。把它做成运行期开关会让发布版带着一整套只在开发期有意义的分支，使行为难以归因、产物难以判定。

## 开关

一个主开关与三个子开关，子开关默认跟随主开关：

```cmake
option(ACSD_DEV_MODE              "开发模式：启用中间产物落盘/检查点/探针（发布版 OFF）" OFF)
option(ACSD_DEV_INTERMEDIATE_CACHE "开发模式子项：中间产物落盘" ${ACSD_DEV_MODE})
option(ACSD_DEV_CHECKPOINT         "开发模式子项：检查点与续跑" ${ACSD_DEV_MODE})
option(ACSD_DEV_PROBES             "开发模式子项：性能探针"     ${ACSD_DEV_MODE})
```

主开关默认关闭，子开关取主开关的值。发布打包以 `-DACSD_DEV_MODE=OFF` 构建；开关通过 `target_compile_definitions` 传播到对应目标，各能力以编译期条件包裹。

**开关的授权边界只有一条**：开关决定**中间产物是否额外打印/落盘**，**不得改变执行路径**。同一个输入在开关的两种取值下必须走同一条计算路径、读同一份数据、给出同一份结论；唯一的差别是磁盘上多或少几份复核用的中间件。凡"关掉开关就走另一条路"（改用别的数据来源、或改变流程存续）都属越权，按缺陷处置。

**实现现状（照实登记）**：四个宏里只有 `ACSD_DEV_INTERMEDIATE_CACHE` 有代码消费者（阶段一调度适配层的两处），其余三个（`ACSD_DEV_MODE`、`ACSD_DEV_CHECKPOINT`、`ACSD_DEV_PROBES`）**无任何消费者**——定义与不定义对行为没有影响。有消费者的那一处当前**越权**：它在两条分支上分别改变了取数来源与流程存续，见「运行前检查与中间产物」一节的退役登记。

## 覆盖的能力

**帧级平面产物落盘**。校准面、清理面、坏列掩膜与测光施加面（`calibrated_`、`cleaned_`、`badcol_`、`badcolsrc_`、`photoapplied_`）只作**额外输出**：写到该块的输出目录，供逐节点复核与复算，**不参与任何取数路径**。标准模式下节点之间的像素面经内存块传递。

**检查点与续跑（未实现）**。设计意图是记录每帧已完成的阶段，使中断后可按帧粒度跳过已完成的整帧、只重跑未完成的整帧。该能力在本仓**不存在**：`ACSD_DEV_CHECKPOINT` 定义后无任何代码消费者，也没有检查点写入与读回实现。本节保留为设计意图登记，**不得当作既有能力引用**。

**性能探针（未实现）**。设计意图是低开销的运行时探针，用于资源与时序剖析。该能力在本仓**不存在**：`ACSD_DEV_PROBES` 定义后无任何代码消费者。本节保留为设计意图登记，**不得当作既有能力引用**。

## 标准模式下的产物面

**标准模式的产物只有两项**：**逐帧 HiPS 产品树**与**一个阶段二输入 JSON**。两次运行之间的交换只通过这两项（以及运行级 manifest）发生；阶段一内部节点之间交换的像素面与辅助量经内存块传递，不经磁盘。

**逐帧 JSON 是调试输出，不是产物**。`p1_wcs.json`、`p1_sources.json`、`p1_phot.json`、`p1_snr.json`、`p1_psf.json`、`p1_flux.json`、`p1_final.json` 等在标准模式下不落盘；需要逐节点复核时由开关开启，写到该块的输出目录。它们当前之所以在盘上，是因为依赖边的载体仍是磁盘文件；依赖边改为内存块承载之后，调度器按端口名注入与取用内存块，节点顺序的保证不再依赖文件落盘。

**`p1_stack.json` 属跨进程契约，不是调试输出**。它写在逐帧 HiPS 产品树内，阶段二在**另一个进程**中读取其中的 `finest_input_arcsec` 以导出天光面节点几何。凡跨阶段交换的内容都属 HiPS 产品树与阶段二输入 JSON 的契约面，**不随本开关关闭**。

**平台与构建形态宏**（共享库导出、异常模型、CFITSIO 锁统计等）与开发模式无关，不随本开关变化。

## 中间产物的门控

**门控对象**：帧级平面件（校准面、清理面、坏列掩膜、测光施加面）与逐帧 JSON（`p1_wcs`、`p1_sources`、`p1_phot`、`p1_snr`、`p1_psf`、`p1_flux`、`p1_final`）的**写出侧**。它们只作额外输出，门控它们不改变任何节点的取数。

**取数侧必须先改造**：cos 节点以校准面为输入，drz 节点在逐帧判决分支中要求消费测光施加面；另有四个逐帧 JSON 被阶段一内部三至四处读回。这些边当前走输出目录的文件约定，关闭缓存后前者会失去输入、后者会直接失败。改造方向是把这些边改为内存块绑定——调度器已有块流能力（按名注入输入、按名取产物、带角色与生命周期），但阶段一节点尚未使用它，因此这是**新增接线**而非切换既有绑定。改造后取数不再依赖磁盘，且不需要在节点内复制校准或施加的实现。

## 运行前检查与中间产物

输入面在运行前校验，运行期间不再需要中间产物校验。输入面包含两类：观测亮场，以及母版校准帧（偏置、暗流、平场）。对它们的要求是存在、匹配、合法。

**已实现的部分**。合法性检查已覆盖：母版平场的有效性，母版单位与标度声明的解析，暗流约定，平场归一化键与其取值规则，平场中位区间键的形状与有序性，输入亮场清单的存在与非空，以及每帧产品目录键的唯一性。存在性同时已具备**清单式**形态：运行前把该次运行需要的校准帧逐个列出并核对，缺项即点名报出（不再只由读取失败体现）。运行前检查集中在阶段一调度适配层的 `p1_prerun_input_check`，在进入节点之前一次性执行。

**匹配检查**。校准帧（母版偏置、暗流、平场）与亮帧的**图像尺寸必须一致**。判据只有尺寸一条：不比较滤镜、增益、温度等。三面都查：母版之间、每个母版与每一帧亮帧。几何经 `aio_read_header_only` 与 `aio_get_geometry` 读取头部取得，**不加载整幅像素**；失败按数据域错误报出并落原因，错误信息点名具体文件与两侧尺寸。

**中间产物的取数与缺失判定（退役登记）**。校准面的取数路径与"产物缺失怎么办"的判定，都是"中间产物要经磁盘"这一现状的产物：产物在盘上，才需要判它在不在；才需要讨论缺了是回退、报错还是留痕。标准模式下节点之间经**内存块**交换像素面，中间产物不经磁盘，因此**回退与缺失判定都不存在**——上游节点要么已经把块交出来，要么本节点没有输入可消费；两种情形都不需要第二条路径。

据此，阶段一当前的两处实现**退役**：`p1_calibrated_path` 只保留**一条**路径（取该块的产物），"缺了改用原帧"的回退分支与 `calibrated_fell_out` 留痕都不保留；`p1_prerun_calibrated_check` 的"缺失即 fail-closed"判定同样不保留。两处共用的编译期条件（`ACSD_DEV_INTERMEDIATE_CACHE`）随之失去对象，一并删除——**同一个输入在开关的两种取值下不再有第二种行为**。缺失情形的表达改由内存块的可用性承担，不另设门。

**运行前合法性与「不设门禁」的关系**。运行前检查的 fail-closed 是**输入域合法性判定**（母版与亮帧不属于同一读出几何时不得继续），不是阻塞正常流程的门禁：通过的运行不被任何检查拦截，检查只产出可复核的读数与明确失败。最高设计第 13 章针对的是把正常流程挡在关卡后面的机制，两者不冲突。上一条退役的"中间产物缺失即 fail-closed"不属输入域合法性，它是产物面判定，故按退役处置。

**取数侧的清点**。校准面与测光施加面的读取侧尚未改造，仍走输出目录的文件约定；四个逐帧 JSON（`p1_wcs`、`p1_sources`、`p1_phot`、`p1_snr`）同样被阶段一内部读回。调度器侧的内存块流能力已就绪但阶段一未接线：`lib/infrastructure/scheduler/src/block_flow.cpp` 的 `set_input`、`set_input_f64`、`product`、`run_unit` 四个符号在 `lib/` 全树**零消费者**。接线方式按第 13 章的复用条执行——在已有文件上暴露并使用该公开 API，**不得另写一份等价实现**；块的角色与生命周期取自该公开面，不在调用方各自约定。

**必须同批落地（显式耦合登记）**。写侧门控与取数侧内存块绑定**必须同批落地**，不得只做一侧：只闸写侧会切掉取数侧的输入，只做取数侧会在取数处必然失败；两者同批才构成一条可用的发布路径。同批还包含：逐帧 JSON 的读回改块（与平面件同一批，见下一节）、阶段二输入 JSON 的接线。

**发布构建可用性**。判别标准只有一条：**标准构建下中间产物不需要落在磁盘上，且同一个输入只有一种行为**。当前仓库的实际状态与目标有两处差距：① 写侧尚未门控，校准面与测光施加面仍照常落到输出目录；② 取数侧的两处判定按编译期条件分叉——定义开关时回退原帧并留痕继续，未定义时返回缺失路径并 fail-closed，**同一份配置在两种构建下得到两种行为**。因此当前**未达成**，且差距 ② 属缺陷（开关越权改变执行路径）。达成路径 = 取数侧改内存块（消除分叉）+ 写侧按开关额外输出 + 阶段二输入 JSON 接线，三者同批。

## 与数据流文档的关系

本文件定义构建期能力边界，是上位正本；数据流文档描述节点之间交换什么、以什么形态交换，其"中间量是单节点执行期的内存对象、标准模式不落盘"的措辞由本文件给出依据并指向本文件。产物命名规则只有一份实现，位于阶段一调度器适配层。
