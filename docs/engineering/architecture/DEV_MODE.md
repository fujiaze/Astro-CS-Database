# 开发模式与构建期能力边界

## 为什么需要一条边界

ACSD 的科学产物是帧级 HiPS 产品树与结构化 JSON：单帧标准化只把校准后的像素面写成球面产品，节点之间通过内存管线传递像素面与辅助量。开发期间，为了逐节点复核、复算与性能剖析，需要在磁盘上留下中间图像、检查点与探针读数；发布版本不需要这些，也不应把它们编进二进制。

这条边界是**构建期**的，不是运行期配置：同一个能力要么在二进制里，要么不在。把它做成运行期开关会让发布版带着一整套只在开发期有意义的分支，使行为难以归因、产物难以判定。

## 开关

一个主开关与三个子开关，子开关默认跟随主开关：

```cmake
option(ACSD_DEV_MODE              "开发模式：启用中间产物落盘/检查点/探针（发布版 OFF）" OFF)
option(ACSD_DEV_INTERMEDIATE_CACHE "开发模式子项：中间产物落盘" ${ACSD_DEV_MODE})
option(ACSD_DEV_CHECKPOINT         "开发模式子项：检查点与续跑" ${ACSD_DEV_MODE})
option(ACSD_DEV_PROBES             "开发模式子项：性能探针"     ${ACSD_DEV_MODE})
```

主开关默认关闭，子开关取主开关的值。发布打包以 `-DACSD_DEV_MODE=OFF` 构建，三个子项随之全关；开发者可以只开其中一项（例如只开性能探针），因此"探针可独立开启"这一能力不因归并而丢失。开关通过 `target_compile_definitions` 传播到对应目标，各能力以编译期条件包裹。

性能探针沿用既有的编译期零开销写法：关闭时宏展开为空语句，不引入任何符号与头文件依赖。

## 覆盖的能力

**帧级平面产物落盘**。校准面、清理面、坏列掩膜与测光施加面（`calibrated_`、`cleaned_`、`badcol_`、`photoapplied_`）在开发模式下写到该块的输出目录，供逐节点复核与复算。

**检查点与续跑**。检查点记录每帧已完成的阶段，使中断后可以按帧粒度跳过已完成的整帧、只重跑未完成的整帧。它属开发期能力。

**性能探针**。低开销的运行时探针，用于资源与时序剖析。

## 不属于开发模式

**逐帧 JSON 是标准产物**。`p1_wcs.json`、`p1_sources.json`、`p1_phot.json`、`p1_psf.json`、`p1_snr.json` 等不是调试缓存，而是节点之间的契约载体：调度器把 `wcs`、`photprov`、`sources`、`snr` 声明为类型化输入端口，据此绑定依赖边，保证例如解算先落盘再 drizzle。发布版必须产出它们，否则依赖边无从绑定、节点顺序无保证。

**平台与构建形态宏**（共享库导出、异常模型、CFITSIO 锁统计等）与开发模式无关，不随本开关变化。

## 门控分两批

**第一批可立即落地**：清理面、坏列掩膜、测光施加面的写出侧、检查点与续跑、性能探针。清理面与坏列掩膜在仓内只写不读，测光施加面的写出侧也只需产出；门控它们不影响任何节点的取数。

**第二批需先改造**：校准面与测光施加面的读取侧。cos 节点以校准面为输入，drz 节点在逐帧判决分支中要求消费测光施加面；这些边当前走输出目录的文件约定，关闭缓存后前者会失去输入、后者会直接失败。改造方向是把 `calibrated → cos` 与 `photoapplied → drz` 两条边改为内存块绑定——调度器已有块流能力（按名注入输入、按名取产物、带角色与生命周期），但阶段一节点尚未使用它，因此这是**新增接线**而非切换既有绑定。改造后取数不再依赖磁盘，且不需要在节点内复制校准或施加的实现。

## 运行前检查与中间产物

输入面在运行前校验，运行期间不再需要中间产物校验。输入面包含两类：观测亮场，以及母版校准帧（偏置、暗流、平场）。对它们的要求是存在、匹配、合法。

**已实现的部分**。合法性检查已覆盖：母版平场的有效性，母版单位与标度声明的解析，暗流约定，平场归一化键与其取值规则，平场中位区间键的形状与有序性，输入亮场清单的存在与非空，以及每帧产品目录键的唯一性。存在性目前不是清单式校验，而由读取失败体现——节点读不到母版即报 I/O 错误。这一处可以补为清单式，使缺失在进入节点之前就报出。

**匹配检查**。校准帧（母版偏置、暗流、平场）与亮帧的**图像尺寸必须一致**。尺寸不一致说明两类数据不属于同一读出几何，用它们做校准会得到无意义的结果，因此在运行前报数据域错误并落原因，错误信息点名具体文件与两侧尺寸。

**运行期的静默回退**。校准面的取数路径在产物缺失时静默改用原帧，这条回退与运行前检查不同源——检查在取数之前通过，取数时才发现缺失。标准模式下中间产物不经磁盘、节点之间经内存交换，因此这条回退在发布版不应存在。做法是用编译期条件把它包住，发布版编译期即不含该分支；开发模式保留它，但必须显式留痕：取数返回降级标记与原因，调用方把它们写进 manifest 与诊断。

测光施加面的取数路径在产物缺失时报错停止，不是静默回退。它属开发期产物缺失的判定，随把两条边改为内存块绑定而自然消失。

补全运行前检查并去掉运行期的静默回退之后，运行期不再需要中间产物校验。

## 与数据流文档的关系

本文件定义构建期能力边界，是上位正本；数据流文档描述节点之间交换什么、以什么形态交换，其"中间量是单节点执行期的内存对象、标准模式不落盘"的措辞由本文件给出依据并指向本文件。产物命名规则只有一份实现，位于阶段一调度器适配层。
