# API-001 — 公共 API 与错误模型（V6）

> 状态: ACTIVE  版本: 1.0.0  owner: AstroCS
> 上游: DATA-001, ARCH-001  下游: BLD-001, CORE-001..008, CPU-001
> 公共 C++ API 只在同一 toolchain 边界；CPU DLL/so 使用 C ABI；exception 不跨 ABI。

## 1. 分层

| 层 | 类型 | 边界 | 说明 |
|---|---|---|---|
| CLI 命令面 | 进程 | stdout JSON / stderr 日志 | `astrocs version|doctor|benchmark|config validate|pipeline validate|pipeline graph|run|test|artifacts verify` |
| Pipeline Runtime API | C++ public | 同一 toolchain | IR/registry/scheduler/services |
| Module API | C++ public | 进程内注册 | `IModule` 描述/plan/execute |
| CPU Provider ABI | C | DLL/so 边界 | `astrocs_cpu_provider_v1` |
| I/O ABI | C | 进程内 | `aio_*`（保留冻结） |

## 2. 错误模型

### 2.1 CLI 退出码（`cli/exit_codes.h` 唯一源，冻结）

| 码 | 含义 |
|---|---|
| 0 | 成功，且所有请求门禁通过 |
| 2 | CLI 参数或配置错误 |
| 3 | 输入缺失、格式或 hash 错误 |
| 4 | 科学验证/数值不变量失败 |
| 5 | backend ABI/签名/CPU 特征/加载失败 |
| 6 | 计算执行失败 |
| 7 | I/O 失败 |
| 8 | 输出完整性/验证失败 |
| 9 | 用户取消或超时 |
| 10 | 资源利用率或内存增长门禁失败 |
| 70 | 未分类内部错误（必须生成 crash report） |

### 2.2 Error domains（CORE-001 目标，错误码稳定）

- `CONFIG / DATA / SCIENCE_PRECONDITION / IO / RESOURCE / BACKEND / CANCELLED / INTERNAL`。
- 模块不得调用 `exit/abort`；异常只在内部转 `Result`，不能穿过 C ABI。
- `Result<T>` 支持 nested cause、serialization、cancel、错误码映射。

### 2.3 C ABI 规则

- 结构带 `size`/`version`；禁止跨 DLL 传 STL/异常/allocator 所有权。
- 固定宽度类型；显式 size/version 校验；坏 provider 拒绝且优雅 fallback。

## 3. 机器输出

- `--json` 输出 schema 固定；日志不得污染 stdout JSON。
- 事件流 JSONL：`run/node/artifact/time/sequence/severity/type/metrics`（CORE-008）。

## 4. 生命周期/线程安全/可重入/取消

- RunContext 只在节点执行期间有效；模块不得保留 context 到 execute 返回后。
- 公共对象 thread-safety 在 header 注释声明；所有权（borrow/shared/unique/persisted）
  按 DATA-001。
- 取消经 CancellationToken 传播；checkpoint 只在 Artifact 原子提交后写入。
