## Defects found and fixed (root cause -> counterexample -> fix)

1. **Per-pixel drizzle at 4096**: the old normalizer materialised one
   `OverlapContribution` (592 B plus strings) per pixel per source: 10.5 min,
   6.4 GiB sky vector and 6.1 GiB product for 256x256, extrapolating to 19-28
   GiB at 4096.  Fixed with the typed `drizzle_grid` operation (58 operations,
   22 processes) sharing one `DrizzleAccumulator` with `build_drizzle`; the
   certified interval formula is unchanged.  256x256: 11.4 s, 78 MiB RSS,
   identical 122 leaves, new enclosure contains the old signal, median
   relative width 6.24e-5 vs 6.57e-5.
2. **HiPS tile mapping**: leaves were bit-reversed into 122 scattered tiles up
   to 32 deg off sky.  LSB-first NESTED decode; 256x256 product now writes 122
   leaves into one tile, maximum residual 0.003", values bit-identical.
3. **HPX WCS**: face anchor/CRPIX used an unsigned subtraction and wrapped to
   9.22e18.  Only equatorial faces 4-7, signed arithmetic; CRPIX verified.
4. **Export closure**: the target row Q was not stored, so every export
   publish failed; typed `closure_actions` now stored by `publish_graph` and
   reopened by `open_product` (fail-closed; the reader also reopens
   `spatial_actions`).  The first reopen check compared the semantic identity
   with the content hash and rejected every healthy product; it now checks the
   semantic reference set.
5. **FITS header record overflow**: `header_block` did `resize(2880)`, so a
   4096 export with 37 cards lost its CONTINUE ACSUNIT card and its END; a
   strict reader refused the file.  It now pads to the next 2880 record.
6. **Export capacity**: the admitted Q size was `pixels x leaves` (the dense
   matrix, 4e11 entries); the streaming projection builds a sparse row whose
   size is bounded by the target pixel/leaf geometry.  The 4096 export now
   admits and runs.
7. **Epoch**: `DATE-OBS` was read with its FITS quotes, so the parser failed and
   the epoch stayed 0: proper motion was propagated by -2016 yr (4.7 px
   offsets).  Quotes stripped, JD-OBS added; epochs now 2025.945/2025.978/
   2025.989.
8. **Background model**: a frame-wide constant background on the M42 nebula
   gradient produced `F=-2.99e6 / -1.23e6 ADU` and 5/12 negative fluxes in the
   256x256 window.  The science contract now fixes a per-source local plane
   (constant plus two detector-linear terms, block diagonal); the same window
   gives 12/12 positive fluxes with the same positions.  Contract revision in
   `docs/engineering/rebuild/processes/sources.measure.md`.
9. **PSF sample / saturation**: the PSF fit used 4 stars (rank deficient) and
   never saw the DQ; it now filters windows with more than 15% saturated
   samples through the runtime store and fits 12 stars.  A 24-source measure
   also under-declared its work (the candidate scan) and was refused; the plan
   now includes it.
10. **Resource declarations**: calibrate's output arena was an exact 26n fit and
    failed the last (DQ) allocation; +64 KiB.  `build_sky_controls` declared
    `block*terms*24` bytes for a whole T/H/A/E assembly that is built at once;
    the stage now declares the real upper bound.  The coadd plan under-declared
    the support arrays (teammate fix).
11. **Relative sky at 4096**: `fit_relative_sky` densified the control operator
    T (108x71368) only for a shape check; `dense_action` refused anything with
    more than 4096 columns.  The estimator is control-space (108x108), so the
    dense copy was dead work; replaced by a sparse payload validation (no cap
    raise, no model change).  See the reviewer-facing note from the
    implementation.

## Remediation round 1 (after the independent FAIL)

- **Sky**: the additive offset is now fitted on the darkest 10% of *sky* patches
  (patch ids are sky based and aligned across the three frames; the frames
  20251224/20251228 are 180 deg flipped, so each frame's own dark detector
  patches would not be the same sky).  On the S1 data the fit gives
  beta = +1.5956e11 / -1.7696e11, matching the reviewer's dark-leaf
  +1.9e11 / -1.5e11, instead of the previous +3.837e12 / -1.038e12 which
  absorbed the multiplicative night scale.  The residual scale is *measured on
  the corrected frames over bright leaves* by the mosaic workflow and named in
  the estimate assessment (f1/f0 median 1.1505, p16 1.0296, p84 1.2380;
  f2/f0 0.9419, 0.8784, 1.0029), with the omitted/conditional state.  It is not
  applied by the equal-weight coadd (unknown noise); the assessment says so.
- **Saturation**: `drizzle_grid` reads the DQ and excludes saturated native
  samples from both numerator and normaliser, names the removed count
  (f0 24900/16777216 = 0.15%, f1 36705 = 0.22%) and omits the nonlinearity flag
  that the dataset does not provide.  The exact 65535 plateau disappears from
  the leaf signal; pixels just below the ADC ceiling remain legal data and the
  missing nonlinearity bit is stated.
- **Absent leaves**: NaN signal and zero area (previously 0.0 and a full leaf
  area; the 7 "absent" mosaic leaves are the unresolved grazing leaves of
  f1/f2, not regions outside every frame).
- **Provenance**: the manifest `source_hash` is now the git revision
  (`ACSD_SOURCE_ID`, `-dirty` when the tree is dirty), not the hash of the
  algorithm name; Normalize records the observation/response/WCS identities and
  the Export records the input product manifest hash.
- **WCS identity**: the supplied solution identity hashes c/e/north/CD/CRPIX/
  SIP/epoch/detector frame; it was the constant `acsd.cli.target.wcs` for every
  frame.
- **Unit**: the coadd carries the frames' common physical unit (scale "1",
  linear 1, sr -1) and the HiPS tiles/properties take the `Unit`, so
  BUNIT/hips_unit are ADU/SR rather than 1.

## Open items at the time of writing

- Night-to-night relative scale: the frozen low-background photometry reports
  1.2766 between 20251212 and 20251224; the mosaic sky model is additive only
  and the coadd weights are equal (unknown noise), so a multiplicative scale is
  not estimated.  This is the main scientific open item for S1; it must be
  estimated by the declared photometry path or named as an unseparated
  systematic with its measured effect before S1 PASS.
- The SkyFit object (beta) is not stored in the mosaic product closure; the
  offsets in this file come from the deterministic fit and the product lists
  the three input manifest hashes, so the mosaic is reproducible from the
  inputs, but not reopenable from the product alone.
- Independent reviewer verdict: in progress (docs/audit/reviews/).  The S2
  issue is not created before a PASS.
