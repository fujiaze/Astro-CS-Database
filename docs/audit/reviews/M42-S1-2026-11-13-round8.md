### 2.4 “fails closed on truncation”：只覆盖了不会发生的分支

`mosaic.cpp:799-807`：

```cpp
U64 coef_count = 1;
for (U64 extent : val(weights)->coefficients->shape) coef_count *= extent;
Result<std::vector<double>> coef_values = operators::read_f64(
    seam_context, val(weights)->coefficients, 0, coef_count);
if (ok(coef_values) && val(coef_values).size() != coef_count) {
  return fail<ProductLocation>(Code::invalid_model,
                               "the coefficient array read is truncated", ...);
}
```

`operators::read_f64`（`src/operators/linear_action.cpp:27-49`）在
`begin+count > total` 或 storage 读失败时返回 `!ok`，**不会返回短 vector**。因此
`ok && size != count` 这个分支实际上永远不触发；而 `!ok` 时后面的
`if (ok(coef_values) && ...)` 为假，`seam_measured` 保持 false，`:984` 只是
不追加 seam 文本，产品**照样发布**。要真正做到“截断即拒绝发布”，需要
`if (!ok(coef_values)) return fail<ProductLocation>(...)`，而不是只查长度不等。
本轮“fails closed on truncation”的声明**只对“读取成功但长度不符”成立**，对
“读失败/block 截断”不成立（实际风险因 coadd 自身也读同一数组而较低，但声明
与代码不符）。

## 8. 结论

Round 8 是一次**真实且改对了核心数值**的整改：全足迹读缓冲、真标签亮度分带、
med|Δ|+signed 三项我**逐位复现**（6.315/2.871/1.875，主带 8.428），round-7 的
1/3 截断确实消失；conditional mosaic 的幅度与诚实性**可接受**。

但 S1 **仍 FAIL**，因为接缝证据的形式与两处陈述仍不成立：

1. **低频场**：代码只做 8 个 interior 格，产品却写 “8x8 … (17-cell field)”；
   真 64 格 interior 是 **0.81–23.82%**、K1/K3 边界是 **1.18–45.19%**——产品把
   边界场漏掉、把 interior 场平滑掉 5 倍以上，文本不实。
2. **§S1.5-2 要素**仍缺 A/B 方向、支持像元/`N_eff`、相关噪声；标准化残差被误称
   “not computable”（实际 Δ/MAD_interior = 3.37/1.53/5.09 可算）；亮度带缺
   signed/MAD；缺明确可辨识域判断句。
3. **export 的 `included` 没有 seam 摘要**，而冻结记录声称 “the seam summary is in
   both”；**“fails closed on truncation”** 只覆盖不会发生的长度不符分支。

按 `AUTONOMOUS-RECOVERY-TO-FULL-DATASET.md` §3/§7，S1 FAIL 时不得创建/推进 S2。
修复只需 §6 的 1–4 条（**科学算法不动**，mosaic 14 s + export 4.8 min），然后做
第九轮独立复核。**不得**以“数字都能逐位复现”“产品已标 conditional”“qc.json 全绿”
或“接缝幅度 round-6 已放行”放行——本轮缺的恰是把**全足迹的、正确标注的 64 格低频
场、§S1.5-2 的其余要素、以及 export 的传播**写进产品。
