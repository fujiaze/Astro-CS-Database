# D1｜ACSD V2 最终实施路线、依赖、维护责任和结项裁决

## 目标和总体管理哲学

本项目要**一次性完成可信软件雏形的彻底科学与工程重构**，而不是完成一轮文档迭代后再来一轮“整改检查脚本”。工作清单以真实数学问题和源代码缺口为驱动，能用现成的成熟方法解决则不重造；创新算法保持严谨、有限域、原始实验和独立审查。所有真实实现提交到`rebuild/acsd-v2`；不推`main`，不force push，不建PR，不开启CI和文档/覆盖率门禁。

一个任务结束的标志是**存在可被独立质询的完整论证＋真实源码/产品＋指定域证据**，不是Issue关闭、Markdown清单勾选或者CI绿色。

## 第一阶段：历史与外来理论的唯一来源（A0、A1、A2）

**顺序**：最新工作树调查→真实代码/文档/实验状态→全文文献索引与合法归档→R1–R5实验身份审查→冲突科学段落修订列表。
- 逐process标明当前代码现况，不用历史`M0–M4 16/16`推断新算法正确。
- DOI/原始论文/页式号必须逐项定位；拿不出来源/无法推导的算法先标`SPECIFICATION_GAP`。
- 每个原创扩展须有对照最接近已发表方法的具体数学改进和独立证据，而不是把成熟BLUE/Drizzle/GLS换名即宣称原创。
- 审核者不读生产内部即可复现R1–R5的**数学目标**；无法复现历史数字时记录其原因/缺陷，不“重新发明报告”。

**阶段交付**：科学来源索引、原始科研档案索引、各Process来源链接、差异/缺口清单及科学论证优先级。

## 第二阶段：科学基础与原语阻碍（B0、B1）

**顺序**：前向物理/单位/坐标、数学与证据等级→区间/矩阵原语严格修复→上游认证依赖重建。
- 全部连续观测→离散像元→面亮度产品的估计量保持同一语义，异响应/未知噪声/物理模型偏差诚实表示。
- 当前interval四类P0必须从数学域、端点与舍入实际操作修；rank/eigen/QP/迭代的数值证书不能以字段或普通残差冒充。
- 精确Oracle的意义是对照一条已证明的命题；在普通IEEE点运算里跑百万随机例不替代有向数值包含的逐代码理由。
- 公共NUMERICS完成后再允许被其依赖的Process出具`certified`，不能先把其它任务逐项填PASS。

**阶段交付**：五份Foundation正本一致、共享NUMERICS实际源码有审计和反例、认证/conditional可解释、已知P0不再阻断已承诺的本期科学域。

## 第三阶段：Normalize的科学实现与首次真正闭环（B2、B3部分、C0）

从已知无噪声原生模型/给定WCS开始：
`calibration/regroup → coordinates/catalogue → sources PSF/measure → response/photometry → geometry R → information → publish`。
- 先在解析模型中给定真实WCS/PSF/背景证明核心估计量；逐次释放已知约束（需要真实solve、PSF fit、未知gain/PSF、共享latent、非平凡SIP），每次失败追到具体条件。
- 实际X01 B组误差明确区分低SNR随机波动与系统偏差；事后扩大容差/调整truth不算修正。合成8帧发布只是工作流贯通证据，不代替已知科学真值。
- 细化球面几何时必须同步检验同`R`支持、信号、PSF、随机根、error和信息泛函。
- 用`src/workflows/normalize.cpp`正式入口，不拿独立契约驱动成功冒充生产。

**阶段交付**：至少一组无噪声+有噪声标准合成输入、完整Normalize产品、解析/独立真值一致与当前适用域的有界错误/未知信息。

## 第四阶段：Mosaic、Export与统计闭环（B4、B5、C0）

- 基于完整多帧Normalize产品，Sky按可比较控制图推算同一basis/同数据P；每个连通分量的gauge和无法识别模式清晰。
- 按可信Γ执行已定义policy；小N的拒绝算法只在其前提内使用，真实变星或异通带不能被硬塞成共同均值。
- `coadd.integrate` 只使用明确冻结`Selection/WeightSolution`；输出一个正式Signal HiPS及完整辅助模型。
- Export按照真实支持`Q`转换成指定二维WCS-FITS，并经外部读取及科学语义对照。
- 对完整前向仿真做多次有噪声、强差模、不同WCS/PSF与混合响应；逐源和最终产品各自使用正确被估计量。

**阶段交付**：可在新进程按三个正式命令得到外部可读HiPS/FITS，包含统计/支持/数值条件与产品有效域；不能有关键步骤只在模拟driver存在。

## 第五阶段：工程基建最终稳健化（C1、C2）

工程可与科学路径合理并行，但“科学计算可产生结果”与“工程能承载真实大图”必须一起结项：
- 唯一CPU pool/Memory/Storage/Task/Pipe的生命周期、所有权、缓存/诊断、资源上界与明确失败/取消路径；
- 真正跨Process的大量像元流式传递和外存、1/多线程、32/256MiB、磁盘满/杀进程、非本进程产品恢复；
- 原生FITS的结构与字节序、外部reader互操作；Windows/Linux实际构建运行；
- GUI仅通过正式服务调用科学核心，具备可用的输入/进度/错误/取消/产品查看；
- 性能按真实科学成功域测得，无“失败更快即优化成功”。

**阶段交付**：两个平台可用软件、可打开科学产品、有可复现环境及输入的工程证据、现实设备下内存与吞吐报告、安全失败与恢复记录。

## 第六阶段：独立科研/工程双审核和冻结（D0、D1）

安排至少两种相互独立的审查角色：
1. **科学审查**：不先读旧C++/测试，逐论文核对、独立重推数学假设与反例，再审实际实现和真实数值/统计。对自研R1–R5挑战创新性与适用域。
2. **工程审查**：从实际公开入口→源码调用图→Lease/Task/Pipe/Storage→新进程→产物追踪，寻找并发/资源/串账/半产品/版本错配，在真实双平台操作。
3. **终值反向审查**：独立选取真实FITS图像的像元及代表性source，由最终的可见科学单位和误差状态逆向追溯至输入原生ADU、响应、WCS、R、SkyFit、WeightSolution、Q、源论文/自研证明。对未知物理项说明条件，不允许假装全部已知。

修订后独立复核。**禁止只由实现Agent自证所有任务完成**；不需为此引入自动CI或代码覆盖率政策。

## 任务结束前必须真实回答的十个问题

1. 每一项对外可执行的科学算法，可否直接打开原始论文或项目自推导并找到对应公式、实际参数和本项目修改？
2. 所有R1–R5实验是否能区分成熟基础、新推导、可复现证据及真实数据仍未知的东西？
3. 从真实原始观测到最终面亮度，所有单位、response、坐标、面积/采样链是否有一致且无隐藏交换的数学意义？
4. interval/线性代数/矩阵rank/非线性拟合是否仅在实际具备正确数值证书时声称严格认证？
5. 重建的信号、PSF、背景和随机协方差是否消费同一物理观测、同一R/共享latent与正确的revision，丢失能力是否如实标unknown？
6. 真实低频天体结构能否在所声明的可比较Sky模型中得到保护，不能保护的域是否明确解释？
7. Mosaic的排异与权重是否使用与其声明estimand一致的方差，选择后统计不确定度是否与冻结mask估计区分？
8. Export的FITS/WCS/支持/负数/零/未知项是否经外部程序读取，最终产品能否新进程打开并逆向追溯？
9. 在本期明确支持域内，普通用户能否在Windows/Linux运行完整三命令，取消、低内存、磁盘错误和GUI异常是否安全？
10. 是否仍存在实际必需功能的P0/P1、文档/源码在关键公式处矛盾、无来源的算法、关键链条隐含假设或只能靠“测试绿”作结论的地方？

只有所有问题在**声明适用域内**有可审查证据，才能正式写“V2 本期完成”。用户真实未知物理量不应成为永远不能完成程序的逻辑陷阱，但若属于本期承诺的能力且尚不能正确处理，则必须整改或明确不支持；不能靠降低文档要求或让错误变成“conditional”绕过本期主要功能。

## 裁决与变更规则

- “科学设计/算法数学/实际源码/数值认证/概率统计/真实适用性/工程运行/最终产品”分栏给结论，任何单项通过不能自动推出全局通过。
- 关键模型前提若有反例，先修改Foundation和Process、重推所有被影响的下游，再改代码与独立实验；严禁改容差或真值生成程序消除失败。
- 性能优化只可用数学等价或指定误差界内的替换，不允许偷偷改mask、秩、科学目标或高精度failover语义。
- 新程序内部只保留一套当前API/对象/数据格式，无旧V1兼容/迁移义务；既有科研报告、Git历史和真正失败证据永久保留。
- 用户不要求再发展SACoadd高级算法或GPU；不以无止境功能扩展阻止本期V2完成。对新增功能在本期之外管理，而非强行纳入最终签核。
- 冻结交付不是强行将`main`合并进V2；重构分支可以独立完成并由用户决定何时提升为新主线。
