# AUDIT-REVIEW-001 · 方法、复现与 claim 索引

> 本文件给出：复核口径、独立 Oracle 的判定面、负向 mutation 设计、逐条命令与退出码、以及 50 条 claim 的完整索引（保证人读正文与机器表逐条对应）。

## 1. 复核口径

1. **权威分层**（宪章 §1.1）：FROZEN 宪章 > `docs/owner/PROJECT_SPEC.md` > 三份 Phase 详细设计 > `docs/science/UNIFIED_SCIENCE_MODEL.md` / `PSF_SIGNAL_WEIGHT.md` > 专项 SCI/ALG/DATA/API > 模块与代码 > 历史文档/旧报告/旧控制包（仅线索）。
2. **历史审核包与旧控制包的地位**：审核包 `reports/review-package-20260915/` 是**证据输入**（V4 `00_READ_FIRST.md` 明文），不是活动规范；V3/V4/V5 包为 ARCHIVED_SUPERSEDED（`ACTIVITY_STATE.md` §2）。
3. **判定粒度**：以「结论/裁决/缺陷面」为条（claim），不逐字重述原文；每条给源锚与目标锚。
4. **不改判**：不新增、不删除、不改判任何缺陷 id；不修改任何上位规范、公式、容差或冻结门。

## 2. 独立 Oracle（`run/v6/review-audit/tools/audit_oracle.py`）

Oracle 不调用任何被测生产实现，也不读本报告的结论；它只做五类独立判定：

| # | 判定 | 方法 |
|---|---|---|
| (a) | claim 锚必须真实 | 每条 claim 的 `source.quote`/`target.quote` 去掉全部空白后必须是所引文件内容的子串 |
| (b) | 账本口径独立重算 | 直接解析 `reports/review-package-20260915/03_缺陷账本/DEFECT_LEDGER.json`，重算 785 与处置分布，与 claim 表的 `recomputed_facts` 比对 |
| (c) | Phase2 三模式可达性 | 独立目录扫描（跳过 `run/` 等），要求 0 命中 |
| (d) | 标识真实存在 | 所有 `owners` 必须在 V6 `TASK_MANIFEST.json`；所有 `defect_ids` 必须在 785 账本 |
| (e) | 叶子/合并层缺口 | 独立抽取 `问题扫描/_cache/L*.md` 标题中的 `L<digits>-<digits>` 与 `ROOT_CAUSES.md` 引用者，验证其与账本交集为 0 |

另有绑定检查：每条 claim id 必须出现在 `reports/v6/review-audit/*.md`；`reopen`/`coverage_gap` 必须有 owner 或 `needs_controller=true`。
