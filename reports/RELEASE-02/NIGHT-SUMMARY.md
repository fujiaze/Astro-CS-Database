## 一、最重要的结论：两个真缺陷被定位并修复

### 1. 天光面在生产链上**从未生效** —— 已修复（FIX-SKY）

- 现象：每次 mosaic 都 `[sky_plane] build FAILED rc=6 reduced normal matrix not SPD` ⇒ 回退 UPM C 场；
- **根因（纠正了第一版归因）**：不是 3 维 gauge 零空间，而是**惩罚自身的 4 维 bilinear 零空间**
  `{1, ix, iy, ix·iy}`（rank(D)=26/nullity=4）；且**惩罚 trace 0.228 vs 数据 trace 1.80e-18，相差 1.27e17**，
  浮点舍入（~1e-18）淹没了数据在零空间上的曲率（~1e-20）⇒ `H_solve` 失去正定；
- **修法**：先走原直接 Cholesky（常规量级档**逐位不变**），仅失败时对零空间加 `α·QQᵀ` 极小 Tikhonov 锚，
  再用 **deflation** `B = B_a + Q·G⁻¹(Qᵀrhs − QᵀH_red B_a)` **精确扣回锚偏置**；只锚零空间，不全矩阵加 jitter；
- **验证**：修后 `rank=30`、`κ=2.845e5`，与独立 stacked-QR 一致到 2.8e-7；
  **实测新版 `sky_plane FAILED` 计数 = 0**，`[sky_plane] ok n_used=277234 n_nodes=36 n_frames=49`；
- **效果（VISUAL-B 数值）**：大尺度天光平坦度 **14.0% → 0.43%**（改善 33×）；
  卫星线残留 **4.45% → 0.50%**（改善 **≈9×**，1.86σ → 0.29σ）。

### 2. 权重链 F_ref 约定混用 —— 已修复（FIX-W）

- 现象：`weight_mode=2` 在真实数据上 fail-closed（stderr 中文被 locale 吞成 `?????`，真实原因是「F_ref 逐帧不一致」）；
- **裁决（四方证据）**：`SNR_f = a_f·F_ref/σ_f ⇒ SNR_f²/F_ref² = a_f²/σ_f² = w_f`，
  **成立当且仅当分母 F_ref 与定义 SNR 时用的是同一个** ⇒ **必须组内公共**；
  文档面（DESIGN §4.3:256、07_noise_snr:59-63、UNIFIED_MODEL:42、aio_hips.h:302）高度一致；
  文献 Horne 1986 + Gauss–Markov `w=a²/σ²`；实测混用偏差 **3.5×**；
- **修法**：删 `snr_frame_science.cpp` 的逐帧中位数回退 ⇒ fail-closed；`p1_op_noise` 整块取一个公共 F0
  （显式 config 优先 / 块级两遍法中位数次选 / 非法即 DATA fail）；`p1_snr.json` 增 `scope=group` provenance；
  Phase2 闸门**保持 fail-closed**（不放宽）；
- **验证**：ctest **461/461**。

## 二、性能：我的第一版结论是错的，已更正

**初版称「drizzle 仅 1.21 核（单线程）」—— 错误**，系测量脚本时间对齐缺陷：
探针阶段事件的 `ts_utc` 是**结束**时刻，被当成开始时刻 ⇒ 采样到阶段结束后的空闲尾段，按 cpu=0 加权。
由 PERF-DRZ 分片独立发现并给出反证。**修正后**：

| 阶段 | 总耗时(s) | 占已计 | **平均核数** |
|---|---|---|---|
| **drizzle** | **2076.2** | **75.4%** | **12.82** ← 并行度 96.5%，不是瓶颈 |
| star_psf | 175.9 | 6.4% | 5.83 |
| noise | 172.0 | 6.2% | 3.62 |
| photometry | 159.1 | 5.8% | 2.02 |
| wcs | 115.0 | 4.2% | 5.35 |

⇒ **Phase1 瓶颈是算法总工作量（约 26,614 核·秒），不是调度。**

**Phase2 才是真正的并行度问题**：整跑 1327.9s 仅 **0.71 核**，而 `active_workers` 恒 16；
逐阶段 upm_apply **0.86**、reject **0.68**、sample **0.69**、integrate **0.53**。
根因（PERF-P2）：`p.work_units = 1`、`parallel_axes` **全仓零消费者**、`execute()` 拿到 16 租约却只在调用线程上跑；
三个最大阶段是**裸串行 for**。

**额外重大发现**：**33% 墙钟（439s）在资源门监测窗之外** —— 67 个产物 / **18.45 GB 的串行哈希**，
且有**重复计算**（同一文件算 2–3 遍）与整文件入内存。
