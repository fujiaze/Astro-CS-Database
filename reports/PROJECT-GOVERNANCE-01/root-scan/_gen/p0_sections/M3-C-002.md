- 问题说明: 合同把「饱和」定义成两个判据的析取，实现只有第一个（`psf_status==0`），第二个判据**无处可施**：`matchWithKdTree` 无 qf 形参，六个公共导出也无 qf 入参，`lib/photometric_calib/cpp/src` 全文 grep `quality_flags|SATURATED|saturat` 零命中。可达性在复核时点已证：① PSF 状态码里根本没有饱和态（dynamic_psf.h:117-120），且 PSF 显式不消费检测阶段的饱和列（README:45），② p1psf 自己的 B3 用例断言「满量程饱和星的 `status == DPSF_FIT_OK`」（:1048），③ 同仓 SNR 层把「status==0 但 qf 含饱和」当成独立第三态 `fit_status=2`（noise_model.cpp:314），④ 生产编排里 `star_measurements` 块第 13/14 列携带 saturated/has_saturated（orchestrator.cpp:2515-2516），测光阶段却只取 status 列（:2652-2659）——即信息在调用边界可得而被丢弃。结果：邻域含饱和像素（flux 被截顶）的星直接进入 `r=log10(F_instr/F_syn)` 与 IRLS，污染 `location/scale/sigma_residual`，并经 `I_cal=I·scale` 改变整帧数值。SCI 为该判据给的锚 `star_matcher.cpp:35-40` 实为 `percentileOf` 函数，与饱和无关。
- 影响: 星团/银心等亮星密集真实帧高概率触发；全帧测光零点被截顶通量拉偏，且 QA 面无法归因（`rejected_quality` 只统计 status 无效数）。P0 成立。
- 建议处置: 公共 API 增 `const uint32_t* quality_flags` 入参并在有效域处过滤（推荐，配套补 §8 返回/计数语义），或按 §1.2 修订 SCI-PHOT §4/§10 并给出「PSF status 已隐含饱和排除」的上游合同证据（当前 dynamic_psf 侧证据恰好相反）。
- 置信度: 高
