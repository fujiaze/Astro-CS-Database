- 问题说明: 四个视角一条根因：① 「order ≤ 29」在标准中不存在（2^29 是 HEALPix 官方工具在 64 位下的工程约束），却被写进注册表「标准要求」列并据此判 CONFORMANT；② 代码侧根本没有该上界，require_valid_nside 只查 2 的幂、npix 连幂次校验都已移除，12ULL·nside·nside 在 nside=2^31 处按模 2^64 回绕为 0；③ 在册测试不但没守上界，还把 order 31 断言为「合法边界」→ 回归无法发现；④ 条款号错挂：ang2pix/pix2ang 挂 §5.3（实为 Pixel Boundaries），nside 幂次与等面积公式挂 §5.1（正文属 §5 引言）。ALG 与 IO_002 各按自己口径写 order 域，形成文档/标准/代码/测试四层互斥。
- 影响: 全仓唯一 NESTED 权威核心对 order 无界；生产写入口可用 ≥2^31 的幂次静默产出错网格（npix=0 → 枚举空集、面积归一除零/NaN 传播）；测试把越界钉成合法，使缺陷不可被回归捕获。
- 建议处置: ① 先定口径：把 order ≤ 29 改写为本项目工程上界并挂 DATA/ALG ID（不得写成 Górski 条款），或按 IO_002 的 K≤29 与 NSIDE=2^(K+9) 语义写明叶级 order 上界；② require_valid_nside / npix 内实施真实上界，越界返回/抛出显式错误；③ 订正 D.healpix 三处条款号（§5 / §5.1 / §5.2）；④ order31 用例改「越界必拒」正反双测（改造本身即回归钉）。
