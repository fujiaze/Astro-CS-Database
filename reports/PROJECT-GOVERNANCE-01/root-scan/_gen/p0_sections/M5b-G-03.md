### M5b-G-03 AST-API 门为同一头文件自反比对（恒真），参数数提取后弃用，且不读任何 API 文档

- 建议优先级: P0

- 问题说明: 判据是「同一头文件的正则声明名集合 ⊆ 同一头文件 AST 的 name 集合」——对任何可被 clang 解析的自包含 C/C++ 头**恒真**；`nparams` 在 `declared[name]=n` 处算出后仅作循环变量出现，从未参与比较（docstring 承诺的「参数个数一致」「visibility/ownership 对比」全未实现）；脚本从不读 `docs/contracts/PUBLIC_API.md` 或 `API_CONTRACTS.csv` ⇒「AST ↔ API 文档」这一环在仓库内无实现（`check_api_docs.py::_count_params_in` 走正则数逗号，非 AST）。门可失败的唯一路径是环境级（header 缺失、clang 失败、正则零命中），不属合同判定。覆盖面另只有 3 个 C++ 头，`include/astrocs/abi/*.h` 全不在内；profile 仅 `linux-main`、`waivable=false`。ID 冲突：`DOC-004` 同时是 `tools/check_ast_api.py` 与 `tools/quality/gen_module_readmes.py` 的文档 ID，且 `TEST_MATRIX.md:62` 把「TRACEABILITY.csv 断链校验」也归给 DOC-004 ⇒ 三个对象共用一个 ID。
- 影响: §12.3-5 形同虚设；签名/参数/可见性与 API 文档不一致无法被发现；`AST-API`/`DOC-004_PASS` 文案被活动文档当作机器证据引用。
- 建议处置: 改为「AST 集合 ↔ API 文档声明集合」双向差集并比较参数个数/类型/可见性；扫描面并入 abi 头族；ID 与 `gen_module_readmes`、`TEST_MATRIX` 解冲突。
