### M8-F-003 单入口安装树合同门（`tests/cli/test_cli_single_install.py`）在 CI 侧恒 SKIP：前置产物在根 `build/` 从不被任何 CI 步骤产出，且 install 失败被降级为 skip

- 类别码: F_TEST_GAP
- 优先级: **P0**（宪章 §3.1 单入口承诺的门实际执行数为 0）
- 位置: `tests/cli/test_cli_single_install.py::TestCliSingleInstall.setUpClass`（复核时点 :16 skipUnless、:24-30 have_tree→SkipTest）、`::test_01`（:48-49）、`::test_02/03/04`（:53/:70/:79/:89 四处 `self.skipTest("install 失败")`）；CI 产出面 `ci/steps/linux_build_root_graph.sh`（:13 preset linux-control、:14 --target astrocs、:25 cp astrocs、:29 cp version_generated.h）；对照 `CMakeLists.txt:133 add_library(astrocs_runtime SHARED ...)`、`cmake/install_layout.cmake:65-69`
- 证据摘录:
  > （:24-30）have_tree = all(os.path.isfile(os.path.join(cls.bdir, p)) for p in ("astrocs", "libastrocs_runtime.so")) / if not have_tree: raise unittest.SkipTest(...)
  > （ci/steps/linux_build_root_graph.sh:25）cp -f build/linux-control/astrocs build/astrocs     ← 只复制 exe，无 .so
  > （:53 等）self.skipTest("install 失败")   ← 被测对象失败被表达为跳过
- 权威依据: 宪章 §3.1（用户入口唯一）、§12.3-4、§13.2；`packaging/install-tree.contract.json:9`（PLATFORM-RUNTIME required=true）
- 问题说明: 全仓（含 `.github/workflows/*`、`ci/steps/*`、`ci/checks.json`、`ci/run.py`、`cmake/install_layout.cmake`、`CMakeLists.txt`、`packaging/*`）对 `libastrocs_runtime.so` 的命中仅 8 处（口径=逐文件 grep 命中行数，排除 run/build/evidence/reports/问题扫描），其中**没有任何一处是"在根 `build/` 产出该文件"的步骤**：该 target 真实存在（根 CMakeLists:133），但 CI 只把 `astrocs` exe 复制进根 `build/` ⇒ `have_tree` 恒 False ⇒ 类级 SkipTest。次级缺陷：即使构树齐备，`install_rc != 0` 时 test_02/03/04 也只 skipTest 而非 fail。类级 `skipUnless(which(cmake) and which(g++))` 再加一层环境跳门。UT-CLI 的 `waivable=false` 只保证外层不记 SKIPPED，掩盖不了 unittest 内部静默跳过。
- 影响: 「install 树恰一个用户 exe / 无 legacy exe 泄漏 / CLI 不 shell-out」三条单入口合同实际执行数为 0；旧 phase/benchmark exe 复归或 CLI 出现 shell-out 都不会让 CI 变红。
- 建议处置: ①CI 构建步补 `cmake --install build/linux-control --prefix <tmp>` 或直接产出根 `build/libastrocs_runtime.so`（与脚本 :9 注释自述的意图对齐）；②install 失败由 skipTest 改 fail；③若 hosted 确实不产该产物，则在 windows-main/Fatduck 侧建等价门并在 checks.json 注记原因。
- 置信度: 高（两处现场逐字 + 全仓命中面枚举；订正：不说"目标不存在"，说"CI 侧不产出"）
