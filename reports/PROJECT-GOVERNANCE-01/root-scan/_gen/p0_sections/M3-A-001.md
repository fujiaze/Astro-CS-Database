- 问题说明: 复核时点全仓至少并存三套互不相同、且都叫「SNR」的量：
  ① **合同唯一授权**的定义是 `signal/√variance`（SCI-NOISE §9a:98 明文，且声明本层不产出 SNR 图）。
  ② **实际进入产品的量**是 HISS SNR 目录/控制点值 = `(A−B)/residual_scale`（PSF 峰幅除以残差尺度），链路完整可追：`snr_extract_model*` 三处同式（:544/:663/:768）→ `SnrControlPoint.snr_psf` → drizzle 写 SNR 块（drizzle_engine.cpp:1162/:2037）→ `sampler.cpp` 读目录得 `frames[i].snr`/`o.snr` → `stage2.cpp` 组 `local_snr_map`（:380-405）并在 :1136 平方后进入权重。该量**不含任何方差项**，且其自身所在通道在公共头里被标注为「legacy (A-B)/mad … SNR-008 已退休路径」（:288/:300）、在 :19-20 被标注为「已降级为 legacy heuristic / diagnostic only … 不再作为生产科学权重」。SCI-CW 却把它定义为「区域级 SNR 倍率、无量纲」并消费。
  ③ 第三种 `snr_phot = 1/(ln10·sigma_residual)`（:381）是相对定标误差的倒数，同样无任何 SCI 定义，且与 `PhotometricCalibrationQuality.sigma_cal_rel` 为同一量（同文件 :33-49），后者被明文禁止当权重。
  即：被标注为「已退休/仅诊断」的量，同时在生产链的另一侧被当作权威 SNR 消费；而合同授权的定义无人产出。三套量纲与数值域互不相容，`snr` 在全仓无唯一定义。
- 影响: Phase1 SNR 产品（HISS SNR 块、SNR 控制点、`p1_snr.json`）语义与 SCI-NOISE 合同不符；Phase2 的 `local_snr/frame_snr` 权重因子（见 M3-A-002）建立在该量上，量级亦非 SNR（例：A=5000、B=1000、residual_scale=120 → 「snr」≈33，平方后为 ≈1100 的权重倍率差）。真实数据路径：stage6 SNR → HISS → stage2 积分/排异。属「科学输出错误 + 定义不唯一」双料，P0 成立（复核时点成立）。
- 建议处置: 由负责人冻结唯一 SNR canon：(a) 若保留 HISS SNR 目录，须为其另立 SCI 名（如 `fit_snr_proxy`/`frame_quality`）并在 GLOSSARY 与 SCI-CW 中与 `signal/√variance` 显式区隔；(b) 否则目录/控制点值改按 SCI-NOISE §9a 构成，`(A−B)/residual_scale` 退回诊断字段并撤销其在 Phase2 权重中的消费；(c) `snr_phot` 一律改名（它是定标误差倒数，不是 SNR）。三处「已退休/仅诊断」自述与实际消费必须收敛为一。
