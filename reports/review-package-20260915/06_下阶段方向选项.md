## 二、方向选项

### 选项 A · 完成 phase1 冻结 → 跑 M42 R 通道样例（你已指的方向）
- **做什么**：① drizzle 冻结口径定案（K2+缓存，K1 待裁）；② 调度落地并入（P36）；③ 三项都过“干净树 ctest 全绿 + 绑核 1/4/16 产物逐位一致”；④ 跑 `M42:R`（49 帧）phase1 → phase2 出一张 R 马赛克。
- **工作量**：中（主要是各批复验与提交 + 49 帧 phase1 约 1.5-2 小时 + phase2）。
- **收益**：拿到**第一个端到端同滤镜双望远镜马赛克**，把阶段 7 从“未开始”推到“样例通过”。
- **依赖**：K1 裁决（B4）。
- **前台建议**：**做**，且作为主线。

### 选项 B · 治理收口（阶段 8 冻结的前置条件）
- **做什么**：① 宪章修订签字（§10.5/§17.6 记录/裁决分离）；② **提交动作收敛到单一写者**（或加回滚检测门）——本轮已被回滚两次、P23 被回滚三次；③ 7 项 CI 红逐项定性（哪些是“门本身错”、哪些是真缺陷）并清零。
- **工作量**：中-大（CI 红里至少 `CON-API-CONTRACTS`/`CON-DOC-SYMBOLS`/`THREAD-BUDGET`/`CON-TRACEABILITY` 涉及门本体重写）。
- **收益**：阶段 8 冻结的**必要前提**；否则冻结永远差“CI 通过”一项。
- **前台建议**：**A 之后立刻接 B**（或与 A 并行，CI 红不冲突于 phase1 代码）。

### 选项 C · 缺陷账本处置（785 条）
- **做什么**：按 `问题扫描` 的域处置表逐条销账；**优先级最高的是被 SUMMARY 点名的系统性根因**：机器门“**看着在跑、实际不会红**”（注释门空壳、线程预算门对 `std::thread`/裸 `omp` 不可见、追溯门无条件 `return 0`、`io_ownership` 累加 failures 却不进退出码、CLI 协议族打在兼容二进制上……）。
- **工作量**：**大**（650 条待修 + 374 条缺处置表；80 条需你裁决）。
- **收益**：直接决定“发布前提是否可证伪”，是**质量面最大的一块**。
- **前台建议**：**先做 P0 门族**（估计 20-30 条，是“门不会红”的根因），其余按域滚动；**不建议一次性全铺**。

### 选项 D · Windows / Fatduck 移植验证（阶段 9）
