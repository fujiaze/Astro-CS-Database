# 研究协议（RESEARCH_PROTOCOL）

> 控制包 SCI-RES-01 的作业规程。**研究包与重构包（PROJECT-GOVERNANCE-01）是两条独立流程**：研究包只产出「可被负责人批准的结论 + 文档修订提案」，不直接改工程实现。

## 1. 研究包的定位

- 触发：重构执行中暴露出「最新权威文档里没有数值/没有定义」的点（例如 GAP-024 的默认值缺口）。
- 产出：科学课题结论（数值 + 适用域 + 不确定度 + 反例）+ 对 docs/science 或 docs/algorithms 的**精确修订提案**（逐字写清改哪一段、改成什么）。
- 不产出：实现代码、工程重构、合同 schema（这些归重构包）。
- 结论生效方式：提案经**负责人批准**后，才允许改 docs/science/** 与 docs/algorithms/**（这两处是冻结权威，Agent 无权自行改）。

## 2. 铁律

1. **禁止编造数值**。没有推导、没有文献依据、没有数据支撑的数值一律不得写入结论；只能登记为仍缺依据。
2. **先定义后取值**：任何数值必须给出定义式或判据（量纲、适用域、边界行为），再给取值。
3. **权威只读**：docs/science/** 与 docs/algorithms/** 在研究阶段只读；研究产出是提案，不是改动。
4. **可复跑**：每个结论附可复跑命令（脚本 + 输入 + 输出路径），脚本放 run/SCI-RES-01/<课题ID>/ 或 tools/research/<课题ID>/（后者需在提案里说明是否入库）。
5. **反例必备**：每个结论必须给出至少一个「取错值会怎样」的反例（阈值过松/过紧的后果）。
6. **不确定度**：给出建议值的可接受区间与敏感度（结论依赖哪些假设、假设变了值怎么变）。
7. **不得沉默取舍**：研究中的任何简化必须写明删去了什么、影响多大。

## 3. 单个课题的产出格式（固定）

1. 问题陈述（要定什么量、为什么必须定）；
2. 现有权威依据（逐条引用，含「查无此项」的检索口径与命令）；
3. 定义与量纲（含符号表）；
4. 方法与推导（可复跑脚本路径）；
5. 结论（建议值 / 取值范围 / 适用域 / 反例）；
6. 对权威文档的修订提案（逐字 diff）；
7. 残余不确定性（仍缺什么才能收紧）；
8. 复跑命令与证据路径。

## 4. 状态词

- NOT_STARTED → IN_PROGRESS → CONCLUSION_READY（结论与提案就绪，待负责人批准）/ BLOCKED（缺数据/缺设备/缺定义）；
- 批准后由重构包执行文档修订，状态转 LANDED。

## 5. 与重构包的关系

| 事项 | 归属 |
|---|---|
| 默认值/阈值/密度的**数值确定** | 研究包（本包） |
| 把批准后的数值写进 docs/science 或 docs/algorithms | 研究包出提案 + 负责人批准 + 重构包执行 |
| 把数值转录进 config/defaults.json | 重构包 CFG-001（引用研究结论，自行不裁定） |
| 工程规范清单对齐（ENGINEERING_SPEC §7 等） | 重构包 |
