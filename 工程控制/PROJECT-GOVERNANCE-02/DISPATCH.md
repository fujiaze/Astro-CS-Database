# PROJECT-GOVERNANCE-02 · 派发与验收

## 1. 角色

- **前台（后台常驻）**：读权威、拆工作包、派发、复核证据、**唯一 git 写者**（commit/push）、裁决冲突、维护 claim 编号与验收文档。
- **执行线（子代理）**：按任务卡执行、自跑四门、交自证摘要 + 证据日志；**零 git 写**；可自行再派子代理（须在回执里列出被派线与其写域）。

## 2. 任务卡格式（派发时必给）

```
ID / 标题
写域（允许改动的文件或目录，越界即回退）
禁止面（如 docs/science/** 冻结段、ci/**、问题扫描/**、reports/**）
入口条件（依赖哪条线已完成、需要哪些证据）
交付物（自证摘要路径 + 证据日志路径 + 改动文件清单）
验收判据（可执行：命令 + 期望 rc）
四门要求（D2）与构建目录（D1）
纪律引用（D3–D10 中与本卡相关的条目）
```

## 3. 回执格式（执行线回报，**限 40 行以内**）

1. 结论一行（做了什么 + 门结果）；
2. 改动文件清单（含行号区间，供后台提交时写归属）；
3. 四门逐条（命令 + rc + 日志路径:行号）；
4. 判据变更（如有）：旧判据 vs 现权威逐字依据 + 双向可假证据；
5. 未完成项与归属（D10）；
6. 跨域触及声明（改了本卡写域之外的文件必须显式列出并说明原因）。
**超过 40 行的细节一律放 `run/PROJECT-GOVERNANCE-02/<ID>/自证摘要.md`**，回执只给摘要与指针（避免上下文被报告吃掉）。

## 4. 验收流程

1. 执行线交回执 → 后台**先查门证据是否自洽**（rc、日志行号、是否增量目录）；
2. 后台按需**独立复跑**关键判据（至少一次，用后台自己的构建目录或静态复核）；
3. 通过 ⇒ 后台原子提交（每线一笔，显式 pathspec，逐条写归属）；不通过 ⇒ 退回并写明**哪条不满足**（不给整改建议以外的模糊评价）；
4. 跨域冲突 ⇒ 后台裁决（谁对：按权威条款与实测证据），必要时立案 ECP。

## 5. 举证要求（D9）与常见假绿（附录 H.5 族，必查）

| 假绿类型 | 检查方式 |
|---|---|
| 退化注入（注入体本身无效果） | 注入后**必须期望红**，且红的原因点名被测对象 |
| 空断言 / 空扫描面 | 打印被扫描对象计数；计数为 0 必须判失败或显式标注 |
| 门依赖 configure 缓存 | 全新目录首次 configure 必须可直接跑通（否则修 CMake） |
| 静默退化读入（`except: return ""`） | 缺失输入必须判失败或标 `UNREADABLE` |
| 恒真 / 恒返 0 / 结论与退出码不一致 | 打印 FAIL ⇒ 必须 rc≠0 |
| 生成物被手改 | 改生成器，不手改产物（D6） |
| 魔数冻结 | 计数由注册表/清单重算（D7） |

## 6. 冻结窗口

后台宣布提交点时，广播冻结窗口：执行线**停止写工作树**，只写 `run/`；窗口内后台跑整门（**全新目录全量重建**，防混合版本假红）→ 提交 → 广播解除。
