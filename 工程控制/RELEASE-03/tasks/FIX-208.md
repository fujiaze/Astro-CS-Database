# 任务：FIX-208 事件流默认输出 + 磁盘门收窄（§9.74）

## 目标

让事件流成为默认输出，资源门只剩磁盘，与 §9.74 裁决一致。

## 权威依据

- GAP_AUDIT.md §9.74 裁决 7-a（负责人逐字：「默认输出事件流。这样 gui 后续我可以用其他语言，直接捕获 cli……-y/-yes 这两个是我之前设计的，还有 -force」）
- GAP_AUDIT.md §9.74 裁决 10（负责人逐字：「不应该有资源超限（除非存储不足）。那个问题直接在跑前报 warn，写入磁盘满了报错……只考虑磁盘写满这一个问题」）
- ASTROCS_DESIGN.md §3.5（预检）、§6.3（事件流默认输出 + 唯一命令树）

## 改动范围（文件域，互斥）

允许改：`lib/infrastructure/cli/**`、`lib/infrastructure/observability/**`、`contracts/resource_gate_v1.json`、`tests/**`
禁止改：`docs/**`（DOC-203）、`config/templates/**`（FIX-207）

## 步骤

1. **事件流改为默认输出**（不需要旗标开启）；GUI 用其它语言直接捕获 CLI 输出；
2. 事件流**只有一份 schema**：字段名与事件枚举唯一；事件先后**只**由进程内单调序号决定；**stdout 无日志污染**；
3. **日志双通道同源**：人可读摘要与机器 JSONL 同源生成；单行 ≤ 4096 字节；绝对路径/盘符/UNC/凭据 ⇒ `<redacted>`；`level=error` 带来源/符号/状态三要素；
4. **资源门收窄为磁盘门**：跑前磁盘余量不足 ⇒ **warn**（不阻断）；运行中写盘失败/磁盘满 ⇒ **error**（fail-closed）；**内存/CPU/线程不设门**；
5. **退出码 10 收窄为「磁盘写满 / 写盘失败」**（一般性资源超限门取消）；
6. `-y` / `-yes` / `-force` **保留为正式接口**（`-force` 跳过全部检查直接运行）；
7. 其余旗标（`--strict-resource-gate` / `--on-resource-gate` / `--cpu-profile` / `--mode` / `--export-mode` / `--output`）**如实登记现状**，不赋予合同承诺。

## 验收门（可机器复跑）

- [ ] 不带任何旗标运行 ⇒ **有事件流输出**（默认行为）
- [ ] 事件流 schema 唯一（正/负例：注入第二种字段命名 ⇒ 判红）
- [ ] 磁盘满模拟（小 tmpfs）⇒ **运行中报 error**（fail-closed）；跑前余量不足 ⇒ **warn 且不阻断**
- [ ] 内存/CPU 无门（`grep` 证据：无相应 enforce 路径）
- [ ] `-y`/`-yes`/`-force` 三旗标存在且行为符合定义
- [ ] `ninja -C build` rc=0；`ctest` 全绿

- 不得在 main 外开分支
- 不得挂 waiver
- **不得为省事保留一般性资源超限门**
