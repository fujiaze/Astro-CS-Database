# 任务：FIX-203 提升键落地（§9.73 A44 后续）

## 目标

让合同声明但 CLI 缺失的键有载体，消除「合同键集 ≠ CLI 键集」的割裂。

## 权威依据

- ASTROCS_DESIGN.md §3.3（三命令通用输入合同：键名一律以命令行实际认的键为准）
- run/RELEASE-02/merge/MULTIBLOCK.md（MB 实测：`snr_path`/`precision` 在 `parser.cpp` 0 命中）

## 改动范围（文件域，互斥）

允许改：`lib/infrastructure/cli/**`、`ci/ledgers/dead_config_keys.json`、`tests/cli/**`
禁止改：`contracts/schemas/**`、`config/templates/**`（FIX-207）、`docs/**`

## 步骤

1. `snr_path` / `rotation_deg` / `crpix_px` 加入对应会话的 `config_fields()` + 白名单；
2. `precision` **不新造键**，统一用既有 `drizzle.precision_mode`（0=FP32 / 1=FP64）；mosaic/export 会话是否新增 `drizzle` 对象键**由本任务定并登记**；
3. 提升后**生产零消费**的键在 `ci/ledgers/dead_config_keys.json` 登记「**合同声明但生产零读取**」——**不得**让它们静默变 no-op；
4. `tests/cli/test_command_tree.py` 的 `FIELDS_MIN` 同步；
5. 实测：`mosaic --help` / `export --help` 含新键；`--template` 生成模板含新键。
