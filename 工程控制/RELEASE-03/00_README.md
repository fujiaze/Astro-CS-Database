## 5. 自主裁决授权（沿用 RELEASE-02 §3a，负责人明确授权）

执行 agent 按「**发现问题 → 派子 agent 研究 → 订正文档 → 修改代码 → 补 Oracle/负例 → 前台独立验证 → 统一提交**」
闭环自行推进；**一个问题走到闭环再进下一个**，不把技术问题原样上抛。

**可自行裁决并直接落地**：科学方法问题（有出处与推导即可走变更 claim）；门禁/判据问题（**改进门禁本身**，
配可执行正例/负例 + `--self-test`）；工程实现选型；P1/P2 差距与测试欠账；开源对照（GPL 只读不进仓库）。

**必须上呈负责人（穷尽列出）**：
- 发布/不发布、交付物是否合格的最终判定；
- **版本号与发布时间**；
- 改变顶层合同：三命令划分、JSON 输入输出合同的**结构性**变更、HiPS 产品数据模型的**破坏性**变更；
- 许可证存疑；
- **删除或覆盖 testdata / 用户数据 / 交付物**；
- 穷尽文献与实验后仍无法收敛、且存在互斥产品方向取舍的科学争议。
