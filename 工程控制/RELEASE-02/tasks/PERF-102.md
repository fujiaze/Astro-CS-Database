# PERF-102 性能验收（真实数据面必须零违约）

## 目标

FIX-E 优化后，在真实 L4 数据上复跑资源门，G-RES-01 零违约，性能指标达标。RELEASE-01 只做了基线（FAIL），本任务是验收。

## 判据（contracts/resource_gate_v1.json，真实数据面）

| 判据 | 内容 | 目标 |
|---|---|---|
| ① | 单阶段活跃计算线程 p50 | ≥2（RELEASE-01 mosaic 3/4 违约） |
| ② | 连续 ≥10s 利用率 <60% 且就绪线程中位数 >16 | 0 次 |
| ③ | 内存稳健增长斜率 | <32 MiB/s 且回收比例 ≥0.5（RELEASE-01 实测 45 MB/s，4/4 违约） |
| ④ | 均值 CPU 利用率 | ≥85%（RELEASE-01 normalize 仅 51–65%） |
| ⑤ | 分阶段利用率 p50 | ≥90% |
| ⑥ | 逐样本通过率 | ≥0.70 |

## 步骤

1. `python3 ci/resource_monitor.py --gate-required --gate-workers 16` 包裹两组 L4 全流程（或 `run_monitored.py` 等价入口），取真实数据判定；
2. 逐节点计时对比 RELEASE-01 基线（drizzle 56.2%/psf 13.1%/snr 11.6%/phot 10.7%），给出优化前后墙钟与占比；
3. Gaia 缓存：重复天区查询的命中率/查询合并证据；
4. 内存峰值、增长斜率、回收比例实测；mosaic 全阶段计时无盲区；
5. 负例面：串行注入 RESOURCE-GATE-REAL-NEG 必须判红。

## 验收门

- 六项判据在两组数据上全部达标、零违约（判据经 FIX-E 按 §3a 走证据改进并同步文档的，以改进后判据为准，但必须保留负例且判红能力不削弱）；
- 优化不改科学结果：E2E 1/N 一致性与合成 Oracle 同步复跑通过；
- 输出优化前后对比表、热点新排序、剩余热点与后续建议；
- 前台独立复跑，不用 record_only 结果充数。
