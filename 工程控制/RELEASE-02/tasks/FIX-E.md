# FIX-E 性能与资源编排

## 目标

消除 PERF-001 的 G-RES-01 违约，达到负责人要求的高资源利用率与低内存占用，为 PERF-102 真实数据面零违约负责。

## RELEASE-01 基线（问题证据）

- normalize 耗时：drizzle 56.2%、psf 13.1%、snr 11.6%、phot 10.7%；只有 drizzle 接近满载（12.8–13.7/16 核，80–86%），cal/phot/snr/psf 单线程化，整体均值利用率仅 51–65%；
- 判据③内存无界增长 4/4 normalize 违约：实测增长 45 MB/s（失败线 32），回收不足；
- 判据①mosaic 活跃计算线程 p50<2，3/4 违约；
- locality-aware 编排、cache_budget、Gaia 瓦片键/两级缓存/查询合并全部缺失（新文档语义）。

## 修复内容

1. **多核化**：calibration / photometry / snr / psf 节点按帧/按瓦片并行，消除单线程串行；mosaic 采样、天光面拟合、积分、写盘阶段保持足够活跃计算线程（p50≥2 且满足利用率门）；
2. **内存治理**：定位 45 MB/s 无界增长来源（疑似瓦片缓冲/中间帧不释放），实现显式生命周期与回收；流式分块，不用不占，cache_budget 上限可配；内存增长斜率 <32 MiB/s 且回收比例 ≥0.5；
3. **编排 locality-aware**：同一 HiPS 瓦片/同一帧的作业就近连续完成再切换，避免"A 做一半做 B 再回 A"的重复加载与缓存颠簸；作业调度顺序、瓦片亲和、阶段衔接由子 agent 推导最优方案并写设计说明；
4. **Gaia 客户端缓存**：同一组天区查询最大复用——瓦片键缓存、两级（内存/磁盘）缓存、查询合并（in-flight 去重）；命中率与重复查询数有指标；
5. **drizzle 热点**：占比 56%，在多核化后重新 profile，按新热点排序优化（向量化/内存布局/IO 重叠），优化前后有计时对比；
6. 天光面/权重按需求值（FIX-A/C）本身即是内存优化的一部分，联合验证。

## 方法要求

- 先量化再优化：每轮优化前后保留 wall time、逐节点耗时、CPU 利用率、活跃线程 p50、内存斜率/峰值、缓存命中率；
- 不改科学结果：所有优化后重跑 1/N worker 一致性与合成 Oracle，数值不变（允许浮点重排容差内）；
- 判据若经实测证明不合理（阈值无依据），按 §3a 改进判据并同步文档，不得放松判据凑绿。

## 验收门（真实数据面，CI RESOURCE-GATE-REAL）

- 判据①活跃计算线程 p50≥2：0 违约；判据③内存斜率 <32 MiB/s 且回收≥0.5：0 违约；
- 均值 CPU 利用率 ≥85%（判据④）、逐样本通过率 ≥0.70（判据⑥）；
- normalize 均值利用率较基线 51–65% 显著提升（目标 ≥85%）；mosaic 墙钟中无 profile 覆盖的盲区补齐阶段计时；
- Gaia 重复查询第二次起命中缓存（有日志/指标证据）；
- 全部结论有 `run_monitored.py --gate-required --gate-workers 16` 复跑证据。
