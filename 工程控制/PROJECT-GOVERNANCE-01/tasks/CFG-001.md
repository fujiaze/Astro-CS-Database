## 目标

落位根 `config/defaults.json` 与 `config/filters.json`，并为 normalize/mosaic/export 建立 phase_config schema 与模板，使 cpu_profile 混入科学配置必然失败。

- UNIFIED_MODEL §3 规定 `cpu_profile` 缓存于程序安装目录。

## 改动范围（文件域）
### 允许改
- `config/**`（新建）
- `contracts/schemas/*config*`、`*profile*`、`*manifest*`
- `tests/config/**`
- `docs/contracts/**`（配置语义与索引）

### 禁止改
- 把 cpu_profile 字段（ISA/workers/block/CPU 型号）写入 phase_config
- 改算法默认公式与默认容差（默认值只能从 docs/science 转录）
- `cli/**` 实现（模板命令实现归 CLI-002）

## 步骤
1. 建 `config/defaults.json`：每个字段给出 value、unit、constraint、source（指向 docs/science 或 docs/algorithms 条款）；建 `config/filters.json`：滤镜名、带宽、零点，并标注来源。
2. 建三份 phase_config schema（normalize/mosaic/export）：只含科学参数、输入路径、输出 output_dir、算法选择；不含硬件字段。
3. 建 cpu_profile schema：绑定 CPU/OS/软件版本/provider hash 与 ISA/workers/block，声明只有 benchmark 可写。
4. 建 run_manifest schema：冻结源码 SHA、配置哈希、输入输出哈希、工具链版本。
5. 写负例：① 未知滤镜名 ② 缺 output_dir ③ precision 越界 ④ cpu_profile 的 workers/isa 出现在 phase_config。④ 必须失败。

## 验收门（前台独立复跑）
- [ ] 三份模板 JSON 均可通过对应 schema 校验（给出校验命令与 rc=0）
- [ ] 四个负例各自必败（逐条给失败输出）
- [ ] `config/defaults.json` 每个字段都有 unit 与 source（计数断言：字段数 == 带 unit 数 == 带 source 数）
- [ ] cpu_profile 字段名与 phase_config 字段名交集为空（给出可复跑断言）
