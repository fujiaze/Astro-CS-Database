# 任务：CLI-003 收敛机器输出、退出码与取消协议

状态：`NOT_STARTED`
层：L3　依赖：CLI-001, AIO-001, RT-001　文件域互斥组：S7-B

## 目标

退出码以 `include/astrocs/exit_codes.h` 为唯一源并与 §6.3 表一致；`--json` 时 stdout 恰一个 JSON 文档且无日志污染；取消返回 9 且不留完整产品。

## 基线状态（编制时实测）

- 现有 `include/astrocs/exit_codes.h` 与 `cli/exit_codes.h` 需核对是否为同一处定义。
- `cli/jsonl.h`、`cli/protocol.h` 已存在，但需核对 `schema_version/event_id/run_id/kind(progress|resource|artifact|backend|final)` 字段。
- `ci/checks.json` 的 `UT-CLI`、`CON-*` 系列绑定旧协议。

## 权威依据
- ASTROCS_DESIGN.md §6.3（配置挂载、机器输出、退出码表 0/2/3/4/5/6/7/8/9/10/70、取消协议）
- ENGINEERING_SPEC.md §9（统一状态码、JSONL 事件、不跨 C ABI 抛异常、未捕获异常 exit 70 + 脱敏 crash report）

## 改动范围（文件域）
### 允许改
- `lib/infrastructure/cli/**`
- `include/astrocs/exit_codes.h`（唯一源）
- `contracts/schemas/*event*`、`*run_record*`
- `tests/cli/**` 协议测试

### 禁止改
- stdout 日志污染
- 跨 C ABI 抛异常
- 新增未登记退出码
- 失败后留下看似完整的产品

## 步骤
1. 把退出码收敛到公共头唯一源，删除 `cli/` 下的重复定义（若存在）。
2. 实现 `--json` 的 stdout 契约：恰一个 JSON 文档；日志/进度走 stderr 或 JSONL 事件流。
3. 定义 JSONL 事件 schema：`schema_version`、`event_id`、`run_id`、`kind` 及各自必需字段。
4. 实现 Ctrl-C 协作取消：关 writer → 写 incomplete manifest → 删/隔离临时产物 → exit 9。
5. 测试：每个退出码的触发路径；未捕获异常 → 70 + 脱敏 crash report（不得含密钥/绝对私有路径）。
