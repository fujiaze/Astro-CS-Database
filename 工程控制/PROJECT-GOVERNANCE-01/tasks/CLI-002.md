## 缺陷登记（2026-09-16 · TEST-CLI-SYNC 实测，GAP-034）：export 无合法配置可运行

**现象**：新命令树下 `export` 的**预检**与**会话层**对 `source` 的形态要求互斥，不存在能同时通过的配置；唯一可跑通路径是 `-force` 绕过预检。

**证据**：
1. `lib/infrastructure/cli/subcommand.h:62-68` —— 对 source 只做 `is_array()/is_string()` 计数，对象形态恒记 0 ⇒ 判 `error` 阻断（实测 rc=2，报「source 为空：没有输入产品」）；
2. `lib/phase3_session/p3_session.cpp:84-87` —— 要求 `source.hips_dir`（对象+字符串），故 `"source": "<路径>"` 被拒（missing source.hips_dir）；
3. `export --template` 产出 `"source": ""` 与 `"center": [0.0, 0.0]`，与会话层要的 `source.hips_dir` + `center.ra_deg/dec_deg` 不一致 ⇒ **模板填好也不能直接运行**；
4. 仅 `-force` + 会话口径配置可 rc=0（实测产出 `output_phase3.fits` / `p3_*.json`）。

**违反条款**：ASTROCS_DESIGN §3.5（预检分级与 force 白名单语义：force 只能越过可强制项）、§6.1（模板输出**可直接运行**的完整 JSON）、§6.2（七行命令树）；docs/plugins/infrastructure/18_cli.md（薄入口 + 模板生成）。

**验收门（本任务修完后必须成立，前台独立复跑）**：
- [ ] `export --template -o t.json` 产出的 JSON，**不加 -force** 直接 `export --json t.json -y` → **rc=0**（模板可直接运行）；
- [ ] 预检能正确识别 export 的 source 形态（对象 `source.hips_dir`）并给出 correct 判定；
- [ ] `-force` 的白名单语义与 §3.5 一致（只越过可强制项；口径冲突类必须仍然阻断）；

**连带**：TEST-CLI-SYNC 会把 export 相关用例保持为**显式红**（不 skip、不 -force 掩盖），待本任务修复后转绿。

三命令的 `--template` 产出可直接运行的完整 JSON；运行前预检按绿/橙/红分级；error 存在时强制阻断，只有 `-force` 可越过白名单项，`-y` 不能越过 error。

## 改动范围（文件域）
### 允许改
- `lib/infrastructure/cli/{normalize,mosaic,export}/**`
- `config/**` 的模板文件（与 CFG-001 协调，模板值不得偏离 defaults）
- `tests/cli/**` 预检/确认测试

### 禁止改
- 改变科学默认值
- 让 `-y` 绕过 error
- 让 `-force` 绕过白名单外的错误
- 把预检逻辑塞进算法模块

## 步骤
1. 实现 `--template [-o <path>]`：输出填好默认值的完整 JSON，字段带单位与约束（或在 `help` 中给字段说明）。
2. 实现预检分级：`correct`（可自动纠正）/`optimize`（建议）/`error`（阻断）三类，逐条给出检测项与判定依据。
3. 实现确认流程：交互输入 `yes` 或 `-y`；error 存在时 `-y` 仍阻断。
4. 实现 `-force` 白名单：只允许越过缺校准帧类可强制项，越界项报 rc=2。
5. 三命令同构测试矩阵：同一组输入对 normalize/mosaic/export 分别断言模板、预检、确认、force 行为一致。
