> 研究线交付「决策建议书」，负责人只需**确认或否决**，不必自己做调查。

## 研究线共同要求（每条都适用）

研究（**不是**整改）任务，**零 git 写**；交付落 `reports/PROJECT-GOVERNANCE-01/research/<ID>_<主题>.md`。每份必须含 6 节：

1. **权威原文**：逐条抄录相关权威条款（`文件:行` + 逐字原文），并标注其在 `ASTROCS_DESIGN §0` 权威链中的位置；
2. **外部依据**：标准/文献/参考实现怎么说（如 astropy/WCS 论文、SCI 引文、NumPy 语义），**能跑实验的必须跑**并给命令与输出；
3. **实现事实**：当前代码实际行为（命令 + 逐字输出 + `文件:行`），与 1/2 逐条对照；
4. **⭐ 门禁自审**：**这条门（或这条判据）本身是否正当**——① 有无权威依据；② 是否可测量、可复现；③ 是否把「实现缺陷」误判成「文档错误」或反之；④ 阈值/量测域是否定义清楚；⑤ 是否会误报/漏报。**若门本身错，直接说「门应为 X」并给依据；**
5. **建议裁决**：给出**唯一推荐结论** + 置信度 + 反方论证（最可能被反驳的点）+ 最小改动路径（改哪份文档/哪个 registry/是否需要变更 claim）+ 影响面；
6. **证据清单**：全部命令、退出码、产物路径。

纪律：不得用「需负责人裁决」当结论（研究线的职责就是把裁决做到可决策）；不得改任何仓库文件；不得采信 `问题扫描` 账本的 `fix_state`。
