## 1 要决策的一件事（单点）

> **drizzle 输入帧的逐像素 variance 块（AIO frame block "variance"）到底绑定到哪一条已冻结的方差来源？**
> 候选 A：噪声模型（SCI-NOISE / NoiseWeightModelV1）产出的**空背景逐像素方差场**；
> 候选 B：由既有 SNR 产品（local_snr/frame_snr，相对质量权重场）换算的方差；
> 候选 C：输入帧头 GAIN/READNOI + 饱和电平的即席方差（等价于 A 的一个特例，但不含 PSF/星点掩膜项）。

我方**不自行拍板**（前台裁决 §3）：本提案只给候选、影响面、判据与回退方案，请裁决并指派实施线。

## 2 为什么现在必须问（证据锚）

1. 引擎侧接线**已经存在**：drizzle_engine.cpp:1909-1912 仅在 varianceData != nullptr 时累加 sumVarNum（:1557-1559）；hp_drizzle_api.cpp:1018-1043 读输入帧的 variance 块，注释即写「逐像素方差图，由 SNR 阶段 NoiseWeightModelV1 填充」；
2. writer 侧接线**本批已闭合**：astro_sphere_sink.cpp 的 write_hips_phase1 现在只要累加器含有限正方差即落 variance/ivar 子产品（DATA-P1-HIPS §12.1/§12.2/§4a）；
3. 但 `p1_op_drizzle`（module_adapters.cpp:2905+）**从不注入 variance 块**，`p1_op_noise`（:2683+）只把帧级标量 variance/ivar 写进 p1_snr.json（不是逐像素平面）⇒ 默认配置下 normalize 永远产不出 variance/ivar ⇒ mosaic 默认 weight_mode=2 fail-closed（IVAR-001 取证：rc=2「2/2 (3/3) frames missing ivar」）；
4. legacy 参考实现在 lib/infrastructure/pipeline/orchestrator/cpp/src/orchestrator.cpp:4681-4894（由 header GAIN/READNOI + PSF 星点掩膜 + 饱和电平构造 NoiseWeightModelV1），**但该目录当前不在根构建图**（根 CMakeLists 0 命中）⇒ 直接照搬无法被编译验证（前台裁决顺序 ① 已覆盖此点）。

## 3 候选与合同对齐

| 候选 | 合同依据 | 与 SCI-CW §1/§5 的关系 | 风险 |
|---|---|---|---|
| A 噪声模型空背景方差场 | docs/science/NOISE_MODEL.md §1/§7/§9a（本层唯一产出为逐像素 variance/ivar，ivar=1/max(variance,floor)）；SCI-NOISE 公式权威 | 一致：SCI-CW §5 明令 frame/local SNR 不得替代科学方差，A 正是「另有一条方差来源」 | 需定义「空背景」估计域（含/不含天体）、floor 取值、星点掩膜的判定；A 的 floor 与 F-UNC-001 的 0/NaN 语义必须同批定 |
| B 由 SNR 产品换算 | 无（§20.3 红线段落明确禁 support 冒充 ivar；SCI-CW §5 禁把相对质量权重当科学方差） | **冲突** | 不推荐；若选 B 必须同时改 §20.3/SCI-CW §5 并做双向可假门 |
| C 头关键字即席方差 | 部分（GAIN/READNOI 是噪声模型输入之一） | 一致但不等价于 A（缺 PSF/掩膜/饱和项） | 与 NOISE_MODEL 的产出重复，可能造成两套方差 |

## 4 变更内容（若裁决为 A，实施线按此拆单）

1. `p1_op_noise`（module_adapters.cpp:2683+）：调用 snr_noise_model_v1 / _f64 / _fill（ABI 已冻结）产**逐像素** variance 平面，落盘为节点产物（建议 `p1_variance.fits`，单位 ADU²，NaN/0 语义与 §4a 对齐）并在 p1_snr.json 增加指向键；
2. `p1_op_drizzle`（:2905+）：读该平面并以 aio_frame_add_block(frame, "variance", AIO_BLOCK_FLOAT32/FLOAT64, ...) 注入（读端 hp_drizzle_api.cpp:1018-1043 无需改）；
3. `write_hips_phase1`：**本批已接线**（有方差即请求 VARIANCE|IVAR 并交 var_num_sum），无需再改；
4. `p1_op_writer`：**本批已改**为磁盘事实回读（products/uncertainty_available 由叶 tile 事实决定），无需再改；
5. 合同面（需负责人/前台处置，本线不擅改）：DATA_SEMANTICS §7（Phase1→Phase2 交接枚举）增列 variance/ivar，与 §20.1/§20.3 口径收敛；

## 5 影响面

- **产品**：Phase1 HiPS 默认新增 variance/、ivar/ 子产品（成对）；文件数/体积增加，manifest 哈希面变化；
- **接口**：新增节点间产品（p1_variance.fits）需登记 artifact/UnitId（ADU²）与 contracts/schemas 面；
- **科学**：mosaic 默认 weight_mode=2 从「默认不可用」变为「默认可生产」，uncertainty_available=true 成为默认；
- **性能**：多一次逐像素噪声估计 + 一块方差读写（须给 CPU/内存预算数值后再定阈值）；
- **兼容**：旧 Phase1 产物无 ivar ⇒ 行为不变（仍 fail-closed 或显式降级），无静默兼容问题；
- **回退**：见 §7。

## 6 判据（受理与验收）

1. 正例：合成夹具（含已知方差）→ normalize → mosaic 默认（缺 weight_mode 键）端到端 rc=0，且 p1_final.products=[signal,support,variance,ivar]、uncertainty_available=true、mosaic p2_final.weight_basis=per_sample_ivar、ivar_product_missing_frames=0；
2. 数值判据：逐像素 variance 与注入真值的相对误差门（建议 <1e-3，取决定性可复现夹具）+ ivar·variance=1（<5e-3）；对已知方差解析场的 oracle 比对（NOISE_MODEL 层已有 numpy oracle 资产可复用）；
3. 负例（双向可假门）：注入「方差平面缺失」⇒ 必须回到 fail-closed rc=2（既有门 + ASTROCS_IVAR_FAULT=silent_fallback 红臂）；注入「方差平面被 support 顶替」⇒ 必须判红；
4. 不得跌破：ninja 0 FAILED、ctest 全绿（计数不降）、锚点门 rc=0；未放宽任何既有断言。

## 7 回退方案

- 单点回退：以配置开关（或编译期默认关闭）隔离 p1_op_drizzle 的 variance 注入；关闭后行为与当前一致（产物面逐字节不变，mosaic 默认仍 fail-closed）；
- 数据回退：已产出的 variance/ivar 子产品可整体删除（writer 对无方差输入的路径本批已验证逐字节不变）；
- 合同回退：不触及任何 SCI 冻结式；若裁决为 B 类（需改 §20.3/SCI-CW §5）则本提案作废，另起工程变更。
