## 4. 科学工作纪律（最高优先级）

- 三个创新点是 alpha 发布的必要条件，**实验未证实不声称科学正确、不进入发布门**；
- 每个结论三重佐证：DOI/arXiv 核验过的论文、开源项目+版本+文件:行、仓内实测（最高设计 §12.1）；
- 三类数据相互印证：HST 真实信号物理仿真、纯解析代数合成（含非退化负例）、testdata 真实数据（§12.2）；
- 负责人明确说过：**他提出的方法不一定对，科学文档也不一定对**。发现前提可疑时，派子代理查一手文献与开源实现、做实验裁决，按"发现问题 → 研究 → 订正文档 → 修改代码 → 补 Oracle/负例 → 前台独立验证 → 统一提交"闭环推进，不把技术问题原样上抛；
- 实验若证明负责人思路不成立，带证据、替代方案与推荐意见上呈，不擅自改顶层设计。

## 5. 自主裁决授权

可自行裁决并落地：科学方法问题（有出处、推导与实验即可走变更）；门禁/判据问题（改进门禁本身，配可执行正例/负例与 `--self-test`）；工程实现选型；P1/P2 差距与测试欠账；开源对照（GPL 代码只读不进仓库）；历史代码与工件的清理（按 ENGINEERING_SPEC §2/§9，删除清单在任务回执中逐项列出）。

必须上呈负责人（穷尽列出）：

- 发布/不发布、成品帧是否合格的最终判定；版本号与发布时间；
- 顶层合同结构性变更（三命令划分、JSON 合同结构破坏、HiPS 数据模型破坏）；
- 三个创新点经实验证明不成立、或存在互斥产品方向取舍；
- 许可证存疑；删除/覆盖 testdata、用户数据、交付物。
