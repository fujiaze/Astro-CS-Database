# 未来算法接入指南（本支线禁止执行）

本文件只供底层合并 `main`、用户完成其他算法逻辑验证后使用。

## 1. 接入门槛

只有经真实计时确认是显著热点、且改造收益明显高于维护成本的模块才接入。CPU一两秒完成的普通模块默认不改造。

首批候选可以是 Drizzle、批量积分/叠加等，但必须在未来独立集成分支中重新审计，当前 ACR 分支不得触碰。

## 2. 最小改动模式

- 独立元素：`parallel_for`；
- 图像块：`parallel_tiles`；
- 求和统计：`parallel_reduce`；
- 独立对象：`parallel_batch`；
- scan/FFT/GEMM/冲突scatter：专用 adapter。

算法作者只写单工作项或单Tile逻辑，选择 TaskClass，不管理设备和比例。

## 3. 不可盲拆

- 前项依赖后项；
- 多工作项写同一位置且未声明原子/归约；
- 循环内I/O、虚函数、复杂全局状态；
- 无设备可编译实现；
- 数据迁移成本明显大于收益。

## 4. 分支

后续从最新 `main` 创建独立算法集成分支，不继续使用 `feature/astrocompute-runtime`。每个算法单独验收，不一次性重构全项目。
