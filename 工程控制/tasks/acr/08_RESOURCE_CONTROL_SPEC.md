# 资源占用控制

## 1. 资源目标与路由分离

```yaml
cpu_target: 0.95
gpu_target: 0.95
io_target: 0.95
ram_limit: 0.95
vram_limit: 0.95
```

- CPU/GPU/I/O：软利用率目标；
- RAM/VRAM：容量上限；
- 这些参数不表示CPU/GPU任务比例；
- 路由只由硬件画像、任务特征、数据驻留和当前队列推算。

## 2. CPU

- 所有可用逻辑线程均可进入ACR arena；
- 不通过永久少开一个线程实现95%；
- 使用任务粒度、队列水位、提交节奏、worker让步和优先级控制平均占用；
- 控制窗口建议100～500ms；
- 线程错峰让步，不做全线程长时间同步睡眠；
- 保持取消、状态和GPU submit响应；
- 记录所有worker是否参与。

## 3. GPU

- 通过queue/stream深度、batch大小、kernel时长和提交节奏控制；
- 显示GPU优先短batch；
- 不允许无界排队；
- 利用率API不可用时按队列预算估算并明确标记；
- 多GPU独立控制；
- 目标95%允许稳定波动，不承诺每毫秒精确。

## 4. RAM/VRAM

```text
limit = min(total * ratio, total - fixed_reserve)
```

达到上限：停止新提交、缩小块、释放可重建缓存、选择低内存路径、回退其他设备或明确失败。

## 5. 控制器允许反馈，但不学习性能

控制器可根据实际利用率调节提交节奏。这是资源闭环，不是路由模型在线学习。它不得修改：

- 算术/内存/卷积性能曲线；
- 设备成本模型；
- hardware-profile；
- Qualification原始数据。

## 6. 配置

用户可配置目标、容量、后端启用和回退策略；不得提供CPU/GPU share参数。

## 7. 验收

资源控制器可在50%、80%、95%、100%目标点做测试，以证明控制功能。这里的百分比仅是设备利用率目标，绝不是任务切分测试。报告平均、p95、误差、worker参与和系统响应。
