## 1. 三层 CI 架构（固定为 V2 门禁拓扑）

| 层 | 宿主 | 职责 | 不可豁免门 |
|---|---|---|---|
| L1 虚拟机门 | GitHub ubuntu-24.04 / windows-2022 | 编译 + 合成数据 + 静态/文档/合同检查（现 ci-linux.yml runs-on ubuntu-24.04、ci-windows.yml windows-2022，profiles linux-main/windows-main） | 每个 push：LINUX-GATE、WINDOWS-GATE（编译+全量合成测试+文档/合同）|
| L2 本机 Linux 真实数据 | 本机（testdata 30G、GaiaDR3 41G、GaiaDR3SP 64G 在位） | REAL-000/001/VIS-001 全流程（校准/solve/Phase1/2/3/九宫格/拉伸预览） | REAL-GATE：REAL-001 报告 + VIS-001 视觉判定 + STD-F1 九宫格无 1px 偏移 |
| L3 Fatduck Windows 真实数据 | self-hosted [self-hosted, fatduck-realdata]（现 fatduck.yml 已在） | 同 SHA Windows 候选 benchmark + 真实数据 Windows 复验（子集；若负责人批准传 GaiaDR3 41G 则全流程） | FAT-GATE：同 SHA digest 复核 + 复验结论 |

原则：L1 失败不进 L2/L3；L2 失败不进 L3；三层产物均绑定同一 source SHA 与数据 manifest 哈希。
CI 注册表（ci/checks.json）为唯一事实源：任何新测试目标必须同提交注册检查项（STD-F7 处置）。

## 2. 主线/修复双线与并行度（取代"串行单飞"）

- **repo-write lane 容量 1 保持**（同工作区 tracked 写互斥），但**并行度来自多 lane**：
  read-only(4) + realdata(1) + windows(1) + owner(1) 同飞，max_parallel 提升至 6。
- **写域互斥分组**：V2 任务全部声明精确 write_scope；不同目录域的任务排队进入
  repo-write，同域必须串行、跨域天然错峰；禁止"整轮串行等待"。
- **CI 修复线（常驻）**：每轮结束时前台拉取上一轮全部 CI 报错（GitHub Checks API /
  run/ci/monitor/*.json），生成 `run/ci_repair/<round>/FINDINGS.json`；下一轮派发
  `CI-REPAIR-xxx` 任务与主线并行（域=ci/、tools/、.github/），修完必须在本轮
  GitHub 双虚拟机复跑绿后才可闭环。
- **轮次节奏**：一个"轮"= 一批并行任务 + 一次全量 L1 CI 复跑 + 轮报（含上一轮 CI 结果回拉）。

## 4. V2 任务谱系（草案，46 任务；写域互斥→并行错峰）

- **R0 CI 订正线**（并行于一切）：CI-REG-002（新测试全注册+关键检查 waivable=false+
  known-failures 基线机器化+astropy 依赖登记）→ CI-REPAIR 常驻线。
- **R1 治理/标准线**：STD-REG-001（docs/standards/STANDARDS_REGISTRY.md）；
  STD-F1 裁决落地（owner 选 a/b/c 后原子任务）；DOC 状态收敛。
- **R2 科学缺陷线**（互相独立，可轮内并行）：STD-F2（phase2 integrate 拒绝剔除）、
  STD-F3（AIO NREJ/NUSED+五键通道）、WCS-001 遗留锚（NB_GRID=7 与 81×81 文档一致性）等。
- **R3 架构线**（依赖 R2 相关项）：RT-001 唯一 Executor（拆 RT-001a registry 接入/
  RT-001b 模块私池拆除/RT-001c 资源门接线）；MOD-001a 安装树/b loader/ABI verify/
  c 产品 manifest 生成；CLI-001a validate/plan/b run 薄化/c inspect。
- **R4 CI 平台线**：CI-001b（workflow 与注册表联动核死）；CI-002 双虚拟机同 SHA 门。
- **R5 真实数据线**（本机）：REAL-000 → REAL-001（三层验收+99% 硬门+九宫格）→ VIS-001。
- **R6 Windows 线**（Fatduck）：WIN-000（数据面准备：候选+子集清单或 GaiaDR3 传输裁决）
  → WIN-001 复验。
- **R7 收口**：DOC-001、AUD-001（含 V1 未竟的 ARCH-AUDIT-P1、BASE-UTIL-001）、PACK-001。
