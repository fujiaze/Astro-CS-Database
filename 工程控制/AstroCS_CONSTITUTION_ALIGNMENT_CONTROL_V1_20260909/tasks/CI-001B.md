1. ci-linux.yml/ci-windows.yml 与 ci/checks.json profile 联动核死：workflow 只调用 ci/run.py（不复制业务命令）；2. windows candidate 缺失路径与 WIN-PACKAGE-CANDIDATE 不可豁免联动（候选缺失必须 FAIL，不得 warning 跳过）；3. actions SHA lock 维持并复验。

## 写入白名单
- `.github/workflows/`
- `ci/`

## 非目标与禁令

- 不 reset/stash/clean/rebase；不创建 branch/worktree/clone；SubAgent 不 git add/commit/push。
- 新增/修改测试必须同提交注册 CI 检查项；运行产物禁止落根目录。

## 必须动作
1. 审计 workflow 全部 step 与注册表检查一一对应；2. 负向：构造候选缺失场景，验证 WIN-PACKAGE 门 FAIL 而非跳过；3. workflow 语法校验 + 手动触发双虚拟机验证。

## 验收
- write_scope 零越界；候选缺失场景 FAIL（非 warning）；双虚拟机 run 绿；三 SHA 一致。
- 一个任务一个原子 commit 并 push main。

## 返回证据
