# 工程控制 / RELEASE-01 启动文档（00_README）

## 1. 目的

本控制包执行 AstroCS 预览版发布前的**收尾验证**：以负责人提供的最新文档包为权威，完成文档替换、设计-实现差异审计、科学自审与文献对照、逐模块构建冒烟、测试审查补充、全流程真实数据端到端、视觉验证、性能计时与优化，交付成品帧给负责人验收；负责人认可后收尾并准备发布 `0.0.1 alpha`。

## 2. 方向与范围

- **权威来源**：负责人上传的**最新文档包**（36 篇，含 `ASTROCS_DESIGN.md`、`AGENTS.md`、`ENGINEERING_SPEC.md`、`ACCEPTANCE_SPEC.md`、`CONTROL_PACK_SPEC.md`、`docs/` 全部分级文档、`docs/research/SNR_WEIGHT_RESEARCH_PACK.md` 研究包）；
- **执行对象**：仓库 `Astro-CS-Database` 当前 main（执行 agent 先前已推送全部实现）；
- **科学立场（最高优先级）**：负责人明确指出——**设计意图在大纲里，但负责人提出的方法不一定对，科学文档也不一定对**。执行 agent 必须依据真实论文、真实开源代码对 `docs/science/`、`docs/algorithms/` 与实现代码进行自审、校对，并**补充参考文献、参考代码库等到科学文档中**，不得盲从文档或代码（见 AGENTS.md §8 查证流程与 `docs/research/SNR_WEIGHT_RESEARCH_PACK.md`）；
- **范围**：仅发布准备相关验证与必要修正；不引入新功能、不改变已验证科学口径（除非科学自审证明文档有误，走 ENGINEERING_SPEC §3 变更 claim）。

## 3. 文档包替换说明

- 负责人**先**将最新文档包（zip）上传并解压到仓库（替换现有文档集）；本控制包第 1 个任务 `DOC-001` 即为"核验文档包已正确替换"；
- 文档包替换是负责人显式授权的**一次例外**（GOVERNANCE-02 例行纪律排除文档集替换）；执行 agent 不得再次自行替换文档包内容；
- 替换后所有后续任务的权威条款一律以新文档包为准，旧文档残留（如旧版本号、旧目录）按 `DOC-001` 清单清理。

## 4. 执行入口

- 触发：负责人指示"执行 RELEASE-01"；
- 前台 = 执行 agent（调度 + 独立验证 + 统一提交）；SubAgent = 干活的手（零 git 写权限）；
- 任务按 `TASK_LIST.md` 的依赖图串并行执行：先 `DOC-001`，随后 `AUD-001 / SCI-001 / BLD-001 / DOC-002` 并行，`TST-001` 紧随 `BLD-001`，全部通过后 `E2E-001`，再 `VIS-001` 与 `PERF-001`，随后 `DEL-001`，负责人认可后 `FIN-001`；
- 每个任务独立验收（验收门见各任务文件），PASS 由前台写入 `ACCEPTANCE.md`；
- 全部任务 PASS 后前台写 `SUMMARY.md`；`FIN-001` 完成后由负责人决定发布。

## 5. 交付物（最终）

1. 验收记录 `ACCEPTANCE.md`、阶段汇总 `SUMMARY.md`、差异审计 `GAP_AUDIT.md`；
2. 科学文档修订（含新增参考文献、参考代码库清单）与变更 claim 记录；
3. 全流程真实数据运行日志、视觉验收图（整幅 PNG + 分块 PNG + 可疑区域裁剪放大）、性能计时与热点分析报告；
4. 两个成品帧平面 FITS（R 通道，M42 与 Galaxy Center 两组）——**只交付负责人检查**，不推发布；
5. 负责人认可后：更新 README、设置 CLI `--version` 为 `0.0.1alpha`、发布包白名单/哈希/provenance 就绪。
