# 任务：AUD-001 设计-实现差异审计

## 目标

以新文档包为权威，派大量 SubAgent 并行扫描仓库实现，产出**结构化差异清单 GAP_AUDIT.md**，覆盖所有模块与数据流。

## 权威依据

- CONTROL_PACK_SPEC.md §3（制作流程：SubAgent 只找不改、证据可复核、差距类型枚举）
- ASTROCS_DESIGN.md（最高权威）+ docs/plugins/ 各插件文档 + docs/design/UNIFIED_MODEL.md + docs/science/ + docs/algorithms/
- ENGINEERING_SPEC.md（代码/测试/提交规则，检查器覆盖清单）

## 改动范围（文件域，互斥）

- 允许改：本任务**不改代码**；只写 `GAP_AUDIT.md`（差异审计表，含证据路径）
- 禁止改：任何源码、测试、配置、文档（只找不修）

## 步骤

1. 按方向分片派 SubAgent：按模块（normalize 8 模块 / mosaic 5 模块 / export 3 模块 / infrastructure 7 模块）+ 按横向条款（CLI 契约、config/、契约 schema、CI 检查器）分片并行扫描；
2. 每 SubAgent 输出结构化偏差证据：文件/行/命令 + 对照的文档条款号；
3. 前台汇总去重，按差距类型分类：`缺口（未实现）`、`违规（与文档冲突）`、`过时（文档已撤销仍存在）`、`漂移（实现偏离文档细节）`、`无主（有代码无合同）`；无法判定登记 `UNRESOLVED`；
4. 每条差距给出：条款引用、现状复现路径、影响面、建议归属（哪个后续任务修）；
5. 差距分级：P0（阻断发布，必须修）/ P1（发布前应修）/ P2（可登记遗留）。

## 验收门（可机器复跑）

- [ ] GAP_AUDIT.md 全模块覆盖：normalize/mosaic/export/infrastructure 每个模块至少一条审计结论（含"无差距"）;
- [ ] 每条差距含条款号 + 可复现证据（文件/行/命令）;
- [ ] 分级完整：P0/P1/P2 与建议归属齐备;
- [ ] P0/P1 差距与 E2E-001、VIS-001、PERF-001 的修复合规路径对应（不静默跳过）;
- [ ] SubAgent 零代码改动（git status 干净，仅 GAP_AUDIT.md 变更）。

- 差距可能被 SCI-001 的科学结论推翻（如文档公式有误）——P0/P1 在 AUD/SCI 合并裁决后确定最终归属。
