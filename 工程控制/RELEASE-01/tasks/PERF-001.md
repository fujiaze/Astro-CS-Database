# 任务：PERF-001 性能计时与热点优化

## 目标

对全流程各阶段做**耗时计量与资源分析**，定位热点（CPU/内存/IO/编排），优化到"CPU 利用率接近满载、内存占用合理且无无界增长、编排无低效切换"（最高设计 §8 与 ACCEPTANCE_SPEC L2）。

## 权威依据

- 最高设计 §8（内存极简化、编排连续性与数据局部性、资源分析先行、G-RES-01）
- ACCEPTANCE_SPEC L2（G-RES-01 判据、CPU 利用率、内存工作集、线程扩展、编排连续性、缓存复用指标）
- docs/plugins/infrastructure/19_runtime.md（locality-aware 编排）、21_observability.md §8（G-RES-01）、22_gaia_xpsd_client.md（缓存复用）

## 改动范围（文件域，互斥）

- 允许改：性能相关实现（调度、分块、缓存、内存管理、IO 路径）；性能测试与计时脚本
- 禁止改：科学公式与数值结果（优化不得改变产品数值，1/N worker 一致、Oracle 一致必须复验）

## 步骤

1. **计时基座**：对 E2E-001 的运行日志/资源记录做分段计时（normalize 各模块、mosaic 各模块、export 各模块），输出每流程耗时表与累计占比；
2. **热点定位**：按耗时占比与资源记录定位热点——CPU 热点（单线程长计算/无并行）、内存热点（峰值/无界增长/重复分配）、IO 热点（读写字节、I/O wait）、编排热点（上下文切换/块重载/worker 空转、缓存未命中）；
3. **资源分析先行**：每个待优化模块给出峰值工作集估算、缓存复用点、调度顺序与切换次数（预估值），与实测对照；
4. **优化**：按最高设计 §8 原则实施——locality-aware 编排（一块连续节点一次走完、块间流水、work stealing 防空转）、流式内存（工作集=当前块+显式依赖、用完即释、按需现场求值）、缓存复用（Gaia 查询合并 + 两级缓存 LRU、缓存字节预算）；优化以不改变科学结果为前提；
5. **复验**：优化后重新运行受影响流程，验证：数值一致（1/N worker、Oracle）、G-RES-01 零 enforce 违约、峰值 RSS 随块大小而非总数据量增长、同组 Gaia 查询外部请求计数为 1、编排指标达标（空转率/切换/搬运量）；
6. 归档：优化前后对比表（各流程耗时、CPU 利用率、内存峰值、缓存命中率、编排指标）、热点分析报告、`benchmark` 输出（安装目录，自动读取）。

## 验收门（可机器复跑）

- [ ] 全流程分段计时表与热点分析报告归档（优化前基线 + 优化后对比）；
- [ ] G-RES-01 enforce 项零违约、record_and_justify 无未解释超标；
- [ ] 无单线程跑满全程、无连续 ≥10 s 低利用窗且队列有工作；均值/p50 利用率达标或超标有合理解释；
- [ ] 峰值内存随分块大小而非总数据量增长（流式验证），无无界增长；
- [ ] 优化不改变科学结果：1/N worker 一致、Oracle 对拍一致（复验通过）；
- [ ] 缓存复用与编排连续性指标达标（同组 Gaia 外部请求计数 1、块重载/切换次数显著下降）。

## 边界

- 性能优化不得以牺牲科学正确性为代价；"接近完美"= 科学正确 + 性能达标，两者缺一不可；
- 优化不出的瓶颈登记 UNRESOLVED 上呈负责人（含证据与分析），不静默降级。
