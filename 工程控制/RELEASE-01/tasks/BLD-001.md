# 任务：BLD-001 逐模块并行构建与小规模冒烟

## 目标

由 **1 个负责构建的 SubAgent 分管**，把不同模块派发给**不同的次级 SubAgent**，并行完成各模块独立构建与小规模冒烟测试，暴露编译/链接/接口/运行级问题。

## 权威依据

- ENGINEERING_SPEC.md（构建、模块 manifest/注册表/ABI、测试规则、检查器）
- docs/ci/（检查项怎么跑）
- 各插件文档的"接口/ABI"与"测试与 Oracle"节

## 改动范围（文件域，互斥）

- 允许改：本任务只**构建与测试**，不改实现；若冒烟发现缺陷，登记缺陷条目（文件/行/现象），由前台分派修复任务（可回本任务文件域或专门任务）
- 禁止改：科学公式、默认容差、契约 schema（冒烟阶段不改科学口径）

## 步骤

1. 分管 SubAgent 读取构建基线（cmake/ninja/ctest）与模块清单（lib/algorithms 并联模块 + lib/infrastructure），设计并行分组；
2. 按模块派发次级 SubAgent（每模块一个或按依赖聚组）：normalize 8 模块、mosaic 5 模块、export 3 模块、infrastructure 7 模块；每次级 SubAgent 完成：模块独立构建 → 模块级单测/冒烟 → 1/N worker 一致性 → 结果证据（日志、rc、产物路径）；
3. 汇总冒烟结果：绿模块清单、缺陷清单（编译/链接/运行/数值）、失败原因初判；
4. 与 GAP_AUDIT.md 差距对照：冒烟发现的缺陷补充进差距清单或直接转入修复任务；
5. 修复后的模块**重新构建 + 重新冒烟**，直至全部模块冒烟绿。

## 验收门（可机器复跑）

- [ ] 全模块独立构建 rc=0（cmake + ninja 全目标）；ctest 全绿；
- [ ] 每模块冒烟测试有证据（命令 + rc + 产物路径）记录在 ACCEPTANCE.md 对应行；
- [ ] 1/N worker 一致性：冒烟覆盖的模块输出数值一致（容差按合同）；
- [ ] 缺陷清单清零或全部转 P0/P1 修复任务并已修复复验；
- [ ] 构建产物无隐藏平台依赖（Linux amd64 基线可用）。

## 边界

- 次级 SubAgent 零 git 写权限，只构建测试取证；
- 冒烟数据用合成/最小真实数据，不做全量真实数据（那是 E2E-001）。
