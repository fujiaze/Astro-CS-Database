# 任务：TST-001 测试审查与补充

## 目标

**独立审查 BLD-001 冒烟所用的测试是否合理、是否真在验证科学条款**，补齐缺失的测试（负例、Oracle 对拍、不变量、边界、并行确定性），防止"空断言/SKIP 充数/检查器静默退化"。

## 权威依据

- ACCEPTANCE_SPEC.md（L1 合成 Oracle、负例面、每核心检查可执行负例；L2 性能指标；L3/L4 端到端）
- ENGINEERING_SPEC.md §5（测试规范、合同测试、可执行负例、Oracle 对拍）
- 各插件文档"测试与 Oracle"节

## 改动范围（文件域，互斥）

- 允许改：测试代码、测试数据生成脚本、测试配置（test/、tests/、scripts 下测试相关）；为暴露真实缺陷的最小修复登记后转修复任务
- 禁止改：科学公式与默认容差；产品代码（除非审查证明实现缺陷，登记转修）

## 步骤

1. 审查 BLD-001 冒烟测试覆盖：是否每条核心合同都有独立测试、是否每条检查有**可执行负例**（注入错误必判红）、是否有 SKIP/空断言/无断言测试；
2. 逐模块对照插件文档"测试与 Oracle"节与 ENGINEERING_SPEC §5，列出测试缺口矩阵（模块 × 测试类型：合同/负例/Oracle/不变量/边界/并行确定性/性能）；
3. 补充缺口测试（含 L1 合成 Oracle 对拍用例、能红能绿负例、1/N worker 一致、流式/缓存/编排指标用例）；
4. 对"看起来通过"的测试做严格性抽检：断言强度、容差合理性、是否测到真实计算路径（非短路）；
5. 补充后全量跑测试，记录前后对比（测试数、覆盖、负例数）。

## 验收门（可机器复跑）

- [ ] 测试缺口矩阵填满：无空白缺口或全部登记转修；
- [ ] 每个核心检查具备可执行负例（`--self-test`/`--fault-inject` 注入必判红）;
- [ ] 无 SKIP 充数、无空断言、无静默退化；抽检报告存档；
- [ ] 补充后 ctest 全绿，且新增负例在无注入时全绿、注入时全红；
- [ ] 测试覆盖（按合同对象）达到 ACCEPTANCE_SPEC L1 通过标准。

## 边界

- 测试合理性的判断以"是否验证科学条款"为准，不以"数量多"为准；
- 发现产品缺陷只登记证据，修复由前台分派（不越权改产品代码）。
