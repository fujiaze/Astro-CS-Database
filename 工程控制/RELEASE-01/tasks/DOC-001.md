# 任务：DOC-001 文档包替换核验

## 目标

核验负责人上传的最新文档包已正确替换仓库文档集，清理旧文档残留，建立"新文档包为权威"的基线。

## 权威依据

- 负责人指示：先替换新的文档包
- CONTROL_PACK_SPEC.md §3（制作纪律：逐条引用、现状可复核）
- 文档风格红线：正向表述、无头部元信息块、无治理 ID/日期/历史叙事、Mermaid 图文并茂

## 改动范围（文件域，互斥）

- 允许改：`docs/` 与根目录 `*.md` 文档（与负责人上传的最新文档包对齐）
- 禁止改：`lib/`、`testdata/`、`config/`、`contracts/`（本任务只核验文档，不改实现）

## 步骤

1. 比对负责人上传的最新文档包（36 篇）与仓库现有文档，列出差异文件清单（新增/删除/修改）；
2. 将文档包内容替换到仓库对应位置（保留文档包内目录结构）；
3. 清理旧文档残留：旧版本号（`0.1alpha` 等）、旧目录引用、已撤销历史口径、治理痕迹（日期/commit/任务 ID/历史叙事）；
4. 全局搜索校验：`0.1alpha`、已废弃目录名、无头部元信息块、无治理 ID 残留；
5. 验证文档内引用互相可达（每个 `docs/...` 相对引用指向存在的文件）；
6. 建立一致性基线：抽取 3–5 条最高设计硬约束，确认与实现代码当前状态可对应（只登记，不改）。

## 验收门（可机器复跑）

- [ ] 文档包替换后 diff 为空或仅含授权差异；文档数量与结构一致；
- [ ] `grep -rn "0.1alpha" docs/ 根目录 *.md` 无命中；旧目录名无命中；
- [ ] 无头部元信息块、无治理 ID（R-4/SC-FIX/GAP-xxx 等）残留；
- [ ] 文档间相对引用可达性检查通过；
- [ ] 一致性基线登记表（3–5 条硬约束 ↔ 代码现状）写入 GAP_AUDIT.md 附录。

## 边界

- 文档包内容是负责人定稿，不擅自增删语义；只做替换、清理残留与可达性核验；
- 发现文档包内部矛盾时登记 UNRESOLVED 上呈负责人，不自行裁决。
