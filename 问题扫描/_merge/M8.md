## 0. 元结论（两条，本域对全局的贡献）

### 0.1 「门在三个方向上是空集」（本域元结论，落点 M8-G-001）

仓内存在一批**能失败的门**（`check_ctest_registration.py` 有 C1-C6 + S1-S7 负例自检、`validate_registry.py` 有 R 规则、`check_standards_registry.py` 有 C1-C6、`ci/run.py` 有退出码与 known_failures 挂账），但它们的审计对象都不是「应当被执行的东西」，而是「已经被登记的东西」。于是三向同时为空：

- **方向①：测试源存在，但从未注册**（M8-F-005：实测 61 个 C/C++ 测试源在 CMake 非注释行 / `ci/**` / Makefile / `tools/**/*.py` 全部零命中）⇒ 注册门从 `add_test` 出发，看不见它们。
- **方向②：被采集，但采集数为 0**（M8-F-001：`tests/abi` 5 个测试文件里 4 个无 `TestCase`；M8-F-008：组名漂移后循环体一次不跑；M5b-F-01 已定稿的 `CI-BINDING-TESTS -p test_ci001b_*.py` 只命中 2/21）⇒ `R4` 只验 `-s` 目录**存在**，不验用例数，`Ran 0 tests / OK` 退出码 0。
- **方向③：证据文件存在，但从不执行**（M8-F-004：`STANDARDS_REGISTRY.md`/`TEST_MATRIX.md`/`TRACEABILITY_MATRIX.json` 把从未编译的 .cpp/.c 记为 CONFORMANT 的验证；判定器 `C3_evidence_path_*` 的唯一判据是 path_exists，且 `_clauses` 解析后被丢弃）⇒ 符合性判定与执行面脱钩。

三条建议门（写进 M8-G-001 建议处置，均为"改判据方向"而非"加门"）：
1. **discover 采集数 > 0 硬门**：`ci/validate_registry.py` 对命令为 `unittest discover` 的检查项，增判「`-s` 目录内 TestCase 子类数（或 `-p` pattern 命中文件数）> 0」，为 0 即 FAIL。
2. **测试源未注册即 FAIL**：`tools/quality/check_ctest_registration.py` 增反向枚举规则——磁盘上的 `*_test.cpp\|test_*.c` 未出现在 `add_test` 且不在显式 LEGACY/ARCHIVE 白名单即 FAIL；并把 `ci/**`、`*.sh`、`*.ps1`、`Makefile`、`tools/**/*.py` 一并纳入"执行面"匹配集。
3. **EVIDENCE 路径必须出现在执行面**：`check_standards_registry.py` 的 C3 由 path_exists 升级为「路径 ∈ `ci/ctest_baseline.json` ∪ `ci/checks.json` ∪ discover 采集根」三者之一，同时把该判定器自身注册进 `ci/checks.json`（消除"只被文档引用"）。

同仓正对照（防过判，均已在条目内引用）：`check_ctest_registration.py::C6`（无 glob 的登记名必须出现在 command 参数里）、`p1cos/p1cal/p1noise` 的 `*_tests_selfcheck.cpp` 故障注入必败自检、`p1star_test_main.hpp:97` 的 unknown-group 守卫、`p2hips\|aio_abi` 的同类守卫、`UT-CPU-AVX2/AVX512` 成对 runner、`CTEST-LINUX-FULL`（`waivable=false`）、`tests/artifact/test_provenance.py::TestDeterministicDigest`（真断言 + 被 UT-ARTIFACT 采集）。
