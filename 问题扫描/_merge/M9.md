## 2. 三条 P0 的独立复验结论（前台必问项 1）

**结论：L24-001 / L24-002 / L24-003 三条 P0 全部独立复验成立**，且本代理各补一项叶子未记的加重事实；另对本域新增 P0（L26-001）做量纲复算。

1. **L24-001 → M9-H-1（H_NUMERIC/P0）成立并加重。** 复验：`json_append_escaped`（module_entry.c:384）确无容量入参；`head[512]`（:738）三处 `hw += snprintf(hw, (size_t)(head+sizeof(head)-hw), …)`（:741/:770/:774）用应写长度推进；`memcpy(hw, schema, schema_len)`（:766-768）无界；`json_append_escaped(&hw, c.catalog_dir)`（:776）配 `char catalog_dir[1024]`（:211）。第二站点 `gaia_inspect`（:930-:940）在指针越界后 `buf+sizeof(buf)-w` 变负 → size_t 巨量，逐字命中。**本代理补充两项**：①越界长度会被回读进产品——`total = (uint64_t)(hw - head)`（:808）+ `memcpy(big, head, (size_t)(hw - head))`（:857），而 :816-817 作者自述「head 是栈缓冲…严禁作为 total 长度源直接拷贝」恰被该行违反 → 产品 manifest 携带栈相邻字节（信息外泄），不只溢出；②触发点前移——`cap==0` 的"仅报尺寸"分支（:830-841）同样执行整段拼装，故**两阶段协议的第一次调用即已溢出**。越界面独立复算：前缀+schema(127)+spec 三段 ≈ 300–390 字节，余量 120–210，catalog_dir 1023 字符全转义膨胀 2046 → 越界上限约 1.9KB（与叶子同量级）。正对照（同文件同族）：`strbuf_write`（:101-105）容量不足即 `ACS_ERR_PARAM` + `BUFFER_TOO_SMALL`；`json_copy_str`（:144）`c = n < dst_cap-1 ? n : dst_cap-1`。
