- 问题说明: 漂移之所以普遍且门抓不到，是三条结构性缺口叠加，不是个案疏漏：①**判据弱**——门只判"可解析 + 目标存在 + 行号在 1..目标行数内"，界内错锚 100% 放行（C3 的语义只是越界）；符号绑定只有 41 条且"任一锚命中即通过"，同一符号被多处锚共享时（`integrate.cpp` 一个文件 16 锚共享 :49）界内检查在 ±100 行漂移下几乎不可能触发；②**语法面外**——223 处表格裸 `:NNN` 锚不匹配 ANCHOR_RE；③**作用域外**——doc_globs 只有 science/algorithms 两目录，docs/owner、docs/architecture、docs/contracts、docs/modules、README/AGENTS/CHANGELOG 全部不在门内，而这些正是承载"当前提交实测绿"结论的层。外加 git 异常 fail-open：无 timeout、返回非 0 即跳过两项跟踪检查并照常输出 DOC_LINE_ANCHORS_PASS。
- 影响: L0/L3 文档中"当前提交内可核"的行锚成片失效（本域复算 4/4 抽点全错），核对者按锚打开会读到无关代码，据此做出的"实测绿"判断不可信；门持续输出 PASS 造成"锚点已被机器守护"的假象（同 §12.3-12 缺口，见 M6b-G-005）。
- 建议处置: ①锚一律迁移为 `path::symbol` 形态并把 41 条 binding 扩为「每条锚至少一个符号断言」；②doc_globs 扩到全部 ACTIVE_NORMATIVE 文档（`docs/DOCUMENT_INDEX.yaml` 可直接作为作用域输入）；③新增"裸 `:NNN` 单元格锚"采集（或禁止该形态）；④`git_ls` 加 timeout，git 失败输出 TOOLING_FAILURE 并 exit 3（与本仓"不允许伪 PASS"一致）；⑤C4 改为逐锚判定而非"任一命中即通过"。
