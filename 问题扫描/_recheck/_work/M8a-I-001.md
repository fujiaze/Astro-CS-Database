- 问题说明: 这是"**标准本身缺该要求**"的一族（与 M8a-G-006/-007 的"有要求无门"相对，后者定 G_GOV_GATE P1）。宪章的 README 硬义务只覆盖"可独立调度的科学模块"，而该面 21/21 形式已满足 —— 于是负责人点名的"每子库 README"在条文层无处落脚，基建/CLI/tests/tools/cmake/ci 共约 35 个单元既无义务也无门，长期无人追责是**制度后果**而非执行懈怠。要素层同样缺三件（构建安装/偏差登记/状态词），所以即便 README 存在，也不能据标准判定其"要素齐备"。 **另须登记的宪章↔树不一致（§1.1 要求此类不一致必须建 finding）**：§8.4 的义务范围写作 `lib/algorithms/ 中每个可独立调度的科学模块`，但按本代理复算（口径：glob `lib/algorithms/**` = **0 文件**；grep lib/algorithms 于 `CMakeLists.txt` 与 `docs/` 均 **0 命中**），该目录在本仓不存在 —— 于是 §8.4 的 README/module.yaml 硬义务对实际 21 个模块（全部落在 `lib/<module>/`）**字面不成立**，这是"每子库 README 无条文"的机制性原因，不是执行懈怠。
- 影响: 负责人诉求无法验收（没有可判据）；`lib/core` 与 `cli/` 无 L2 入口文档，新人/Agent 只能靠 L3 生成物与口传。
