### M5b-G-16 CLI 配置模板把产物写到仓库根，AGENTS.md 禁而 CLI_PROTOCOL 认，门只豁免不拦
- 类别: G_GOV_GATE · 建议优先级: P1
- 位置: `cli/commands.cpp::kConfigTemplate`（现 :97-101，`\"output_dir\": \".\"`）；`cli/commands.cpp::（output_dir 回退默认，多处）`（现 :842、:1042、:1218、:1483）；`cli/commands.cpp::cmd_bench_cpu 默认输出`（现 :2286）；`docs/api/CLI_PROTOCOL_V1.md::§7`（现 :63、:74）；`ci/checks.json::UT-CLI.dirty_ignore_prefixes`（现 :1407-1415）；`ci/known_failures.json::failures[UT-CLI]`（现 :44-66）
- 证据摘录:
  >   \"output_dir\": \".\"
  > CLI 不得以进程 CWD(\".\")作为隐式缺省写出,否则在工作区根散落产物并触发
  >     "dirty_ignore_prefixes": [ "astrocs_run_", "run/" ]
- 权威依据: AGENTS.md 目录规范「禁止将运行产物产出到项目根目录」「CLI 运行产物 `astrocs_run_*.json` 一律落 `run/cli_runs/`」；宪章 §14.2、§12.3-11
- 问题说明: `config init` 产出的模板即把产物目录设为 CWD，CLI 各路径的 `output_dir` 缺省回退同样是 `"."`，`benchmark cpu` 未给 `--output` 时默认写 CWD `cpu_profile.json` ⇒ 合规调用 `astrocs phaseN run --config <config init 产物>` 必然在仓库根生成运行产物；`CLI_PROTOCOL_V1.md:74` 已记载该缺陷未解（且 :63 自身与 :59 的 `run\|graph --out-dir <dir>` 允许值表述互斥），治理侧的处置是把 `astrocs_run_`/`alloc_`/`resource_`/`worker_balance.csv` 加进 UT-CLI 的 dirty 豁免集（现 :1407-1415）并把 UT-CLI 以 `expected=fail` 挂账到 2026-12-31（known_failures 现 :44-66，其 reason 字段自认"根因在 cli/commands.cpp 产物默认落点"）⇒ **以豁免替代修复**，目录规范机器面失效。
- 影响: 工作区根持续被运行产物污染（本会话工作树内即可观察到）；豁免集使"CLI 运行是否写根目录"永久不可判定。
- 建议处置: 模板与所有回退默认改 `run/cli_runs/`（或强制 `--output`）；撤 dirty 豁免，把"无根目录残留"做成 `no CWD residue` 负向判据；解除 UT-CLI 挂账。
- 置信度: 高 · related: M5b-G-18、M5b-C-04
