### L24-001 Gaia 模块 manifest 拼接：snprintf 返回值推进指针 + 转义无容量参数 → 栈缓冲越界写
- 类别码: H_NUMERIC（主）；次挂 C_DOC_CODE_GAP、G_GOV_GATE
- 优先级: P0（前台已逐字复验锚点）
- 位置:
  - lib/gaia_xpsd_client/src/module_entry.c::gaia_execute（char head[512]，:738；hw += snprintf(...) :741/:770/:774；json_append_escaped(&hw, c.catalog_dir) :776）
  - 同文件::gaia_inspect（char buf[512] :930；json_append_escaped(&w, inst->cfg.catalog_dir) :939）
  - 同文件::json_append_escaped（:384，签名为 (char** w, const char* s)，无剩余容量入参）
  - 站点参数来源：同文件 gaia_cfg::catalog_dir 为 char catalog_dir[1024]（:211）
- 权威依据: 宪章 §14.4（信任边界含 CLI/配置输入与用户可控数据，须 fail-fast 返回明确状态码）、§8.6（跨 DLL 边界返回稳定状态码）、
  §11（不得吞错后继续生成看似成功的产品）；同文件 :24-27 自述的输出事务合同（尺寸查询→写入，不足→PARAM+BUFFER_TOO_SMALL）
  **只覆盖出参 strbuf，未覆盖这两个内部栈缓冲**
- 问题说明: 三重缺陷叠加。①转义函数逐字节无界写入；②snprintf 返回「本应写入的字符数」而非实际写入数，代码用它直接推进 hw，
  一旦头部（module_id+op+schema+spec 三字段与键名，实测约 330-390 字节）+ catalog_dir 超过 512，hw 越过数组末尾继续写；
  ③静态算术：head 剩余约 121 字节，而 catalog_dir 容量 1024、转义后最坏 2046 → 越界写最多约 1900 字节；
  gaia_inspect 更严重——w 越过 buf+512 后 (size_t)(buf + sizeof(buf) - w) 变成负数的 size_t 巨值，
  随后 snprintf 以近无限 max 继续格式化写出。不是"截断显示"级问题，是缓冲区溢出。
- 影响: astrocs_catalog_gaia 是随产品清单发布的官方模块；execute 是每次星表查询必经路径、inspect 是 host 诊断必经路径。
  触发条件仅要求 catalog_dir 超过约 121 字符——Windows 深路径、网络盘、含空格目录都会命中。后果为栈破坏：
  随机崩溃或被构造的目录字符串操控返回地址；Phase1/Phase2 均以该模块取参考星与光谱，属发布阻断级。
- 建议处置: ①json_append_escaped 增加剩余容量入参并返回是否溢出；②所有推进点对 snprintf 返回值取 min(返回, 剩余) 夹紧，
  越界即返回 ACS_ERR_PARAM/INTERNAL 并停止产品提交（只在边界校验一次，不在 CLI/AIO/算法层重复）；
  ③head/buf 改为「先精确计算所需长度再一次性分配」，与同文件出参两阶段合同同口径；
  ④负向用例：catalog_dir 120/121/1023 字符 + 含引号反斜杠 + 控制字符，断言不越界且状态码正确（ASan 版 ctest 注册）
- 置信度: 高（前台复验）
- related: S1-001（同族堆版：lib/hips/src/module_entry.cpp::hips_execute_write_product，预算 384u+strlen+64u 且同用无容量转义函数）

### L24-002 XPSD 自报 spectrumCount 无上限即用作每星 memcpy 长度 → 堆越界读 + OOM 放大
- 类别码: H_NUMERIC（主）；次挂 G_GOV_GATE（§14.4 外部文件解析边界）、B_STD_MISMATCH（Gaia DR3 光谱 343 列固定面）

  唯一处置点为「等于 0 才兜底」（:2049-2050、:2089-2090、:2240-2241、:2431-2432）
- 权威依据: 宪章 §14.4（外部文件解析属真信任边界；明文要求对"会造成数据破坏、安全问题或 ABI 未定义行为"的输入校验）、
  §5.3/§7.3（科学路径数值语义不得静默漂移）；D.catalog（Gaia DR3 光谱波段数固定 343）
- 问题说明: spectrum_count 来自文件内 XML parameters 字符串的 atoi，全文件**从未校验其是否 ≤343、是否为负、
  是否超过记录可用长度**。星记录在块内可用字节由 STAR_STRIDE_SP=384 固定，块长度又受限于文件自报的 block_size，

  同文件其它自报计数都有上限（tree_count<16、file_count<MAX_FILES、magnitude 判 NaN/Inf 回落），说明作者知道这道防线，唯独此处漏。
- 影响: XPSD 是从外部拉取的持久化产品（GaiaDR3/、GaiaDR3SP/），属不受信输入。后果 ①堆越界读（崩溃或把相邻堆内容当光谱字节）；

  gaia_client_cone_search_with_spectrum），即**污染测光定标所用光谱数值且不报错**（宪章 §11 禁止的吞错继续）。
- 建议处置: ①建立"文件自报计数"统一上限策略：1 ≤ spectrum_count ≤ WL_COUNT，越界即整文件拒绝并给显式损坏状态码
  （边界之后信任 typed contract，不在查询路径重复校验）；②spectrum_start/step/bits 同样校验；
  ③spec_collector_push 的 memcpy 长度改为 min(spectrum_count, 记录剩余可读字节)，源不足返回错误；
  ④负向用例注入 spectrumCount=0/1/343/344/65535/-1 六个 XPSD，断言拒绝与不越界（ASan 注册）
- 置信度: 高
- related: L10-008（同一 load_xpsd_file 的 header_len 弃用与 root_pos/child 不设限——本条是该族第四个未校验字段）

### L24-004 XPSD 魔数/长度校验失败不解除映射，句柄随下一次 memset 永久失联（P1）
- 类别码: G_GOV_GATE（主，违 §14.4 fail-fast 应带资源回收）；次挂 H_NUMERIC
- 位置: lib/gaia_xpsd_client/src/gaia_client.c::load_xpsd_file 失败返回点 :1034（前台已复验该行原文：
  `if (xf->mmap_size < 16 || memcmp(xf->mmap_data, XPSD_MAGIC, 8) != 0) return -1;`）；唯一回收处 ::close_xpsd_file；
  调用方 ::gaia_client_create_ex 目录扫描循环两条
- 问题说明: 三重叠加。①映射建立后的第一个校验直接 return -1，跳过本文件自己写明的两条回收路径；
  而上游三个失败分支（打开失败 / hMap 失败 / mmap 失败）都就地回收 → 是漏项不是风格。
  ②调用方只在 load 返回 0 的分支调用 close_xpsd_file，返回 -1 时无补偿。③放大：file_count 不自增，
  下一个候选文件用**同一下标**进 load_xpsd_file，函数首行 memset(xf,0,...) 把上次的 mmap_data/fd/hMap/hFile 清零 →
  映射与句柄在本进程内永久不可达，destroy 也救不回。另该路径不区分「太短」「魔数不符」「读取截断」，
  与 §14.4 要求显式损坏状态码不符。
- 影响: 目录中每有一个损坏或非 XPSD 的 *.xpsd，每次 create 永久泄漏 1 映射 + 1 fd（或 2 内核句柄）；
  MAX_FILES=32 使单次有界，但 plan/create 在一次 run 中可多次调用 → 长跑表现为 fd 耗尽与地址空间持续增长。修复面极小。
- 建议处置: 该 return -1 前统一走已有回收（或引入单一 fail 标签）；调用方对非 0 返回值也调用 close_xpsd_file
  （该函数对 mmap_data==NULL 幂等）；注入「长度 8 的文件」与「魔数为 XPSD0000 的文件」并断言 fd 数不增。
- 置信度: 高（代理本轮一度误判为假，按符号重读两处调用点后确认为真 —— 该自我纠错过程保留为方法证据）

### L24-005 read_leaf_block 用文件自报偏移与长度直接寻址映射区，无映射长度约束（P1）
- 类别码: H_NUMERIC（主，越界访问面）；次挂 G_GOV_GATE

- 问题说明: block_offset 与 data_position 全部来自文件，相加后与 mmap_size **无任何关系校验**；
  compressed_size 与 block_size 亦互相独立，唯一校验是解压后 dest_len==block_size（事后）。字段撒谎或文件截断时：

- 影响: 畸形/截断 XPSD → 段错误；或把映射外兄弟数据当星块解压 → ra/dec/mag/光谱全部错位，
  而调用方无法区分「正确解压」与「读错区域解压出垃圾」，属静默错误科学数据。
- 建议处置: 在 load_xpsd_file 末尾（解析完全部树、返回 0 之前）做一次性块区间模型校验：
  每叶节点要求 data_position+block_offset+max(compressed_size,block_size) ≤ mmap_size，任一不满足即整文件拒绝
  （显式损坏状态码，与 hiss 同口径）；读取热路径不重复校验，只留 assert/不变量注释指回该校验；
  负向用例补「只截断数据段而保留头」的 XPSD（现有 negative 模式覆盖不到字段撒谎）。

### L24-006 树节点数组分配失败被 break 吞掉，仍返回成功并少注册若干棵树（P1）
- 类别码: G_GOV_GATE（主，违 §14.4 禁「宽泛处置后继续」与 §11 禁吞错）；次挂 C_DOC_CODE_GAP

  函数继续初始化块缓存并**返回 0（成功）**，调用方据此 file_count++ 并把该文件当完整数据集用。

  同函数其它静默点（字段缺失、find_max_block_size 返回 0）按「要么完整要么拒绝」复核；
  若确实希望「部分树可用」，必须变成显式契约：plan 上报完整性、execute 携带 PARTIAL 状态、禁止下游把 PARTIAL 当成功。

### L24-007 Gaia 配置数组计数循环可无限自增（strtod 不推进时不消费字符）（P1）
- 类别码: G_GOV_GATE（主，违 §14.4 配置输入边界 fail-fast）；次挂 H_NUMERIC（活性 + CWE-190）
- 位置: lib/gaia_xpsd_client/src/module_entry.c::json_get_f64_array :191-192（前台复验原文：
  `while (*q && *q != "]") {` / `if (*q == '-' || (*q >= '0' && *q <= '9')) { count++; strtod(q, (char**)&q); }`），
  消费点 ::gaia_cfg_parse 的 ra_list/dec_list
- 问题说明: 设计意图是「数字起头则 strtod 消费，否则手动 q++」，但 '-' 属数字起头而 strtod 在无法转换时**不推进 endptr**
  （输入如 `[-]`、`[1,-,2]`、`[1e]`）→ *q 仍是 '-'、循环条件恒真 → **count 无限自增且永不推进**，进程挂死；
  count 为 int，持续自增另构成有符号溢出 UB。第二遍 :199-202 用 `i < count` 夹紧，故**不会**越界写数组 —— 本条只登记活性与 UB。
  另 count 无上限，超大数组 → malloc(count*8) 与 plan 阶段内存预算（§10.5/§14.4）脱钩。
  该解析器被 validate_config / plan / create 三处调用 → 模块生命周期每一步都可被一次配置挂死。
- 建议处置: ①计数循环记录 prev=q，strtod 后若 q==prev 即判语法错误（*out_n=-1 返回 NULL）——把「零推进」显式判为非法；
  ②对 count 设登记常量上限，超限返回 ACS_ERR_PARAM 而非分配；③负例 `[-]`、`[1,-,2]`、`[]`、`[1e]`、超大元素数各一，
  断言不挂死且状态码明确，挂在已注册的 gaia ABI 测试面
- 置信度: 高

### L24-008 HiPS SNR 目录读出的容量入参为 int 且未判负，(size_t) 强转使负值变巨值（P1）
- 类别码: H_NUMERIC（主）；次挂 C_DOC_CODE_GAP（头合同未声明该入参域与负值语义）
- 位置: lib/astro_image_io/src/hips/aio_hips_reader.cpp::aio_hips_read_snr_catalog :519/:526（前台复验：
  `int n = (int)std::min((size_t)max, d->snr.size());`）；合同面 include/aio_hips_reader.h 该声明只写
  「调用方分配; 返回实际点数 (0=无)」，未写负值处理
- 问题说明: 调用方以 int 承载「失败/无数据」的 -1 哨兵并透传时，`(size_t)max` ≈ 1.8e19 → min 取 snr.size() →
  n 被赋为产品内实际点数（可远大于调用方缓冲），随后按 n 逐条写 ra/dec/snr/star_id/quality_flags/photometric_status
  **六个调用方缓冲** → 越界写最多 (snr.size()-max) 条 × 约 36 字节。
- 正对照（同文件即有正确写法）: `aio_hips_tile_ipix` 首行 `if (!d || !out_ipix || i < 0 || (size_t)i >= d->tiles.size()) return -1;`
  → 说明这是漏项而非有意设计。
- 可达性: 该 API 是 Phase2 采样与 stage2 读 SNR 的唯一入口（sampler.cpp:399/569、stage2.cpp:82、
  orchestrator.cpp:3906/4922 经 dlsym、healpix_browser_qt:350）。当前五处调用点均传正数（sampler 传 1<<20），
  故定性是「边界不设防」而非「已知必崩」；但 orchestrator 侧按函数指针动态调用，签名不匹配或未来任一调用方
  以 -1 表示「无缓存」即造成越界写。
- 建议处置: ①首行加 `if (max < 0) return -1; if (max == 0) return 0;`（与姊妹入口同口径）；
  ②头文件与 contracts/API_CONTRACTS.csv 该 API 行补写 max 定义域与负值语义；
  ③负例并入 hips_robust_sanitize_driver.cpp —— 但该 TU 目前只测 max=8 正例**且自身从不进构建**（见 L24-003）
- 置信度: 高

### L24-009 AHPX 权重/SNR 块按字节数 memcpy 进按 float 个数 resize 的缓冲（P1）
- 类别码: H_NUMERIC（主，堆越界写）；次挂 G_GOV_GATE（§14.4 外部文件解析）
- 位置: lib/astro_image_io/src/ahpx/aio_ahpx_reader.cpp::readSnr :572/:574 与 ::readWeight :633/:635；
  **正对照同文件 ::readPixels :546-549**（前台逐字复验，三处 memcpy 对比）
- 逐字对照: readPixels 先 `size_t expectedSize = (size_t)w*h*c*sizeof(float); if (rawData.size() != expectedSize) {…拒绝…}`；
  而 readSnr/readWeight 直接 `size_t floatCount = rawData.size()/sizeof(float); result.resize(floatCount);
  std::memcpy(result.data(), rawData.data(), rawData.size());`
- 问题说明: **分配 N*4 字节却拷 rawData.size() 字节**。块长度非 4 的整数倍（畸形或截断的 AHPX 尾部）时
  memcpy 越界写 1~3 字节到 vector 堆缓冲之外。同路径的 readPixels 明确做了等值校验 → 作者知道需要这一步，两处属漏项。
  次级：两函数也不校验块长度与 imageInfo 的 W*H*C 一致，故「块只覆盖 1/10 像素」的撒谎头会被静默当完整平面交下游
  （返回 vector 长度即 floatCount，消费方无从知晓它与几何不符）。
- 影响: AHPX 是 Phase3 投影/重采样的 tile 容器；readSnr/readWeight 的输出作为 SNR 平面与 drizzle 权重平面参与归一化与排异。
  ①堆元数据/相邻对象被 1~3 字节覆写（分配器相关崩溃或静默破坏）；②几何不符的短平面静默进入积分 →
  **科学数值被污染且不报错**（§11 禁止形态）。本仓自产 AHPX 恒为 4 的倍数，故外部产品是主要暴露面。
- 建议处置: ①与 readPixels 对齐（snr 至少校验 %4==0 且 ==w*h*c*4，不符返回空并打印期望/实际）；
  ②memcpy 长度改为 result.size()*sizeof(float) 或 min(dst_bytes, src_bytes)，杜绝任何源长于目的的拷贝形态；
  ③负例：块长度 4k+1 / 4k+3 / 截半，断言拒绝且不越界（注册 TU，见 L24-003）
- 置信度: 高（正反对照逐字复验）
