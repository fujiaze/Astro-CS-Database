### L17-001 追溯门禁 check_traceability 无条件 return 0，断链永不使 CI 变红
- 类别: G_GOV_GATE
- 建议优先级: P0
- 位置: tools/quality/check_traceability.py:157-163；ci/checks.json:37-61（检查项 TRACEABILITY）
- 证据摘录:
  >     print(f"traceability: rows={len(trace)} ok={rows_ok} broken={len(broken)} "
  >           f"symbols={sym_ok}/{len(symbols)}")
  >     return 0
  >       "id": "TRACEABILITY",
  >       "command": ["python3","tools/quality/check_traceability.py"],
  >       "waivable": false,
- 权威依据: 宪章 §17-2「文档—模块—源码符号—测试追踪无断链」；§12.3-3/-4/-9；§12.3 末段（机器检查须能证明结构一致）
- 问题说明: 该检查器计算 `broken`/`sym_broken` 并写进 reports JSON，但 `main()` 结尾无条件 `return 0`——
  不存在任何 `if broken: return 1` 分支。因此注册为不可豁免 CI 项（waivable=false、linux-main+windows-main 双平台）的
  TRACEABILITY 门在数学上不可能失败，断链数量与它无关。ci/run.py 的内容级校验（ci/run.py:60-65 V_EMPTY_OUTPUT）
  只要求「stdout/stderr 留痕」，该脚本始终打印一行汇总，故恒判 PASS。
- 影响: §17-2 门禁项名存实亡；任何 SCI/ALG→源码符号→测试的断链（包括 requirement 行缺实现或测试文件、
  实现文件未被 git 跟踪）都不会被 CI 拦下，「追溯无断链」的发布结论失去机器证据。真实数据路径上的科学声明
  随之失去可核证性（§1.1「科学定义=算法=接口=代码=测试」）。
- 建议处置: 让该检查器按 `broken`/`sym_broken` 非空返回 1（并保留 JSON 输出）；或把它降级为报告、
  另立真正会失败的门禁项；同时在 ci/tests 增加「注入断链必 FAIL」负向用例（见 L17-010 关于其不被执行）。
- 置信度: 高
- related: L17-018、L17-010、L17-005
