### M5a-A-001 ACR 等价容差 1e-6 的推导量纲不成立且自身乘积已超其宣称包络
- 类别: A_SCI_DEF
- 建议优先级: P1
- 来源: L11-012
- 位置:
  - `docs/science/ACR_EQUIVALENCE.md::§9 精度策略`（:84-88）
  - `docs/algorithms/ACR_EQUIVALENCE.md::§9 容差来源`（:65）
- 证据摘录:
  >   - `float32 mosaic_reject`：`CPU/GPU` 差 `max_abs ≤ 1e-6 ADU`（FMA 阶差异，预冻结）；
  >   - 推导：`float32` 机器精度 `~1e-7` × `depth≤32` 累积 × `tiles 714` 独立像素，实测 `≤1e-6` 包络；禁止失败后增大。
  - `docs/algorithms/ACR_EQUIVALENCE.md:65`：「1e-6 float32 (depth≤32累积), 1e-12 float64, support exact, 预冻结.」
- 权威依据: 宪章 §5.3（误差传播与累积精度）、§4.1（不得混淆的量/单位）；`docs/standards/NUMERIC_STANDARD.md` L16（epsilon 必须说明物理/数值来源）；SCI-ACR-EQUIV-001
- 问题说明: 该「推导」把三个不同量纲的因子相乘：`eps≈1e-7`（无量纲相对量）× `depth≤32`（累积步数）× `tiles 714`（**独立像素个数**）。① 独立像素个数不放大 `max_abs` 判据（max 是逐像素量，与像素数无关）；② 即便接受其自身算术，`1e-7 × 32 = 3.2e-6` 已经大于宣称的 `1e-6` 包络 3.2 倍，再乘 714 更相差三个数量级 → 该式在自身数值上即自相矛盾；③ 正确形式应为按信号幅值给出的界（线性累积 `32·eps·|v|max`，或随机游走 `√32·eps·|v|max` 并说明归约序/FMA 假设），而容差却以绝对 ADU 表述，未给归一化条件；④ `float64 ≤ 1e-12 ADU` 同为一无来源绝对量（ALG:65 也只复述 depth≤32）。⑤ 结论是「预冻结 + 禁止失败后增大」，即一个不可辩护的数被冻结为验收界。
- 影响: FROZEN 科学文档的默认容差失去依据；CPU/GPU 等价门（含未来激活的异构路径）判据不可复核；后续实现者按此式推其他内核容差会复制该错误。因 ACR 生产不可达（§10.1），暂不改变真实数据数值，故不定 P0。
- 建议处置: 重写为「相对量 + 幅值条件」的误差界（含归约顺序与 FMA 说明），或改为「由独立 Oracle 实测包络 + 尾分布统计」并登记来源；两文档同步；未闭合前把 §9 标为推导待订正，删除「禁止失败后增大」的无条件冻结措辞。
- 置信度: 高
