  降级理由：本轮未找到**仓库内部**任何把未归一平场喂入 `ac_calibrate_frame` 的可达生产路径（仓库内唯一母版生产者 `generate_master_flat` 自带归一），故不构成「当下产出错误科学数值」；本条性质是「冻结合同的必要前提缺失 + 合同点名的实现是死代码 + 消费边界不校验」，属一致性/可核验性断裂 → P1。若负责人认为「按 SCI 字面直调公共 DLL 即属可达生产路径」，本条应回到 P0（判据：`lib/calibration/include/astro_calibration.h` 是交付 ABI 面、`docs/contracts/API_CONTRACTS.csv:153` 起把四个 ac_* 登记为公开 API）。
- 影响: 冻结合同的输入语义不完整；按 SCI 字面实现或直调 DLL 会产生相差 `median(flat)` 倍的校准输出；矩阵与 README 的 VERIFIED/一致性断言（§5:53「与源码一致」）在合同点上不可复核。不涉及当前产品数值。

### M3-A-004 SCI-NOISE 符号表把 `ivar` 单位写成 `pixel⁻²·ADU⁻²`，与同文 §3/§7 及 DATA/GLOSSARY 冲突
- 类别: A_SCI_DEF
- 建议优先级: P1
- 来源: L07-007
- 位置: `docs/science/NOISE_MODEL.md::§2 符号表 ivar 行`（复核时点 :16）对照 `同文 §3 :29`、`§7 :76`、`§9a :99`；`docs/GLOSSARY.md::ivar 行`（:11）
- 证据摘录（复核时点重读）:
  > | `ivar` | `1/variance` (pixel⁻²·ADU⁻²) | `variance_bg_global` 倒数 / `fill` |（NOISE_MODEL:16）
  > - `x, σ_bg, √variance`: ADU…；`variance`: ADU²；`ivar`: ADU⁻² …（NOISE_MODEL:29）
  > - **量纲一致**：`variance` [ADU²] → `ivar` [ADU⁻²] 倒数关系精确…（NOISE_MODEL:76）
  > | ivar | 逆方差=1/variance… | ADU⁻² |（GLOSSARY:11）
- 权威依据: 宪章 §4.1/§4.3（每个量必须写明单位，不得混淆量纲）、§12.3-1；DATA-HIPS-IVAR-001；SCI-NOISE-001 §3/§7
- 问题说明: `ivar = 1/variance` 的量纲只能是 ADU⁻²；`pixel⁻²` 不是方差或逆方差的组成（variance 是像素值的方差，不是单位面积上的量）。同一份 FROZEN 合同的符号表（:16）与其 §3 单位表（:29）、§7 不变量（:76）、§9a（:99）直接互斥，且与 GLOSSARY/DATA 层的 ADU⁻² 口径冲突。该错误单位还会随 manifest/产品声明外流。
- 影响: 产品单位声明与量纲核对；任何按符号表做单位一致性校验的机器检查或下游消费者会拿到与合同其余四处相反的结论。不改变当前数值。
- 建议处置: 按 §1.2 订正 §2 符号表为 `ADU⁻²`，与 GLOSSARY/DATA_SEMANTICS §13/§30 统一；不保留 `pixel⁻²` 作为可选单位。
- 置信度: 高
- related: M3-H-001、M3-A-008、L09 域（ivar 产品消费侧）

### M3-A-005 平面 LS 退化判据 `|det|>1e-24` 无出处、量纲不闭合，退化求解仍报 `has_spatial_field=1`
- 类别: A_SCI_DEF
- 建议优先级: P1
- 来源: L07-010
- 位置: `lib/snr_estimator/cpp/src/noise_model.cpp::fill_impl`（复核时点 :392-398，关键语句 :393 `const double det = sxx * syy - sxy * sxy;`、:394 `if (std::fabs(det) > 1e-24)`）；`同文件::noise_model_impl 的 has_spatial_field 赋值`（复核时点 :263-264）；`docs/science/NOISE_MODEL.md::§4/§5`（:38、:49）；`docs/algorithms/NOISE_ESTIMATION.md::§5`（复核时点 :99 附近）
- 证据摘录（复核时点重读）:
  >         const double det = sxx * syy - sxy * sxy;（:393）
  >         if (std::fabs(det) > 1e-24) {（:394）
  >             b = (sxv * syy - syv * sxy) / det;（:395）
  >             c = (syv * sxx - sxv * sxy) / det;（:396）
  >         }（:397 —— else 缺失：b=c=0 静默，且 has_spatial_field 不回退）
  >         const bool has_spatial_field = (c.enable_spatial_field && n >= 4);（:263-264 语义，与 det 无关）
  > 空间场: 最小二乘平面 var(x,y) = a + b·x + c·y；负预测 clamp 至 variance_floor (1e-12)（SCI §5:49）
  > 平面场仅 `enable_spatial_field==1 && n_control_points>=4` 启用，否则退化为全局常量场（`has_spatial_field=0`）（SCI §4:38）
- 权威依据: 宪章 §4.1（阈值必须有定义与出处）、§5.3（未登记的数值魔数）、§14.4（禁止无告警静默降级）；SCI-NOISE-001 §4/§5
- 问题说明: SCI §4 只登记了 `n>=4` 的启用条件，合同里**不存在任何条件数/行列式判据**。实现另加一条 `|det|>1e-24` 的隐式判据，且：① 阈值无出处、量纲不闭合——`det = sxx·syy − sxy²` 的元素是「像素距差平方」的乘积，量纲为 px⁴·px⁴=px⁸（受控制点像素尺度与 variance 幅度双重影响），一个固定的 1e-24 在不同帧网格尺度下含义完全不同；② 判据失败时 `b=c=0` 静默执行（无 else 分支、无退化标记），而 `has_spatial_field` 仍为 1，于是输出 `var(x,y)=a` 常量场却对外声称空间场成立，平面模型的实际退化与 §4 的 `has_spatial_field=0` 语义不再对应；③ 该分支与 :405 的 clamp 叠加后，退化场看起来完全合法（方差为正、ivar 有限）。
- 影响: 共线/近共线的控制点（小图、patch 大量被拒、极端掩膜）时空间方差场被静默替换为常量场，逐像素 ivar 场失去真实梯度；Phase2 侧无法从模型字段判别。真实数据：大掩膜、少合格 patch 帧。
- 建议处置: 把退化判据写入 SCI（含形式与出处，例如条件数阈或 `det/(sxx·syy)` 相对阈），并在实现中判据失败时置 `has_spatial_field=0` 或返回退化码；不得保留无标记的静默 `b=c=0`。
- 置信度: 高
- related: M3-H-001、M3-H-002、L09 域（ivar 消费侧）

### M3-A-006 测光/噪声诊断公式在注释与单测中以相反增益方向书写，且与 SCI §5 诊断式量纲不符
- 类别: A_SCI_DEF
- 建议优先级: P1
- 来源: L07-014
- 位置:
  - `lib/phase1/noise/noise_model.h::gain_variance 声明注释`（复核时点 :33）
  - `lib/phase1/noise/noise_model.cpp::NoiseModel::gain_variance`（复核时点 :57-58）
  - `tests/unit/p1_noise_test.cpp::test_monte_carlo_poisson`（复核时点 :44、:56、:63-65）
  - `lib/phase1/photometry/photometer.cpp::flux_error`（复核时点 :69、:77-79）
  - `docs/science/NOISE_MODEL.md::§5 诊断模型 / §11`（复核时点 :58、:114）
- 证据摘录（复核时点重读）:
  > // Poisson+read noise 解析模型 (SCI §10 诊断): variance = signal/gain + read_noise²（noise_model.h:33）
  >   // variance = signal/gain + read_noise² (e⁻ 域 → ADU²)（noise_model.cpp:57）
  >   double var = signal / gain + read_noise_e * read_noise_e / (gain * gain);（noise_model.cpp:58）
  >   // 模型: x = Poisson(signal/gain)*gain + N(0, read_noise)（p1_noise_test.cpp:44）
  >     double adus = electrons * gain + rdist(rng);（:56）
  >     // 解析: variance = signal*gain + read_noise²  (ADU²)（:63）
  >     const double analytic_var = signal * gain + read_noise * read_noise;（:64）
  >   // Poisson + read noise 简化误差: sqrt(sum + n*sigma_sky^2)（photometer.cpp:69）
  >   var_ADU = max(signal,0)/gain + (read_noise_e / gain)²   # signal: ADU, gain: e-/ADU, rn: e-（SCI §5:58）
- 权威依据: 宪章 §4.1（不得混淆量纲/单位）、§4.3（公式与代码必须一一对应）、§12.2（注释不得与代码/合同矛盾）、§13.1；SCI-NOISE-001 §5/§11
- 问题说明: 三处独立失实：① `noise_model.h:33` 的头注释写 `variance = signal/gain + read_noise²`，漏掉 read noise 项的 `/gain²`，与同函数实现（:58，与 SCI §5:58 一致）及 SCI 都不符——按注释实现即得量纲错误（e⁻² 与 ADU² 混加）。② `p1_noise_test.cpp` 的「解析」期望是 `variance = signal*gain + rn²`：生成器把 ADU 写成 `electrons*gain`（:56），而 gain 定义为 e⁻/ADU，正确换算应为 `ADU = e⁻/gain`，故该 fixture 与断言自洽地把增益方向取反（相对 SCI 错 `gain²` 倍），并作为已注册 ctest（`p1_noise`）为错误的单位换算背书；同时其容差为 ±15%（:35 variance、:65 相对差）与 SCI §11 的 5%（:113/:114）不一致，:38 的 `|σ−10|<1` 即 ±10%。③ `photometer.cpp:69/:79` 把天空噪声写成 `n·σ_sky²` 而 `σ_sky` 由 :77 的 `1.4826·MAD` 得到（4 位截断常数），既非 SCI 的 15 位常数，也无「本层不产出 SNR」的合同依据（SCI §9a:98 声明 SNR 只在消费侧由 `signal/√variance` 构成）。
- 影响: 涉及科学量（variance/gain）的注释与测试失实；按注释或旧测试改生产实现即引入 `gain²` 量级误差。当前生产 `snr_noise_gain_variance`（noise_model.cpp:456-464，与 SCI 一致）与 `lib/phase1/noise` 的 `estimate` 主路径不受影响，故不定 P0。
- 建议处置: 订正三处文字与断言：头注释补 `/gain²`；p1_noise_test 的生成器与解析式按 ADU=e⁻/gain 重写并把容差对齐 SCI §11 的 5%（差异须在合同侧登记）；photometer 的常数改指单一权威定义点（见 M3-A-008）并在 ALG 登记该误差式不是 SNR 合同的 `signal/√variance`。
- 置信度: 高
- related: M3-A-008、M3-F-002、L07 域内 DISP-PHOT-008
