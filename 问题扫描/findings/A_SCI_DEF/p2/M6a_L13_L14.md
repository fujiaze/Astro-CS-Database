- 问题说明: ①出处虚假：ARCH-P3 §3 通篇没有 order/leaf 数上限条款，ALG 再引回代码注释，形成「注释→自身」的循环出处；②算式错：order n 的 HEALPix 叶数是 12·4ⁿ，注释写 `2^(2*20)=4^20` 少 12 倍，且未给「叶数→字节」的换算，无法据以推 20 这一界；③口径互斥：AIO 读取层合法 [0,29]、Phase3 properties 拒 >20、`p3_order_select` 拒 >20、会话 `max_order` 把 >20 静默降为 20 —— 同一 order 值在不同层「可读/被拒/被改写」，而 :196 注释自称「上限=输入实际 order」。
- 影响: 魔法数 20 的决策不可追溯；order∈[21,29] 的合法 HiPS 产品会出现「reader 可开、properties 拒、会话降阶」三态，provenance 记录（M6a-C-001）随降阶进一步失真。
- 建议处置: ①注释改真实出处：写出「内存上界式 → 允许的 leaf_nside → order 上限」的完整推导（含 12·4ⁿ 与 tile 字节数），或在 ALG/ARCH 正式登记为守卫条款后引用；②20 收进单一权威常量，三处（properties/resample/session）共用并同域；③越界一律显式拒绝 + 诊断（与 CON-006 精神一致），禁静默 clamp。
