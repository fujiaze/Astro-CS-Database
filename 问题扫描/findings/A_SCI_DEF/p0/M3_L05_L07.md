- 权威依据: 宪章 §4.1（`snr` 必须是由 SCI-NOISE/SCI-SNR 定义的信噪比，不得是任意质量分；支持度/覆盖率不得充当科学权重）、§1.1（层间不一致必须建 finding）、§12.3-10（活动文档不得以历史状态冒充当前状态）；SCI-NOISE-001 §9a/§10；SCI-CW-001 §2/§4；SCI-PSF §1/§8（q_psf 非 SNR）
- 问题说明: 复核时点全仓至少并存三套互不相同、且都叫「SNR」的量：
  ① **合同唯一授权**的定义是 `signal/√variance`（SCI-NOISE §9a:98 明文，且声明本层不产出 SNR 图）。
  ② **实际进入产品的量**是 HISS SNR 目录/控制点值 = `(A−B)/residual_scale`（PSF 峰幅除以残差尺度），链路完整可追：`snr_extract_model*` 三处同式（:544/:663/:768）→ `SnrControlPoint.snr_psf` → drizzle 写 SNR 块（drizzle_engine.cpp:1162/:2037）→ `sampler.cpp` 读目录得 `frames[i].snr`/`o.snr` → `stage2.cpp` 组 `local_snr_map`（:380-405）并在 :1136 平方后进入权重。该量**不含任何方差项**，且其自身所在通道在公共头里被标注为「legacy (A-B)/mad … SNR-008 已退休路径」（:288/:300）、在 :19-20 被标注为「已降级为 legacy heuristic / diagnostic only … 不再作为生产科学权重」。SCI-CW 却把它定义为「区域级 SNR 倍率、无量纲」并消费。
  ③ 第三种 `snr_phot = 1/(ln10·sigma_residual)`（:381）是相对定标误差的倒数，同样无任何 SCI 定义，且与 `PhotometricCalibrationQuality.sigma_cal_rel` 为同一量（同文件 :33-49），后者被明文禁止当权重。
  即：被标注为「已退休/仅诊断」的量，同时在生产链的另一侧被当作权威 SNR 消费；而合同授权的定义无人产出。三套量纲与数值域互不相容，`snr` 在全仓无唯一定义。
- 影响: Phase1 SNR 产品（HISS SNR 块、SNR 控制点、`p1_snr.json`）语义与 SCI-NOISE 合同不符；Phase2 的 `local_snr/frame_snr` 权重因子（见 M3-A-002）建立在该量上，量级亦非 SNR（例：A=5000、B=1000、residual_scale=120 → 「snr」≈33，平方后为 ≈1100 的权重倍率差）。真实数据路径：stage6 SNR → HISS → stage2 积分/排异。属「科学输出错误 + 定义不唯一」双料，P0 成立（复核时点成立）。
- 建议处置: 由负责人冻结唯一 SNR canon：(a) 若保留 HISS SNR 目录，须为其另立 SCI 名（如 `fit_snr_proxy`/`frame_quality`）并在 GLOSSARY 与 SCI-CW 中与 `signal/√variance` 显式区隔；(b) 否则目录/控制点值改按 SCI-NOISE §9a 构成，`(A−B)/residual_scale` 退回诊断字段并撤销其在 Phase2 权重中的消费；(c) `snr_phot` 一律改名（它是定标误差倒数，不是 SNR）。三处「已退休/仅诊断」自述与实际消费必须收敛为一。
- 置信度: 高
- related: M3-A-002（同一量的权重口径）、L09-003、L18-002、SNR-008、M3-E-001（被引文档/测试 ID 不存在）

- 问题说明: 复核时点代码语义**已可确定**（前台要求给出「实现到底是哪套」）：生产默认 `weight_mode=2` → 逐像素 `ivar`（stage2.cpp:549 注释 + :1106-1118 + :1359-1375 双站点，注释在 :1355-1357 明写「mode 2 (ivar, 默认)」）；`support × snr²` 只在 `weight_mode==0` 分支（:1136/:1396），且 :1115/:1374 的 support 回退仅在显式 `legacy_allow_weight_fallback=true` 时可达（stage2_common.cpp:389-390 默认 false，ivar 缺失时 fail-closed rc=7）。同仓词表四处一致：DATA_SEMANTICS:919、ACR_EQUIVALENCE:19、PHASE2_REJECTION:52-56、GLOSSARY:12-13（`pixel_weight=ivar`，并注「legacy snr² 权重仅 ablation 域」）。
  在此背景下，**FROZEN 的 SCI-CW §4 把 `support × snr²` 标注为 `weight_mode=2` 的「像素级」权重（:38/:42/:27）**，与实现、与另四份登记、与 SCI-UPM-WEIGHT-001 的生产禁令三方互斥。SCI-CW 还与自身矛盾：§1:12-14 说该量是「控制权重中的 SNR 因子」并与逐像素 ivar「不混用」，§5:65-66 与 §6:72 再申「二者不混用」，§7:78 甚至把「将 local_snr 与逐像素 variance/ivar 当作同一权重语义」列为**不可接受变化**——而 §4 的公式块正是这么做的。
  此外，该 `snr_v` 的数值来源即 M3-A-001 的已退休质量比：即使按 ablation 域解读，SCI-CW 也未说明 `snr_v` 的定义式，等于把一个无 SCI 定义的量写成冻结合同里的权重因子。
  机器门侧：`tools/docs_machine_consistency.py::config_weight_mode_ivar`（:57-63）只比对 CONFIG_SCHEMA 的 `weight_mode(auto)` 与 `stage2_common.cpp` 的解析串，不校验 SCI-CW 的权重式，故该矛盾不可能被现有门捕获。
- 影响: Phase2 排异/积分权重的**权威定义层**给出错误的生产权重。任何按 SCI-CW 落码或据其复核（含真实数据终验的权重核算、ACR 等价判据、后续 Agent 的整改）都会被引导至「以 support 为权重、以质量比平方为统计权重」，直接改变马赛克加权结果并违反宪章 §6.3 与 SCI-UPM-WEIGHT-001；同时 UPMW-001 的 snr/support 扰动不变门与该 SCI 条款相互否定，验收判据不可同时满足。P0 成立（两份 FROZEN SCI 互斥 + 与实现/门禁互斥；前台要求的代码语义结论已在问题说明中给出）。
- 建议处置: 按 §1.2 由负责人裁决并**只保留一套**口径：修订 SCI-CW §4 块首注释与 §2 符号表（`snr_v²` 只存在于 `weight_mode=0` legacy/ablation 域；`weight_mode=2` 为逐像素 ivar；support 仅 eligibility/coverage），并把 `snr_v` 的定义指向唯一 SNR canon（与 M3-A-001 联动）；若确要把 `support×snr²` 留在生产权重域，须显式登记与 SCI-UPM-WEIGHT-001、宪章 §6.3 的冲突裁决，不得两份 FROZEN SCI 并行有效。同时把 `config_weight_mode_ivar` 门扩为校验 SCI-CW 公式块首行与 DATA_SEMANTICS 词表一致。
- 置信度: 高
- related: M3-A-001、M3-F-005（SCI-CW 无测试/无追溯行）、M3-E-001、L09-003、L18-002（跨域，本条不重复登记）；L08 域 kcorr/权重并线事项见 M3.md 移交清单
