### M2b-A-01 HiPS 写入口对 nside 零校验：非 2 的幂与 order>29 均被接受并静默产出错产品；lib/hips 的正确校验在生产调用点被绕过
- 类别: A_SCI_DEF
- 建议优先级: P0
- 位置:
  - 写侧唯一闸门：lib/astro_image_io/src/hips/aio_hips_writer.cpp::aio_hips_product_begin（只比大小 + ilog2 向下取整）
  - 被绕过的正解：lib/hips/src/module_entry.cpp::hips_cfg_parse（require power-of-two + 上界）
  - 生产调用点 3 处：lib/core/src/module_adapters.cpp::p1_op_writer（write_hips 节点）、lib/core/src/module_adapters.cpp::p2_op_write（write_mosaic 节点）、lib/healpix_db/healpix_drizzle/astro_sphere_sink.cpp::写通道 begin；另 lib/phase2/tools/stage2.cpp（legacy 工具）
  - 合同：docs/contracts/DATA_SEMANTICS.md::§2 非法值拒绝 + ::DATA-P1-HIPS §12.1；lib/astro_image_io/include/aio_hips.h::aio_hips_product_begin
  - 共享核心：lib/common/healpix/healpix_core.h::require_valid_nside、::nside_to_order
- 证据摘录:
  - 写侧闸门（原文）：

  - ilog2_u64（原文）：「uint32_t ilog2_u64(uint64_t v) { uint32_t l = 0; while (v > 1) { v >>= 1; ++l; } return l; }」
  - 共享核心的正确口径（原文，aio_hips_writer.cpp 同文件即 include）：

  >     if (nside == 0 || (nside & (nside - 1u)) != 0u) {
  >         throw std::invalid_argument("healpix: nside must be a power of two (got " + std::to_string(nside) + ")");

  - 公共头承诺（本次以 ripgrep 整行取回，规避 read 单行截断；aio_hips.h:101）：「// nside - 叶级 NSIDE (2 的幂, >= 512)」——头文件把「2 的幂」写成入参契约，实现端不校验（口径注：本会话早期记录的英文原句「leaf-level NSIDE (power of 2, >=512; non-power-of-two is rejected)」在当前树中 ripgrep **0 命中**，说明该句已被并发改写为上面的中文行；两条均只承诺、不校验，结论不变）

- 权威依据: DATA_SEMANTICS §2「非法值拒绝」+ §12.1「nside 恒为 2 的幂；非 2 次幂入参被拒绝」；Górski 2005 §5（Npix=12·Nside²，等面积网格前提）；宪章 §14.4（非法值 fail-fast、不得生成看似成功的产品）、§5.2/§6.2（HiPS 写出归 AIO、单一写出路径）、§12.2（注释与实现一致）
- 问题说明:
  1. **写入口零校验**：闸门只比 `nside < 512`，无「2 的幂」判定、无上界；`leaf_order` 用 ilog2 **向下取整**把非法值静默夹到最近 2 的幂。实例（与 L03 独立复算一致）：nside=1536 → leaf_order=10、tile_order=1、A_cell=4π/(12·1536²)——properties 的 `hips_order=1` 宣告 nside=1024 网格（512·2¹），而 A_cell/pixlist/MOC UNIQ 全按 1536 计算，产品内部即不自洽（`4·4^K + ipix` 与真实 cell 不对应）。nside=2^31 → leaf_order=31、tile_order=22，`hips_estsize`/`A_cell` 与 npix 全越界。
  2. **「已实现但被绕过」是本条核心**：正确校验确实存在**两处**——共享核心 `require_valid_nside`/`nside_to_order`（writer 已 include healpix_core.h 却不调用），以及模块面 `astrocs.p1.hips_writer` 的 `hips_cfg_parse`（power-of-two + 上界 2^24 齐全，且它把 writer 写进 staging）。被绕过的具体调用链（本次实读定位）：
  > CLI `astrocs phase1 run` → cli/commands.cpp::cmd_run → cli/runtime_client.cpp::run_pipeline → ::build_pipeline_ir → Runtime 按 IR 节点执行 → runtime/pipeline/module_ports.registry.json 绑定 `astrocs.phase1.writer` / operation `write_hips` / entry `astrocs_phase1_writer_v1` → lib/core/src/module_adapters.cpp::p1_writer_descriptor → `make_p1_node_module` → **p1_op_writer() 直接调 `aio_hips_product_begin`**（Phase2 侧同构：`astrocs.phase2.write` → `p2_op_write` → 同一个 begin）
  即生产链走 lib/core 的 IR 节点内嵌实现，**不经过** lib/hips 的 C ABI adapter（`astrocs_module_query_v1`）；该 adapter 目前在仓内唯一的消费者是 `tests/unit/p1_hips/adapter_test.c`（经 `ASTROCS_HIPS_DLL_PATH` dlopen）。lib/hips/module.yaml 与 docs/contracts/PUBLIC_API.md 都明说「registry descriptor 注册与 Phase DAG 接入归 P1-HIPS-INT」「entrypoint=MISSING——registry 无 descriptor」，故正确校验与事务化写出**在生产路径上零可达**。
  3. 测试面亦未覆盖：`lib/astro_image_io/tests/p1hips/p1hips_tests_negative.cpp::N1` 只测 256/511（下界两侧），无 1536 类非 2 的幂、无上界用例；`tests/unit/p1_nside_test.cpp` 只测 512/1024/2048/4096 合法幂。ALG §9「负面矩阵」列了 nside<512 却没列非 2 的幂（见 M2b-F-02 相关）。
- 影响: 三条生产写链（Phase1 write_hips、Phase2 write_mosaic、drizzle 直写 sink）在 nside 非 2 的幂时静默产出「properties 与几何不自洽」的伪产品；调用点注释「aio_hips 硬校验同款」为不实陈述，会让人误信非法值已被 fail-closed。真实数据路径受影响（drizzle 侧 nside 目前由 `512u<<order` 派生，故现网未爆；风险在入参直传/配置手改/上游容器头被外部产物污染时，写侧本身不设防）。
- 建议处置: ① `aio_hips_product_begin` 改调 `astrocs::healpix::require_valid_nside` + 显式上界，非法值返回 NULL 并置 `INPUT_CORRUPT` 语义的 `last_error`（宪章 §14.4）；② `leaf_order` 改 `nside_to_order`（越界即抛→捕获为错误），删除 ilog2 向下取整；③ 三个生产调用点在 begin 之前统一走同一个校验函数，或按 M2b-G-01 的裁决把 IR 节点接回模块 adapter（使 `hips_cfg_parse` 的校验与 staging 真正生效）；④ 补负面用例：nside=1536（非 2 的幂）与 nside=2^31 必拒；⑤ 订正 module_adapters 的「硬校验同款」注释。
- 置信度: 高

### M2b-A-02 tile 几何合同三源互斥：层级 tile NSIDE 卡（代码 2^(k+9) vs ALG 2^k vs IO_002 2^(K+9)）与 hips_order 入参域四层互斥，自产 hierarchy tile 不被自家输入合同接受
（L03-002 与 L03-017 并档为一条根因，两个实例面全留）
- 类别: A_SCI_DEF
- 建议优先级: P0
- 位置:
  - 写侧：lib/astro_image_io/src/hips/aio_hips_writer.cpp::finalize_hierarchy（`nside_k = 1u << (k + 9)`）与 ::aio_hips_product_begin（`tile_width != 512` 即拒）
  - 算法侧：docs/algorithms/HIPS_WRITER.md::ALG-HIPS-004 (4c)（同一小节内同时出现 2^(k+9) 与 2^k）
  - 输入合同：docs/interfaces/io/IO_002_HIPS_INPUT_INTERFACE.md::§3.1 表 + ::§3.3 tile 头卡表
  - 读侧执行：runtime/io/hips_core.c::hips_parse_properties（`h->nside = 1ULL << (order + 9u)`）与 ::hips_tile_validate（NSIDE 必等 `h->nside`）
  - 另两层口径：modules/services/io/include/astrocs/io/hips_input_v1.h::ACS_HIPS_ORDER_MAX/ACS_HIPS_TILE_WIDTH_MAX；lib/phase3_session/hips_properties.h::kMaxOrder/kHipsTileWidth；lib/hips/src/module_entry.cpp::hips_cfg_parse（nside 上界 2^24、tw 恒 512）
- 证据摘录:
  - 代码（原文）：
  > const uint32_t nside_k = 1u << (k + 9);
  > cards.push_back({"NSIDE", std::to_string(nside_k)});
  > cards.push_back({"FIRSTPIX", "0"});
  > cards.push_back({"LASTPIX", std::to_string(n - 1)});
  - ALG 同节自相矛盾（原文，先给 2^(k+9) 再给 2^k）：
  > (4c) 落盘：finalize 时对每阶 k<T（:797-880）：nside_k=2^(k+9)、A_cell_k=4π/(12·nside_k²)（:800-801）…
  > 约定。FITS cards ORDERING=NESTED + NSIDE=2^k；三处 scatter 同 (2a) 式（:809）。
  - IO_002（原文，两句同页互斥）：
  > `hips_tile_width` | tile 宽 TW | 十进制整数；**必须为 2 的幂**且 1 ≤ TW ≤ 16384；TW=512 标准
  > `hips_order` | tile order K | 十进制整数，0 ≤ K ≤ 29；K 与 NSIDE=2^(K+9) 一致
  > `NSIDE` | 若存在必须等于 `2^(K+9)`（tile 像素分辨率）
  - 读侧执行（原文）：「h->nside = 1ULL << ((uint64_t)order + 9u);」——TW 不参与该式
- 权威依据: Górski 2005 §5（NSIDE 唯一决定 cell 边长）；IVOA HiPS 1.0 §4.2.1（tile 含 2^S×2^S 个 cell、"Tile pixel angular size =~ sqrt(4*PI/(12 x (tileWidth x 2^order)2))" ⇒ 叶级 NSIDE = tileWidth × 2^K，故 512 时 = 2^(K+9)、1024 时 = 2^(K+10)）（URL: https://www.ivoa.net/documents/HiPS/20170519/REC-HIPS-1.0-20170519.pdf）；DATA_SEMANTICS §2；宪章 §12.2（文档=代码）
- 问题说明:
  1. **层级 tile NSIDE 三向冲突（L03-002 实例）**：代码写 2^(k+9)、ALG 同节另一行写 2^k（代码前者正确、后者错），IO_002 要求「若存在必须等于 2^(K+9)」中的 K 是 properties 的 `hips_order` = 顶层 tile_order T。读侧以 `h->nside = 2^(T+9)` 比对，于是自家自产的 Norder k (k<T) 层级 tile（头里 NSIDE=2^(k+9)）**必然**被判 `ACS_HIPS_ERR_TILE_INVALID`；若按 ALG 改写成 2^k，叶级 tile 的 NSIDE 又会与 properties 冲突。DISP-HIPS-012 只登记「FIRSTPIX/LASTPIX 声明性无消费方」，未登记 NSIDE/FIRSTPIX 这对语义互斥（同一文件里 NSIDE=2^(K+9) 宣告全球网格、FIRSTPIX=0/LASTPIX=262143 宣告本 tile 的 cell 区间，二者不可能同时为真）。
  2. **入参域四层互斥（L03-017 实例）**：IO_002 声明 TW ∈ {2 的幂}∩[1,16384]，而 `h->nside = 2^(order+9)` 硬编 512 的位移 ⇒ 一个合法 TW=1024、order=20 的外部产品被按 NSIDE=2^29 校验（应 2^30）→ 系统性误判 TILE_INVALID；同时 `aio_hips_product_begin` 与 `aio_hips_reader.cpp::valid_product_params` 硬 TW==512、`lib/hips` 硬 tw==512 且 nside 上界 2^24、`hips_properties.h` 硬 TW==512 且 order ∈ [0,20]、`hips_input_v1.h` order ∈ [0,29]/TW ≤ 16384。同一入参域四层各写一份，且**没有一个字面与 IO_002 一致**；`aio_hips.h` 承诺的 `tile_width>=16` 已不存在，成为悬空承诺（写死 `tile_width != 512` 即拒）。
- 影响: ① 自产 hierarchy tiles（每个低阶 tile，signal/support/variance/ivar 四产品 × tile_order 阶）都不被自家输入合同接受，且 `docs/algorithms/PHASE2_MOSAIC_WRITE.md` 把层级 tile 读列为生产功能；② 任何 TW≠512 的合标外部 HiPS（IO_002 明写合法域）在 NSIDE 面被系统性误拒，合同自相矛盾；③ ALG 的 2^k 若被当作权威实现，将直接破坏叶级 tile 的 NSIDE↔order 对应（Górski §5）。
- 建议处置: ① 先定单一权威：叶级 nside = TW × 2^K（标准算式），properties 的 `hips_order` 与 TW 必须共同决定 NSIDE；② IO_002 §3.1/§3.3 改为「NSIDE = TW·2^K」并给出 TW 的真实支持域，与 `hips_parse_properties` 一致化（要么全面支持 TW，要么在合同里诚实收窄为 TW==512 并撤销 16384 承诺）；③ ALG (4c) 删掉「NSIDE=2^k」错句；④ hierarchy tile 的 NSIDE 语义（是「本 tile cell 边长」还是「产品叶网格 nside」）显式定义并挂 ID；⑤ FIRSTPIX/LASTPIX 改为该 tile 覆盖的 cell 区间或删卡，另立 DISP 登记；⑥ 统一 order/TW 上界为单一来源（建议 contracts 层常量），删除 `aio_hips.h` 的 `tile_width>=16` 悬空承诺。
- 置信度: 高
- related: M2b-A-01、M2b-B-07、M2b-C-05、L03-002、L03-017、DISP-HIPS-012、M2a（IO_002/IO_003 合同侧会签）
- 来源: L03-002 + L03-017（并档）
