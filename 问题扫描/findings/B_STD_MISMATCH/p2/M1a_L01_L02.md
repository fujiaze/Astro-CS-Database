## M1a-B-006 求解后头块不清理输入自带 CDELT1/2（CD 与 CDELT 混写），且 SIP 回写循环含 i+j<2 非法项

- 类别: B_STD_MISMATCH · 优先级: P2 · 来源: L01-016
- 位置: lib/orchestrator/cpp/src/orchestrator.cpp::run_stage_platesolve（WCS 头写回块）
- 证据摘录（逐字）:
  > （orchestrator.cpp:2069-2072）wcsResult.cd11 … "CD1_1" 写入 …  "CD2_2" 写入
  > （orchestrator.cpp:2088-2095）for (int i = 0; i <= wcs_result.sip_order; ++i) { for (int j = 0; j <= wcs_result.sip_order - i; ++j) { … snprintf(key, sizeof(key), "A_%d_%d", i, j); …
  > （orchestrator.cpp:4226-4227）"CDELT1 = %.10e" / "CDELT2 = %.10e"（读入 passthrough，全文件无删除/改写路径）
- 权威依据: FITS WCS Paper I §1.1/§8.1（CDi_j 与 CDELTi 同现时行为未定义，不得混写）；SIP（Shupe 2005）§3：A_ij/B_ij 只对 **i+j ≥ 2** 定义；宪章 §12.3-15
- 问题说明: SIP 回写从 i=0、j=0 起（含 A_0_0/A_1_0/A_0_1），产生标准未定义的键；同时若输入头自带 CDELT1/2，写出块只覆盖 CD/CRPIX 族而不清理 CDELT，形成 CD 与 CDELT 混写。两者均为**产品头面**（非合同镜像文本）。
- 影响: 严格 WCS 读者对混写头的处理不可预期（astropy 会发警告并按 CD 优先，wcstools 行为不同）；SIP 非法项被 astropy 忽略但按标准应视为非合规。当前无实测产品失败记录 → 定 P2。
- 建议处置: ①SIP 循环改 `i+j>=2` 起；②写 CD 时显式删除/改写输入 CDELT1/2（或改为只用一族并在合同登记）；③在头写回后加一次"键族互斥 + i+j 值域"自检（可用 p3_output.cpp:400 的逐键对拍模式）。
- 置信度: 高 · related: L01-002、M1a-B-004
