- 问题说明: 由代码/ALG 自己声明的恒等式 `A = X²/4 + Y² = 1 − cosθ·cos(φ/2)`（本代理代入正向公式复算并数值验证：θ=0,φ=π → A=1；θ=30°,φ=60° → A=0.22985 = 1−cos30°cos30° ✓）可得：天球（|θ|≤π/2 ⇒ cosθ≥0；|φ|≤π ⇒ cos(φ/2)≥0）的像恰为 **A ≤ 1**（边界 A=1 是两极与 φ=±180° 经线；赤道端点 X=±2、Y=0 亦在 A=1 上）。实现的两个判据都挡不住 1<A<2：`dsq>0` 就是 A<2；`|Y·D|≤1` 在该环带内也常成立。数值见证（本代理代入实现式，非执行）：取 (X=0, Y=√1.5≈1.2247)，A=1.5 ⇒ dq=√0.5≈0.7483、sinθ=0.916…→ 实际 = 1.2247×0.7483=0.9165 ≤1 → θ≈66.4°；`atan2(0, dsq−1=−0.5)=π` ⇒ φ=2π ⇒ RA 经 `normalize_ra` 绕回中心经线 ⇒ 返回 `(RA0, +66.4°)` 且状态 OK；而正向映射 `(RA0, 66.4°)` 给的是 Y=sinθ/√(1+cosθ)=0.9165/1.1834≈0.7745 ≠ 1.2247 —— 往返不闭合且未被拒绝，即环带内的像素被折叠到一个合法天区值上。`make` 的四角域守卫因走同一 pix2world 而同样放行。
- 影响: 一旦按 §7.3/§18.1 把 AIT 挂上生产（DISP-P3PROJ-001 的 INT 任务），宽视场（AIT 设计目标为全天空 360°×180°，其椭圆外接矩形必落入 1<A<2 环带）四角与边缘像素会静默产出错误天区坐标；自测与「独立」Python oracle 用同一式与同一域判据 ⇒ 宪章 §7.3 要求的独立性不成立，该缺陷不可能被现有测试面发现。
- 建议处置: ①逆映射域判据改 `A ≤ 1`（含数值容差），并把该域写进 registry 的「适用天区」字段；②订正 ALG §15.3/§15.4 的「椭圆域边界 X²/4+Y²=2」为「A=1」；③两侧 oracle 的域外取样点改取 1<A<2 的样本（现取 1e9 属远域，必然通过），并要求与第三方（wcslib/astropy 的 AIT）对拍；④与 M1a 的 AIT/CAR oracle 共源定稿（M1a-F-001）并档整改：共源问题在其处，域判据错文在本处。
