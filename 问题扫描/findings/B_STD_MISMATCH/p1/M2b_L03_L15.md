### M2b-B-05 SNR metadata.xml 命名空间 URI 含字面空格，产出即非合规 VOTable
- 类别: B_STD_MISMATCH
- 建议优先级: P1（前台终裁可升 P0：交付文件语法即不合规）
- 位置: lib/astro_image_io/src/hips/aio_hips_writer.cpp::finalize_snr_product（VOTABLE 头 fprintf 常量串，共 4 处 "http:// "）
- 证据摘录:
  > "<?xml version=\"1.0\"?>\n"
  >             "<VOTABLE version=\"1.3\" xmlns=\"http:// www.ivoa.net/xml/VOTable/v1.3\"\n"
  >             "         xmlns:xsi=\"http:// www.w3.org/2001/XMLSchema-instance\"\n"
  >             "         xsi:schemaLocation=\"http:// www.ivoa.net/xml/VOTable/v1.3 http:// www.ivoa.net/xml/VOTable/v1.3\">\n"
- 权威依据: IVOA VOTable 1.3 命名空间（xmlns 必须为不含空白的合法 URI）；IVOA HiPS 1.0 §4.4.3「Catalogue HiPS metadata: the meta data are stored in metadata.xml file as a fully defined VOTable」（URL: https://www.ivoa.net/documents/HiPS/20170519/REC-HIPS-1.0-20170519.pdf）；宪章 §11、§17.11
- 问题说明: URI 内的字面空格使 xmlns 不是合法命名空间名：严格解析器直接报错，宽松解析器把它当**未知命名空间**，根元素因此不再被识别为 VOTable。ALG §10 DISP-HIPS-010 只登记了「properties 值无转义 / FITS 头 68 字符静默截断」这类低危项，未登记这条当场产出不可解析文件的缺陷。测试面只查 "<VOTABLE" 子串（见 M2b-F-03），故无判别力。
- 影响: 凡 flags 含 SNR 的写出，snr/metadata.xml 均对外不可解析；列定义（star_id/ra/dec/snr/quality_flags/photometric_status 的 datatype/unit/ucd）全部失效——按 HiPS §4.4.3「tile 内头卡被客户端忽略」，列元数据**只有** metadata.xml 一个载体，故 catalogue HiPS 的列语义整面丢失。TSV 数值本身不受影响。
- 建议处置: ① 去掉 URI 内空格；② 测试改判「XML 可解析 + 根元素命名空间等于 VOTable URI」；③ 以 astropy.io.votable 或 hipsgen LINT 作独立解析 Oracle。
- 置信度: 高
- related: M2b-F-03、M2b-B-02、L03-012

### M2b-B-06 hips_status 缺标准必填的第三组词表、hips_hierarchy 写布尔值，均偏离标准词表
- 类别: B_STD_MISMATCH
- 建议优先级: P1
- 位置: lib/astro_image_io/src/hips/aio_hips_writer.cpp::finalize_image_product；docs/standards/STANDARDS_REGISTRY.md::D.hips 清单行 4 + 偏差表 DISP-HIPS-003；docs/algorithms/HIPS_WRITER.md::ALG-HIPS-005 (5b)
- 证据摘录:
  > kv.push_back({"hips_status", "private master"});
  >     kv.push_back({"hips_hierarchy", "true"});
  - HiPS 1.0 §4.4.1（实测取回）：
  > 6. hips_status : HiPS status description – Format: list of blank separated words ("private" or "public"), ("master", "mirror", or "partial"), ("clonable", "unclonable" or "clonableOnce") – Default : public master clonableOnce
  > 示例 properties 文件：hips_status = public master clonable / hips_hierarchy = mean
  - URL: https://www.ivoa.net/documents/HiPS/20170519/REC-HIPS-1.0-20170519.pdf （§4.4.1）
- 权威依据: IVOA HiPS 1.0 §4.4.1（hips_status 为 9 个 mandatory 之一，格式 = 三组空白分隔受控词表；标准示例中 hips_hierarchy 取值为聚合方法词 mean）；STD-REG-001 §1.4
- 问题说明: hips_status 是标准必填键且格式硬定义为三组词，实现只写两组（缺 clonable/unclonable/clonableOnce）；注册表把该行归入「可选/推荐键」判 PARTIAL，与它在标准中的 mandatory 地位不符。hips_hierarchy 在正文键表未列取值域，仓库唯一证据（标准示例）用方法词 mean，实现写 "true" 是把「是否存在层级」塞进「层级聚合方法」语义位。
- 影响: 对外 properties 的 hips_status 不满足必填格式、hips_hierarchy 语义歧义；客户端无法判断镜像/克隆策略与层级聚合语义；外部 LINT 报不合规。不改变像素数值。
- 建议处置: ① hips_status 补齐第三组并按真实发布策略取值，同时参数化（摘掉 DISP-HIPS-003）；② hips_hierarchy 改标准方法词或删键并在偏差表说明；③ 注册表把该行改挂 mandatory 面（与 M2b-B-04 一并不动结论：登记为真实偏差）。
- 置信度: 高（hips_status 三组词为硬事实）/ 中（hips_hierarchy 词表由标准示例支撑）
- related: M2b-B-04、M2b-B-08、L15-005、DISP-HIPS-002、DISP-HIPS-003

- related: M2b-B-02、M2b-B-04、M2b-B-07、M2b-G-02、M2a（D.fits §6 行同形态）、L15-008、L15-009、L15-010、L15-014、M1a（L01-004/L01-012 同主题实例）、M7（六域横向并档）

### M2b-B-10 注册表六域清单的「条款」列与标准章节内容整体错挂（fits 5 行 + healpix 2 行 + spherical-projection LONPOLE 行 + hips 4 行），机器门对「条款号↔内容」零判据
- 类别: B_STD_MISMATCH
- 建议优先级: P1
- 位置: docs/standards/STANDARDS_REGISTRY.md::D.fits CLAUSES 与清单行 1/2/3/4/5/6；::D.healpix 清单行 1/3（§5.1/§5.3 行）；::D.spherical_projection 清单行 3（PROJECT_DEFINED LONPOLE 行）；::D.hips CLAUSES 与清单行 1/3/5/6；docs/standards/checks/check_standards_registry.py::C3_clauses_form；各标准原文（URL 见下）
- 证据摘录（注册表声称 ↔ 标准实际章节，均本次实测取回）:
  - FITS：注册表 CLAUSES「§3.1（基本文件结构/80 字节卡）/§4.2（SIMPLE/BITPIX/NAXIS 基本头）/§4.4（扩展 HDU）/§5（表扩展）/§6（DATASUM/CHECKSUM）」；官方目录实测为「4.2 … Logical/Integer number/Real floating-point number（即 Value 类型面）… 4.4 Keywords … **4.4.1 Mandatory keywords** … **4.4.2 Other reserved keywords** … 5 Data representation … **6 Random-groups structure** … 7 Standard extensions … Appendix J CHECKSUM implementation guidelines」⇒ SIMPLE/BITPIX/NAXIS 实在 §4.4.1（非 §4.2）、扩展 HDU 实在 §3.4/§7（非 §4.4）、表扩展实在 §7（非 §5）、DATASUM/CHECKSUM 实在 §4.4.2＋附录 J（§6 是随机群）。URL: https://fits.gsfc.nasa.gov/standard40/fits_standard40aa-le.pdf
  - HEALPix：注册表把 ang2pix/pix2ang 往返挂 §5.3、把 nside 幂次/等面积公式挂 §5.1；实测 arXiv 正文 §5.1 = **Pixel Positions**、§5.2 = **Pixel Indexing**、§5.3 = **Pixel Boundaries**，而 Npix=12N²side、Ω=π/(3N²side) 出自 §5 正文引言。URL: https://arxiv.org/html/astro-ph/0409513
  - WCS Paper II：注册表行「| Paper II §2.1（LONPOLE 与旋转） | 允许通用 LONPOLE/φ_p 附加旋转机制 | PROJECT_DEFINED | … | 无（本实现固定 θ₀=+90°…） |」；实测该文小节为「2.1 Spherical projection / 2.2 Reference point of the projection / **2.3 Spherical coordinate rotation**」，LONPOLE 与 θ₀/φ_p 机制属 §2.2–§2.3，§2.1 不含 LONPOLE。URL: https://arxiv.org/abs/astro-ph/0207413（ar5iv 渲染件同文）
  - HiPS：四条错挂（目录结构/tile/properties/Moc.fits 应分别为 §4.1/§4.2/§4.4.1/§4.4.2）已由 M2b-B-04 定档，本条只登记其为**跨域同形态**而非 hips 独有
  - 机器门判据（原文，docstring）:「C3_clauses_form」（仅形式检查）；实测其实现只断言 CLAUSES/条款列含 `§` 形态锚，无任何「条款号↔主题」映射表
- 权威依据: STD-REG-001 §1.2（禁止按实现反推标准）、§1.6（域/条款映射变更须走宪章 §1.2）、§5 C1–C7 机器合同；宪章 §12.3-3/-9、§17.11
- 问题说明: 同一失效模式横跨四域（11 处错挂），说明它不是个别笔误而是**流程缺口**：注册表把「条款号」当作自由文本写，检查器只查形态不查语义，标准原文又从不入库比对。后果是所有据此清单做的收敛（DISP-FITS-001、STD-F4、D.healpix/D.spherical_projection 各行）都对着错误的章节验证。特别地：spherical-projection 的 LONPOLE 行除条款号外，其 PROJECT_DEFINED 理由本身也失真（把柱面投影的 θ₀ 说成 +90°，标准明写「In cylindrical projections, where θ₀ = 0」；且「不写 LONPOLE = 标准默认」仅在 δ₀≥0 成立）——该语义部分连同 1-based 桥接第二实现、TAN 半球界等价断言、CRVAL2 不进映射三条，一并移交 M1a/M7（投影域），本条只登记条款锚错挂面。
- 影响: 六域符合性判定的「条款↔实现」对应关系整体不可信，注册表的机器可校验前提（§5）名存实亡；按错锚施工会产新违规（STD-F4 即为一例，见 M2b-B-04）。
- 建议处置: ① 逐行重挂四域条款号（FITS：§3.1/§4.4.1/§4.4.2+附录 J/§7；HEALPix：§5 正文/§5.1/§5.2；WCS II：§2.2/§2.3；HiPS：§4.1/§4.2/§4.4.1/§4.4.2）；② 检查器新增 C8′「条款号↔主题白名单」——为四份标准各入库一份**机器可读的条款表**（可由本次实测的官方目录/正文生成），逐行断言条款号存在且主题匹配；③ 把「标准原文取回件（URL + 取回日期）」入库为注册表的旁证列，杜绝再次凭记忆写条款号。
- 置信度: 高
- related: M2b-B-04（hips 实例）、M2b-B-07（healpix 实例）、M2b-B-09（fits §6 行的实质后果）、M2b-B-08、M1a/M7（LONPOLE/θ₀ 语义、1-based 第二桥接、TAN 等价断言、CRVAL2 映射四条移交）、L15-007、L15-011
- 来源: L15-007 + L15-011（条款锚面并档；语义面移交）
