### M5a-D-001 三个跨模块公共头把 cpu_workers=0 释义为 auto/OpenMP，实现却一律退化为 1（串行）

- 问题说明: 三个公共头（跨模块 C ABI 面）把 `cpu_workers=0` 解释为「auto：omp_get_max_threads / hardware_concurrency」，并声明并行受 `P2_ENABLE_OPENMP` 宏支配；复算实现：`sampler.cpp:883` 与 `upm.cpp:515/615/658/775` 一律 `>0 ? x : 1`，即 0 与负值 → **1（串行）**，`upm.cpp:1478` 同型；且 OpenMP 条件已从 sampler/upm 移除（`sampler.cpp:880-882` 自述「OpenMP 条件已移除」，并由 `tests/backend/test_p2001_parallel_sampler.py:91`、`test_p2002_parallel_upm.py:97` 反向断言钉住）。三处头之间亦互斥：sampler.h 说 0=omp/hw，execution_options.h:16 说 0=max(1,hw)，实现说 0=1。另注（诚实标注登记状态）：upm.h:89-91 的漂移已在 ALG 层登记为 DISP-P2UPM-002 且未整改，而 upm.h:176 的「auto=omp_get_max_threads」与 sampler.h:54-56 的「0=auto + OpenMP 门控」**不在任何偏差 ID 覆盖内**。公共头均未给出线程安全/租约前置条件。
- 影响: 任何按头文件语义传 0 期望「自动并行」的调用方，在 Phase2 采样/UPM 物化上得到单线程执行（§17.6 禁止项），而门侧看到的 workers 仍是预算值（M5a-G-004），无法发现；`tests/unit/p2_workers_test.cpp` 的 `== 0 || >= 2` 类断言亦随语义摇摆。
- 建议处置: 统一 0 的语义（要么 auto=Runtime 预算，要么显式禁止 0 并返回参数错误），在三个公共头写清「取值来自 Runtime 租约、0/负值的确定行为、线程安全与所有权前置条件」，删除 upm.h:176 与 sampler.h:55 的 OpenMP 表述；把未覆盖的两处并入 DISP-P2UPM-002 同型登记或直接整改。
