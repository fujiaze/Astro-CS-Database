### M3-D-001 `calibrator.cpp` 文件头登记了不存在的搜索算法与固定线程数，与同文件正文自相矛盾
- 类别: D_COMMENT ｜ 优先级: P1 ｜ 来源: L05-005
- 位置: `lib/calibration/src/calibrator.cpp::文件头注释块`（复核时点 :3-26，关键行 :5、:14-16、:25）对照 `::calibrate_d 上方注释`（:98-99）；对照 `lib/calibration/src/dark_optimizer.cpp::optimize_dark_k`（:97）；对照 `docs/algorithms/CALIBRATION_ALGORITHMS.md::F3.2/F4.2`
- 证据摘录（复核时点重读）:
  > 5: 独立实现优化搜索算法 (黄金分割线搜索)，自动推导最优 Dark-Bias 扣除系数 K（文件头）
  > 14-16: 科学公式 (SCI-CAL-001 §5): … dark_opt=1: cal = (raw - bias - K*(dark - bias)) / flat_norm, K = optimize_dark_scale(...)
  > 25: OpenMP: 可独立并行，固定 16 线程
  > K 由调用方显式传入（t_light/t_dark，见 ALG-CAL §4），本模块不使用优化搜索。（calibrator.cpp:98-99）
- 权威依据: 宪章 §12.2（注释与文档/代码不得冲突）、§12.3-1、§4.1；SCI-CAL-001 §10（K 必须是比值）
- 问题说明: ① 全文件不存在 `optimize_dark_scale` 或任何搜索实现，实际 K 优化在另一文件且为**网格搜索**（`dark_optimizer.cpp::optimize_dark_k`，非黄金分割）；② 头注把 `K=optimize_dark_scale(...)` 写进「科学公式 (SCI-CAL-001 §5)」名下，而 SCI §5 冻结的是 `K=t_light/t_dark`，同文件 :98-99 又正确声明「本模块不使用优化搜索」→ 同一文件内头注与正文互斥，且头注把违禁算法表述为合同公式；③ 头注指向的 `lib/astro_calibration/include/astro_calibration.h` 路径在仓库中不存在（复核时 glob 零命中）；④ 「固定 16 线程」无任何 `num_threads` 支撑（`lib/calibration/src` 内 `#pragma omp parallel for` 一律裸写，线程数由 OpenMP ICV 决定，属 Runtime 预算，禁私有预算）。
- 影响: 注释把「SCI 禁止的 K 搜索」呈现为本模块职责，是 orchestrator/config 层历史 `dark_scale_mode=optimized` 无效参数（M3-C-009）的同族误导源；「16 线程」是与宪章 §10.4 相悖的私有预算措辞。
- 建议处置: 重写文件头：算法清单只保留实际存在的 `normalize_flat/calibrate/calibrate_d`；K 一律表述为 `t_light/t_dark`；删除「固定 16 线程」改述「并行度由 Runtime/OpenMP ICV 决定」；路径改指 `lib/calibration/include/`。
- 置信度: 高 ｜ related: M3-C-009、M3-D-002、M3-A-006、M5a-C-002

### M3-D-002 公共头用「全链路 double 不降级」总括 FP64 路径，与同段细则和 API 合同相反
- 类别: D_COMMENT ｜ 优先级: P1 ｜ 来源: L05-010
- 位置: `lib/calibration/include/astro_calibration.h::FP64 变体段落头注`（复核时点 :110-120，关键 :112 vs :115-116）；`lib/calibration/src/ac_api.cpp::ac_calibrate_frame_f64 实现注`（:139-141）；对照 `docs/contracts/API_CONTRACTS.csv::API-CAL-008`（:43）、`docs/architecture/PUBLIC_API.md::P1CAL 表`（:123-124）、`docs/algorithms/CALIBRATION_ALGORITHMS.md::F4.2`
- 证据摘录（复核时点重读）:
  > // FP64 变体：输入输出全链路使用 double，不降级 float（astro_calibration.h:112）
  > // 归一化统计（median/MAD）与坏点检测统计仍在 FP32 域计算后转 double 阈值；
  > // mask 语义与 FP32 完全一致（1=坏）。（astro_calibration.h:115-116）
  > // FP64 包装：输入转 double 处理，输出降级 float（ac_api.cpp:140）
  > API-CAL-008 … 内部 float32 处理（登记偏差）（API_CONTRACTS.csv:43）
  > 偏差已登记：统计核 FP32；输入/输出双精度；不降级 float…（PUBLIC_API.md:123-124）
- 权威依据: 宪章 §12.2、§5.3、§12.3-1；SCI-CAL-001 §9（精度策略）
- 问题说明: 同一段落内 :112 的总括（「全链路…不降级」）与 :115-116 的细则（统计核 FP32）互相限定，且实现注释 :140 又出现第三种说法「输出降级 float」（实际 `ac_calibrate_frame_f64` 输出是 `double*`，:141 的「降级」指内部 `ac::calibrate` 在 float 域完成）。四处措辞三种口径，而登记偏差的准确版本只存在于 API_CONTRACTS/PUBLIC_API。公共头是 L7 但被当作实现输入（AGENTS.md 第 4 条），读头者会认为整条 FP64 链为双精度。
- 影响: 精度合同的可核验性；对 `_f64` 变体的误差预算推断（是否 FP32 截断）会得出错误结论。
- 建议处置: 头注统一为 PUBLIC_API:123 的登记口径：「I/O 为 double；归一化与坏点统计核为 FP32（偏差已登记 API-CAL-008）」；删除 :140 的「输出降级 float」。
- 置信度: 高 ｜ related: M3-D-001、M3-I-001、M3-A-009

### M3-D-003 SNR 公共头缺线程安全/生命周期注释，且 `star_ids` 承诺回填而实现直接丢弃、`fit_status` 把 NaN 状态误判为拒绝

- 问题说明: ① `PsfFitQualityRow` 结构体（:68-79）**没有** `star_id` 成员，因此头注「star_ids 可空（空则填 0）」描述的是一条不存在的输出通道；实现只 `(void)star_ids;`（:325），既不回填也不校验长度（传入短数组不报错，因根本不被读）→ 注释给出错误的接口承诺，且与同头 :311-315 的 `SnrControlPointV3.star_id`「lineage 已接」声明形成两套事实：PSF 质量行**无**行号血缘；② `fit_status` 用 `status != 0.0` 判「拒绝」，`status=NaN`（上游非有限时常见）会静默落入「正常拒绝」，与同函数 :317 专门区分「非有限输入 → 3」不对称；且 :77 的注释枚举与实际分支不完全对应（NaN 情形未登记）；③ `snr_noise_model_v1_free` 只做 `delete[]` 与 `free`，头注（:207）未登记内部 `model_floor_registry()` 的残留语义；同头 `:259-262`「线程安全：同一 model 并发只读安全；并发写不安全」在 `snr_estimator.cpp` 内 grep `omp|std::thread|atomic|mutex` 零命中，属无对应实现的承诺；④ `g_model_floor` 注册点在 `noise_model_impl`（:126），而公共入口 `snr_noise_model_v1` 的 `variance<=0 → rc=1` 分支（:225-227）不注册 → `free` 对未注册键执行 erase 是空操作（无害但注释未区分）。
- 影响: 按 `:82` 注释的调用方会传 `star_ids` 并期待行号血缘，实际拿不到，导致 SNR 控制点与 PSF 目录行的血缘断裂被误认为已建立；PSF 质量行无法归因到具体星。
- 建议处置: (a) 给 `PsfFitQualityRow` 增加 `star_id` 并真正回填（推荐，与 V3 一致），或删除 `:82` 该行注释并显式声明「输出行序即目录行序」；(b) `status` 非有限单列一码；(c) 为 `free` 登记残留语义；(d) 线程安全承诺若保留，须有实现或测试支撑。
- 置信度: 高 ｜ related: M3-C-011、M3-A-001、M3-C-002
