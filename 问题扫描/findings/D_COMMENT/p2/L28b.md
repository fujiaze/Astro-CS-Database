- 问题说明: 三点。①行尾的 [] 是**被掏空的溯源括号**（原样为 [ID] 或 [文件:行] 形式，内容已删而括号留下）——同一注释块在结构上仍呈现「有引用」的形状，人扫一眼会以为已挂锚，机器关键词门（找 reference/来源/[] 括号）同样判通过；②复算：本仓「注释里出现行尾空括号」的模式共 5 处（grep 命中计数），其中 4 处是合法数组语法（如 snr_estimator.h:349 的 SnrControlPointV3[]），只有本条是溯源残留 ⇒ 该模式若原样入门，假阳率 80%，必须再加「括号前无标识符/紧邻数值常量」限定；③1.25 在唯一含该数值的 ALG 文档里指的是外接圆半径因子（HP_CIRCUMRADIUS_FACTOR，用于 quick-reject 的 lim 计算），与本处「局部像素尺度比 max/min 的细分阈」语义无关，两文档间无任何一句区分 ⇒ 按值反查文档会取到错的语义，且此阈直接决定 nside 自适应细分（改变输出像素尺度与通量面）。
- 影响: 自适应细分阈的取值依据在仓内不可解析（既无 ID 也无推导）；1.25 的同值双义使「文档里能找到 1.25」被误当作已溯源证据；真实数据路径（healpix_drizzle 重采样）受影响面为该阈触发的层级选择，无当前错值证据。
- 建议处置: ①补该阈的出处（SCI/ALG 条款或推导）或按 COMMENT_STANDARD:15 显式登记为经验值并给保守方向（false positive/negative 取向）；②删除 [] 残留括号，机器门加判据「注释行尾出现空括号 [ ] 或（）→ 判 D_COMMENT-EMPTY-CITATION」，并按①②限定条件排除数组语法；③DRIZZLE_GEOMETRY.md 补一句两个 1.25 的区分（或改代码常量为具名不同值来源）。
