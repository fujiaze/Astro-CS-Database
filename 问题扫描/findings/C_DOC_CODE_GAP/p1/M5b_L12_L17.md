### M5b-C-04 实例生命周期合同要求的并发语义与 double-destroy 报错在实现中不存在，且检测本身读已释放内存
- 类别: C_DOC_CODE_GAP · 建议优先级: P1
- 位置: `include/astrocs/abi/lifecycle_v1.h::（状态机/并发规则/错误映射）`（现 :37、:44-49、:70-73）；`include/astrocs/abi/module_api_v1.h::（destroy 签名 / request_cancel 注释 / phase 字段）`（现 :48、:101-107）；`lib/calibration/src/module_entry.cpp::cal_inst::state`（现 :612-613）、`::cal_execute`（现 :1335、:1389）、`::cal_inspect`（现 :1424-1427）、`::cal_request_cancel`（现 :1444-1445）、`::cal_destroy`（现 :1454-1464）；同族 `lib/cosmetic/src/module_entry.cpp`（现 :523-524、:1224-1226）、`lib/snr_estimator/src/module_entry.cpp`（现 :894-896）
- 证据摘录:
  >  *   - 同一实例: execute 之间互斥…；inspect 可并发（const 只读诊断）; request_cancel 可并发（原子置位）
  >   - 调用时序/状态违例（含 execute 期间 destroy、destroy 后访问、double destroy 检测）→ ACS_ERR_STATE + …
  >     int                    state;      /* ACS_LC_STATE_* */
  >     volatile int32_t       cancel_req;
  >     if (inst->state == ACS_LC_STATE_DESTROYED) return;   /* double → 忽略 */
  >     inst->state = ACS_LC_STATE_DESTROYED;
  >     if (host && host->allocator && host->allocator->free) { host->allocator->free(..., inst); }
  >     void (*destroy)(acs_module_instance_v1* inst);
- 权威依据: 宪章 §8.6（C ABI 边界、所有权与失败语义）、§9、§11（不得吞错继续产出看似成功的产品）、§13.2；`docs/architecture/abi/ABI_002_MODULE_ABI.md`
- 问题说明: ①`state` 是普通 `int`（5 处实现一致），既非 `_Atomic` 也无锁，却被 execute/cancel 在"允许并发"的规则下读写 ⇒ "request_cancel 可并发（原子置位）"与"inspect 可并发"在 C++ 内存模型下是数据竞争；只有 `cancel_req` 用 volatile，而 volatile 不构成原子性/可见性合同。②`destroy` 先读 `inst->state` 判 double、再置 DESTROYED、**然后** `free(inst)`（:1458-1463）⇒ 第二次 destroy 的判定读的是已释放内存（当前 allocator 是 host 注入的 free，可被后续分配复用），检测建立在 UAF 读上；`inspect` 在 DESTROYED 分支同样读已释放对象（:1424-1427）。③合同要求 double destroy → `ACS_ERR_STATE + ACS_DIAG_ECODE_DOUBLE_DESTROY`，但 vtable 里 `destroy` 返回 `void`，**无法返回任何状态**，故 :70-73 承诺的错误面在 ABI 层不可实现（另两模块 `drizzle/hips/gaia` 的 destroy 前校验返回 ACS_ERR_STATE，说明签名不统一）。④`module_api_v1.h:48` 的 `phase` 字段值域写成 `1|2|3|catalog=0?`（带问号），`lifecycle_v1.h:28` 注释称"本头枚举+判定函数冻结"却不含该值域，`module_dll_contract.schema.json` 的 `phase` 为 `maximum:3,minimum:1` ⇒ "唯一真源"三处并存且互相排除。
- 影响: 取消/销毁路径在并发下为未定义行为；double-destroy 与 destroy 后访问既不可检测也不可报错，与 ABI 合同文本相反；宿主无法据 ABI 做"独立加载/卸载"验证（§17-3）。
- 建议处置: `state` 改 `_Atomic int`（或 acquire/release 显式化）并把规则写回头文件；double-destroy 检测改为 host 侧句柄表判定或把 `destroy` 改为返回 `acs_status` 并统一 5 处实现；`phase` 值域以生成头单一提供。
- 置信度: 高 · related: M5a 并发条目、M5b-G-14
