- 问题说明: 复算 `commands.cpp` 内 `--cpu-profile` 的全部引用只出现在 `cmd_show_effective`（预览命令）及其辅助段；三个 `phaseN run` 与 `run_with_resource_gate` 均不读取该值，预算恒取 `cli_affinity_cpu_count()`，适配器层 provider 字段以 15 处 `"baseline"` 字面量写死。于是 `astrocs phase2 run --cpu-profile cpu_profile.json` 会**接受并静默忽略**该参数：profile 里的逐 kernel provider/workers/block 不参与执行，`route_kernel_from_profile` 在真实执行路径中一次也不被调用（该函数唯一调用点在 show-effective）。后果包括：§10.3 的逐 kernel 选路（BENCH-005/ARCH-BACKEND-001 §5）在产品行为上不存在；`config show-effective` 报告的 `kernel_routes` 与实际执行不一致，属「预览值与执行值两套口径」的结构风险（注意：show-effective 本身是 plan 语义，尚不构成 §11 的「计划值伪装实际值」，故本条不升级）；AVX2/AVX-512 的 SHIP 决策对产品无效果。

- 置信度: 高
