## M7-C-201 ALG 称 `bitpix=−64` 输出 FP64 精度，而该通道上游源恒 float32 ⇒ 声明的精度增益不存在（L20-025）
- 类别: C_DOC_CODE_GAP · 优先级: P2（本代理同意原级：误导元数据与容差前提，不改变数值）
- 位置 `docs/algorithms/PHASE3_FITS_IMPL.md::§/bitpix 块`（复核时 :38/:76/:86/:121 命中 bitpix）
- 问题说明 文档把 `−64` 与「double 精度」绑定，但同一链上游（重采样源像素 / tile 缓冲）恒 float32 ⇒ `−64` 只是把 float32 值零扩展，有效位不变。连带两处后果：①`M7-A-129③`（bilinear Σw 逐位）在该通道下**并不会真的可见**，本代理据此把该子项从「独立破口」降为「接入真 FP64 源后才成立」；②同篇的「逐值精确」类容差（`M7-F-201`）在错误的精度前提下被判定。
- 影响 精度声明失真；据此设的逐位容差与 Oracle 判据失去意义。
- 处置 ①文档改述「−64 是容器位深，有效位由源 float32 决定」；②若确要 FP64 增益，须按 §1.2 登记精度口径变更并改上游累加域；③全层口径按父层 3 号移交统一为「**五处 FP64 声明与实际累加域不符 + 两处真实 FP32→FP64 截断**」（旧「三处 FP32 累加」表述作废，本文件与 `M7-I-201` 已按新表述写）。
- 置信度 中高（上游恒 float32 引 M2a 的 L04-001 累加域定稿 + 本代理复核文档措辞）
