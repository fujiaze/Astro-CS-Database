### M2b-C-05 lib/hips/types.h 的 ALG-HIPS-002..005 语义映射与 ALG-HIPS-001 §0 分节索引整体错位一格
- 类别: C_DOC_CODE_GAP
- 建议优先级: P2
- 位置: lib/hips/include/astrocs/hips/types.h::ASTROCS_HIPS_*_ID 宏段（「公式语义源」注释）；docs/algorithms/HIPS_WRITER.md::§0 分节索引 与 ::章头（ALG-HIPS-002/003/004/005）
- 证据摘录:
  - types.h（原文）:「/* SCI-DRZ-001 为共享引用 …；ALG 面 001..005 中 describe 的 alg_id 槽承载主公式面 ALG-HIPS-001 (产品语义), 002..005 同链 (**ALG-HIPS-002 variance/ivar, 003 hierarchy 聚合, 004 MOC/UNIQ, 005 SNR Catalogue**)。 */」
  - ALG §0 索引（原文）:「001 产品生命周期与参数校验（本文 §1）；002 叶级 tile 写出信号/支撑（§2）；003 方差/逆方差 tile（§3）；004 hierarchy 聚合（§4）；005 MOC/properties/SNR/manifest（§5）」（本次实测 ALG 章头逐条对应：「## 3. ALG-HIPS-003 — 方差/逆方差 tile（VARIANCE/IVAR 产品）」「## 4. ALG-HIPS-004 — 低阶 hierarchy 聚合」「## 5. ALG-HIPS-005 — MOC、properties、SNR 产品与 manifest 收尾」）
- 权威依据: 宪章 §7.3（科学=算法=接口=代码=测试 的 ID 同构）、§12.3-3（交叉引用可定位）
- 问题说明: 头文件给出的 002..005 语义与 ALG 实际分节整体**后移一格**：002 实为「叶级 tile 写出（信号/支撑）」而非 variance/ivar；003 实为 variance/ivar；004 实为 hierarchy；005 实为「MOC/properties/SNR/manifest 收尾」。另 types.h 把 manifest 与 SNR 拆为独立 ID（005/006 语义链），而 ALG 侧 manifest 是 005 的 (5d) 小节、SNR 是 (5c)——即一次错位 + 一次拆分。头文件是模块合同的签名级权威，按此映射查公式会系统性读到相邻错项（例如按 004 读 MOC/UNIQ 公式，实读到 hierarchy 聚合）。
- 影响: ALG↔接口↔注册表三面的 ID 对应关系在此断开；将来若把 alg_id 纳入机器核对（describe 面已回显该 ID），会以假红/假绿掩盖真实缺项。当前无功能错误（纯映射声明），故 P2。
- 建议处置: ① types.h 注释按 ALG §0 索引订正（002=叶级 tile 信号/支撑，003=variance/ivar，004=hierarchy，005=收尾含 MOC/SNR/manifest）；② 如确需为 manifest/支持像素带各立 ID，在 ALG §0 索引正式增设并同步 SCI/接口三面，不在头文件单方面宣布；③ 把 alg_id 映射纳入 check_doc_symbols 类检查的比对项。
- 置信度: 高
- related: M2b-E-01（同类：合同面引用与真源脱节）、M2b-A-02、L03-013

### M2b-C-06 manifest 的 nrej_tiles/nused_tiles 恒取叶级 tile 总数，与同文件 products 清单的 present 判据自相矛盾，且两键不在 ALG (5d) 字段清单内
- 类别: C_DOC_CODE_GAP
- 建议优先级: P2
- 位置: lib/astro_image_io/src/hips/aio_hips_writer.cpp::aio_hips_finalize 的 manifest 段（prods[] 表与 fprintf 参数）；docs/algorithms/HIPS_WRITER.md::ALG-HIPS-005 (5d) 字段清单 + ::§9 不变量 I8；lib/astro_image_io/src/hips/aio_hips_reader.cpp::manifest 键混淆注释段
- 证据摘录:
  - products 清单用 present 判据（原文）:「// 诊断平面只在真正写过 tile 时进入 products 清单 (与磁盘事实一致, 供 aio_hips_verify_product_set V4 双向核对)」＋表项「{AIO_HIPS_PRODUCT_NREJ, "nrej", ps->diag_nrej_tiles},」「{AIO_HIPS_PRODUCT_NUSED, "nused", ps->diag_nused_tiles},」＋「if ((ps->flags & p.flag) && p.present) { … }」
  - 计数字段却只看 flag（原文）:「  \"nrej_tiles\": %zu,\n"」「  \"nused_tiles\": %zu」实参「(size_t)(ps->flags & AIO_HIPS_PRODUCT_NREJ ? ps->leaf_ipix_list.size() : 0),」「(size_t)(ps->flags & AIO_HIPS_PRODUCT_NUSED ? ps->leaf_ipix_list.size() : 0)」
  - ALG 字段清单（原文，(5d)）:「manifest.json（:1086-1128）：format_version=1、hips_version="1.4"、nside/tile_width/data_type、products 列表、n_leaf_tiles=leaf_ipix_list.size()、moc_sky_fraction、astrocs_covered_sky_fraction、signal_dtype。」——**未列 nrej_tiles/nused_tiles**
  - ALG §9 不变量（原文）:「I8 manifest 计数字段=实际文件数」
  - reader 侧已知此混淆（原文）:「// nrej_tiles/nused_tiles 计数键混淆)」
- 权威依据: ALG-HIPS-001 §9 I8（manifest 计数字段=实际文件数）与 (5d) 字段集；宪章 §12.2、§12.3-9
- 问题说明: 同一 finalize 内两条互斥判据：products 清单要求 flag **且** diag_*_tiles 为真（即真正写过 tile）才登记 nrej/nused；nrej_tiles/nused_tiles 两个计数却只看 flag，值取 **leaf 级 tile 总数**（既非 nrej 通道自己的 tile 数，也不随 present 归零）。后果：① 若 NREJ 位置位但 diag 通道被跳过（本文件确有 fault_injected skip_write 注入口），manifest 会同时给出「products 不含 nrej」与「nrej_tiles=N」；② 计数语义与 I8 直接冲突；③ 这两个键不在 ALG 声明的字段集内，属未经合同登记的 manifest 扩展；④ reader 注释已把该问题标为「混淆」但无人订正文档。
- 影响: manifest 作为产品自我声明面出现内部矛盾与越权字段；按 I8 做审计的下游（发布层、verify V4）会拿到不可解释的计数。不改像素数值，故 P2。
- 建议处置: ① 计数改与 products 同一判据（present 为假则记 0），且计数应为该通道实际落盘 tile 数（可用新增的 diag 计数成员，而非 leaf 总数）；② 要么在 ALG (5d) 正式登记两键与其语义，要么从 manifest 移除；③ 补一条断言：manifest.products 与 *\_tiles 计数方向一致（present=false ⇒ count=0）。
- 置信度: 高
- related: M2b-F-02（同一「声明↔事实」不一致族的测试面）、M2b-E-01（(5d) 锚亦漂移）、L03-019
- 来源: L03-019
