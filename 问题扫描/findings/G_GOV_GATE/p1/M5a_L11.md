### M5a-G-006 同一进程存在第二线程预算源：OpenMP 隐式组队与 hardware_concurrency 自取绕过 Runtime 预算
- 类别: G_GOV_GATE
- 建议优先级: P1
- 来源: L11-006
- 位置:

  - `docs/architecture/THREAD_BUDGET_ARCH.md::§1`（:8-10）；`docs/standards/CONCURRENCY_STANDARD.md`（:5-6、:19）
  - 正确做法的既有实现（未被 run 路径消费）：`lib/backend_host/cpu_features.h:22`、`lib/backend_host/worker_advisor.h:41,51`、`lib/backend_host/hardware_inspect.cpp:171`
- 证据摘录:
  > // lib/phase2/include/astro/phase2/execution_options.h — 全局执行预算唯一来源
  > inline int default_cpu_workers() {
  >     const unsigned hc = std::thread::hardware_concurrency();
  >     return hc > 0 ? static_cast<int>(hc) : 1;
  > - 一个进程只有一个资源调度器和线程预算源；   （宪章 §10.4 第一条）
  - `docs/architecture/THREAD_BUDGET_ARCH.md:8`：「CLI 启动时建立**唯一**全局预算对象：`available_cpus = affinity ∩ cgroup ∩ Job Object`（非机器总核…）」
  - `docs/standards/CONCURRENCY_STANDARD.md:5-6`：「库内随意修改全局 OpenMP setting（omp_set_num_threads 等）— 由 run context 统一控制（orchestrator stage 级）。」
- 权威依据: 宪章 §10.4（一个进程一个预算源；Runtime 防嵌套并行与超额订阅）、§17.6；ARCH-THREAD-001 §1（预算取值 = affinity ∩ cgroup ∩ Job Object）；STD-CONC:19
- 问题说明: ① `ExecutionOptions` 自称「全局执行预算唯一来源」，默认值却直接取 `hardware_concurrency()` 即**机器总核**，既不过 cgroup/Job Object 也不受 Runtime `ThreadBudget` 约束，与 ARCH-THREAD-001 §1 冻结取值直接冲突；同仓库 `lib/backend_host` 已实现 `cgroup_or_job_cpus` 折算，证明正确做法存在但 run 路径不消费。② `lib/` 生产源 99 处 `#pragma omp parallel`（带数字 `num_threads(\d)` 子句者为 0）按 `omp_get_max_threads`/环境自行组队；Runtime 不在 run 起点设 `OMP_NUM_THREADS`，租约数与其无关，故「Σ active ≤ budget」只在 std::thread 侧成立。③ 并发标准把统一控制权交给「orchestrator stage 级」，而 orchestrator 不在生产链（宪章 §3.2/§8.1 与 MODULE_MAP 的历史通道口径）→ 控制者指向空。④ 剔除叶子一处误归属：`cli/parser.cpp:273` 现属 `local_cpu_signature()`（:275-280），注释自述「非调度线程数」，是 profile 机器指纹而非预算源。
- 影响: 生产 run 的实际并发度可由 OpenMP 环境变量或宿主总核数决定；资源门看到的 workers 与 U 分母不覆盖这部分线程（§10.4 第二条不可证），cgroup 受限场景下造成超额订阅。
- 建议处置: Runtime 在 run 起点统一设定 `OMP_NUM_THREADS`/`omp_set_num_threads`（唯一源，取值 affinity∩cgroup∩Job），或把 OpenMP 区域改为受租约约束的 executor；`ExecutionOptions` 默认值改为消费 cpu_profile/lease；CONCURRENCY_STANDARD 的控制者改为 Runtime/CLI。
- 置信度: 高
- related: M5a-G-005、M5a-G-007、M5a-G-004
