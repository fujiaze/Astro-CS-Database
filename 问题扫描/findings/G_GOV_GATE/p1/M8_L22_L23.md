### M8-G-001 【元结论】注册面在三个方向上是空集：任何现有门都不能回答「这个证据/测试是否真被执行」

- 类别码: G_GOV_GATE
- 优先级: **P1**（判定器/门缺口；其三个实例分别已定 P0：M8-F-001、M8-F-004）
- 位置:
  - 方向①（存在但从未注册）：`tools/quality/check_ctest_registration.py::collect_real`、`::ADD_TEST_NAME_RE`（只从 add_test 出发，C1-C6 单向闭包）
  - 方向②（被采集但 0 用例）：`ci/validate_registry.py::R4`（:156 只验 discover 的 -s 目录存在）
  - 方向③（证据文件从不执行）：`docs/standards/checks/check_standards_registry.py::evaluate`（:209 `_clauses` 丢弃、:249 C3 只验 path_exists）+ 该判定器本身在全仓 `STD-REGISTRY` **0 命中**（既未注册也未挂账）
  - 配套空集面：`ci/known_failures.json` 全文仅 2 条挂账（UT-CLI expected:fail、p1_noise_adapter expected:conditional）
- 证据摘录:
  > （check_ctest_registration.py C1）扫描活动 CTest 面全部 CMake 源 ... 解析 add_test(NAME <target> ...)   ← 起点即"已注册"
  > （validate_registry.py:156）目录不存在 → FAIL("R4 ... -s 目录不存在")   ← 只验目录，不验用例数
  > （check_standards_registry.py:249）results.append(check("C3_evidence_path_%s" % key, False, "证据路径不存在: %s" % ref))   ← 唯一判据是存在性
- 权威依据: 宪章 §12.3-4（机器一致性检查必须能失败且指向真实对象）、§13.2（登记的验证须实际执行）、§17.10（追溯/证据清零）、§14.4（最小充分校验 fail-fast）
- 问题说明: 三条独立门各自"能失败"（CI-REG-002 还有 S1-S7 负例自检、R 规则、C6 防"登记但未真跑"），但**没有一条能从"应当被执行的东西"出发**，于是：一个 .cpp 测试源不写进 add_test → 无门报警；一个 discover 目录里 0 个 TestCase → 门绿；EVIDENCE 列指向从未编译的 .cpp → 判定器判 CONFORMANT。三个空集共同使「注册面 = 被执行面」这一隐含前提失效，也解释了为何 M8-F-001/004/005/006/011 全部落在同一根因上。
- 建议处置（三条建议门，按落点成本排序）: ①**discover 采集数硬门**：给 `ci/validate_registry.py` 增一条规则，检查项命令为 `unittest discover` 时，其 -s 目录内 `TestCase` 子类数（或 `-p` pattern 命中文件数）必须 > 0，为 0 即 FAIL（同 M5b-F-01 的 pattern 面）；②**测试源未注册即 FAIL**：给 `check_ctest_registration.py` 增一条反向枚举规则（磁盘上的 `*_test.cpp` / `test_*.c` 未出现在 add_test 且不在显式 LEGACY/ARCHIVE 白名单 → FAIL），并把 `tools/**/*.py`、`*.sh`、`*.ps1`、`Makefile` 一并纳入"执行面"匹配集；③**EVIDENCE 必须出现在执行面**：`check_standards_registry.py` 的 C3 由 path_exists 升级为「路径 ∈ ctest_baseline ∪ checks.json ∪ discover 采集根」，同时把该判定器注册进 `ci/checks.json`（消除"只被文档引用"的①号断点）。
- 影响: 门禁的"非豁免"外观（waivable=false）与实际可失败性脱钩；P0 级 §13.1 验证缺口无法被任何现有门自动收敛。
- 置信度: 高（三个门的判据逐行读；同仓正对照已计入，见 _merge §6）
- 来源: L23 §7 元结论（本代理独立复算并落为条目）
- related: **M2a-G-1**（断点①判定器不在册，主落 M2a）、**M7**（断点②判定式维度 < 条款面，:186/:193）、M8-F-001/004/005/006/011、M5b-F-01
- 说明: 本条为 M8 的元结论落点；「符合性证据链三处断点」总述由 M8 持有并直接进 SUMMARY（前台指定），本节即其机器面依据。

### M8-G-002 「选中检查全部合同化 SKIP」被 `ci/run.py` 判为整体 PASS；叠加 R4 不验采集数，形成"跑了个空集也算过"

- 类别码: G_GOV_GATE
- 优先级: **P1**
- 位置: `ci/run.py`（复核时点 :1038-1057，`SKIP_EXIT_CODE = 77`；`elif not executed and skipped_executed:` → 整体 PASS 分支）；对照 `ci/checks.json` 的 `prerequisite_tools` 面（全仓 18 处）与 `waivable` 字段
- 证据摘录:
  > （ci/run.py :1046-1053 区段）若本轮无 executed 但有 skipped_executed → 汇总判 PASS（不产生 no_checks_selected 类错误）
  > （实测）`no_checks_selected` 字面串在 ci/ 与 tools/ 0 命中
- 权威依据: 宪章 §12.3-4、§14.4（fail-fast）、§17.10
- 问题说明: 该分支本身是有意设计（合同化 SKIP 表示前置不满足），但与 M8-F-003（install 门恒 SKIP）、M8-F-011（realdata 只在可豁免 profile）叠加后，效果是"整条 profile 可以只由 SKIP 组成而仍报绿"，且没有任何门报告"本轮有效用例数"。这是 L23-014 原文里被错挂在「空集 PASS」标题下的那半部分（另半部分见 M8-F-015）。
- 影响: CI 汇总层的"绿"不再蕴含"有判定发生"；缺依赖的 profile 会静默空转。
- 建议处置: ①对 `waivable=false` 的检查项，若其内部全部用例为 skip，则至少降级为 SKIPPED 汇总并在日志打印 skipped 计数；②增加一条 profile 级不变量：每个非豁免 profile 的有效用例总数必须 ≥ 登记下限（与 M8-G-001 ① 同批实现）；③对 `prerequisite_tools` 未登记的项（如 UT-IO）要求显式声明，避免"依赖已装"成为口头假设。
- 置信度: 中高（分支逐字复核；"历史上是否真发生过整轮全 SKIP"需 CI 运行日志 → _merge §7 R6）
- 来源: L23-014（拆分后的 ①；改判为 G_GOV_GATE）
- related: M8-F-003、M8-F-011、M8-G-001；M5b-G-02/G-03（同族"恒 PASS"根因，主落 M5b）

### M8-G-003 已知失败基线的 40 个探针自身含 4 个恒真探针，且唯一针对恒真断言的 F-022 探针只查 1 个文件

- 类别码: G_GOV_GATE
- 优先级: **P1**
- 位置: `tools/quality/known_failures_baseline.py`（复核时点：F-032 :996 条件尾部 `or True`；F-033 :1002、F-036 :1028、F-037 :1034 判据为字面 `True`；F-022 :912-916 `p3_vacuous = "CHECK(true)" in p3_assembly_test`）
- 证据摘录:
  > （:996）results.append(probe("F-032", ... or True))            ← 恒真探针
  > （:1002/:1028/:1034）probe("F-033"/"F-036"/"F-037", True, ...)  ← 判据为字面 True
  > （:912-916）p3_vacuous = "CHECK(true)" in p3_assembly_test      ← 探针只读 p3_assembly_test.cpp 一个字面串
- 权威依据: 宪章 §12.3-4（检查器必须可失败）、§13.1、§14.5（修复须独立可验证）
- 问题说明: 该基线自测器（40 探针）的作用是"证明门会红"。其中 4 个探针无条件为真 ⇒ 它们对"门是否真能失败"贡献 0 证据，却计入自检通过数（探针总数与全绿计数被虚增）。而唯一针对恒真断言形态的 F-022 只覆盖 `p3_assembly_test.cpp` 一个文件的一个字面串 ⇒ M8-F-015 的另 4 处与 M8-F-007 的 2 处 `|| true` 全部在探针之外。
- 影响: 「基线自测 40/40 PASS」被读作"门都能失败"，实际含 4 个永不失败的自证探针；对 tests 面恒真化的防护半径远小于宣称。
- 建议处置: ①F-032/033/036/037 改为真判据（或显式标注为 POLICY 型并在 `ci/known_failures.json` 登记），自检报告分列"真判据探针数 / POLICY 探针数"；②F-022 探针正则扩集：全 `tests/**` + `lib/**/tests/**` 的 `CHECK(true)`、`CHECK(1)`、`CHECK(x || true)`、`if (true)`，命中即 FAIL；③给该自测器补"探针必须能因输入变化而改变结论"的元自检。
- 置信度: 高（四处逐字 + 探针面 grep）
- 来源: L23-014（本代理复验期间新增的子事实；非叶子原述）
- related: M8-F-007、M8-F-015、M8-G-001（方向②）、M5b-G-03（自反恒真根因，主落 M5b）
