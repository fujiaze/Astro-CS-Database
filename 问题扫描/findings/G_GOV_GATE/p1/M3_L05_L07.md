### M3-G-001 产品 manifest 把 cosmetic 报为 `available`，但两通道给检测的 Dark/Bias 恒为 `nullptr` → 检测在配置层不可能生效
- 类别: G_GOV_GATE ｜ 建议优先级: P1 ｜ 来源: L05-011
- 位置:
  - `lib/phase1_session/p1_session.cpp::cosmetic 阶段`（复核时点 :390-420，调用 :401-404 `ac_correct_frame(image_px(...), w, h, nullptr, nullptr, fixed.data(), …)`）
  - `lib/core/src/module_adapters.cpp::p1_op_cosmetic`（复核时点 :1367-1432，调用 :1401-1403 同为 `nullptr, nullptr`）
  - `lib/phase1_session/p1_session.cpp::manifest availability 块`（:444-452，`{"cosmetic","available"}` 与 `status="partial"`）
  - `docs/algorithms/COSMETIC_ALGORITHMS.md::§13 编排语义与 DISP-COS-009`（:146-156）
  - `lib/cosmetic/module.yaml:::31-33`（`status: CONTRACT_READY`）与 `docs/contracts/INDEX.yaml:::122-123`（`astrocs.phase1.cosmetic: CONTRACT_READY`）
  - 配置面：`docs/development/CONFIG_SCHEMA.md`（全文 85 行，无 cosmetic 母版/开关键）；`p1_session.cpp` 的 cosmetic 段只读 `method/hot_sigma/cold_sigma/max_structure_size`
- 证据摘录（复核时点重读）:
  >             const int rc = ac_correct_frame(image_px(im.get()), image_w(im.get()), image_h(im.get()), nullptr, nullptr, fixed.data(), …)（p1_session.cpp:401-404）
  >     const int rc = ac_correct_frame(im.px(), im.w(), im.h(), nullptr, nullptr, fixed.data(), hot_sigma, cold_sigma, method, mss, &hot, &cold);（module_adapters.cpp:1401-1403）
  >     s->manifest["availability"] = { {"calibration","available"}, {"cosmetic","available"}, … };（:445-447）
  > - 关键编排语义（生产事实，禁止美化）：`dark==NULL` 或 `hot_sigma<=0` → 热检测关闭；`bias==NULL` … 两者皆关 → 模块退化为空转 pass；（ALG-COS:146-149）
- 权威依据: 宪章 §16.2（未实现或未验收必须明确报告为未就绪，不得声明可用）、§12.3-10、§17-4；SCI-CAL-001 §8（坏点全帧须显式）
- 问题说明: 两条通道调用 `ac_correct_frame` 时第 4/5 参数（master_dark/master_bias）一律传 `nullptr`，按同一仓库的 ALG 登记语义（`dark==NULL → 热检测关闭`、`bias==NULL → 冷检测关闭`）等价于「两检测全禁用 → 逐像素恒等复制」；manifest 于是必然报 `cosmetic: available` + `stage ok` + `hot_fixed/cold_fixed=0`，而这两项在真实数据上永不为非零。**关键在于这不是运行时偶发而是配置层不可达**：两通道的输入键只有 method/sigma/max_structure_size，没有任何 `master_dark_path`/`master_bias_path` 键，CONFIG_SCHEMA 亦无对应项，用户无法通过配置启用检测。ALG-COS:146-156 诚实登记了该现状（DISP-COS-009「禁止美化」），但同一事实在**产品状态声明层**（availability=available）被反着表述。
  注：叶子原判含「`if (rc==AC_OK && (n_hot>0||n_cold>0))` 使计数为 0 时不置 available」这一形态，复核时点两通道均已无该形态（现为一律 available），故该子证据不成立、已剔除，本条结论改建立在「配置层不可达 + availability 声明」上。
- 影响: 发布状态声明与真实能力不一致（§16.2）；下游按 `available` 认为坏点已被修复，真实含热/冷缺陷的帧以「已清洗」名义进入 PSF/测光/积分，且 `hot_fixed=0` 看起来像「干净」而非「未检测」。
- 建议处置: (a) 把两通道的 cosmetic availability 降为 `disabled`/`degraded: no_master`，并在产品/manifest 里区分「未检测」与「无坏点」；(b) 若要保持 available，则补 `master_dark_path/master_bias_path` 配置键（含缺失时 fail-closed）并接线到 `ac_correct_frame`；(c) ALG-COS 的 DISP-COS-009 与本条声明层冲突应在同一控制包内一并闭合。
- 置信度: 高 ｜ related: M3-C-005、M3-I-001、M3-F-004
