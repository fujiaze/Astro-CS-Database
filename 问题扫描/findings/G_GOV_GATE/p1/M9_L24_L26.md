## M9-G-1 XPSD 魔数/长度校验失败不解除映射，句柄随下一次 memset 永久失联

- 类别: G_GOV_GATE（主，违 §14.4「fail-fast 须带资源回收」）；次挂 H_NUMERIC
- 优先级: P1
- 来源: L24-004（复验成立；锚点**保留**，:1034 逐字命中；本代理把「上游三个失败分支」精确化为 Win 3 支 + POSIX 2 支）
- 位置: lib/gaia_xpsd_client/src/gaia_client.c::load_xpsd_file（校验失败返回点）、::close_xpsd_file（唯一回收处）、::gaia_client_create_ex（目录扫描循环调用方）
- 证据摘录（逐字，复核时点现文）:
  > （:1034）if (xf->mmap_size < 16 || memcmp(xf->mmap_data, XPSD_MAGIC, 8) != 0) return -1; —— 无 UnmapViewOfFile/CloseHandle，也无 munmap/close。
  > 上游回收正对照（同一函数内）：Win 侧（:1021）if (!xf->hMap) { CloseHandle(xf->hFile); return -1; }、（:1023）if (!xf->mmap_data) { CloseHandle(xf->hMap); CloseHandle(xf->hFile); return -1; }；POSIX 侧（:1031）if (xf->mmap_data == MAP_FAILED) { close(xf->fd); return -1; }；打开失败（:1016/:1026）直接返回。
  > 放大机制（:1009）memset(xf, 0, sizeof(*xf)); —— 函数首行即清零，且 file_count 不自增时**下一个候选文件用同一下标**再进本函数 → 上一次的 mmap_data/fd/hMap/hFile 被抹掉，永久不可达。
- 权威依据: 宪章 §14.4（信任边界校验失败须就地回收并返回明确状态码；INPUT_CORRUPT 显式化）、§11、§10.5/§18.2（资源门禁：不受控句柄增长属发布门禁禁止项）。
- 问题说明: 三重叠加——①映射建立后的第一个校验直接 return，跳过本文件自己写明的回收路径（上游 5 个失败分支都做对了 → 是漏项不是风格）；②调用方只在 load 返回 0 的分支调用 close_xpsd_file，返回 -1 时无补偿；③:1009 的 memset 使失联不可恢复（destroy 也救不回）。另该路径不区分「太短」「魔数不符」「读取截断」，与 §14.4 要求显式损坏状态码不符。
- 影响: 目录中每有一个损坏或非 XPSD 的 .xpsd，每次 create 永久泄漏 1 映射 + 1 fd（或 Win 2 个内核句柄）；MAX_FILES=32 使单次有界，但 plan/create 在一次 run 中可多次调用 → 长跑表现为 fd 耗尽与地址空间持续增长。修复面极小（一处 goto fail 标签）。
- 建议处置: ①该 return -1 前统一走已有回收（引入单一 fail 标签）；②调用方对非 0 返回值也调用 close_xpsd_file（该函数对 mmap_data==NULL 幂等）；③区分并返回「长度不足 / 魔数不符 / 截断」三种损坏状态码；④注入「长度 8 的文件」与「魔数为 XPSD0000 的文件」并断言 fd 数不增（注册面见 M9-F-1；在册的 gaia_cat_test::mode_negative 已覆盖坏魔数但只断言 file_count==0，不断言句柄数——故该修复当前无回归可验）。
- 置信度: 高
- related: M9-H-3（同一函数的块区间模型缺失）、M2a-C-9（同函数静默接受面，主落 M2a）、M9-F-1（在册负例只断言"静默跳过"为期望，未断言资源不增）

## M9-G-2 树节点数组分配失败被 break 吞掉，仍返回成功并少注册若干棵树（部分天区静默为空）

- 类别: G_GOV_GATE（主，违 §14.4 禁「宽泛处置后继续」与 §11 禁吞错）；次挂 C_DOC_CODE_GAP
- 优先级: P1
- 来源: L24-006（复验成立；锚点**保留**，:1106/:1137 两处逐字命中）
- 位置: lib/gaia_xpsd_client/src/gaia_client.c::load_xpsd_file（树解析循环的 break 与出口 return 0）
- 证据摘录（逐字，复核时点现文）:
  > （:1104-1106）if (node_count > 0 && root_pos > 0) { ti->nodes = malloc(…); if (!ti->nodes) break; —— break 跳出的是「解析所有 Tree」的外层循环，不是失败路径。
  > （:1137）xf->tree_count++;（仅对已成功解析的树自增）；函数出口在树循环之后 return 0。
  > 同函数正对照：更早的 open/mmap 失败均正确 return -1（:1016/:1021/:1023/:1026/:1031）。
- 权威依据: 宪章 §14.4（禁宽泛处置后继续）、§11（禁吞错后产出"看似成功"的下游输入）、§5.3/§7.3（科学路径数值语义不得静默漂移）。
- 问题说明: tree_count 保持已解析棵数（可为 0），函数继续初始化块缓存并**返回 0（成功）**，调用方据此 file_count++ 并把该文件当完整数据集用。同一函数对更早失败都正确返回 -1 → 属漏判而非有意降级。附带同族静默点：::find_max_block_size（:935-942）返回 0 时 scratch 退化为 65536（:1865）而无任何状态暴露；:1867 if (!scratch) continue; 同型。
- 影响: 「部分加载被当成功」——树与树覆盖不同天区，被丢掉的树所在**整片天区在锥查询中静默为空**，返回 0 颗星与「该天区确实没有亮星」在接口上不可区分。下游 plate_solve 可能因参考星不足而失败或退化、测光定标的参考星集合被静默裁剪 → 直接改变科学数值。触发条件为内存压力或节点区撒谎造成超大分配（与 M9-H-3 同源）。
- 建议处置: ①malloc 失败改为资源类失败返回（与 open/mmap 失败同状态码语义）且不注册该文件；②同函数其它静默点（字段缺失、find_max_block_size 返回 0、scratch 分配失败 continue）按「要么完整要么拒绝」复核；③若确要保留「部分树可用」语义，必须变成显式契约：plan 上报完整性、execute 携带 PARTIAL 状态、禁止下游把 PARTIAL 当成功；④负例：注入 node_count 谎大致超大分配的 XPSD，断言 create 返回失败而非 file_count 少一（在册 mode_negative 的「只要部分树可加载即接受」断言须同步订正，见 M9 §8）。
- 置信度: 高
- related: M9-H-3（同一撒谎字段驱动超大分配）、M2a-C-9（在册测试把半加载钉成期望——本条修复会让该断言假失败，同 M9 §8 主题）、M9-G-1

## M9-G-3 Gaia 配置数组计数循环可无限自增（strtod 不推进时不消费字符）→ 模块全生命周期可被一次配置挂死

- 类别: G_GOV_GATE（主，违 §14.4 配置输入边界 fail-fast）；次挂 H_NUMERIC（活性 + CWE-190）
- 优先级: P1
- 来源: L24-007（复验成立；锚点**保留**；本代理**改写一处事实**：叶子称"三处调用"，实测 **4 处**）
- 位置: lib/gaia_xpsd_client/src/module_entry.c::json_get_f64_array（计数循环）；调用方 ::gaia_cfg_parse；上游入口 ::gaia_validate_config、::gaia_plan、::gaia_create、::gaia_execute
- 证据摘录（逐字，复核时点现文）:
  > （:191-192）while (*q && *q != "]") { / if (*q == '-' || (*q >= '0' && *q <= '9')) { count++; strtod(q, (char**)&q); } else q++ —— 单引号 '-' 属"数字起头"分支，而 strtod 在无法转换时**不推进 endptr** → *q 仍是 '-'、循环条件恒真。
  > 消费点：ra_list/dec_list 解析（:285-286 邻域）；gaia_cfg_parse 的调用点实测 4 处（:458 / :478 / :556 / :600）。
  > 第二遍夹紧（:199-202 邻域）用 i < count 限制写入 → 越界写不成立，本条只登记活性与 UB。
  > 同文件正对照：:101-105（出参容量不足即返回 PARAM + 诊断码）、:144（显式夹紧拷贝）。
- 权威依据: 宪章 §14.4（配置/CLI 输入属信任边界，须 fail-fast 返回明确状态码）、§10.5/§18.2（内存预算与资源门禁：无界分配属禁止项）、§11。
- 问题说明: 设计意图是「数字起头则 strtod 消费，否则手动 q++」，但 '-' 被归入数字起头而 strtod 可零推进 → count 无限自增且永不推进，进程挂死；count 为 int，持续自增另构成有符号溢出 UB（CWE-190）。另 count 无上限，超大数组 → malloc(count*8) 与 plan 阶段内存预算脱钩。触发输入如 [-]、[1,-,2]、[1e]。
- 影响: 该解析器被 validate_config / plan / create / **execute** 四处调用（叶子漏计 execute 一处，本条已改写）→ 模块生命周期每一步都可被一次配置挂死；无超时/活性护栏时表现为整进程无响应，属 §14.4 与 §10.5 双违。
- 建议处置: ①计数循环记录 prev=q，strtod 后若 q==prev 即判语法错误（*out_n=-1 返回 NULL）——把「零推进」显式判为非法；②对 count 设登记常量上限，超限返回 ACS_ERR_PARAM 而非分配；③负例 [-]、[1,-,2]、[]、[1e]、超大元素数各一，断言不挂死且状态码明确，挂在已注册的 gaia ABI 测试面（gaia_cat_test 已在册，可挂同处，成本最低）。
- 置信度: 高
- related: M9-H-1（同一 catalog_dir 配置面，另一事实=栈溢出）、M9-G-4（同为「一次输入即破坏原子提交不变量」的交付面缺陷）

- 类别: G_GOV_GATE（主，违 §11 原子提交条款）；次挂 C_DOC_CODE_GAP
- 优先级: P1
- 来源: L24-011（复验成立；锚点**保留**，:1077/:1078/:1228/:1229/:1095-1099 全部命中；常量定义处已定位到真实头文件）
- 位置: runtime/io/fits_core.c::acs_fio_writer_begin_v1（拷贝与 tmp 生成）、::fio_writer_make_tmp_name、结构体 acs_fio_writer_v1_s；常量 ACS_FIO_PATH_MAX 定义于 modules/services/io/include/astrocs/io/fits_stream_v1.h:33（=512）
- 证据摘录（逐字，复核时点现文）:
  > （:1077-1078）char target[ACS_FIO_PATH_MAX]; / char tmp[ACS_FIO_PATH_MAX];（:747 邻域同用该常量）
  > （:1228）snprintf(wr->target, sizeof(wr->target), "%s", path_utf8); （:1229）fio_writer_make_tmp_name(path_utf8, wr->tmp, sizeof(wr->tmp)); （:1231）st = fio_file_open(&wr->f, wr->tmp, "w+b", …)
  > （:1095-1099）static void fio_writer_make_tmp_name(const char* target, char* out, size_t cap) { … snprintf(out, cap, "%s.tmp.%ld.%lu", target, (long)getpid(), seq); } —— **不检查返回值**。
  > begin_v1 的入参校验面：仅 NULL 与 err 容量，无 strlen(path_utf8) 对照。
  > 同仓正对照：runtime/io/hips_core.c:533-536 static int hips_join_path(char* path, size_t path_cap, …) { … if (dn + 1 + rn + 1 > path_cap) return ACS_HIPS_ERR_PARAM; }（调用点 :579/:812/:871 均传 sizeof(path)）→ **溢出即报错的写法本仓已有，且就在同一 runtime/io 目录内**。
  > 另一正对照（同族发布原语）：lib/hips/src/aio_publish.cpp:299 if (n <= 0 || (size_t)n >= sizeof(stage) || (uint64_t)n >= stage_path_cap) return AIO_PUBLISH_ERR_PARAM;（对 snprintf 返回值做截断拒绝）。
- 权威依据: 宪章 §11（临时文件+原子重命名提交；禁原地覆写产品路径）、§14.4、§8.3（IO-001 为唯一写出边界）、§12.3。
- 问题说明: target 用 snprintf 拷贝（超长静默截为 511 字符），tmp 由「path_utf8 + .tmp.<pid>.<seq>」再 snprintf 到同样 512 字节。当 strlen(path_utf8) ≥ 511 时 **tmp 的截断结果恰等于 target → tmp == target**：随后以 "w+b" 截断模式**原地打开并清空最终产品路径**，写入过程直接暴露在正式路径上（崩溃/取消/EPIPE 都留下半截正式文件），最后 rename(wr->tmp, wr->target) 变成自己改自己、永远"成功"。两个后果同时发生：①原子提交被静默替换为原地覆写，且 overwrite=0 的"目标已存在则失败"保护也失效（探测用未截断的 path_utf8，实际写的是截断路径）；②**不同目标只要前 511 字符相同即塌缩到同一文件，两帧/两 tile 互相覆写而无任何错误**。Linux 无 PATH_MAX 硬限制 → 该形态**主要在 Windows 正式平台必现**（Linux 上 512 只是保守常量，不必然触发）。
- 影响: 该 writer 是 IO-001 唯一 FITS 原子写实现（astrocs_io 导出）。**当前 lib/cli 内无生产调用点**（本代理复核口径：对 acs_fio_writer_begin_v1/end_v1/write_v1 全仓 grep 后按文件归属计数，调用者只有 modules/services/io/tests/fits_core_selftest.c、tests/io/{make_hips_fixture,test_fits_stream_contract,hips_output_fixture}.py 与 runtime/io/fits_core.c 自身，lib/ 与 cli/ 命中 0），故当下生产写出路径不受影响；但 tests/io 的 HiPS/FITS 合同测试与 fixture 生成器都走它，一旦按 §8.3 把三个 Phase 的写出收敛到本边界，深输出目录 + 中文目录 + 长 run 目录场景即为产品破坏。
- 建议处置: ①begin 入口校验 strlen(path_utf8) < ACS_FIO_PATH_MAX - 48（为 tmp 后缀留确定余量），超限返回 PARAM 并在 err 里写清上限与实测长度；②ACS_FIO_PATH_MAX 提到 OS 上限（Linux 4096 / Windows 长路径 32767）或动态分配；③长度回归用例 511/512/508 三档 + "两目标仅尾部不同"的碰撞用例，断言拒绝且不留半成品；④确认发布物是否声明 longPathAware；⑤把 hips_core.c::hips_join_path 的"溢出即报错"写法提为 runtime/io 共用小函数（同目录即有，成本一行）。
- 置信度: 高
- 条件升级: **当前 P1 → 接线即升 P0**。触发判据：任一生产写出路径改走 acs_fio_writer_*（即 §8.3 的 IO 收敛批次落地，或 lib/drizzle、lib/hips、p1_* 节点的 FITS 写出改为经 IO-001）。升档理由：彼时该缺陷直接破坏正式产品文件（原地覆写 + 相互塌缩），属"产品不合规/数据破坏"而非"边界不设防"。
- 平台盲区: **是**（Linux 无 PATH_MAX 硬限，Windows 才必现；聚合清单见 _merge/M9.md §4）
- related: M9-G-5（同一提交点的另一事实=无 fsync）、M9-C-1（同边界另一事实=无 UTF-8→UTF-16 适配）、F00-07b（前台已重挂至本文件本函数）、M9-H-6（第三条 Windows-only 站点）、M9 §3 正对照表第 3/4 行

- 影响: 与 M9-G-4 同面——**当前 lib/cli 无生产调用点**（同一复核口径），故属"边界承诺与实现不符"而非现产数据损失；一旦写出收敛到 IO-001，即成为交付产品的静默损坏来源（且极难在 Linux CI 复现）。
- 建议处置: ①acs_fio_writer_end_v1 在 close 前对文件句柄加 durability barrier（POSIX fsync(fileno(fp))；Win 用 FlushFileBuffers 或 CRT _commit，照抄 aio_publish.cpp:34 的同仓写法），失败即整体失败并删除 tmp；②rename 成功后对**父目录**做一次 fsync（同 aio_publish :369-384 分支），或在合同面明示不做并说明理由；③把 :14 的流程注释与 :1464-1480 实际序列订正为一致（写明"flush=到内核，fsync=到介质"）；④新增用例：rename 前注入写回失败/进程终止，断言 target 不出现零长度产品（真掉电场景标注为**需执行权限**，见 _merge/M9.md §12）；⑤与 M9-G-4 一并交给「IO 写出收敛」批次的验收清单（同一提交点，勿分两次改）。
