- 问题说明: 三套私造 logger 与 host `acs_logger` 并存，各自定义：①私有级别环境变量（`DYNAMIC_PSF_LOG_LEVEL`/`STAR_DETECTOR_LOG_LEVEL`，且缺省级互不一致：WARN vs INFO）；②以 **CWD 相对路径** 在源码树内 `create_directories` 并追加写 `lib/<模块>/logs/*.log`（ipv 更是 `<frame>/` 逐帧目录 + stderr 双写）——日志落点取决于进程当前工作目录，既污染真源树又不可定位，直接违反 AGENTS 目录规范与 §11；③科学/生产路径无条件 stderr：`photometry_apply`（每次调用打印 w/h/photscal/总像素）、`snr_estimator.cpp`（逐星/每帧中间量）、`sampler.cpp`（计算区间入口与关键节点）——其中 `master_generator.cpp:15` 还把「日志输出到 stderr」当作设计陈述写进注释。
- 影响: 模块日志绕开 Runtime 的 run-trace/resource 证据链（§11 八件套），Fatduck/CI 侧无法按 run 收集；大帧/高频调用下的 stderr 洪水落在计算区间内，扰动 §10.5 利用率与 I/O wait 测量；`lib/*/logs/` 使工作树脏化（git status 噪声、并发扫描代理误读）。
- 建议处置: ①三套 logger 收敛到 host `acs_logger`（级别由 Runtime/profile 决定，禁私有环境变量）；②日志路径一律由 host 注入、禁 CWD 相对路径与源码树落点；③无条件 stderr 打印改为 DEBUG 门控或经 host logger，并删除把该行为写成设计的注释；④机器门：禁止 `lib/**` 内出现 `create_directories("(lib|build)/...` 与相对 `logs` 字面量。
