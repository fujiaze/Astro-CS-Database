# V19 片1 · P1（恒绿空壳 profile 与依赖声明反向闭包缺失）

### V19-N-02（P1）`fatduck` profile **成员 0 却映射 exit 0** ⇒ 真机复验通道是恒绿空壳
- 实测：profiles census = `{fast:63, linux-main:122, windows-main:68, linux-deep:7, **fatduck:0**}`；platform census = `{any:71, linux:57, windows:4}`（**无 fatduck**）；而 schema 的 `profiles` enum **里有 `fatduck`**。
- 代码链：`ci/run.py:1043-1045` `verdict="FATDUCK_PENDING"`（**executed 为空即给**）→ `:1294 return EXIT_OK if verdict in ("PASS","FATDUCK_PENDING")` ⇒ **`--profile fatduck` 在零项检查下返回 0**。`问题扫描/` 全树检索 `FATDUCK_PENDING` **0 命中 ⇒ 新站**。
- 改法二选一：①真登记 `platform:"fatduck"` 的门（哪怕只校外部证据包）使 profile 非空；②无此计划则**从 `PROFILES`/schema 枚举删 `fatduck`**，并把 `:1043-1045` 并入 `:1055-1057` 的 `no_checks_selected` FAIL ⇒ **`FATDUCK_PENDING` 只准作 `CI_RESULT` 标记，不得映射 `EXIT_OK`**。
- **related** `M8-G-002`（选中全 SKIP 判整体 PASS，同"空证据也算过"族）、`V9-N-10`、`C-19`、`R-05`/`R-13`、`FD-F-003`

### V19-N-03（P1）`serves_checks` 只声明 **2** 个消费者，实消费其产物的门有 **9** 道；两个 serve 步**无 `require_outputs`** ⇒ 连"产物是否在位"都不核
- `ci/workflow_binding.json`：`LINUX-PREPARE-FIXTURES` 与 `LINUX-BUILD-ROOT-GRAPH` 均 `serves_checks:["UT-BACKEND","UT-CLI"]`、`fail_closed:true`、**无 `require_outputs`**。实测消费方：`UT-API`（`build/linux-openmp-on/libphase2.a` ×5 文件 + `lib/astro_image_io/astro_image_io.dll`）、`UT-ABI`（`build/linux-control`）、`UT-QUALITY`、`UT-CPU-BASELINE/DISPATCH/AVX2/AVX512`、`UT-BACKEND`、`UT-CLI` = **9 道，声明 2 道**。
- **闭包方向缺一半**：`validate_workflow_binding.py` **B10 只核"正向"**（`serves_checks` 的 id 在注册表内且非豁免），**无反向闭包** ⇒ 新增一个消费门**不会让任何门变红**。
- 改法（**同仓正对照就在同一文件**）：`WINDOWS-VALIDATE-CANDIDATE` 已用 `require_outputs:["artifacts/candidate/AstroCS-candidate.zip"]` + `fail_closed:true` ⇒ 把该语义搬到两个 linux serve 步（`build/astrocs`、`build/cli/astrocs`、`build/linux-openmp-on/libphase2.a`、`lib/astro_image_io/astro_image_io.dll`），`serves_checks` 补齐到 9 道；**并加 B10b**：凡 command 或其 discover 目录源码字面量引用某 step 的 `require_outputs` 者，必须出现在该 step 的 `serves_checks`（**正反向双向闭包**）。
