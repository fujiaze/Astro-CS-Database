### V11-N-01 `AioHipsSnrPoint` 镜像落后 C 头两字段 ⇒ 越界读 24 字节，且**交付 HiPS SNR 目录第 2/3 条记录是邻堆垃圾**
- **ID** V11-N-01 ｜ **类别** G_GOV_GATE ｜ **优先级** **P0** ｜ **状态** OPEN
- **位置**：C 头 `lib/astro_image_io/include/aio_hips.h:84-92` = **6 字段**（`ra_deg`/`dec_deg`/`snr`/`star_id`/`quality_flags`/`photometric_status`），`sizeof=40`（`…`star_id@24`、`quality_flags@32+4`、`photometric_status@36+4`）；镜像 `lib/astro_image_io/tests/hips_direct_smoke.py:34-38` 只 **4 字段**、末字段名仍是**已废弃的 `source_id`**，`sizeof=32` ⇒ **Δ8 字节/元素**。
- **消费方向坐实（这才是 P0 的理由）**：脚本 `:98-102` `pts=(AioHipsSnrPoint*3)(...)` 分配 **96 字节** → `:102` `aio_hips_write_snr_points(ps, pts, 3)`；C 实现 `lib/astro_image_io/src/hips/aio_hips_writer.cpp:913-914` `for (int i=0;i<n;++i) ps->snr.push_back(pts[i]);` 按 **40 字节步长**取元素 ⇒ **越界读 120−96=24 字节**；第 2/3 条整体错位 8 字节 ⇒ **写进交付 HiPS SNR 目录的 `star_id`/`quality_flags`/`photometric_status` 是邻堆垃圾**。
- **成因（git 只读坐实）**：C 侧字段由 `6d810a37`（"共享 HEALPix core + SNR 稳定 ID 闭环"）追加，`git log -L 84,92:aio_hips.h` 逐字显示 `- int64_t source_id;` → `+ star_id + quality_flags + photometric_status`。同仓另两份镜像（`v5_snr_precision_roundtrip.py:33`、`gen_hips_browser_test.py:41`）**已同步为 6 字段/sizeof=40** ⇒ **三副本漏改一份**，即"改结构未同步全部镜像"的机器可证形态。
- **门可见性**：该结构**无 `struct_size`/`abi_version`**；该脚本在 `ci/`、`tools/`、`scripts/`、`cmake/`、`tests/`、`.github/` 全域 grep 仅 `docs/architecture/execution_inventory.csv` 一处登记，**不在 `ci/checks.json` 任何 profile**（`UT-ABI` 只 discover `tests/abi`）⇒ 机器门不可见。
- **依据条款**：宪章 §8.6（跨语言结构须自描述/尺寸可断言）、§11（不得越界；发布单元 ABI 边界）、§5.3/§16.2（交付数据完整性与清单可判别）。
- **影响**：不是"可能崩"，而是**静默产出错的交付目录**——错位字段（尤其 `star_id`/`quality_flags`）会让交叉认证与后续匹配拿到看似合法的垃圾值。
- **建议处置（三步，成本都很低）**：①同步该镜像为 6 字段并改字段名；②给 `AioHipsSnrPoint` 加 `struct_size` 首字段，C 与 Python 两侧各断言一次；③**把"同一 C 结构的所有镜像必须逐字段一致"写成机器门**（一份 AST 脚本遍历 `ctypes.Structure` 与头文件字段列表比对即可，正是 V11 已经在跑的 `_v11_ctypes_structs.py`/`_v11_fields.py`，接进 `ci/checks.json` 非豁免项）。
- **取证口径** V11 两侧 sizeof 推导 + 消费方向逐字 + `git log -L` 成因 ｜ **置信度** 高 ｜ **related** **V2-N-01**（同族且同批双标）、**V11-N-02/03**、**C-14**（本条给出门槛数字）、`M9-H-1/H-2`、簇 9

### V11-N-02 `AstroSphereTileView` **五份镜像全部**落后（无一份可作参照物）⇒ 当前无越界路径，但"variance/ivar 产品在 Python 侧无处可写"
- **ID** V11-N-02 ｜ **优先级** **P1** ｜ **状态** OPEN
- **位置**：C 头 `aio_hips.h:69-81` = **8 字段**（第 8 项 `const void* var_num_sum` 由 `05cccb4e` 的 DRZ-014/HiPS variance 传播追加），`sizeof=56`；五份镜像 `hips_direct_smoke.py:24`、`v5_snr_precision_roundtrip.py:23`、`v5_maptile_oracle.py:29`、`hips_mapping_oracle.py:29`、`gen_hips_browser_test.py:31` **全部 7 字段/sizeof=48** ⇒ Δ8，**无一份同步**。
- **V11 给自己的严重度约束（我采纳，不夸大）**：读 `var_num_sum` 的只有 `aio_hips_write_variance_tile`（`writer.cpp:679/713/716`），而**全仓 Python 零调用**该函数（三级复核：整句 grep `variance_tile` → 放宽 `variance|ivar` → 定点读 6 个命中，全是 Phase2/3 UPM 的 `control_ivar` 与 P3 文档，无一为 AIO ctypes 路径）⇒ **不存在越界路径，故判 P1 不判 P0**。
- **真实危害是"表达不能"**：镜像里没有该字段 ⇒ 后来者想用这些脚本产出 variance/ivar 产品时**在 Python 侧根本没有地方写这个指针**；一旦有人按 7 字段镜像传参，C 会把偏移 48..55 的邻堆字节**当指针解引用**。同属 §8.6 要防的形态，且**五份一起错意味着没有任何一份能当参照物**（比"漏改一份"更糟的信号）。
- **建议处置**：五份镜像统一补 `var_num_sum` + `struct_size`；并把 `aio_hips_write_variance_tile` 纳入某条真调用链或标注"仅 C 侧可用"。

### V11-N-04（系统性规模，给 **C-14** 定门槛）公共头 106 个 `typedef struct` 中带自描述者仅 **35 个 = 33.0%**
- **ID** V11-N-04 ｜ **优先级** **P1**（治理类，覆盖面广）｜ **状态** OPEN
- **数字口径**：`include/` 公共头 `typedef struct` **106** 个，含 `struct_size`/`abi_version` 自描述者 **35（33.0%）** ⇒ **71 个无自描述**。其中被跨语言/跨二进制消费的就构成本轮已证的三起（`IpvParams` 越界**写**、`AioHipsSnrPoint` 越界**读+交付污染**、`GaiaSpectrumStar` 静默**错位**）。
- **另两条待 V11 后片确证**：①`fio_check_head` 的 `struct_size==0 放行` 与 session 三处 `!=` 严格相等**互斥** ⇒ **同一份仓内两套 `struct_size` 语义**；②`.def` 导出表只放 `astrocs_module_query_v1`，而 IPv/AIO/SDET/DPSF/GAIA 五个 DLL 走 `*_EXPORT` 白名单 ⇒ **口径不一**。
- **正面样本（划清风险边界，避免把本轴读成"全是错的"）**：V11 逐字段核为**一致**的有 `SDetParams`（3 份镜像，C=PY=36）、`DPSFFitParams`（3 份，16）、`DPSFFitResult`（1 份，104，13 字段全同）、`IpvWcsResult`（1560，20 字段全同，含 3×288 字节 sip 数组）、`acs_fio_keyword_v1`（153）、`acs_fio_header_v1`（**156720**，两侧逐字段同）、`acs_fio_trace_hooks_v1`（40/40，**含 `struct_size`/`abi_version`**）⇒ **fio 族是正确范式**，C-14 可直接引用它作模板。
- **建议处置（并 C-14）**：以 `acs_fio_*` 为模板，规定「跨语言/跨二进制消费的公共结构体首字段一律 `struct_size`，且全仓只允许一种语义（0=旧产物兼容须显式声明，不得既放行又严格相等）」+ 机器门做镜像逐字段比对。
