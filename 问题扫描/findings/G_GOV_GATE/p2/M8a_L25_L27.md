## M8a-G-009 vendored json-schema-validator 无许可全文、无登记，版本只活在 Makefile 注释（裁决 P1→P2）

- 类别: G_GOV_GATE
- 定稿优先级: P2（L25 原报 P1，本代理裁决降级，理由见下）
- 位置: `lib/orchestrator/cpp/third_party/json-schema-validator/`（全目录）、`::json-validator.cpp`（4-6）、`::smtp-address-validator.hpp`（10）、`::nlohmann/json-schema.hpp`；`lib/orchestrator/cpp/Makefile::版本注`（复核 17）
- 证据摘录:
  > Makefile:17 「#-Ithird_party/json-schema-validator: nlohmann-json-schema-validator v2.4.0 (vendor, 正式 Schema validator)」
  > json-validator.cpp:4-6 「Copyright (c) 2016-2019 Patrick Boettcher… SPDX-License-Identifier: MIT」；smtp-address-validator.hpp:10 另含 Gene Hightower 版权行
  - 独立复算（口径：glob 该目录全部文件 + glob 许可候选名 `LICENSE*`/`COPYING*`）：文件 **10**，许可全文文件 **0**；`CMakeLists.txt::add_subdirectory` 全集（172/177/184/191/199/208/670/677）**不含 `lib/orchestrator`** → 该目录不在根交付图。
- 权威依据: MIT 条款（分发副本须含许可声明）；宪章 §14.2（公共许可证须可寻址）、§16.3（审核包白名单=当前源码基线）、§12.3-1

- 影响: 审核包/源码分发面的许可义务缺口；版本无锚不可复现。
- 建议处置: 与遗留 `lib/orchestrator/cpp` 通道清理同批处置（补 LICENSE 全文 + lock 登记，或整目录迁档）；不得维持"仅 Makefile 注释记版本"。
- 置信度: 高
- 来源: L25-004
- related: M8a-G-003（根因）、M8a-C-001（遗留通道定性）、L12；F00-03（登记面≠事实面同主题）

- 权威依据: 宪章 §17.11（哈希/provenance 全部通过）、§16.3（审核包=当前源码基线）、§16.2
- 问题说明: 树内保留上游全集（构建脚本、示例、m4/utilities 等），而锁的完整性证明只覆盖参与编译的 60 源 + 1 个头 → 其余文件的"未改动性"在仓内没有任何锚可核；同时上游已发 4.7.0（安全修复版），锁仍把 4.6.4 登记为「安全修复版」，既无升级评估记录也无"暂不跟进"的理由登记，外部 CVE 情报与锁更新之间无流程联动。**四态判定**：哈希覆盖面不足 = 仍成立；「168 追踪文件」与「树未漂移」= 无法判定（规程禁 git，本代理不跑 `git ls-files`/`hash-object`，故只登记"证明粒度不足"这一结构性事实，不宣称已检出漂移）。
- 影响: 全部 FITS I/O 地基的上游一致性证明不完整；上游安全更新与本地锁无联动记录。
