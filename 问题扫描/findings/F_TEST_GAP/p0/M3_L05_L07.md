- 问题说明: 四个可分别证伪的事实：① **承诺的复算不存在**——该文件不 import numpy，自带的独立统计助手 `median()/rsig()/KSIG` 是死代码，全文无任何「NumPy 对同 data 复算 variance/ivar」的实现；唯一的 `1e-9` 出现在 :177 的 scale_law 绝对增量断言，与「variance/ivar 复算」无关。② **该文件不是独立 Oracle**：它把 `lib/snr_estimator/cpp/src/noise_model.cpp` 用 g++ 编成临时 DLL 后 ctypes 调用生产实现（:99-:109），即被验对象与"参考"同源，宪章 §13.1 的独立性在该文件上不成立（真正独立的复算在 `lib/snr_estimator/tests/p1noise/p1noise_oracle.hpp`，见 M3-F-004）。③ **可整类静默跳过**：`skipUnless` 挂在类上（:97），g++ 或源文件任一不可得即整个 `TestNoiseOracle` 不执行且不算失败；在 MSVC 为主的 Windows 验证节点上必然发生。④ **容差与配置非冻结值**：断言为 5% 带（:128/:139/:152/:156/:168）与 fill 侧 `0.40×(1/16)`（:191），且使用 `min_patch_samples=32/8`、`variance_floor=1e-9` 等非生产默认值（:112/:123），生产默认 64/1e-12 的边界从未被该面覆盖。
  同时必须澄清：该文件**确实**被 CI 的 `UT-BACKEND` 以 `discover -s tests/backend` 方式执行（linux-main profile，非豁免门），因此本条不是「测试从不运行」，而是「SCI §11/§15 承诺的验收手段没有对应实现，运行的是另一套更弱且可跳过的面」。
- 影响: FROZEN 合同的 §15 验收项「Python 参考 rtol 1e-9」为无证据声明；Phase1 噪声模型（= Phase2 逐像素 ivar 权重唯一来源）的验收证据链在文字与实现之间断裂；Windows 侧噪声回归实际不执行而无红。P0 成立。
