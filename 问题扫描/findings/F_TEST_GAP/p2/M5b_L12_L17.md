### M5b-F-02 tests/cli 的 TestManifestVerify 类定义在 __main__ 守卫之后，直跑时静默不执行
- 类别: F_TEST_GAP · 建议优先级: P2
- 位置: `tests/cli/test_cli_protocol.py::（if __name__ 与后续类定义）`（现 :230-233 及其后）
- 证据摘录:
  > if __name__ == "__main__":
  >     unittest.main(verbosity=2)
  >
  > class TestManifestVerify(unittest.TestCase):
  >     """CLI-003: config schema mutation / hash / stale profile / verify 闭环。"""
- 权威依据: 宪章 §14.4、§12.3-4
- 问题说明: 直跑该文件时 `unittest.main()` 先于类定义执行 ⇒ CLI-003 的 config schema 突变 / hash / stale profile / verify 闭环整组用例收集数为 0，且输出仍是绿色汇总；只有 `unittest discover`（UT-CLI 现状）才会收到该类。任何"手工复跑单个 CLI 测试文件"的验证记录都不含这组断言。
- 影响: 手工验证与 CI 的覆盖面不一致，易产生"已复跑"的错觉；不影响 CI（discover 正常收集），故定 P2。
- 建议处置: 把 `if __name__ == "__main__"` 块移到文件末尾。
- 置信度: 高 · related: M5b-G-01、M5b-G-15
