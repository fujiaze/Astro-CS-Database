### M2b-F-02 在册 ctest p1_hips_writer 含恒真断言与「同一文件读两次当 hash」，并以 ALL_V19 声明 variance/ivar 却零数据即判成功
- 类别: F_TEST_GAP
- 建议优先级: P1
- 位置: tests/unit/p1_hips_writer_test.cpp::主用例；tests/unit/CMakeLists.txt::p1_hips_writer add_test；lib/astro_image_io/src/hips/aio_hips_writer.cpp::aio_hips_finalize（variance/ivar 分支）与 ::provenance 守卫段；docs/algorithms/HIPS_WRITER.md::§9 不变量 I8
- 证据摘录:
  - 恒真断言（原文）:「CHECK(tile.find("XTENSION= 'IMAGE   '") != std::string::npos || true);」
  - 析取式弱断言（原文）:「CHECK(props.find("hips_version") != std::string::npos || props.find("hips_release_date") != std::string::npos);」＋「CHECK(props.find("obs_title") != std::string::npos || props.find("creator_did") != std::string::npos);」
  - 伪 hash 一致性（原文）:「std::string a = read_file(dir + "/signal/Norder0/Dir0/Npix0.fits"); std::string b = read_file(dir + "/signal/Norder0/Dir0/Npix0.fits"); CHECK(a == b);  // 确定性」——同一文件两次读同一内存比较
  - 声明但空（原文）:「view.var_num_sum = nullptr;」＋「aio_hips_product_begin(dir.c_str(), 512, W, AIO_HIPS_FLOAT32, AIO_HIPS_PRODUCT_ALL_V19, …)」＋全程只调 aio_hips_write_signal_support_tile＋「CHECK(frc == 0);」；flags 位域实测「AIO_HIPS_PRODUCT_ALL_V19 = 31, // 全产品 (含 variance/ivar)」
  - 守卫不对称（实测）:诊断通道有「真正写过才算数」判据（「if ((ps->flags & AIO_HIPS_PRODUCT_NREJ) && ps->diag_nrej_tiles) {」）、products 清单同样按 present 判定，而 variance/ivar 分支只判 flags 位；provenance 双向守卫（return -9/-10）**仅在 ps->prov_set 时生效**，本用例未设 provenance ⇒ 不触发
- 权威依据: 宪章 §12.3-12、§14.4（不得生成看似成功的产品）、§13.1；TEST_STANDARD.md:3（每科学契约 ≥1 真 oracle，禁伪通过）；ALG-HIPS-001 §9 不变量 I8「manifest 计数字段=实际文件数」
- 问题说明: 「|| true」使该断言永不失败；两处「||」使键集缺失一半仍通过；第 4 段把「读同一文件两次」当作确定性/哈希一致性的证据，判别力为零。更关键的是：ALL_V19 声明 variance+ivar 而从不写 variance tile，finalize 仍返回 0，于是 signal/support/variance/ivar 四目录 + 四份 properties + 四份 Moc.fits 全部产出、测试判成功——正是宪章 §14.4 禁止的「看似成功的空子产品」。当前写侧唯一在位的同类守卫只覆盖 nrej/nused 两通道，provenance 守卫又被 prov_set 前置条件限制。
- 影响: 该 ctest 对「声明↔产物一致」这条合同（IO_003/ALG I8）实际零判别力；任何回归删掉 variance tile 落盘仍全绿。
- 建议处置: ① 删「|| true」与两处「||」析取（改逐键断言）；② 把「同一文件读两次」换成跨进程二次写出后字节/哈希比较，或直接删除该伪证据；③ variance/ivar 分支补与 diag 通道同型的「真正写过才算数」present 标志（未写则不产该子产品，或显式失败）；④ 补 ALL_V19 + 零 variance tile 的负测：断言 finalize ≠ 0 或该子产品不存在；⑤ p1_hips_writer 保留 ctest 注册（勿摘除）。
- 置信度: 高
- related: M2b-C-01（写出事务化后该项需连带重做）、M2b-F-01、M2b-A-01、L03-018、L23（跨域「声明但空/门禁自证」主题）
- 来源: L03-018

### M2b-F-03 SNR metadata.xml 与 properties 的产品级可解析性无判别测试：只 grep 根元素子串，且真值夹具与生产模板不同构
- 类别: F_TEST_GAP
- 建议优先级: P1
- 位置: lib/astro_image_io/tests/p1hips/p1hips_tests_units.cpp::u5_snr 段；lib/astro_image_io/tests/p1hips/p1hips_tests_properties.cpp（std::to_string 双侧比较段）；lib/phase2/tools/controlled_rejection_truth.py::snr metadata 夹具；docs/algorithms/HIPS_WRITER.md::§9「MOC/properties 键值精确相等」
- 证据摘录:
  - 唯一在册断言（原文）:「P1HIPS_CHECK(xml.find("<VOTABLE") != npos, "u5_snr_votable_present");」
  - 真值夹具（原文，controlled_rejection_truth.py）:「(d / "snr" / "metadata.xml").write_text(\'<?xml version="1.0"?><VOTABLE version="1.3"/>\')」——自闭合空表，与生产模板（含 FIELD 列表与命名空间）不同构
  - 双侧同格式比较（原文，properties 用例）:「// std::to_string 格式双侧一致」＋比较双方都由 std::to_string 产生
- 权威依据: 宪章 §13.1（独立验证）、§17.11；TEST_STANDARD.md:4（测试须用公共生产 API，禁复制内部实现——双侧同格式比较即用实现自证）
- 问题说明: 生产模板写出的是命名空间 URI 含空格的非法 VOTable（见 M2b-B-05），而测试只查前缀子串「<VOTABLE」——非法 URI 同样命中，故该测试对该缺陷零判别力；真值夹具用另一份简化模板，进一步使「生产产物可被第三方解析」这一合同面永不被测。sky fraction 一侧的「双侧同格式」比较同理：格式退化（6 位小数归零）在两侧同步发生，测不出来（见 M2b-H-01）。
- 影响: 产品对外可解析性与数值语义两条合同面缺乏任何有效判别；修复 M2b-B-05 后若无解析型断言，同类回归仍可静默复发。
- 建议处置: ① 断言改为「XML 可解析 + 根元素命名空间等于 VOTable URI + FIELD 数量/名字/datatype 逐项匹配」；② 真值夹具复用生产模板（或反向由夹具生成器单一来源）；③ 以 astropy.io.votable / hipsgen LINT 作独立解析 Oracle 注册进 ctest；④ properties 数值断言改用独立十进制字面量期望值，禁双侧同格式比较。
- 置信度: 高
- related: M2b-B-05、M2b-H-01、M2b-F-02、L03-012（双事实之测试面）
- 来源: L03-012（测试面拆分）
