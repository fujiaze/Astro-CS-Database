- 问题说明: 复算三个事实。① `TST-ACR-001/INV-001/FAIL-001` 三个 ID 在全仓只出现在两份文档与旧表 `docs/TRACEABILITY.csv:68`（外加检查器 fixture `tools/quality/contracts/fixtures/check_traceability/valid_min.csv:11`）——`tests/**` 与 `ci/checks.json` 内无任何同名 ID、同名文件或等价映射。② 加重事实（叶子未报）：权威八层矩阵 `docs/traceability/` 内检索 `SCI-ACR|ACR-EQUIV` **零命中**，即该 FROZEN SCI 根本不在权威矩阵中，SCI:115 只把读者指向旧表；按规程 §0 权威顺序，旧表非八层合同成员，故这条科学门的追溯链在权威面上是断的。③ 文档声明的门本身含 `CPU/GPU 等价`，而 §10.1 下 GPU 路径生产不可达、CI 无 CUDA，该等价面无从取证。④ 现有最接近的测试（`test_reject_integration_oracle.py`、`lib/phase2/tests/synthetic_gate.cpp`）既不叫 TST-ACR-*，也因 `skipUnless` 依赖 `build/linux-openmp-on/libphase2.a`（CI 构建树为 `build/linux-control`）而在 CI 上静默跳过，`ci/checks.json` 亦无 `tests/api` 之外的 synthetic_gate 注册项 → 无当前证据。
- 影响: 「科学定义=算法=接口=代码=测试」五同步在 ACR 等价面上不成立；SCI-ACR-EQUIV-001 标 FROZEN 但无测试锚；审核按权威矩阵检索取不到该 SCI，按旧表检索则撞上悬空 TEST ID（旧表还给它标了 VERIFIED）。
- 建议处置: 要么把该 SCI 与其测试落进八层矩阵并建可定位的 TST-ACR-*（CPU 侧 legacy vs 生产参考；GPU 侧改标 NOT_APPLICABLE 并登记原因），要么把 `docs/TRACEABILITY.csv:68` 的 `TST-ACR-001/VERIFIED` 改为显式 `MISSING`；同时消除矩阵双头（与 F00-01 并档，由 M6 主落矩阵侧）。
