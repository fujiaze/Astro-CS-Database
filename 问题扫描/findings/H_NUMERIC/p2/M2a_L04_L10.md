## M2a-H-3 HiPS 写侧把 support 静默钳到 1.0，层级归约用钳后的 support 反乘通量，覆盖>1 时破坏 §12.2 声明的 flux=sig·sup·A_cell 闭合且无计数暴露

- 类别: H_NUMERIC
- 优先级: P2
- 来源: L04-014
- 位置: lib/astro_image_io/src/hips/aio_hips_writer.cpp::write_tile_core（sup 归一与钳制）、::层级归约累加段；docs/contracts/DATA_SEMANTICS.md::§12.2/§12.3；docs/science/DRIZZLE.md::§9a support 行
- 证据摘录（逐字，复核时点现文）:
  > （aio_hips_writer.cpp:524-526）sig = flux / area;  sup = area / ps->A_cell;  if (sup > 1.0) sup = 1.0;
  > （aio_hips_writer.cpp:596-597）flux = sig_n[i] * sup_n[i] * ps->A_cell;  area = sup_n[i] * ps->A_cell;   // 层级粗化时以钳后的 sup 反推通量
  > （DATA_SEMANTICS.md §12.2/§12.3）support = covered_area/A_cell，无量纲 [0,1]（>1 钳 1.0）；面亮度闭合 signal = flux_sum/covered_area、flux = signal×support×A_cell
  > （DRIZZLE.md §9a）HiPS 产品 support∈[0,1]
- 权威依据: 宪章 §4.1（support 与 coverage/validity 不得混同、须可追溯）、§5.3（须验证 support 与能量语义）；DATA-P1-STACK/HiPS 产品合同；SCI-DRZ-001 §9a
- 问题说明: 钳制本身是合同规定的，因此问题不在「钳」，而在两处后果：**(1)** 叶级 `sup` 被钳后，层级归约 :596-597 仍按 `sig·sup·A_cell` 反乘还原通量 ⇒ 任何 `covered_area>A_cell` 的像素，其上层 tile 通量被系统性低估（低估比例 = 超出部分），与 §12.2 声称的闭合等式不再一致，且等式失效面没有分支标记；**(2)** 全程无 `clamp_count`/`overflow` 计数或 provenance 键，产品消费方无法区分「覆盖恰好 1.0」与「被裁掉一块覆盖」。
- 影响: 层级粗化产品的通量/面亮度在多帧重叠或 pixfrac 边缘场景下不闭合（数值面），属可复现的静默偏差；不改叶级 signal 语义。
- 建议处置: ① 归约改用未钳制的 covered_area 作为反乘底数（signal/support 两列各自保持合同定义）；② 暴露 `support_clamped` 计数进 properties/诊断平面；③ 在 §12.2 注明闭合等式的成立条件与钳制后的偏差方向。
- 置信度: 中（两处代码段与合同式一手核对；实际触发频率取决于生产中 covered_area>A_cell 的出现率，本代理无数据面证据）
- related: M2a-A-1（同属归一化语义）、M2a-A-2

## M2a-H-4 variance 面 FLOAT64 输入被静默窄化为 FLOAT32 后送入引擎，与 signal 侧「f32/f64 二选一、禁混用」的口径不对称

- 类别: H_NUMERIC
- 优先级: P2
- 来源: L04-019
- 位置: lib/healpix_db/healpix_drizzle/hp_drizzle_api.cpp::帧块读取与 variance 装配段；lib/healpix_db/healpix_drizzle/drizzle_engine.h::processPixel（varianceValue 形参）；docs/contracts/DATA_SEMANTICS.md::§11.1 variance 面行；docs/contracts/DATA-002_PHASE_PRODUCT_EXCHANGE.md::variance 平面单位/精度行
- 证据摘录（逐字，复核时点现文）:
  > （hp_drizzle_api.cpp:984-1008 区段）若 variance 块 dtype = AIO_BLOCK_FLOAT64 → 逐元素 `static_cast<float>` 拷贝进 float 缓冲，仅 fprintf 一条日志（不报错、不拒绝）
  > （drizzle_engine.h:143/:151 与 :265）variance 平面入参恒 `const float*` / `float varianceValue`   // 引擎无 f64 variance 通道
  > （DATA-002_PHASE_PRODUCT_EXCHANGE.md:78 区段）variance 平面 units "ADU^2"，精度按块 dtype 声明
- 权威依据: 宪章 §5.3（按合同输出 float32/float64 并验证不确定度传播）、§7.3（不支持的语义须显式拒绝）、§4.1
- 问题说明: signal 侧严格二选一（块 dtype 决定累加域，混型即拒），variance 侧却接受 FLOAT64 块并静默降到 float32（只有 stderr 日志），故「FP64 全链」产品里方差输入的有效位被砍到约 7 位后进入 sumVarNum；合同未声明该窄化，也没有对应的拒绝路径。与 M2a-H-1 同源（元数据精度与实际精度脱钩），但落在不同代码位。
- 影响: 高动态范围帧的 ivar 精度低于产品声明；与 support/variance 传播的组合误差不可见。健康数据数值仍正确到 float32 位。
- 建议处置: ① variance 与 signal 同口径（f64 输入走 f64 通道或显式拒绝）；② 若保留窄化，须写入 DATA §11.1 并给 `variance_precision_mode` provenance；③ 与 M2a-H-1 的一致性校验同一批改。
- 置信度: 高
- related: M2a-H-1、M2a-C-2、M2a-H-2
