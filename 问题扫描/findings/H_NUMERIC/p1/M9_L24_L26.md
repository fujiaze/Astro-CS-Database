## M9-H-5 AHPX 权重/SNR 块按字节数 memcpy 进按 float 个数 resize 的缓冲（堆越界写 1~3 字节 + 几何不符静默通过）

- 类别: H_NUMERIC（主，堆越界写）；次挂 G_GOV_GATE（§14.4 外部文件解析）
- 优先级: P1
- 来源: L24-009（复验成立；锚点**保留**，正反对照三处逐字命中）

- 证据摘录（逐字，复核时点现文）:

  > 缺陷面（readSnr:572-574 与 readWeight:633-635 同型三行）`size_t floatCount = rawData.size() / sizeof(float);` / `result.resize(floatCount);` / `std::memcpy(result.data(), rawData.data(), rawData.size());` —— **分配 N*4 字节却拷 rawData.size() 字节**。
- 权威依据: 宪章 §14.4（外部文件解析须校验边界）、§11（禁静默污染科学数值）、§8.3（AIO 负责必要边界校验）。
- 问题说明: 块长度非 4 的整数倍（畸形或截断的 AHPX 尾部）时 memcpy 越界写 1~3 字节到 vector 堆缓冲之外。同路径 readPixels 明确做了等值校验 → 属漏项而非风格。次级：两函数也不校验块长度与 imageInfo 的 W*H*C 一致，故「块只覆盖 1/10 像素」的撒谎头会被静默当完整平面交下游（返回 vector 长度即 floatCount，消费方无从知晓它与几何不符）。本仓自产 AHPX 恒为 4 的倍数，故**外部产品是主要暴露面**。
- 影响: AHPX 是 Phase3 投影/重采样的 tile 容器；readSnr/readWeight 的输出作为 SNR 平面与 drizzle 权重平面参与归一化与排异 → ①堆元数据/相邻对象被 1~3 字节覆写（分配器相关崩溃或静默破坏）；②几何不符的短平面静默进入积分 → 科学数值被污染且不报错。
- 建议处置: ①与 readPixels 对齐（snr/weight 至少校验 `%4==0` 且 `== w*h*c*4`，不符返回空并打印期望/实际）；②memcpy 长度改为 `min(dst_bytes, src_bytes)` 或 `result.size()*sizeof(float)`，杜绝任何源长于目的的拷贝形态；③负例：块长度 4k+1 / 4k+3 / 截半，断言拒绝且不越界（须注册 TU，见 M9-F-1）。
- 置信度: 高（正反对照逐字复验）
- related: M9-H-6（同一文件的偏移/窄化链，另一事实）、M9-H-4（同族宽度混用）、M9-F-1
- **【E3-实测 2026-09】** 无运行期证据且**构建面缺失**（比「无记录」更前置）：aio_ahpx_reader.cpp 在真源全部 CMakeLists/ci/workflow 零接线（grep 0 命中），`grep -c ahpx build/asan/build.ninja` = 0、`find build/asan -iname '*ahpx*'` 空 ⇒ 该 TU 从未进任何 sanitizer 树，memcpy 越界写在物理上无被检机会。历史唯一 ASan 编译记录=v19r3_sanitizer.sh:81-83 把 ahpx 三源编入 aio_san（2026-08-25），但运行日志 reports/v19r3/evidence/quality/aio.log ahpx 命中 **0**（驱动不调 AHPX，13/13 全 HISS/browser 用例）⇒ **编译在场、执行缺位**。另登记实测：lib/astro_image_io/src/ahpx/DEPRECATED.md（tracked，2026-07-13）自述「已废弃…代码保留供参考，不用于生产路径」——若成立，本条影响面措辞需负责人按死代码面复核（E 层不改判）。详见 _cache/E3.md §1/§4/§5。

## M9-H-6 AHPX 块描述符把 JSON 浮点强转 uint64 作偏移/长度、不与文件长度对照，读取用 (long) 窄化（LLP64 折叠 → Windows 读错块而 Linux 读对）

- 影响: AHPX tile 超 2GiB（HiPS 多通道高层级容器可达）或头字段畸形 → Windows 正式平台读到错块或失败，Linux CI 通过 → 与「CI 主跑 Linux」叠加后极难发现；本仓 HiPS 结构校验可能"Linux 通过、Windows 产物不同"。

- 置信度: 高
- 平台盲区: **是**（Windows-only 暴露；聚合清单见 `_merge/M9.md §4`）
- related: M9-H-5（同文件不同事实）、M9-G-4/M9-C-1（另两条 Windows-only 站点，三条共同构成本域平台盲区闭环）、M9 §3 正对照表第 5 行（hiss_reader）、M5b（windows-main profile 恒零检查面）
