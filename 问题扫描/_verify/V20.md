## §5 机器门建议

### A. 一个 AST 门能否同时覆盖「形参零引用」与「字段只写不读」？——能，但必须是「一棵树 + 四条规则 + 一张豁免表」，且三态判定的核心是「读者集合」而非「读者个数」

建议实现 问题扫描 之外的 tools/quality/check_declared_but_unused.py（libclang 或 tree-sitter 皆可），一次遍历同时产出四类判定：

| 规则 | 判定式 | 本轴实测必须处理的假象 |
|---|---|---|
| R1 形参零引用 | 体内无词边界出现 → UNREF；仅 (void)p; → DELIBERATE；**出参型（非 const 指针且名字含 out_/err/_buf）为 UNREF → ERROR**，入参 → WARN | 构造器成员初始化列表、unnamed 形参、默认实参 = nullptr 被当形参名、(void) 无参函数被当「形参名 void」、模板 Scalar/T 误判、多行签名折行（本轴 61 条里 ≥20 条属此） |
| R2 字段只写不读 | 全仓 x.f / x->f 分写侧读侧，读侧集为空 → WRITE_ONLY | **宏位置初始化**（ACS_KERNEL_ENTRY / AIO_ABI_INFO_V1_INIT / backend_table.inc 表）——本轴 28 个假候选全在此；memset 后逐字段赋值；designated-init .f =；整体拷贝 cfg = *cfg_in（upm.cpp:1300）；聚合 {…} 位置写 |
| R3 声明→读者可达（本轴 V20-N-01/04/05 的门） | 每条 X.value("k",d) / contains("k") / kv_*("k") / CFG_VOCAB 项，要求存在「读者或同 run 生产者」；只被 contains() 用到 → 报 ECHO-ONLY；读键在上游产物写键集中缺失 → ERROR | 用户 config 键需按 kSessionKeys / CFG_VOCAB / DATA_SEMANTICS §16.1 白名单豁免；测试里 fs::exists(p3_writer.json) 这类**存在性断言不算读者** |
| R4 回显 vs 真消费（任务所问的区分法） | 终端集合 SINK_ECHO = {man[k]= / {k,v} 写 artifact JSON / properties KV / fprintf(stderr) / logger / plan JSON 字面量}；REAL = {算术、比较与分支条件、循环界、容器 size 与截断、内存或租约申请量、跨模块入口实参、错误码判定}。读者集 ⊆ SINK_ECHO → 仅回显；含任一 REAL → 消费；读者集为空 → 零消费 | 两条伪 REAL 必须排除：①只在 if (x != 0) return ERR 出现 → **记 REAL**（拒绝即判定，与本轴面 4 口径一致）；②回显写出的表达式不数据依赖于该声明（常量冒充，如 hips plan 的 "max_workers":1）→ 记 **ECHO-FALSE**，本轴新三态，单列报警 |

- 三态可判性的关键（回答「如何区分回显型消费与真消费」）：只看一条 —— **该声明的值是否成为某个终端表达式的操作数**。回显点满足三条同时成立即判「回显即消费假象」：①仅出现在写出集合；②该键在全仓无第二读者（且第二读者不含「非存在性断言」的测试）；③写出表达式不进入任何算术/比较。反例（回显 + 真消费，须放行）：reject_profile（既入词表判定又回显）、psf 的 n_fit_input/psf_fit_truncated（:1746/:1780 写产物，:2789-2791 下游节点再读并参与判定）。
