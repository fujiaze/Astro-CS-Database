## §2 结论条（15 条，宁窄而实）

1. **[P1/N-01] CPU provider 把 4 码探测结果塌成「一律不支持」** —— `providers/cpu/{baseline,avx2,avx512}` 6 站点。**若它是唯一缺失项会漏掉的后果**：provider 与探测库来自不同构建（`struct_size/abi_version` 失配 → `ACS_CAP_ERR_ABI_MISMATCH`）被报成「这台 CPU 不支持 AVX2」，宿主静默退 baseline ISA —— 装配缺陷被归因成硬件事实，ISA 选错从此查不到源头。同一函数 `avx2_provider.cpp:391-395` 对 host_abi 仍正确保留 `ACS_ERR_ABI_MISMATCH`，证明塌缩只在能力支路、不是全局约定。
2. **[P1/N-02] HISS 的 8 码错误域在 5 个 C ABI 出口全塌成 `HIO_ERR_FILE`**。**漏掉的后果**：`HISS_ERR_CHECKSUM`（产物位翻转/被篡改）与「文件打不开」在 `HISS_VERIFY`（`orchestrator.cpp:3689` 明写「read_subblock 内部校验, 不匹配返回 HISS_ERR_CHECKSUM」）面上不可区分，数据完整性事件被归因成 IO/路径问题；`HISS_ERR_UNKNOWN_REQUIRED` 是合同规定的独立拒绝语义，塌缩后无从计数。
3. **[P2/N-03] `read_proc_self` 自算的失败标志被 `(void)ok;` 丢弃并恒 `return true`，唯一调用点再丢弃返回值**。**漏掉的后果**：/proc 不可读（受限容器/命名空间）时产出「全 0 但成功」样本，叠加 N-15 的 `monitor_present=true`，「监控没跑」被归因成「利用率低」（`UtilizationP75Low` 而非 `MonitoringMissing`）。
4. **[P2/N-04] `acs_error_info_v1` 出参被填后从不读，真实细分被 `efill` 写死的静态消息覆盖**（echo 模块为最净实例）。**漏掉的后果**：模块侧 `detail_code` 丢失，宿主只见统一「artifact 打不开」，跨 5 个 DLL 的同类站点失去逐项归因。
5. **[P1/N-05] QA-001 警告门不读任何退出码**：构建没跑、`cd || exit 9`、cmake 缺失被 `|| true` 抹平，三态都产出 `""/"0"` → 打印 `QA-001_PASS … 生产警告=0` 并 exit 0。**漏掉的后果**：「警告清零」合同失去证据，「没测」被记成「测了且为 0」。related：V15（测文本不测行为）、FD_windows_zero_test_green（同门 SKIP 仍 PASS，另一机制）。

## §5 机器门建议（能否与「参数未被消费」共用一次 AST pass）

**结论：可共用同一次 AST 底座，但需两套判定谓词；且类 3/类 4 各有一条更便宜的非 AST 门可先行。**

1. 一次 C/C++ AST（libclang/Clang LibTooling）+ 一次 Python `ast` pass，产出三张同源表：`call_sites(callee, returns_type, used)`、`sym_writes/sym_reads`（本轴类 1/2/3 全靠它）、`param_uses`（对偶轴用）。**必须共用**：本轴的 `ProcSample` 字段与参数轴的 `cfg` 字段混排在同一批文件（`module_adapters.cpp` 一处函数体内两侧都有），分开扫必然两轴重复报同一 struct。
2. 类 1 需要**两段式**，参数轴无法复用第二段：(a)「返回值类型非 void 且 `used=false`」；(b)「被调方返回域基数 `|codes|>1`（从 `enum`/`#define X_ERR_*` 抽）而所有消费点只做成对 `v != OK` 二值判定」。N-01/N-02 两族 6+5 站点全部落在 (b)，而 (b) 正是本轴独有序列。
3. 类 2/类 3 判据 = 「标识符或字面量键在写侧 ≥1、读侧 =0」+ **豁免表**：`artifacts` 数组型重复键、`*_artifact` 路径键、DTO/POD 全字段序列化型（`resource_samples.csv` 那种「结构体整体落盘」不该被判死码，只该被判「列数与读端不匹配」）。N-13 的 14 键与 N-08/N-09 的 5+1 字段就是这套规则的产物；误报控制全靠豁免表，建议豁免表落 `ci/` 并沿用 `ci/checks.schema.json` 的 `additionalProperties:false` closed-schema 风格。
4. 类 4 判据 = 「门禁结构体某字段的**唯一生产写点**是字面量常量（含 `= true/= 0/= 某枚举常量`）」→ 一次即可抓完 N-15/N-16/N-17 三条 P1，是**成本最低、收益最高**的一条，建议先落；且它同时能覆盖对偶轴的「参数被算被记不参与执行」簇（同一条谓词，读侧集合换成分支条件即可）。
5. 产物面（类 3 的 CSV/JSON 两侧 schema）建议不进 AST：做「写端表头列名集合 ↔ 读端解析格式串/键集合」对称检查即可 —— `resource_samples.csv` 15 列 vs 生产行级复读 0 次（N-08 与子代理 B `[3-05]`）用一次列数比对即可抓；JSON 侧用「写侧键全集 ↔ 读侧键全集」差集（本轴 `c3a/c3b.py` 已是可移植实现）。
6. 注册面纪律：上述任一门若入 `ci/checks.json`，需同步 `changed_paths` 与 `prerequisite_tools`，并注意现行 schema **无 `depends_on`/`env` 维度** —— 不要为表达「先跑 AST 再跑比对」而私加键（会破 `additionalProperties:false`）。
