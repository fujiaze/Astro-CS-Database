## 2. 逐条发现

### V14-N-01（P1·①status 跨 manifest 漂移）Windows 产品清单把两个自认骨架的平台 DLL 登记为 IMPLEMENTED
- **登记面**：`packaging/astrocs.product.json` 中 PLATFORM-RUNTIME、PLATFORM-IO `status: SKELETON`，其 note 逐字：「PLATFORM-RUNTIME/IO 平台 DLL 仍为 BLD-003 骨架（单 C ABI 源起步，宿主接线归 RT-002/WIN-*，**不伪装实现完成，维持 SKELETON**）」；而 `cmake/astrocs.product.windows.json.in`（install_layout.cmake:129-134 configure_file 生成并安装到 **Windows 正式安装树**）对同两个 unit_id 写 `"status": "IMPLEMENTED"`。
- **代码实况**：根 CMakeLists.txt:133 `add_library(astrocs_runtime SHARED runtime/artifact_store/artifact_abi_v1.c)`、:146 `add_library(astrocs_io SHARED runtime/io/fits_core.c)` —— 各仅 1 个 C 源，与 Linux 面「单 C ABI 源起步」自述一致；两平台同目标，差别只在 rel_path 后缀。
- **无机制拦截**：S4 同步校验（tests/abi/mod001_install_load_check.py:239-268）只比对 **安装后 manifest ↔ install-tree.contract**（且合同面 unit 无 status 字段），两平台 manifest 模板之间零比对；schema（packaging/schemas/astrocs-product.schema.json）status 枚举只有 SKELETON/IMPLEMENTED，无「平台差异」豁免空间。
- **判定**：Windows 面（宪章 §3.1 正式入口平台）的产品清单对同一事实给出与 Linux 面相反的状态，且 Linux 面 note 的「不伪装实现完成」是负责人口径。消费方（loader/发布评审/§17.12 流程）在 Windows 树读到的将是「已实现」。
- **related**：M9 §7 声明超前簇；M5b-G-01（门验错对象的另一形态：校验器根本不覆盖该面）。

### V14-N-02（P1·①status 单元自相矛盾）MOD-NOOP：产品清单 IMPLEMENTED vs 模块三面（README/module.yaml/CMake 注释）SKELETON 且 verb 返回 UNSUPPORTED
- **登记面**：product.json 与 windows .in 均 `MOD-NOOP status=IMPLEMENTED`，Linux note 且断言「平台 CLI 与**全部模块 unit 已实现**」；但 `modules/conformance/noop/README.md:3/:17`「状态：SKELETON — 可加载性骨架；非完整实现」、`module.yaml:2/:module_status=SKELETON`、CMakeLists.txt:5「本模块为 conformance SKELETON (BLD-003)」；README:76 明确「SKELETON：execute/plan/create 等全部返回 ACS_ERR_UNSUPPORTED」。
- **对照**：真正实现 ABI 动词的是 `modules/conformance/echo`（README:3、module.yaml:11 `IMPLEMENTED`），但它不在 product.json/白名单/install 任何面 ——「实现者」不登记、「骨架」被登记为实现。
- **口径**：同一 schema status 枚举下 RUNTIME/IO 按「语义完成」判 SKELETON、NOOP 却按同一标准判 IMPLEMENTED，两判据互斥（非「字段不同源可辩护」——两侧字段同名同枚举）。windows .in note 还自证曾按 yaml 同步过 MOD-NOOP 的 module_id，说明两域本应同源。
- **related**：与 N-01 同根（manifest status 无语义校验）；FD-I-001（providers 一名两指是同一「登记语义分叉」家族）。

### V14-N-03（P1·④内容比较：漂移已成事实）backend_table.inc（编译交付面）与 baseline_provider.cpp 的 12 行 kernel 表 precision 列 6/12 不一致，唯一守卫是 FD-F-001 的文件名 strstr
