### V18-N-11｜selfcheck 子进程用 `execve` **全量替换环境**，凡非零 rc 一律记"必败验证通过"（P1）
- 站点（11 处，`scripts_v18_sc.py` → `child_env_null=True`）：`p1noise:55` `p1cal` `p1cos` `p1psf` `p1phot` `p1sess` `p1hips` `p1star` `aio_abi`（+`p1drz:72`），形态一律 `char* child_env[] = {fbuf.data(), nullptr};` → `execve("/proc/self/exe", child_argv, child_env)`。
- **机制与后果（两条，都是红的方向错了）**：
  1. **子进程丢光 PATH / TMPDIR / OMP_NUM_THREADS / `ASTROCS_REPO` / 各 `*_DLL_PATH`**（`tests/unit/CMakeLists.txt:559/891/992/1021/1077/1169` 说明这些变量是测试正常运行所必需）。子进程可能因**环境缺失**而 rc≠0 ⇒ 父进程 `if (child_rc == 0) return 1;` 判"必败验证通过"。**注入是否真生效，无人验证**。
  2. `execve` 失败 → `_exit(127)`（`p1noise:64`）→ 在 `p1noise/p1cal/p1cos/p1psf/p1phot/p1sess/p1hips/p1star/aio_abi` 里 **127 被当作"注入成功"**（它们只判 `child_rc == 0`）；唯 `p1drz:95` 单独处理 `rc == 127` 为失败。**同族两种口径**，其余 10 处对 `execve` 失败给绿。
- **为何失去判别力**：这道 selfcheck 门是"报告通路能变红"的元门，它自己在"根本没跑到注入代码"的两种情形下都判通过 ⇒ 元门不具判别力，其上所有"注入锁"的可信度连带扣减（正是 C-21 :182 说的"非豁免真门为何仍绿而事实红"的机制来源）。
- **最小改道**：①`execve` 用 `execve(path, argv, environ)` 继承父环境再叠注入变量（或 `setenv + fork`，如 `p1drz` baseline 相与 `p1hips::test_diag_prov_selfcheck:905` 的 `::setenv/::unsetenv` 成对做法）；②父侧把 `rc==127`（及 `WIFSIGNALED`）判为 FAIL；③phase2 必须**同时**要求 stderr 出现 `FAULT-INJECT <name>` 才算注入生效（现仅 `p1noise` 注释 :7 声明要检、代码未检）。
- **机器门可覆盖**：**部分能**。"child_env 数组只含 1 个条目"、"`_exit(127)` 未被父侧区分" 均可静态判；"注入是否真的生效"须运行期（检 `FAULT-INJECT` 行），本轴不判。
