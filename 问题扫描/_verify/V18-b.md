### V18-N-07｜`ASTROCS_P1STAR_FAULT=` 的"驱动"是**赋空值**，语义为清除而非注入（P1）
- 站点：`lib/star_detector/tests/p1star/CMakeLists.txt:159-162` → `ENVIRONMENT "OMP_NUM_THREADS=1;ASTROCS_P1STAR_FAULT="` + `PASS_REGULAR_EXPRESSION "SELFCHECK PASS"`。
- **机制**：`CheckState::CheckState()`（`p1star_test_main.hpp:33-45`）写 `if (f && *f)` ⇒ 空串被当作"无注入"，所以这条 ENVIRONMENT 的实际作用是**清除环境继承的注入位**（防 `CTEST-LINUX-FULL` 串味）。
- **为何失去判别力**：账面记为"CI 用 ENVIRONMENT 驱动 p1star 注入"，实际驱动数为 **0**。V15 把它列为两处驱动之一 ⇒ **口径需改**：真驱动仅 2 处（`ASTROCS_P3PROJ_FAULT=tan`、`ASTROCS_HIPS_PROV_FAULT=missing_key`），且这 2 处各只覆盖 1 个名。
- **另需登记的连带事实**：其余 harness 的构造器写的是 `if (const char* f = std::getenv("ASTROCS_P1CAL_FAULT"))`（`p1cal_test_main.hpp:90` 型，**不判 `*f`**）⇒ 赋空值在这些家族里 `getenv != nullptr` 为真、解析出 0 个 token，行为仍等价于无注入；但**重入判据**是 `main` 里的 `std::getenv(X) != nullptr`（`p1cal:79` `p1cos:81` `p1noise:86` `p1psf:80`），赋空值即令重入分支被误判为"注入子进程"，跳过 `run_selfcheck()` 直接跑 core 组。全仓 `p1star`/`p1hips`/`p1sess`/`p1phot`/`p1wcs`/`aio_abi` 的重入改用 `argc>=2` + `argv[1]` 判据（`p1hips:134` `p1sess:119` `p1phot:121` `p1star:122` `p1wcs:150` `aio_abi:142-143`）⇒ **两套重入判据并存**，只有前一套会被空值污染。
- **最小改法**：统一成 `argc>=2` 型 argv 重入（或显式 `--fault-child <group>`）；所有 `getenv` 后统一判 `*f`；`ENVIRONMENT` 若要清位用 `set_tests_properties` 不注入该变量的方式，别用"赋空串"。
- **机器门可覆盖**：**能**（扫 `set_tests_properties(... ENVIRONMENT "...FAULT=")` 空值赋值即 WARN；扫 selfcheck TU 重入判据是否为 `getenv!=nullptr` 单条件即 WARN）。

### V18-N-08｜`p1drz` 重入判据是 `argc >= 1`（恒真）⇒ 注入相判定形同"有 env 就算注入"（P1）
- 站点：`lib/healpix_db/healpix_drizzle/tests/p1drz/p1drz_tests_selfcheck.cpp:49`：`if (argc >= 1 && std::getenv("ASTROCS_P1DRZ_FAULT") != nullptr)`。
- **机制**：`argc >= 1` 对任何进程恒真（`argv[0]` 必存在）⇒ 该条件退化为"env 变量存在"。而 `add_test(NAME p1drz_selfcheck COMMAND p1drz_selfcheck_test)`（`p1drz/CMakeLists.txt:72`）**不传参数**，所以正常 ctest 跑时靠"env 未设"才落回 `run_selfcheck()`；一旦环境里出现 `ASTROCS_P1DRZ_FAULT=`（空值，见 N-07 的清位手法），baseline 相就被跳过、直接跑 `"all"` 组且无注入 → 必 PASS → **`p1drz_selfcheck` 在"根本没做注入自检"的情况下报绿**。
- **为何失去判别力**：这是 **fail-open**（默认放行），与 N-07 的清位手法叠加即可静默使一道 selfcheck 门永久绿。另该 TU 的 baseline 走 `run_child_phase(nullptr)`（:34-41）**进程内 `unsetenv` 后直接调 core 组**，与注入相的 `fork+execve` 不对称 —— 注释 :46-48 已自认这个坑（"不得走 `run_child_phase(nullptr)` — 那会 unsetenv 清掉注入变量"），说明作者知道但把另一侧（`argc>=1`）漏了。
- **最小改法**：改 `if (argc >= 2 && std::strcmp(argv[1], "--fault-child") == 0)`（对齐 p1hips 族），或至少 `argc >= 2` + 判 `*getenv(...)` 非空。
- **机器门可覆盖**：**能**（AST/正则：selfcheck TU 中 `argc >= 1` 与 `getenv(...) != nullptr` 合取出现即 FAIL）。
