### C1 M9-H-1（manifest 栈越界写 + 越界长度回读）—— 判 **FIXED 成立**（真闭合），附 3 项残余

现码拼接 helper 层（module_entry.c :391-432）逐处核：

1. `json_append_escaped(char** w, const char* end, const char* s)`：对每输入字符，写入**前**判 `if ((size_t)(end - p) < need) return 0;`，need=2（'"'、'\\'→反斜杠翻倍）或 1（其余字符原样；<0x20 控制字符降为 `?`）。**转义模型是 2x 最坏膨胀，不是审计按的 6x**（`\u00XX` 模型不成立——该函数根本不产出 \\u 序列），但由于逐字符先判界后写，界正确性与膨胀系数无关，模型差异不构成缺陷。
2. `json_append_ch/raw`：写前判 `*w >= end` / `(end-*w) < n`，失败不写不回卷游标。`json_append_fmt`：`vsnprintf(*w, cap=end-w)`，vsnprintf 至多写 cap 字节含 NUL ⇒ 写触达 ≤ end-1 与 end-1+…（NUL 落在 end-1，均在 head[512] 内）；截断（n≥cap）时 `*w=end` 钉边返回 0——**修复前"snprintf 返回值=应写长度推进"的错误模式在 execute/inspect 全部消失**。
3. execute 站点（:786-840）：`char head[512]; head_end=head+511`（保留收尾位），全部 6 类拼接点带 end；`head_ok==0` → `ACS_ERR_PARAM + ACS_DIAG_ECODE_BUFFER_TOO_SMALL`，释放 6 个临时数组 + gaia_cfg_free + executing=0，**在尺寸查询分支之前返回**——"尺寸查询阶段同样拒绝、不泄 size"与代码一致。交付组装 `memcpy(big, head, (size_t)(hw-head))`（:916）：hw≤end ⇒ 长度≤511，**越界长度回读进产品的面被关死**。
4. total 预算与写入器精确吻合（我逐项算过）：`b64_encoded_len(n)=4*ceil(n/3)+1`（:351），b64_encode 实写 `4*ceil(n/3)` 字符 + NUL（rem=1/2 均补足 4 含 '='），段预算 strlen(key)+segs[i] = 键(含开引号)+值字符+闭引号（NUL 位被闭引号顶替）；`total=(hw-head)+Σ段+1('}')`，`big=malloc(total+1)`，末写 `*w='\0'` 落位 total——**无 off-by-one**。
5. inspect 同型第二站点（:994-1013）：`buf[512]`、`w_end=buf+511`，触边 PARAM+BUFFER_TOO_SMALL 不产出诊断 JSON。
