## §2 ①族：cond 与结果计数解耦 / 旁路自增 / 无求值形态

- **机制**：`else if (faultname!=nullptr && Registry::injected(faultname)) { note_injected; ++failures; } else if (!(cond)) {…}` —— C++ `else if` 短路使注入命中时 `cond` **连求值都不发生**。
- **为何失去判别力**：门红的充要条件＝"该字符串出现在某条被跑到的 CHECK 上"，与生产码是否损坏**逻辑无关**；生产真缺陷只要没被注入名标注就永不红 ⇒ 锁的是**报告通路能变红**（V15 结论在 10 个同型上独立复算成立）。
- **V15 未记的新事实**：12 套 harness **并存三种语义**（10 不判即翻 / 1 判后翻 / 1 无注入），且 8 套有 `fault_reported` 传染支、2 套没有，**零一致性门**。
- **最小改法**：①两支不互斥 → `if (injected(name)) note(name); if (!(cond)) ++failures;`；②p1star 删 `ok=!ok`，注入只驱动**生产侧**等价缺陷；③宏体收归单一 `astrocs_test_check.hpp`，禁各 TU 自铸。
- **机器门可覆盖**：**能**。静态判据：对 `#define *CHECK*(…)` 抽宏体，若"`++…failures` 出现在 `!(cond)` 之前"或"存在 `ok = !ok` 型覆盖"即 FAIL。

### V18-N-02｜`fault_reported` 首支传染：一次命中使整组计数失去含义（P1）
- 站点：8 个家族宏体第一支（`p1noise:55-57` `p1hips:66-68` `p1cal:50-52` `p1cos:55-57` `p1sess:85-87` `p1phot:62-64` `p1wcs:152-154` `aio_abi:68-70`）+ `CheckState::note_injected()`（`p1noise:46-50`，置位后不复位）。
- **机制**：`if ((cs).fault_reported && (faultname) != nullptr) { ++(cs).failures; }` —— 首个命中置位后，同组**其后每条带名 CHECK 无条件** `++failures`。
- **为何失去判别力**：① `failures` = 命中点之后所有带名 CHECK 的条数，与被破坏的不变量个数无关；② `note_injected()` 只打印**首个**名字（`if (fault_reported) return;`），故报告里 `FAULT-INJECT <name>` 与实际制造 rc=1 的那批计数**不是同一集合** ⇒ 归因天然失真；③ p1psf/p1drz 无此支 ⇒ 同名注入在不同家族得到不同 failures，跨域比较无意义。
- **最小改法**：删首支；注入命中只登记不计数；打印全部命中名；`failures` 仅在 `!(cond)` 时自增。
- **机器门可覆盖**：**能**（与 N-01 同一条门，加判"`fault_reported` 直接支配 `++failures`"）。
