## 簇 1 · 机器门"看着在跑、实际不会红"是结构性形态，不是个别 bug
- **证据锚（各自域已定稿，此处只列索引）**：注释门 `CON-COMMENTS` 空壳（M6a-G-001，P0）；线程预算门对 12 处 std::thread 与 99 处裸 omp 不可见、自测只断言检查器自己的输出串（M5a-G-005，P0）；
  AST-API 门从同一头文件自反取数、参数解析后整个丢弃（M5b-G-003，P0）；追溯门 `check_traceability.py:159` 无条件 return 0（M6b-E-001，P0）；
  CLI 协议族与 API 门打在 `cmake -S cli` 产出的**同名兼容二进制**上、二进制缺失时静默零检查、windows-main 路径无 `.exe` 故恒零检查（M5b-G-01，P0）；
  `tests/abi` 无 TestCase 子类 → discover 收 0 用例仍"OK"退出 0（L23-001）；`io_ownership` 累加 failures 却无条件 printf PASS + return 0（L23-002）；
  CLI-008 install 门因 CI 从不产出 `libastrocs_runtime.so` 而恒 SKIP（L23-003）。
- **为什么系统性**：这些门的共同结构是「**校验对象 ≠ 交付对象**」或「**判据来自被检物自身**」。所以它们不会因为产品变坏而变红 —— 加更多同类门不解决问题。
- **建议**（已写进 C-01/C-02）：①判定式维度集合 ⊇ 条款面维度集合；②门必须对**交付二进制**取证并具备"自身会红"的负例自检；③discover 采集数>0 硬门 + 测试源 basename 未注册即 FAIL + EVIDENCE 路径必须可执行三向门。

## 簇 2 · "符合性"结论的生成逻辑本身失真（本轮最重的单条根因）
- **M3-G-002（P0）＋ M2a-B-2（已并入）**：`docs/standards/STANDARDS_REGISTRY.md` 六个冻结域的 CONFORMANT 判定式
  **一律不包含其条款自身的判据维度** —— `D.image:104-110` 丢"同一单位与语义"（致 DISP-IMG-001 被自判覆盖）；`D.cal:237` 丢"误差传播与退化标记"；
  `D.detect:443`+`:450` 丢"与外部目录真实星点比对"；`D.nis:283`+`:290` 丢"噪声模型与完备性门"；`D.catalog:186` 丢 J2016.0 历元维。
- **后果不是"某偏差没登记"，而是宪章 §17.1 的发布前提（全部偏差已登记）在结构上不可证伪**；叠加簇 1，偏差清单是"由漏登逻辑自己生成的"。
- 同族第二、三实例：符合性判定器 `check_standards_registry.py` **未进 ci/checks.json**（M2a-G-1）；其 `C3_evidence_path` 只判文件存在、
  致 **60 个零注册测试源中有 ≥15 个在充当 CONFORMANT 证据**（L23-004）→ 已由 M8 汇总为"符合性证据链三处断点"。

- SCI 面：M3-A-002（P0）给出**代码语义唯一结论**：生产默认 weight_mode=2 是逐像素 ivar，`support×snr²` 只属 mode 0（双站点 :1136/:1396），
  而 SCI-CW:27/38/42 把它写成 mode 2 → **两份 FROZEN SCI 互斥**（A-02 待裁决）。
- 代码面：M4-A-003/M4-C-03 的静默 support 回退；ALG 层：L21-001 与 `DATA_SEMANTICS §20.3` 同节 :987 与 :995 字面自相矛盾；
  局限面：L18-002（M6b 下修：实现默认 `legacy_allow_weight_fallback=false` 且 §6.3:191 禁止回退 → 降 P1，**与前三面是不同事实，不并条**）。
- 另 SNR 语义本身被换掉：进入生产权重的是**已退休的 (A−B)/residual_scale 质量比**，而 SCI-NOISE:98 唯一授权 signal/sqrt(variance)（M3-A-001，P0）。

## 簇 4 · 独立 Oracle 缺位：六实例，其中两例是"全量共源"
- **最重的两例**：M2a-F-1 —— Drizzle 覆盖/面积侧 **9003 例全部**以生产函数当"真值集"（nside 64/128 分支 4563 例 ≈50.7% 直接是生产 ∩ 生产），
  而 registry:162 仍以之作 CONFORMANT 证据、偏差列记"无"；M4-F-02 —— 排异 IRLS 无 NumPy 独立实现，改判由**生产实现自证**。
- 其余：L02-001（投影）、L07-006→M3-F-001（§11/§15 承诺的 NumPy rtol 1e-9 复算**在仓库内没有实现**，且类级 skipUnless(g++) 可整类静默跳过）、
  L03-006+L15-013（HiPS/标准侧）、L08-004。宪章 §12.3-4 的"独立 Oracle"要求因此对多数科学路径不可执行。

## 簇 5 · 精度/口径链条上的"不可达验收门"（已升至 5 例，M7 汇总）
- 1e-4 SIP 门（达门的两条路径都不可经 36 项 ABI 消费；FOV 触门阈经 M1a 重算为 **arctan(π/2)=57.5194°**，不是任何人转述的 140°/90°）；
- SNR≥10 召回≥99% 门（判决对象是 σ_k=2.0 平滑图而 σ 取自未平滑图，衰减 1/(2σ_k√π)=0.1411 ⇒ 有效阈 ≈35σ_smooth，任何实现都不满足）；
- PSF 质心 ≤0.01px 门（生产路径系统性 ~0.5px，且门连自定 converged 配置都判 false：p95 0.0228>0.01、椭率 0.114 vs 0.005）；
- pixfrac 通量不变性（M2a 复算 `S_p=B0/pf²` 与网格/nside/覆盖率/帧数无关；pf=1 恰为 1 → 全部在册测试看不见，默认 0.8 → 1.5625×）；
- 1.4826 截断（文档自述偏差 <1e-12，实算 5.602e-12；15 位与 4 位常数并存）。
- **共性**：门的阈值或判决域被写成了"在定义上就取不到"，于是"门绿"与"科学正确"脱钩 —— 这是簇 1 在数值侧的表现。

## 簇 6 · 外部输入的边界校验只做一半，但同仓永远有做对的另一半
- L24 十五条（P0:3）全部落在 gaia 客户端 / AIO / AHPX / HiPS / IO-001 边界，**每条都有同仓正对照**：readPixels 已等长校验、
  `aio_hips_tile_ipix` 已判负、`hips_join_path` 溢出即报错、`load_xpsd_file` 上游三分支已回收、`hiss_reader` 已用 `_fseeki64/fseeko`、
  `aio_util.h` 已做 UTF-8→UTF-16。→ 结论：**不是不知道怎么写对，是新边界没继承老边界的纪律**；修复=对齐既有写法（低成本、低争议）。
- 其中三条**只在 Windows 正式平台暴露**（`(long)` 窄化折叠 ≥2GiB 偏移、`ACS_FIO_PATH_MAX=512` 使 tmp 与 target 塌缩为同一路径、
  UTF-8 路径合同无人实现），而 CI 主跑 Linux 且 windows-main 门恒零检查（M5b）→ **平台盲区闭环**（M9 汇总）。
- HiPS 侧另有结构级不可互操作：`Npix=ipix%10000` 截断（NSIDE=8 → 96 张全错位图块而读端按 12 张解释，静默）；
  文档称"可显式回读"的 5 处实现恒退自动格式（一处用 `MOC` 占位伪装）；`search_radius_deg` 被写进 24486.74°（真值 27.8°）⇒ 消费方**静默空检索**。
