# AUDIT-REVIEW-001 · 覆盖缺口与目标-现状文档冲突

> 本节回答任务正文的第三问：「哪些历史缺陷在新目标下必须重开」的**结构性**部分——不是单条 bug，而是「V6 任务图没有承载」的缺口。

## 1. 覆盖缺口（V6 任务图未覆盖，需控制器补写域或增列验收）

### 1.1 AR-032 · 非 v6 的 `docs/science/*.md` 在 W1–W8 无 owner

- 事实：`run/v6/base/ownership_matrix.md` §3 明文「V6 写域**只有** `docs/science/v6/`」，W1–W4 只能新增 `v6/` 子文档并在 `SCI-ADJ-001`/`CONTRACT-FREEZE-001` 登记偏差。
- 事实：唯一拥有整目录 `docs/` 的任务是 `DOC-CONVERGE-001`（wave 12，`depends_on: WIN-VERIFY-001`，即 wave 11 之后）。
- 后果：W1–W8 实施三模式与信息权重期间，`docs/science/DRIZZLE.md`、`CONTROL_WEIGHT_SNR.md`、`ACR_EQUIVALENCE.md`、`INTEGRATION.md` 仍是**与目标冲突但形式上 FROZEN** 的 L1 文档；`PROJECT_SPEC.md` §11 只给出「作为待迁移基线」的定性处置，没有任务把「哪些段落被 `v6/frozen` 取代」变成可验收项。
- 建议（不代裁）：① 在 `CONTRACT-FREEZE-001` 验收中增列「逐文件列出被取代的 SCI 段与取代者 ID」；或 ② 明确声明非 v6 SCI 对 V6 非权威并在 `DOC-CONVERGE-001` 收口。二者择一，否则 `CONTRACT-FREEZE-001` 的「合同整合与实施放行」在语义上不完整。

### 1.2 AR-033 · 根构建面无 V6 owner（H-1）

- 事实：`ownership_matrix.md` §4 H-1 列出根 `CMakeLists.txt`、`tests/unit/CMakeLists.txt`、`tests/unit/p1snr/CMakeLists.txt` 三个文件「**无任何 V6 任务拥有**（全部 V6 写域里没有根构建面）」，并标注「**控制器裁决**」。
- 事实：三个文件同时处于 dirty 态（根 CMakeLists 回退到 P10 blob；两个测试 CMakeLists 回退）。
- 后果：W5 的 `tests/unit/v6_p1_cal/`、`v6_p1_psfw/`、`v6_p1_drz/`、`v6_p2_*/`、`v6_p3_*/`、`v6_aio/` 都必须经 `tests/unit/CMakeLists.txt` 注册才可能被 ctest 发现；无 owner 即意味着「新测试注册」这一步在 V6 任务图内不可执行，直接触发 AR-041（门恒绿）。
- 建议：控制器在放行 W5 前把根构建面指派给单一任务（候选：`RUNTIME-CI-001` 或单列接线任务），并规定其他任务只读。

### 1.3 AR-034 · 7 项历史 CI 红无 V6 任务验收锚

- 审核包 `01` §五记名：`DOC-LINE-ANCHORS`(41 条)、`DOC-INDEX-STRICT`、`CON-API-CONTRACTS`、`CON-DOC-SYMBOLS`、`THREAD-BUDGET`、`CON-FULL-INTEGRATION`、`CON-TRACEABILITY`（干净 HEAD 即红）。
- Oracle 复核 `eng/ci/checks.json`：除 `DOC-INDEX-STRICT` 外 6 个 id 可命中注册；`DOC-INDEX-STRICT` 在 `eng/ci/checks.json` 中**零命中**（说明其注册缺失或改名），这本身就是一条未被任何 V6 任务登记的 CI 面缺陷。
- 事实：`RUNTIME-CI-001` 任务正文只写「CI 门和负向 mutation」；`DOC-CONVERGE-001` 任务正文只写「同步最终 SCI/ALG/DATA/API/状态/文献」，均未逐名登记该 7 项。
- 后果：即使 `RUNTIME-CI-001` 与 `DOC-CONVERGE-001` 判 PASS，7 项红仍可原样存在；这与 V4 R13「先修假绿根因和现红门」相冲突。
- 建议：在 `RUNTIME-CI-001` 验收中逐名登记 7 项及其终态（红→绿需证据；确认为「门本身错」需登记重写；不可豁免项须给 owner）。

### 1.4 AR-035 · 785 条缺陷账本无销账任务

- 事实：V6 35 个任务无一以「缺陷账本逐条销账」为验收；`QA-MATRIX-001` 只产出科学 QA 矩阵设计。
- 事实：审核包 `06` 选项 C 建议「先做 P0 门族（估计 20-30 条）」，并给出工作量「大（650 条待修 + 374 条缺处置表；80 条需你裁决）」——注意该 650/374/80 属被 V4 作废的旧摘要口径（见 AR-050/AR-051），新口径为 667 待修 + 336 无处置表 + 83 需裁决。
- 建议：控制器决定是否单列一个「缺陷门族销账」任务，或在 `RUNTIME-CI-001`/`FINAL-AUDIT-001` 增列 P0 门族清单。

### 1.5 AR-036 · 宪章修订签字项在 V6 无承载

- 审核包 `02` §A1：`§10.5/§17.6` 的「记录/裁决分离」需负责人签字；V4 R11/勘误6 明确「记录/裁决分离提案不生效」。
- V6 `RULINGS.md` 7 条中没有该条；`RUNTIME-CI-001` 的任务正文是资源预算与 CI 门，未含修改 §10.5 的授权。
- 后果：宪章（FROZEN，最高约束）与工作树 P26 实现（只记录）继续不一致；V6 的 `PERF-SCALE-001` 资源门验收将面对互斥判据。
- 建议：作为唯一允许的请求方，向负责人提出宪章变更或明确恢复自动判决；不得由任务自行放宽（宪章 §1.2）。

### 2.1 关于「相关噪声」的精确区分

- `UNCERTAINTY_AND_COVARIANCE.md` 的「不保存完整 covariance matrix」本身不违 V6：`UNIFIED_SCIENCE_MODEL.md` §7 允许「只存对角 variance」，条件是**同时另存 correlation kernel/scale 或可重建算子摘要**。
- 因此该文件的问题是**目标-现状差距（AR-031）**而非文档错误；而 `DRIZZLE.md` §1/§9a 把协方差产品明文写成「非目标」，则与 §7 的强制输出条款**直接冲突（AR-030）**。
- `DRIZZLE.md` §11 的常量场 Oracle 与 §5/§7 已证否的命题并存，是**同文件自相矛盾（AR-023）**，V4 勘误3 已登记、至今未修。
