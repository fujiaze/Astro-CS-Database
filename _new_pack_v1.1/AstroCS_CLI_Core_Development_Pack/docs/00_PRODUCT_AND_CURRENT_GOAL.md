# 00 产品边界与当前目标

## 1. 最终产品关系

AstroCS 最终会有 GUI，但 GUI 不是当前阶段的开发中心。产品分层为：

```text
GUI / JavaScript 控制层
        │ 命令、配置、进度、取消、结果
        ▼
AstroCS CLI 进程
        ▼
Orchestrator 编排器
        ├─ PipelineFrame 数据通道
        ├─ 算法模块生命周期
        ├─ 任务与错误状态
        └─ HISS / HCSD 持久化
```

GUI 不直接调用各算法 DLL，不传输图像像素，不理解 PipelineFrame 内存布局。CLI 必须能脱离 GUI 独立运行、测试和恢复。

## 2. 当前里程碑

当前唯一主里程碑是 **CLI Real-Data Core v1**：

- Stage 1：真实原始图像 → 真实校准 → 单次星点检测 → 板解算 → PSF → 测光定标 → 稀疏 SNR → Drizzle → HISS。
- Stage 2：多份真实 HISS → 重叠关系 → 球面梯度 → 稳健剔除 → SNR² 加权 → HCSD。
- 输出必须可由独立读取器重新打开，并通过数值、元数据、追溯和完整性检查。
- 任何关键阶段被跳过、DLL 缺失、参数未传入或降级为占位实现，都不得报告成功。

## 3. 非当前范围

- 完整 GUI 页面与交互设计。
- JavaScript 前端框架选型。
- 云端服务、多用户权限、联网账户。
- 把图像数据通过 JSON/IPC 传到 GUI。
- 为了界面演示而绕过真实算法。

## 4. 技术角色

- C++17：正式算法、数据通道、编排器、CLI、格式读写。
- Python：测试、诊断、对照计算、数据检查；最终运行时不能要求用户安装 Python。
- PowerShell/Bash：可作为开发辅助，不是产品协议或必要入口。
- Qt/JS：后续 GUI 控制层；只依赖 CLI 稳定协议和持久化格式。

## 5. 完成标准

CLI Core v1 只有同时满足以下条件才算完成：

1. 固定真实数据集可以重复运行；
2. Stage 1 和 Stage 2 没有静默跳过；
3. 数据块、ABI、配置和输出格式有版本；
4. 失败有稳定错误码，stdout 机器可解析；
5. 峰值内存、运行耗时和输出尺寸有基线；
6. 至少一次长时间批处理与崩溃恢复验证通过；
7. 发布包中包含 CLI、算法库、运行依赖、默认配置、协议和验证工具。
