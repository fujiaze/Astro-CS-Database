# Stage1 开发治理

## 1. Wiki 的作用

Wiki 记录长期有效的产品和算法决策。

- 已冻结页面：实现依据；
- 待确认页面：尚未批准；
- 状态报告：只描述事实，不修改规范。

Agent 不得为了让现有代码“通过”而反向修改 Wiki。

## 2. Agent 权限

Agent 可以：

- 调查；
- 编写规范草案；
- 修改当前明确授权范围内的代码；
- 运行少量代表测试；
- 更新状态和证据；
- 在获得仓库写权限后推送 Wiki。

Agent 不可以：

- 自行通过用户验收；
- 自行改变已冻结公式；
- 自行进入下一里程碑；
- 自行启动 710 帧；
- 把 Python 原型称为正式 C++ 集成；
- 用静态图代替真实浏览器验收；
- 用任务数量代替功能完成度。

## 3. 状态词

只使用：

- `DRAFT`：草案；
- `FROZEN`：用户已确认的规范；
- `IMPLEMENTED`：代码已实现；
- `TESTED`：已按指定测试验证；
- `WAITING_FOR_USER_REVIEW`：等待用户审查；
- `USER_APPROVED`：只有用户明确确认后使用。

Agent 不得自行写入 `USER_APPROVED`。

## 4. 当前唯一里程碑

当前里程碑：

> 冻结 HISS 与完整 Stage1 功能规范。

完成后停止并汇报。不得自动进入源码大改。

## 5. Wiki 修改规则

用户提出意见后：

1. 更新对应 Wiki 页面；
2. 标出旧规则被替换的位置；
3. 提交 Wiki commit；
4. 再派生代码任务。

不再维护多套互相冲突的控制文档。
