### 分析与推荐

- signal (float32) 数据含天文梯度 + 正态噪声, 字节间相关性较低。
- **byte-shuffle + LZ4/Zstd** 通常能显著提升压缩比, 因为 float32 各字节位置的数据分布不同。
- **Zstd** 在压缩比上通常优于 LZ4, 但压缩速度可能较慢。
- 推荐: 综合压缩比和速度, **byte-shuffle + LZ4** 或 **byte-shuffle + Zstd** 可作为 signal 默认候选。

### 分析与推荐

- FULL 模式在低占用率时浪费大量空间 (需存储全 0 的 signal/support)。
- BITMAP 体积 = bitmap_bytes + occupied_signal + occupied_support, 与占用率成正比。

- 推荐: 占用率 > 80% 用 FULL; 20%-80% 用 BITMAP; < 20% 用 SPARSE_LIST (仅为建议区间)。

### 分析与推荐

- 8 字节对齐: padding 浪费最小, 但随机读取可能跨越缓存行。
- 64 字节对齐: 与缓存行对齐, 随机读取效率较好, padding 浪费中等。

- 推荐: 综合体积和读取性能, **64 字节对齐** 作为默认候选。

## 总结

本实验覆盖了 DQ-001 ~ DQ-007 全部未决事项, 使用合成测试数据 (不同占用率的 Tile) 进行了系统对比。
所有候选均通过 CodecRegistry 复用正式 HISS 编解码路径, 确保实验结果具有代表性。

### 推荐汇总

| DQ | 推荐候选 | 理由 |
|----|---------|------|
| DQ-001 (signal) | byte-shuffle + LZ4 或 byte-shuffle + Zstd | shuffle 提升压缩比, LZ4/Zstd 提供速度/比权衡 |
| DQ-002 (support) | LZ4 或 Zstd | 单字节无需 shuffle, 按速度/比需求选择 |
| DQ-003 (BITMAP) | LZ4 或 Zstd | 通用性好; RLE 仅在极稀疏时可选 |
| DQ-004 (SPARSE_LIST) | delta + varint + LZ4 | delta+varint 大幅缩小体积, 再配 LZ4 速度好 |
| DQ-005 (阈值) | FULL>80% / BITMAP 20-80% / SPARSE<20% | 基于体积测量的建议区间 |
| DQ-006 (checksum) | CRC32C 或 xxHash32 | 视硬件加速情况选择 |
| DQ-007 (对齐) | 64 字节 | 平衡 padding 浪费与缓存行对齐 |

> **再次声明**: 此结论仅为实验建议, 未写入冻结规范, 也未设为不可更改的正式默认值, 等待用户与主审助手确认。
