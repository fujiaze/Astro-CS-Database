## 0 读法与口径

本报告是历代控制包的通读叙述件：只读这一份即可掌握四十九个包身份的谱系、七代形态更替与取证口径。全篇不评价优劣、不提改进，无据之处写「未证实」。

分析对象分三层。第一层是四十九个包身份，以 设计大纲/_evidence/packs/pack_inventory.csv 的身份列去重为准（七十五行、七十四条实例记录），每行是一个「身份 × 存形态」实例。第二层是七十四条实例的四种存形态取值：解包工作树二十一条、仅历史复原三十二条、zip 十五条、从 git 对象复原的历史 zip 六条。第三层是三个非包形控制件——工程控制/包规范.md、工程控制/ACTIVITY_STATE.md、问题扫描/（代号 RQS-2026-01），不在 pack_inventory.csv 内，由 coverage.md C 节单列；合计五十二个分析对象，coverage.md 小结记五十二比五十二覆盖闭合。两个旁路口径须与四形态并列：归档容器 engineering/control/archive/2026-09-02_legacy_工程控制_v1.3-to-v6.1 由「父包」列表达，收纳九个子包、自身八百五十五文件，与成员身份各占一行，计数不可相加（P-G11 §一）；run/** 影子树只登记不分析，同一包 marker 在 run/ 下的命中是主副本的三到四倍，V6、V7、模板三族副本各实测七十二、七十、七十份（reports/_前台独立核验.md §5、P-G08 缺口 3、P-G10 缺口 9）。

复原件采取双指针：一是复原件目录内注入的 _PROVENANCE.json——_evidence/packs/history/ 下十三个以八位提交号命名的复原根目录、共三十二份该文件，字段为 pack_rel_path、identity、recovered_files、recovered_from_rev、delete_commits、first_commit、last_commit；二是汇总表 recovered.json（三十二键）与 pack_inventory.csv 的提交列。跨形态比较有一处固定还原：复原件按「含注入文件」计数，比解包件多一文件约零点四至零点五千字节（digest_verify.md 观察 O-1）。

提交锚的权威映射是 _evidence/commits/index.jsonl：一千九百八十八行，每行一个提交的 seq、sha、日期、消息与文件清单；seq 是拓扑序而非日期序（reports/history/00_OVERVIEW.md §0）。本报告写 C<seq>｜<sha8>，查不到 seq 时只写八位 SHA。凡出现「首次／最后提交」，须注意 pack_inventory.csv 对早期身份存在方向倒置的已知缺陷（首列实为删除提交），P-G01 缺口 8、P-G02 缺口 2、P-G03 缺口 2 与 P-G13 缺口 1 已订正，以 provenance 与 git 实测为准。

## 11 形态与自证的陷阱

同一包的 zip 形态与解包形态会给出相反的自校验结论，机制是行尾归一：仓库 .gitattributes 第 2 行的 text=auto eol=lf 规则自迁移期引入（C113 侧，卡 H-S03 记其自述为消除迁移后二百五十二个文件的 CRLF 假阳性），于是"谁写入了 CRLF"多处只能记未证实（P-G12 缺口 3）。发作最重的是 AstroCS_CP0：zip 内 SHA256SUMS 十七条全过、MANIFEST.json 十六条全过，解到 reports/REAUDIT_V3/cp0_out/ 后同一清单变为 ok=1、mismatch=16——十八个文件里十二个纯 CSV 行尾差、六个 md/json/txt 目录版末尾恰多一字节，包自带的 validate_audit_package.py 在 zip 内判 PASS、在解包目录判 FAIL（P-G05 §一.3、缺口 4）。Stage1 交付包同型：zip 态四十八条哈希全过，复现目录四十八条中九条不符，且被验物 MANIFEST.json 自身即与声明值不符（声明 d4678fd3 起、实测 63a91a2c 起）；十个文件的字节差全部是行尾，按 LF 归一后十比十相同，九等于十减去清单自身（P-G03 §一.1、§一.5）。权威包 v2.0 只错一项：control/MASTER_TASK_REGISTER.csv 三十一行逐行一致、仅 zip 内 CRLF 对复原件 LF（P-G02 §一.1）。V7 的差额可精确到字节：zip 内台账 40,677 字节含一百八十九个 CR，解包件 40,488 字节为纯 LF，差值恰等 CR 数、去 CR 后零行差，而包内机器门因此在 zip 态 CONTROL_PASS、解包态三条错误全在 TASK_LEDGER.csv（P-G10 §一、缺口 1）。V8.1 三形态中五十三文件字节一致，只有四份带 CRLF，于是复原件报三项 baseline 不符、解包件零不符、zip 内全过（P-G12 §一、digest_verify §3.6）。反例同样登记在案，防止以偏概全：V4 三形态二十六文件逐字节一致、CP0 两份 zip 同哈希、V6 的 zip 与归档件四十六文件逐哈希全等、RESCUE 双向差零、AstroCS_REAUDIT_V3_REVIEWPACK 在 zip 与解包树两处均四十五条全过（P-G06 §一.1、digest_verify O-5、P-G05 §七）。

## 14 指针索引与再核方法
