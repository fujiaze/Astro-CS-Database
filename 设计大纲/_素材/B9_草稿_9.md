## 9 七条口径演进主线

本节只给序列与失效点，细节不复述第 2 至 8 节。七条主线的共同走向是：口径的权威载体从包内条文逐步上移到仓库代码与冻结宪章，包本身越来越不承担自证。

主线一，用户入口与启动件。序列：v1.0 以包根 00_START_HERE.md 配 agent/AUTONOMOUS_MASTER_AGENT_PROMPT.md（P-G01 §二）；v1.1 至 v1.3 换 AUTONOMOUS_ENTRY.md 加 START_PROMPT.txt 双件，提示词六十一至六十六字符，且被 v1.2 的 tools/validate_pack.py 列为 REQUIRED 首两项（P-G01 §四/§六）；v2.0 沿同式另加 README_INSTALLATION.md，并在 §1 自定"与 README 冲突以 README 为准"、§3 废止 v1.x 旧任务链（P-G02 §四-1）；Stage1 分两套（Agent 包 00_AGENT_START.txt 加 START_HERE.md，交付包 00_README.md），ACR 五包用 00_AGENT_START_PROMPT.txt；V3 起 00_READ_FIRST.md 加 START_PROMPT.txt 定标（P-G05 §二），V4 的 zip 反而缺提示词、V5 恢复并同增清单与哈希件（P-G07 §六 6.1），V6 至 V8.1 提示词长度四十七、四百八十七、七十九、七十一字符摆动（P-G08 §二、P-G09 §四、P-G12 §六）；宪章对齐包再取消提示词、只留 00_READ_FIRST 自称唯一执行入口（P-G13 §二 2.1），救援包又回归双件并自设一百字上限（P-G14 §二）。失效点：v1.x 入口链由 v2.0 条文废止、包体由 C237｜a78f5430 删除；START_HERE 系命名在 V3 定标后不再作包入口；现行根入口由 AGENTS.md 指向冻结宪章。钉死入口的上位约束逐代换人：REQUIRED 清单、V6.1 的 token 断言、V8.1 的一至一百字符机器断言（validate_control.py:255）、宪章期的槽位清单与路由链。

主线二，架构分层与规格骨架。序列：v1.0 根十八份大写规格加六子目录；v1.1 根规格迁入 docs 十九份并新增 contracts 与 reference；v1.2 合同件全 schema 化；v2.0 收敛七十四文件并另立 migration；V3 定型顶层九份、templates 九件、scripts 三件而不得设 tasks 与 schemas（P-G06 §二）；V5 扩至十五份、schemas 独立、首次把清单/提示词/哈希件收齐（P-G07 §二）；V6 一次重构为十九份规格加 fixtures，并把执行态移出包体（P-G08 §六）；V6.1 删十三增十、同名九件仅约束文件逐字节相同（P-G09 §六）；V7 推到九十九文件、二十四份规格、validators 十八件并以 ACTIVE_DOC_INDEX 立文档分层（P-G10 §二）；V8.1 反向收缩五十六文件、十六份规格，取消 schemas 等四目录、新增 baseline 与 ci，且把内嵌的上代 V7.1 包哈希锁进自家机器门（validate_control.py:263-266，P-G12 §二）；宪章对齐包改为根十四加 tasks 五十七加 schemas 一加 validators 二，包体本身即 cprun/v4 图实例（P-G13 §二 2.1）。失效点：担保完整性的一方从包内清单（V5 至 V8.1）换成 git 跟踪与 ACTIVITY_STATE 登记面（STAGE-07 §6）；V6 硬绑的约束文件哈希与仓库现值漂移（P-G08 缺口 13）；架构权威在宪章期移出包体，V8.1 的冻结约束件被降级为历史参照（ACTIVITY_STATE.md L23，P-G15 §五）。

主线三，资源与真机门禁。序列：V3 绝对值门——计算窗口平均 CPU 不低于百分之一百五十、单线程对双线程加速比一点五、串行段占比百分之一（05_NUMERICAL_AND_PERFORMANCE_GATES.md:19-24，P-G05 §四），并强制 CPU/GPU/Mixed 三路；V4 换相对带宽式，取平均核数不低于零点八乘以 workers 与可用核数的较小者，同时取消 ACR 与 Mixed 并记 DEFERRED（P-G06 §四/§六）；V5 承同式再加前十大秒快速失败退出码十（P-G07 §四）；V6 改采样分位数，worker 中位数不小于二、归一 CPU 中位数九十、均值八十五，台账加 heavy_compute 列（八十八行中三十八为 yes），Fatduck 离线定态 WAITING_WINDOWS（P-G08 §三/§四）；V6.1 把阈值写进验收合同并加内存带宽例外（P-G09 §四）；V7 再换数值（heavy 均值八十、百分七十以上采样点占比七十五、连续十大秒不得低于五十、加速比一点六），以 resource_class 三值与 Windows 工具链锁接管真机口径，WAITING_WINDOWS 让位 WAITING_RESOURCE（P-G10 §三/§六）；V8.1 包体回归定性条款，八十五与六十在包内全形态零命中，数值实体在宪章 §10.5 与 §18.2 及 run_monitored.py:453/455、resource_gate.h:108/111，其引入提交均晚于本包（P-G12 §四 4.6）。失效点：绝对值口径死于 V4，WAITING_WINDOWS 死于 V7 而在 V8.1 留痕以枚举外 FATDUCK_PENDING 复活（P-G10 缺口 12），包内数值死于 V8.1。

主线四，版本与包命名。序列：v1.0 无版本串仅 PACKAGE_SHA256.txt；v1.1 记"日期加特性"长串；v1.2 两行；v1.3 收敛为 1.3.0（六十六字节降到六字节）；v2.0 起产品目标版本进 MANIFEST 面；alpha 口径定标于 V5 的 13 号规格第一章并把正则写进终包校验（validate_final_package.py:95-108，P-G07 §四）；V6 以 target_version 0.10.0-alpha.1 加 baseline_commit 绑定，V6.1 升 alpha.2 并改挂 prior_control_sha256、取消 baseline_commit；V7 首次把产品版本放进包根 VERSION 与清单 product_version 同值（0.11.0-alpha.1，P-G10 §二）；V8.1 把根 VERSION 语义改为包版本"8.1"并写成机器断言（validate_control.py:150），产品版本改嵌在包名 ALPHA0.11.0 里（P-G12 §六）；宪章对齐包与救援包内均无 VERSION 件、救援包版本号字面零处（P-G14 §五）。失效点：PACKAGE_VERSION.txt 随 v2.0 本体删除而终；target_version 字段随 V7 换清单而消失；V8.1 的 VERSION 语义与宪章 §16.1 的"根 VERSION 为唯一输入"构成口径冲突，宪章期以宪章为准（两值并列登记）。命名规则另有三处可核对事实：日戳用于分辨同期并存的包（20260828 的 V4、V5、REAUDIT_V4 三包）；同一物可四名并存（V7 抬头、清单、zip 名、解包目录，P-G10 缺口 7）；ALPHA 字样可在 zip 名而不在包内（P-G07 §一 1.2），三者语义不可互代。
