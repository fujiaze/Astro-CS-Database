## 14 指针索引与再核方法

本报告的指针分四类，各有独立复核路径。

形态与实例：读 设计大纲/_evidence/packs/pack_inventory.csv（七十五行、七十四条实例记录，列序为身份、存形态、路径、文件数、字节、zip 或自带 sha256、首次提交、首次日期、最后提交、删除提交、容器（子包数）、父包、台账行数、状态分布、自带 SHA256 核对）。用它复核需做三件还原：把「首次/最后提交」按 _PROVENANCE.json 与 git log --reverse 重判方向（P-G01 缺口 8）；「删除提交」列对多身份以同一 SHA 重复占位，不能当删除次数用（P-G03 缺口 3）；台账列为空的行要先分辨是采集盲区还是真无台账（P-G09 缺口 3、P-G14 缺口 4）。

包内实测：读 设计大纲/_evidence/packs/digest/<身份>.md（四十九份，一身份一件），内含实例清单、入口件摘录、台账表头与行数、SHA256SUMS 核对与 git 事件计数；其六类口径的抽验过程与结果在 reports/packs/digest_verify.md：按层随机抽六包、覆盖十一实例、三十七项指标全等，并留下 O-1 至 O-5 五条口径观察。复原件本体在 _evidence/packs/history/<八位提交号>/（十三个复原根）与 history_zip/（六份 zip 各配一份 .provenance.json）下；取回点即同目录注入的 _PROVENANCE.json（共三十二份）中的 recovered_from_rev 字段，它指向复原所依据的提交父态。

提交侧：_evidence/commits/index.jsonl 每行含 seq、sha、日期、作者、消息、ids 与文件清单，按八位前缀 grep 可反查 seq；cards/0001-<sha8>.md 为逐提交证据卡，行数引用以卡片目录聚合行或 numstat 为最终口径（reports/history/00_OVERVIEW.md §0a 注记 3）。只读命令可复核入库性：git log --all -- 路径、git show --name-status 加八位号、git ls-files 指向 工程控制/_control_packs（实测空）、git check-ignore。包与提交的编号对接复算用 _tools/07_pack_commit_link.py。

写作纪律本身也有底稿：reports/_selfcheck.md 与 _tools/08_check_reports.py 给分片覆盖率，_tools/_ref_audit.py 给提交指针对账（七百六份报告四千四百四十一处 seq 引用、异常零），_tools/_path_audit3.py 给路径存在性核对（对照二万三千三百九十八个历史与磁盘路径），_tools/_discipline_check.py 给围栏与粘贴纪律。本报告沿用同一套指针格式与「未证实」标注；任一指针若与仓库现状不符，以 git 实测为准。
