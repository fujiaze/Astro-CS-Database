# AstroCS Stage1 / HISS 现有仓库修改入口

## 任务性质

本包不是新项目模板，也不是让你新建仓库。必须在用户现有 AstroCS 仓库中直接审计、删除失效内容、更新 Wiki、修改实现并交付必要差异文件。

## 单次执行原则

用户按 Agent 调用次数计费。读取本包后，应在一次授权执行中连续完成所有不依赖用户新决策的工作，不得在“审计完成、Wiki 更新、代码修改、测试完成、实验完成”等普通节点反复停下。

只有以下情况允许中断：

1. 剩余全部工作都被同一个未冻结科学语义阻塞；
2. 必须执行不可逆或破坏性操作，且本包未授权；
3. 发现任务明显超出 Stage1 / HISS 范围。

若某个未决工程选项不阻塞其他工作，应写入 `DECISION_QUEUE.md` 并继续。

## 绝对禁止

- 不新建仓库，不复制完整旧仓库作为“新工程”。
- 不修改或实现 Stage2。
- 不自动启动 710 帧或其他全量回归。
- 不用 Python 原型代替正式 C++ 实现或正式性能实验。
- 不把未冻结的实验结论直接写成最终默认标准。
- 不创建用户可见的 HISS v1/v2 双路线；当前只面向 AstroCS 1.0 的一个最终格式。
- 不交付完整仓库、构建产物、测试数据、缓存或大型日志。

## 必须按顺序执行

1. 阅读 `01_EXECUTION_ORDER.md`。
2. 依据 `02_FROZEN_STAGE1_HISS_SPEC.md` 更新 Wiki，先消除旧契约冲突。
3. 按 `03_WIKI_UPDATE_REQUIREMENTS.md` 标注或删除失效文档。
4. 按 `04_IMPLEMENTATION_REQUIREMENTS.md` 修改现有 C++ / CLI / Browser。
5. 按 `05_CPP_EXPERIMENT_PLAN.md` 用 C++ 做未决工程实验，只汇报，不替用户冻结。
6. 按 `06_TEST_AND_ACCEPTANCE.md` 做代表性正确性测试与性能剖析。
7. 按 `07_FINAL_DELIVERY_STRUCTURE.md` 生成精简交付 ZIP。

## 首次输出要求

开始工作后，先在仓库中生成一份简短审计记录，列出：

- 当前分支与提交；
- 现有 Stage1/HISS 入口；
- 旧 Python 原型、重复实现和冲突 Wiki；
- 计划删除、替换、保留的文件；
- 不影响继续工作的未决项。

然后直接继续，不等待用户确认。
