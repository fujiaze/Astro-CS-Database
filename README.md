# AstroCS

> 面向大规模天文图像标准化、球面投影、跨面板梯度统一与稳健叠加的原生 CLI 内核。  
> AstroCS 将单帧 FITS 数据处理为可分块读取的 HISS 球面帧数据库，再将同一滤镜的多份 HISS 统一到一个 SNR² 加权的全局加性梯度共识曲面，完成排异与叠加，输出 HCSD 球面数据库。

# 1. 项目定位

## 1.1 项目名称

**AstroCS**

当前代码仓库和部分历史文档中可能出现：

- Astro CS Normalization Database；
- Astro-CS-Normalization-Database；
- AstroCS CLI Core。

后续对外统一使用 **AstroCS**。更长的技术描述只作为副标题，不替代项目名称。

## 1.2 一句话描述

AstroCS 是一个原生天文图像处理内核，将真实 FITS 图像转换为标准化 HEALPix 球面帧数据库，并通过 SNR² 加权的全局加性梯度统一、稳健排异和多帧叠加生成连续球面数据库。

## 1.3 产品目标

AstroCS 解决的不是单张天文照片的常规后期处理，而是以下问题：

- 多设备、多视场、多滤镜数据如何进入统一处理链；
- 单帧如何被校准、板解算、测光标准化并投影到统一球面坐标；
- 如何用紧凑格式保存单帧真实球面信号与稀疏质量模型；
- 大尺度马赛克中，不同面板和不同夜晚的加性梯度如何统一；
- 低信噪比帧如何避免反向拖偏高信噪比帧；
- 多帧叠加时如何正确排除卫星线、热像素、局部云雾和其他异常；
- 最终球面数据库如何避免面板边界、覆盖变化和权重变化造成的突变；
- 大规模批处理如何在高 CPU 利用率下避免内存失控；
- 未来 GUI 如何通过稳定协议控制原生 CLI 内核，而不复制算法。

## 1.4 当前阶段

当前阶段首先完成**真实数据 CLI 内核**，不是先制作最终 GUI。

正式主线为：

```text
真实 FITS
  ↓
Stage1：单帧科学处理
  ↓
HISS：单帧球面帧数据库
  ↓
Stage2：全局加性梯度统一、排异、SNR²叠加
  ↓
HCSD：最终球面数据库
  ↓
球面浏览器检查
```

未来 GUI 通过 JavaScript 或类似进程/二进制协议控制 CLI。GUI 不直接调用底层算法 DLL，也不通过 JSON 传输大规模像素数据。

# 2. 用户价值与目标用户

## 2.1 目标用户

AstroCS 面向：

- 需要处理大视场马赛克的天文摄影用户；
- 拥有多设备、多晚、多面板数据的高级用户；
- 需要统一球面坐标数据库的科研或工程项目；
- 希望将原生算法内核嵌入自定义 GUI、自动化平台或观测工作流的开发者；
- 需要对处理过程、权重、梯度与排异进行审计的用户。

## 2.2 核心价值

AstroCS 的价值不应宣传为“自动把照片变漂亮”，而是：

- **统一坐标**：不同面板进入统一 HEALPix 球面；
- **统一光度尺度**：Stage1 通过 Gaia 和设备响应完成测光标准化；
- **统一加性梯度基准**：Stage2 将全部帧校准到一个全局 SNR² 加权共识曲面；
- **质量感知**：稀疏 SNR 控制点、support 和质量信息贯穿梯度、排异与叠加；
- **稳健融合**：异常值被单独识别和拒绝；
- **可扩展存储**：HISS 和 HCSD 支持分块、压缩和局部读取；
- **资源可控**：编排器按动态资源预算投喂帧，而非盲目并发；
- **可审计**：调试模式能够输出梯度、控制点、权重、排异和覆盖层；
- **可集成**：CLI 和机器协议作为未来 GUI 与第三方系统的稳定基础。

# 5. Stage1：单帧科学处理

## 5.1 固定流水线

```text
READ_FITS
→ CALIBRATE
→ PLATESOLVE
→ PSF
→ PHOTOMETRIC
→ SNR
→ DRIZZLE
→ HISS_WRITE
```

可观测阶段必须对应真实工作。不得保留“显示为独立阶段但实际为空壳”的状态节点。

## 5.2 READ_FITS

输入：

- FITS Light；
- FITS Header；
- 设备与观测元数据。

输出进入 PipelineFrame：

- `data`：float32 图像；
- `header`：FITS/WCS/设备元数据。

要求：

- 保留原始动态范围；
- 不在入口阶段量化为 uint16；
- 明确无效像素和 NaN/Inf 策略；
- 记录源文件哈希和稳定标识。

## 5.3 CALIBRATE

正式生产模式要求：

- Master Bias；
- Master Dark；
- Master Flat；

三者均正确匹配并应用。

用户已确认 TestData 配齐主校准帧，因此解析不到 Master 时，优先视为：

- 别名问题；
- 文件扫描问题；
- T1–T4映射问题；
- Header 与说明文档不一致；
- 路径规则问题。

不能直接把它归类为数据缺失。

允许提供显式调试模式进行部分校准，但必须：

- 由参数主动开启；
- HISS metadata 醒目标记；
- 不得进入正式 Stage2 科学验收；
- 发布网站不得用部分校准结果展示正式能力。

## 5.4 PLATESOLVE

正式路径固定为：

```text
PlateSolve 内部检测一次
├── 用于求解
└── 同步导出同一 detections
    └── PSF 直接复用
```

禁止重新引入编排器第二次星点检测。

验证板解结果时必须区分：

- 求解器内部 inlier RMS；
- 最终标准 WCS/SIP 的独立回投闭环；
- 全星表盲匹配诊断。

权威 Gate 应使用求解器确认的 inlier 星对，通过最终写出的 WCS/SIP 独立回投，不得用全星表最近邻误配替代权威星对。

## 5.5 PSF

目标要求：

- 使用 PlateSolve 导出的同一份星点表；
- 优先建立原生 float32 PSF 接口；
- 避免整张 float32 图像重复量化为 uint16；
- 输出质心、FWHM、椭圆率、背景、幅值、MAD、状态等质量信息；
- 为 SNR、星点掩膜和后续调试提供可靠输入。

## 5.6 PHOTOMETRIC

测光链包括：

1. Gaia DR3SP 光谱读取；
2. 滤镜响应与相机 QE；
3. 合成流量积分；
4. Gaia 天球坐标投影到图像；
5. 与 PSF 星点进行唯一空间匹配；
6. 稳健拟合全局光度尺度；
7. 计算残差和离群统计。

“光谱成功解析”不等于“测光成功”。正式成功必须同时满足：

- 有效 Gaia 合成流量；
- 合理空间匹配数量；
- 匹配唯一性；
- `fit_used > 0`；
- 有限且合理的 `scale_factor`；
- `sigma_residual > 0`；
- 重投影残差无系统偏移。

Stage1 负责光度尺度统一。Stage2 不再自由拟合乘性尺度。

## 5.7 SNR

HISS 不保存稠密 SNR 图，而保存稀疏控制点。

每个控制点至少表示：

- 球面位置；
- 局部 SNR 或等价逆方差；
- 来源和质量状态。

控制点应：

- 覆盖有效区域；
- 数量合理；
- 不被少量亮星垄断；
- 能反映图像中心、边缘和局部质量差异；
- 支持 Stage2 在任意有效位置重建 SNR²/逆方差场。

## 5.8 DRIZZLE

Drizzle 将单帧投影为 HEALPix 球面数据。

必须输出：

- 有效 `ipix`；
- float32 `signal`；
- 每像素 support 或累积面积权重；
- 与 HISS metadata 一致的 Nside、nested、pixfrac。

无覆盖区域不得写零冒充真实暗信号。

## 5.9 Stage1 正式验收

每份正式代表 HISS 必须验证：

### 几何

- WCS闭环；
- HEALPix位置；
- 方向和镜像；
- 同一天区多帧重合；
- 图像四角和SIP残差。

### 光度

- Gaia积分有效；
- 匹配数量合理；
- 光度尺度稳定；
- 残差非零且合理；
- 同系统同滤镜无异常漂移。

### SNR

- 控制点非空；
- 分布合理；
- 数值有限；
- 插值趋势符合实际图像质量。

### 数据

- signal 稠密覆盖有效域；
- 无 NaN/Inf；
- support 有效；
- HISS 往返一致；
- 分块随机读取正确；
- provenance 完整。

# 6. HISS：单帧球面帧数据库

## 6.1 定位

HISS 是 Stage1 的正式产物，也是 Stage2 的唯一标准输入之一。

HISS 不是：

- PipelineFrame 内存快照；
- 调试缓存；
- 单纯预览图；
- 稠密全天球数组；
- 只保存少量采样点的摘要。

## 6.2 核心数据

### 稠密有效信号

```text
ipix[]
signal[]
support[]
```

“稠密”指单帧真实覆盖区域内连续、充分的球面信号；存储仍使用稀疏 `ipix`，不为无覆盖全天球分配空间。

### 稀疏 SNR 控制点

```text
position[]
snr_or_inverse_variance[]
quality_flags[]
model_parameters
```

### 元数据

包括：

- 观测；
- 设备；
- 校准；
- PlateSolve；
- 测光；
- SNR；
- Drizzle；
- 软件版本；
- 输入和配置哈希。

## 6.3 压缩原则

- 信号默认保持 float32；
- 不为了显示转成 uint8；
- `ipix` 排序后允许差分编码；
- 每个 Tile/Leaf 独立 zstd 压缩；
- support 可研究 float16 或归一化 uint16，但必须经过误差验证；
- SNR 控制点优先保证数值精度；
- metadata 可压缩 JSON 或结构化二进制；
- 每块应具有长度、偏移、版本和校验；
- 支持局部读取，不允许浏览一小块时解压整份文件。

## 6.4 格式演进

HISS 格式必须显式版本化。

若新格式破坏旧读写：

- Reader 优先兼容旧版本；
- 提供迁移工具；
- 旧文件不得静默按新格式误读；
- 发布网站明确兼容范围；
- 任何格式冻结必须在本 README 和正式契约中同步。

# 7. Stage2：全局加性梯度、排异与叠加

## 7.1 输入约束

一个 Stage2 任务默认只接受：

- 同一规范滤镜；
- 兼容 HISS 格式；
- 有效测光定标；
- 有效 SNR 模型；
- 有效 support；
- 能形成连通重叠图的天空覆盖。

不同滤镜必须分别生成数据库。未来多通道容器另行设计。

## 7.2 只允许加性梯度

Stage2 只允许：

```text
I_corrected = I_original + C_i
```

其中 `C_i` 为第 i 帧的加性校正曲面。

禁止：

- 低频乘性梯度；
- Stage2 再次自由改变光度尺度；
- 同时拟合乘法和加法；
- 用梯度模块补偿 Stage1 测光失败。

## 7.3 全局共识总曲面

总曲面不一定等于真实天光的绝对低频亮度。

它定义为：

> 联合拟合全部帧后，在局部 SNR²/逆方差权重下，使全部帧相对于该曲面的加性偏移总体最小的平滑球面共识曲面。

所有帧先校准到该共识曲面，再执行排异和叠加。

总曲面不是：

- 单一参考帧；
- 最高 SNR 帧；
- 按顺序拼接的前一张结果；
- 最终叠加后再提取的背景；
- 对真实天空低频结构的绝对恢复。

整体零点使用全体帧 SNR² 加权零均值约束，不选择单一参考帧。

## 7.4 梯度控制点

### 有效区域

控制点只从以下区域采样：

- 真实观测覆盖；
- support 有效；
- 非无数据区；
- 非 NaN/Inf；
- 非填零；
- 非危险边缘。

真实覆盖且接近暗天空的区域可以采样。

“无信号区域”在 AstroCS 中指没有有效观测覆盖，不指正常暗背景。

### 星点和异常掩膜

利用 Stage1 星点、PSF、饱和标记构建动态掩膜：

- 普通星点；
- PSF外翼；
- 亮星星晕；
- 饱和及溢出；
- 衍射结构；
- 宇宙线；
- 卫星线；
- 坏点；
- 局部失败区域；
- 低support边缘。

掩膜半径根据 FWHM、流量、饱和程度和外翼动态扩展。

### 稀疏窗口

每个控制点来自球面局部窗口，而非单像素。

窗口统计至少包括：

- sigma-clipped median 或 biweight location；
- MAD/局部方差；
- 有效像素比例；
- SNR；
- support；
- 局部结构强度；
- 污染比例。

银心等扩展天体区域可以参与相对拟合，因为正确配准、同滤镜、已测光标准化的帧在差分中会抵消共同结构；但陡峭边缘、配准敏感区和高频复杂结构需要降权或剔除。

## 7.5 梯度拟合必须使用 SNR² 权重

“梯度和最终叠加解耦”指算法目标和阶段分离，不是梯度拟合不用权重。

梯度控制点权重必须考虑：

- 局部 SNR² 或逆方差；
- 两帧联合质量；
- support；
- 边缘置信度；
- 掩膜质量；
- 局部结构风险；
- 控制点可靠度。

低信噪比帧不能凭借大量噪声样本拖偏高信噪比帧。

梯度拟合权重与最终叠加权重来源相关，但不得直接复用为同一结果。

## 7.6 曲面实现

候选实现：

- 球面紧支撑 RBF；
- 分层球面 B-spline；
- HEALPix 分区 surface spline；
- 稀疏全局求解。

要求：

- 控制点稀疏；
- 曲面平滑；
- 不追踪星点和高频结构；
- 覆盖全部有效信号区域；
- 无数据区无需构建；
- 各面板共同求解；
- 不按面板顺序累积误差；
- 重叠图不连通时分成独立分量求解。

## 7.7 排异

梯度校正完成后，再逐球面像素执行排异。

排异输入包括：

- 已校正信号；
- 局部 SNR；
- support；
- 覆盖数；
- 边缘置信度。

候选方法：

- 加权中位数；
- weighted MAD；
- Huber/Tukey；
- Winsorized sigma；
- 小样本专用规则。

必须能处理：

- 热像素残留；
- 宇宙线；
- 卫星轨迹；
- 局部云雾；
- 导星失败；
- 局部校准异常；
- 面板边缘异常。

高 SNR 坏值仍必须能被拒绝。低 SNR 正常值不能仅因权重低而自动判为异常。

## 7.8 最终 SNR² 叠加

排异完成后，独立计算最终权重：

- 局部 SNR²；
- support；
- 边缘置信度；
- 梯度曲面置信度；
- 有效覆盖；
- 排异状态。

输出为剩余样本的归一化加权平均。

要求：

- 权重随位置连续；
- 单覆盖到多覆盖无亮度跳变；
- 面板边缘无硬切换；
- 无覆盖区不参与；
- 权重和为零时输出无数据，不输出零亮度。

# 9. 资源感知编排器

## 9.1 问题

当前观察到：

- CPU 间歇性占满；
- 内存间歇性达到高位后释放；
- 多帧高峰阶段可能同时到达；
- 固定并发或简单线程池无法保证安全。

这不是单个算法的性能问题，而是编排器缺少资源感知准入控制。

## 9.2 目标

- CPU 可以长期保持高利用率；
- CPU 达到 90% 以上时停止投喂新帧；
- 内存安全优先于 CPU；
- 多帧异步推进，但高峰阶段错峰；
- 预估单帧最坏内存；
- 保留 OS 和瞬时分配余量；
- 避免 OOM；
- 不依赖固定并发数。

## 9.3 资源画像

为每个阶段建立模型：

- READ_FITS；
- CALIBRATE；
- PLATESOLVE；
- PSF；
- PHOTOMETRIC；
- SNR；
- DRIZZLE；
- HISS_WRITE。

估算因素包括：

- 图像宽高；
- 像素数；
- 图像副本数；
- 星点数；
- PSF候选数；
- Gaia光谱数；
- Nside；
- 输出球面像素数；
- 历史峰值；
- T1–T4设备类型。

## 9.4 动态学习

每次运行记录：

- 预测内存；
- 实际峰值；
- 阶段时间；
- CPU；
- RSS/Commit；
- 临时分配；
- I/O。

资源估算器根据历史误差更新系数。预测不确定性较高时自动提高安全系数。

## 9.5 预约式准入

进入下一阶段前先预约：

```text
当前已预约内存
+ 下一阶段预测峰值
+ 预测误差余量
+ OS安全余量
+ 单帧最坏峰值保护
< 可用内存预算
```

只有满足才进入。

不得先启动，再等待是否爆内存。

## 9.6 CPU 回滞

- 滚动 CPU 达到停止门限：暂停新帧准入；
- 已运行阶段继续完成；
- CPU 下降到恢复门限后继续；
- 停止和恢复门限不同，避免频繁振荡；
- 内存门限始终优先。

## 9.7 显式 spill

内存压力处理顺序：

1. 停止准入；
2. 等待高峰阶段释放；
3. 清理可重建缓存；
4. 暂停可暂停任务；
5. 将已序列化、可恢复的大块显式 spill 到 scratch；
6. 释放内存；
7. 恢复后再加载；
8. 最后才允许 OS swap。

默认不得丢弃未持久化科学数据。

允许释放：

- 可重建缓存；
- 重复索引；
- 调试副本；
- 已持久化且可重新读取的数据块。

单帧即使独占资源仍无法满足安全预算时，应安全失败并报告需求，不得尝试运行到 OOM。

# 10. 球面浏览器

## 10.1 定位

浏览器当前是**科学检查工具**。

它用于验证：

- HISS 稠密信号；
- SNR 控制点；
- support；
- 球面位置；
- 面板重叠；
- 总曲面；
- 每帧校正曲面；
- 排异数；
- 总权重；
- 接缝；
- HCSD连续性。

它不是现阶段的主要最终产品，但必须足够正确和流畅，使用户能够检查结果。

## 10.2 正确性优先

浏览器不得为了性能：

- 将科学数据永久量化为 uint8；
- 把无数据区显示为零信号而不区分；
- 使用错误 LOD 误导接缝判断；
- 忽略坐标方向和 HEALPix 索引；
- 隐藏调试层的真实数值。

## 10.3 性能优化方向

优先顺序：

1. 打开 HCSD/HISS 时只读 Header 和索引；
2. 持久只读句柄；
3. 批量 Tile/Leaf 读取；
4. 后台 I/O 和解压；
5. 请求代际与取消；
6. CPU/GPU LRU；
7. 交互期间低 LOD；
8. GPU Tile Renderer；
9. 根据真实测量决定是否增加磁盘 LOD 金字塔。

## 10.4 性能验收

性能只能使用：

- 真实 Qt 窗口；
- 真实 OpenGL 渲染；
- 真实 HISS/HCSD；
- 实际拖动与缩放；

进行测量。

CLI 模拟循环不能作为 GUI FPS。

应记录：

- 打开时间；
- 首帧时间；
- 拖动最低帧率；
- p95帧时间；
- 最长卡顿；
- 峰值内存；
- Tile延迟；
- 缓存命中；
- 高分辨率收敛时间。

# 23. 术语

- **PipelineFrame**：Stage1 内存数据通道；
- **HISS**：单帧球面帧数据库；
- **HCSD**：多帧融合后的最终球面数据库；
- **support**：Drizzle覆盖和贡献支持度，不等同于SNR；
- **SNR控制点**：用于重建局部质量/逆方差场的稀疏点；
- **总曲面**：全部帧在SNR²权重下加性偏移总体最小的全局共识曲面；
- **校正曲面**：单帧对齐到总曲面所需的加性曲面；
- **排异**：对梯度校正后的多帧样本识别并拒绝异常值；
- **Tile/Leaf**：HISS/HCSD分块读取单元；
- **Gate**：必须有真实证据的阶段验收点；
- **调试质量层**：生产默认关闭，用于检查梯度、覆盖、权重和排异的数据层。

# 24. 项目治理结论

AstroCS 后续所有工作必须围绕以下四项真实成果展开：

1. 可信的 Stage1 和 HISS；
2. 正确的全局加性梯度、排异和 SNR²叠加；
3. 安全高效的资源感知编排器；
4. 能够检查科学结果的球面浏览器。

任何不能直接推进这四项成果、不能降低关键风险、不能提供真实验收证据的工作，都应降级、合并或停止。
