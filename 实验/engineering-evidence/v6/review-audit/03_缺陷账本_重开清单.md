### 1.1 新增发现：785 是「合并层」口径，523 个叶子 id 结构性不可表达（AR-051）

- 官方抽 id 正则（`METHOD.md` §三，与 `gen_fix_ledger.py` 逐字节相同）为 `(?:M\w+|L\d+b?c?d?e?|FD|V\d+|W\d+|SA)-[A-Z]{1,4}\d*-\d+`，要求破折号后**必须有大写字母**。
- 因此 `L<digits>-<digits>` 形式的叶子 id（如 `L24-001`、`L13-001`、`L23-002`）**在该正则下恒不匹配**。
- Oracle 独立重算：`问题扫描/_cache/L*.md` 的三/四级标题含 **523** 个不同 `L<digits>-<digits>` id；`ROOT_CAUSES.md` 逐字引用其中 **15** 个（L02-001、L03-006、L08-004、L15-013、L18-002、L18-010、L21-001、L22-005、L23-002、L23-004、L24-001、L24-002、L24-003、L26-001、L26-007）。
- 该 523 个与 785 条账本的交集 = **0**；该 15 个与账本的交集 = **0**。
- 含义：785 账本是 `findings/**` 的**合并层**视图，叶子层（`_cache/L*.md`）不在其中；`ROOT_CAUSES.md` 却以叶子 id 作「代表条目」。任何「缺陷已全覆盖」的声明必须先声明用哪一层。
- 处置去向：`SCI-ADJ-001`/`QA-MATRIX-001` 在建立新门时须显式声明层；控制器决定是否要求合并层账本补登记叶子映射。
