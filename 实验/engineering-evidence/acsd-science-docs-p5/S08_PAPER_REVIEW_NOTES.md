## R-1（必须修正）H3 论文 表 4 第 6 行的 pre/post **不是同一构型**，成对比较误导

**现状（S08a 工作树）**

```
| 6 | 逐 drop 叶边类 max|ε| | nside=512/4096/16384, pixfrac=0.8 |
    6.4952e-04 / 1.7874e-05 / 1.1672e-05  →  2.2099e-08 / 2.0005e-07 / 2.1035e-07 |
    叶边/顶点类修复 | docs/S02_P3_NORM_evidence.json |
```

**源表**（`run/ACSDSDOC-02/S02/results/s02_tables.md`，列序 `scale″ | before | norm01 | after | before_nleaf | after_nleaf`）

`### leaf_edge / nside=512`
```
| 0.005 | +6.4952e-04 | +1.2896e-08 | -5.6337e-10 | 2 | 2 |
| 290   | +2.2099e-08 | +2.2099e-08 | +2.2099e-08 | 2 | 2 |
```

`### leaf_edge / nside=16384`
```
| 0.005 | -1.1672e-05 | -4.6527e-06 | -4.0475e-09 | 2 | 2 |
| 290   | +2.1035e-07 | +2.1035e-07 | +2.1035e-07 | 388 | 388 |
```

**问题**：该行把 **0.005″ 档的 `before`** 与 **290″ 档的 `after`** 配对。而在 290″ 档，`before == norm01 == after`（**本补丁未改变该档**），
`+2.2099e-08`、`+2.1035e-07` 只是该档的原值，**不是 0.005″ 档修复后的值**。后果是把修复效果低估约 30 倍，且**恰好掩盖了「大 drop 档未修」这一必须声明的边界**。

**正确写法（同构型 pre→post，档位 0.005″、pixfrac 0.8）**

| nside | before（pre） | after（修后） |
|---|---|---|
| 512 | `+6.4952e-04` | `−5.6337e-10` |
| 4096 | `+1.7874e-05` | `−2.1e-09`（以源表 4096 段为准，逐位值须回填） |
| 16384 | `−1.1672e-05` | `−4.0475e-09` |

并与 `实验/healpix-polar/REPORT_experiment.md` 附录 C 的 `−5.6e-10 / −2.1e-09 / −4.0e-09` **一致**（附录 C 的取值是对的）。

**另**：该行「来源脚本」列写 `docs/S02_P3_NORM_evidence.json`，但该 JSON 不含 `6.4952e-04` 与 `2.1035e-07`；
源应为 `run/ACSDSDOC-02/S02/results/s02_tables.md`（由 `code/s02_summarize_tables.py` 生成）。
提交前须把引用改到**确实含有全部所列数值**的产物，或把该 JSON 补齐。
