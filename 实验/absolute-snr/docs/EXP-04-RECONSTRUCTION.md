## 0. 结论页（先给判定）

### 0.1 直接回答负责人的三个问题

**问一：重建算法选什么？**
**推荐默认 = 自然边界双三次样条 + 值域钳制**（算子 id 建议 `natural_bicubic_spline_clip_v1`，
即 §2.7 实测的 `spline_natural_clip`）；
**并在"cell 内含未分辨亮源"的域（HST 类高对比）叠加 3×3 mesh 中值前置滤波**
（`sextractor_spline_clip`）。

理由（每条都有实测，见 §2.7 与 §4.2）：
1. **值域钳制是决定性的、且几乎免费**：未加钳制时"光滑插值类"在病态控制网格上失控到
   E = 761 ~ 7.8e5；加钳制后降到 **0.80 ~ 1.45**（降 3–6 个数量级），而在正常面上代价只有
   ×0.998 ~ ×1.004。**有界性不再需要靠中值滤波换取。**
2. **不带滤波的样条在"真实地面数据"上更好**：M42 三帧 Δ=64 实测 E =
   0.0325 / 0.0314 / 0.0249，与现行双线性（0.0324 / 0.0315 / 0.0254）持平或略优，
   而带滤波版本（0.0452 / 0.0545 / 0.0415）**劣 39–74%**。
3. **带滤波版本只在 HST 类域胜出**：HST Δ=64 实测 0.0490（不带滤波 0.1375，**2.8 倍**），
   且在 Δ=64 上击败帧级兜底（0.0530）——同 Δ 下 `photutils_zoom1` 0.0449 更优，两者同族（见 §4.4）。
4. **代价**：1024² 输出 0.031 s（最便宜的样条），外推 4096²/帧 ≈0.6 s。

**问二：稀疏重建与稠密的精度对比？**
- **同粒度下两者接近，稠密并不系统性更优**：Δ=64 时最优稀疏算子与 `dense_P32` 互有胜负
  （解析可分辨域稀疏胜 0.0072 vs 0.0148；未分辨结构域稠密胜 0.4143 vs 0.4345；
  HST 稀疏胜 0.0449 vs 0.0564；**M42 三帧中 M1/M2 稠密略胜、M4 稀疏胜**）。
- **稠密唯一的、也是决定性的劣势是存储**：4096²/帧 = 64 MiB = 1 MiB 预算的 **64 倍**；
  稀疏 Δ=64 = 32 KiB = 预算的 **3.1%**。**比值 2048×**。
- **诚实结论（SP-0 要求，v2 收紧）**：**在 testdata M42 三帧上"稠密更优"只在 2/3 帧成立**
  （M1 0.0312 vs 稀疏 0.0323；M2 0.0268 vs 0.0313），**M4 帧相反**（稠密 0.0280 vs 稀疏 0.0246，
  稀疏胜 12%）。因此该域只能给**定性**结论："稠密与稀疏在 ~15% 内互有胜负，稠密的价值不足以
  抵偿 2048× 存储"。**不得写成"真实地面数据上稠密更好"。**
- **B3 的"HST 类高对比域帧级标量更优"只在用现行双线性算子时成立**：换用中值滤波算子后
  稀疏更优（§3.2）。

**问三：现行默认还站得住吗？**
**站不住（有明确证据）**。生产代码里唯一实现的重建算子是**双线性**
（`lib/algorithms/integration/v6/src/weight_chain.cpp:136` `reconstruct_sparse_snr`，
`operator_id = "bilinear_regular_grid_v1"`），而**文档从未规定算法**（`07_noise_snr.md` §4.5
只说"重建算子返回预测方差"）。实测：
- 可分辨结构域上双线性比自然样条差 2.2 倍（E 0.0204 vs 0.0091）；
- **HST 类数据上双线性稀疏在 Δ ≥ 32 就劣于帧级兜底臂**（Δ*=32 px，定义见 §5.3），
  而生产 Δ=64 ⇒ 比"退化成帧级"差 **2.1 倍**（0.1136 vs 0.0530）。

### 1.2 判据（7 项，全部给出）

| 编号 | 判据 | 定义 | 备注 |
|---|---|---|---|
| **A1** | 精度 | `RMSE(log10 ρ)`，两侧中位数归一（全局尺度相消） | 单位 dex |
| **A2** | 水平偏差 | `median(log10(σ̂/σ_true))` | 单位 dex |
| **A3** | **权重效率损失 E** | `E = Var_w/Var_opt − 1`，`w_i=1/σ̂_i²` | **非退化主判据**（§8b）：全局尺度相消，`E=0 ⇔ σ̂ ∝ σ_true` |
| **A4** | 空间增益 G | `G = E_frame − E_op` | 帧级臂相对该算子的效率损失差 |
| **A5** | 代价 | 重建 wall_s（含 N 标度）、控制点数 N、字节数/帧 | |
| **A6** | 边界行为 | 无效区传播半径与污染足迹、阶跃超调/振铃、图像边界误差 | |
| **A7** | 跨帧一致性 | 同一天区不同实现重建出的绝对 σ 场在 log10 域的离散 | |

**判据的两条已知局限（v2 新增，必须与结论同读）**：
1. **E 对乘性偏差完全免疫**：`frame_median` 与 `frame_global_mad` 在 HST 上 E 完全相同
   （均 0.0530），水平偏差却是 0.094 vs **0.818** dex。**E 只回答"权重效率"，不能替代 A2。**
2. **明确排除、不作证据**：`帧级臂 RMSE ≤ K·s_field` 对任意真值场恒真（K 足够大即可）——
   在对抗洗牌场（E 高达 0.43）下 K≥5 仍为真，且 K=1 的判别余量仅 3.4e-5 ~ 8.6e-5（见 §6 `G4`）。

### 1.3 现行生产算子的只读核实（**文档未规定，代码是双线性**）

- **代码事实**：`lib/algorithms/integration/v6/src/weight_chain.cpp:136`
  `bool reconstruct_sparse_snr(const SparseSnrLayer&, double x, double y, ...)`，
  内部 `eval_bilinear` lambda；`local.operator_id = "bilinear_regular_grid_v1"`；
  散点模式回退 `nearest_control_point_v1`。网格几何 `x = x0 + i·dx, y = y0 + j·dy`
  （`weight_chain.h:90-98`）；查询点越出定义域 ⇒ `out_of_domain=true` + **fail-closed
  （不外推、不回退帧级）**（`:233-237`）；域内**先钳到节点范围再求值**（`:239-240`）；
  另有控制点自身复现自检 `node_reproduction_max_abs`（`weight_chain.h:105`）。
- **文档事实**：`07_noise_snr.md` §4.5 只说"重建算子返回预测方差"；`ASTROCS_DESIGN.md`
  §5.3 只说"稀疏控制点插值重建"；`UNIFIED_MODEL.md:46` 只说"Phase2 由它重建稠密 SNR"。
  **算法名在整个文档集中不存在** ⇒ 本任务的空白点（`07_noise_snr.md:141` 亦自记为登记项）。
- **v6 家族的去留**：`07_noise_snr.md` §4.4（`:131`）明示该家族在 orchestrator 接线搬入
  scheduler 后删除 ⇒ **推荐算子需要在新落点重新实现，不能依赖 v6**。
- **等价性验证**：本单元 `op_bilinear` 与逐行镜像生产语义的 `op_bilinear_prod`
  实测差 **1.78e-15**（自检门 **S6**，Δ=16/32/64 三档，落盘 `selftest.log`）
  ⇒ 本单元对"现行算子"的所有评价可直接外推到生产实现。
- **接口差异（落地必读）**：生产把控制点放在 `x0 + i·dx`，本单元与 B3 放在 **cell 中心**
  `(i+0.5)Δ − 0.5`。稀疏层按 cell 存控制值时，**`x0/dx` 必须按 cell 中心设置**，
  否则整场平移半个 cell。

### 2.2 最坏情况有界性（115 个非退化 (面,Δ) 单元）

**口径说明（v2 新增）**：该 115 = (19 个解析面 + 1 个 HST 面 + 3 个 M42 面) × 5 Δ，
**混合三类数据面**；"最坏 E"对 12/15 个算子出现在解析面，但 `gpr_rbf`/`rbf_gauss`/`rbf_mq` 的
最坏就在 HST 面（见 §9.2#16）⇒ 引用时不得笼统说"最坏出现在解析面"，也不得当作 HST 生产域的数字。

   解析可分辨域（0.0072 vs 稠密 0.0148，**稀疏胜 2 倍**）、HST（0.0449 vs 0.0564，**胜 25%**）。

   中值滤波+样条 0.0492，**跨度 3.1 倍**。
3. **`frame_reconstruct` 只在"帧内噪声场无空间结构"时最优**（平坦场精确 E=0）；
   其余域它**从不最优**，但它是**唯一永远可用**的兜底（无需稀疏层、跨帧一致性最好 0.00094 dex）。
   它作为兜底是合理的，**作为默认则不是**。

### 3.2 对 `b3_domain_map.json` 既有结论的复核（独立实现重算，`results/exp04_e8_review_b3.json`）

复核方法：另写 `mad_cell_indep()`（显式循环 + `np.median`，不复用 `sci_b_common.sigma_field_fast`），
同 crop（2048）、同 Δ 网格（16…512）、同 P=32 评价粒度。

| B3 结论 | 复核结果 | 判定 |
|---|---|---|
| HST Δ=32 sparse 水平偏差 **+0.0297** dex | **+0.0297** | **成立** |
| HST Δ=256 sparse 水平偏差 **+0.2626** dex | **+0.2626** | **成立** |
| HST Δ=512 sparse 水平偏差 **+0.4444** dex | **+0.4444** | **成立** |
| HST 真实结构面 **Δ\*=16 px** | Δ*=16（crossed） | **成立，但 16 px 是 Δ 网格下限 ⇒ 是"网格边界"而非测得边界，无法分辨 Δ\*<16** |
| 纯合成面无源污染时 sparse 在 Δ=512 仍胜 | 5 个 ℓ 全部 `no_crossing` | **成立** |
| `dense` 4096² = 64 MiB = 预算 **64 倍** | 64.0× | **成立** |
| 退化门 `DEGENERATE_flat_field_ranking_never_true` | 登记成立，无违例 | **成立** |
| 恒真判据 `帧级臂 RMSE ≤ K·s_field` | K=1 假、K=5/10/100 真（对抗场 E=0.43 下仍真）；**K=1 余量仅 8.6e-5** | **成立，无证据资格** |

**复核的独立性强弱（v2 如实登记）**：六档偏差与 B3 **逐位相等**（同一 double），
这是 median/selection 类运算无算术漂移的预期结果，说明本次复核在**数值路径上并未真正走另一条路**；
它的价值是**代码独立性**（不同实现、不同调用链）而非数值独立性。

**B3 结论需要修正的一处（诚实登记）**：
> B3 §8b 写"HST 类高对比结构域：**帧级标量更优**"。复核发现**该结论依赖于所用重建算子**：
> 它成立于 B3 使用的双线性（Δ=64 E=0.1112–0.1136 > 帧级 0.0514–0.0530），
> 但**不成立于 SExtractor/photutils 式"中值滤波 + 样条"算子**（E=0.0428–0.0472 < 帧级 0.0514，
> 在 B3 自己的 patch32 粒度上也成立）。**结论应改写为**：
> "HST 类高对比域：**在双线性/未滤波样条等算子下帧级标量更优；换用中值滤波算子后稀疏重建更优**。
> 该域的判定必须与算子绑定，不能只写'帧级更优'。"
>
> **但该修正的验证范围有限（v2 新增）**：e2 用的是 **1024 crop**（`max_over_median=213.5`），
> B3/e8 用的是 **2048 crop**（`max_over_median=33099`，高 155 倍）；
> 且 e8 只复核了**双线性**稀疏臂。**"换算子可翻转 B3 结论"尚未在 B3 自己的高对比 crop 上验证。**

**另一处需要登记的脆弱点**：
> B3 用 `Δ/ℓ` 归一化失效边界。本单元实测 **ℓ 的估计不稳定**：同一个 HST M16 场，
> 2048 crop 上 ℓ=32.3 px（B3），1024 crop 上 ℓ=106.8 px（本单元 e2）。
> ⇒ **原始 Δ\*（px）是稳健量，`Δ/ℓ` 不是**。文档引用时应以 Δ\*(px) 为准。

## 4. ④ 推荐默认算子与理由

### 4.1 推荐（v2 已全部实测）

```
# 默认（地面/seeing-limited、解析可分辨域、以及一般情形）
snr_reconstruct_op          = natural_bicubic_spline_clip_v1
                              # = 自然边界双三次样条 + 值域钳制（§2.7 实测的 spline_natural_clip）
snr_reconstruct_nan_policy  = nearest_valid        # SExtractor back.c:770-798 语义
snr_reconstruct_clip        = true                 # 钳到有效控制值值域（photutils interpolators.py:111-114 语义）

# 高对比域开关（cell 内含未分辨亮源：HST/空间高分辨率）
snr_reconstruct_mesh_filter = 3x3 median           # 开启后 = sextractor_spline_clip（§2.7 实测）
```

算法（默认路径，全部 O(N)）：
1. **无效控制点**：取最近有效控制点（等距并列取平均）；全部无效 ⇒ fail-closed。
2. **可分离自然边界双三次样条**（y 向 natural BC → x 向 natural BC）。
3. **钳到有效控制值值域** `[min(ctrl), max(ctrl)]`。

高对比域在 1 与 2 之间插入 **3×3 mesh 中值滤波**（边界 replicate，无条件——
SExtractor `BACK_FILTTHRESH` 默认 0.0 语义）。

### 4.2 理由（每条都有本单元实测）

1. **值域钳制是决定性的、且几乎免费**（§2.7）：病态控制网格上 E 从 761 → **0.80**、
   2.48e4 → **0.29**、7.80e5 → **0.66**（降 3–6 个数量级）；而在正常面上代价只有
   ×0.998–×1.004（解析面 ×1.001–1.002、M42 ×0.979–1.002、HST 滤波版 ×0.998）。
   **有界性由钳制保证，不需要靠中值滤波去换。**
2. **默认路径在"真实地面数据"上不劣于现行算子**（§2.7 C5；**注意 `bicubic_cc_clip` 与它三帧近似并列**，见 §4.4）：M42 三帧 Δ=64 E = **0.0325 / 0.0314 / 0.0249**，
   与现行双线性（0.0324 / 0.0315 / 0.0254）持平或略优，比中值滤波版（0.0452 / 0.0545 / 0.0415）
   好 **39–74%**；在解析可分辨域 E=0.0091（中值滤波版 0.0847，**差 9.3 倍**）。
3. **高对比域必须用滤波版**（§2.7 C2；**这是必需项而非可选优化**）：HST Δ=64 实测 **0.0490**
   vs 默认路径 0.1375（**2.8 倍**）；**默认路径单独用在 HST Δ=64 上比帧级兜底（0.0530）差 2.6 倍，
   其 Δ\*=32 px 与现行双线性相同**——只有叠加中值滤波后才改善到 0.0490、Δ\*=128 px。
   **滤波版是 Δ=64 上唯一能击败帧级兜底（0.0530）的推荐配置**；同 Δ 下 `photutils_zoom1` 0.0449
   更优，两者同族（见 §4.4）。
4. **零超调、无非物理值**（§2.7 C1）：阶跃场超调 **0.0000**、输出严格落在控制值域内；
   未加钳制的 `spline_natural` 超调 0.1079，且在随机控制网格上会给出**负的 σ**
   （自检门 S7 的 seed29 网格实测 min = **−0.5585**，可复现；更宽值域网格达 −1.18），**非物理**。
5. **代价最低的样条**：1024² 输出 **0.031 s**（滤波版 0.040 s），N 标度 O(N) 斜率 0.08，
   外推 4096²/帧 ≈0.6 s。
6. **与两个独立主流实现同族**（不是自创）：SExtractor 2.28.2（mesh 中值滤波 + natural 双三次样条）
   与 photutils 2.2.0（mesh 中值滤波 + `zoom(order=3)` + **值域钳制**）；
   且 **6 个主流实现全部把噪声 σ 与背景电平放在同一 mesh 几何 + 同一插值器下**（§7.1）。
7. **文献支持**：Gnuastro 0.24 文档一手明确拒绝"无钳制的双三次"（原文
   "they will effectively **extrapolate on the edges, creating strong artifacts**"）——
   本单元 B2 实测的超调（样条 0.1079、gpr_rbf 0.1382）与之一致；
   Bergé et al. 2011 §3.1 明确判定 RBF（含 thin-plate）"too unstable"（本单元实测最坏 479–9.9e4）。

### 4.3 高对比域开关的判据：**本单元未能标定出一个可靠的标量诊断（如实登记）**

尝试过两个候选诊断，**都不能分开"HST（滤波有益）"与"M42_M2 / 解析面（滤波有害）"**：

| 诊断 | 定义 | HST（滤波**有益**） | M42_M2（滤波**有害**） | grf ℓ=16 s=0.03（有害） | grf ℓ=128 s=0.30（有害） |
|---|---|---|---|---|
| ρ | `median|Δ_adjacent log10 ctrl| / (√2·ε_cell)` | 2.17 | 1.45 | 1.09 | **7.98** |
| s/ε | `std(log10 ctrl) / ε_cell` | 12.4 | 5.9 | 1.5 | **25.8** |

> **为什么这 4 列能证明"标量诊断不可用"**：`grf ℓ=128 s=0.30` 的 ρ=7.98、s/ε=25.8 **双双高于 HST**
> （2.17 / 12.4），而该域**滤波有害**（它 ℓ≫Δ，滤波只会破坏可分辨结构）⇒ 两个诊断都不是
> "越大越该滤波"的单调量。另有 **M42_M1/M4 全帧 ρ 精确为 0**（16-bit 整数数据的量化地板，
> 见 §2.6）⇒ **该诊断在整数真实数据上直接失效**。

⇒ **落地时建议用"数据来源"判据而非从控制网格自身推断**：
**该域是否含未分辨点源**（HST/空间高分辨率 ⇒ 开滤波；地面 seeing-limited ⇒ 不开）。
**无法判断时取默认（不带滤波）**：默认的目标域（地面/seeing-limited）在全部真实数据上不劣于
现行算子，而滤波版在该域劣 39–74%；只有在**能判定为 HST 类高对比域**时才开滤波。
（v2 初稿曾写"无法判断时取滤波版更安全"，方向错了——滤波版的代价恰落在默认的目标域上。
两配置的有界性口径也不同：滤波版在 115 个非退化单元上最坏 5.64，默认路径在 e9 的 C3 病态集上
最坏 5.62，两者同级。）

### 4.4 为什么不是另外几个

| 候选 | 不选的理由（实测） |
|---|---|
| **`bilinear`（现行生产算子）** | 有界但系统性偏差：可分辨域 E=0.0204（默认路径 0.0091，**差 2.2 倍**）、HST E=0.1136（**差 2.3 倍**，且劣于帧级兜底 0.0530）。它是**下界**，不是选择。 |
| `nn` | 严格被支配：可分辨域 E=0.0365（双线性 0.0204）、HST 0.1098；只保留作非退化基线。 |
| `bicubic_cc`（无钳制） | 最坏 E=**761** ⇒ 必须加钳制。**加钳制后是推荐默认的近似并列备选**（实测：M42 三帧 0.0325/0.0311/**0.0246** vs 默认 0.0325/0.0314/0.0249；HST Δ=64 **0.1223** vs 0.1375，略优；阶跃超调 0.0741 vs 0.1079，更小）。**默认仍选自然样条的理由**：① 解析可分辨域胜 30%（0.0091 vs 0.0118）；② 与 SExtractor/photutils 主流实现同族（natural BC 双三次样条），便于与既有实现对照。**若落地实测发现局部三次更易分块并行，`bicubic_cc_clip` 是可接受的替代，不应视为错误选择。** |
| `spline_natural`（**无钳制**） | 与推荐默认同核，但**无钳制时最坏 E=2.48e4，且会产生负 σ** ⇒ 必须带钳制。 |

| `photutils_zoom3` | 与滤波版同族（超调 0、平坦场 E=0.0002），但 `scipy.ndimage.zoom` 的 IIR 样条预滤波带来非局部的几何衰减边界效应（线性场相对误差：边缘 3.0e-2 → 3.6e-3 → 9.6e-4 → 2.6e-4 → **6.9e-5@4Δ**），且耗时 4 倍（0.124 s vs 0.031 s）。可作为**独立交叉验证实现**保留。 |

### 4.5 与"稀疏层存绝对值"改动的接口（落地必读）

负责人已裁决**废弃 SNR(x,y) = frame_snr × rel(x,y) 的分解**：稀疏层控制点存**绝对** SNR，
稠密场**由控制点直接重建**，不再乘帧级标量。该裁决在合同侧**已经落地**：

- `eng/contracts/schemas/phase_config_mosaic.schema.json:166`（`snr_path` 的 description）：
  "SNR(p) 由**绝对** SNR 控制点重建为稠密场，**不乘帧级标量**"；
- `docs/plugins/algorithms_phase2/13_integration.md:22/:37`：同口径，并要求"重建算子与误差入 manifest"。

因此本单元的推荐必须满足以下**接口约束**（逐条已在本单元验证）：

| 约束 | 说明 | 本单元证据 |
|---|---|---|
| **不得再乘/除帧级标量** | 重建输出**直接就是**绝对 `SNR(x,y)`；旧分解的 `frame_snr` 只保留为 `frame_reconstruct` 路径的输入 | §2.7 全部 E 都是"控制值 → 稠密场"直接比较，无任何帧级因子 |
| **不得对控制值做归一化** | 旧"中位数归一"口径（相对值）彻底废弃；算子在 log/线性域都不得先除以中位数 | §2.1 的 E 判据全局尺度相消，故本单元结论对"是否归一化"不敏感——但**归一化会破坏绝对值语义**，属接口层禁止项 |
| **必须正值保持** | σ 必须 > 0；未加钳制的自然样条在病态网格上给出**负 σ**（S7 实测 −0.5585） | 自检门 **S7**（钳制契约） |
| **必须带值域钳制** | 既是正值保证，也是有界性保证（E 7.8e5 → 0.66） | §2.7 C1/C3/C4 |
| **几何：控制点须落在 cell 中心** | 生产 `eval_bilinear` 用 `x=x0+i·dx`；按 cell 存控制值时 `x0/dx` 必须使节点落在 `(i+0.5)Δ−0.5`，否则整场平移半 cell | §1.3；生产出处 `weight_chain.cpp:239-240` |
| **域外 fail-closed 语义保持** | 不外推、不回退帧级（`out_of_domain=true`） | `weight_chain.cpp:233-237`；本单元 `op_bilinear_prod` 逐行镜像（S6） |
| **manifest 字段已有落点** | `SparseReconstruction.operator_id`（`weight_chain.h:102-103`）已存在，可直接编码 `natural_bicubic_spline_clip_v1` / `..._mesh_median_v1`；`node_reproduction_max_abs` 保留为自检量 | `weight_chain.h:101-107` |
| **开关缺落点（v2 新登记）** | `SparseSnrLayer` 只有 `operator_id`/`regular_grid`/`max_radius_px`，**没有声明"是否开 mesh 滤波"的字段** ⇒ 落地须扩合同或把开关编码进 `operator_id` | §9.2#17 |

## 5. ⑤ Δ 推荐值与依据

### 5.1 事实基线

- 现行生产值 `sparse_snr_spacing_px = 64`，`Δ = hips.tile_width/8 = 512/8`（`07_noise_snr.md` §5），
  复用 Phase2 UPM 的 8×8/tile 控制网格 ⇒ **Δ 的当前取值来自几何复用，不是来自精度实验**。
- 存储预算 1 MiB/帧允许 **Δ 降到 16 px**（FP64 下 512 KiB，占预算 50%）⇒ **存储不构成约束**。
- 控制点估计量的自身噪声地板 `ε_cell = 1.166/ln10/√(Δ²/2)`（`exp04_common.py:67`）：

  | Δ | 64 | 32 | **16** |
  |---|---|---|---|
  | ε_cell (dex) | **0.01119** | **0.02238** | **0.04476** |

  （v1 误写为 0.0158 / 0.0224，v2 已按定义改正。）

### 5.2 实测 Δ 依赖（E，estimated）

| 面 | Δ=16 | Δ=32 | **Δ=64（现行）** | Δ=128 | Δ=256 |
|---|---|---|---|---|---|
| HST M16（滤波版 `photutils_zoom1`） | **0.0124** | 0.0214 | **0.0449** | 0.0724 | 0.0468 |
| HST M16（滤波版 `sextractor_spline`） | 0.0134 | 0.0226 | 0.0492 | 0.0826 | 0.0498 |

> **读表一条**：解析面上"最优算子"本身随 Δ 变——Δ=16/32 时中值滤波类与局部算子最好，
> Δ≥64 时 GPR/RBF 族最好。这再次说明**没有算子在所有域最优**，也说明"选算子"与"选 Δ"不能分开决策。
> 该面最优 E 从 Δ=64 的 0.0072 升到 Δ=256 的 0.1762（**24 倍**）——
> 可分辨结构域上**细 Δ 的收益与算子差异同量级**（该面同一 Δ 下算子极差：Δ=16 为 5.1 倍、
> Δ=32 为 3.5 倍、Δ=64 为 **12.6 倍**、Δ=128/256 为 1.2–1.7 倍；排除中值滤波族后 Δ=64 仍 5.1 倍）。
> 因此"选 Δ"与"选算子"都必须做，不能只做其一。

### 5.3 推荐

| 项 | 推荐值 | 依据 |
|---|---|---|
| **默认 Δ** | **保持 64 px** | ① 与 Phase2 UPM 的 8×8/tile 控制网格几何复用（`07_noise_snr.md` §5），改 Δ 会同时改动 UPM 接口；② **在默认路径的目标域（地面/seeing-limited 与解析可分辨域）上，Δ=64 已落在适用域内**。**注意（v2 补登）**：**推荐默认自身在 HST 类域 Δ=64 的 E=0.1375，比帧级兜底 0.0530 差 2.6 倍**，其 Δ*（HST）= **32 px，与现行双线性相同**；**只有叠加中值滤波后才改善到 0.0490、Δ*=128**。⇒ **HST 类域的滤波开关是必需项，不是可选优化**（该事实在 v2 初稿中未登记）。 |
| **HST 类高对比数据的推荐 Δ** | **32 px**（可选 16 px） | HST 实测 E：0.0449(64) → 0.0214(32) → 0.0124(16)，**Δ=32 相对 Δ=64 收益 2.1 倍**，代价是存储 0.031 MiB → 0.125 MiB（仍只占预算 12.5%）。 |
| **Δ 下限** | **16 px（且已到估计量噪声地板）** | ① 存储：512 KiB = 预算 50%；② **ε_cell(16)=0.0448 dex，与 HST/M42 的 `s_field`（0.049 / 0.05）同量级** ⇒ 16 px 时控制点估计量噪声已与场的真实空间变化相当，**再细下去由估计量噪声主导**；若要 Δ=16 必须先降 ε_cell（更大 cell 内像素数或更强的控制点估计量）。 |
| **禁止** | Δ > 64（除非显式声明降级） | HST 上 Δ=128 时滤波版 E=0.0826、**推荐默认 `spline_natural_clip` 0.2918**，均已劣于帧级兜底 0.0530；Δ=256 时**无钳制的 `gpr_rbf` 单独失控到 7.80e5**（同 Δ 下 `spline_natural`/`gpr_matern32`/`gpr_exp` 在 23 个面上最大仅 5.62——1e4–1e5 量级失控发生在 **Δ=16** 的格子，v2 初稿把两处混淆）。 |
| **失效边界 Δ\*（须写明定义与算子）** | 定义 = **"该算子 E 首次劣于帧级臂的最小 Δ"**：<br>· 现行 `bilinear`：**Δ\* = 32 px**<br>· 滤波版 `sextractor_spline`：**Δ\* = 128 px**<br>· **推荐默认 `spline_natural_clip`：Δ\* = 32 px（与现行双线性相同）**<br>· ⇒ "换算子把失效边界推后 4 倍"**只对滤波版成立**；**默认路径在 HST 类域必须靠滤波开关**，否则一步都没推后 | `exp04_e2_hst.json`。**v1 误写为"16→128，8 倍"**：16 是 B3 在 **RMSE 判据 + patch32 + 2048 crop** 下给的值，128 是本单元在 **E 判据**下给的值，两者**定义与判据都不同，不可直接相比**。 |
| **非单调现象（如实登记）** | Δ=256 时滤波版 E=0.0498 / pz1 0.0468 **又优于帧级 0.0530** | 原因未查清，登记为**未解释现象**；不得据此认为 Δ=256 可用（同 Δ 下无钳制算子已失控）。 |

> **给负责人的一句话**：现行 `Δ=64` 本身没有错，**错的是配套的算子**。
> 用双线性时 Δ=64 在 HST 类数据上比"退化成帧级"还差 2.1 倍；换成推荐算子后 Δ=64 才成立。

| **Gnuastro 文档**（一手，版本见 §7.1） | `doc/gnuastro.texi` | 原文："We do not use parametric interpolation methods (like bicubic), because they will effectively **extrapolate on the edges, creating strong artifacts**." ⇒ 与 B2 实测超调一致，支持"必须带钳制" |

### 7.3 本单元与文献的分歧（如实登记）

- 文献（Bergé 2011）对 RBF/thin-plate 的否定与本单元一致（最坏 E 479–9.9e4）。
- 文献（Liu & Miller）对 B-spline 的否定与本单元**部分不一致**：本单元里自然样条在
  **可分辨平滑域与真实地面域最好**，只在**控制点噪声大**（HST 类）时才需要中值滤波保护。
  差异根源：他们的 B-spline 用于天光**电平**建模且 knot 数固定，本单元用于**噪声 σ 场**且
  Δ 由 UPM 几何固定。**不能直接互相外推。**

## 9. ⑨ 诚实边界与未核实项

### 9.1 依赖仿真/实现假设的部分（结论随假设可变）

1. **物理前向仿真的参数是"声明坐标"**：HST 面用 `gain=1.3, RN=10 e⁻, dark=0.5 e⁻, sky=200 e⁻,
   σ_median=200 e⁻`（与 B3 同口径）。改变这些会改变控制点噪声量级，从而改变"中值滤波收益/损失"
   的 crossover，但**不改变"钳制把最坏情况从 1e5 压到 1.45"这一有界性结论**。
2. **HST M16 的 ℓ 估计不稳定**：2048 crop → 32.3 px（B3），1024 crop → 106.8 px（本单元）。
   因此本报告以 **Δ\*(px)** 为准，`Δ/ℓ` 只作辅助。**ℓ 的稳健估计方法本身是未解决问题。**
3. **GPR 是本单元自己实现的局部窗口版本**（O(H·W·K)，窗口半径 4 cell，含 1e-6·k(0) 数值 nugget，
   含局部常数均值）。**与 sklearn/GPy 的全局 O(N³) 实现不是一回事**；对 `gpr_*` 的结论
   **只适用于该实现**。落地若采用 GPR 必须重新标定 nugget 与窗口。
4. **平滑参数未做超参搜索**：`tps_smooth smoothing=1.0`、GPR `sigma_n=0` + 数值 nugget 均为默认值。
   **平滑类算子的最优平滑参数是本单元未覆盖的维度**，其潜在收益（尤其在 HST 上）可能被低估。
5. **中值滤波只在 3×3、无条件替换这一档做了测量**；SExtractor 允许 1..11（`preflist.h:60`，**本仓库无 2.28.2 的 preflist.h，行号未复核**）、
   photutils 允许任意奇数 `filter_size`，且都有"仅在超过阈值时替换"的模式。**滤波核尺寸未扫描。**
6. **高对比域开关的标量判据未能标定**（§4.3）：ρ 与 s/ε 两个候选诊断都不能分开"HST（滤波有益）"
   与"M42_M2 / 解析面（滤波有害）"。落地只能用"数据来源"判据。

### 9.2 未核实 / 未能穷尽的项（明确列出，不冒充已验证）

1. **photutils 的 `interpolation` 旧参数名不存在**：`Background2D.__init__` 与
   `interpolators.py` 中**无该形参**；该名字在全包只作为 matplotlib `imshow` 参数出现
   （**33 处命中**，v1 误写为"grep 0 命中"）。真实改名是 `method`/`backfunc` → `interpolator`（CHANGES.rst 0.3, PR #437）。
   任务书里"photutils `Background2D` 的 `interpolation` 选项"这一说法**核实为不成立**。
2. **SExtractor 从 bilinear 切到 bicubic 的版本节点未核实**：1996 论文写 bilinear、2.28.2 源码是
   natural 双三次；线索只有 `src/back.c:1239` 的 `VERSION 02/02/98` 表明 `backrmsline` 1998 年已存在。
3. **de Boor / Wahba 书内关于 natural 边界条件与 thin-plate 远场行为的逐字论述未核实**
   （版权限制，只核到章节标题与 DOI）。
4. **其他主流项目是否也做噪声场稀疏重建未能穷尽**：只对**已取得源码副本**的项目成立（§7 表头已列明）。
   Pan-STARRS psphot / THELI / DECam CP / hscPipe 未核。
5. **M42 三帧的 ℓ 估计（27–30 px）与 B3 的（23.4 / 214.3 / 28.0 px）差异大**，
   其中 M2 帧 B3 给 214 px、本单元给 30.2 px（crop 尺寸与估计器口径不同）。
   **真实地面帧的 ℓ 估计同样不稳定**，M42 的适用域判定只能作定性参考。
6. **未做端到端生产验证**：本单元只在 Python 侧实现算子并评价，**没有把推荐算子接进
   `lib/algorithms/`**（任务约束：不改生产代码）。推荐算子在生产路径上的实际代价
   （缓存友好性、分块并行、FP32/FP64 混用）**未测量**；§2.3 的"外推 4096²/帧"是**线性外推**。
7. **未测量"重建算子 × 排异 × 集成"的联合效应**：E 判据是"用 σ̂ 代替 σ_true 做逆方差加权的
   方差膨胀"，不含 Phase2 的排异、UPM 加性归一化与 drizzle 重采样。
8. **`frame_global_mad` 臂是"已知错误构造"**（整帧未裁剪 MAD）：它在 HST 上给出 0.82 dex 的
   水平偏差。**该臂不是候选，只作对照**，不得被引用为"帧级路径的表现"。
9. **`idw` 忽略 `nan_policy`**（`operators.py:297` 起全程不用该参数；
   `e6::B1_invalid` 中 idw 的 `nearest_valid` 与 `frame_median` 两行逐位相同）
   ⇒ "同输入同判据"在 NaN 策略这一维上对 idw 不成立。
10. **负例门覆盖面有限**：G1 只覆盖 11 个算子，`tps`/`tps_smooth`/`rbf_mq`/`rbf_gauss`
    **完全没有进任何负例门**；G1 的 `max_abs_dev` 不参与判定；G5 门槛仅 ≥7/15 且被测算子集
    不含推荐算子与 `photutils_zoom3`；S4 容差 0.5 dex 对"精确插值类"过松。
11. **Δ\* 的网格下限**：e8 R2 在 Δ=16 已 `sparse_worse_than_frame=true`，"Δ\*=16 稳健"实为
    **网格边界**而非测得边界，无法分辨 Δ\*<16。
12. **"换算子可翻转 B3 的 HST 结论"只在低对比 crop 上验证**：e2 用 1024 crop

    基本持平，M4 0.0249 vs 0.0254 略优。**推荐的收益主要在解析可分辨域（2.2 倍）与
