## 一、负责人点名的四条

### 1. 阶段一：内存块接线 + 中间产物不落盘（工程）

- **是什么**：标准/发布模式本应「不落盘中间产物」，改由**内存块**在阶段内传递；发布构建下校准产物的取数也应走内存。
- **现状**：**一半完成**。
  - **已完成**（已入库）：开发模式开关体系（**构建期**生效，发布以主开关关闭构建）；运行前输入面校验（存在 / 匹配 / 合法；**匹配判据 = 尺寸一致**；有正反例实测）；**发布构建下"找不到校准产物就悄悄用原帧"的静默回退已去掉**，改为明确报错。
  - **未完成**：**写侧**的编译期闸（现在默认构建仍靠中间文件在盘上才跑得通）；**内存块接线**（把校准产物、测光产物在阶段内用内存块传递）尚未实现。
- **后果（要紧）**：**发布构建目前不可用**——一旦中间文件不存在，阶段一会必然在校准取数处失败。文档已写明「现在默认构建能跑通 ≠ 发布构建可用」。
- **下一步**：实现内存块接线 + 写侧闸；**二者必须同批落地**（只闸一侧必然失败）。
- **状态**：**进行中**（排队：排在当前第 2 条之后）。

### 2. 当前问题：产物"帧零点"的语义与它带出的下游污染

- **是什么**：产物里一个名叫"帧零点"的量，实际是**那片天区被检出星的中位颜色**（与帧无关）；下游把它当成"这一帧的零点"，从而把**逐天区的颜色差**带进了 **5σ 深度**与**帧间权重**。
- **量级**：深度最多带 **约 0.06 mag 的天区间系统差**；帧间权重跨天区相对误差可达 **约 11%**（阶段二受影响）。
- **修法（已定）**：把绝对锚常数定清楚，然后 `仪器零点 = 锚常数 − 2.5×log10(帧标度)`；颜色项只作诊断、不再进零点。
- **状态**：**进行中**（改名已编译通过；正本键表、缺陷登记、验收待补）。

### 3. 测光精度优化

- **是什么**：把单帧测光精度进一步压下去。
- **现状**：**未开始**。已摸清的空间：逐星残差有一个**不随信噪比下降的底**（约 0.014 dex），五个可测协变量**只解释 10.6%**；PSF 宽度含约 5% 信号；**颜色项目前测不了**（光谱路径把色指数置零、产物不落逐星颜色）。
- **下一步**：先补「逐星颜色」这一层产物（否则颜色项永远测不了），再重做归因。
- **状态**：**待办**。

### 4. 马赛克接缝

- **现状**：**加性半边已验**——真实两帧接缝 **0.151 → 0.0081（改善 95%）**；生产口径逐边 **70.5%** 改善；结构不被削、噪声不抬。
  **乘性半边不能动**——三条独立路线对"帧级增益"只给到约 **15%** 一致度；单独施加星比那一路会把接缝从 0.151 弄到 **0.206**（更差）。
- **遗留**：只测了**一条**真实接缝（样本，不是分布）；**≥3 帧 / 整个重叠区**未做。
- **状态**：**进行中**。
