# 负责人问题台账

面向负责人。每条一句话说清「**是什么 / 现在什么状态 / 下一步**」。
状态取值：**待办 · 进行中 · 待裁决 · 已完成**。完成的条目不删除，改状态并写明结论落在哪。

**处理顺序（负责人口径）**：**科学性优先**；期间发现的**工程问题只记账、暂不处理**（见第二节）。

**工作纪律（负责人口径，一律照此执行）**：
1. **验证之后，先订正文档，再改代码**——科学性问题与工程问题同样适用。
2. **修正后第一时间订正对应文档**，不允许"代码改了文档欠着"。
3. **遇到不清楚的地方，先去读文档确认**，不凭印象动手。
4. 改注释/改文档**必须全文 grep**，不得只改被点名的那几行（已据此补出多处漏项）。
5. **不得把未兑现的事写成设计意图**——本轮已两次据此拦下过度宣称。
6. 改**绝对刻度/零点**这类量，必须先用**物理合理性**卡一道（深度、星等要落在仪器能到的范围）。

## 一、科学性（按此顺序处理）

### S1 产物"帧零点"的语义 + 它带出的下游污染 ｜ **进行中（接近收口）**

- **是什么**：产物里名叫"帧零点"的量，实际是**那片天区被检出星的中位颜色**（与帧无关）；下游把它当"这一帧的零点"，把**逐天区颜色差**带进 **5σ 深度**与**帧间权重**（跨天区相对误差可达约 **11%**）。
- **已完成**（逐项都有提交）：① 键改名 + 正本键表 + 下游缺陷登记 + **行为逐位不变对拍**；② 科学正本那句过宽表述收窄；③ 端口正本《正确的仪器零点式》+ 附录 P 作废原因；④ **方案 A 实施**：帧的仪器零点改用**冻结常数**（不再逐帧取颜色项），代码与正本同批；⑤ **权威倒挂订正**：科学正本与 schema 里旧口径 `ZP_syn` 清零（6 处）；⑥ 又一处过度宣称订正（绝对刻度**当前锚在参考域**，非已锚在 Gaia G）。
- **当前口径**：`zp_inst = C_abs − 2.5·log10(k_photo)`；`C_abs = −14.276811281840642 mag`（参考域 = 16 帧 T2 参考集、参考通带 = **Baader R**、**分通带**）。**边界如实写**：该常数含参考域样本的中位合成颜色 ⇒ 绝对刻度锚在**参考域**，与 Gaia G 锚定相差一个**尚未测定**的量；该差是常数、在相对权重里整体抵消、只影响深度的绝对数值。
- **两个欠账**：
  1. **16 帧端到端验收未做**（仅有单帧冒烟：深度 20.577 vs 基线 20.588，差 0.0111 = 本帧自身颜色项与冻结值之差；顶层锚逐位等于冻结常数）；
  2. **通带适用范围**：当前只对参考通带正确，非参考通带会**静默复用**参考常数（深度绝对值错、可达 1 等量级，且**不会自暴露**）。**已改判为实施守卫**：按运行通带判定（配置里已有 `filter_passband`，代码里已解析出库键），非参考通带或身份取不到 ⇒ **失败关闭**（不伪造、不复用）。**守卫 + 负例实测 + 16 帧验收待做。**
