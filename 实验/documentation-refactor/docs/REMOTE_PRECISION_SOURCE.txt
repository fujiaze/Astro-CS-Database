# 科学设计与生产源码差异地图

本页连接最高设计[1]、科学模型[2]与真实生产源码。目标合同、静态实现和已有实验分别列出；本页不包含新的编译、数值实验或真实帧运行。源码路径和函数名是可追踪定位，数学定义仍由对应 science 正本拥有。Normalize 是当前实现收敛范围，Mosaic/Export 在此只说明相邻消费和产品边界。

## 1. 已有生产路径

| 环节 | 静态实现 | 结论边界 |
|---|---|---|
| Normalize 八节点 | `lib/infrastructure/cli/commands.cpp::run_phase1_block` → IR → `lib/infrastructure/scheduler/src/module_adapters.cpp::P1NodeModule` 与 `p1_op_*` | 不是 calibration-only 的 `lib/phase1_session/p1_session.cpp::run_session` |
| WCS 与科学源 | `p1_op_wcs` 真调用 IPV；`p1_op_star_psf_impl` 消费已解 WCS | 原始头无 WCS 不等于求解失败；solver 候选和科学源不同 |
| 球面参考精度 | `p1_op_drizzle` → `lib/infrastructure/scheduler/src/normalize_precision.cpp::stage_frame_precision` → `lib/algorithms/noise_snr/cpp/src/sparse_reference.cpp::complete_spherical_reference` | canonical 计算已接入代码；不是所有响应、PSF、噪声和单位状态都已闭合 |
| precision 持久化 | `lib/algorithms/integration/normalize_science/src/normalize_science.cpp` 的 `write_local_model_file`、`write_frame_science_document`、`read_frame_science_document`、`publish_staged_frame_science`；writer 有实际调用 | serializer、reader 与发布均存在；合同覆盖范围见下表 |
| Mosaic 自由组合 | `lib/algorithms/coverage/src/coverage.cpp` 不因 filter 字符串不同拒绝输入 | 保留可解释坐标、格式与几何的数据检查；不能据此声称未知通带已同一化 |
| Mosaic 最终产品 | `module_adapters.cpp::p2_op_write` 使用 `AIO_HIPS_PRODUCT_SIGNAL` | 内部 support/variance 仍参与计算，不构成最终图像层 |
| Export 最终产品 | `module_adapters.cpp::p3_op_writer` 的 `unc=false`；正式写出走单信号路径 | 不要求阶段二发布 variance/ivar，不凭单信号制造精确误差层 |
| 开发编译边界 | 根 `CMakeLists.txt` 将 `ACSD_PROBES`、开发子项由 `ACSD_DEV_MODE` 派生，并固定关闭 checkpoint 子项 | 兼容 option 名称仍存在不等于可独立启用；运行等价依证据而定 |

## 2. Normalize：合同与实现边界

字段、单位和状态以 NORMALIZE_DATA 为准[3]；接口与实际落点见实现规格[4]。下表是本页唯一的实施差异登记，不由其它导航页另立平行清单。

| 主题 | 已有实现与可追踪符号 | 仍受限制的合同或静态风险 |
|---|---|---|
| Runtime typed 对象 | `lib/include/acsd/normalize_data.h` 已有 ObjectHeader、ReferenceDefinition、ReferenceControl、SparseReferencePrecision；descriptor 已有关键排序边 | `lib/include/acsd/core/context.h::RunContext` 仍以 artifact descriptor 为主；实际跨节点读取 p1_*.json/FITS，缺完整 typed 仓、revision 与消费者 lease；noise 的合成 `fluxes` 边和生产读取不一致 |
| 帧身份 | `p1_frame_key` 及侧车 frame_id 已贯穿若干路径 | 当前键来自净化 basename；生产 fdoc 构造没有绑定 input_occurrence；重复输入、同名文件与对象版本未满足 occurrence 合同 |
| 逐帧响应 | `p1_op_photometry::p1_resolve_frame_binding` 已读取 `photometry.frame_overrides`，为逐帧拟合选择 filter/QE 并保留继承来源 | 匹配依输入路径、basename 或净化 key，第一条命中即停止；重复路径的不同 occurrence、同名冲突和冻结输入序号仍未满足严格身份合同，不能将其概括为完整 occurrence 绑定 |
| 参考来源 | `normalize_precision.cpp::parse_reference_config` 支持 explicit_linear_flux；缺参考明确 unavailable | sed_response 明确记录积分 not_wired；不能宣称已由实际参考 SED/响应生产 F_ref,k，也不以检出星中位数补 canonical |
| GLS 矩阵与秩 | `complete_spherical_reference` 的常规路径已对 Qᵀ 作列主元 Householder QR，投影白化模板并独立判背景秩/通量可辨识；Jacobi 对照保留平方逆公式 | m×nl 超过工作集阈值时仍回到 Jacobi oracle；两条路径的截断与边界需分别验证。不能继续写“生产只用 Jacobi”或“背景冗余必然拒绝通量” |
| 数值子空间诊断 | `PivotedQr` 显式重算残余列范数并以相对主元门限截断；有 solver/rank/tolerance 诊断 | I_F 已改为显式残差两轮投影后取平方范数，保存响应/残差范数和 condition_estimate_method；旧范数平方相减问题不再描述该分支。QR 主元门限不等于奇异值门限，主元比平方仍不能仅凭方法名成为谱条件数或保守上界；通量残差平方与阈值的尺度、Jacobi 分支分别核对 |
| 最终信号算子 | `build_patch_windows` 用完整捕获贡献汇总 N，设置 R=(a/A_drop)/N；Drizzle 的捕获筛选已按目标叶保存贡献 | 捕获完整性、候选遗漏和同次正式叶归一仍需独立核对；不能将局部算子自洽等同全域几何正确 |
| 原生 gain 与 alpha | completion 已纳入 alpha²/a_ref 的源泊松项，合成非平凡常量标度有证据[5] | 生产请求已有 pixel_alpha_at，经同一 photo_spatial_m 求值，再填每窗 pixel_alpha；优先于旧 cfg.pixel_scale 和常量。真实 applied 空间场的端到端证据不能由 alpha=1 的运行替代。`a_ref=Σalpha P` 仍使用当前窗口，信息模板取 w.profile；截断总通量/空间标度的配对问题见科学问题记录 |
| PSF 与模板 | `pixel_integrated_psf.cpp::pixel_integrated_moffat4_profile` 已实现归一椭圆 Moffat4 的像元求积；`normalize_precision.cpp::pixel_integrated_profile` 已实际调用 | 已消费逐帧 psf_params，PSF 库构建三角剖分并混合顶点积分响应；逐点包络/求积误差与帧摘要已经分离。当前模型无孔洞/跨无效区约束输入，凸包外/剖分失败仍回退帧常 sigma，不能由拟合成功行推定全部质量与空间支持合格；相邻阶差只作自检 |
| 随机与共同误差 | 背景方差、参考源分量及 omitted_terms 已进入 completion | 生产请求固定 master_uncertainty_modelled=false；母版 Jacobian、修复相关、光度参数共同项与交叉项仍未完整求值；upper_bound 的使用须满足真实 PSD 缺项与固定模板前提 |
| 支持与摘要 | 目标叶由中心 sky 的共享 ang2pix 取得，叶号0具显式有效性；摘要使用面积加权 log SNR 中位数 | 当前支持来自捕获邻域 Σmin(D_l,Ω_leaf)，不是一般覆盖并集，也不自动等于整个非重叠 patch 支持。当前查询半径和首次叶归属的采样选择仍影响摘要 |
| 科学模型载荷 | h、Z 和预算内 C 已产生；预算外 writer 使用 local-factor/v2，分别声明源 v、派生 C 与 R 的单位/shape，以及 solver 和假设字段 | PSF 文件仍主要写 h，平面 P 的独立持久化覆盖需核验；covariance support_note 已同步 v2，逐点 PSF 诊断已分开，不能沿用旧 v1/帧极值问题概括。空间顶点与权重当前多在 note 中且精度受格式化限制；精确因子仅对声明对角模型成立，不补全遗漏相关项 |
| 叶阶与单位 | controls 使用实际 leaf order；signal 保存 scale_state；侧车有单位字段 | `p1_op_drizzle` 仍给 signal.leaf_order 赋 k−9，与 controls 的 k 不一致；sidecar 默认 ADU/sr/adu 及 writer 固定 BUNIT 未随 applied 数值单位完整更新 |
| 应用身份 | reader 会拒绝 scale_applied=true 却缺 application_id | 生产 fdoc 只写 scale_applied/status，没有赋 application_id；因此已标度分支不能由 native 单帧记录推断已成功发布 |
| reader | 已恢复 SIP、leaf/order、kind/domain/representation 与状态；另有 `load_local_model_payload`、`reconstruct_factor_covariance` 和 `verify_frame_science_factor_models` 实现 | 通用 `read_frame_science_document` 尚未调用模型 verifier；独立读取仍缺真实模型 hash/重建及 h-C-Z-R、V_F/T/summary 全面核对。重建函数已加入 expected_linear_unit，核对基础线性单位和平方指数；该函数修复不等于通用 reader 已调用它。发布器的 hash 校验不能替代读侧完整验证 |
| 发布 | 发布器逐文件验证 hash、原子写模型及 sidecar、回读并返回结果 | 整帧 signal 与所有模型/sidecar 尚非同一发布事务；回读失败直接返回且未撤回已写 sidecar；writer 将该失败记为 precision 不可用，不能等同合法 unavailable 产品已完整发布 |
| Drizzle frame 生命周期 | `p1_op_drizzle` 在 `hp_drizzle_run_phase1_hips` 返回后调用 `aio_pipeline_frame_destroy(frame)`；`aio_pipeline.cpp` 的 destroy 释放块并 delete frame | 后续 precision staging 的 exposure fallback 在原始 EXPTIME 无效时仍调用 `aio_frame_kv_get(frame,"header","EXPTIME")`，形成释放后访问路径。需在销毁前保存所需元数据或延长明确所有权；本轮仅静态定位，没有执行缺 EXPTIME 构型或修复代码 |

上表列出的数学/模型风险保持源码证据身份。它们不声明已运行新反例，不修改科学定义，不否定合法 signal 的存在；需要科学裁决的具体反例回到唯一 science 正本处理。

## 3. 相邻阶段的消费与统计含义

`module_adapters.cpp::p2_sparse_layer_probe` 仍读取 `ACSD_SPARSE_SNR_LAYER` 指向的规整像素网格。它不是 frame_science.json reader；新增 canonical sidecar 不表示 Mosaic 已经消费该物理对象。当前积分优先 corrected variance，其次已有 ivar，缺失时才走兼容 SNR 链。阶段二切换不属于 Normalize 文档或接口存在所自动授权的行为。

`lib/algorithms/integration/phase2_integrate/src/weight_chain.cpp` 的 SNR 路径使用 (SNR/F_ref)² 一类公式，得到点源通量精度 I_F；若要成为球面面亮度权重还需同条件 T=V_B/V_F。已有 P1 reference-source transfer 也不能直接作为任意 actual-scene 位置的噪声。精度重建、PSF、相关性与模型误差的边界由噪声科学正本规定[6]。

覆盖模块仍以输入最大叶阶的最小值取 target_order，尚不等于独立配置的科学目标分辨率。Mosaic writer 已记录 response_distribution 并可写混合响应；其 `first.empty()` 判首帧的逻辑使先空通带、后已知通带的序列可能仍被标为 same。分布记录有价值，但 `obs_filter` 不能在此边界被当作精确总体通带。

背景控制的统计量和方差与参考点源精度分名；连通分量独立规范不提供断连分量的绝对天空锚。乘性残余、颜色差和 PSF 差不能因接缝减小而被统称为加性天光。本文不依据接口存在宣称背景、曲边或 Export 的独立科学验证已完整。

## 4. 日志、监控与诊断的接线边界

`runtime_client.cpp::exit_code_for_error_domain` 已实现核心错误域映射，失败节点 manifest 的 `error_kind=input/disk_full` 在最终映射前分类。核心 `Error` 直接成员为 domain/message/cause，不是完整 CLI error_report。当前 CLI 源码未找到 `log_artifacts[]` 写出点；Python 结构化日志生成器与 Core logger 存在，不能据此称正式运行的同源双日志和清单登记已完整接入。

Python 监控的 `TraceSnapshotObserver` 只重放构造时事件快照，未按构造 run_id 过滤；active_workers 当前是活动节点数，granted_workers 取快照内正租约最大值。Linux 默认采样 `/proc/self`，Windows Python 后端为 stub。各字段的实际来源和解释见[资源监控合同](../resources/observability/RESOURCE_MONITORING.md)；代理指标和分母分歧保存于[待核对记录](../../../实验/documentation-refactor/docs/SCIENTIFIC_QUESTIONS.md)。这些静态事实未重新运行验证。

开发快照入口 `dev_diagnostics.cpp` 仍持全局 mutex 同步写盘，与低干扰目标存在差异；头文件“不阻塞”注释不代表已实现有界异步队列。`probe.h` 的既有性能输出字段与规范中的拟议完整 perf 格式分别解释，不能凭示例 JSON 认为已有相应 schema。正式 cache/spill 和被动快照不能因名字近似而混为同一依赖。

## 5. 已有证据怎样使用

验证记录[5]中异方差反例的生产 V_F 与解析值均为 2.6470588235294117；所列背景、秩亏、leaf 0、确定性标度与 Monte Carlo 构型给出局部支持。QR、像元积分 PSF 和因子 v2 的后续实现与验证由独立复核[8]记录，不用这些实质修复之前的静态结论描述当前代码。日志包含构建记录；本页未重跑，不能据此宣称全 CLI、所有平台、真实响应、空间模板、发布事务或 OFF/ON 科学等价已独立验证。

独立复核[7]保留实际原始头无 WCS 单帧的 IPV 记录，并明确该帧未施加 photometry。它也保存了可判错的数理反例和当时实现事实。查阅此类证据须按对应源码和构型归因，不将已修正的数学问题继续写成现行实现，也不将局部修复升级为完整阶段一验收。历史研究单元与失败脚本继续保留。

# Normalize 生产链与模块责任

Normalize 将单帧校准观测变为独立 HiPS 信号及可解释的科学模型。科学因果链以阶段一科学正本为准[1]，字段、所有权和发布合同由数据合同规定[2]。本文说明真实调用、目标端口及其实现边界；函数存在、调度连接、已有运行和独立科学支持分别陈述。

## 1. 用户入口与八节点

用户调用经 `lib/infrastructure/cli/commands.cpp::run_phase1_block` 构建 IR，再由 `lib/infrastructure/scheduler/src/module_adapters.cpp::P1NodeModule` 调度实际 `p1_op_*`。八个节点的职责如下。

| 节点 | 实际入口 | 实际数据流与责任 |
|---|---|---|
| calibration | `p1_op_calibrate` | lights/masters → calibrated 积分线性面 |
| cosmetic | `p1_op_cosmetic` | calibrated → cleaned、有效性与修复记录 |
| astrometry | `p1_op_wcs` → `ipv_solve_from_memory_with_callback_d` | calibrated 像元、Gaia、粗指向/尺度 → 逐帧 TAN+SIP 或 unsolved |
| guided sources / PSF | `p1_op_star_psf_impl` | cleaned、已解 WCS → Gaia 引导 science_sources、PSF 参数 |
| photometry | `p1_op_photometry` | 源/PSF 记录、WCS、实际平面与响应拟合 → 标度、photoapplied、photprov |
| noise | `p1_op_noise` | cleaned、sources、photprov → 平面噪声诊断及兼容帧级 SNR |
| Drizzle / sphere completion | `p1_op_drizzle` → `hp_drizzle_run_phase1_hips`；`stage_frame_precision` → `complete_spherical_reference` | 逐帧应用面与 WCS → HiPS；捕获同次交叠 → 局部球面参考模型及 sidecar staging |
| writer | `p1_op_writer` → `publish_staged_frame_science` | 检查 HiPS、发布模型与 frame_science.json、登记逐帧产品状态 |

IPV 内部自行盲检 `solver_detections`，不消费解算后的 science_sources。科学源表在 WCS 已解后使用完整投影；两种候选不能互作替代。原始 FITS 不含 CRVAL/CD 只说明输入头部属性，不能推出 IPV 无法解算。`explicit_config` 与 `ipv` 必须保留不同来源。

`lib/phase1_session/p1_session.cpp::run_session` 只实现读取、校准、坏点和校验写出，并将其余科学域标为 unavailable。它是局部会话/兼容 facade，不是另一条完整 Normalize 生产链。

## 2. 因果依赖与现行载体

```mermaid
flowchart LR
    C[calibrated] --> W[IPV WCS]
    C --> K[cleaned]
    W --> S[science_sources / PSF]
    K --> S
    S --> P[photometry / applied plane]
    W --> P
    P --> N[planar noise / reference model]
    P --> D[Drizzle]
    W --> D
    S --> D
    N --> D
    D --> R[noise 库 sphere completion]
    D --> O[writer]
    R --> O
```

图中是合同要求的科学依赖；sphere completion 在 Drizzle 节点内调用 noise 库，不增加调度环。当前 `p1_*_descriptor` 已声明 WCS→sources/photometry/Drizzle、photprov→noise/Drizzle、sources/SNR→Drizzle 等排序边。但跨节点取数仍读取工作区 `p1_wcs.json`、`p1_sources.json`、`p1_phot.json`、`p1_snr.json`、平面 FITS 和逐帧 `p1_stack.json`。声明 typed port 并不等于这些边已承载 Runtime 类型对象。

光度实际读取 sources 所指的 cleaned 面，descriptor 仍声明 calibrated；光度施加与 Drizzle 选面还须按逐帧 provenance 核对。noise descriptor 的 `fluxes` 仅用于合成 IR，生产 noise 没有对应读取点。独立 `psf` 输出尚无完整显式消费者；部分参数随 sources 工作文件传递。球面 precision 经 Drizzle 局部向量与 staging 传给 writer，descriptor 与实际 CLI IR 已补 frame_science 输出/输入边；载体仍是 output_dir 工作文件，不等于 Runtime 已传输完整 typed 模型或完成消费者 lease。

目标是 Runtime 管理、发布后只读的有名对象；路径仅用于 AIO spill、正式缓存或产品定位。对象键绑定 run、输入 occurrence、对象类型、revision 与输入版本。`BlockFrame`/`RunContext` 的数值块和 artifact 服务可复用，但当前没有完整的 metadata/model typed 对象仓和消费者 lease。具体接口及逐边迁移由实现规格承载[3]。

## 3. 算法所有权与完成边界

| 对象或计算 | 所有者 | 生产与消费边界 |
|---|---|---|
| `AstrometrySolution` | IPV 与 WCS adapter | 校准像元求解；下游只消费本帧解及 SIP，不重新求天测 |
| `ScienceSourceCatalogue` / `EffectivePsfModel` | detection / PSF | 完整 WCS 引导测量；photometry、noise、Drizzle 使用相同模型身份 |
| `PhotometricSolution` / `PhotoAppliedPlane` | photometry | 逐帧响应、标度、实际应用身份；随机协方差按二次幂变换 |
| `ConditionalNoiseModel` / planar reference | noise | 应用后平面的条件噪声；原生 gain 与数组单位分开 |
| `DrizzleObservation` | Drizzle | 实际 WCS、面积、算子 R、支持与 AIO staging；不另造近似几何供 precision |
| `SparseReferencePrecision` / frame summary | noise 的 sphere completion | 用同次 R 形成 h、C、Z，计算局部 V_F、SNR 和条件 transfer |
| `FrameScientificProduct` | writer / 统一 AIO | 唯一正式 sidecar、模型引用、哈希、信号与运行清单 |

`lib/include/acsd/normalize_data.h` 已声明参考、状态、控制点和摘要等类型；`lib/algorithms/noise_snr/include/acsd/sparse_reference.h` 与其实现已有球面 GLS；`lib/algorithms/integration/normalize_science/` 已有 serializer、reader 和发布函数。不能继续将这些接口统称为未实现，也不能由它们的存在推断完整数据合同已满足。

当前 canonical 可执行参考路径为 `explicit_linear_flux`。`parse_reference_config` 对 `sed_response` 明确记录响应积分未接线；逐帧 response/SED 与 Runtime 完整迁移仍受实现限制。PSF 已从逐帧 psf_params 构建空间三角模型，逐控制点求积；无三角支持时仍回退具名帧常宽度。空间 alpha 已按窗口求值，支持空洞、回退状态和总通量配对的合同覆盖仍需核对。实际限制及可追踪符号集中在差异地图[4]，不在本页复制待办台账。

## 4. 产品发布与能力状态

每个合法 signal 是独立帧产品；precision 的 availability 为 available/unavailable，available 对象另记 accuracy=conditional_complete|approximate|upper_bound；各字段由数据合同规定，不能把未建模误差当零。缺 WCS 不发布伪球面图；缺参考或 PSF 只限制相关精度能力。运行清单应枚举所有输入 occurrence 和逐帧原因，保留可用帧且准确报告集合完整性。

现行 Drizzle 已直接写 HiPS；precision 模型与 sidecar 先写工作区 staging，writer 再调用统一发布函数。该实现具有模型文件哈希核对、sidecar 原子写及回读，但不等于“signal、全部模型、sidecar、完成 manifest”已形成一个完整事务。正式目标仍是 writer 在所有 AIO 完成后统一发布；发布失败、损坏输入和合法 unavailable 必须分开。[2]

阶段一可有必要的 support/variance/ivar 辅助数据；阶段二最终只发布 signal，阶段三只导出信号 FITS。这不要求阶段一删除物理模型或制造第二份 canonical 精度真源。

科学 spill/缓存属于正式数据流，不能由开发开关关闭；snapshot/perf 是只读旁路。根 CMake 已将相关探针子项由 `ACSD_DEV_MODE` 派生，不能再据保留的兼容 option 名称认定其能独立激活。运行等价和误差仍须依实际证据判断。

## 5. 证据的解释范围

已有验证日志直接调用生产 GLS 源，覆盖异方差、背景 nuisance、秩亏、非平凡标度和 Monte Carlo，支持所给合成条件下的局部数学行为[5]。它没有运行当前全部 CLI、真实逐帧响应、空间 PSF、独立模型 reader 和完整发布事务。已有原始头无 WCS 的单帧 IPV 记录证明该次尝试发生且产出解；拟合内点残差不等于独立留出误差，也不代表全部输入成功率。文档、静态接线、已有运行和独立支持的区别由收敛说明维护[6]。

## 数值与模型载体的模块责任

条件协方差允许用 CSR(R) 与源像元方差 v 的精确因子表示 C=R diag(v)Rᵀ，不要求每控制点默认写稠密矩阵。该精确性限于已声明的平面独立条件模型；共享母版、标度和修复相关项仍需独立表达。`local-factor/v2` 分别保存源方差与派生球面协方差的 shape、线性单位和 sr 幂次，reader 验证真实载荷；字段由数据合同拥有[2]，接口由实现规格细化[3]。

像元积分 PSF 由 `lib/algorithms/psf` 提供；适配器传位置、参数和像元足迹，不能另存未归一中心轮廓。噪声库从同一 R、P、v 和背景模型计算可辨识的通量分量。数值求解可以使用可靠 QR/SVD 或等价子空间实现，不能为了加速静默截断选定叶的真实随机贡献。逐点模型与帧摘要分别记录，科学状态不由求解器成功标志代替。

生产已具备逐输入响应绑定、QR 投影、像元积分 PSF 和因子 v2 的实现路径；当前真实覆盖与剩余差异统一见[实施地图](SCIENCE_IMPLEMENTATION_DELTA.md)。typed Runtime、参考 SED 积分、空间模型的支持/误差状态、applied 空间 alpha 的真实运行和共同误差分别核对，不从局部数值修复推断八节点整体闭合。独立审查与运行记录保留在收敛文档[6]及其引用的实验单元，不在架构正文复制历史耗时和 SNR。

# Normalize 接口与迁移实现规格

本页从 [数据合同](../../engineering/contracts/NORMALIZE_DATA.md) 推导 C++ 修改边界；科学定义来自 [Normalize 科学正本](../../science/normalize/NORMALIZE_SCIENCE.md)。本页区分已经存在的调用接口与 Runtime 迁移目标[1,2]。目标签名不是已导出的 ABI；内部容器可按工程需要实现，字段语义、算法所有权和生产—消费边保持合同定义。实际实现限制集中在[科学实施差异地图](../../engineering/architecture/SCIENCE_IMPLEMENTATION_DELTA.md)。

## 1. 放进现有模块的类型和接口

| 接口/类型 | 声明与实现落点 | 修改责任 |
|---|---|---|
| 帧对象仓、ObjectHeader、runtime payload binding | `lib/include/acsd/core/context.h`、`block_frame.h` 及其现有实现 | Runtime 持有 typed payload；数值块不变成 metadata 字节猜解器 |
| FrameIdentity、PlaneView、节点 typed bundle | `lib/include/acsd/core/module_adapters.h`；与算法库对接 | host adapter，仅用于运行绑定 |
| WCS 对象/转换 adapter | `lib/algorithms/platesolve/cpp/ipv` 的现有 public headers；`module_adapters.cpp` 的 WCS/SIP adapter | IPV 求解只复用一份；规范化原点并保留全部 SIP |
| PSF position evaluator | `lib/algorithms/psf/include/dynamic_psf.h` 及其实现 | 单星参数→空间模型/积分响应；不复制 Gaussian/Moffat 数学到 scheduler |
| response、reference、photometric solution | `lib/algorithms/photometry` 现有 public headers/实现 | 每帧 R_k 绑定；共享 cache 以真实曲线/QE/积分 convention 指纹为键 |
| noise/ref precision、GLS completion | `lib/algorithms/noise_snr/include/acsd/sparse_reference.h`、`cpp/src/sparse_reference.cpp`；兼容帧摘要仍在 `wrapper_phase1/snr_frame_science.h/.cpp` | canonical 数学只在 noise 库；兼容聚合接口不冒充球面控制点 |
| spherical operator/model view | `lib/algorithms/drizzle/healpix_drizzle/hp_drizzle_api.h`、引擎/已有 sphere sink | 同一次几何的信号/PSF/噪声系数；C ABI 只经版本化 POD/handle |
| sidecar 读写、manifest/model refs | `lib/algorithms/integration/normalize_science/include/acsd/normalize_science.h` 与 `src/normalize_science.cpp`；复用统一 AIO 原子/哈希原语 | 一个 JSON serializer/reader；writer 决定发布时机，AIO 拥有文件边界 |

优先编辑现有文件；确需新编译单元时同步 source-set/build 清单，不能以源码列表维护困难为由把科学代码一直堆在 scheduler。所有 `p1_op_*` 最终只负责 config→typed inputs、调用模块、注册 outputs、错误/生命周期；算法库不读取块级 output_dir 来找上游。

## 2. 已有调用与目标接口

| `complete_spherical_reference(windows, cfg)` | `vector<PlanarPatchWindow>`、`SphericalCompletionConfig` → `SphericalCompletionResult` | noise 库同步计算；windows 与 controls 同序；不可辨识由具名状态表达 |
| `stage_frame_precision(req, windows, doc_template, frame_key, var_plane, model_payloads)` | 返回 `StagedPrecision`，包含 document、状态与模型载荷 | scheduler adapter 组织请求并调 noise；大面不是 Runtime 长期 typed 副本 |

### 2.1 Runtime 目标接口形状

```cpp
// 位于 host C++ 内部，Result 与错误域复用 acsd::core。
struct ObjectHeader {
  std::string run_id, frame_id, producer;
  uint32_t schema_version;
  uint64_t revision;
  std::map<std::string, uint64_t> input_revisions;
};
template<class T> struct FrameObject {
  ObjectHeader header;
  T value;
};

// Runtime 仓：发布后 const；显式完成 consumer 后释放。
template<class T>
Result<void> publish_frame_object(RunContext&, FrameObject<T>&&);
template<class T>
Result<std::shared_ptr<const FrameObject<T>>> acquire_frame_object(
    RunContext&, const std::string& frame_id, uint64_t revision);
Result<void> finish_frame_consumer(
    RunContext&, const std::string& frame_id,
    const std::string& object_id, const std::string& consumer_id);

// scientific views 引用 Runtime/AIO 拥有的数组/模型，不持久复制大面。
Result<ConditionalNoiseModel> build_conditional_noise(
    const PlaneView&, const CalibrationUncertaintyView&,
    const PsfView&, const PhotometricSolution&, const NoiseConfig&);
Result<PlanarReferenceModel> evaluate_planar_reference(
    const ConditionalNoiseModel&, const PsfView&,
    const ReferenceDefinition&, const SamplingConfig&);
Result<SparseReferencePrecision> complete_spherical_reference(
    const PlanarReferenceModel&, const DrizzleObservationView&);
Result<DrizzleObservation> drizzle_frame(
    const PlaneView&, const AstrometrySolution&,
    const PsfView&, const ConditionalNoiseModel&, const DrizzleConfig&);
Result<FrameScientificProduct> publish_frame_product(
    const FrameProductInputs&, AioPublishContext&);
```

`T` 对应数据合同中的有名对象；实现不得用调用方任意字符串替代类型检查。`Result` 的 fail 表示损坏/执行失败；precision 无法辨识是成功返回内带 unavailable/reason 的结果，不由抛异常或空向量暗示。所有视图寿命覆盖同步调用；异步任务持有 Runtime 显式 lease。模板接口可作为现有类成员实现，不能另建全局静态 map。

## 3. 关键对象数值字段

```cpp
struct ReferenceControl {
  std::string control_id, support_id, psf_model_id, covariance_model_id;
  double ra_deg, dec_deg;                 // ICRS
  double source_x0, source_y0;             // detector 0-based centers
  uint64_t leaf_ipix;                     // NESTED at declared leaf_order
  std::optional<double> reference_flux;   // integral unit of reference
  std::optional<double> flux_variance;    // same integral unit squared
  std::optional<double> reference_snr;    // F/sqrt(V_F), not legacy proxy
  PrecisionStatus status;                 // availability/accuracy/omitted terms
  SurfaceTransfer transfer;              // value+unit+condition or reason
};
```

其它逐字段类型按数据合同和 sidecar schema 一一映射；枚举取 schema 的 tokens，单一 serializer 负责映射。`leaf_ipix` 在 JSON 中为十进制字符串，避免读取者用 IEEE double 丢掉 64-bit 索引；leaf order 单独存整数。控制点计算保留 FP64；导出 Catalogue 浏览可降精度但不得逆写 canonical 文件。

PSF 模型必须区分 `flux_estimator=analytic_total|aperture_with_correction|diagnostic`，窗口截断和模型积分一致。检测块 Gaussian 宽度不能直接作为 Moffat 参数。PSF 残差尺度不能冒充背景噪声，FWHM 不能替代模板 h。空间模型基线采用有效样本的局部模型求值，支持外标 limited；没有证据不能默许全帧常 PSF。

## 4. 配置与一次标度应用

在已有 normalize 配置的 `snr` 下扩展 `reference`：

```json
{"reference":{"kind":"explicit_linear_flux","reference_id":"user:ref-star",
              "flux":1000.0,"flux_unit":"adu","normalization":"photo_applied"}}
```

`sed_response` 改为具名 `sed_id`、SED 文件/hash、归一/单位或参考星等及 `response_id`，响应积分规则由 photometry 显式给出；读取配置后成为 ReferenceDefinition，不全链传 JSON。逐帧响应 override 在 block 的 `frame_overrides` 以输入 occurrence 绑定，字段包含 response/masters/gain；不靠 basename 或滤镜字符串推测曲线。override 未提供时继承 block，头部冲突如实记录并按明确配置优先级解析。真实未知曲线记 unknown，不自动拿同名滤镜库代替。

这是目标对象与配置绑定。当前 CLI 的适配层读取嵌套 `photometry.frame_overrides[]`，以路径、basename 或 frame_key 首次匹配；它不能替代上述严格 occurrence 身份。用户配置的实际消费范围见[配置合同](../../engineering/contracts/CONFIG.md)，迁移差异见[实现差异地图](../../engineering/architecture/SCIENCE_IMPLEMENTATION_DELTA.md)。

现有 `snr.reference_flux_adu` 仅映射 `legacy_explicit_flux` 诊断；用户明确给新 reference ID/归一后才能进入 canonical。现有 `reference_magnitude` 若没有参考通带/SED/零点合同，同样不能自动升级。缺 reference 输出 unavailable，不阻断合法 signal。缺响应时可保留 native-calibrated signal 或显式相对锚标度；状态为 native/relative，不制造 scale=1 且已绝对测光的假成功。

photometry 优先消费 `CleanedPlane`，保证检测、PSF、flux 和输入像素有效性一致；原校准面保留给 IPV。光度节点输出 `PhotoAppliedPlane` 与 application ID。已 applied 的对象不能再次应用同一 scale；noise 输入若需要原生 Poisson，只能按原生 gain+原生期望建模后通过 D_alpha 变换，不能把 photo-scaled 数值直接除以原生 gain。

## 5. 逐边迁移与代码清理

| 现有载荷/实现 | 确定迁移方向 | 保留范围 |
|---|---|---|
| `p1_wcs.json` | WCS typed object；work cache 显式注册 | explicit_config 适配、debug 旁路、版本化 resume |
| `p1_sources.json`、`p1_psf.json` | source/PSF typed 对象，photometry 明确接 psf | 有效星表记录与模型实现 |
| `p1_phot.json`、photoapplied FITS | typed solution+plane；必要科学 spill 经 AIO | 老文件读取 adapter、未迁边暂存 |
| `p1_snr.json` | legacy diagnostics 与新 planar model 分名，sphere completion 产 canonical | 旧 frame 数值来源可查 |
| `p1_stack.json`、Drizzle 内写 HiPS | DrizzleObservation/AIO staging handle→writer | 大面流式写，不复制整幅球面 |
| `HioSnrControlPoint` / SNR Catalogue | 保留 proxy 类别；可选浏览投影使用新值+明确元数据 | 不修改旧 ABI 结构意义、不伪造转换 |
| `p1_session.cpp` | calibration/cosmetic 局部会话或兼容 facade | 有效局部能力；CLI 只经 P1NodeModule 全链 |

每一边同时修改 descriptor、typed IR builder、`module_ports.registry.json`、artifact-to-port bridge、生命周期与实际取数；注册表标明 `runtime_payload` 或正式 cache carrier，不能写不存在的科学生产者。删除仅供合成 IR 的虚构 flux 输入边，或让其真的承载相同对象；生产事实和测试图不可各有一套定义。

转换只在一个 adapter 完成；禁止双写两份都当权威、typed 不存在时静默读取旧 run 的文件、DEV_MODE 改科学载体。撤掉阶段一组内 passband 全等拒绝时，同时建立每帧 response binding，不能只删检查。共享母版的误差引用以真实 master hash 合并，未知项记 unmodelled，不默认为独立零误差。

## 6. 实施范围与验证含义

执行 Agent 可据本页完成阶段一结构、接口、科学模型和 writer 的实施，无需再选择参考定义或载体。各项验证针对对应行为：原点/SIP 的独立读写、scale 一次与 covariance 二次幂、参考 GLS 的有效协方差、秩亏/不可辨识、sidecar round-trip 和负例、缺模型但合法信号、OFF/ON 取数等价。它们是代码及模型的检验意图，不规定服务器运行批次、数据目录或新的审批门。

当前生产入口、目标端口及证据边界见 [NORMALIZE_PIPELINE](../../engineering/architecture/NORMALIZE_PIPELINE.md) 与 [NORMALIZE_CONVERGENCE](../../engineering/governance/NORMALIZE_CONVERGENCE.md)；代码变化与实测支持分别报告，尚无独立支持的部分保持未验证身份。Mosaic 本轮只兼容读取新产品/能力状态，不改默认权重、背景拟合或 Export 算法。独立数学反例由前台修正科学正本，不由执行者新立一套科学方案。

## 7. 完成实现时的数据边界

### 7.1 Runtime 对象与缓存

对象键为 `(run_id, input_occurrence, object_kind, revision)`；frame_id 由冻结输入清单中的 occurrence 绑定，不由 basename 或源 hash 单独充当。RunContext 拥有每帧 BlockFrame 或同生命周期的 typed payload 容器；容器以类型检查过的 owned immutable object/模型 lease 保存元数据和大面视图。publish 校验唯一 producer 与上游 revisions，acquire 校验实际类型/帧/run/revision，consumer 完成、异常及取消均归还 lease。实现不需另建全局 map，也不要求把 STL 放入 C ABI。

八个现有调度节点可以保持 execute 调用方式；一次节点处理多帧时，对每个 occurrence 发布/获取独立对象。科学数组由 Runtime 预算管理，必要 spill 用带键与 hash 的 AIO cache 句柄；Drizzle 大 tile 可以直接流式进入私有 staging。普通内存充足执行不能为取得上游元数据而写读 p1_*.json；这些文件仅保留具名诊断或显式恢复兼容用途。缓存重算失效须跟随 upstream revision，不能按 mtime 或文件碰巧存在判断。

### 7.2 每帧响应与参考 SED

frame_overrides 在 ingest 时按 input occurrence 一次解析，形成该帧的 masters、gain、response/QE 绑定；优先级为显式逐帧配置、block 继承、允许的真实元数据推导，来源逐项保留。滤镜头名称只是观测记录，不能替代曲线。响应 identity 包含曲线字节 hash、波长/响应单位、光子/能量积分约定与实际 QE 组合。相同 identity 可共享计算缓存，不能拿第一帧的 filter/QE 给不同 identity 的帧用。

sed_response 的基础可执行输入是带 sed_id/hash/波长单位/f_lambda 单位的已归一参考谱，以及本帧响应与拟合系数。复用 photometry 的同一响应积分公开 API 得到 Q_k,ref；在科学分册的 `f_obs=a_k m_k Q_k` 约定下，F_native(u)=a_k m_k(u) Q_k,ref，再按实际像元标度求 F_applied(u)。代码中若存逆系数，须由一个显式 adapter 转换。参考谱已具有绝对归一时不再额外要求任意星等零点；若输入选择星等归一，则须有具名通带、星等系统及其零点/参考谱的可执行定义。缺这些输入的 unavailable 是数据能力状态；有完整输入仍返回 not_wired 则是实现未完成。

逐位置参考通量和模板的标度变换使用 NORMALIZE_DATA §5 的 a_ref、P' 配对，不用中心 alpha 冒充全窗空间变换。显式积分通量参考仍是合法独立路径，不能被用于绕开已配置的 sed_response。

### 7.3 噪声与共同误差

ConditionalNoiseModel 分别承载背景/读噪/暗流、冻结参考源 Poisson、校准/修复算子和共享参数的模型或具名缺项。输入已含哪些分量必须可查询，不能在 completion 重复加源泊松。校准算法对已有母版不确定度输入提供 Jacobian 传播及共享 master hash；仅有母版均值而无原始样本/误差模型时，不从一个文件杜撰母版方差。光度拟合参数协方差及与测量共享数据的交叉项同理，未知交叉项不能默认为0或被称完整。

缺实测噪声输入允许单帧 approximate，但对应模型接口、已知输入的求值与持久化路径须实现并由合成真值检验。基础 diagonal 模型、低秩共同项和需要局部显式协方差的情形需明确 representation，不把所有噪声强塞进一个 variance 数组。PSF 模型失配、母版未知、标度共同误差、几何近似和截断分别反映在状态/来源中；仅缺已知 PSD 随机分量且符合科学分册的前提时才允许 upper_bound。

### 7.4 局部球面模型与独立读取

正式工程载体依[Normalize 数据合同](../../engineering/contracts/NORMALIZE_DATA.md)。优先使用模型精确因子：source pixel index（长度 m）、球面叶索引（长度 nl）、CSR(R) [nl,m]、source diagonal variance v_j（长度 m）、实际 h=RP、背景基 Z_s、量纲/响应与 PSF/支持域模型，声明 C_ref=R diag(v)Rᵀ。只有平面条件噪声确实为 diagonal 时它才是模型内部精确表示；未建模 master/scale 等误差仍记 omitted。

小控制窗可保存显式 C_ref [nl,nl] 对照；因子 values=[v_j] 的 [m,1] 不表示派生 C 的 shape。`local-factor/v2` 分开保存源方差单位、算子单位和派生 C 单位，也分开逻辑矩阵与因子 shape。基础线性单位与 sr 幂次均需一致。v1 只经明确来源和语义的兼容适配使用，不能仅改单位标签升级。

每控制点记录真实 leaf_order=log2(nside)，不是 tile order；目标 leaf=0 合法，必须有 `has_target_leaf`。CSR R 的每个非零值 \(R_{lj}=(a_{lj}/A_{\rm drop,j})/N_l\)，N_l 是同次正式 Drizzle 产出的**完整**叶归一分母；debug 或 patch 截断算子不得冒称相同 R。PSF P 和 F_ref 的 flux_estimator/单位配对，h=RP 在 sphere leaf 域的单位为 sr^-1。Z 按 [nl,n_bg] 定义，background nuisance 的估计值与单位与模型不可脱钩。

读者除 schema/hash/shape/索引与版本核对外，还必须重算或可复核：P 的总通量口径、h=RP、C factor 与派生单位、V_F、SNR=F_ref/√V_F、T=V_B/V_F、support/leaf 位置、scale once、含 SIP 的 WCS、frame-summary 去重。这些是科学语义而非仅“JSON 能解码”。损坏 refs/null 未经辨识的字段均不得以 availability=available 吞错。

### 7.4A 秩亏球面信息求解器

科学证明由[噪声分册](../../science/noise_snr/NOISE_SNR.md)拥有。用同次实际 R 和 D=diag(v)，Q=R D^1/2、W=D^-1/2 [P,Z]，取可靠分解得到 Q 的行空间正交基 V_r 或零空间正交基 N；参数信息矩阵为

\[
 M=W^\mathsf{T}V_rV_r^\mathsf{T}W
 =W^\mathsf{T}W-(N^\mathsf{T}W)^\mathsf{T}(N^\mathsf{T}W).
\]

R 满列秩时等价于 A_srcᵀD^-1A_src；小零空间允许低维修正，但求 N 本身仍需可靠分解。nuisance Z 有冗余但 F 可辨识时，使用通量分量正交于背景列空间的有效信息 I_F 解 V_F，不能因整个参数矩阵不可逆就拒绝通量。

使用经过独立检验的 QR/SVD 或等价子空间实现，记录正交性、残差、数值秩和阈值来源。当前常规生产采用列主元 Householder QR，大工作集仍有 Jacobi 分支；两者的有效域与科学截断分别检验。数值加速不允许静默裁掉所选叶的真实随机贡献；改选观测域时明确改变后的估计量和近似误差。实现与日志见[差异地图](../../engineering/architecture/SCIENCE_IMPLEMENTATION_DELTA.md)。

### 7.4B 像元积分 PSF 的固定实现边界

默认通量口径 `flux_estimator=analytic_total`。依据[PSF 分册](../../science/psf/PSF.md)的单位总通量连续 Moffat4，对实际像元面积和子像元相位求积。部分 footprint 的 \(f_{\rm enc}=\sum P_j\) 不重新归一，f_out 从实际像元集合求，不以理想圆半径代替实际边界；超1不以 clamp 掩盖。复用 PSF 库的有效模型，scheduler 不另实现无单位中心模板。

生产已调用 `pixel_integrated_moffat4_profile`，并通过 PSF 库 `build_spatial_model` / `spatial_pixel_response` 在控制点混合顶点积分响应；无空间定位时的帧常宽度仍是近似。空间 alpha 由 `PrecisionFrameRequest::pixel_alpha_at` 逐窗填入 `PlanarPatchWindow::pixel_alpha`，不是整帧常量字段。参考通量、Poisson、截断窗口与实际应用模板仍须配对。每控制点保存自身包络、参数、相位和积分误差，帧级极值只作摘要。当前逐点求积诊断已经分离；空间模型的全部顶点参数、有效支持和可独立重算精度仍须验证，不能只凭 note 中三角ID/低位权重推断持久化完整。缺空间支持或响应失败按自身状态报告，不以每窗重新归一挽救。单点求积正确不等于完整跨设备参考精度已验证。

### 7.5 发布事务

writer 在私有 staging 内等待所有 AIO 完成，先验证 signal、sidecar、模型与 manifest 的同帧同版本关系，再统一发布并最后标记完成；中途失败/取消不可留下可被普通 reader 当作完整产品的新 sidecar。运行清单反映全部 occurrence，包括 failed/cancelled/precision unavailable。旧 HiPS 的显式读取兼容保留，旧损坏产品不在本机静默修成新 canonical。
