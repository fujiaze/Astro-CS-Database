# 测试标准与测试矩阵

上游：最高设计的验证体系一章（科学正确性与三重佐证、验证层级与四层验收），以及模块与 ABI 一章。

## 1 定位

测试集是**独立于产品代码的一套代码集**，目标是主动暴露缺陷、检验科学口径，不与产品代码混放[6]。
测试面随模块在位：共址测试放在实现模块自己的测试面内，与实现同处一个模块目录；验证数据与
验证脚本放在 `eng/tests/`。每个独立可调度模块的测试面清单由该模块的二级细节文档登记。

测试集可以接入持续集成，但**以非阻塞为常态**。重构期间测试随代码同步更新，保持测试集本身干净；
接入持续集成时报告红项而不裁决合入，**只有科学口径错误这类关键问题才作为阻塞项**。测试不是
约束代码的门，它是暴露代码问题的工具。

本文规定：覆盖判据（第二节）、确定性与容差规则（第三节）、通用容差规则与 NaN/Inf 语义的冻结取值（第四节）、
命名与跳过（第五节）、覆盖率分母（第六节）、长期回归集合（第七节）、变更纪律与受影响范围
（第八节）、执行范围与分档（第九节）、失败处置（第十节）、科学条款到用例的映射（第十一节）、
变更类型与验证范围（第十二节）、测试侧独立 Oracle 的归属面（第十三节）。

**正本地位**：第 4 节是**通用浮点容差**（数值、可满足性下限）与**NaN/Inf 语义**（非有限值与缺失的位置与语义）
的唯一正本。其它文档与合同（调度合同、配置合同、架构数据流、各模块科学页）一律回引本节，不复述数值。

## 2 覆盖判据

- 每条科学契约至少配一个用例或 Oracle，三选一：性质检验、解析或高精度参考、定种子蒙特卡洛。
- 每个度量具备非退化判据：真值无效应时度量必须归零或报警。恒真的比较没有证据资格。
- 用例只经公共生产接口进入；实现面只有生产一份。
- 三类实验数据（仿真成像、解析代数合成、真实数据）各有独立用例面，不以某一类数据代表全部
 科学正确性。
- 科学 Oracle 与科学不变量两类判据必须有可复算的实验证据（复现命令、实测读数、产物路径），
 证据齐备才认作通过；判据必须能红，注入缺陷时读数不随之变红即判该判据失效。

## 3 确定性

- 固定种子；同一输入重复运行逐字节同结果。
- 浮点断言用容差加容差来源说明；容差在写用例前冻结，取值见第 4 节。
- 非有限值与缺失的位置与语义与产品逐项精确一致。
- 并行度不改变科学产品：1 worker 与 N worker 在冻结容差内等价。

## 4 通用容差规则（事前冻结，阈值只按事前冻结值取用）

本节是**通用浮点容差**（数值与可满足性下限）与 **NaN/Inf 语义**（非有限值与缺失的位置与语义）的唯一正本。其它文档与合同（调度合同、配置合同、架构数据流、各模块科学页）一律回引本节，不复述数值。

| 量类 | 取值 |
|---|---|
| 元数据、掩膜、计数、索引、端口、选择结果 | 精确一致 |
| 双精度非归约 | `rtol = 1e-12`，`atol = 1e-13 × scale` |
| 单精度产品非归约 | `rtol = 5e-6`，`atol = 1e-6 × scale` |
| 归约 | `γ_n = n·u/(1−n·u)`，门限 `C·γ_n·Σ|terms| + atol`，`C ≤ 4` 事前冻结 |
| 并行等价（1/N worker、基线与变体） | 上述三档容差等价，不是逐位一致；整数、掩膜、索引、计数、端口精确一致 |

### 4.1 归约误差模型中的 `u`（单位舍入）

`u` = **unit roundoff**，最近邻舍入的相对上界，按被比较量的 dtype 取值[3]：

| dtype | `u` | 表达式 | 数值 |
|---|---|---|---|
| IEEE 754 binary64 | `2⁻⁵³` | 1 + 2⁻⁵²，`2⁻⁵³ ≤ (1+δ)/1 − 1 < 2⁻⁵²` | `1.1102230246251565e-16` |
| IEEE 754 binary32 | `2⁻²⁴` | 1 + 2⁻²³，`2⁻²⁴ ≤ (1+δ)/1 − 1 < 2⁻²³` | `5.9604644775390625e-08` |

- `γ_n` 取的是**同一 dtype** 的 `u`：f64 路径的归约用 `2⁻⁵³`，f32 路径用 `2⁻²⁴`。混用（f64 数据按 f32 的 `u` 判）把门限放宽约 `2²⁹` 倍，属判据失效；
- `n` 取该次归约的**实际项数**，不是数据总像素数；
- **浮点舍入的通用背景**（`u` 的定义、最近邻舍入、以及「`x·(1+δ)` 型误差随 `n` 次运算线性增长」的论证）见[2]；
- `C ≤ 4` 是前向误差放大预算的项目冻结值，既不是 `u` 也不是 `γ_n` 的函数；
- **归约误差模型来源**：高阶精度算法手册[1]给出 `γ_n` 增长因子模型；`C ≤ 4` 的取值由前向误差放大预算决定，属项目冻结值而非文献值。

### 4.2 并行归约

确定性用固定分块或树合并；否则按可复现但落在界内文档化。

### 4.3 绝对容差的可满足性下限

任何绝对容差只有在被比较量的量级 `scale` 满足 `atol ≥ 1 ulp(scale)` 时才可判。模块冻结绝对容差时必须同时声明适用量级域，超出该域按同值的相对形式判，只放宽不收紧；低于 1 ulp 的绝对容差不可满足。

### 4.4 NaN 与 Inf 语义

本节是**非有限值与缺失**的位置与语义的唯一正本，适用范围是全部比较面：

- **位置**：非有限值与缺失的**位置集合**必须与产品逐项精确一致。比较面必须同时覆盖有限与非有限像素，只比有限子集的比较不算通过；
- **语义**：非有限值按 IEEE 754 语义解释（`NaN` 无序，`±Inf` 参与比较、进入运算后可产生 `NaN`）。「缺失」是与非有限值**并列的第三态**，在产品面上必须有区别于 `NaN` 的表示，不得由 `NaN` 兼表；
- **传播**：比较器不得把非有限值折叠成 `0` 或任何哨兵值后再参与有限比较；
- **与容差档的关系**：非有限值与缺失**不受**上表三档浮点容差约束。它们要么位置精确一致、要么判错，不存在「落在容差内通过」的中间态。

容差调整单独提交，附失败分布与推导。

## 5 命名与跳过

- GoogleTest 命名取 `Suite.Feature` 形式。
- 硬件能力不可用时用 `GTEST_SKIP`，不以伪通过掩盖未执行。
- 负例必须可红：正确实现给绿，注入缺陷给红。

## 6 覆盖率

覆盖率分母明确：发布单元与测试单元各自独立计数，不合并成一个数字。

## 7 长期回归集合

判据骨架固定，实测数值与逐档读数归实验单元。

| 回归项 | 判据 |
|---|---|
| HiPS 序列化 | 与外部实现（`hipsgen`）对拍，逐成员一致 |
| 阶段间产品交换 | `normalize` 输出（signal、support、覆盖、稀疏信噪比、质量、帧标识、manifest）被 `mosaic` 与外部标准一致读取 |
| 信号面权重 | 并行度改变时权重归一结果在冻结容差内等价 |
| 原子发布 | 注入磁盘写满或写失败时无完成标记，产物可恢复 |
| 路径与词法 | 路径穿越、符号链接、非法文件名一律判红 |

## 8 变更纪律

变更模块必须重跑该模块的相关验证。引用未变更模块的既有产物时，必须以构建指纹（内容散列）
证明同源，否则重跑。受影响验证范围由改动集算出，只扩大不缩小。

## 9 执行范围、改动集与分档

执行者是人：结论由人读对抗审核给出，每条结论都附可复算的证据。测试集不产出流水线判决。

### 9.1 三种执行范围

| 范围 | 触发 | 含义 |
|---|---|---|
| 增量 | 默认 | 影响面增量：只跑与本轮改动集相交的判据 |
| 全量 | 必须显式 | 判据集合整档全量，不做任何按改动的裁剪 |
| 点名 | 显式点名 | 点名判据，不受档位与改动面过滤 |

增量是默认，全量是显式动作；全量用于发布前、跨域大改与任何拿不准的场合。档位限定候选集，
全量加指定档位才是该档整档全量。结果必须携带范围、改动文件、是否升级为全量、未覆盖路径、
是否无改动五项。

### 9.2 改动集

改动集是下列两者的并集，路径统一为仓库相对 POSIX 路径：

1. `git diff --name-only <base>`（已提交但不在基线内的改动）；
2. `git status --porcelain=v1 --untracked-files=all`（工作树未提交改动，含未跟踪文件）。

基线引用默认 `HEAD`。基线引用不存在、仓库不可用或路径无法解析时复核失败，不得据此给出任何
通过结论。**空改动集不产生任何通过结论**：必须显式写明无改动并就此结束；「没选中要跑的东西」
记成通过是假绿。

### 9.3 选择规则

- 候选是本轮档位内适用的判据，逐条来自本标准与各合同的判据条款；
- 选中是候选与「判据的输入面路径模式与改动集中某路径匹配」的交集；
- 通配语义：`dir/**` 命中该目录及其任意子孙，含 `*`、`?`、`[...]` 的模式按 shell 通配匹配
 且 `*` 不跨 `/`，不含通配符的模式为精确路径匹配；
- 受影响的构建目标由构建图反查得出，数据源是构建系统的依赖边，见 `../build/BUILD_GRAPH.md`；
- 选择结果必须可逐条复核：每条判据给选中或跳过的结论与命中的路径模式或构建图依据。

### 9.4 增量档必须能红的三条

| # | 触发条件 | 判红形态 |
|---|---|---|
| 1 | 改动集中存在不匹配任何在册判据输入面模式的文件 | 列出未覆盖路径，提示补判据或显式全量 |
| 2 | 改动命中敏感面（构建入口、构建与依赖声明面、公共头面、合同面、产品清单面、文档索引面） | 自动升级为全量并打印命中的敏感面 |
| 3 | 改动集非空而选中判据数为 0 | 判红 |

三条各配一条注入负例（人为构造改动落在未覆盖路径、改动命中敏感面、选择器被置为恒空），
必须判红。显式全量与升级后的全量不适用第 1 条，但仍须把未覆盖路径打印为判据缺口。

### 9.5 超时与总预算

每条命令都带超时；超时缺失或非法一律复核失败，不得据此给出通过结论。单步超时上界不超过
`max(60 s, 3 × 最近一次实测墙钟)`，且不超过该档的硬上限。增量档设总预算，实际耗时超出即报告
应拆分并停止。

「最近一次实测墙钟」的记录面、记录者与更新时机（**该判据可执行的必要条件**）：

| 项 | 规定 |
|---|---|
| 记录面 | 每次验证落的结果件本身，取其**各步墙钟**字段（见第 9.7 节的结果件必需字段），按「档位 × 判据 ID × 步名」索引；本标准不另设独立台账，避免出现第二份取值面 |
| 记录者 | 执行该档验证的执行者，在写结果件时按实测填入；不得由后续复核者改写，也不得由文档作者手工填 |
| 更新时机 | 该判据**成功完成且结果件落盘**时立即覆盖为新值；判红、超时、中断或未执行的档**不更新**，原值保留 |
| 取不到时的行为 | 该判据**尚无实测墙钟**（首跑，或该键在结果件中缺失）时，`最近一次实测墙钟` 取该档的硬上限；此时该判据记为「超时上界由档位硬上限给出」，不得记为「已由实测校准」 |
| 跨面隔离 | 墙钟值只在**同一机器、同一数据、同一配置**的档内比较；换机器或换数据后重新记录，不沿用旧值 |

### 9.6 分档与代价显式

| 档 | 触发 | 内容 |
|---|---|---|
| 快速档 | 本地与每次改动 | 秒级一致性面：静态、合同、文档、轻量单测 |
| 集成档 | 提交前必跑 | 真起子进程、真跑产品可执行程序、含真实测量窗的用例 |
| 全量档 | 拿不准或发布前 | 完整构建加完整测试加集成档全部内容 |
| 测量档 | 负责人触发，一次性 | 性能测量、真实数据端到端、资源与扩展性测量 |

- **代价必须显式**：快速档变快靠的是把真起子进程、真跑产品可执行程序、真测量窗的步骤移出去，
 不是靠放宽判据，也不是靠跳过。
- **提交前必须跑集成档**，否则事件流、磁盘面、资源面与运行时集成用例无人跑。只跑快速档时，
 结论里必须写明集成档未跑。
- 集成型用例以目录归属划出，不以跳过标记或环境变量绕过。
- 重步骤带输入指纹缓存：指纹取提交、相关配置内容散列、数据清单内容散列与 worker 数；指纹命中
 则复用已有归档（写明复用了指纹），指纹变化才重跑。
- 环境在 Windows 与 Linux 双平台运行；两平台读数齐备后记录各自的运行证据。

### 9.7 运行结果的可复核面

每次验证落一份结果，至少含：范围与档位、基线引用、改动文件清单、每条判据的判词与结构化
证据路径、是否升级为全量及原因、未覆盖路径、是否无改动、各步墙钟与超时预算。判结论的每一
条都有结构化证据，证据可归因到被核对的对象本身。判红结论逐项给检查名、对象计数与被判红的
前 10 条对象路径。

## 10 失败处置

- 红项是缺陷信号，按修复或回退处理；测试不裁决合入，合入由提交纪律决定。
- 复核基础设施故障：重跑一次；连续失败由负责人介入，不以豁免放行。
- 所有失败必须有可复现证据（命令、日志、读数）。环境问题或工具问题的归因同样以这份证据为准；
 无证据的归因不成立，也不得用来降级判据。
- 判红结论的复算按验证证据标准的盲复算与三态判定执行。

## 11 科学条款到用例的映射

下表是当前冻结的映射。SCI 与 ALG 编号的正本在 science 分册；被映射量的标度类别与量纲正本见 `../standards/NUMERIC.md`[5]。

**容差列的「适用量级域」是必填项**：每档容差都必须同时给出被比较量的量级域 `scale`，
否则该档容差不可判（见第 4.3 节的可满足性下限）。「载体」列取值为
「已落位」= 该路径在本仓存在且含对应用例；「无载体」= 判据的**绑定**已冻结但**执行面未落位**，
后者**不得**在任何判词或台账中记为该用例已执行。

| 科学条款 | 用例 ID | Oracle 类型 | 容差（数值） | 适用量级域 `scale` | 载体 |
|---|---|---|---|---|---|
| 校准 SCI-CAL-001 | TEST-CAL-001 | 解析 | 绝对零 / `rtol = 1e-6` | 标定后 flux，ADU，量级 1e1–1e5 ADU | 无载体 |
| 天体定位 SCI-WCS-001 | TEST-IPV-001 | 高精度 | 往返 `1e-8` 像素 | 像位置素，量级 1e2–1e4 像素（帧宽 ≤ 1e4 像素） | 无载体 |
| 测光 SCI-PHOT-001 | TEST-PHOT-001 | 解析 | 通量 `rtol = 1e-6` | 单源积分通量，ADU，量级 1e1–1e6 ADU | 无载体 |
| PSF SCI-PSF-001 | TEST-PSF-001 | 高精度 | 质心与半高全宽判据 | 质心像素（1e2–1e4 像素）与 FWHM 像素（1e0–1e2 像素） | 无载体 |
| 噪声 SCI-NOISE-001 | TEST-NOISE-001..015 | 解析加蒙特卡洛 | 固定种子统计界 | 帧级信噪比，量级 1e0–1e4（无量纲） | 无载体 |
| 球面重采样 SCI-DRZ-001/014 | TEST-DRZ-CAND-001、TEST-DRZ-VAR-001 | 解析、性质 | 漏检为零（精确）；方差按尺度平方传播，落第 4 节归约档 | 方差按标度类定域：像素面 1e0–1e2 ADU²；面亮度面 1e10–1e14 ADU²/sr² | 无载体 |
| 信号面权重 SCI-UPM-001 | TEST-UPMW-001..007 | 蒙特卡洛加性质 | 冻结常数取几何查表口径；`rtol = 1e-9` | 信号面残差，量级 1e-4–1e0（归一化单位） | 无载体 |

| 导出 SCI-P3-001 | SYN-007 五件套 | 解析加性质 | WCS 紧门 `1e-8` 像素；全域保守门 `1e-6` 像素；常数场 | 角秒每像素，量级不小于 0.9 角秒每像素（紧门适用域）；保守门覆盖全部输入尺度 | 无载体 |

**载体面的登记纪律**：本表的科学条款 → 用例 ID → 容差与量级域的**绑定**是冻结判据；
载体未落位时该判据的状态是「绑定已冻结、执行面未落位」，选档计算必须把它计入未覆盖路径，
不得按「已执行」计入绿。载体落位后本表的载体列改记为已落位路径。

# 验证证据标准

上游：最高设计的验证体系一章。

本标准规定每条科学判据与每道工程条款的证据形态：独立 Oracle、零用例即红、负向 mutation 目录、基线比较矩阵与声明边界；判定结论的计入绿资格、零对象守卫强度、判别力核查的合格定义、复核与上报纪律、判据的自报义务。

判定结论由两条路径给出：实验单元 qa-design 数据面的 mutation 目录、Oracle 运行器与规格校验器跑出的读数，以及人读对抗性审核构造反例后给出的复核结论。本标准规定判据与证据形态，不规定注册、登记与流水线流程。

## 1. Oracle 独立性

1. 独立真值来源限于白名单：`independent_numpy`、`independent_numpy_mc`、`independent_stdlib`、`structural`、`real_data_checklist`、`preregistered_comparison`、`independent_driver`。
2. 每条判据必须声明 `oracle.truth`（真值来源）与 `oracle.must_not`（独立于被测对象的对象集，至少含产品可执行程序本身）。
3. Oracle 参考实现只用 NumPy 与标准库，参考实现为显式矩阵、解析恒等式与定种子 Monte Carlo；被测公式以独立转写的形式作为 subject 接受检验。
4. 断言面是值断言；子串存在性只作辅助。期望值由独立参考实现生成，与被测实现分离。
5. 真实数据判据的期望值取自独立真值，生产输出只作辅助证据。
6. 任何「Oracle 全过」的结论一律逐条判据重新实测，不接受历史结论沿用。

## 2. 零用例即红

判据台账逐条登记 `required_cases`、`executed_cases`、`skipped_cases`、`pends`、`counts_as_pass`，逐条实测按下列规则判退出码：

```text
executed_cases == 0 且非 pending -> rc=2（不计通过）
skipped_cases >= executed_cases（skip-only） -> rc=2
pending 判据未声明 counts_as_pass=false 或无 owner -> rc!=0
executed_cases < required_cases -> rc!=0
```

零用例与 skip-only 两类退化由规格校验器检出（rc=1），二者各配一条负例 mutation 证明该规则能红。同一规则约束人读复核：审不出实算例数的判据按同一面判红，不按「已覆盖」放行。

| M-FBIAS | 通量偏差 |
| M-SBBIAS | 面亮度偏差 |
| M-EPSF | 由有效 PSF 脉冲响应测量的 FWHM |

### 4.4 声明规则

- `psfsw_robust` 只允许「在指定验收数据上优于指定基线」；禁止点源逆方差、Fisher、`1/W_psfsw` 语义。
- `pixel_ivar` 与 `equal` 是文档基线，禁止科学最优声明。
- `psf_snr_power` 保持延迟，不得进入生产路由。
- 训练与调参样本不得与最终验收样本相同。
- 真实数据比较必须配解析、Monte Carlo 或外部参考真值，不得以生产输出为唯一期望值。

## 5. 判读纪律

1. 每个比较单元必须预注册数据、基线、度量、效应量与置信区间；训练调参样本与验收样本各自独立。
2. 相关帧必须用联合协方差；点源信号权重的协方差只能从实际组合系数传播。
3. 报告必须包含有效 PSF，以及相对基线的检测功率、测光方差、FWHM、通量偏差与面亮度偏差。
4. 真实数据比较必须配解析、Monte Carlo 或外部参考真值。
5. 本标准给出的是证据形态与声明边界；数值阈值由实验单元的预注册冻结，正文以冻结值为准。

## 6. 判定结论计入绿的三条资格

一条判定给出的红与绿只有同时满足下列三条时才算数；缺任一条，它既不给红也不给绿，单列为「未生效」并从绿集合里剔除。

| # | 资格 | 判据 | 缺项处置 |
|---|---|---|---|
| Q1 | 读真实对象 | 声明的 `object_class` 与实际读到的对象一致，且读到的不是该判定自造的夹具；输入面声明非空且实算对象数 > 0 | 改造，或降级为 `fixture-only`；`fixture-only` 判定不进发布层，不得被引用为产品证据 |
| Q2 | 有牙 | 注入对应缺陷必红，且至少一条负例落在该判定自身的豁免、白名单或降级分支内 | 不出绿资格：该判定的绿不计入任何层结论，直到补齐 |
| Q3 | 可归因 | 读者能从留证复算它跑没跑、跑了几个对象、判了什么值：执行证据逐项在案（实算对象数、判了什么值、结论由谁据以行动），判结论的项带可解析的结构化证据 | 整项零执行的判定从绿集合剔除并单列「未生效」 |

「给不出注入负例的判据不进清单」：答不出「注入什么它会红」的判据不写进判据台账，不以报告项、观察项或待补项的名义进册。

层结论逐层取值，每层给有效判定数 / 判红项 / 未生效项 / 可信性存疑项；发布层在任一层有效判定数为 0 时判红并点名该层。

## 7. 零对象守卫的强度要求

`inputs` 声明本身可以是空的或假的，因此守卫是**两条而不是一条**，两条同时成立：

1. 声明非空且实算对象数 > 0，否则红；
2. 声明的对象数必须与该判定实际消费的数一致：判定在自己的留证里输出 `n_objects`，复核者核对 `n_objects` 与输入面实算数之差不超过声明容差，差异过大判红并点名。

- **正例**：某文档判定声明一个非空目录，留证里的 `n_objects` 与输入面实算数相等且大于零，绿。
- **负例**：把输入面指向一个空目录，`n_objects = 0`，该判定自红；把输入面改成一个不存在的路径，复核按输入缺失判红；把 `n_objects` 写成常量，第 2 条判红。
- **内层同样断言**：守卫加在单元级不等于项级成立。判据集合自身为空（规则数为 0）按第 2 条同面判红，不因外层扫描面非空而放行。判据集合的来源要求见 `../governance/DOCUMENT_GOVERNANCE.md` 的登记面一节[3]。
- **进册面 fail-closed**：除 `object_class = fixture-only` 与标为纯构建步骤的单元外，每个非豁免单元必须声明 `inputs` 或 `optional_inputs` 之一，缺失即红；未声明输入面的判定进不了册，复核者才能独立复核这一步到底看了几个对象，不依赖读者对实现体的信任。

## 8. 判别力核查的合格定义

判别力核查分两类，各判各的对象：**判定器自身的证据管道**测判定手段本身（证据缺失、证据损坏、无输出三面对共用判定逻辑的反应），**逐判定点核查**测每一个判定点。名号与对象相称：判定器管道核过的结论，其含义限定为判定器管道核过，不被读作全仓判别力已核。

逐判定点核查的合格定义七条，每条都是判据，由人读对抗性审核逐条给出：

| # | 要求 | 判据 | 不满足时 |
|---|---|---|---|
| S1 | 对象是被核查的判定点 | 对每个在册判定点构造其负例登记所对应的缺陷、复跑判定、断言结论点名该判定点的真实对象 | 记「未覆盖」，不计入通过 |
| S2 | 同时验证绿 | 未注入时同一复跑路径必须给绿，防止「一律判红」的假判定 | 该判定记可信性存疑 |
| S3 | 负例落在该判定自己的豁免或兜底分支 | 必须有一条 `red-through-exemption` 负例：构造一条会被本判定白名单或降级分支放行的违规，断言仍红 | 记「fail-open 面未覆盖」，不计入通过 |
| S4 | 面归属与被覆盖面同源 | 核查读到的强制面等于判定实际会强制的面：盘点一份集合、据另一份集合下结论即为不成立 | 核查本身判红 |
| S5 | 规模锚用实算值 | 断言受核查单元数等于被覆盖面实算出的单元数，或不低于登记高水位且只增不减并保存读数；禁止任何无来源的魔数阈值 | 红 |
| S6 | 内容级负例 | 把某个真判定的判定逻辑换成恒真，**只换它，不换共用逻辑**，核查必须点名**该判定** | 红 |
| S7 | 产物可核 | 核查结果落留证并带被审对象标识与判据台账摘要；证据新鲜度核对留证读数与现算一致 | 红 |

- **S6 是本节的判别核心**：注入点必须是该判定自身的判定逻辑。把注入点放在共用判定逻辑上，等价于把自己的总分擦掉再证明能发现分数被擦。
- **反例复跑必须隔离**：构造反例只允许在临时副本上改，不写仓库留证与产品面。只能在就地改动仓库才能造出反例的判定点，标注为「不可核查」——后者一律出绿资格（Q2）。
- 与科学缺陷注入登记册对象不同：那张面登记的是近似实现被抓没有，本面登记的是判定能不能抓到东西。两张面各自合法，判别力核查不吞并它，也不引用它作为「有牙」的证据。

## 9. 复核与上报纪律

### 9.1 盲复算与三态判定

- 复核任何既有判定一律走盲复算：先只读对象的位置与锚，自己取证得数并写下结论，再打开既有判定对比。顺序颠倒则本次复核无效。
- 对比落**三态之一**：`一致`、`旧判偏松`、`旧判偏严`。三态必落其一，并判谁对；不许并列存疑。
- 既有台账、清单与状态登记里的「已判」「已确认」「已修」一律按**线索**处理。引用它们时给出本轮自取的证据；不得据其跳过取证，也不得据其缩小取证面。
- 偏松清单本身是交付物：它给出上游给了下游多少虚假授权。

### 9.2 四态复核与准入

每条问题条目的复核结论落**四态之一**：`确认`、`降级`、`推翻`、`待证`。

- 只有 `确认` 与 `降级后仍成立` 进正文、任务书与负责人清单。
- `待证` 写明缺哪一条证据、怎么补。
- `推翻` 条目保留在册并标注不可再引用，不得删除。
- 每条问题条目同时具备两项准入：自己取证所得的复算读数，与另一路代理的独立复核结论。缺任一项不进正文与任务书。科学结论的三重佐证面见最高设计的验证体系一章[1]，两者是不同的准入面，不互相替代。

### 9.3 零命中自证

- 报「零命中」「无人引用」「不存在」之前，把检索词换两三套再试，并把**同一条命令在一个已知应命中的对象上跑通**。两件事都做了才可报零命中。
- 已知假阳来源逐条检查：路径由多个字面量拼成时整串检索不到；`rg` 在部分环境不可用，改用 `git grep`；`head` 截断造成的「看不到」；`git grep` 默认只搜跟踪集。
- 引用任何条款前核对该文档的现行版本：条款的表述与方向可能被上游反转，按现行版本判定。
- 报「零命中」时把用过的检索式一并列出，读者可复算。

### 9.4 定级与误绿指控的硬门槛

- **定级硬门槛**：定最高档必须能沿生产调用路径逐跳写出位置。写不出触发路径的最高只能定次一档，并注明缺运行时触发路径。
- **误绿硬门槛**：判 fail-open 或误绿之前先把不等式方向定下来——丢掉被测量的一项只会让结果变大还是变小，方向决定偏红还是偏绿。方向没定的误绿指控不予受理。
- **判「某类缺陷已修」要同时核四项**：它被谁据以行动了；跑的是产品还是自家夹具；参数面能否表达在册数据形状；它在那个面上现在红还是绿。四条不齐只写「机制已就绪、接线未闭合」。
- 状态词不跨轴串用：`未实现` 不等于 `未接线`（在库里但生产零引用），不等于 `已退役`，不等于「文档没写」。

## 10. 判据的自报义务

承担判别职责的手段——实验单元的脚本、实验复核、人读对抗性审核——一律适用本节。

- 每个判别手段的正文写明三项：已知的假阳形态、被排除的采集面、这三项的现值。缺任一项即缺陷。
- 这三项本身是**该手段自己的缺陷登记项**：它的假阳与被窄化的采集面按自身缺陷登记，不记在使用者名下，也不等使用者报告。
- 排除面按 `../governance/DOCUMENT_GOVERNANCE.md` 的登记面一节[3]的三字段与三分类 `reason` 登记，命中数逐条复算。
- 采集面收窄导致的读数变化显式写出：口径变了而读数没变的报告不作为证据。报告项不得在补齐采集面之后继续沿用原读数。
- 验收判据必须能自证到两侧：自证同时覆盖「必须判红」与「必须不判红」；只有「必须判红」一侧的自证不足以证明判据有牙。自证可以是脚本自检，也可以是审核者构造正反算例后复跑。
- 判红输出逐项给检查名、对象计数与被判红的前 10 条对象路径。

## 11. 四层验收判据与递进规则

本节是四层验收的判据与流程口径正本[1][2]。层级定义、每层核心判据与状态阶梯以本标准 12.4 豁免面 与 12.5 文档域不设机器执行项 为上位来源；本节展开各层的目标、数据、执行方与递进规则，并给出各层判据的取证面。

### 11.1 递进规则

- 四层由小到大、由合成到真实、由可量化读到目视，**前一层未通过，后一层不开始**；
- 任一层不通过：登记问题 → 修复 → **从受影响的那一层重跑**，其后各层的结论不再作为有效结论；
- 五个创新点的实验单元属 L1 的核心组成，未全部证实前不进入后续层（单元清单与命名以本标准 12.3 fail-closed 与锚存活 为唯一正本）。

```mermaid
flowchart LR
 L1["L1 合成科学性"] --> L2["L2 合成性能"]
 L2 --> L3["L3 小批量端到端"]
 L3 --> L4["L4 真实视觉验收"]
 L4 --> G["发布门汇总"]
 L4 -.不通过.-> F["登记问题 · 修复 · 从受影响层重跑"] -.-> L1
```

### 11.2 四层总览

| 层 | 目标 | 数据 | 主要执行方 |
|---|---|---|---|
| L1 | 科学性 | 三类实验数据（本标准 12.2 登记面与准入），真值已知 | 实验单元复跑（Oracle、mutation 目录与规格校验）+ 独立审稿 |
| L2 | 性能 | 规模化合成数据，重计算区间足够长 | 资源采集与记录复核（阈值唯一数值源 = `eng/contracts/resource_gate_v1.json`，采集与判定脚本 = `eng/tools/quality/resource_monitor.py`） |
| L3 | 可行性 + 科学性 + 性能 | `testdata/` 小批量真实帧 | 三命令实测 + 执行方抽检 |
| L4 | 视觉正确性 + 发布决策 | `testdata/` 的 M42 与银心全量（本版仅 R 通道） | 执行方初审 + 负责人目检 |

每层提交时附完整证据：实验单元与工程实测证据落 `实验/`，性能实测读数落 `实验/engineering-evidence/l2_performance/`，分层证据与验收报告按发布候选归档面留存（归档面定义 = ``../data/ARTIFACTS.md``）。前一层全绿是进入后一层的硬前提（四层验收.1）。

### 11.3 L1 · 合成科学性

**目标**：在真值已知的条件下证明每个科学算法的实现与 `docs/science/` 的公式和定义一致。

判据：

| 类别 | 判据 |
|---|---|
| 独立 Oracle 对拍 | 每个科学模块至少一条不调用生产实现的 Oracle 或解析解；投影与 Astropy / WCSLIB 独立对拍（正反变换、CRPIX↔CRVAL 不变量、dec≠0 用例） |
| 科学不变量 | 校准通量守恒；帧级信噪比定义与计算；Phase2 逆方差叠加（权重由各源像素信噪比导出）；drizzle 面亮度与总积分通量守恒；投影正反互逆；HiPS 层级像素面积关系 |
| 精度 | FP32 / FP64 两条路径分别满足合同容差；常数使用全精度字面量 |
| 判据判别力 | 每个度量都有「真值无效应 ⇒ 度量归零或判红」的负例；恒真判定不计证据（见 判别力核查的合格定义一节） |
| 统计与排异 | 稳健尺度口径、排异的逐像素档位路由、归约顺序与科学文档逐项一致（档位表正本在 `docs/detail/` 的 Phase2 排异分册） |
| 边界 | 样本级掩膜与重归一、覆盖级无效值与计数、空输入、极端参数、错误输入均有确定行为 |
| 并行确定性 | 同一输入 1 worker 与 N worker 数值一致，判据为事前冻结的浮点容差 |

**通过判据**：五个创新点的实验单元结论成立且独立审稿通过；全部科学测试与合同测试通过；每个科学模块至少一条 Oracle 对拍与一条不变量用例；负例面齐全。测试工程要求见 `TEST.md`[2]。

### 11.4 L2 · 合成性能

**目标**：证明重计算负载下 CPU 利用率接近满载、内存占用合理且无无界增长。规模化合成数据须使每段重计算区间严格大于冻结结阈值（阈值唯一数值源 = `eng/contracts/resource_gate_v1.json`，判据 ID 与冻结表见 `../resources/PERFORMANCE_MODEL.md`）。

判据：

| 类别 | 判据 |
|---|---|
| CPU 利用率 | 无单线程跑满全程；无连续低利用窗且队列有工作；均值、p50 与逐样本利用率达标或超标登记有解释 |
| 内存工作集 | 峰值工作集随分块大小而非总数据量增长；稠密权重面与信号面按需现场求值，不整轮驻留 |
| 线程扩展 | 多个 worker 档位测量吞吐与加速比，档位取自 benchmark 生成的机器画像，**不硬编码并行度**（最高设计 复核与上报纪律一节）；worker 均衡度由均衡度记录佐证 |
| 编排连续性 | 同一数据块的连续节点在同一 worker 内走完；worker 空转率、块重载次数与跨 worker 搬运量归档，无「一段做一半换 worker 再切回来」 |
| 缓存复用 | 外部星表同组查询的请求计数为 1（查询合并 + 两级缓存）；命中率归档（判据见 `../standards/CACHE.md`） |
| I/O | 读写带宽与 I/O wait 在案；统一 I/O 层不构成不可解释瓶颈；磁盘门零违约 |

**通过判据**：磁盘门零违约；内存与 CPU 的记录项无未解释超标；工作集流式性、缓存复用与编排连续性达到实现前的资源分析预估；线程扩展与内存曲线归档为基线。资源门只管磁盘，内存、CPU 与线程不设阻断门。

### 11.5 L3 · 小批量端到端

**目标**：在真实观测数据上证明三命令流程可行、科学正确、性能达标。数据 = 从 `testdata/` 抽取的小批量帧（每个滤镜组少量亮场加对应 bias / dark / flat），覆盖至少两种望远镜或两种滤镜。

```mermaid
flowchart LR
 J1["normalize --json p1.json<br/>预检 → 确认 → 运行"] --> P1["Phase1 HiPS + 结果 JSON"]
 P1 --> J2["mosaic --json p2.json<br/>输入承接上个 JSON"]
 J2 --> P2["Phase2 天球产品"]
 P2 --> J3["export --json p3.json"]
 J3 --> P3["平面 FITS + WCS"]
```

判据：

| 类别 | 判据 |
|---|---|
| 可行性 | 三命令退出码均为 0；阶段之间只经磁盘产品 + manifest + 哈希交接（唯一正本 = 本标准第 8 节判别力核查的合格定义）；Phase1 的输出 JSON 直接满足 Phase2 输入并串行跑通；运行前预检三级（correct / warn / error）与确认开关语义按 `../governance/DOCUMENT_GOVERNANCE.md` 的引用与登记纪律[3] 生效（correct 与 warn 需确认，warn 不阻塞，error 阻塞且不可越权跳过） |
| 科学性 | 产品通过 schema 校验、manifest 字段完整；WCS 与已知天区坐标对拍；星点定位与通量抽检与合成层结论一致；信噪比权重链可追溯 |
| 性能 | 全程资源记录归档；真实负载下无异常；内存峰值合理 |
| 并行确定性 | 同批数据 1 worker 与 N worker 产品数值一致 |
| 原子性 | 中断或失败（含中途终止）后，产品目录只出现完整产品，无半成品被误认为正式产品 |

**通过判据**：全部数据块三命令串行跑通，科学抽检全过，资源记录无异常。

### 11.6 L4 · 真实视觉验收

**目标**：在两组有代表性的真实天区完成全流程并做整幅视觉验收，作为预览版发布的最终门。数据 = M42（亮星云、高动态范围、密集星场）与银心（极密集星场、背景结构、大尺度马赛克）；帧数与筛选口径以 `testdata/README.md` 为准。

产品生成链：

```mermaid
flowchart LR
 A["两组全量原始帧 + 校准帧"] --> B["normalize 全量处理"]
 B --> C["mosaic 拼成一整张马赛克"]
 C --> D["export 导出整幅平面 FITS（WCS 直接生成）"]
 D --> E["拉伸脚本：固定参数、可复现的深空非线性拉伸 → 整幅 PNG"]
 E --> F["切块脚本：固定网格切块，保留行列编号与整幅缩略图"]
 F --> G["执行方逐块 + 全局初审 → 负责人目检"]
```

- 两组天区使用同一套脚本，脚本与参数随证据归档；
- 视觉判定基于分块 PNG 与整幅 PNG，不靠低分辨率整幅图下结论；有疑问的区域裁剪放大后再读；
- 执行方提交前逐块自检并附接缝的逐边度量与背景定量度量；发现问题自行修复并从受影响层重跑，直至两组数据全部无异常。

视觉验收清单：

| 检查项 | 合格表现 |
|---|---|
| 无黑洞 | 无异常零值区、死区或未填充孔洞；稀疏区与重叠区过渡自然，无不自然暗斑 |
| 无亮斑 | 无宇宙线或卫星线残留、校准伪影、饱和溢出形成的异常亮点；星云高亮区有层次而非死白 |
| 无接缝 | 帧间与块间无亮度或灰度阶跃，无重影、错位与重复星点。判据量：沿真实帧足迹取法向差分，量的是**有符号台阶**相对边界局部背景电平之比；只对两侧都在数据内部的帧边界计入，被排除的边界逐条落盘；噪声比与方差比只作诊断量、不判红（方差比对电平阶跃原理性失明）。门限为 `max_e \|rel_step(e)\| ≤ 1e-2`（法向采样半距默认 2 px）；门限推导与实测标定的正本 = `../../science/sky/UPM.md`「参数与常数」一节；本标准不复述门限数值。执行方按该判据量自算逐边度量并附读数，对抗性审核对读数构造注入台阶与零台阶两侧算例复核其判别力 |
| 星点质量 | 星点圆锐，无拖尾、拉伸或双线；跨帧星点重合 |
| 背景与几何 | 背景均匀、天光结构连续；无明显投影畸变，WCS 网格与星点位置吻合 |

**提交物**：整幅平面 FITS（两组）、整幅 PNG、全部分块 PNG、拉伸与切块脚本、三阶段日志与资源记录、各阶段计时与热点分析。两组全部通过后进入发布门汇总；档位判词的写法见本标准第 13 节，发布决定权属最高设计第 13 章（版本与发布权）。

## 12 判据体系：条款强度分级、登记与判据可信性

本节是判据体系本身的正本：条款强度分级、登记面、判据可信性、豁免面、执行面归属、判据边界、
性能判据的执行纪律与工具链冻结取值的处置。判据保护的对象是条款，条款的正本在 最高设计
与 science 分册。本节的档位是**条款强度**——它回答「这条条款有多硬」，不回答「由什么工具执行」。

### 12.1 条款强度分级

| 级 | 含义 | 判红处置 |
|---|---|---|
| P0 | 硬约束条款 | 结论判红，不得豁免；无任何条款的绿可与之抵消 |
| P1 | 硬约束条款（可显式豁免） | 结论判红；豁免由负责人显式登记 |
| P2 | 报告项 | 不判红，但结果必须留存并可复算 |

- **档位由它所守护的条款决定，不由它是否易跑决定**；把难跑的强条款降级是分级错误。
- **一条层结论成立**的定义 = 全部 P0 绿加全部 P1 绿（或已按登记面豁免）。P2 只统计与留存，不参与红绿。
- 档位只决定判红后果，不决定取证深度：P0 与 P1 都进红绿计算，都必须逐条给出结论，不因档位高就只抽查。

### 12.2 登记面与准入

- **每条判据对应定稿文档的一条条款，映射登记**；条款变更时同步判据。映射表是判据体系的唯一登记面。
- **登记即实现**：没有实现的判据不登记为 P0 或 P1 档。文档承诺而实现缺席的判据，其缺陷在审查面判红，不得留在硬约束档造成假绿；登记在册但无实现的条目不进入红绿计算。
- 每条判据必须**能绿能红**：正确实现绿、注入对应缺陷红。正例与负例都由对抗性审核构造并复跑给出：注入负例必须真的被复跑、读数必须被读到，只有文字声明而无复跑读数的不算。不要求以可执行注入入口的形式随门附交，但要求反例的构造过程与复跑读数可被另一路代理按 「盲复算与三态判定」一节 盲复算。
- 给不出注入负例的判据不进册，不以报告项、观察项或待补项的名义进册。
- 一条判据从提出到进册的路径：写清所守护的条款 → 备齐正例与反例并复跑确认红绿双向 → 登记面补条目并声明档位与输入面。路径中的每一步都产出可复核的物，不依赖口头确认。

### 12.3 fail-closed 与锚存活

- **fail-closed**：输入缺失、路径不存在、依赖不可用、证据缺失或不可解析时判红；判定过程崩溃同样判红。「文件不存在」按「有违规」处理（实扫对象数为 0 即判红）。判定只走具名分支，「读不到就按全部合规处理」是未具名形态。
- **锚存活**：判据中硬编码引用的仓库路径必须存在。失效时以具名失败（`ANCHOR_STALE: <常量名> <路径>`）显式判红并点名；traceback 与静默降级一律按失败处理，不按通过或跳过处理。
- 零对象守卫的两条形态（声明非空且实算对象数 > 0；声明对象数与实际消费数一致）见 零对象守卫的强度要求一节。

### 12.4 豁免面

- 豁免由负责人显式登记，登记面**只减不增**。
- 豁免只豁免检查项，**不豁免科学判据与工程硬约束**；未被授权的条款不可豁免。
- 红灯不以豁免覆盖。合法降级必须显式、可溯，且不改变科学语义；降级记入证据，不记入豁免。
- 平台或工具不可用导致的显式跳过按 零用例判红一节 的 skip-only 判红处理，不计通过。

### 12.5 文档域不设机器执行项

**文档域不设机器执行项。** 文档域指四个面：文档一致性、文档写法、文档索引、锚存活。

- 文档域的正确性由**人读对抗性审核逐条覆盖**，执行面是 `../governance/DOCUMENT_GOVERNANCE.md`[3] 的对抗性审核准入一节。审核记录逐条给检查名、输入面、实测计数与判红对象路径。
- 文档域条款按 `../governance/DOCUMENT_GOVERNANCE.md`[3]的谓词形式书写（输入面、红条件、计数证据三要素），但**谓词形式不构成登记为机器执行项的依据**。谓词形式与执行面是两件事：谓词保证条款可判定，执行面决定谁来判。
- 文档域的下列判据**没有机器执行面**，正确性完全由审查兜住：判据登记面与文档条目集合的双向一致、验收判据关键词与上位设计冻结语句的口径一致（在场性与反义检测）、体积与规模类数字是否解析到配置键、配置真值逐键复算、文档索引与文件树闭合、文档内引用悬空。
- 同一事实若在别的面具备实质判据（例如产品层的 schema 符合性、产物层的字段自洽），按该面的判据登记，不因它出现在文档里就回到文档域。
- 因此本标准与 `../governance/DOCUMENT_GOVERNANCE.md`[3]对文档域只规定**写法与审查义务**，不规定任何文档域的机器门。

### 12.6 判据边界

| 不得 | 说明 |
|---|---|
| 用豁免掩盖红灯 | 未被授权的条款不可豁免（「豁免面」一节） |
| 把「能编译」当「验收过」 | 验收判据是断言、复跑与对抗性审核；构建成功只支撑 `IMPLEMENTED` |
| 把合成测试标成 VERIFIED | 合成层结论只支撑 L1 / L2；真实数据验收在正式平台由负责人触发（档位判词与子集判词分离一节） |
| 用全量重算代替独立科学 Oracle | Oracle 必须独立于生产实现（Oracle 独立性一节 的 `oracle.must_not`） |
| 把恒真、空断言、不读真实对象的判据计入绿 | 见 判定结论计入绿的三条资格一节 的 Q1–Q3 与 判别力核查的合格定义一节 的 S1–S7 |
| 保留一个没有实现的硬约束档判据 | 假绿；见「登记面与准入」一节 |
| 把过程产物当证据而不带内容指纹 | 见 「证据面」一节 |

### 12.7 性能门与采样隔离

- 性能门的判据与监控字段语义按 `../resources/PERFORMANCE_MODEL.md` 执行，阈值唯一数值源 = `eng/contracts/resource_gate_v1.json`。
- **判据值越界必须真判红**。「记录并给出理由」是无违规样本时的记录语义，不参与裁决；只采样留证的执行单元不请求性能门判定。请求判定与只采样留证是两种执行语义，必须显式区分，不靠推断。
- **采样隔离**：并行判据的采样器与被测计算共享物理资源时，采样器不得改变被测的工作集大小、线程亲和与调度策略。采样自身失败、丢样或解析失败一律判红，不按「无超限」通过。
- 同一运行的样本集合只在同一构建指纹下比较；跨指纹的读数不构成比较。已归档运行证据必须能被同一判据重放并给出与当时一致的判定。
- 适用域不成立的执行单元是**显式分类**，不是豁免：作为验收证据提交时按未通过处理，作为常规监控检查时记不适用并保留读数。

### 12.8 冻结工具链取值的处置

工具链版本号属契约冻结值，处置固定为三段，顺序不可换：

1. **显式 pin**：向构建的 configure 与 build 子进程注入版本，等价于构建系统自身承认的覆盖入口；不依赖主机默认的隐式命中；
2. **构建后实测**：从构建产物自报的编译记录读出实际使用的工具链目录，与 pin 值比对；
3. **fail-closed**：未命中 pin 值或测不到证据，即判红不放行，不按「大概率是命中的那版」处理。

- **禁止**为让判定转绿把冻结版本放宽到实测漂移值。
- 冻结取值的唯一数值源在 `../build/BUILD_NODES.md`；本节只规定处置纪律，不复述版本号。

### 12.9 状态由检查与验收现场计算

- 状态取最高设计 「状态阶梯」一节的阶梯，**由检查与验收现场计算，登记表不预写状态**。状态是读数，不是计划。
- 合成测试节点与历史轮次不构成真实数据 `VERIFIED`。
- `READY_FOR_OWNER_REVIEW` 是 agent 自验的上限，不等于发布；发布决定权属最高设计 「版本与发布权」一章。

## 13 档位判词的写法判据

本节规定「档位判词这句话怎么写才算有据」。它不改任何科学公式、阈值或冻结定义；科学判据的数值正本在 `docs/science/`，四层验收的层级与递进见 四层验收。

### 13.1 两条轴与分母点名

| 轴 | 键 | 分母 | 判词对象 |
|---|---|---|---|
| 帧数轴 | `frame_count` | `planned_frames`（计划帧 = 实际入册帧数） | 逐帧 `ACCEPT` / `REJECT` / `NOT_EVALUATED` |
| 覆盖度轴 | `coverage` | `total_px`（输出平面总像素） | `covered_px / total_px`、`finite_px / total_px` |

- **两条轴必须同时报，分母必须显式点名**。只报一条轴的档位结论不成立。
- 允许的分母词表（封闭）：`evaluated_frames` / `planned_frames` / `total_px` / `covered_px` / `finite_px`。改词表等于改判据，走变更流程。
- 判词的规模阶梯与四层验收对应：单帧标准化是小批量的最小单元；多帧集成是小批量端到端；全量帧三段全跑是真实验收的规模。各档帧数与筛选口径以 `testdata/README.md` 为准。

### 13.2 档位判词与子集判词分离

| 判词 | 充分必要条件 |
|---|---|
| `VERIFIED` | ① `n_evaluated == planned_frames`；② 阶段面覆盖该档要求；③ 无被拒帧；④ 无未消冻结门命中；⑤ 每个主张都在 `guaranteed_scope` 内 |
| `NOT_VERIFIED` | 证据不足以支撑 `VERIFIED`（首帧中止、未跑满、阶段面缺段）——**这是默认值**，不是例外 |
| `BLOCKED` | 有具体阻塞条件（环境 / 上游门 / 负责人明令），且阻塞面已按原因码登记 |
| `NOT_ATTEMPTED` | 0 帧被求值，且 `not_attempted_reasons` 非空 |

- **子集判词是独立词表**：`SUBSET_VERIFIED` / `SUBSET_NOT_VERIFIED` / `SUBSET_REJECTED`，不与档位判词混用。
- **子集证据只能支撑子集判词**。把子集证据写成档位 `VERIFIED` 判红。这是 「状态由检查与验收现场计算」一节「合成测试或历史节点不等于真实数据 VERIFIED」在帧级的落点。

### 13.3 形态处置：首帧中止 ≠ 全部失败

块以帧序执行、首帧失败即中止 ⇒ **未求值的帧不是「失败的帧」**。混写形态会让读者无法区分「本档在第一帧就停了」与「本档全批都被拒」，而这两者的处置完全不同。

| `block_outcome` | 硬性要求 |
|---|---|
| `first_frame_abort` | 必给 `aborted_at.frame_id` + `frame_index`；`n_evaluated < planned`；`rejected != planned` |
| `all_failed` | **`n_evaluated == planned`**（每一帧都被实际求值并拒绝）、`accepted == 0`、`rejected == planned`，`aborted_at` 留空 |
| `partial` | 存在未评估帧，且已评估部分有结论 |
| `complete` | 全部求值，`not_attempted == 0` |
| `not_attempted` | 0 帧求值 + 原因码齐全 |

- 计数守恒：`accepted + rejected + not_attempted == planned`。
- 形态判红的两种典型：把首帧中止写成 `all_failed`；把 `n_evaluated < planned` 的记录写成 `VERIFIED`。

### 13.4 未尝试面

- 未尝试 ≠ 失败，也 ≠ 不提。逐项必填：`item` / `reason_code` / `owner` / `evidence`。
- 原因码封闭词表：`BLOCKED_UPSTREAM` / `OWNER_STANDDOWN` / `ENV_MISSING` / `RESOURCE` / `SCOPE_EXCLUDED` / `OTHER`；取 `OTHER` 必须在 `note` 写明。
- `counts.not_attempted` 必须与逐帧 `NOT_EVALUATED` 权重对账。

### 13.5 证据面

- 每个 `evidence` 指针必须**存在且非空**；落在过程产物目录（`run/`）下的必须带内容 `sha256`。
- 逐帧可按 `frame_ids` + `frame_count` 显式分组（组内同判词），但权重必须与 `counts` 对账。
- 拒绝记录必带五项：门 ID、原文原因、分类（不得为 `unknown`）、出口、确定性复现。

### 13.6 主张范围

- `claim_scope ⊆ guaranteed_scope` 是硬规则。判据能断言的范围必须与实际能保证的范围一致：小批量子集能保证「这批帧全 `ACCEPT`」，不能保证「全量档通过」。

### 13.7 规则清单

| 规则 | 内容 |
|---|---|
| 判词-01 | 分母声明齐（计划帧、指纹、分母词表、阶段面、两条轴、档位） |
| 判词-02 | 计数守恒 `accepted + rejected + not_attempted == planned` |
| 判词-03 | 形态判定自洽（首帧中止 ≠ 全部失败） |
| 判词-04 | 子集证据只支撑子集判词 |
| 判词-05 | 逐帧记录完备（`frame_id` / `frame_ids` + 判词 + 证据） |
| 判词-06 | 拒绝记录五字段齐（门 ID / 原文原因 / 分类 / 出口 / 确定性） |
| 判词-07 | 未尝试面四字段齐（原因码 / owner / 证据） |
| 判词-08 | 证据指针可解析且非空；过程产物目录下的带 `sha256` |
| 判词-09 | 覆盖度轴：`covered_px ∈ (0, total_px]`、`finite_px ≤ total_px`、`total_px` 已声明 |
| 判词-10 | 报出比率可按声明分母复算 |
| 判词-11 | `claim_scope ⊆ guaranteed_scope` |
| 判词-12 | 存在未消冻结门命中或被拒帧时，`VERIFIED` 判红 |

- 每条规则各配一条注入负例；缺任一条必需用例即判据自证失败。自证同时覆盖「必须判红」与「必须不判红」两侧（判据的自报义务一节）。

### 13.8 判词记录的裁决

- 档位判词记录的裁决必须自证到两侧：一侧构造合法记录并确认给绿，一侧注入对应缺陷并确认判红。缺任一侧即无绿资格（「登记面与准入」一节）。
- 裁决的产物落点按 最高设计 判据的自报义务一节（I/O 与原子产品）执行；正例与反例的记录留证可被另一路代理按 「盲复算与三态判定」一节 盲复算。
- 档位判词记录是冻结门命中与停工型阻塞的登记面；命中成立与否由对抗性审核给出，写 `VERIFIED` 本身不构成确认（见 `追溯规范`）。

## 14 判据适用域与同名量隔离

### 14.1 同名量隔离

- 同一个量名在不同适用域里出现时，**每个域各自定义，引用处必须带域限定**；不带域限定的裸量名引用判缺陷，按 `../governance/DOCUMENT_GOVERNANCE.md` 的锚纪律[3]处理。
- 换算或比对两个域的同名量之前先确认它们是同一个量；不是同一个量时禁止直接代入或互相引用。
- 同名异域的每一处出现必须能追溯到各自域的正本条款；追溯不到的按悬空引用处理。
- 正例：`min_samples` 在信号面 patch 域的定义正本 = `../../science/sky/UPM.md`；登记与引用纪律见 `../governance/DOCUMENT_GOVERNANCE.md` 的正向设计纪律一节[3]（patch 保留样本数下界，与 patch 半径共同构成定义域）；其他域引用该名时必须带域限定。

### 14.2 适用域是前置约束

- 判据的**适用域是前置约束，不是放松阈值**。被适用域排除的对象逐条落盘（排除原因与余量），不静默丢弃。
- 适用域前置条件要求「最小有效样本数」时，边界两侧各能放下该数量级的有效样本才计入；不足的边界按本条落盘，判据量与被排除边数分别报出。
- 判据被要求运行而适用域内零有效对象时判红，不按「不适用」放行（与 零对象守卫的强度要求一节 的零对象守卫同面）。
