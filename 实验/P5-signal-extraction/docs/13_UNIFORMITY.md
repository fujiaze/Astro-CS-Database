# 重采样修正与覆盖均匀性硬自检

## 1 改动（对应派单第 1 条）

| 项 | 上一轮（不合格） | 本轮 |
|---|---|---|
| 重采样 | **最近落格**：每个帧像素整格搬到一个输出像素（`floor(xo)`） | **双线性投影**：每个帧像素按 `(1-fx)(1-fy), fx(1-fy), (1-fx)fy, fx·fy` 分摊到输出网格 4 个邻像素，与生产 export 的 `SAMPLER=bilinear` 同口径 |
| 代码 | `code/p5z_run.py::sample_image` | `code/p5w_run.py::sample_bilinear` |
| 覆盖自检 | 无（只报 NaN 占比） | 新增 `code/p5w_run.py::uniformity`，逐行/逐列计数 + 拍频指标，**不过就不测判据** |

同时**修掉一个未被上一轮发现的半像素错位**：落格法用 `floor(xo)`，而 0-based 像素坐标里
坐标 `xo` 的所属像素是 `floor(xo+0.5)`；双线性用 `floor(xo)` + 小数权重是自洽的（`xo=100.0` 时
权重全在像素 100），错位随之消失。

## 2 硬自检的口径与定阈理由

对每个臂，取覆盖判据 `ncov>0` 的行/列有效像素计数序列 `r[i]`：

```text
alt_ratio   = median(|r[i+1] − r[i]|) / median(r)      ← 拍频指标
interior_zero = 行/列中「两端有数据、内部为 0」的个数    ← 空洞指标
判定：alt_ratio ≤ 0.10 且 interior_zero = 0
```

**定阈理由**：帧（`CDELT` 0.967″/px）比输出网格（1.8″/px）细 1.86 倍，且各帧方位角近乎相同，
落格法会在输出行方向**拍频**——相邻输出行抽到的帧行数在 1 与 2 之间跳。双线性分摊后，单行计数只应
随**足迹形状**平滑变化。相邻行计数变化中位超过 10%，意味着平均每行有约 435 px（4352 px 的 10%）
的边界在抖动，这对一片连续覆盖的足迹已明显异常；**不设 max/min 阈值**，因为足迹是斜角/不规则外形，
行计数最大值与最小值之比本来就可以很大（本轮 162/4106 = 25.3），拿它当判据会误杀。

## 4 更正：覆盖率是 9.41%，不是 27.04%

`p5w_stage1.json` 里报的 NaN 27.04% 来自覆盖位掩码 `cnt_bits`（`int32`），而 43 帧超过 `int32` 的位宽：
`1 << k` 在 `k ≥ 32` 时在 numpy int32 上得 0，帧 32…42 的覆盖**没有留下任何位**。按权重和 `den>0`
统计的真实覆盖是 **90.59%（NaN 9.41%）**，且与生产成品非 NaN 区的 **IoU = 0.9938** —— 双线性重采样后
覆盖足迹与生产成品几乎重合。缩略图与成品 FITS 都是用 `den>0` 写的，所以**成品本身的覆盖是对的**；
只有依赖位掩码的那部分读数（均匀性用的是 `cnt_bits>0`）受影响。均匀性的结论（`alt_ratio`=0、
无内部零行）在产品覆盖上重新成立，但为稳妥起见，下一轮应把掩码改成 `int64` 后重跑一次。
