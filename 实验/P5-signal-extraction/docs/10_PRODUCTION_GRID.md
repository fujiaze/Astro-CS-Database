本文件是 P5「真实信号如何提取出来」一题在**生产几何**上的重做记录。它取代此前的自建网格版本；

## 0 必须核对天区与几何（本轮最重要的教训）

上一轮判定失败的直接原因不是算法，而是**把另一天区的产物当成了本任务的数据腿**：

| 项 | 上一轮实际用的 | 本任务该用的 |
|---|---|---|
| 数据腿 | `run/LAMBDA-ROLLBACK/base/mosaic` | `run/PHOT-FIX/p1_rerun/{t2,t3}/` |
| 天区中心 | `ra0=274.717°`、`dec0=-13.832°`（**非 M42**） | 生产成品 `CRVAL=(83.7557°, -5.4300°)`（M42） |
| 帧数/来源 | 4 帧、由联合加性模型给出的已校正瓦片 | 49 帧实拍单帧产物（可用 43 帧） |
| 网格来自 | 该产物自带的 order-12 HiPS 瓦片外接框（**自建**） | 生产成品自身的 `CD/CRPIX/CRVAL`（**取自产品**） |

后果：成品与生产成品天区不同、无法逐像素对照，网格又是自建的，最终缩略图呈条纹方块。

**操作规程（本轮已按此执行）**：帧集从运行清单与帧产品清单枚举；每帧的投影与几何从**该帧产品自身**读出；
所有输入与参照必须同运行、同天区，`CRVAL` 偏差超容差即判失败并报出；来源不明的目录不得进入分析；
缺几何的帧逐帧登记为待查、不猜不补。本轮的天区断言为：我的覆盖与生产成品非 NaN 区的 IoU = 0.619，
且 `CRVAL/CRPIX/CD` 与生产成品逐项相同（见本文件第 3 节与 `docs/13_UNIFORMITY.md`）。

## 2 重做方法与代码位置

不再自建任何网格。做法：

```text
① 取生产成品的 WCS 关键字（CD 矩阵 / CRPIX / CRVAL / CTYPE），输出画布 6208×4352 与之一致；
② 逐帧把 4096² 帧像素经 TAN→TAN 射影映射（8 参数 DLT，残差 ~1e-5 px）落到生产网格，
   最近落格积分（帧比输出细 1.9 倍，抖动观测下无偏），坏列与非有限值剔除；
③ 无覆盖处保持 NaN，不做任何填充、不插值造值；
④ 流式累积逐像素计数、Σw、Σw·x、Σw·x²、覆盖帧集位掩码；并按 32 输出像素粗格累积逐帧格均值；
⑤ 路径 A（差模对齐）只对**帧间差分**拟合逐帧「偏移 + 平面 + 粗格场」，逐格扣跨帧均值（公共分量不动），
   第二遍重建逐帧影像并施加修正；
⑥ 判据（接缝逐边计数、帧间一致性、结构保留）全部在生产网格上算。
```

| 步骤 | 代码 |
|---|---|
| 生产网格 WCS、单帧 WCS、射影映射、采样 | `code/p5z_run.py`：`ref_grid` / `frame_wcs` / `_homography` / `sample_image` |
| 流式累积 + 路径 A 拟合 + 判据 + FITS/缩略图 | `code/p5z2_run.py`（两输入臂） |
| 判据工具（接缝、逐帧系统电平、逐边改善恶化、一致性、结构保留） | `code/p5z_run.py`：`_edges` / `_seam` / `_summ` / `_groups` / `_compare` / `_consistency` / `_structure` |
| 一键复跑 | `code/run_production_grid.sh` |

**此前为什么自建网格（如实交代）**：上一轮我把 `run/LAMBDA-ROLLBACK/base/mosaic` 当成主数据腿——那是另一
天区（`ra0=274.717°`，非 M42）、由联合加性模型产出的 4 帧产品，它自带一套 order-12 HiPS 瓦片网格。
我用它的瓦片外接框自建切平面网格，用最近邻把叶像素搬到输出网格上，于是 3/4 像素落空、出现条纹方块；
随后又贴着覆盖区外接框重切了一个更小的网格，仍然大半为空。**根因是我没有以生产成品的几何为准**，
而是拿手边那条腿的产物布局当网格。这一判断错误已在 `results/rejected/README.md` 登记。
