# AstroCS 自治主 Agent 指令

## 1. 使命

你负责把 AstroCS 从当前不完整、不可系统验证的开发状态，逐步推进为可复现、可测试、可审计、可发布的长期工程。你的职责不是一次性重写全部系统，而是依照控制包中的任务依赖和 Gate，一项一项完成、验证、复核并留下证据。

默认执行模式为 **AUTONOMOUS_SINGLE_OWNER_WITH_INDEPENDENT_REVIEW**：用户只提供项目目录、压缩包和一次启动指令；后续部署、恢复、任务推进、状态维护和复核均由 Agent 完成。

## 2. 每次启动或恢复时

依次读取：

1. `engineering/control/PROJECT_STATE.yaml`
2. `engineering/control/CURRENT_WORK.md`
3. `engineering/control/MASTER_TASK_REGISTER.csv`
4. `engineering/agent/AGENT_OPERATING_RULES.md`
5. 当前任务对应的 `engineering/tasks/*.md`
6. 当前任务引用的 spec、checklist、注册表和既有证据

然后执行：

- 检查 Git commit、分支、dirty 状态、远端和可用工具；
- 检查上次任务是否存在未完成报告或中断检查点；
- 优先恢复未完成工作，不重复覆盖已通过证据；
- 输出当前任务、入口条件、允许范围、计划测试、超时和回退；
- 立即实施，不等待用户确认。

## 3. 单任务闭环

每个任务必须经过以下状态：

`BACKLOG → IN_PROGRESS → IN_REVIEW → DONE`

任务实施流程：

1. **事实预检**：验证入口条件，记录实际状态；
2. **失败证据或基线证据**：修缺陷前必须先建立可重复失败；治理类任务必须先建立当前事实快照；
3. **最小范围实现**：只修改任务允许范围；
4. **分层测试**：先最小测试，再相关回归，最后按任务要求运行更高层测试；
5. **证据归档**：生成 TASK_REPORT、TEST_REPORT、EVIDENCE_INDEX；
6. **提交复核**：任务置为 IN_REVIEW；
7. **独立复核**：按 `AUTONOMOUS_REVIEW_PROTOCOL.md` 执行；
8. **复核处理**：FAIL 则回到 IN_PROGRESS 修正；PASS 才可置为 DONE；
9. **自动推进**：从任务注册表中按文件顺序选择第一个依赖全部 DONE 的 BACKLOG 任务，置为 IN_PROGRESS，并重写 CURRENT_WORK；
10. **继续执行**：不得因为完成一个任务而停止。

## 4. 独立复核

优先使用独立子 Agent，并把 `agent/REVIEW_AGENT_PROMPT.md`、任务报告、测试报告、diff 和证据目录交给它。

运行环境不支持子 Agent 时，执行隔离复核：

- 先结束实现步骤并保存状态；
- 重新从任务规范、验收条件和原始 diff 开始检查；
- 不引用实现阶段的主观结论作为证据；
- 运行关键测试或抽查证据；
- 生成 `REVIEW_REPORT.md`，结尾必须有 `VERDICT: PASS`、`VERDICT: FAIL` 或 `VERDICT: BLOCKED`；
- 没有 PASS 不得置为 DONE。

## 5. 自动推进规则

- 任何时刻最多一个主任务为 IN_PROGRESS；
- 允许并行的只读调查不得写业务代码；
- 下一任务必须满足所有 `depends_on`；
- 同时满足依赖时，按 `MASTER_TASK_REGISTER.csv` 从上到下选择；
- 阶段最后任务完成后，先核对 Gate 清单和阶段报告；Gate 未通过不得进入下一阶段；
- 状态文件、任务注册表、证据目录三者必须一致；不一致时先修复控制状态再继续。

## 6. 真实阻塞的定义

只有以下情况可以停止：

- 关键源码无法从当前仓库、Git 历史、已配置远端、同级目录、构建产物或控制包恢复；
- 必须由用户提供的私有凭据缺失；
- 任务明确要求的实体硬件不可用且无仿真替代；
- 不可替代的真实数据缺失且不能生成合成数据完成当前验收；
- 两项不可兼容的需求会改变项目根本目标，且现有 ADR/文档无法裁决；
- 全部任务已经完成。

在宣告 BLOCKED 前，必须至少检查：当前目录、仓库历史、分支/tag、远端配置、同级目录、现有二进制/头文件、历史文档和控制包。不得把“需要思考”“任务较大”“测试时间长”当作阻塞。

## 7. 阻塞和恢复

阻塞时：

- 在当前证据目录生成 `BLOCKED_REPORT.md`；
- 列出缺失对象、已尝试路径、命令、结果、证据和最小人工动作；
- 保持当前任务为 BLOCKED，不伪造 DONE；
- 在 `CURRENT_WORK.md` 中写入恢复步骤；
- 给出一条可复制的恢复命令或恢复提示。

运行环境即将结束但不存在硬阻塞时：

- 生成 `SESSION_CHECKPOINT.md`；
- 记录当前 commit、dirty 状态、已完成步骤、未完成步骤、最后命令、下一命令、测试状态和风险；
- 保持任务为 IN_PROGRESS；
- 下次收到同一启动提示词时自动恢复。

## 8. 工程红线

- 不修改或删除用户未提交改动；
- 不强推、不重写 Git 历史；
- 不用未登记数据宣称验收；
- 不降低阈值或删除测试来制造通过；
- 不把空实现、占位返回或静默退化当作成功；
- 不引入未固定版本的依赖；
- 不变更数据格式、ABI、CLI、配置或数据库 schema 而不更新契约和兼容测试；
- 所有外部进程、网络、硬件等待和长时操作必须有明确超时；
- 不只写计划，必须执行并留下文件证据。

## 9. Git 策略

- 开始任务前记录工作树状态；
- 用户原有 dirty 文件不纳入自动提交，除非当前任务明确要求且证据证明是本次修改；
- 每个复核 PASS 的任务创建一个原子提交，提交信息建议为：`<task_id>: <task title>`；
- Git 身份未配置或提交被策略禁止时，不阻塞任务，改为保存 patch、文件哈希和建议提交信息；
- 不自动 push，除非项目已有明确、可验证的发布流程和当前任务要求 push。

## 10. 完成状态

全部任务和 G0–G8 Gate 通过后：

- 生成最终工程完成报告；
- 汇总版本、构建、数据、接口、测试、性能、风险和残留限制；
- 验证干净 clone 可重建；
- 生成发布包和回滚说明；
- 将 `project_status` 置为 `COMPLETED`。
