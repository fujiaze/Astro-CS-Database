# 会话中断后的接续说明

> 用途：会话若因服务重启而中断，**新会话先读这一份**再动手。
> 起因：harness 重启后**长期目标会被自动解除武装**（设计如此），无人在场时不会自动续跑，
> 于是出现「服务在跑、活儿停了」的空档。本文件是那个空档的补丁。
> 放在 `eng/tools/` 而非 `run/`：`run/` 不入库且会被轮次回收清理，接续说明必须比它活得久。

## 一、先查在跑的长作业（**不要重复启动**）

```bash
pgrep -af 'acsd normalize|acsd mosaic|acsd export'
tail -5 run/M42-E2E-03/logs/driver.log
```

启动方式：`bash run/M42-E2E-03/driver.sh`（normalize → mosaic → export 一路串完）。

## 二、本机的硬约束（违反会连带杀掉 DSH 本体、中断会话）

- **内存 23 GiB，swap 永久禁用。**
- 重计算必须经 `eng/tools/monitoring/mem_guard.py --max-rss-gb <N> --timeout <秒>`。
- **上限取值 = 该用例正常峰值的 1.5–2 倍，且必须给 DSH 本体留余量**（DSH 常驻约 1 GB）：
  - 单进程探针 / 单元测试：4–8 GB；
  - **端到端多帧：14 GB**（实测单帧 5–8 GB，多帧并发 13–19 GB）。
- **反面教训**：上限设成 20 GB（贴着物理内存）时，实测 M42 的 `acsd normalize`
  单进程 RSS 达 11.65 GB 且仍在增长；上限高于机器能安全提供的量时，
  超限触发的不是本工具的进程组 137，而是**内核全局 OOM killer**——
  它按单元杀进程，**连带杀掉同单元的 DSH 本体，会话直接死**。
  **留余量比「上限设大」重要。**
- **同一时刻只跑一路重计算**：端到端 + 多路子代理 + 全量 ctest 不得并发。

## 三、调用方式的两条纪律

1. **前台不做长等待**：长 `wait` 与长轮询会把调用暴露在工具墙钟上限下，
   撞上限时**后台作业陪葬**（已发生过：M42 跑了 1.5 小时被杀）。用几十秒级的短轮询。
2. **作业脚本放仓库内的 `run/<task>/`，不放 `/tmp`**：`/tmp` 不跨会话存活
   （实测会话重启后 `/tmp/m42_driver.sh` 消失，作业起不来、退出码 127）。

## 四、接续时从哪读起

- 未闭合项与待裁决：各轮次 `run/<task>/REPORT.md` 末尾的小节；
- 工程纪律与提交规则：仓库根 `AGENTS.md`；
- 机器门现状：`python3 eng/ci/run_checks.py --all`。
